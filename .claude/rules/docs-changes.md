# Самоконтроль при правках фреймворков и документации

Грузится, когда Claude читает файл, подходящий под `paths` во frontmatter ([memory](https://code.claude.com/docs/en/memory), «Path-specific rules», сверено 30.07.2026). Правила выведены из реальных рассинхронов (Reviewer-фазы разошлись между библиотекой и рецептом; лимит «250 символов» не подтверждён и нарушался собственными агентами).

- **Один факт - один нормативный дом.** Перед добавлением правила - `rg` по docs/, CLAUDE.md и .claude/rules/: уже описано в другом месте -> ссылка, не копия. CLAUDE.md держит строку-суть + ссылку, нормативный текст живёт в одном файле.
- **Что кладём в `CLAUDE.md`, а что в skill или в `.claude/rules/`.** В `CLAUDE.md` - то, что должно быть в контексте каждой сессии в репо: конвенции, устройство каталога, грабли репозитория, «всегда делай X». Многошаговая процедура и правило, относящееся лишь к части дерева, уезжают в skill или в path-scoped rule ([memory](https://code.claude.com/docs/en/memory), «When to add to CLAUDE.md», «Write effective instructions», сверено 27.07.2026). Оттуда же ориентир объёма: целевой потолок - **200 строк на файл**, дальше падает следование инструкции.
- **Кто на самом деле читает `CLAUDE.md`.** Помимо главного цикла - **каждый кастомный и плагинный субагент**: иерархия `CLAUDE.md` входит в стартовый контекст субагента. Исключение ровно два - встроенные `Explore` и `Plan`, и переключателя у них нет; правило, нужное им, повторяется в тексте делегирования ([sub-agents](https://code.claude.com/docs/en/sub-agents), «What loads at startup», сверено 27.07.2026). Не наследуется субагентом, в частности: авто-память главного цикла, output style и размер контекстного окна (оно по модели самого субагента). Форк - исключение, он наследует родительский контекст целиком.
- **Фреймворк не впитывает содержимое артефактов.** Детали одной роли (таблицы меток, перечни маркеров, готовые формулировки) живут в референс-артефакте (агенте/skill), фреймворк - контракт + ссылка. Сигнал нарушения: запись в «библиотеке типовых фаз» длиннее 5-6 строк атрибутов.
- **Утверждение о поведении платформы Claude Code** (лимиты, обрезка, поддержка полей) - только со сверкой по официальной документации или живым экспериментом; источник фиксируется рядом. Недокументированное помечается «не задокументировано», цифры не выдумываются. Это анти-паттерн №11 SKILL_FRAMEWORK, применённый к docs.
- **Заявление «это проверяет валидатор» сверяется с кодом валидатора.** Лимит/правило в self-check без реальной проверки в `tools/validate-*.js` помечается как ручное (👁), не выдаётся за автоматическое.
- **Числа состояния каталога** (количество агентов/плагинов/строк) в нормативный текст не хардкодить - устаревают молча. Либо без числа («десятки»), либо там, где число и так бампается (marketplace.json).
- **Roadmap / «Что дальше» / «Статус миграции»** - не в нормативных доках; место - PR description и git history. Исключение - с датой и условием удаления.
- **После правки правила - кросс-сверка дублей:** `rg` по ключевым терминам изменённого правила по docs/, CLAUDE.md и .claude/rules/; каждая найденная копия либо синхронизирована, либо сведена к ссылке. Путь пишется до `rules/` (или добавляется `--hidden`): по умолчанию `rg` в скрытую директорию не заходит вовсе, а если взять корнем поиска `.claude/`, содержимое отсечёт правило `.claude/*` из `.gitignore` - негацию `!.claude/rules/` git учитывает, `rg` в этом случае нет.

Гейт перед коммитом (`npm run validate`, что закрывает CI, а что ручное) - `.claude/rules/plugin-changes.md`.
