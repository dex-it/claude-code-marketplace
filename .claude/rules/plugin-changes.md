# Правки каталога: версии, синхронизации, гейт перед коммитом и CI

Грузится, когда Claude читает файл, подходящий под `paths` во frontmatter ([memory](https://code.claude.com/docs/en/memory), «Path-specific rules», сверено 30.07.2026). Общие принципы содержания и конвенции - в корневом [CLAUDE.md](../../CLAUDE.md).

## Версионирование при изменениях (semver)

| Тип изменения | Bump | Пример |
| ------------- | ---- | ------ |
| Новый плагин | `1.0.0` | Создан новый skill / специалист |
| Новый плагин -> версия каталога | minor каталога | `marketplace.json` `version` `5.6.0` -> `5.7.0` при добавлении плагина |
| Изменён состав bundle (`includes[]` или `dependencies[]`) | minor bundle | Добавлен/убран компонент - bump версии самого bundle |
| Rename плагина | major (`2.0.0`) | Переименование имени в frontmatter / директории |
| Breaking change в workflow / API агента | major | Новый рецепт, изменение output format |
| **Добавление новых ловушек в skill** | minor (`+0.1.0`) | Обогащение существующего skill обратно-совместимо |
| Новая категория ловушек | minor | Добавлен раздел, keywords расширены |
| Dedup с другим skill | minor | Перенос общих ловушек в базовый skill |
| Fix description / keywords / опечатка | patch (`+0.0.1`) | Уточнение без содержательных правок |

**`description` живёт в двух жанрах, и они не сводятся друг к другу.** Жанр 1 - **поле срабатывания**: `description` во frontmatter скилла и агента. Им артефакт выбирается: «Claude uses this to decide when to apply the skill» ([skills](https://code.claude.com/docs/en/skills)), «Claude uses each subagent's description to decide when to delegate tasks» ([sub-agents](https://code.claude.com/docs/en/sub-agents), оба сверено 22.08.2026); у скилла оно лежит в контексте постоянно и режется на 1536 символов вместе с `when_to_use`. Форма (anchor+aspects, фраза-триггер, лимиты) - [SKILL_FRAMEWORK.md](../../docs/SKILL_FRAMEWORK.md). Жанр 2 - **витрина**: `description` в `plugin.json` и в записи каталога, «Brief explanation of plugin purpose», показывается в `/plugin` picker и на решения Claude не влияет ([plugins-reference](https://code.claude.com/docs/en/plugins-reference), сверено 22.08.2026). Отсюда запрет: **сверять эти два текста дословно нельзя** - витрина, набитая триггерами, и поле активации без них хуже оба. Сверяется только непротиворечивость по существу (витрина не обещает того, чего в теле нет) - ручная ось ревью, валидатор её не видит.

**Витрина внутри своего жанра дублируется, и дом у неё один - `plugin.json`.** Копия в записи `marketplace.json` **генерируется**: `npm run sync:marketplace` (`--check` - показать расхождения без записи), руками не пишется. Расхождение ловит `description-mismatch` (error). Основание дома - зонд 22.08.2026: при разных текстах установленный плагин показывает описание манифеста (`claude plugin details`), каталожное после установки не видно нигде; документация правила приоритета для `description` не даёт вовсе, хотя для соседних полей записи даёт явно (`displayName` «Falls back to `name`», `defaultEnabled` «Takes precedence over the same field in the plugin's `plugin.json`»). Копия не удалена, потому что поведение браузера каталога ДО установки из CLI не наблюдаемо.

**Витрина пишется по-русски и по телу артефакта.** Каталог русскоязычный; английская витрина у части плагинов давала в `/plugin` перемешанный список (правило `description-not-russian`, warning - нет ни одного кириллического символа). Текст берётся из тела артефакта, а не переводом поля активации: жанры разные, и витрина, набитая триггерами, хуже обеих (см. абзац выше).

**Версии обновляются в двух местах одновременно:** `.claude-plugin/plugin.json` **и** `.claude-plugin/marketplace.json`. Несогласованность - частая ошибка; ловит `npm run validate` правилом `version-mismatch` (warning, охват - каждый плагин под `plugins/`).

**Версия самого каталога** (`marketplace.json` верхнеуровневое `version`) бампается при добавлении/удалении плагина - это отдельный счётчик, не выводится из версий плагинов и легко забывается. Новый плагин = minor каталога.

## Обязательные синхронизации

- **Создал новый skill** -> добавить запись в `.claude-plugin/marketplace.json` (иначе плагин не виден каталогу)
- **Запись каталога несёт `category`, и значение выводится из содержимого плагина**, а не выбирается: `bundle.json` -> `bundle`, `agents/` -> `specialist`, `skills/` -> `skill`, `hooks/` либо `commands/` -> `utility` (порядок признаков именно такой - специалист несёт `commands/` наравне с `agents/`). Поле группирует витрину `/plugin`; `npm run sync:marketplace` его не пишет - генератор трогает только `description` и `version`, остальное ведётся руками. Пропуск проходил гейт молча, пока правила не было (пойман на `dex-sdlc-nudge`: запись без `category` и `keywords`); теперь ловит `catalog-category-mismatch` (error). `keywords` правилом не покрыты - сверять их значение не с чем, заполняются по телу артефакта
- **Бандл должен быть замкнут по артефактам своих компонентов.** Каждый артефакт, который называет полной формой `` `dex-X:Y` `` агент, скилл или команда из состава бандла, обязан ехать в этом же бандле - установка плоская, каскада «специалист -> его скиллы» нет, недостающий артефакт не приедет и компонент молча деградирует. Это проверяет `npm run validate:bundles` (`bundle-not-closed`, `bundle-agent-not-closed`, `bundle-command-not-closed`). Триггеры: добавил компонент в bundle, добавил компоненту новую ссылку, создал артефакт для компонента из bundle. **Вызов, который называет артефакт как один вариант из набора, помечается `` `[справочно]` `` вплотную за вызовом** - реестр зон перечисляет все треки, меню стека все стеки, а грузится один, по проекту: `` `dex-skill-kafka:kafka` `[справочно]` ``. Пометка снимает обязанность поставки и стоит у самого вызова, не у строки и не у заголовка - в одной строке соседствуют безусловный вызов и условные. Забыл пометку - валидатор потребует положить артефакт в бандл; поставил лишнюю - артефакт перестанет требоваться, и потребитель деградирует молча. **Пометка снимает поставку, поэтому ставится только там, где артефакт не нужен проекту вовсе** - чужой стек (`dex-skill-redis` в проекте без Redis), чужая зона (трек продукта у .NET-разработчика). Меню внутри собственного предмета пометки не несёт: «для DI - ..., для LINQ - ...» у .NET-кодера условно по задаче, а не по проекту - какой понадобится, решается в работе, и приехать обязаны все.
- **Создал новый skill, на который ссылается агент в фазе Skill-Based Scan** -> проверить, что точное имя `{plugin}:{skill}` совпадает с фактической директорией
- **Поменял description / keywords skill** -> длина в лимите. Числа, уровни (error/warning) и парные константы валидатора - [SKILL_FRAMEWORK.md](../../docs/SKILL_FRAMEWORK.md) («Лимиты (валидатор)»); здесь не дублируем - копия разошлась бы молча
- **Точное число внутренних единиц артефакта не хардкодить в `description`.** Число фаз агента, фокусов скана, ловушек skill, шагов команды - деталь реализации; дом - тело артефакта, там оно и живёт. `description` дублируется в 3+ мест (frontmatter + plugin.json + marketplace.json) - число в нём даёт столько же точек тихого рассинхрона (self-reviewer: «7 фокусов» в трёх описаниях при восьми в теле). В описании - нехрупкая форма: «многофокусный скан», перечень тем-фокусов (усиливает и авто-активацию сильнее цифры), «фазы X->Y->Z» по смыслу. Частный случай запрета хардкодить числа состояния ([docs-changes.md](docs-changes.md)) для поля `description`
- **Поменял агента** -> mandatory-фазы требуют явного обоснования «почему mandatory», иначе валидатор упадёт
- **Переименовал агента (`name`) или завёл новый норматив этапа** -> править карту владельцев `ALLOWED_PRELOAD_SKILLS` в `tools/validate-agent.js`. Она сверяет `name` дословно: после rename владелец этапа перестаёт им быть и падает на собственном frontmatter (`frontmatter-skills-not-own-stage`), а норматив без строки в карте вообще не pre-loadable (`frontmatter-skills-not-preloadable`). Смысл разделения - [AGENT_FRAMEWORK.md](../../docs/AGENT_FRAMEWORK.md#подключение-skills-pre-load-безусловного-императив-условного)

## Перед коммитом

`npm run validate` (или точечно `validate:agents` / `validate:skills` / `validate:commands` / `validate:bundles`) - 0 ошибок. Проверки строгие, мягкого режима нет.

Цепочка `validate` шире плагинов: за артефактами идёт мета-валидатор `validate-rules-documented.js` (каждое правило из `tools/validate-*.js` имеет строку в [VALIDATOR_RULES.md](../../docs/VALIDATOR_RULES.md), фикстуру в `tools/__fixtures__` - и наоборот).

**`npm test` - вторая половина гейта, `npm run validate` её не заменяет.** Валидаторы гоняются на живом каталоге, где правило и должно молчать: выключенное правило там неотличимо от соблюдённого. `tools/test-rules.js` прогоняет каждую пару «валидатор x правило» на фикстуре, где дефект заведомо есть. Отсюда следствие: **завёл или переименовал правило -> строка в реестре правил и директория `tools/__fixtures__/<validator>/<rule>/`**, иначе падают `rule-not-documented` / `rule-registry-stale` / `rule-untested`. Устройство фикстур и контракт `expect.json` - [VALIDATOR_RULES.md](../../docs/VALIDATOR_RULES.md#регрессия-правил-фикстуры).

**Правка `optimize-for-llm` (тело скилла или его `references/`) закрывается прогоном, а не валидатором.** Валидатор судит форму файла, предмет правки - поведение исполнителя на резе, и молча деградирует именно оно. До коммита: прогнать кейсы [tests/optimize-for-llm/](../../tests/optimize-for-llm/README.md), покрывающие тронутое правило, плюс O-08 (правильный исход - не резать; ловит перекос в сторону дельты). Исход - строка в реестре прогонов [tests/README.md](../../tests/README.md): версия скилла, кейсы, «да / нет» по каждому инварианту, находки. Прогон невозможен инструментарно (нет `Agent`) - в PR названо, какие кейсы не прогнаны и почему; молчание = правка не сдана. Тронул правило, под которое кейса нет, - кейс заводится этой же правкой.

**CI повторяет локальный гейт целиком.** Чек прогоняет все валидаторы цепочки `npm run validate` отдельными шагами (агенты, скиллы, команды, бандлы, мета-валидатор правил) плюс `npm test`. Шаги перечислены поимённо, а не вызовом `npm run validate` - при падении видно, какой валидатор упал, не вчитываясь в лог. Отсюда обязанность: **новый валидатор -> строка в `package.json` И шаг в job `validate`**, иначе проверка живёт только на локальной машине. Фильтра путей на `pull_request` нет, поэтому чек приходит на любой PR, включая PR из одних `.json` (бампы версий, `bundle.json`, `marketplace.json`).

**Не возвращать `paths` в `pull_request`.** Оба чека required, а required-чек, который не запустился, пройденным не считается: PR, ни один файл которого не попал под фильтр, не получает чек вовсе и висит в BLOCKED навсегда, write-права bypass не дают. Перечислять пути под required-чеком не сходится - список расширяли четырежды и каждый раз после того, как PR уже завис. Фильтр в `push`-блоке к этому отношения не имеет: прогон на `main` пост-мерджевый и гейтом не служит.

Размер skill и команды, лимиты `description` и существование плагина из Skill-ссылки **агента** валидаторы закрывают сами - в ручной список это не выносим. Проверки размера агента нет ни в одном валидаторе - это ручное. Ручное остаётся там, где валидатор не видит:

- **Имя скилла** в ссылке `{plugin}:{skill}`. В теле агента сверяется только половина-плагин (`skill-reference-unknown`), и только у ссылки в бэктиках с префиксом `dex-skill-`; опечатка в половине-скилле не ловится. Во frontmatter `skills:` наоборот: ловится половина-скилл при известном плагине (`frontmatter-skills-unknown-skill`) и голое имя плагина без скилла (`frontmatter-skills-bare-plugin-name`), а **опечатка в половине-плагине не ловится нигде** - нормализация берёт часть после последнего `:`, а неизвестный плагин объявлен вне области проверки. Проверено зондом: правка `dex-skill-node-contract` на `dex-skill-nodecontract` даёт 0 ошибок, правка `node-contract` на `nodecontract` - 2. В теле **команды** ссылка `{plugin}:{skill}` проверяется целиком, обе половины, любой скилл-поставляющий плагин (`skill-reference-unknown` в `tools/validate-command.js`) - шире агентской проверки, опечатка в любой половине ловится
- **Содержание `references/`**: у вынесенного материала валидатор ловит ссылку на `docs/` каталога (`catalog-docs-link`) и ссылку за корень плагина (`link-escapes-plugin`), а размер меряет предупреждением - и по файлу, и суммой по директории (`reference-chars-exceed-recommended`, `reference-dir-chars-exceed-recommended`); дубль с телом, устаревший кусок, висячую ссылку и потерянную нормативную силу он не видит вовсе. Ревью артефакта берёт `references/` в предмет наравне с телом - `dex-skill-artifact-review:artifact-review`
- **Handoff**: содержание объявленной сигнатуры - какие поля названы, что блокирующее, куда уходит нехватка - [AGENT_FRAMEWORK.md](../../docs/AGENT_FRAMEWORK.md#self-check-перед-коммитом). Присутствие самих атрибутов и pre-load контракта стыка ручным больше не является: его держат `handoff-input-missing`, `handoff-output-missing` и `frontmatter-skills-missing`, все error
- **Содержание**: обобщённость ловушки, отсутствие документации API, пункты 👁 в self-check фреймворков
