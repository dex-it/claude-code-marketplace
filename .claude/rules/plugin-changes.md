# Правки плагинов: версии, синхронизации, гейт перед коммитом

Грузится при работе с `plugins/`, `.claude-plugin/` и `tools/`. Общие принципы содержания и конвенции - в корневом [CLAUDE.md](../../CLAUDE.md).

## Версионирование при изменениях (semver)

| Тип изменения | Bump | Пример |
| ------------- | ---- | ------ |
| Новый плагин | `1.0.0` | Создан новый skill / специалист |
| Новый плагин -> версия каталога | minor каталога | `marketplace.json` `version` `5.6.0` -> `5.7.0` при добавлении плагина |
| Изменён состав bundle (`includes[]`) | minor bundle | Добавлен/убран компонент - bump версии самого bundle |
| Rename плагина | major (`2.0.0`) | Переименование имени в frontmatter / директории |
| Breaking change в workflow / API агента | major | Новый рецепт, изменение output format |
| **Добавление новых ловушек в skill** | minor (`+0.1.0`) | Обогащение существующего skill обратно-совместимо |
| Новая категория ловушек | minor | Добавлен раздел, keywords расширены |
| Dedup с другим skill | minor | Перенос общих ловушек в базовый skill |
| Fix description / keywords / опечатка | patch (`+0.0.1`) | Уточнение без содержательных правок |

**Версии обновляются в двух местах одновременно:** `.claude-plugin/plugin.json` **и** `.claude-plugin/marketplace.json`. Несогласованность - частая ошибка.

**Версия самого каталога** (`marketplace.json` верхнеуровневое `version`) бампается при добавлении/удалении плагина - это отдельный счётчик, не выводится из версий плагинов и легко забывается. Новый плагин = minor каталога.

## Обязательные синхронизации

- **Создал новый skill** -> добавить запись в `.claude-plugin/marketplace.json` (иначе плагин не виден каталогу)
- **Бандл должен быть замкнут по скиллам своих агентов.** Каждый не-by-stack скилл, который грузит агент из `includes[]` бандла, обязан быть в этом `includes[]` - установка плоская, каскада «специалист -> его скиллы» нет, недостающий скилл не приедет и агент молча деградирует. Это проверяет `npm run validate:bundles` (правило `bundle-not-closed`). Триггеры: добавил агента в bundle, добавил агенту новую Skill-ссылку, создал skill для агента из bundle. Исключение - by-stack профильные скиллы (`dex-skill-{стек}-*`): грузятся условно по стеку проекта, в каждый бандл не тащатся (см. `dex-skill-stack-registry:stack-registry`). Но как только бандл везёт хотя бы один скилл этого стека (стековый бандл, dotnet-developer и т.п.), он обязан быть замкнут и по этому стеку: иначе стек-специфичный агент (`dex-dotnet-coder`) останется без скилла, который всегда грузит.
- **Создал новый skill, на который ссылается агент в фазе Skill-Based Scan** -> проверить, что точное имя `{plugin}:{skill}` совпадает с фактической директорией
- **Поменял description / keywords skill** -> длина в лимите. Числа, уровни (error/warning) и парные константы валидатора - [SKILL_FRAMEWORK.md](../../docs/SKILL_FRAMEWORK.md) («Лимиты (валидатор)»); здесь не дублируем - копия разошлась бы молча
- **Поменял агента** -> mandatory-фазы требуют явного обоснования «почему mandatory», иначе валидатор упадёт

## Перед коммитом

`npm run validate` (или точечно `validate:agents` / `validate:skills` / `validate:commands` / `validate:bundles`) - 0 ошибок. Проверки строгие, мягкого режима нет.

**CI уже локального прогона, и в двух местах сразу.** Чек запускает валидаторы агентов, скиллов и команд, а `validate:bundles` в нём не идёт вовсе - замкнутость бандла гейтит только локальный прогон. Фильтр `paths` покрывает `plugins/**/*.md`, `tools/**`, `docs/**`, `CLAUDE.md`, `run-claude/**`, `**.sh`, `package.json`, `package-lock.json` и сам workflow. **PR из одних `.json`** (бампы версий, `bundle.json`, `marketplace.json`) под фильтр не попадает, а чек required: такой PR не получает его вовсе и висит в BLOCKED навсегда, write-права bypass не дают.

Размер skill и команды, лимиты `description` и существование плагина из Skill-ссылки **агента** валидаторы закрывают сами - в ручной список это не выносим. Проверки размера агента нет ни в одном валидаторе, ссылки на скиллы в теле команды тоже не проверяются - и то, и другое ручное. Ручное остаётся там, где валидатор не видит:

- **Имя скилла** в ссылке `{plugin}:{skill}`. В теле агента сверяется только половина-плагин (`skill-reference-unknown`), и только у ссылки в бэктиках с префиксом `dex-skill-`; опечатка в половине-скилле не ловится. Во frontmatter `skills:` наоборот: ловится половина-скилл при известном плагине (`frontmatter-skills-unknown-skill`) и голое имя плагина без скилла (`frontmatter-skills-bare-plugin-name`), а **опечатка в половине-плагине не ловится нигде** - нормализация берёт часть после последнего `:`, а неизвестный плагин объявлен вне области проверки. Проверено зондом: правка `dex-skill-node-contract` на `dex-skill-nodecontract` даёт 0 ошибок, правка `node-contract` на `nodecontract` - 2
- **Handoff**: объявленная сигнатура, `Input` фазы входа, `node-contract` у узла - [AGENT_FRAMEWORK.md](../../docs/AGENT_FRAMEWORK.md#self-check-перед-коммитом)
- **Содержание**: обобщённость ловушки, отсутствие документации API, пункты 👁 в self-check фреймворков
