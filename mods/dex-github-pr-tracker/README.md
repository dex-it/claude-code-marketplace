# dex-github-pr-tracker

Pull request GitHub, за которым не надо ходить в браузер.

Мод берёт репозиторий из git-remote той папки, в которой открыта сессия, находит PR текущей ветки и держит его перед глазами: строка над полем ввода несёт состояние, merge state status, исход обязательных проверок, вердикт ревью, счётчик тредов, комментариев и коммитов; панель `/pr` раскрывает то же подробно, с каждым тредом по файлу и строке и с перечнем упавших проверок. Когда ревьюер открывает тред, отвечает в нём, ставит апрув или падает проверка - в сессию приходит тост и строка в транскрипт. Команда `/pr threads` выписывает открытые треды текстом, `/pr checks` - не зелёные проверки со ссылками на логи, и модель читает их как задание на правки.

Это **мод** - плагин на function hooks: TypeScript, который исполняется внутри процесса Claude Code, а не команда оболочки на событие. Function hooks в раннем доступе и включаются переменной окружения (см. «Установка»).

Рядом живёт [dex-gitlab-mr-tracker](../dex-gitlab-mr-tracker/README.md) - то же для merge request GitLab, той же формы строки и панели. Различия между ними - не вкусовые, а от хостингов: они названы ниже по месту.

## Требования

- Claude Code с поддержкой function hooks (проверено на 2.1.282) и `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1`.
- Доступ к GitHub одним из двух способов:
  - [`gh`](https://cli.github.com), залогиненный в нужный хост (`gh auth login`, для Enterprise Server - `gh auth login --hostname gh.example.com`) - рекомендуемый путь: он уже знает и хосты, и токены;
  - либо токен с правом чтения pull request в `GH_TOKEN` (или `GITHUB_TOKEN`, для Enterprise Server - `GH_ENTERPRISE_TOKEN` / `GITHUB_ENTERPRISE_TOKEN`, либо в настройке `token` мода) - тогда мод ходит в GraphQL сам.
- Сессия открыта в клоне репозитория GitHub; хост и путь `owner/repo` берутся из remote (`origin` по умолчанию).
- Необязательно: macOS для звука (`afplay`) и `open` для «открыть в браузере»; на Linux пробуется `xdg-open`.

## Установка

1. Включить function hooks. В `~/.claude/settings.json`:

   ```json
   { "env": { "CLAUDE_CODE_ENABLE_FUNCTION_HOOKS": "1" } }
   ```

   Без этого мод поставится, но ничего делать не будет. Для одной сессии хватит префикса: `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1 claude`.

2. Поставить из каталога:

   ```sh
   claude plugin install dex-github-pr-tracker@dex-claude-marketplace
   ```

   Попробовать без установки, из клона каталога:

   ```sh
   CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1 claude --plugin-dir mods/dex-github-pr-tracker
   ```

3. Открыть сессию в проекте GitHub на ветке, у которой есть PR. Строка появится над полем ввода в течение нескольких секунд.

## Использование

- **PR текущей ветки** подхватывается сам и переключается вместе с веткой. Отключается настройкой `autoWatchBranch`.
- **`/pr`** - открыть или закрыть панель.
- **`/pr 123`**, **`/pr <ссылка>`** - добавить PR (в том числе из чужого репозитория - ссылка несёт хост и путь) и показать его.
- **`/pr threads`** - выписать открытые треды в транскрипт: файл, строка, автор, число комментариев, первая строка и ссылка на комментарий. Это вход для модели: после него можно просто сказать «закрой замечания».
- **`/pr checks`** (или `/pr ci`) - выписать не зелёные проверки: имя, обязательная или нет, исход и ссылка на лог.
- **`/pr status`** - то же про состояние PR одним блоком.
- **`/pr refresh`** - опросить GitHub сейчас.
- **`/pr drop [123 | all]`** - снять с отслеживания.
- **Ссылка на PR целым промптом** включает и выключает наблюдение, не тратя ход модели; ссылка внутри обычного промпта просто добавляет PR.
- **PR, который открыл Claude** (`gh pr create` через Bash, либо ссылка в его ответе), берётся под наблюдение сам.
- **Кнопки** строки - «открыть», «детали», «×» - нарисованы приглушённо и жмутся мышью либо с клавиатуры: `ctrl+x tab` берёт полосу над вводом в фокус. В панели свои кнопки: «открыть в браузере», «снять с отслеживания» и **«треды в промпт»** - открытые треды уедут контекстом следующего промпта один раз.

## Как читать строку

```
marketplace#128 open · blocked · ci success · ●2/7 · ✎24 · ↑12 · ✔1 · Фикс гонки в очереди
```

- **`marketplace#128`** - репозиторий и номер PR. Ссылка кликается там, где терминал рендерит гиперссылки (Ghostty, iTerm2, WezTerm - да; Terminal.app - нет, останется текстом); в остальных случаях открывает кнопка «открыть».
- **состояние** - `open`, `draft`, `merged`, `closed`.
- **merge state status** - `mergeStateStatus` GitHub в нижнем регистре, раскрашенный по смыслу: зелёный `clean` и `has_hooks` («mergeable and passing commit status»); красное требует вмешательства в ветку (`dirty` - конфликт, `behind` - голова отстала от базы); серое не требует ничего (`draft`); жёлтое - штатный гейт ещё не пройден (`blocked` - правила репозитория, `unstable` - мержить даёт, но проверка красная, `unknown` - ещё считается). Перечень задан схемой GraphQL и состоит из восьми имён, но Enterprise Server отстаёт от github.com, поэтому незнакомое значение рисуется жёлтым как есть, а не прячется.
- **`ci`** - исход **обязательных** проверок головного коммита. Это не то же, что роллап GitHub: у PR рядом с обязательными проверками ветки крутятся необязательные, и роллап краснеет от любой из них. Строка отвечает на вопрос «мешает ли что-то мержу», поэтому необязательная красная джоба её не красит; весь перечень, с пометкой обязательной, печатает `/pr checks`. Обязательных проверок у ветки нет вовсе - берётся роллап, других сведений тогда и нет.
- **`●2/7`** - открытых тредов из всех. У GitHub тред решает сам GitHub (`isResolved` - поле треда), поэтому второго класса тредов тут нет: делятся только на открытые и закрытые.
- **`✎24`** - комментарии в обсуждении PR (ленте). Комментарии внутри тредов считаются по треду и видны в панели - это у GitHub отдельный корпус, а не те же записи.
- **`↑12`** - коммиты ветки, число точное (приходит счётчиком, не длиной страницы).
- **`✔1`** - апрувы, по последнему ревью каждого человека. Цвет - вердикт ревью: зелёный `одобрен`, красный `нужны правки`, жёлтый `ждёт ревью`. Репозиторий, где ревью не обязательно и никто не высказался, эту отметку не показывает вовсе.
- **`опрос не удался`** в конце - последний запрос не прошёл, показаны прежние значения.

## Когда мод опрашивает GitHub

Три повода, и все три - сами, без кнопки:

- **таймер** - раз в `pollSeconds` (по умолчанию минута, минимум 15 секунд);
- **конец хода модели** - вы возвращаетесь к промпту и видите то, что в GitHub сейчас, а не то, что было на последнем тике;
- **своя команда в Bash**, меняющая PR: `git push`, `git commit`, любое действие `gh pr`.

Два последних повода не дублируют таймер: PR, опрошенный меньше 20 секунд назад, пропускается. Принудительный опрос - `/pr refresh`.

Отдельный повод - **слияние, которое ещё не вычислено**. GitHub считает мержабельность фоном, и сам запрос её вычисление запускает; после пуша первый ответ приходит с `unknown`. Мод перезапрашивает такой PR один раз через три секунды, чтобы строка не несла `unknown` целую минуту.

## Что приходит в сессию

Каждый опрос сравнивается с предыдущим. Первая загрузка PR не объявляет ничего. Дальше в транскрипт ложится строка (она остаётся в истории), а поверх - тост:

- состояние и `draft`, merge state status;
- **исход обязательных проверок** - красная необязательная джоба не объявляется: она ничего не блокирует, и будить ею значит приучить не смотреть на тосты;
- **новый тред** - с файлом, строкой, автором и первой строкой замечания;
- **тред закрыт** и **тред открыт заново**;
- **новые комментарии** в известном треде и в обсуждении PR;
- **новые коммиты** и force push;
- **вердикт ревью** и число апрувов.

Настройка `notify`: `all` (по умолчанию), `important` (без отдельных комментариев) и `off`. Звук (`sound`) по умолчанию выключен.

## Настройки

Правятся через `/config`, раздел мода.

| Поле | По умолчанию | Смысл |
| --- | --- | --- |
| `remote` | `origin` | remote, из URL которого берутся хост и путь репозитория |
| `host`, `repository` | пусто | задать вручную, если из remote не выводятся; `repository` - в форме `owner/repo` |
| `pollSeconds` | `60` | период опроса, от 15 секунд до часа |
| `autoWatchBranch` | `true` | искать PR текущей ветки |
| `backend` | `auto` | `auto` - gh, иначе GraphQL с токеном; `gh`; `api` |
| `token` | пусто | токен с правом чтения pull request для источника `api` |
| `notify` | `all` | что объявлять |
| `sound` | `false` | звук на изменение (macOS) |

## Где садится панель

Место и размер панели выбирает Claude Code, мод на них не влияет - `$.ui.open` параметра ширины не имеет вовсе, а ширина тела приходит в отрисовку только на чтение.

| Режим терминала | Где панель | Ширина | Высота |
|---|---|---|---|
| Fullscreen (alternate screen), от 110 колонок | доком сбоку от транскрипта | узкая колонка, не настраивается никем | во весь экран |
| Главный экран (`CLAUDE_CODE_NO_FLICKER=0`, и по умолчанию в tmux), любая ширина | над полем ввода | вся ширина терминала | по содержимому PR, не больше половины экрана |

Отсюда практическое следствие: широкая панель - это главный экран, а не док. В доке адрес треда ужимается с головы (`.../Eye/Command/CreateEyeLinesData.cs:54`), чтобы имя файла и строка оставались видны на любой ширине.

## Чем отличается от мода GitLab

Форма строки, панели, команд и настроек - одна; различия идут от хостингов, и каждое видно в коде:

- **Один запрос вместо четырёх.** Состояние треда - решён он или нет - у GitHub существует только в GraphQL: REST-эндпоинт комментариев PR такого поля не несёт вовсе. Поэтому мод спрашивает один GraphQL-запрос, который отдаёт и состояние PR, и проверки, и коммиты, и треды, - вместо четырёх REST-вызовов, как у GitLab.
- **Свёртку тредов делать не надо.** У GitLab `resolved` есть только у заметки, и тред «закрыт, когда закрыты все его резолвимые заметки» - допущение мода. У GitHub `isResolved` - поле самого треда.
- **Обязательность проверки.** У GitLab один пайплайн и один статус; у GitHub проверок десятки, и часть из них ничего не блокирует. Отсюда `isRequired` в запросе и правило раскраски строки.
- **Ссылка на тред приходит готовой.** У GitLab форму якоря заметки приходилось собирать самому (`#note_<id>`), у GitHub `url` комментария отдаёт API.
- **Точное число коммитов.** GitLab отдаёт страницу, и мод показывает `12+`; GitHub отдаёт счётчик, и число точное.
- **Отказ по токену останавливает опрос.** На череду неудачных попыток аутентификации GitHub начинает отказывать любой - поэтому после такого отказа мод перестаёт опрашивать до `/pr refresh`, а не повторяет запрос каждую минуту.

## Пределы

- Один опрос PR - один запрос GraphQL, плюс по запросу на каждую следующую страницу тредов (страница - 50 тредов, страниц не больше пяти). Счётчик тредов приходит полем и остаётся верным, даже когда прочитаны не все страницы.
- Лимит github.com - 5000 точек в час на пользователя; один опрос стоит одну точку. Внутри GitHub Actions бюджет 1000 точек в час на репозиторий.
- Условных запросов (`ETag`) у GraphQL нет, поэтому сэкономить на неизменившемся PR нельзя - только периодом опроса.
- Приватный репозиторий отвечает 404, а не 403, чтобы не подтверждать своё существование, поэтому «PR не найден» и «не хватает прав» мод различить не может и называет оба.
- Проверки берутся только с головного коммита; проверок прежних коммитов PR не видно. Контекстов читается до 50 на коммит.
- Список наблюдения живёт в памяти сессии: перезапуск или горячая перезагрузка мода начинают с PR текущей ветки заново.
- Панель и строка рисуются только в интерактивной сессии; в `-p` работают команды, но опрос по таймеру не запускается.
- Мод только читает GitHub. Резолв тредов, ответы, мерж и любые записи - вне объёма.

## Разработка

```sh
npm run typecheck:mods                            # tsc по mods/ (входит в npm run validate)
npm run test:mods                                 # прогон чистой половины
claude plugin validate --strict mods/dex-github-pr-tracker   # манифест, перечень хуков и вызовов $
CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1 claude -p "/pr status" --plugin-dir mods/dex-github-pr-tracker
```

Последняя команда - живой прогон без установки: она берёт PR текущей ветки и печатает его состояние текстом, то есть проверяет весь путь от remote до ответа GitHub.

Относительные импорты внутри мода идут **с расширением `.ts`**: без него `node --test` не резолвит цепочку, и прогоном закрывались бы только модули без импортов. Форма проверена живым прогоном на 2.1.282.

Контракт типов - `mods/types/claude-code.d.ts`, пишется командой `/plugin-types` и руками не правится. Устройство класса, инструментарий и self-check - [MOD_FRAMEWORK.md](https://github.com/dex-it/claude-code-marketplace/blob/main/docs/MOD_FRAMEWORK.md).

Правки подхватываются горячей перезагрузкой запущенной сессии; если перезагрузка сорвалась на середине, транскрипт скажет об этом - помогает перезапуск сессии.
