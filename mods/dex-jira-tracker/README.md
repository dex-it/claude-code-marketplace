# dex-jira-tracker

Jira, за которой не надо ходить в браузер, и кнопка от задачи до pull request.

Мод читает Jira через [jira-cli](https://github.com/ankitpokhrel/jira-cli) и держит перед глазами задачи проекта: строка над полем ввода несёт итог (в работе, открытых, мои) и те задачи, которые ждут вас; панель `/jira` раскрывает список по группам, а вход в строку - детали задачи с описанием и комментариями. Когда в Jira что-то меняется - статус, исполнитель, приоритет, приходит новая задача, коллега пишет комментарий или упоминает вас, - в сессию приходит тост и строка в транскрипт. Если что-то случилось, пока сессия была закрыта, при старте придёт одна сводка.

От задачи работа идёт кнопками: **постановка** (написать задание по идее или по задаче), **взять в работу** (назначить на себя, перевести в рабочий статус, завести ветку, реализовать), **сдать** (push, PR/MR, ссылка в задачу). Мод сам почти ничего не делает: он готовит поручение и отдаёт его модели в основной цикл, где у вас есть слово «стоп». Инструменты берутся из каталога, если они установлены (`/feature`, `/implement`, трекеры PR/MR), а если нет - работает встроенное поручение, и транскрипт называет, что именно и как поставить.

Это **мод** - плагин на function hooks: TypeScript, который исполняется внутри процесса Claude Code, а не команда оболочки на событие.

## Требования

- Claude Code 2.1.287 или новее: с этой версии моды включены без переменных окружения. Всё проверено на 2.1.309.
- [jira-cli](https://github.com/ankitpokhrel/jira-cli) в `PATH` и работающий вход: `jira me` называет вас. Нет бинаря - `/jira install` поставит его через brew, `/jira setup` покажет остальные способы.
- Для кнопок «сдать» и PR/MR: `gh` либо `glab`, залогиненный в хостинг репозитория.
- Необязательно: macOS для звука (`afplay`) и `open` для «открыть в браузере»; на Linux пробуется `xdg-open`.

## Быстрый старт

1. Подготовить jira-cli: `jira me` называет вас (нет бинаря или входа - см. «Подготовка jira-cli»).
2. Запустить Claude Code с модом: быстро и без установки - «Посмотреть локально», постоянно - «Установка из каталога».
3. Набрать `/jira`. Откроется панель со списком задач проекта, а над полем ввода появится строка с итогом.
4. Нажать на ключ задачи: откроются детали с описанием и комментариями. Кнопки в деталях ведут по рабочему пути: «постановка», «взять в работу», «сдать (PR/MR)».
5. Работать как обычно. Когда в Jira что-то изменится, придёт тост и строка в транскрипт; строка над вводом покажет, какие задачи ждут вас.

## Подготовка jira-cli

Мод читает Jira только через [jira-cli](https://github.com/ankitpokhrel/jira-cli): токен и конфиг он не читает и нигде не хранит.

```sh
brew tap ankitpokhrel/jira-cli && brew install jira-cli   # или /jira install прямо из сессии
export JIRA_API_TOKEN=...                                # Cloud: email + API-токен; Server/DC: JIRA_AUTH_TYPE=bearer + PAT
jira init                                                # тип установки, сервер, проект, доска
jira me                                                  # проверка: назвал вас
```

Получение токена - в [CREDENTIALS.md](https://github.com/dex-it/claude-code-marketplace/blob/main/CREDENTIALS.md). Нет jira-cli или вход не настроен - в транскрипте будет одна строка с причиной и командой, а строка над вводом не рисуется, пока вы не вызвали `/jira`.

## Посмотреть локально, без установки

Ничего ставить из каталога не нужно: Claude Code подгружает мод прямо из папки на время одной сессии. После выхода из сессии в вашей конфигурации не остаётся следов (кроме снимка набора в store плагина, он нужен для сводки «что изменилось, пока сессия была закрыта»).

1. Взять каталог и перейти в его корень. Если клон уже есть, достаточно `git pull`.

   ```sh
   git clone https://github.com/dex-it/claude-code-marketplace.git
   cd claude-code-marketplace
   ```

   Мод ещё не влит в основную ветку? Переключитесь на его ветку: `git switch feat/mods-jira-tracker`.

2. Убедиться, что jira-cli отвечает: `jira me` назвал вас, `jira issue list --paginate 0:3` показал задачи. Иначе - «Подготовка jira-cli».

3. Запустить Claude Code с подключённым модом. Обязательно из корня клона, путь относительный:

   ```sh
   claude --plugin-dir mods/dex-jira-tracker
   ```

   Из другого места укажите полный путь: `claude --plugin-dir /путь/к/claude-code-marketplace/mods/dex-jira-tracker`. Переменные окружения не нужны (нужен Claude Code 2.1.287 или новее, проверьте: `claude --version`). Работать можно в любой папке: Jira мод читает через jira-cli, а репозиторий нужен только кнопкам «взять в работу» и «сдать».

4. В открывшейся сессии набрать `/jira`. Команда должна появиться в подсказке при наборе; если нет, смотрите «Если не заработало».

5. Что попробовать по порядку. Шаги 1-6 только читают Jira, в ней и в репозитории ничего не меняется:

   | Шаг | Что сделать | Что увидите |
   |---|---|---|
   | 1 | `/jira` | Панель со списком задач проекта и итогом; над полем ввода - строка «Jira KEY · в работе N · открытых N · мои N» |
   | 2 | Отборы «в работе», «мои», «новое» в панели (или `/jira mine`) | Список сужается, итог остаётся по всему набору |
   | 3 | Нажать на ключ задачи (или `/jira SUP-12`) | Детали: статус, исполнитель, описание, последние комментарии |
   | 4 | `/jira comments SUP-12` | Комментарии запишутся в историю этой сессии: так их читает модель |
   | 5 | `/jira tools` | Что подхвачено из каталога (`/feature`, `/implement`, трекеры PR/MR) и чем заменено остальное |
   | 6 | `/jira spec выгрузка отчёта в CSV` | Модель напишет постановку текстом в ответе; в Jira ничего не пишется и код не правится |
   | 7 | Оставить комментарий к своей задаче в браузере и подождать период опроса (или нажать «обновить») | Тост и строка в транскрипте о новом комментарии; задача в списке помечена |
   | 8 | `/jira work SUP-12` на **своей тестовой** задаче | Назначит задачу на вас, переведёт в рабочий статус, заведёт ветку и отдаст реализацию модели. Это записи в Jira и в репозиторий: делайте на задаче, которую не жалко |

   Ждать уведомление два периода опроса необязательно: `pollSeconds` минимум 30 секунд, а кнопка «обновить» опрашивает сразу.

6. Выйти из сессии как обычно (`/exit`). Назначение и статус, выставленные на шаге 8, остаются в Jira; верните их `jira issue assign` и `jira issue move`.

Быстрая проверка без интерактивной сессии (только текст, панели нет, ничего не пишется):

```sh
claude -p "/jira list" --plugin-dir mods/dex-jira-tracker
claude -p "/jira tools" --plugin-dir mods/dex-jira-tracker
claude -p "/jira SUP-12" --plugin-dir mods/dex-jira-tracker
```

### Если не заработало

| Симптом | Причина и что делать |
|---|---|
| `/jira` не предлагается и не работает | Версия Claude Code ниже 2.1.287 (`claude --version`, обновить: `claude update`) либо `--plugin-dir` указан неверно; проверьте: `claude plugin validate mods/dex-jira-tracker` |
| В транскрипте «jira-cli не установлен» | Бинаря нет в `PATH`: `/jira install` (brew) или другой способ из `/jira setup` |
| «jira-cli не вошёл в Jira» | Нет или неверен `JIRA_API_TOKEN`; на Server/DC нужен `JIRA_AUTH_TYPE=bearer` и PAT. Поправьте и вызовите `/jira refresh`: после отказа входа опрос по таймеру остановлен намеренно |
| «jira-cli не настроен» | Нет конфига: выполните `jira init` в терминале |
| Строки над вводом нет, а `/jira` работает | Выключена настройка `band`, либо задач в наблюдении нет (проверьте `/jira scope`, `/jira project`) |
| Список пуст при `scope: sprint` | Нужна доска Scrum с открытым спринтом; на Kanban охват `sprint` пуст |
| «Список обрезан лимитом» | В проекте больше `limit` свежих задач: сузьте охват (`/jira mine`, свой `/jira jql`) |
| «взять в работу» не перевело статус | Статус в вашем workflow называется иначе: задайте `workStatus` (например, `В работе`) |
| Кнопки «постановка» и «взять» отдают встроенное поручение, а не `/feature`, `/implement` | Плагины каталога не установлены или не перечитаны: `/jira tools`, затем `/jira tools install` и `/reload-plugins` |
| Тосты о моих же комментариях | `jira me` называет вас иначе, чем `author.name` в комментариях; см. «Пределы» |

## Установка из каталога

```sh
claude plugin install dex-jira-tracker@dex-claude-marketplace
```

Нужен Claude Code 2.1.287 или новее. Дальше - «Подготовка jira-cli» и `/jira`. Постоянно меняются настройки в `/config`, раздел мода (список - «Настройки»).

## Использование

- **`/jira`** - открыть или закрыть панель. Из деталей задачи ведёт к списку.
- **`/jira list`** - список в панель и в транскрипт: итог и по строке на задачу (ключ, что изменилось, исполнитель, название). **`/jira mine | progress | open | new | done | all`** сужает список.
- **`/jira SUP-12`**, **`/jira 12`**, ссылка на задачу - детали задачи; задача вне наблюдения (другой проект, старая) тоже показывается. **`/jira next`**, **`/jira prev`** - соседняя в списке.
- **`/jira comments [SUP-12]`** - последние комментарии текстом. Всё, что мод показал вам, он умеет отдать и модели, поэтому после `/jira SUP-12` можно просто сказать «разберись с замечанием».
- **`/jira seen [SUP-12 | all]`** - отметить просмотренным. Открытие деталей тоже отмечает.
- **`/jira project KEY`**, **`/jira scope project | mine | sprint | jql`**, **`/jira jql <запрос>`** - что именно наблюдается. Только на эту сессию; постоянный выбор - в `/config`.
- **`/jira spec [SUP-12 | идея]`**, **`/jira publish [SUP-12]`**, **`/jira work [SUP-12]`**, **`/jira ship [SUP-12]`** - рабочий путь, ниже.
- **`/jira pr`** - трекер PR/MR хостинга репозитория (`/pr` или `/mr`), если он установлен.
- **`/jira tools [install [all | роль]]`** - что подхвачено из каталога и чем заменено остальное.
- **`/jira setup`**, **`/jira install`**, **`/jira refresh`**, **`/jira help`**.
- **Кнопки** жмутся мышью либо с клавиатуры: `ctrl+x tab` берёт полосу над вводом в фокус. В списке - отборы и «взять» у каждой задачи, внизу поле для идеи новой задачи; в деталях - вся цепочка кнопок.

## Как читать строку

```
Jira SUP · в работе 45 · открытых 54 · мои 17 · 2 ждут вас · новое: 3        [список] [обновить]
● SUP-1600  назначена на вас  [Back][Front] Вкладка Качество...               [детали]
```

- **в работе** - статусы категории «In Progress», как бы их ни называл ваш workflow; **открытых** - остальные незакрытые; **мои** - назначенные на вас.
- **ждут вас** - ваши задачи, в которых что-то изменилось с тех пор, как вы на них смотрели. **новое** - то же в чужих задачах.
- Под итогом - до двух задач, которые ждут вас. Больше - в списке.

## Откуда мод знает, что изменилось

Опрос идёт по таймеру (`pollSeconds`, по умолчанию две минуты), на конце хода модели и после команды модели, пишущей в Jira (`jira issue move`, `create`, `comment`). За опрос уходят четыре вызова `jira`: сама выборка (до `limit` задач, свежие по обновлению) и три запроса одних ключей - какие задачи не закрыты, какие в работе, какие ваши.

Закрытость определяется **категорией статуса** (`statusCategory`), а не полем `resolution`: workflow может закрывать задачу, не выставляя resolution, - на живой Jira так и оказалось, и по `resolution = Unresolved` закрытые задачи считались открытыми.

Каждый опрос сравнивается с предыдущим:

- состояние и закрытие, переоткрытие;
- исполнитель - отдельно «назначена на вас» и «снята с вас»;
- приоритет, название, описание (описание сравнивается по отпечатку);
- **новая задача** в выборке;
- **новый комментарий**. Список jira-cli комментариев не несёт (`comment.total` в нём всегда 0), поэтому по сдвигу `updated` мод запрашивает задачу и берёт комментарии новее прежнего `updated`. Свои комментарии не объявляются (сверка по логину из `jira me`, на Cloud - по e-mail); комментарий с упоминанием `[~ваш_логин]` объявляется как «упомянул вас».

Первая загрузка ничего не объявляет. Дальше в транскрипт ложится строка (она остаётся в истории), а поверх - тост. Каждое непросмотренное изменение копится в задаче до просмотра.

**Что было, пока сессия закрыта.** Набор сохраняется в store плагина (без текста описаний), и первый опрос новой сессии сравнивается с ним: придёт одна сводка «с прошлой сессии изменились N задач» и несколько примеров. Снимок старше недели не используется - всё читалось бы как изменённое. Каждая смена охвата, проекта или запроса начинается с чистого листа.

Настройка `notify`: `all` (по умолчанию), `important` (создание, статус, закрытие, исполнитель, комментарии - без правок названия, описания и приоритета) и `off`. `notifyMineOnly` оставляет только ваши задачи и те, за которыми вы наблюдаете в Jira; назначение на вас объявляется всегда. Звук (`sound`) по умолчанию выключен.

## Рабочий путь: от идеи до PR

Каждый шаг - отдельная кнопка и отдельная команда; между шагами решаете вы.

| Шаг | Команда | Что происходит |
| --- | --- | --- |
| Постановка | `/jira spec <идея>` или `/jira spec SUP-12` | Модель пишет постановку: контекст и цель, объём, критерии приёмки, ограничения, открытые вопросы. С установленным `dex-business-analyst` - его командой `/feature`, без него - встроенным шаблоном. В Jira ничего не пишется, код не правится. |
| Оформление | `/jira publish [SUP-12]` | Постановка из последнего ответа уходит в Jira: новая задача (`jira issue create --template`, тип из настройки `issueType`) либо существующая. Описание уже непустой задачи не затирается: постановка добавляется комментарием. Каждую команду записи вы видите до запуска. |
| В работу | `/jira work [SUP-12]` | Мод сам назначает задачу на вас и переводит открытую в `workStatus` (две записи, которые называет кнопка; при ошибке он останавливается, не пускаясь в работу над чужой задачей). Затем отдаёт реализацию: с установленным `dex-implement` - командой `/implement` с ТЗ из задачи, базой и именем ветки, без него - встроенным порядком (ветка, малые правки с проверкой, тесты, коммиты с ключом). Перед началом проверка чистоты рабочей копии; push не делается. |
| Сдача | `/jira ship [SUP-12]` | Прогон проверок, `git push` только этой ветки без `--force`, `gh pr create` либо `glab mr create` (хостинг по remote), ссылка на PR/MR комментарием в задачу, при заданном `reviewStatus` - перевод статуса. Merge не делается. |
| После сдачи | `/jira pr` | Если установлен трекер хостинга (`dex-github-pr-tracker` или `dex-gitlab-mr-tracker`), PR/MR берётся им под наблюдение сам по ссылке из вывода `gh pr create` / `glab mr create`; `/jira pr` открывает его панель. |

Имя ветки собирается из настройки `branchPattern` (по умолчанию `{type}/{key}-{slug}`): `fix` для багов и `feature` для остального, ключ задачи и название латиницей - `fix/SUP-12-padaet-vygruzka-zakazov`.

### Что подхвачено из каталога

`/jira tools` перечисляет роли и то, что их исполняет:

| Роль | Команда | Плагин | Без плагина |
| --- | --- | --- | --- |
| постановка | `/feature` | `dex-business-analyst` | встроенный шаблон постановки |
| реализация | `/implement` (`implementCommand`) | `dex-implement` | встроенное поручение |
| саморевью | `/self-review` | `dex-self-reviewer` | проверки проекта остаются в поручении |
| ревью чужого PR/MR | `/mr-review` (`reviewCommand`) | `dex-mr-reviewer` | без ревью из мода |
| слежение за PR (GitHub) | `/pr` | `dex-github-pr-tracker` | ссылка в транскрипт |
| слежение за MR (GitLab) | `/mr` | `dex-gitlab-mr-tracker` | ссылка в транскрипт |

Список перечитывается при каждой передаче работы: поставили плагин - следующая кнопка уже его использует. `/jira tools install [all | роль]` ставит недостающее командой `claude plugin install <плагин>@dex-claude-marketplace`, только по этой команде; команды в текущей сессии появятся после перечитывания плагинов. Каждая передача работы пишет в транскрипт строку: что использовано и, если нужного плагина нет, как его поставить.

## Настройки

Правятся через `/config`, раздел мода.

| Поле | По умолчанию | Смысл |
| --- | --- | --- |
| `project` | пусто | ключ проекта; пусто - проект из конфига jira-cli |
| `scope` | `project` | `project` - весь проект; `mine` - только ваши; `sprint` - открытые спринты (доска Scrum); `jql` - свой запрос |
| `jql` | пусто | запрос для охвата `jql`, без `ORDER BY`: jira-cli дописывает свой |
| `pollSeconds` | `120` | период опроса, не меньше 30 секунд |
| `limit` | `100` | сколько задач держит наблюдение (свежие по обновлению); потолок jira-cli - 100 |
| `doneDays` | `1` | сколько дней закрытая задача остаётся в списке; 0 - уходит сразу и её закрытие не объявляется |
| `notify`, `notifyMineOnly`, `sound` | `all`, `false`, `false` | что и о чём объявлять |
| `band` | `true` | рисовать строку над вводом; выключено - остаётся панель |
| `workStatus` | `In Progress` | статус для кнопки «взять в работу»; назван по workflow вашей Jira (`В работе`); пусто - статус не трогать |
| `workAssign` | `true` | кнопка «взять в работу» назначает задачу на вас |
| `branchPattern` | `{type}/{key}-{slug}` | имя ветки |
| `baseBranch` | пусто | база для ветки и PR/MR; пусто - основная ветка репозитория по `origin` |
| `reviewStatus` | пусто | статус после открытия PR/MR (`In Review`); пусто - не менять |
| `issueType` | `Task` | тип новой задачи при оформлении |
| `hosting` | `auto` | `github` / `gitlab`, если по имени хоста remote не видно |
| `implementCommand`, `reviewCommand` | `implement`, `mr-review` | команды сессии, которым мод отдаёт реализацию и ревью |

## Пределы

- Источник данных один - jira-cli. Своего REST-клиента у мода нет: токен остаётся там, где его хранит `jira`. Из этого следует всё остальное: версии Jira, которые jira-cli не тянет, мод не тянет тоже.
- Опрос - четыре вызова `jira` за период плюс по вызову на каждую задачу, у которой сдвинулся `updated` (не больше шести за опрос, по три разом). Большой проект с шумным потоком правок читает комментарии не мгновенно.
- Выборка - до `limit` самых свежих по обновлению задач. Задача, которую давно не трогали, в наблюдение не попадёт, пока ей не напишут; в списке при обрезке об этом сказано.
- Закрытие, случившееся, пока сессия была закрыта дольше `doneDays`, не объявляется: задача уже ушла из выборки.
- Отказ входа (401/403, «API token») останавливает опрос по таймеру до `/jira refresh`: Jira Server на череду неверных входов отвечает CAPTCHA, а затем блокировкой.
- Свои комментарии узнаются по логину из `jira me` (Server) либо e-mail (Cloud). Если `jira me` называет вас иначе, чем `author.name` в комментариях, свои комментарии будут объявляться.
- Название статуса для «взять в работу» мод не угадывает: workflow у всех свои. Отказ Jira называется в ответе вместе с подсказкой про `workStatus`.
- Кнопки «взять в работу» и «сдать» мод не пытается откатывать. Назначение и перевод статуса остаются в Jira, даже если реализация потом остановлена; `jira issue assign` и `jira issue move` вернут как было.
- Передача работы модели идёт не из самой команды, а сразу за ней: движок (проверено на 2.1.309) не принимает отправку промпта изнутри хука команды, пока ход ждёт ответа хука, поэтому мод отправляет её таймером после ответа. И промпт, начинающийся с «/», движок отклоняет: команды каталога (`/feature`, `/implement`) мод запускает как команды (`$.command.run`), а не как набранный текст.
- Панель и строка рисуются только в интерактивной сессии; в `-p` работают команды, а опрос по таймеру не запускается. Поле для идеи в списке есть на терминале и в десктопе; на телефоне - `/jira spec <идея>`.
- Мод пишет в Jira сам только назначение и перевод статуса по кнопке «взять в работу». Остальные записи (создание, описание, комментарии, статус после PR) делает модель командами `jira`, которые вы видите и подтверждаете в обычном порядке разрешений.

## Разработка

```sh
npm run typecheck:mods                              # tsc по mods/ (входит в npm run validate)
npm run test:mods                                   # прогон чистой половины
claude plugin validate --strict mods/dex-jira-tracker   # манифест, перечень хуков и вызовов $
claude -p "/jira list" --plugin-dir mods/dex-jira-tracker
```

Проводку хуков в самом движке (опрос на подменённом `jira`, полоса и список на четырёх поверхностях, нажатие кнопок, ограничения на отправку промптов) проверяет `claude plugin test` - набор `claude-code/testing`; в CI клиента нет, поэтому этот прогон ручной (👁), а `npm run test:mods` берёт чистую половину.

Последняя команда - живой прогон без установки: она проходит весь путь от jira-cli до текста и печатает список.

Формы вывода jira-cli сняты с jira-cli 1.7.0 на Jira Server 9.2. `issue list --raw` - собственная плоская структура jira-cli (`issueType`, `assignee.displayName` и ничего больше о человеке, `comment.total` всегда 0), `issue view --raw` - тело REST. Если у вашей версии формы иные, разбор в `hooks/jira.ts` и фикстуры в `tests/jira.test.ts` - то, что надо править.

Относительные импорты внутри мода идут **с расширением `.ts`**, решения живут в `.ts` без `$`, а `.tsx` держит только отрисовку и точку входа. Контракт типов - `mods/types/claude-code.d.ts`, пишется командой `/plugin-types` и руками не правится. Устройство класса, инструментарий и self-check - [MOD_FRAMEWORK.md](https://github.com/dex-it/claude-code-marketplace/blob/main/docs/MOD_FRAMEWORK.md).
