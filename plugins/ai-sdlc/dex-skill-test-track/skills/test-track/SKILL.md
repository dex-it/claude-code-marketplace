# Test Track

Цель = закрыть матрицу покрытия по приоритету, не прогон ради галочки.

Оператору вопросов не адресует: матрица покрытия и её приоритизация - технический выбор трека, не
развилка, которую стоило бы спрашивать - `mode` нечему переключать.

## Матрица покрытия

Оси покрытия - общий якорь движка `dex-sdlc:engine` [[P-test-axes]] (happy-path / негатив /
краевые / все ветки логики), не своя система координат этого трека. Приоритизация и порядок
закрытия - решение трека: покрыл подмножество - скажи, что отрезал, без тихого усечения.
Саморевью: изоляция, не тавтология, антипаттерны.

## Покрытие требований: обратное ребро

Матрица закрывает оси случаев и не отвечает на другой вопрос - какое требование не проверяется ни
одним тестом. Второе измерение ведётся явно: по каждому `FR-NNN`/`NFR-NNN`, `AC` истории и `INV-NNN`
конституции назван тест (файл + имя теста), который его проверяет. Требование без теста получает
исход, а не молчание: покрыто на другом уровне (назвать, каком) | автотестом не проверяемо (причина;
на стенде его закрывает `dex-skill-acceptance-track:acceptance-track`) | разрыв покрытия -> добор
этим треком. Прямое ребро (тест -> требование) вопроса не закрывает: оно называет проверенное, а
ищем непроверенное.

**Множество требований берётся из корпуса на диске, не из пересказа во входе** (`node-contract`,
`references/quality-and-review.md` п.7): расположение корпуса приходит сквозным полем, не пришло ->
`dex-skill-project-docs-map:project-docs-map`. Читаются сценарии `UC` с расширениями и исходом каждой
ветки (оттуда негативные и краевые случаи), `FR`/`NFR` с методом проверки, истории с `AC`,
`non-goals` фичи (что тестировать не надо), `INV-NNN` и применимые `NFR-P-NNN` уровня 0. Пришло три
`AC` из двенадцати - ребро, построенное по входу, закроется «полностью» на неполном множестве, и
неполнота ненаблюдаема. Корпус недостижим (адреса нет И поиск пуст) -> ребро строится от success
criteria работы и объявляется статусом `requirements-coverage: unverifiable` с местом поиска.

Процент покрытия за это измерение не считается - он меряет строки кода, а не требования: файл с
90% строк и ни одним тестом на `FR-007` порог берёт, требование остаётся непроверенным. Порог по
коду держит `dex-skill-test-coverage:test-coverage`, оси - якорь движка, требования - этот раздел;
три меры не заменяют друг друга.

Требований нет ни в корпусе, ни во входе (работа без формальной постановки) -> ребро строится от
success criteria работы; нет и их -> назови это в выходе, ребро не подменяется перечнем написанных
тестов.

## Граница доверия к тесту

Мок внешней границы, точка входа до теста, развилки путей - держит
`dex-skill-integration-boundary:integration-boundary`, грузит его исполняющий тесты узел, не
трек.
