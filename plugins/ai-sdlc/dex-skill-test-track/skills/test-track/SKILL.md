# Test Track

Цель = закрыть матрицу покрытия по приоритету, не прогон ради галочки.

Оператору вопросов не адресует: матрица покрытия и её приоритизация - технический выбор трека, не
развилка, которую стоило бы спрашивать - `mode` нечему переключать.

## Матрица покрытия

Оси, не одна (happy-path не матрица):

| Ось | Что закрывает |
|---|---|
| happy-path | основной сценарий |
| негатив | невалидный ввод/ошибки/исключения дают ожидаемый исход, не happy молча |
| краевые | границы значений, пусто/предел/overflow, конкурентность если применима |
| все ветки логики | каждая ветвь/провайдер/fallback/retry прогнана, не только основная |

Покрыл подмножество - скажи, что отрезал (без тихого усечения), приоритизируй осознанно. Саморевью:
изоляция, не тавтология, антипаттерны.

Оси одни и те же во всех треках, где заходит речь о достаточности тестов (Development Track,
Followup Track, MR Review Track); свою систему координат под задачу не заводи.
