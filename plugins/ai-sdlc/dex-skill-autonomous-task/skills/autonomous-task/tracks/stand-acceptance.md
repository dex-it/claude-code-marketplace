# Трек «Приёмка слитой фичи на стенде» - дельта сверх таблицы

> Дополнение к строке «Приёмка слитой фичи на стенде» таблицы треков в `SKILL.md`. Ядро читает
> этот файл, определив трек (mandatory-Read из шага 1) - до плана. Якоря `P-fact`/`P-recon`/
> `P-root` - в `SKILL.md`.

*Объект - развёрнутый стенд, не исходник и не diff; цель = доказать, что слитая фича работает
против ТЗ.* Вход - **ТЗ/критерии приёмки** + **ветка/стенд**, где фича развёрнута. Фича уже в
основной ветке; приёмка идёт **после** мерджа.

**Зелёный деплой - не доказательство.** Pod `Running`, health 200, чистый merge, «пайплайн
зелёный» доказывают, что *код выкатился*, не что *фича работает*. Каждое требование ТЗ
закрывается **пробой на стенде** (запрос, сценарий, наблюдаемый эффект), не передеплоем и не
чтением кода.

**Граница с соседями.** «Ревью входящего MR» смотрит diff **до** мерджа; здесь - поведение
**после**. «Диагностика/инцидент» идёт **от симптома** к первопричине; здесь идём **от
требования** к пробе - поломка может и не всплыть. Правку кода этот трек **не делает**:
найденные дефекты уходят в ремедиацию (ниже).

## Конвейер

1. **Привязка образа к коду.** Что реально крутится на стенде: образ/тег -> **merge-коммит**,
   из которого собран (sha назван). Без привязки приёмка проверяет неизвестно что.
   **Образ не содержит merge-коммита фичи** (старее) -> приёмка невозможна: **выкат этот трек
   не делает** (read-only, стенд не мутируем) - верни наверх статусом `blocked` с указанием,
   какой образ на стенде и какой sha нужен. Не «примем на том, что есть» и не выкатывай сам.
2. **Требование -> проба.** Каждое требование ТЗ (`FR-NNN`/`NFR-NNN`, если пришли из BRD -
   корпус требований проекта, его расположение даёт `dex-skill-project-docs-map`; породила
   их зона 1, `/feature`) получает **пробу на стенде**: что дёрнуть, что ожидаем наблюдать.
   Требование без пробы = непроверенное, не «очевидно работает».
3. **Прогон проб.** Каждое утверждение о поведении опирается на **наблюдение**: команда+вывод,
   id лога/трейса, метрика, скриншот. Выдуманный ответ стенда запрещён; недоступный источник -
   явный статус «недоступен» с указанием какого, не молчание ([[P-fact]]).
   Read-only: стенд общий - **не мутируй** (не перезапускай, не правь конфиг, не чисти БД).
   Нужен мутирующий шаг для проверки -> это стоп-линия костяка (`SKILL.md`), выноси
   предложением, не выполняй.
4. **Регрессия соседей.** Слитая фича могла задеть то, что рядом (общие эндпоинты, шина,
   схема). Проба не только на новое поведение, но и на **соседний путь**, который фича трогала.
5. **Фальсификация находок.** Находка на стенде - гипотеза ([[P-recon]]): «упало» может быть
   тестовыми данными, чужим стендом, устаревшим образом, правами. Опровергни, прежде чем
   заводить: воспроизведи, сверь с кодом merge-коммита, исключи окружение.
6. **Ремедиация.** Подтверждённые дефекты -> **follow-up ветка**, **не правка общей ветки**.
   Пачку багов чинит `bug-fixer` (тип узла - пакетная ремедиация; лечит **корень**, [[P-root]]),
   но он **заканчивается на локальных коммитах** - push, саморевью и MR остаются на тебе (сдача
   костяка, шаг 8). Довести до конца: MR влит -> фикс выкачен на стенд -> **повторная проба там
   же, где баг найден**. «Тесты зелёные» и «MR влит» приёмкой не считаются - фикс, не
   проверенный на стенде, не проверен.
   Дефектов нет - трек закрывается приёмкой.

## Верификация трека («готово»)

1. **Образ привязан** к merge-коммиту фичи (sha назван).
2. **Каждое требование ТЗ** имеет исход: проба прошла (с наблюдением) / проба провалилась
   (дефект заведён) / **не проверяемо на стенде** с явной причиной. Требование без исхода =
   приёмка не закрыта; «остальное вроде работает» - не исход.
3. **Каждый дефект** доведён: follow-up MR влит **и** повторная проба на стенде зелёная.
   Отложенный дефект - заведённая задача + строка в блок сдачи, не молчание.
4. Отчёт-приёмка: требование -> проба -> наблюдение -> вердикт.

## Саморевью трека

Не принят ли зелёный деплой за работающую фичу; привязан ли образ к merge-коммиту (а не
«наверное, свежий»); есть ли наблюдение под каждым утверждением (или явный «недоступен»); не
выдуман ли вывод стенда; фальсифицирована ли каждая находка (окружение/данные/права исключены);
верифицирован ли фикс **на стенде**, а не только тестами; не мутировал ли общий стенд.
