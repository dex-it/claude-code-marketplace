# /review-plan

Провести полученное на свой MR/PR ревью через `dex-skill-followup-track:followup-track`: от сбора
ревизии до правок и ре-ревью дельты. Не только план - код правится узлами трека, ответы публикуются.

## Goal

Провести ревизию через универсальный цикл движка и фазы трека: сбор комментариев ревизии (полный
контекст, не выборка), классификация (actionable / clarify / disputed) и верификация чтением кода
до снятия находки, план правок P0..P3 с blast radius, правки исполняющими узлами, публикация
ответов в треды, ре-ревью дельты `mr-check-reviewer` до закрытия ревизии. Ревизия ограничена 5 циклами;
каждая находка на выходе несёт явный исход (fixed / disputed / clarify / not-in-scope), не молчание.

## Input

Аргумент - ссылка на MR/PR или short-id. Опционально REVIEW_SHA, если sha момента ревью не
выводится из истории комментариев.

## Output

- Контекст ревизии: сколько комментариев по приоритетам, менялась ли задача, что докоммичено
- План правок P0..P3 с файлами, blast radius и риском регрессии
- Правки по плану (коммиты), вопросы к ревьюеру (clarify), снятые замечания (disputed) с основанием
- Опубликованные reply в треды с sha фикса, resolve только после подтверждённого фикса
- Ре-ревью дельты `mr-check-reviewer`: статус по каждой находке прошлой ревизии

## Constraints

- Неоднозначный комментарий идёт в clarify, не трактуется за ревьюера
- Гейт scope - ничего сверх замечаний; соседний баг вне ревью - в наблюдения, не в план и не в правку
- Конфликт с базовой веткой - `dex-conflict-resolver:conflict-resolver`, не разрешается на глаз
- До команды `отвечай` ни одной записи в MR; resolve только после reply и подтверждённого фикса
- Ревизия не закрывается без ре-ревью дельты; 5 циклов - потолок, дальше эскалация оператору

Вызови `Skill` -> `dex-sdlc:engine` (откроет/возобновит цикл, авто-ledger с треком
`dex-skill-followup-track:followup-track`), затем `Skill` -> `dex-skill-followup-track:followup-track`
с **`mode: interactive`** - без этого поля трек берёт автономную планку (`autonomous`) и цикла
команд (`делай`/`отвечай`) не будет: канал у тела команды есть, спрашивать по нему трек будет
только с этим полем.
