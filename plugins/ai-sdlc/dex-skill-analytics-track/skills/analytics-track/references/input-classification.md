# Классификация входа: шесть значений и что каждое меняет в прогоне

Дом обязательства - `SKILL.md`, Phase 1: классификация обязательна, стоит ровно одним из шести
значений и несёт основание; «непонятно» не допускается. Здесь развёрнуто каждое значение - признак,
по которому вход к нему относят, и что оно меняет в дальнейших фазах.

- **сырая тема** - названа область без разобранных нужд, целей, акторов -> Phase 2 целиком;
- **проработанная идея** - нужды, цели и границы сформулированы -> Phase 2 без шторма;
- **чужой готовый документ** - разбирается на единицы по классам прогоном, а не переписывается
  механически в свои шаблоны: переписанный текст не отличить от дописанного, и вопрос «откуда
  взялось требование» перестаёт отвечаться. Входная приёмка по `node-contract` раздел C: метка
  `verdict: passed` есть -> оракулы не дублировать; нет -> прогнать самому;
- **правка принятого** - правка единицы либо изменение внешнего основания, на которое единицы
  сослались, -> Phase 2-5 не выполняются целиком, работа идёт дельтой (раздел ниже);
- **реализованное без постановки** - поведение уже в коде, требования оформляются по факту (свой
  свежий код либо чужое легаси). Материал - наблюдаемое поведение, чтение исходников этим входом
  составителям разрешено; охват - **область работы и контракты её границ**, внутренности соседних
  областей не разбираются: иначе первая же фича в ядре тянет проект целиком. Черновая формулировка
  автора пришла -> сверяется с наблюдаемым, разошлись -> в корпус идёт итоговое поведение, прежняя
  формулировка с причиной смены - строкой в `decision-log`; не пришла -> сверки не было, названо
  строкой выхода. Два сопоставимых прочтения поведения (замысел либо дефект) - **вопрос** (форма по
  разделу 1 схемы), не допущение: код принятой единицей не является и основанием служить не может
  (`R-3`). Терминал в `autonomous`: пункты остаются открытыми, единицы на них не строятся, набор -
  `status: partial` с их перечнем. До подтверждения единица несёт указание, из чего выведена (место
  в коде); подтверждённая от прочих не отличается - постоянного атрибута происхождения корпус не ведёт;
- **не единица конвейера требований** - работа, из которой не выводится ни одного `FR` и ни одного
  `NFR`: рефакторинг, обновление зависимостей, чистка мёртвого кода, перенос кода между модулями без
  изменения наблюдаемого поведения. Исход - `status: blocked` с названным основанием: что именно из
  входа не выводится и почему. **`BR` ради прохождения конвейера не сочиняется**, гейт покрытия по
  такой работе не заводится (раздел 7 схемы). Вход смешанный - фичевая часть разбирается, остальная
  называется отдельной строкой и в набор не идёт.
