# Ключ прогона: как определяется и как ищется совпадение с корпусом

Дом обязательства - `SKILL.md`, «Ключ прогона»: ключ определяется в Bootstrap на каждом прогоне,
совпадение фиксируется по корпусу, а не по новой формулировке темы. Здесь развёрнут алгоритм -
источники ключа по приоритету, построение слага, поиск среди заведённых фич и ветки исхода по режиму.

**Ключ прогона - имя фичи, и определяется в Bootstrap заново на каждом прогоне** - постоянного
журнала между прогонами трек не ведёт, продолжение читается из корпуса. Вход несёт папку фичи или
явный ключ - берётся он. Иначе слаг строится из темы (нижний регистр, буквы, цифры и дефис,
остальное в дефис) и ищется среди фич корпуса - по каталогам и артефактам, уже заведённым (слаг
несёт сама раскладка - дефолт `<NN>-<слаг>`, `dex-skill-artifact-naming:artifact-naming`; на чужой
раскладке слаг ищется в шапках артефактов): точное совпадение - продолжение прогона; совпадения
нет, но есть похожие - предъявляются оператору вопросом «продолжаем эту или заводим новую»; пусто -
фича новая. В `autonomous` вопроса нет: трек решает сам и пишет строку в список принятых за
оператора решений. **Совпадение фиксируется по корпусу, а не по новой формулировке темы**: слаг уже
принятой фичи берётся из найденного пути и не подменяется слагом, выведенным заново из новой фразы -
две формулировки одной темы иначе заводят два набора артефактов под одну фичу.
