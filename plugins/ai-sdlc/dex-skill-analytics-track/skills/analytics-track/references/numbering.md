# Номера единиц и счётчик `.req_counter`

Дом обязательства - `SKILL.md`, шапка; здесь механика.

**Разрядность.** Старший разряд выводится из номера фичи: фича `01` нумерует с тысячи. Младший
каждый составитель берёт сам - **инкрементом файла своего ключа в `.req_counter`** (ключ
`NN.<КЛАСС>`), а не по памяти прогона: прочитал, увеличил, записал тем же действием, каким завёл
единицу.

**Стартовых отрезков не раздавай:** `FR` и `NFR` живут в разных пространствах номеров, а внутри
класса пишет один узел - отсюда двух составителей одного класса параллельно не спавнить.

**Дырки не переиспользуются:** ссылка на снятый номер иначе завтра укажет на другое требование.

**Блок исчерпан** -> `feature` увеличивается, фича получает второй блок целиком, не соседний
занятый. Вторым слоем работает корпус - даже с потерянным счётчиком занятый номер виден в
требованиях, и оттуда файл ключа восстанавливается.

**Где счётчик.** Директория `.req_counter` при корпусе, файл ключа `feature`. Путь к нему не
разрешай процедурой расположения - **читай ключ `counter` из `.docs_layout`** в корне репозитория;
как искать, если файла нет, и что делать при расхождении с корпусом -
`dex-skill-project-docs-map:project-docs-map` (п.5). Счётчик один на корпус, а не на репозиторий:
реп у продукта бывает много, а блок номеров у фичи один.

**Счётчика нет** (конвейер пришёл на занятый проект впервые) - собери его один раз сплошным
проходом: максимальные номера, уже стоящие в единицах корпуса, по классам и блокам; считать по
номерам единиц, а не по папкам `features/` - на чужой раскладке таких папок нет вовсе. Дальше живут
файлы ключей, и пересчёта по корпусу больше не делается; путь заведённого счётчика запиши в
`.docs_layout`.

**Фича снята решением человека** - `feature` назад не откручивай; блок остаётся дыркой и следующей
фиче не достаётся.

**Файл недостижим при записанном пути** -> `status: blocked`. Это не `unverifiable`, при котором
работа идёт с пометкой: выданный вслепую номер молча столкнёт два набора единиц в одном блоке.

**Конфликт в `.req_counter` при слиянии** - не текст, а факт: номер выдан дважды. Выбором стороны не
закрывай - максимум значения, перенумерация входящей стороны, правка ссылок на неё (трасса, `AC`,
записи гейтов, `decision-log`), проверка «двух единиц с одним номером в корпусе нет»; порядок -
`project-docs-map` (п.6).
