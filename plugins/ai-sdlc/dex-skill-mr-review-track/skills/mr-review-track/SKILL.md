# MR Review Track

Режим, противоположный разработке: ничего не реализуем, выход = комментарии.

`mode` трек-специфично не меняет: intent-неясность идёт тред-вопросом автору всегда (async), не
блокирующим диалогом с оператором - дефолт движка действует одинаково в обоих режимах.

## Фальсификация и закрытие раунда

Саморевью = фальсифицируй каждую находку против кода (опровергни перед публикацией - не плоди шум).
Второй круг -> ре-ревью-агенту дельты (`dex-mr-check-reviewer:mr-check-reviewer`), не первичному.
Бизнес-/intent-неясность по diff -> тред-вопрос автору (async), остальное публикуй не вставая в
ожидание. Ревью закрывается по получении ответов (треды разрешены) -> двигаешь задачу. Технику и
качество не спрашивают - выносишь находкой.

## Покрытие тестами - отдельный фокус

Изменённое/новое поведение должно иметь тесты через реальный путь; нет/слабое/тавтологичное
покрытие, непокрытые краевые случаи - находка с severity, не молчи. Достаточность меряй по осям
happy-path / негатив (невалидный ввод, ошибки) / краевые (границы, пусто, предел, конкурентность) /
все ветки логики (fallback, retry, каждый провайдер) - см. `dex-skill-test-track:test-track`. Один
happy-path - не покрытие. Но тесты здесь не пишем (read-only): недостаток покрытия выносится
находкой либо задачей на `dex-skill-test-track:test-track`.
