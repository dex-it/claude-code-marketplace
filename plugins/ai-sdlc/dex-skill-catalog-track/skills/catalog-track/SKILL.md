# Catalog Track

Трек ведёт правку **артефакта-инструкции** - текста, который исполняет модель, а не компилятор:
skill, агент, команда, бандл, манифест плагина, нормативное правило репозитория. Вызывается движком
`dex-sdlc:engine` и отдельно от него не запускается: движок ведёт цикл и стоп-линию, трек - порядок
этой зоны. Работа заканчивается локальными коммитами: push, MR и мердж трек не делает.

**Отличие зоны от разработки - чем проверяется «работает».** У исходника есть сборка и тесты; у
инструкции их нет. Валидатор репозитория судит **форму** файла (поля, размер, ссылки), а предмет
правки - **поведение исполнителя**, и молча деградирует именно оно. Отсюда два следствия, которыми
трек и отличается: правка, меняющая поведение, закрывается **прогоном**, а не зелёным валидатором
(Phase 6); и норма живёт **ровно в одном доме** (Phase 2) - у текста нет линковщика, который поймал
бы разъехавшиеся копии.

**Проектно-нейтрален.** Состав валидаторов, команда гейта, конвенция версий, носители витрины -
**берутся из правил репозитория, в котором идёт работа** (его `CLAUDE.md`, его path-scoped правила,
его `package.json`), не зашиты здесь. Правил нет - выясняются по репозиторию и называются
допущением, а не выдумываются.

**Режим и ярус.** Режим совпадает с ярусом: трек грузится в тело исполнителя, `interactive` в фазах
ниже адресует возврат оператору. Вниз, в делегированные узлы, тем же значением едет планка
эскалации, канал не едет (`dex-skill-node-contract:node-contract`, D.11).

**Исполнителя правки выбирает трек** по критерию движка («Как выбрать исполнителя»): правка понятна
и локализована - трек пишет сам, через явно поднятый профильный скилл; сквозная по многим носителям,
или требует независимого взгляда - узел. Каждое решение «сам» - строка журнала `channel: self` с
причиной и именем поднятого скилла; без строки решение не принято.

## Phase 0: Repository Norms

Goal: поднять нормы репозитория раньше первой правки - его конвенции сильнее любой общей привычки.
Output: подняты `CLAUDE.md` репозитория и его path-scoped правила, покрывающие тронутые пути;
названы фреймворк типа артефакта (skill / агент / команда), команда гейта и состав валидаторов.
Exit criteria: каждая норма названа с адресом носителя, не «обычно так делают»; норма, которой в
репозитории нет, называется отсутствующей явно - её не заменяет общее правило по памяти.

Mandatory: yes

## Phase 1: Intake & Artifact Type

Goal: понять, что правится и ради чего.

**Input (handoff):** контракт стыка - `dex-skill-node-contract:node-contract`. `[blocking]` предмет
правки в любой форме: находка ревью, запрос оператора, дефект артефакта, новая норма. Предмета нет
вовсе -> halt + возврат вызывающему. `[default-ok]` `mode` (дефолт `autonomous`), путь к артефакту
(не пришёл - ищется по имени), тип артефакта (не пришёл - определяется здесь).

Output: тип артефакта назван (skill trap / skill process / агент / команда / бандл / манифест /
правило), назван **класс правки** - новая норма, снятие дефекта формулировки, дедуп, перенос дома,
удаление; названа цель, которой правка служит.
Exit criteria: тип и класс названы; цель правки сформулирована наблюдаемо - что исполнитель начнёт
или перестанет делать после неё. «Стало лучше» целью не является.

Mandatory: yes

## Phase 2: Home Inventory

Goal: найти **все** носители того факта, который правится, до того как он будет записан ещё раз.

Output: перечень мест, где факт уже записан (тело артефакта, его `references/`, соседний артефакт,
правило репозитория, витрина); назван **дом** - единственный носитель, где норма живёт полностью;
для каждого остального носителя решён исход: указатель на дом, или рез, или он и есть дом.
Поиск ведётся по формулировке и по имени сущности сразу - одна и та же норма живёт под разными
словами, и поиск по одному слову её половину не находит.

**Имя сущности берётся из словаря репозитория**, а не изобретается: термина нет - строка заводится
**этим же изменением**, не следующим. Имя, помеченное к вытеснению, в новом тексте - дефект.
Словаря в репозитории нет - имя называется допущением с формулировкой, из которой выведено.

Exit criteria: дом назван и он один; по каждому найденному дублю назван исход; ни один носитель не
остался с частичной копией нормы - частичная копия расходится молча и хуже полной.

Mandatory: yes

## Phase 3: Formulate

Goal: написать формулировку, которая читается одним способом и не даёт легально пропустить шаг.

Output: текст правки, прошедший четыре проверки:
- **однозначность** - «может ли добросовестный исполнитель прочитать это так, что правило к его
  случаю не относится или противоречит соседней единице?»; да -> переписать или развести область
  применения явным условием;
- **терминал ветки** - у каждого «если X» есть «иначе»; у шага с проверкой назван исход провала
  (откат, возврат наверх, статус); уход от проверки фиксируется **статусом с обоснованием**, не
  молчанием;
- **механизм вместо ярлыка** - названо, что именно ломается, а не как это называется;
- **обобщённость** - имена конкретного продукта, репозитория и его сущностей убраны: «убери имена
  проекта - правило всё ещё читается и применяется?».

Exit criteria: все четыре проверки пройдены с названным исходом по каждой; правка, вводящая
обязательный шаг, несёт **след в выходе** - продукт шага, по которому его пропуск виден. Шаг без
следа пропускают молча, и безупречность формулировки этого не меняет.

Mandatory: yes

## Phase 4: Edit Plan

Goal: разложить правку по носителям в порядке, не оставляющем корпус в противоречивом состоянии.
Output: P1..Pn - носитель, суть правки, критерий готовности шага; порядок таков, что дом заводится
раньше указателей на него, а имя - раньше первого употребления.
Exit criteria: каждый Pi проверяем отдельно; ни между какими двумя шагами корпус не остаётся с
нормой в двух домах или с указателем в пустоту.

Mandatory: yes

## Phase 5: Apply

Goal: внести правку по плану.
Output: изменённые файлы; на каждый Pi - исполнитель по критерию из шапки, и при `channel: self`
строка журнала с причиной и именем поднятого скилла.
Пунктуация артефакта - по конвенции репозитория; тронул файл - приводишь его к ней целиком, не
только свои строки.
Exit criteria: все Pi закрыты либо явно отложены со статусом и причиной; ни один носитель не
остался с текстом, противоречащим дому.

Mandatory: yes

## Phase 6: Behaviour Run

Goal: проверить, что правка меняет **поведение исполнителя** в нужную сторону, а не только текст.

Вызови `Skill` -> `dex-skill-optimize-for-llm:optimize-for-llm` и прогони по нему изменённый текст:
подача сухая, повторы срезаны, нормативная сила и статусы ухода от проверки не тронуты.

**Правка правила, влияющего на поведение, закрывается прогоном кейсов**, если репозиторий их ведёт:
прогоняются кейсы, покрывающие тронутое правило, плюс кейс на обратный исход (правильное поведение -
**не** применить правило) - он ловит перекос в сторону дельты. Исход - строкой в реестр прогонов
репозитория: что прогнано, что вышло, какие находки. Правило тронуто, а кейса под него нет - кейс
заводится этой же правкой.

Output: результат прогона оптимизации; результат прогона кейсов либо явный исход `n/a` с причиной
(репозиторий кейсов не ведёт) или `unverifiable` (прогон инструментарно невозможен - названо, какие
кейсы не прогнаны и почему).
Exit criteria: оптимизация прогнана; по кейсам назван исход - прогнаны, `n/a` или `unverifiable`.
Молчание здесь читается как «правка не сдана», а не как «прогон не нужен».

Mandatory: yes

## Phase 7: Sync & Version

Goal: свести все носители, которые правка сдвинула, - они расходятся молча и валидатором видны не
все.
Output: версия артефакта поднята по конвенции репозитория во **всех** носителях, где она записана;
запись в каталоге приведена в соответствие (генератором, если он есть, - не руками); витрина
называет заведённый или переименованный артефакт; бандл, везущий изменённый компонент, замкнут по
артефактам, которые тот называет полной формой; переименование - проверено на потребителей старого
имени во всём репозитории.
Exit criteria: по каждому носителю из перечня назван исход - синхронизирован или неприменим с
причиной; ни одно имя, которое правка ввела или переименовала, не осталось без потребителей,
сведённых с ним.

Mandatory: yes

## Phase 8: Gate

Goal: прогнать гейт репозитория и не сдавать работу на молчании инструмента.
Output: прогон валидаторов и тестов, объявленных Phase 0, - **фактический**, с приведённым
результатом; предупреждения разобраны поимённо: снято или принято с причиной.
**Числа порогов не переписываются в артефакт** - размер судится прогоном: сработало правило, порог
назван в его сообщении; промолчало - носитель в пределах.
Exit criteria: гейт зелёный либо каждый незакрытый пункт назван в выходе со статусом; провал гейта
порог сам не понижает и артефакт под фактический результат не переписывает.

Mandatory: yes

## Саморевью зоны

Шаг 7 движка «Саморевью» для этой зоны.

**Момент запуска - по режиму** (шаг 7 движка): `autonomous` - сразу после Phase 8; `interactive` -
после подтверждения оператором, что правки завершены, до него прогон не запускается. Подтверждения
нет - трек ждёт, шаг не снимается: `complete` без исполненного саморевью не выдаётся.

**Оси ревью артефакта - не свои.** Вызови `Skill` -> `dex-skill-artifact-review:artifact-review` и
пройди правку по его осям: он нормативный дом ревью skill, агента и команды, и generic-ревью его не
заменяет. Метку `quality-checks` по итогу не ставь - автор правки здесь ты; результат идёт в
`self-check` выхода. Скилл не загрузился -> строка «саморевью без `artifact-review`» +
`unverifiable` с причиной, и фазу это не закрывает: перечисленные ниже классы проверяются своими
силами.

Сверх осей скилла - четыре класса, специфичные для правки нормы, каждый со своим исходом: не
потеряла ли правка нормативную силу при сжатии (обязанность, уехавшая в условную ветку, читается как
необязательная); не осталось ли двух домов у одной нормы; закрыт ли терминал у каждой введённой
ветки; виден ли пропуск нового шага по следу в выходе.

**Чей это взгляд.** Дельта сквозная либо правка меняла нормативную силу - прогон ведёт отдельный
узел через `Agent`: разбор своего текста изнутри своего же контекста систематически пропускает
именно эти классы. Исполнителя подбирай по «Как выбрать исполнителя» движка; имени под ревью
артефакта в сессии нет -> прогон своими силами и строка `unverifiable` о том, что взгляд не был
независимым. Вход узлу: цель правки Phase 1, план Phase 4, оси `artifact-review`, `mode`; отчёт
принимай, только если по каждой оси назван исход. Дельта точечная и силу нормы не трогала - разбор
своими силами, `channel: self` строкой в журнал с этой причиной.

Маршрут по находкам решает трек: находка своего уровня закрывается правкой тем же порядком, что и
Phase 5, после чего Phase 6 и 8 повторяются по новой дельте. Незакрытое - перечнем в выход со
`status: partial`.

## Выход трека (handoff)

**Output (handoff):** первым полем `status` (словарь исхода - `node-contract`), затем: перечень
коммитов (sha + что в каждом); цель правки Phase 1 с исходом; дом нормы и перечень сведённых
носителей (Phase 2, 7); исход прогона Phase 6 - оптимизация и кейсы, каждый со своим статусом;
результат гейта Phase 8 с разобранными предупреждениями; допущения, каждое с источником вывода;
**решения, принятые за оператора**, отдельным перечнем; открытые наблюдения вне предмета правки;
журнал исполнителей со строками `channel: self` и их причинами; перечень незакрытого при
`partial`/`blocked`.

**Exit criteria:** Output несёт все перечисленные поля; `complete` выдаётся только когда гейт
пройден фактом прогона и по прогону поведения назван исход; иначе `partial`/`blocked` с перечнем.

**Mandatory:** yes

## Boundaries

- Предмет правки - и только он: замеченный дефект соседнего артефакта идёт в открытые наблюдения, а
  не правится попутно. Исключение - носитель, который **эта** правка сделала противоречивым: он
  входит в предмет по Phase 2.
- Нормативную силу за сжатие не отдают: сокращается подача, не обязательства, статусы и терминалы.
- Артефакт не адресует документ, которого у исполнителя не будет: норма, нужная в рантайме, живёт в
  самом артефакте либо в скилле, который у пользователя установлен.
- Правка, снимающая проверку или ослабляющая гейт, - решение уровня оператора: `interactive` -
  предъяви до Phase 5, `autonomous` - выведи из принятого и объяви отдельным пунктом.
