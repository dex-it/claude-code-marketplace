# /investigate

Расследовать инцидент на общем стенде через `dex-skill-diagnostics-track:diagnostics-track`, найти
доказанную корневую причину и предложить фикс на источнике. Режим по умолчанию - только чтение;
стенд общий.

## Goal

Провести инцидент через универсальный цикл движка и фазы трека, делегирующего
`incident-investigator` (Access & Map, Problem Specification, Parallel Evidence, Hypotheses &
Chain, Falsification, Fix Plan, Report, Gated Fix). Трек нарезает гипотезы срезами и требует
фальсификации каждой до принятия причины - корреляция не равно причинность.

## Input

Аргумент - описание инцидента (симптом, сообщение об ошибке, что и как заметили). Опционально ветка
стенда. Стек и связи проектов определяются по манифестам и стенду.

## Output

- Спецификация IS / IS-NOT с моментом начала, хронология, собранные доказательства по источникам
- Причинно-следственная цепочка до структурной причины с severity / confidence
- Проблемы и план фикса на источнике с фальсификацией фикса
- После команды `фиксируй` - серия правок по одной проблеме с верификацией red -> green

## Constraints

- Режим по умолчанию - только чтение; любой эффект на общий стенд - отдельное подтверждение
- Симптом не равно причина: фикс на источнике, не на месте проявления
- Confidence ниже 80 на причине - гипотеза под вопросом, не объявленная причина
- Сбор улик со стенда делегируется инфра-плагинам (kubectl / glab / teamcity / grafana / seq), не
  дублируется

Команды цикла: `оформляй` (полный отчёт), `фиксируй` (фикс по одной проблеме), `стоп` (прекратить).
Вызови `Skill` -> `dex-sdlc:engine` (откроет/возобновит цикл, авто-ledger с треком
`dex-skill-diagnostics-track:diagnostics-track`), затем `Skill` ->
`dex-skill-diagnostics-track:diagnostics-track` с **`mode: interactive`** - без этого поля трек
берёт автономную планку (`autonomous`) и цикла команд не будет: канал у тела команды есть,
спрашивать по нему трек будет только с этим полем.
