# Карта документации проекта

Предмет - **расположение** корпуса (принятые требования, ADR, спеки), не его содержание: что извлечь, решает вызывающий узел по своей задаче.

## 1. Дом путей - раздел документации в CLAUDE.md

Пути к корпусу - **обязательный атрибут CLAUDE.md проекта**. Читается в начале работы, до выводов о том, что требуется и как принято.

Обе формы пути штатны - правило, требующее доки рядом с кодом, отсекает типичный случай:

| Форма | Пример | Особенность |
|---|---|---|
| каталог репозитория | `docs/requirements/`, `docs/adr/` | читается всегда |
| отдельный репозиторий | URL или путь клона | может быть не склонирован либо закрыт по правам - п.4 |

**Корпус проекта != рабочее состояние задачи.** Документация задачи (`docs/<TASK>/` и корпус выше) в
git и едет с MR; **auto-ledger** - журнал автономной работы (`dex-skill-autonomous-task`) - лежит вне
рабочего дерева и в корпус не пишется. Запись не по назначению даёт либо утечку служебного состояния
в MR, либо потерю документации задачи вместе со средой.

## 2. Раздела нет - искать и записать

Отсутствие раздела - нехватка **инженерная**: восполняется самостоятельно в любом режиме, наверх не эскалируется, работу не останавливает.

1. Искать по стандартным местам: `docs/`, `docs/adr/`, `docs/decisions/`, `*.adr.md`, `docs/requirements/`, `docs/specs/`.
2. Найденное проверить на принадлежность проекту (п.3).
3. Прошло проверку -> дописать раздел путей в CLAUDE.md **текущего** репозитория. Корень определяй `git rev-parse --show-toplevel`; нет `Bash` в tools узла - бери `CLAUDE.md` рядом с корнем рабочего каталога, а неоднозначность корня (вложенный репозиторий, монорепа) фиксируй пунктом выхода и запись не делай.
4. Запись отразить явным пунктом выхода: что дописано и на основании чего найдено (`node-contract` п.5 - решение узла в выход, не молча).

Ничего не найдено -> зафиксировать это пунктом выхода и работать по восстановленному из кода контексту. Отсутствие корпуса halt'ом не является.

## 3. Принадлежность проекту - по содержимому, не по соседству

Найденные доки относятся к этому проекту, если **называют** его продукт, сервис или репозиторий. Файловое соседство доказательством не является: монорепа, соседний клон и submodule дают доки чужого проекта на расстоянии одного каталога.

Подтвердить принадлежность не удалось -> пути идут в выход пунктом, **запись в CLAUDE.md не делается**. Догадка в чужой файл не пишется.

## 4. Пути есть, корпус недостижим - статус, не молчание

Три состояния различаются, и каждое имеет свой терминал:

| Состояние | Действие |
|---|---|
| путей нет | п.2 - искать, записать найденное |
| пути есть, корпус читается | сверяться, как предписывает задача узла |
| пути есть, корпус недостижим (не склонирован, закрыт по правам, каталог пуст) | `unverifiable` + причина в выход |

Недостижимость **не** трактуется как «сверка не нужна» и **не** чинится подменой путей на локальные. Молча пропущенная сверка превращается в «проверено, конфликтов нет» на узле ниже, который метке доверился.

## 5. Сверка по предмету узла - обязательна

Корпус прочитан -> свериться по своему предмету:

- **новое требование** - не дублирует и не противоречит принятому; нумерация `FR`/`NFR` продолжает сквозную, а не начинается заново;
- **решение** - покрыто `Accepted` ADR либо отклонение от него обосновано явно (детали ADR-осей - `dex-skill-codebase-conventions`, ось 6);
- **спека/дизайн** - опирается на действующую версию, не на `Superseded`.

Расхождение найдено -> находка в выход по контракту узла, не тихая правка чужого артефакта.
