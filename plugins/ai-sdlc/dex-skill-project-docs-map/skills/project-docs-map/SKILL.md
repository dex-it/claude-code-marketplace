# Карта документации проекта

Предмет - **расположение** корпуса (принятые требования, ADR, спеки), не его содержание: что извлечь, решает вызывающий узел по своей задаче.

## 1. Дом путей - раздел документации в CLAUDE.md

Пути к корпусу - **обязательный атрибут CLAUDE.md проекта**. Читается в начале работы, до выводов о том, что требуется и как принято.

Обе формы пути штатны - правило, требующее доки рядом с кодом, отсекает типичный случай:

| Форма | Пример | Особенность |
|---|---|---|
| каталог репозитория | `docs/requirements/`, `docs/adr/` | читается всегда |
| отдельный репозиторий | URL или путь клона | может быть не склонирован либо закрыт по правам - п.4 |

**Корпус проекта != рабочее состояние задачи.** Документация задачи (`docs/<TASK>/` и корпус выше) в
git и едет с MR; **auto-ledger** - журнал автономной работы (`dex-skill-autonomous-task`) - лежит вне
рабочего дерева и в корпус не пишется. Запись не по назначению даёт либо утечку служебного состояния
в MR, либо потерю документации задачи вместе со средой.

## 2. Раздела нет - искать и записать

Отсутствие раздела - нехватка **инженерная**: восполняется самостоятельно в любом режиме, наверх не эскалируется, работу не останавливает.

1. Искать по стандартным местам: `docs/`, `docs/adr/`, `docs/decisions/`, `*.adr.md`, `docs/requirements/`, `docs/specs/`.
2. Найденное проверить на принадлежность проекту (п.3).
3. Прошло проверку -> дописать раздел путей в CLAUDE.md **текущего** репозитория. Корень определяй `git rev-parse --show-toplevel`; нет `Bash` в tools узла - бери `CLAUDE.md` рядом с корнем рабочего каталога, а неоднозначность корня (вложенный репозиторий, монорепа) фиксируй пунктом выхода и запись не делай.
4. Запись отразить явным пунктом выхода: что дописано и на основании чего найдено (`node-contract` п.5 - решение узла в выход, не молча).

Ничего не найдено -> зафиксировать это пунктом выхода и работать по восстановленному из кода контексту. Отсутствие корпуса halt'ом не является.

## 3. Принадлежность проекту - по содержимому, не по соседству

Найденные доки относятся к этому проекту, если **называют** его продукт, сервис или репозиторий. Файловое соседство доказательством не является: монорепа, соседний клон и submodule дают доки чужого проекта на расстоянии одного каталога.

Подтвердить принадлежность не удалось -> пути идут в выход пунктом, **запись в CLAUDE.md не делается**. Догадка в чужой файл не пишется.

## 4. Пути есть, корпус недостижим - статус, не молчание

Три состояния различаются, и каждое имеет свой терминал:

| Состояние | Действие |
|---|---|
| путей нет | п.2 - искать, записать найденное |
| пути есть, корпус читается | сверяться, как предписывает задача узла |
| пути есть, корпус недостижим (не склонирован, закрыт по правам, каталог пуст) | `unverifiable` + причина в выход |

Недостижимость **не** трактуется как «сверка не нужна» и **не** чинится подменой путей на локальные. Молча пропущенная сверка превращается в «проверено, конфликтов нет» на узле ниже, который метке доверился.

## 5. Карта фич - тот же дом, отдельная строка путей

Карта фич - файл уровня проекта: строка на фичу, «номер фичи, слаг, где лежит её корпус». Номер фичи задаёт блок номеров единиц (`dex-skill-unit-identity:unit-identity`), поэтому карта - **предмет расположения, а не содержания**: где она лежит, устанавливается здесь; как по ней считается номер - там.

**Место карты записывается, а не выводится.** Путь карты стоит в разделе путей CLAUDE.md рядом с корнем корпуса. Процедурой расположения артефакта он не разрешается: у корня допускается несколько кандидатов, и две ветки завели бы две карты, каждая из которых считает себя единственной, - молча, без конфликта при слиянии, то есть ровно то, ради чего карта заводилась.

Пути карты в разделе нет:

1. Искать в корне корпуса и на уровень выше: `features.md`, `feature-map.md`, `features/README.md`, раздел «фичи» в существующем индексе документации. **Найденное - карта, даже если имя другое:** факт сильнее конвенции, второй файл рядом с существующим списком фич не заводится.
2. Нашлось две -> **остановка с находкой**, а не выбор одной из них: номера в них уже могли разойтись, и сводит их человек. Третья карта не заводится, «первая по порядку» не выбирается.
3. Не нашлось ничего -> завести `features.md` в корне корпуса и **тем же действием** записать её место в разделе путей CLAUDE.md (п.2, шаги 3-4: корень репозитория, отражение записи пунктом выхода). Имя - дефолт для пустого места, а не норма поверх существующего.
   **Заводится карта не пустой:** корпус непустой - блоки в ней восстанавливаются один раз сплошным проходом по старшим разрядам номеров уже стоящих единиц (`unit-identity`), а не по папкам раскладки: на чужой раскладке каталогов под фичи нет вовсе, а номера есть. Пустой файл при занятом корпусе выдаст новой фиче первый блок поверх чужого. Проход делается однократно - дальше читается файл.
4. Заводит физически тот узел, которому номер понадобился первым (дирижёр прогона; при прямом вызове - сам составитель), тем же инструментом, каким пишет артефакты. Отдельного владельца у файла нет: строка дописывается в конец, и одновременная запись двух веток даёт конфликт слияния в одной строке - видимый, в отличие от двух одинаковых номеров.

Состав строки - три поля, каждое обязательно:

| Поле | Пример | Зачем |
|---|---|---|
| номер фичи | `03` | старший разряд блока единиц; максимум в карте плюс один - номер новой фичи |
| слаг | `password-reset` | по нему человек узнаёт свою фичу; без слага столкновение двух прогонов неотличимо от законной записи |
| где лежит корпус | `docs/requirements/03-password-reset/` | связывает номер с местом; корпус ещё не заведён - поле пустое с пометкой «блок выдан», строка пишется всё равно |

Форма - таблица markdown, порядок строк по номеру. Одна фича - одна строка; исключение единственное: блок исчерпан, и у фичи появляется вторая строка со вторым номером (`unit-identity`).

**Снятая фича строку не теряет.** Строка остаётся с пометкой снятия, номер не переиспользуется - по тому же правилу, что и номер снятой единицы: на её `FR`/`NFR` ссылались, и блок, переданный другой фиче, молча переводит эти ссылки на чужие требования. Удаление строки возвращает номер в оборот, и происходит это невидимо.

## 6. Сверка по предмету узла - обязательна

Корпус прочитан -> свериться по своему предмету:

- **новое требование** - не дублирует и не противоречит принятому; номер берётся в блоке своей фичи и в своём классе - не заново с единицы и не сквозняком по проекту (`dex-skill-unit-identity:unit-identity`);
- **решение** - покрыто `Accepted` ADR либо отклонение от него обосновано явно (детали ADR-осей - `dex-skill-codebase-conventions`, ось 6);
- **спека/дизайн** - опирается на действующую версию, не на `Superseded`.

Расхождение найдено -> находка в выход по контракту узла, не тихая правка чужого артефакта.
