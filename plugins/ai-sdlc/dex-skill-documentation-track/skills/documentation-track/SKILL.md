# Documentation Track

Трек ведёт документ от запроса до текста, каждое утверждение которого подтверждено кодом или
конфигом. Артефакт - нормативный текст; верификация = синхрон с кодом плюс стандарт жанра.
Вызывается движком `dex-sdlc:engine` (`/documentation`) - отдельно от него не запускается: движок
ведёт цикл и стоп-линию, трек - порядок этой зоны.

**Исполнителя выбирает трек** по критерию движка («Как выбрать исполнителя»): правка понятна и
локализована (абзац, раздел, факт по месту) - трек пишет сам, строкой `channel: self` с причиной и
именем поднятого скилла; документ целиком или новый - по жанру узлу: `dex-doc-writer:doc-writer` -
спецификации, руководства, README, release notes, runbook; `dex-adr-writer:adr-writer` - ADR;
`dex-diagram-creator:diagram-creator` - диаграммы. Работой трека остаются жанр и аудитория, сбор
фактов из кода, приёмка текста против фактов и место документа в дереве проекта (`channel: self`).

**Возобновление и продолжение прогона.** Свёртка контекста внутри прогона - «Возобновление» движка
(`dex-sdlc:engine`) по auto-ledger. Новый прогон по тому же предмету ledger не находит: состояние
читается от намерения (тикет, спека, план, `decision-log`) и от того, что фактически лежит - рамка в
`references/ledger-and-recovery.md` движка, раздел «Восстановление между прогонами». Носитель
состояния этой зоны: сам документ в git и его история. Не восстановилось ни одним носителем - строка
в сдаче, не догадка.

## Обзор фаз

| # | Фаза | Кто исполняет |
|---|---|---|
| 0 | Audience, Genre & Standard | трек (сам) |
| 1 | Facts from Code | трек (сам) |
| 2 | Draft | узел по жанру (doc-writer / adr-writer / diagram-creator) |
| 3 | Verify Sync | трек (сам) |
| 4 | Self-Review & Placement | трек (сам) |

## Phase 0: Audience, Genre & Standard

Goal: определить, кому и в каком жанре пишем и по какому стандарту это судится.

**Input (handoff):** контракт стыка - `dex-skill-node-contract:node-contract`. `[blocking]` предмет
документа: что документируем (компонент, решение, релиз, процедура). Предмета нет -> `status:
blocked` наверх: документ без предмета не пишется. `[default-ok]` `mode` (дефолт `autonomous`),
`approve` (дефолт нет - потолок статуса `review`, см. Phase 4), жанр (не пришёл - выводится из
предмета и запроса), аудитория (не пришла - выводится из жанра, вывод идёт в выход допущением), путь
размещения (не пришёл - определяется через `Skill` `dex-skill-project-docs-map:project-docs-map`),
расположение аналитического корпуса (сквозное поле), `quality-checks`, путь к журналу решений.

Стандарт жанра - `dex-skill-doc-standards:doc-standards`; для API-документации дополнительно
`dex-skill-api-documentation:api-documentation`. Жанр задаёт критерий готовности: ADR - контекст ->
решение -> последствия; runbook - воспроизводимые шаги под стресс; API-док - контракт точь-в-точь как
код; release notes - что изменилось для пользователя, а не перечень коммитов.

Output: жанр, аудитория (оператор в 3 ночи / интегратор / новичок / автор соседнего сервиса),
стандарт с адресом, критерий готовности жанра.
Exit criteria: жанр и аудитория названы; критерий готовности взят из стандарта жанра, а не придуман
здесь.

Mandatory: yes

## Phase 1: Facts from Code

Goal: собрать фактическую основу документа из первоисточника.

Факты берутся из кода, конфигов, манифестов и схем - **не из памяти и не из других документов**: те
протухают, и документ наследует их расхождение, добавляя ему второй носитель. Требования и решения,
на которые документ опирается, читаются из аналитического корпуса и журнала решений по расположению
из сквозного поля (`node-contract`, `references/quality-and-review.md` п.7), а не из пересказа в
задаче.

Output: перечень утверждений будущего документа, каждое с адресом источника (`file:line`, ключ
конфига, идентификатор требования, номер ADR).
Exit criteria: каждое планируемое утверждение имеет адрес источника либо помечено `unverifiable` с
причиной; утверждение, источник которого - другой документ, помечено этим явно и проверяется по коду
до включения.

Mandatory: yes

## Phase 2: Draft

Goal: получить текст по фактам Phase 1 руками узла жанра.

Спавн узла по жанру (см. вводный абзац); вход узла - жанр, аудитория, стандарт, перечень утверждений
с адресами источников, путь размещения. Диаграмма внутри документа - отдельный узел
(`dex-diagram-creator:diagram-creator`), не пересказ схемы прозой.

Источник режима - вход трека (`mode`), нет поля -> `autonomous` (`node-contract` D.11); вниз режим
передаётся тем же значением - канал к оператору держит трек, планку эскалации несёт узел.

Output: файл документа по пути размещения; перечень мест, где узел не нашёл фактической опоры.
Exit criteria: документ создан по пути Phase 0; места без опоры перечислены поимённо, а не заполнены
правдоподобным текстом.

Mandatory: yes

## Phase 3: Verify Sync

Goal: сверить готовый текст с кодом, а не с намерением автора.

Каждое утверждение документа проверяется против первоисточника Phase 1 повторно - по тексту, а не по
плану: узел мог достроить утверждение, которого в перечне не было. Расхождение документа с кодом
разбирается по природе: код прав, текст неверен -> правка текста; текст описывает принятое решение, а
код ему не соответствует -> это находка о коде, она идёт в выход трека и не «исправляется» правкой
документа под фактическое поведение.

Output: по каждому утверждению - `verified` (с адресом) | `unverifiable` (с причиной) | `contradicted`
(с уликой расхождения).
Exit criteria: утверждений без исхода нет; ни одно `contradicted` не закрыто переписыванием документа
под код без явного решения об этом в выходе.

Mandatory: yes

## Phase 4: Self-Review & Placement

Goal: довести документ до состояния, в котором он не спорит сам с собой и с деревом документации.

Проверяется: полнота по критерию жанра Phase 0; отсутствие LLM-маркеров и воды -
`dex-skill-output-hygiene:output-hygiene`; single source of truth - утверждение, уже имеющее дом в
другом документе, заменяется ссылкой, а не копией (копия расходится молча); место в дереве
документации и входящие ссылки - документ, на который никто не ссылается, не будет найден.

**Статус документа.** Подъём до `approved` (для ADR - `Accepted`) - санкция оркестратора: право даёт
поле `approve`, не режим (`node-contract`, словарь полей). Санкции нет -> потолок `review`, и это
называется в выходе. Публикация во внешнюю систему (wiki, портал) - outward-facing действие по той же
норме, самовольно не выполняется ни в одном режиме.

Output: финальный документ, чеклист самопроверки с исходом по каждому пункту, статус документа,
перечень мест, откуда на него ведут ссылки.
Exit criteria: все четыре пункта проверки имеют исход; статус не выше того, что разрешает `approve`.

Mandatory: yes

## Режимы

Режим здесь совпадает с ярусом: трек грузится в тело исполнителя, узлом не спавнится, поэтому
канал держит то же тело, - и `interactive` адресует возврат оператору. Состав фаз он не меняет: `interactive` - выбор жанра при двусмысленном запросе
и решение по `contradicted` предъявляются оператору; `autonomous` - решение принимается и идёт в
выход перечнем «принято за оператора». Права на подъём статуса и на внешнюю публикацию режим не даёт -
только поле `approve` и санкция оркестратора (Phase 4).

## Выход трека (handoff)

**Output:** первым полем `status` (словарь исхода - `node-contract`), затем: путь документа и его
статус; жанр, аудитория и стандарт с адресом; таблица «утверждение -> источник -> исход» Phase 3;
перечень `unverifiable` с причинами; находки о коде (`contradicted`) отдельным перечнем с адресатом;
чеклист самопроверки Phase 4; входящие ссылки; допущения (включая выведенную аудиторию); решения,
принятые за оператора, отдельным перечнем; сквозные поля входа как есть; перечень незакрытого при
`partial`/`blocked`.

Читатель выхода - движок (шаг 8, сдача). Правка кода по находкам `contradicted` - отдельная работа
(`dex-skill-bugfix-track:bugfix-track` `[справочно]` либо трек разработки), не продолжение этого трека.

**Exit criteria:** Output несёт все перечисленные поля; `complete` выдаётся только когда каждое
утверждение имеет исход и чеклист Phase 4 пройден; иначе `partial`/`blocked` с перечнем.

**Mandatory:** yes

## Boundaries

- Факты - из кода и конфигов; другой документ источником не является без проверки по коду.
- Расхождение кода с принятым решением - находка о коде, а не повод переписать документ под
  фактическое поведение.
- Статус `approved`/`Accepted` и публикация вовне - по санкции оркестратора, не по режиму.
- Дубль чужого дома заменяется ссылкой; копия нормативного текста в новом документе запрещена.
