# dex-sdlc-nudge

Поднимает движок конвейера `dex-sdlc:engine` на рабочей просьбе. Ставится рядом с `dex-sdlc`; без
него бессмыслен - подталкивает к скиллу, которого не будет.

## Проблема

Движок - режим работы, а не справка о предмете, и механизмом отбора скиллов он не выбирается.
Замер 23.08.2026 (`node tools/run-activation.js --case engine --runs 2`, sonnet, пустая песочница
с полным каталогом плагинов):

| Формулировка | Прогон 1 | Прогон 2 |
|---|---|---|
| «возьми тикет PROJ-412, доведи сам, работай автономно» | ни одного Skill | ни одного Skill |
| «реализуй фичу экспорта в CSV, сам до коммитов» | ни одного Skill | ни одного Skill |
| «разберись и почини, на проде падает профиль» | ни одного Skill | ни одного Skill |
| «отревьюй MR 341 и разбери замечания» | ни одного Skill | `dex-sdlc-review:mr-review` |
| «что следующее по задаче, продолжай сам» | ни одного Skill | ни одного Skill |

**0 из 10.** Тот же замер на скилле-диспетчере, чьё `description` набрано из одних формулировок
задач, - тоже 0 из 10; зонд в настоящем репозитории с кодом и `CLAUDE.md` - 0 из 2. То есть дело
не в тексте поля и не в размере скилла: в 9 запусках из 10 модель не вызывает **ни одного** скилла.
На вопрос о предмете («как построить кэш на Redis») отбор работает штатно - на поручение сделать
работу он не идёт в скиллы вовсе.

Отсюда вывод: правка `description` тут не рычаг (класс 3 из базы прогонов активации), нужен
детерминированный канал.

## Механизм

`UserPromptSubmit` получает поле `prompt` и отдаёт `additionalContext` «alongside the submitted
prompt» ([hooks](https://code.claude.com/docs/en/hooks), сверено 23.08.2026). Матчера у события нет
- хук срабатывает на каждом промпте.

Хук вычитывает stdin, берёт `cwd` и молчит вне git-репозитория (конвейер стоит на ветках, MR и
тикетах). В репозитории инжектит одну короткую подсказку: рабочая просьба -> `Skill` ->
`dex-sdlc:engine` до первого действия; вопрос, разговор, правка в пару строк -> обычным путём.

**Реестра зон хук не несёт.** Дом реестра один - `references/zone-registry.md` движка, движок
резолвит зону сам на шаге 1 цикла. Копия в тексте хука разошлась бы с ним молча.

**Фильтра по словам в хуке нет.** Условие неприменимости несёт сам текст инжекта, и модель его
соблюдает: в замере с хуком «поправь опечатку в README» и «какой у нас стек в проекте» конвейер не
подняли, а «реализуй», «почини», «покрой тестами», «собери требования», «отревьюй MR» - подняли с
верной зоной. Регулярка по глаголам отсекала бы хуже, чем модель.

**LLM-хук (`type: "prompt"`) на это событие не годится**: его схема ответа - `{ok, reason,
impossible}`, `additionalContext` он не отдаёт, а `ok: false` на `UserPromptSubmit` завершает ход и
показывает reason предупреждением.

## Ограничения

- **Инжект идёт на каждом промпте сессии**, включая разговорные (матчера у события нет). Цена -
  порядка полусотни токенов на ход; поднимать движок на них модель при этом не начинает.
- **Хук не видит, поднят ли движок уже.** Текст одинаков весь прогон; на уже открытом цикле он
  избыточен, но безвреден - «до первого действия по ней» к продолжающейся работе не относится.
- **Точность зоны - на движке, не на хуке.** Промах реестра выглядит как поднятый не тот трек;
  ловится тем, что движок обязан назвать выбранную строку в допущениях выхода.
- **Без `dex-sdlc` бесполезен**: `Skill` не найдёт `dex-sdlc:engine`, и подсказка останется шумом.
