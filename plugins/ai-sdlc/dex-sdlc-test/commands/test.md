# /test

Закрыть матрицу покрытия тестами через `dex-skill-test-track:test-track`: не запуск существующих
тестов ради отчёта, а добор покрытия по осям в приоритетном порядке. Стек определяется по манифесту
затронутой папки - явно указывать не нужно.

## Goal

Провести область под тест через универсальный цикл движка и трек: закрыть оси покрытия
(happy-path / негатив / краевые / все ветки логики - общий якорь движка `[[P-test-axes]]`) по
приоритету, делегируя написание узлу `test-writer` по стеку (.NET - `dotnet-test-writer`, TS/JS -
`ts-test-writer`). Границу доверия к тесту (мок внешней границы, точка входа до теста, развилки
путей) держит `dex-skill-integration-boundary:integration-boundary`, грузит исполняющий узел.

## Input

Аргумент - путь к файлам/модулю под тест или diff-scope (по умолчанию - незакоммиченный + staged
diff текущей ветки). Стек и тестовый раннер определяются по манифесту (`*.csproj` -> `dotnet test`
с `--collect:"XPlat Code Coverage"`; `package.json` -> Vitest/Jest по конфигу).

## Output

- Тест-файлы, закрывающие приоритетные оси покрытия по diff-scope
- Branch coverage по diff-scope с указанием, какое подмножество осей закрыто, а какое отрезано и
  почему - без тихого усечения
- Статус прогона (passed/failed/skipped, время); для упавших - имя, ожидание vs результат,
  предполагаемая причина
- Саморевью узла: изоляция тестов (не флейки от порядка/таймеров/моков), не тавтология с кодом,
  отсутствие типовых антипаттернов

## Constraints

- Приоритизация осей и порядок закрытия - решение трека, не оператора; `mode` здесь нечего
  переключать
- Тесты не собираются - сначала чинится компиляция/type-check, затем покрытие
- Coverage ниже 50% для файлов с бизнес-логикой - подсвечивается как критичный, не молчаливо
  принимается

Вызови `Skill` -> `dex-sdlc:engine` (откроет/возобновит цикл, авто-ledger с треком
`dex-skill-test-track:test-track`), затем `Skill` -> `dex-skill-test-track:test-track`.
