# /documentation

Написать техническую документацию через `dex-skill-documentation-track:documentation-track`:
нормативный текст, факты только из кода/конфигов, синхрон со стандартом жанра.

## Goal

Провести задачу через универсальный цикл движка и фазы трека, делегирующего `doc-writer`
(Understand Requirements -> [Study Project Context?] -> Generate -> Validate), а по жанру -
`adr-writer` (ADR) или `diagram-creator` (C4/sequence/ER/диаграммы) как дополнительные узлы.

## Input

Тип документа (tech spec / README / release notes / API doc / architecture doc / runbook /
migration guide / onboarding guide / ADR) и источник содержания - код, ТЗ, обсуждение. Опционально
путь записи, целевая аудитория, шаблон. Тип не указан - трек запрашивает, не угадывает; источника
содержания нет - halt со статусом `blocked`.

## Output

- Готовый документ по чеклисту жанра из `dex-skill-doc-standards:doc-standards`
- По каждому техническому факту (версия, конфиг, имя API, поведение) - сверка с `file:line` или
  статус «не подтверждён»; ни одного `[TODO]`/`[TBD]` в финале
- Незакрытые места - с причиной по каждому, не тихим пропуском
- ADR/диаграммы - там, где жанр требует, отдельными узлами трека

## Constraints

- Факты - из кода/конфигов, не из памяти и не из других доков (протухают)
- Аудитория и стандарт проекта - технический выбор трека, не развилка к оператору; `mode` здесь
  нечего переключать
- Существующий документ на ту же тему - предложить обновление, не плодить дубль
- Тривиальный предмет без бизнес-логики - предупредить о низкой ценности документа, не писать молча

Вызови `Skill` -> `dex-sdlc:engine` (откроет/возобновит цикл, авто-ledger с треком
`dex-skill-documentation-track:documentation-track`), затем `Skill` ->
`dex-skill-documentation-track:documentation-track`.
