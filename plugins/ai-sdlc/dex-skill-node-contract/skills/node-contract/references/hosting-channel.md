# Канал доступа к хостингу: native-интеграция приоритетом, CLI - фолбэк

Материал контракта узла (`node-contract`), читаемый по требованию. Обязателен узлу, работающему с
MR/PR на хостинге: чтение метаданных, diff, тредов; запись тредов, reply, overview.

Канал выбирается по доступности, не по привычке:

1. Native-интеграция хостинга (MCP-сервер платформы) подключена и отдаёт нужную операцию -> через
   неё: серия операций идёт одним протоколом, без ручной сборки запросов. Атомарность - условное
   свойство операции канала, не класса native: протокол даёт атомарную публикацию серии ->
   использовать её, частичная доставка исключена; не даёт -> native не атомарнее CLI, действует
   инвариант доставки фазы (стоп на первой ошибке, без досыла вслепую).
2. Native-интеграция не подключена в среде прогона ИЛИ не покрывает операцию -> фолбэк на CLI
   хостинга. Условие фолбэка явное (нет канала / нет операции), не «по усмотрению».
3. Ни native, ни CLI не дают операцию -> `status: blocked` оркестратору: недоступность канала
   переключает на запасной, шаг не отменяет и молча не пропускает.

Подключённость native-интеграции - свойство среды прогона, не узла: узел канал не угадывает, пробует
приоритетный и падает на фолбэк по факту недоступности. Норма симметрична для чтения и записи и
платформу не называет - конкретные тулы приоритета и фолбэка держит фаза самого агента (дом
инструмента - агент, не этот skill).

Право на запись в чужой MR (санкция оркестратора) - отдельная ось, см. «Outward-facing действие» в
ядре: выбор канала не даёт права писать.
