# /rulebook

Свод правил проекта через `dex-skill-rulebook-track:rulebook-track`: что в этом репозитории принято - правила ревью, конвенции, гайдлайны, - выведенное из тредов и последовавших правок. Результат кладётся в корпус документации репозитория по ключу `rulebook`.

Это не инвентаризация проблем кода - для неё есть зона обзора; и не суждение об одной чужой правке - для него есть ревью MR.

## Goal

Дать репозиторию читаемый адрес того, что в нём принято, чтобы ревьюеры - и люди, и агенты - опирались на записанное, а не на память. Трек делегирует узлу добычи: тот определяет окно, читает существующий свод, спавнит read-only сборщиков по источникам, сводит кандидатов, фальсифицирует каждого по якорю и пишет корпус.

## Input

Аргумент - путь к одному репозиторию, по умолчанию текущий: свод один на репозиторий, и второй репозиторий - второй прогон. `--window` сужает период истории; без него разность считается по реестру источников существующего свода, а при первом прогоне берётся вся доступная история. `--publish` даёт треку санкцию создать MR со сводом; без него тело MR готовится и уходит в отчёт, наружу не пишется ничего. `--approve` даёт санкцию поднять свод до принятого после вердикта; без неё потолок - `review`, и единицы остаются предложенными.

`--mr` открывает **второй круг** по уже опубликованному своду: прогон не добывает заново, а разбирает замечания владельца на этом MR, проводит правки, отвечает в треды и обновляет тот же MR. Историю ради разметки не перечитывают, и второго MR не заводят: его номер - якорь для тредов и для реестра источников. Круг повторяется столько раз, сколько владелец возвращает свод, - свод принимается не с первого предъявления, его предмет договорённость. `--publish` при этом не нужен: он разрешает **создать** MR, а тут он уже создан и владелец на нём.

## Output

Индекс свода: действующая схема таксона с версией, строка на каждое правило с идентификатором, формулировкой, таксоном, областью применения, статусом и признаком принуждения.

Разделы таксона: единицы `RUL-NNNN` целиком - формулировка в повелительной форме, дословная цитата источника со ссылкой на тред или коммит, область применения, контрпример из истории репозитория.

Реестр источников: у каждого разобранного MR, треда и коммита - исход из закрытого перечня, включая «правила не дал» с основанием. По нему следующий прогон отличает непросмотренное от разобранного.

Наблюдения и расхождения: кандидаты, не ставшие правилами, и места, где принятое в репозитории расходится с распространённой внешней практикой - чтобы следующий прогон не выводил их заново.

## Constraints

- Правило без якоря на источник в свод не пишется: оно уходит в перечень кандидатов отчёта
- Правило, выводимое из кода, конфига или прогона инструмента, в свод не идёт - идёт признак принуждения
- Принятое в репозитории не отбрасывается по внешней рекомендации; расхождение с ней называется отдельно
- Свод судит трек, не автор; подъём до принятого - по санкции, потолок без неё - `review`
- Противоречие между единицами и правка уже принятого - решение владельца корпуса, а не прогона
- Фактическая часть замечания владельца проверяется, нормативная принимается: «это уже ловит анализатор» - утверждение с носителем, а не указание
- Требование, меняющее не свод, а сам жанр (схему таксона, состав корпуса), этим прогоном не исполняется и уходит в выход с названным адресатом
- Свод существует на уровне репозитория: два репозитория одного продукта ведут свои своды

Аргумент `--mr` едет треку полем `published_mr`; трек передаёт разбор `dex-skill-followup-track:followup-track`, назначая исполнителем правок узел добычи, а оракулом дельты - оракул свода: иначе на документе отработает узел, пишущий код.

Вызови `Skill` -> `dex-sdlc:engine` (откроет либо возобновит цикл, авто-ledger с треком `dex-skill-rulebook-track:rulebook-track`), затем `Skill` -> `dex-skill-rulebook-track:rulebook-track` с **`mode: interactive`**: у зоны три гейта оператору - развернуть ли заготовку корпуса, разметка владельца по единицам и «ок» на текст описания MR. Без этого поля трек уйдёт в `autonomous`, разметку спросить будет не у кого, и свод останется в `review` навсегда.
