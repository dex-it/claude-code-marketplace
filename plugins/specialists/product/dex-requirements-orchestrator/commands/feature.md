# /feature

Провести фичу от идеи до апрувнутых user stories с трассировкой требований.

## Goal

Породить BRD, требования системы и stories и провести каждый артефакт через гейт качества до явного апрува оператора - чтобы дефект требования не размножился на нижележащие артефакты.

Три уровня разведены: `BR-NNN` - цель стороны с мерой успеха MOE; `FR-NNN`/`NFR-NNN` - проверяемое поведение системы, выведенное из `BR`; story с AC - нарезка `FR` под разработку. Уровень не перепрыгивается: story прямо от `BR` означает, что решение «что именно должна делать система» принято молча.

## Input

Аргумент - один из трёх видов входа; ветка выбирается по проработанности, не по размеру текста:

- **сырая тема** («личный кабинет») - идея прорабатывается в диалоге, затем пишется BRD;
- **проработанная идея** (нужды, цели, границы уже сформулированы) - шторм пропускается, сразу BRD;
- **путь к чужому готовому BRD** - вместо порождения выполняется входная приёмка оракулами.

Аргумент не передан - тема запрашивается первым вопросом.

## Output

- BRD с нумерованными `BR-NNN` и MOE, `non-goals`, допущениями;
- требования системы `FR-NNN`/`NFR-NNN`, каждое с `traced from BR-NNN`;
- user stories с acceptance criteria в Given-When-Then и метками `[FR-NNN]`;
- сквозная трассировка `BR -> FR -> AC`: каждое `BR` раскрыто требованием системы, каждый `FR` покрыт story - либо переведён в `non-goals` с основанием;
- `status: complete` - выдаётся только после апрува всех трёх гейтов; неапрувнутый или неполный результат уходит как `blocked`/`partial` с перечнем незакрытого (перечень статусов - `node-contract`, правило стыка A);
- метка `quality-checks` с записями по BRD, требованиям системы и stories;
- handoff в зону 2 (`/design`).

Спека, ADR, нарезка задач и код - НЕ здесь.

## Constraints

- Апрув гейтов - явный, оператором; молчание апрувом не считается, авто-approve нет.
- Бизнес-решения (scope, приоритет, нужность требования) принимает оператор, не агент.
- Согласование чужих готовых требований без порождения новых - `/review-requirements`.
- Правая граница - апрувнутые stories; дизайн и спека - `/design`, другой владелец и другой апрув.

Делегировать агенту `requirements-orchestrator` с **`mode: interactive`** во входе (команда исполняется главным циклом - канал к оператору есть; без явного `interactive` агент уйдёт в дефолтный `autonomous` и вместо диалога и апрува вернёт `status: blocked`).
