# dex-requirements-orchestrator

Дирижёр зоны 1 (требования): ведёт путь «идея -> BRD -> `FR`/`NFR` -> stories» через интерактивные гейты качества с апрувом аналитика.

## Состав

| Артефакт | Что делает |
|---|---|
| Агент `requirements-orchestrator` | Классифицирует вход, спавнит составителей, гоняет гейты, собирает апрув |
| Команда `/feature` | Точка входа оператора; передаёт агенту `mode: interactive` |

## Зачем

Дефект требования дёшев в момент рождения и дорог в конце цепочки: дырявый BRD размножается на N историй, оттуда в код и всплывает как «баг» в проде, хотя код написан правильно. Дирижёр ставит проверку сразу после порождения каждого артефакта - до того, как он размножится.

## Как работает

```
вход (тема / проработанная идея / чужой BRD)
  |
  v
Bootstrap - классификация входа по проработанности
  |
  v
Ideate -> BRD   (спавн dex-business-analyst:business-requirements-analyst)
  |  ГЕЙТ BRD: метка составителя + оракул набора -> находки оператору -> апрув
  v
Derive -> FR/NFR  (спавн dex-requirements-analyst:requirements-analyst)
  |  ГЕЙТ требований: метка + оракул набора + трассировка BR->FR -> находки оператору -> апрув
  v
Decompose -> Stories  (спавн dex-user-story-analyst:user-story-analyst)
  |  ГЕЙТ stories: метка + трассировка FR->AC -> находки оператору -> апрув
  v
Handoff -> зона 2 (/design)
```

**Два слоя гейта, метку ставит дирижёр.** Слой единицы - `requirement-quality`: составитель прогоняет его как самоконтроль и отчитывается полем `self-check`, метку `quality-checks` не ставит (автор своему артефакту не судья); дирижёр прогоняет оракул единицы сам, `self-check` составителя прогон не заменяет. Слой набора - `requirement-set-quality`, тоже дирижёр: субагент видит только свой артефакт, полноту множества против источника установить не может.

**Толерантный вход.** Стадия шторма пропускается по проработанности входа, а не по его размеру: длинный текст без разобранных нужд остаётся сырой темой, три строки с целью, актором и границами - проработанная идея.

**Режим.** `/feature` передаёт `mode: interactive` - есть диалог и апрув. При спавне субагентом режим по умолчанию `autonomous`: канала к оператору нет, гейты не авто-апрувятся, а возвращаются наверх как `status: blocked`.

## Границы

- Артефакты пишут составители, не дирижёр.
- Апрув всегда явный оператором; авто-approve нет.
- Согласование чужих готовых требований - `/review-requirements`, не эта команда.
- Правая граница - апрувнутые stories. Дизайн и спека - зона 2 (`/design`), задачи и код - движок `autonomous-task`.

## Использование

```
/feature                                  # тема запрашивается в диалоге
/feature личный кабинет с экспортом отчётов
/feature docs/brd/payments.md             # чужой готовый BRD - входная приёмка
```
