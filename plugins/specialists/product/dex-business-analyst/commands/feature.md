# /feature

Провести фичу от идеи до набора требований, по которому пишется код: реализатор принимает решения
только о способе - алгоритм, структура кода, имена внутри модуля. Любое решение о наблюдаемом
исходе, мере или границе, которое ему пришлось бы принять самому, - незакрытое место набора.

Классы разведены, звено не перепрыгивается:

| Класс | Что несёт | Из чего выводится |
|---|---|---|
| `BR` | цель стороны с мерой успеха | идея, бриф, запрос заказчика |
| `UC` | сценарий: кто, при каких условиях, что происходит и что если не так | `BR`, взятые в разбор |
| `FR` | правило: случай, субъект, наблюдаемый результат | шаг или расширение сценария |
| `NFR` | мера с методом и условиями замера | `BR` и ограничения среды - своя ветка, сценариев не ждёт |
| `AC` | пример на конкретных данных | правило плюс применимые меры, при нарезке в историю |

Правило прямо из цели минует вопрос «а как это происходит», и отказные ветки не появляются вовсе.

## Input

Аргумент - один из видов входа; ветка выбирается по проработанности, не по размеру текста:

- **сырая тема** («личный кабинет») - прорабатывается в диалоге, затем пишутся цели; **проработанная
  идея** (нужды, цели, границы сформулированы) - шторм пропускается;
- **путь к чужому документу** - разбирается на единицы по классам, а не переписывается в свои
  шаблоны: переписанный текст не отличить от дописанного;
- **реализованное без постановки** (пути области кода) - требования оформляются по наблюдаемому
  поведению; расхождение с черновой формулировкой автора идёт решением в `decision-log`, поведение
  с двумя прочтениями предъявляется вопросом, а не закрывается догадкой;
- **правка принятой единицы** - род изменения объявляется до правки файлов, задетое считается по
  трассе, остановка предъявляется после пересчёта.

Аргумент не передан -> запроси тему первым вопросом.

## Порядок делегирования

Порядок ведёт главный поток: канал к оператору есть только у него. Составителям вниз идёт та же
планка эскалации, но не канал - невыводимое они возвращают сюда.

| Порядок | Узел | Что даёт |
|---|---|---|
| 1 | `dex-business-analyst:business-requirements-analyst` | цели `BR-NNN` с мерами успеха |
| 2 | `dex-usecase-analyst:usecase-analyst` | сценарии `UC` с ходом и расширениями |
| 3 | `dex-requirements-analyst:requirements-analyst` | правила `FR` из шагов и расширений, меры `NFR` своей веткой |
| 4 | `dex-user-story-analyst:user-story-analyst` | истории с критериями приёмки |
| 5 | `dex-implementer-reader:implementer-reader` | проба готовности: что пришлось бы додумать |

Приёмка собранного набора - одна остановка оператора, на неё же идёт результат пробы.

## Output

- цели `BR-NNN`, сценарии `UC`, правила `FR-NNN` и меры `NFR-NNN`, истории с критериями приёмки;
- у каждой единицы - вид основания и метод проверки; у каждого расширения назван исход;
- покрытие по каждому стыку в обе стороны: единица источника дала выход либо получила явный исход,
  единица набора несёт годное основание;
- результат пробы готовности с исходом по каждому пункту;
- `quality-checks` по каждому артефакту, каждая запись с версией текста, по которой судили;
- `decision-log` фичи: решения оператора, допущения с исходом, открытые пункты, находки гейтов;
  форму записи и способ ссылки на неё даёт `Skill` -> `dex-skill-decision-log:decision-log`.

`status: complete` - только когда остановка закрыта и открытых пунктов нет; иначе `blocked` или
`partial` с перечнем. Спека, ADR, нарезка задач и код - не здесь.

## Constraints

- Безусловная остановка одна: финальная приёмка набора. До неё остановка только условная -
  невыводимая находка либо полномочная ось, где цена ошибки лежит вне артефакта
- Проба готовности предъявляется в той же пачке, что приёмка
- Нижней границы у числа вопросов нет: всё замкнуто выводом из принятого -> остановка без вопросов
- Апрув - явный ответ оператора; молчание апрувом не считается
- Бизнес-решения (объём, приоритет, нужность требования) принимает оператор
- Проверка своего набора - `/feature-check`, чужого документа - `/review-requirements`
- Правая граница - принятый набор; дизайн и спека - `/design`, он же следующий шаг
