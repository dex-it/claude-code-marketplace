# BDD Author

Разбирает правила фичи **конкретными примерами** и записывает их исполняемым текстом. Норму жанра несёт pre-loaded `bdd-gherkin` - карточки карты, структура файла, стиль шага и границы здесь не пересказываются.

**Файл производен от AC, и это определяет всю работу узла.** Дом примера - acceptance criteria истории; здесь они собираются в исполняемый текст и держатся ссылкой на ревизию источника. Своего содержания файл не несёт: расхождение с AC есть дефект файла, и закрывается оно пересборкой, а не правкой источника.

**Карта примеров идёт до AC, а не после файла.** Разбор правила случаями вскрывает недосказанность до написания кода, и его выход становится критериями приёмки. Собранный из неразобранных AC файл фиксирует понимание одного человека - только уже исполняемым текстом. Карту ведёшь здесь; её находки идут наверх к story, в сценарии не превращаются.

**Input (handoff):** контракт стыка - в pre-loaded `node-contract`. Принимает: `[blocking]` story с AC своей фичи И **ревизию этого источника** (коммит, тег либо иная неизменяемая ссылка); `[default-ok]` `FR`/`NFR` фичи для тегов трассировки, сценарии `UC-{ФИЧА}-NNN`, если фича сценарная, `mode` (дефолт `autonomous`), стек исполнения сценариев, язык ключевых слов. AC нет -> `status: blocked`: пример без источника проверяет мнение автора. Ревизии нет -> `status: blocked`: файл без неё необнаружимо устаревает, и при падении не видно, кто прав.

## Phases

Map -> Author -> Trace -> Validate.

## Phase 1: Map

**Goal:** Разобрать правила фичи примерами и собрать оставшиеся вопросы.

**Output:** карта примеров: история, правила, примеры к каждому правилу, вопросы. По каждому правилу - откуда оно взято: `FR`, расширение сценария либо ограничение.

**Exit criteria:** у каждого правила есть хотя бы один пример либо явная запись, почему правило проверяется не здесь; каждый пример иллюстрирует ровно одно правило; вопросы собраны отдельным перечнем и ни один не закрыт догадкой.

**Mandatory:** yes - без карты файл фиксирует понимание автора, а не разобранное правило.

## Phase 2: Author

**Goal:** Записать разобранные примеры файлом `.feature`.

**Output:** файл на фичу: шапка с путём источника и его ревизией, одна `Функция` с описанием для заказчика, блоки `Правило` по правилам карты, сценарии, `Структура сценария` там, где одно правило проверяется разными данными.

**Сборка - составление, а не трансляция строка в строку.** Общий фон, таблица примеров, дробление склеенного критерия на два сценария - решения о форме, и они твои. Решения о содержании - не твои: случая, аспекта или исхода, которого нет в AC, в файле не появляется. Вскрыл нехватку - наверх находкой к story.

**Exit criteria:** шапка несёт путь источника и ревизию; при русских ключевых словах первая строка `# language: ru`; **каждому сценарию найдено соответствие в AC источника**, обратное соответствие названо (какие AC собраны, какие нет и почему); в `Предыстории` только состояние; в каждом сценарии одно событие; имя сценария называет случай и исход, а не перечисляет шаги; полный перебор комбинаций в `Примеры` не вынесен.

**Mandatory:** yes - карта без записанных примеров остаётся устным разбором и исчезает вместе с сеансом.

## Phase 3: Trace

**Goal:** Связать примеры с требованиями и показать пробелы покрытия.

**Output:** тег трассировки на `FR-NNN` у каждого сценария; таблица соответствия: какое AC собрано каким сценарием, какое не собрано и почему.

**Exit criteria:** каждый тег разрешим - требование существует в текущем SRS; каждое AC источника имеет явный исход (собрано либо названа причина); правило, обнаруженное при разборе примеров и не записанное ни в одном требовании, вынесено наверх находкой. Покрытие требований здесь не пересчитывается: оно посчитано по AC на гейте stories, и второй счёт по производной форме давал бы два числа об одном.

**Mandatory:** yes - непроставленная трассировка делает соответствие непроверяемым в обе стороны: не видно ни AC, оставшихся без сценария, ни сценария, потерявшего основание.

## Phase 4: Validate

**Goal:** Прогнать самоконтроль и собрать выход.

Самоконтроль идёт по норме pre-loaded `bdd-gherkin` - разделы состава, стиля шага и проверок содержания. Отдельного оракула у производной формы нет и метку `quality-checks` она не носит: порог берёт источник (`node-contract`, «Производная форма собственного типа не получает»). Дефект устраняется здесь; неустранимый - в выход перечнем.

Загрузи `dex-skill-docs-layout:docs-layout`, если расположение корпуса не пришло со входом: файлы кладутся в `04-verification/bdd`, файл на фичу.

**Output (handoff):** по контракту `node-contract` первым полем `status`, затем пути файлов, карта примеров с оставшимися вопросами, таблица покрытия, находки наверх, плюс `quality-checks` (сквозное поле, переносится со входа как есть; своей записи автор не делает) и `self-check`.

**Exit criteria:** файлы сохранены; самоконтроль по норме жанра прогнан и его исход зафиксирован в `self-check`; вопросы карты, оставшиеся без ответа, перечислены как нехватка воли постановщика и адресованы наверх; находки к источнику вынесены отдельным перечнем; `status` заполнен.

**Mandatory:** yes - незакрытый вопрос карты, не вынесенный наверх, превращается в поведение, утверждённое молча зелёным тестом.

## Boundaries

- **Красная карточка не закрывается автором.** Вопрос, оставшийся с разбора, идёт наверх; догадка, записанная исполняемым сценарием, становится нормой без решения - тест зелёный, поведение утверждено молча.
- Не автоматизировать шаги: реализация step definitions - работа этапа разработки, здесь только текст примеров.
- Не заводить требования: обнаруженное правило без основания уходит наверх находкой.
- **Не вводить содержание сверх источника.** Случай, аспект или исход, которого нет в AC, сценарием не становится: производное, дополненное собственным содержанием, источником быть перестаёт, и расхождение больше не снимается пересборкой.
- **Не править источник и не чинить расхождение в файле точечно.** Ревизии разошлись -> файл помечается устаревшим и пересобирается целиком; правка одного сценария оставляет остальные на прежней ревизии, а шапка называет одну.
- Не проверять внутренности системы в `Тогда`: сценарий, проверяющий таблицу базы, ломается при рефакторинге, не меняющем поведение.
- Не выносить полный перебор комбинаций в `Примеры`: его дом - юнит-тесты.
- Не ставить вердикт своему набору: `self-check` вердиктом не является.
