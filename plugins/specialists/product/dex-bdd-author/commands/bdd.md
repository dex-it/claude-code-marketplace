# /bdd

Разобрать правила фичи примерами и записать их исполняемым текстом. Работу ведёт `dex-bdd-author:bdd-author`.

## Goal

Получить `docs/04-verification/bdd/{фича}.feature` с картой примеров, тегами на `FR-NNN` и прогнанным оракулом примеров.

## Input

Аргумент - фича. Не указана - спросить.

**Входной контракт несёт два указателя, а не один:**

- **путь к SRS фичи** - источник правил, которые иллюстрируются примерами;
- **путь к журналу гейтов** этой фичи - находки пройденных гейтов с их статусом.

Дополнительно, если есть: путь к сценариям `UC-{ФИЧА}-NNN` - расширения сценария дают готовые случаи для примеров; стек исполнения и язык ключевых слов - иначе берутся из конвенций проекта.

Журнал не найден - сказать явным пунктом выхода и продолжить; SRS недоступен -> остановка: пример без правила проверяет мнение автора.

## Output

- карта примеров: правила, примеры, **оставшиеся вопросы отдельным перечнем**;
- файл `.feature` на фичу;
- таблица покрытия: какое `FR` получило пример, какое нет и почему;
- `self-check` с результатом прогона `scenario-quality`.

**Красная карточка карты наверх, а не в сценарий.** Вопрос, оставшийся без ответа, - нехватка воли постановщика: догадка, записанная исполняемым сценарием, становится нормой без решения. Метку `quality-checks` ставит судья.
