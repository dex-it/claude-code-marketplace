# /review-plan

Провести полученное на свой MR/PR ревью от сбора ревизии до правок и ре-ревью дельты. Не только план -
код правится, ответы публикуются.

## Input

Аргумент - ссылка на MR/PR или short-id. Опционально `REVIEW_SHA`, если sha момента ревью не
выводится из истории комментариев. Аргумент не передан -> запроси ссылку первым вопросом.

## Порядок делегирования

Ревизию ведёт главный поток: канал к оператору и команды цикла (`делай` / `отвечай`) есть только у
него. Узлам вниз идёт планка эскалации `interactive`, но не канал.

1. `dex-review-planner:review-planner` - сбор комментариев ревизии полным контекстом (не выборкой), классификация
   (actionable / clarify / disputed), верификация чтением кода до снятия находки, план правок
   P0..P3 с blast radius, черновики ответов. Код и треды узел читает сам.
2. **Правки по плану** - после команды `делай`: правку ведёт кодер своего стека
   (`dex-dotnet-coder:dotnet-coder` `[справочно]`,
   `dex-ts-fullstack-coder:ts-fullstack-assistant` `[справочно]`), стек определяется по манифесту
   репозитория. Security-находка идёт не кодеру, а
   `dex-security-reviewer:security-reviewer`: у неё своя модель угроз и свой порог достаточности.
   Кодера своего стека в установке нет - `blocked` с именем недостающего плагина, а не правка
   главным потоком.
3. **Публикация ответов** - после команды `отвечай`, reply с sha фикса; resolve только после
   подтверждённого фикса.
4. `dex-mr-check-reviewer:mr-check-reviewer` - ре-ревью дельты: статус по каждой находке прошлой ревизии. Без него ревизия
   не закрывается.

## Output

- Контекст ревизии: сколько комментариев по приоритетам, менялась ли задача, что докоммичено
- План правок P0..P3 с файлами, blast radius и риском регрессии
- Правки по плану (коммиты), вопросы к ревьюеру (clarify), снятые замечания (disputed) с основанием
- Опубликованные reply в треды, статус resolve по каждому
- Ре-ревью дельты: статус по каждой находке прошлой ревизии
- Каждая находка несёт явный исход (fixed / disputed / clarify / not-in-scope), не молчание

## Constraints

- Неоднозначный комментарий идёт в clarify, не трактуется за ревьюера
- Гейт scope - ничего сверх замечаний; соседний баг вне ревью - в наблюдения, не в план и не в правку
- Конфликт с базовой веткой - вызови `Skill` -> `dex-skill-merge-conflict-resolution:merge-conflict-resolution`
  и веди интеграцию по его протоколу, на глаз не разрешается
- До команды `отвечай` ни одной записи в MR
- Ревьюер не ответил на довод отклонения либо автор не разъяснил неясное - агент ждёт ответа и сам
  находку не закрывает: ни своим решением, ни правкой за другую сторону, ни трактовкой молчания как
  согласия; ревизия закрытой не считается. Чего ждём - перечнем с адресом треда. Канала к оператору
  нет (спавненный узел, `autonomous`) - тот же перечень уходит наверх статусом `blocked`
- Ревизия не закрывается без ре-ревью дельты; 5 циклов - потолок, дальше эскалация оператору
