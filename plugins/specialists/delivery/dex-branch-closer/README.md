# dex-branch-closer

Языко-агностичное закрытие разработки в ветке: от готовых локальных коммитов до открытого MR. Отвечает на вопрос «что значит, что разработка в ветке закрыта» - шесть шагов, у каждого исход: выполнен, `n/a` с причиной (процесса нет в проекте) или `blocked` с названной попыткой. Merge, ожидание апрува и обработка пришедшего ревью - вне границы.

## Команда

`/develop-finish [целевая база] [ветка]` - закрыть текущую ветку. База не угадывается: не названа и не выводится из конвенции проекта - агент возвращает блокер, потому что MR в чужую базу исправляется дороже, чем не открытый MR.

## Архитектура

Команда делегирует агенту `branch-closer` (Diagnose -> Branch -> Execute -> Verify, рецепт Operator). Интеграция базы делегируется дальше узлу-интегратору `conflict-resolver`: тип узла - интегратор, не coder.

Порядок шагов Execute - предмет нормы, а не стиль: база подтягивается **до** прогона (зелёный прогон до слияния о слитом состоянии не говорит ничего), push отделён от открытия MR (push обратим, MR - заявка на чужое время), трекер сводится последним по факту открытого MR. Verify подтверждает каждый шаг чтением состояния системы - удалённая ветка через `git ls-remote`, MR через канал хостинга (native MCP приоритетом, фолбэк `gh`/`glab`), задача через трекер: «команда отработала» не равно «состояние такое».

Описание MR собирается из носителя состояния зоны (`auto-ledger` движка, `decision-log` зоны требований), не из памяти сессии: закрытие ветки - отдельный вызов, выход предыдущей команды в нём не виден. Чего в носителе нет, помечается `unverifiable`, а не реконструируется по смыслу.

## Skills

`dex-skill-branch-closure` (pre-load: норма закрытия - состав и порядок шагов, граница push/merge, источник содержания MR, статусы выпавших шагов), `dex-skill-node-contract` (pre-load: контракт стыка), `dex-skill-git-workflow` в фазе Execute (конвенция коммитов, опасные операции).

## Связанные плагины

- `dex-conflict-resolver` - узел интеграции базы, вызывается фазой Execute.
- `dex-self-reviewer` - предыдущий шаг: pre-push саморевью ветки.
- `dex-skill-autonomous-task` - движок зоны разработки, чей `auto-ledger` служит носителем состояния.
