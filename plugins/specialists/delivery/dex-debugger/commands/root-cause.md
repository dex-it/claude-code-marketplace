# /root-cause

Найти первопричину репортнутого бага по коду и, если правка запрошена, исправить корень с
подтверждающим тестом.

## Input

Симптом и как его наблюдать: stack trace, лог, шаги воспроизведения, ожидаемое против фактического,
окружение. Чего нет - скажи прямо, не додумывай. Стек определяется по манифестам проекта.
Нужна правка кода, а не только диагноз - передай это явно: состав работы не угадывается.

## Порядок делегирования

Расследование ведёт `dex-debugger:debugger`. Вход ему: симптом, ожидаемое поведение (не пришло - пометь, что
эталон реконструирован по коду), поле `apply` - правка кода в составе вызова или только диагноз.
Понадобились runtime-инструменты (профайлер, дамп) - работа передаётся на `/investigate`, здесь она
не имитируется.

## Output

- `status` первым полем (`complete` / `blocked` / `partial`)
- Expected-basis: эталон получен на входе либо реконструирован по коду и не подтверждён - во втором
  случае `status` не выше `partial`
- Находки с `anchor` file:line и evidence, прогнанные по профильным skills стека
- Гипотеза первопричины «если X, то Y, потому что Z», фальсифицированная; техутверждение в её
  основе сверено - `verified` / `unverifiable` / `contradicted`
- Fix: минимальный diff, red -> green тест, статус прогона регрессии - либо предложенный fix с
  названной причиной, по которой он не применён
- Остаточные риски

## Constraints

- Лечить причину, не симптом; обходной путь - только с явной пометкой
- Первопричина не подтверждена фальсификацией - фикс не пишется, это жёсткий гейт
- Глубину под стек дают профильные skills `dex-skill-<стек>-*`, подбираются по реестру стеков
