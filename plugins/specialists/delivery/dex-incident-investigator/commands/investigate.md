# /investigate

Найти доказанную корневую причину инцидента на общем стенде и предложить фикс на источнике.
Режим по умолчанию - только чтение; стенд общий.

## Input

Аргумент - описание инцидента: симптом, сообщение об ошибке, что и как заметили. Опционально ветка
стенда, время начала, доступы. Стек и связи проектов определяются по манифестам и стенду.
Описания симптома нет -> работа не начинается, скажи чего не хватает.

## Порядок делегирования

Расследование целиком ведёт `dex-incident-investigator:incident-investigator` в режиме `interactive` - канал к оператору у
этой команды есть, и развилки предъявляются по ходу, а не уходят в отчёт. Вход ему: симптом,
ожидаемое поведение, ветка стенда и доступы, санкция `deploy` - только если оператор дал её явно.

Улики со стенда собираются профильными плагинами (kubectl, glab, teamcity, grafana, seq) - здесь не
дублируются.

## Output

- Спецификация IS / IS-NOT с моментом начала, хронология, собранные доказательства по источникам
- Причинно-следственная цепочка до структурной причины с severity и confidence
- Проблемы и план фикса на источнике, с фальсификацией самого фикса
- После команды `фиксируй` - серия правок по одной проблеме с верификацией red -> green

## Constraints

- Режим по умолчанию - только чтение; любой эффект на общий стенд - отдельное подтверждение
- Симптом не равно причина: фикс на источнике, не на месте проявления
- Confidence ниже 80 на причине - гипотеза под вопросом, а не объявленная причина
- Корреляция не равно причинность: каждая гипотеза фальсифицируется до принятия

Команды цикла: `оформляй` (полный отчёт), `фиксируй` (фикс по одной проблеме), `стоп`.
