# /rulebook

Собрать свод правил проекта: что в этом репозитории принято - правила ревью, конвенции, гайдлайны, -
выведенное из тредов и последовавших правок. Результат кладётся в корпус документации репозитория по
ключу `rulebook`.

## Input

Аргумент - путь к одному репозиторию, по умолчанию текущий: свод один на репозиторий, и второй
репозиторий - второй прогон. `--window` сужает период истории; без него разность считается по реестру
источников существующего свода, а при первом прогоне берётся вся доступная история. `--publish` даёт
санкцию создать MR со сводом; без неё тело MR готовится и уходит в отчёт, наружу не пишется ничего.
`--approve` даёт санкцию поднять свод до принятого после вердикта оракула; без неё потолок - `review`,
и единицы остаются предложенными.

`--mr` открывает **второй круг** по уже опубликованному своду: прогон не добывает заново, а разбирает
замечания владельца корпуса на этом MR, проводит правки, отвечает в треды и обновляет тот же MR.
Историю ради разметки не перечитывают, и второго MR не заводят: его номер - якорь для тредов и для
реестра источников. `--publish` при этом не нужен: он разрешает **создать** MR, а тут он уже создан и
владелец на нём. Круг повторяется столько раз, сколько владелец возвращает свод, - свод принимается не
с первого предъявления, его предмет договорённость.

## Порядок делегирования

Порядок ведёт главный поток: канал к оператору есть только у него, и гейтов оператору здесь три -
развернуть ли заготовку корпуса, разметка владельца по единицам, «ок» на текст описания MR. Узлам
вниз идёт планка эскалации `interactive`, но не канал: невыводимое они возвращают сюда.

1. **Адрес корпуса** - `dex-skill-project-docs-map:project-docs-map`, ключ `rulebook` в раскладке
   репозитория. Ключа нет -> заготовка дерева предлагается оператору; отказ терминален, свод мимо
   раскладки не пишется.
2. **Добыча** - `dex-rulebook-miner:rulebook-orchestrator` через `Agent`: окно, чтение существующего
   свода, спавн read-only сборщиков по партиям источников, фальсификация кандидатов по якорю, запись
   корпуса. Дальше вердикт `dex-skill-rulebook-quality:rulebook-quality`: оракул судит документ, не
   правила по существу; `failed` -> возврат на добычу с находками, не публикация с оговоркой.
3. **Публикация** - только после `--publish` и «ок» оператора на текст описания: MR со сводом и
   строкой-указателем на него в файле контекста репозитория. Канал - нативная интеграция хостинга,
   фолбэк `gh` / `glab`; ошибка публикации - стоп и доклад.
4. **Круг доработки** (`--mr`) - разбор замечаний владельца ведёт этот поток: по каждому треду класс
   замечания, фактическая часть проверяется, нормативная принимается. План правок уходит тому же
   оркестратору правочным прогоном; ответы в треды идут после правки, не до.

## Output

- Индекс свода: действующая схема таксона с версией, строка на каждое правило с идентификатором,
  формулировкой, таксоном, областью применения, статусом и признаком принуждения
- Разделы таксона: единицы `RUL-NNNN` целиком - формулировка в повелительной форме, дословная цитата
  источника со ссылкой на тред или коммит, область применения, контрпример из истории репозитория
- Реестр источников: исход у каждого разобранного MR, треда и коммита, включая «правила не дал» с
  основанием - по нему следующий прогон отличает непросмотренное от разобранного
- Наблюдения: кандидаты, не ставшие правилами, и расхождения принятого с внешней практикой
- Указатель на свод в файле контекста репозитория: строка с адресом и ролью свода, без копии правил
- Круг доработки: по каждому треду владельца - класс замечания, что сделано, чем закрыто, ответ

## Constraints

- Правило без якоря на источник в свод не пишется: оно уходит в перечень кандидатов отчёта
- Правило, выводимое из кода, конфига или прогона инструмента, в свод не идёт - идёт признаком
  принуждения
- Принятое в репозитории не отбрасывается по внешней рекомендации; расхождение с ней называется
  отдельным перечнем
- Свод судит оракул, не автор; подъём до принятого - по санкции `--approve`, потолок без неё - `review`
- Противоречие между единицами и правка уже принятого - решение владельца корпуса, а не прогона
- Фактическая часть замечания владельца проверяется, нормативная принимается: «это уже ловит
  анализатор» - утверждение с носителем, а не указание; носитель не найден - правило возвращается с
  доказательством, а не остаётся снятым
- Требование, меняющее не свод, а сам жанр (схему таксона, состав корпуса), этим прогоном не
  исполняется и уходит в выход с названным адресатом
- Замечание, снятое ревьюером после правки, закрывается проверкой «не внесено ли уже»: в предмете
  живёт изменение, за которым не стоит никто
- Свод существует на уровне репозитория: два репозитория одного продукта ведут свои своды
- До санкции `--publish` наружу не пишется ничего; на круге доработки ответы в треды владельца
  санкцией `--publish` не гейтятся - MR создан им
