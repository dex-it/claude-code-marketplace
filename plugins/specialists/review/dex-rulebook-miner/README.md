# dex-rulebook-miner

Добыча свода правил проекта из истории ревью: что в этом репозитории принято - правила ревью, конвенции, гайдлайны, - выведенное из тредов и последовавших правок, а не из памяти модели.

Плагин несёт два агента. Оркестратор ведёт окно, читает существующий свод, спавнит сборщиков, сводит кандидатов, фальсифицирует каждого по якорю, отдельной фазой ищет то, на что ревью не смотрит, и пишет корпус. Сборщик разбирает партию источников и возвращает кандидатов; на диск он не пишет - `Write` ему не выдан, а запрет держится нормой, не набором инструментов: `Bash` у него есть под чтение истории.

Тот же оркестратор исполняет **правочный прогон**: пришёл план правок по разметке владельца корпуса - историю он не перечитывает и сборщиков не спавнит, а правит написанное и заводит единицы со слов владельца, с якорем на его комментарий.

## Команда

`/rulebook` - в этом же плагине. Порядок работ ведёт главный поток: санкции публикации и приёмки, разметка владельца корпуса и «ок» на текст описания MR - это канал к оператору, и он есть только у него.

## Архитектура

```
/rulebook              -> главный поток -> Agent -> rulebook-orchestrator -> rule-collector x N
/rulebook --mr <url>   -> главный поток (разбор замечаний владельца)
                                        -> Agent -> rulebook-orchestrator (правочный прогон)
```

Оркестратор - единственный писатель корпуса: два писателя выдали бы два номера одному правилу. Сборщики read-only и работают каждый по своей партии источников, возвращая исход по каждому источнику отдельно.

## Skills

Оркестратор поднимает норматив жанра безусловно (состав свода и атрибуты единицы) и контракт стыка узлов; сверку внешней практики - через скилл сверки фактов в своей фазе. Сборщик поднимает ловушки добычи до формулирования кандидата.

## Требования

Доступ к истории репозитория: нативная интеграция хостинга либо его CLI. Ни того ни другого - узел возвращает `blocked` с указанием недостающей операции, а не читает то, до чего дотянулся.

Своего исполняемого скрипта сбора плагин не везёт. Исполняемый файл в поставке каталога существует только как обработчик события платформы, а команда по норме каталога скриптом не является: сбор идёт вызовами CLI хостинга из тела узла. Ограничение названо здесь, чтобы отсутствие скрипта не читалось пропуском.

## Отличие от соседей

| Плагин | Предмет | Выход |
|---|---|---|
| `dex-rulebook-miner` | что в репозитории принято | свод правил проекта |
| `dex-code-discovery` | что в коде не так | инвентаризация проблем |
| `dex-mr-reviewer` | суждение об одной чужой правке | треды в MR |

Дефект кода в свод не пишется, правило проекта не подсвечивается находкой ревью.

## Связанные плагины

Норматив жанра и оракул свода едут вместе с плагином; карта документации проекта даёт адрес корпуса по ключу.
