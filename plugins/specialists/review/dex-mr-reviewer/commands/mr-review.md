# /mr-review

Провести чужой merge request или pull request от сбора контекста до публикации находок инлайн-тредами,
включая повторные ревизии после правок автора.

## Input

Аргумент - ссылка на MR/PR или short-id (`owner/repo#N` для GitHub, `group/project!N` для GitLab).
Опционально текст задачи для сверки success criteria (первая ревизия) или `LAST_REVIEW_SHA`, если sha
прошлой ревизии не выводится из истории комментариев. Платформа определяется по форме ссылки.
Аргумент не передан -> запроси ссылку первым вопросом.

Необязательные поручения, каждое едет узлу одноимённым полем; ни одного не передано - ревью идёт
ровно как раньше, форма находок не меняется:

- `--classify` - разметить находки типом по закрытой схеме. Без значения берётся встроенная схема
  каталога; со значением - каталог проекта по этому адресу (путь, ключ карты документации либо URL).
- `--breakdown <путь>` - сложить результат ревью носителем разбора: единица на тред, отчёт на MR.
- `--form <схема>` - форма записи разбора: путь к файлу схемы либо её содержимое. Имеет смысл только
  рядом с `--breakdown`; без него - отказ с причиной, а не молчаливый пропуск. Формы нет - разбор
  пишется встроенным составом.

Отправки разбора наружу у команды нет: файл - её результат, а доставку дальше делает тот, кто
разбор заказал.

## Порядок делегирования

Ревизию ведёт главный поток: канал к оператору и команды цикла (`оформляй` / `пушь` / `полный`) есть
только у него. Узлам вниз идёт планка эскалации `interactive`, но не канал - невыводимое они
возвращают сюда.

1. **Первый вызов на этом MR** - `dex-mr-reviewer:mr-reviewer`: контекст и diff, карта изменений, скан по осям,
   фальсификация, severity / confidence / scope, черновики тредов. Код узел читает сам, ему идут
   указатели (URL/ID + SHA) и intent.
2. **Тот же MR после правок автора** - `dex-mr-check-reviewer:mr-check-reviewer`, не первичный ревьюер заново: range-diff
   от `LAST_REVIEW_SHA`, статус прежних находок, новые находки только в дельте. Исход находки
   («исправлено» / «ушло как есть») определяется здесь: у первой ревизии его ещё нет, и разбор,
   написанный только ей, несёт «неизвестно» по каждой единице законно. `--breakdown` и `--form`
   едут и сюда: узел обновляет тот же носитель исходами ревизии, в том числе после слияния MR.
3. **Безопасность** - `dex-security-reviewer:security-reviewer`, когда diff трогает аутентификацию,
   авторизацию, обработку внешнего ввода, секреты или границу доверия: модель угроз и attack-path
   ревьюер общего профиля не строит. Diff их не трогает - строка «security: n/a» с указанием, по
   чему судили.
4. **Публикация** - после команды `пушь`, через канал хостинга (native MCP, иначе `gh` / `glab`).

## Output

- Verdict (APPROVE / REQUEST_CHANGES / NEEDS_DISCUSSION) и overview со счётчиком меток
- Сгруппированные находки с severity, confidence, scope и метками
- Повторная ревизия: diff-обзор - закрыто / осталось открытым / новое по severity, статусы прежних
  находок (closed / partial / open / disputed / no-longer-applicable)
- После команды `оформляй` - план инлайн-тредов (file:line, severity, заголовок) либо апдейтов
- После команды `пушь` - опубликованные треды / reply
- При `--classify` - тип у каждой находки, схема разметки с версией, перечень находок без типа
- При `--breakdown` - путь носителя разбора, число единиц, неполные единицы, при `--form` - её версия

## Constraints

- До команды `пушь` ни одной записи в MR; чужие треды не трогать, approve/unapprove не делать
- Находка снимается только опровержением; низкий confidence уводит её в блок «перепроверить»
- Повторная ревизия работает по дельте; полный ре-ревью только по явной команде `полный`
- Регрессия от фикса прошлой ревизии - severity не ниже HIGH; severity прежних находок не менять без
  причины из нового кода или ответа автора
- На ошибку публикации на любом канале - стоп и доклад, без отката на один общий комментарий
- Разбор пишется после публикации тредов: ключ его единицы - идентификатор треда, выданный хостингом.
  Треды не опубликованы - разбор остаётся с черновыми ключами и помечен недоставляемым
- `--classify` поиск не сужает: оси ревью проходятся в полном охвате, разметка идёт отдельным
  проходом по готовому перечню находок
- Адрес каталога или форма записи недоступны - подстановки встроенной схемы или встроенного состава
  не бывает: исход называется
