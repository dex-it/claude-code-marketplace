# /review-design

Провалидировать и согласовать чужой дизайн-документ **до** написания кода.

## Goal

Провести документ через фазы агента `design-reviewer`: Context (входная приёмка по метке `quality-checks`) -> Domain Priming -> Skill-Based Deep Scan (оракулы по аспектам) -> Set Review (набор как целое) -> Fact Verification -> Cross-Linking -> Severity Calibration -> Deferred Decision Triage -> Output Labeling -> Report.

## Input

Аргумент - путь к дизайн-документу (спека, ADR, диаграмма) либо к каталогу с ними. Опционально второй аргумент - источник требований (BRD, stories, задача) для сверки «дизайн решает поставленное». Источник не передан -> ось `intent: n/a`, дефекты самого документа проверяются как обычно.

**Набор передаётся агенту целиком.** В поле `set` уходит перечень путей всех артефактов работы - дизайн, ADR, спеки: полнота и непротиворечивость набора судятся только с этого уровня, а по одному документу дыра между документами не видна. Передан один файл -> в `set` уходит собранный по каталогу состав, и агент называет в отчёте, что вошло в осмотр.

## Output

- Verdict (APPROVE / REQUEST_CHANGES / NEEDS_DISCUSSION) и счётчик меток; отдельной позицией - вердикт по набору с перечнем осмотренных артефактов
- Находки, сгруппированные по корневой причине: якорь-цитата раздела документа, severity, confidence, метка 🟢🟡🟠🔴🟣, минимальная правка
- Перечень правок для автора - что и в каком разделе поправить
- Блок пропущенных проверок со статусами (`n/a` / `unverifiable` / без проверки skill)

## Constraints

- **НЕ дубль `/review-arch`.** Тот ревьюит архитектуру **реализованного кода** (стек по манифестам, N+1, циклические зависимости, находки с `file:line`); этот - **дизайн-документ до кода**. Запрос на ревью кодовой базы -> перенаправить на `/review-arch`, предмет не подменять.
- В судимый документ ничего не пишется: `Edit` у агента отсутствует, `Write` - только для файла-метки `<имя>.checks.md` рядом с артефактом. Правки формулируются, вносит автор или оператор.
- Находки предъявляются оператору до формулирования правок автору; канал доставки (задача в трекер либо правка в документ) выбирает оператор, агент его не выбирает молча.
- Возражение автора - claim: снимается только проверкой по тексту документа и названным им источникам, не по «звучит обоснованно».
- Альтернативный дизайн не разрабатывается: нужен новый дизайн -> `/design`.

Делегировать агенту `design-reviewer` с **`mode: interactive`** во входе (команда исполняется главным циклом - канал к юзеру есть; без явного `interactive` агент уйдёт в дефолтный `autonomous` и не будет предъявлять находки оператору и выбирать канал доставки).
