# /discover

Обзорное (breadth-first) ревью существующего кода: инвентаризация проблем по топикам, результат в
`docs/discover/`. Не глубокая верификация под рефактор и не ADR-планы.

## Goal

Дать карту проблем проекта вширь: по каждому релевантному топику - находки с приоритетом разбора
(P0-P3), сводный мастер-док с порядком разбора.

## Input

Аргумент - путь к проекту (по умолчанию текущая директория). Без фильтров: обзор всегда идёт вширь
по всем релевантным стеку топикам. Углубление в область - отдельным инструментом по результату.

## Порядок делегирования

Работу целиком ведёт `dex-code-discovery:discover-orchestrator`: детектит стек и масштаб, спавнит `dex-code-discovery:discover-reviewer`
по топикам, связывает находки кросс-топиково, калибрует severity под масштаб, пишет отчёты.
Вход ему: путь к проекту, при наличии - исключаемые области и путь записи. Собственных находок
поверх его отчёта не добавляй.

## Output

`docs/discover/README.md` - мастер-док: карта стека и масштаба, таблица выбранных топиков, сводная
карта приоритетов P0-P3, executive summary, рекомендуемый порядок разбора.

`docs/discover/NN-<топик>.md` - на каждый топик: «что смотрим», таблица находок (`severity ·
находка · якорь file:line · маркер /? · рекомендация`), краткие рекомендации.

Severity - P0-P3 (приоритет разбора, не гейт на мёрдж), калиброванный под масштаб. Маркеры
доказанности обязательны: подтверждённый код прочитан целиком, под вопросом - по grep без полного
аудита.

## Constraints

- Калибровка меняет уровень находки, не вычёркивает её. Надёжность и безопасность по масштабу не
  понижаются
- Дефолт подсветки: нет явного маркера accepted tech debt (TODO+тикет, ADR, пометка в проекте) ->
  находка подсвечивается, не принимается молча
- Рефакторинг-планы и ADR тут не пишутся - это обзор
- Стек не определён -> спроси; и после этого не ясен (нет манифестов, README, понятной структуры) ->
  пройди универсальные топики «Архитектура и слои» и «Качество кода и тестируемость», пометив в
  мастер-доке, что стек не детектирован
