# Bundle: dex-bundle-market-editor

Бандл для того, кто правит **сам каталог**, а не работает с его плагинами: автор скилла, агента или
команды, редактор маркетплейса. Собран вокруг одного предмета - **нормы**: как нормативная единица
пишется, чем судится и как подаётся. Предмет нормы здесь двойной - артефакт каталога (`SKILL.md`,
`agents/*.md`, `commands/*.md`) и корпус документов уровня 0 самого каталога (ценность, словарь,
конституция, конвейеры). Нормы, по которым артефакт судится, живут в `docs/` каталога и вместе с
плагином не устанавливаются - поэтому состав не едет в бандлы разработчика: у пользователя они
неприменимы, а работа над каталогом идёт в локальном клоне.

Цикл автора: единица пишется или переписывается целиком -> `norm-writing` (форма единицы и бюджет
правки: приписка вместо правки, цитата чужой нормы, перечень вместо признака) -> `optimize-for-llm`
(рез подачи без потери нормативной силы) -> `fact-verification` (сверить утверждения об
инструментах) -> `artifact-review` (ревью по осям фреймворка) -> `npm run validate && npm test`.
Порядок между первыми двумя задан: рез недописанной единицы уносит ненаписанный терминал ветки
вместе с водой. Отдельная ветка - `/mr-collect` -> `/mr-analyze` -> `/mr-apply`: уроки из чужих MR
превращаются в предложения по скиллам и агентам каталога.

## Installation

```bash
# Linux / macOS / WSL
./install-bundle/install-bundle.sh market-editor

# Windows (PowerShell)
.\install-bundle\install-bundle.ps1 market-editor

# Preview без установки
./install-bundle/install-bundle.sh market-editor --dry-run
```

## Uninstallation

```bash
./install-bundle/uninstall-bundle.sh market-editor
.\install-bundle\uninstall-bundle.ps1 market-editor
```

## Included Components

Полный состав - `bundle.json`: `includes[]` (профиль роли) плюс `dependencies[]` (подтянутое
замыканием). Авторские артефакты перечислены там же отдельным списком `authorOnly[]`, и разница
списков нормативна: `authorOnly[]` - единственный источник исключения из `catalog-docs-link`, а
попадание такой записи в бандл роли ловится правилом `author-only-in-user-bundle`.

### Skills: норма артефакта каталога
- `dex-skill-norm-writing` - формирование нормативной единицы: бюджет правки (носитель не растёт,
  рост закрывается снятой взамен единицей либо статусом), адрес дома соседней нормы вместо её
  цитаты, признак предмета вместо перечня случаев
- `dex-skill-artifact-review` - ревью артефакта каталога по обязательным осям: соответствие
  фреймворку, fact-check, полезность против целей продукта, лаконичность, сверка с гайдом модели;
  ось формы единицы грузит `norm-writing`, ось лаконичности - `optimize-for-llm`
- `dex-skill-optimize-for-llm` - рез подачи: срезать воду и дубли, сохранить нормативную силу,
  ловушки и поле срабатывания. Дом реза; форму единицы он не судит
- `dex-skill-fact-verification` - сверка утверждений об инструментах и API первоисточником; ось
  fact-check у `artifact-review` держится на нём

### Skills: норма корпуса документов
Редактор каталога ведёт и его собственный корпус уровня 0 - ценность, словарь, конституцию,
нормативы конвейеров, - поэтому нормы корпуса стоят в профиле, а не приезжают хвостом:

- `dex-skill-project-docs-map` - карта корпуса: какой документ где лежит и кто его дом
- `dex-skill-docs-layout` - раскладка документа и разделов, границы между документами корпуса
- `dex-skill-artifact-naming` - имена артефактов корпуса и их файлов
- `dex-skill-unit-identity` - идентификаторы единиц (`BR-NNN`, `INV-NNN` и соседние): выдача,
  стабильность, трассировка

### Utility
- `dex-knowledge-extractor` - `/mr-collect`, `/mr-analyze`, `/mr-apply`: review-комментарии чужих MR
  -> обобщённые предложения для skills и агентов каталога -> применение с саморевью и валидацией

### Замыкание (`dependencies[]`)
- `dex-skill-node-contract` - рантайм-контракт узла (режим, статусы, метка `quality-checks`);
  назван телом `docs-layout` там, где раскладка упирается в ревизию и пороги допуска

## Замечания

- Пересечение составов бандлов - норма, установка плоская. `optimize-for-llm` едет также в
  `code-review`, `dotnet-developer` и `dotnet-fullstack`, нормы корпуса и `node-contract` - в
  бандлах ролей, где корпус ведут аналитики: они применимы к любому корпусу, не только к нашему.
- Оси `artifact-review` ссылаются на `docs/SKILL_FRAMEWORK.md`, `docs/AGENT_FRAMEWORK.md` и
  `docs/COMMAND_FRAMEWORK.md` **каталога**. Они разрешаются в локальном клоне репозитория; вне его
  скилл теряет нормативный дом цифр и лимитов.
- Ревьюер-агенты каталога (`dex-mr-reviewer`, `dex-mr-check-reviewer`, `dex-self-reviewer`)
  `artifact-review` не грузят: для артефактов каталога он и есть ревьюер, и вызывается напрямую.
