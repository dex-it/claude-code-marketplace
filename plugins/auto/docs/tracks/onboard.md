# Трек onboard: спецификация

Эталон для скрипта `dex-auto/tracks/onboard.js`, узлов `agents/scaffolder.md`, `agents/onboarder.md`, сверщика
`agents/corpus-checker.md` в этом треке и сценариев `tests/tracks/run.mjs` (префикс `O`). Ledger трек не пишет,
продуктового кода не меняет, кроме скелета пустого проекта со стеком. Код и сценарии сверяются с этим документом, не наоборот.

Статус документа: **эталон**, сверен с кодом и сценариями O1-O24 21.10.2026; живым прогоном узлы не сверены.
Цель - BR-AUTO-005 (`../brd.md`).

## 1. Назначение и граница

Проект, в который входит агентская работа, имеет корпус - раскладку, `.docs_layout`, счётчик - и уровень 0: BRD
продукта и ADR решений устройства, видимых в коде, единицами `status: review`; предмет, которого не вывести, назван.
Пустой проект со стеком в описании до этого получает скелет на нём, и сборка с тестами скелета зелёные.

- Трек зовёт команда `/onboard` (`commands/onboard.md`); пустоту проекта и стек решает команда, блок `CLAUDE.md` пишет
  команда, не трек (§6).
- Скелет - технический: сборка, модуль, тест со smoke-тестом, гейты, CI. Бизнес-код, архитектурный стиль и
  разбиение на слои - вне трека.
- Существующего трек не правит и не переносит: единица корпуса, описывающая предмет, - `covered`, расходящаяся с
  кодом - `conflicts`; значения существующих ключей раскладки не правятся, недостающие ключ и счётчик дописываются; раскладка, отличная от дерева нормы, - строками `layout`.
- Дельту судит сверщик трека record (`corpus-checker`): предмет полноты ему называет вход.
- Правил проекта трек не выводит из кода и свода не собирает: документ проекта, объявленный нормой, составитель
  называет строкой `rules`; свода нет - непустому проекту команда предлагает собрать его из истории ревью (§6).
- **Скрипт решает только по фактам:** форма входа, исход вызова узла, `status`, перечни выходов, счётчики верификации.
- Вне трека: апрув единиц, выбор стороны в расхождении корпуса с кодом, push - оператор.

## 2. Вход

`args`: `cwd` обязателен; по желанию - `brief` (описание продукта оператором), `stack` (проект пуст, скелет на этом
стеке), `scripts` (каталог скриптов плагина, `verify.py`). Каждое поданное - строка, `stack` - непустая.

## 3. Узлы

| Узел | Агент | Модель и effort | Выход |
|---|---|---|---|
| скелетник | `dex-auto:scaffolder`, **без замены** | сессии | `status`, `files`, `skipped`, `build_cmd`, `test_cmd`, `report_cmd`, `commit`, `decisions`, `missing` |
| верификатор скелета | общий | `haiku`, `low` | схема `VERIFY` (`tracks-shared/verify.js`) |
| составитель | `dex-auto:onboarder`, **без замены** | сессии | `status`, `corpus-status`, `layout`, `units`, `covered`, `unrecorded`, `conflicts`, `map`, `rules`, `guards`, `commit`, `decisions`, `missing` |
| сверщик | `dex-auto:corpus-checker`, **без замены** | сессии | `status`, `corpus-status`, `corpus-basis`, `checks`, `missed`, `foreign`, `decisions`, `missing` |

Контракт узла - его файл; каждое поле схем скелетника, составителя и сверщика названо в нём, у этих схем описаний
нет (O14). Предмет входа - общий блок файлов составителя и сверщика (O14). Схема сверщика и разбор его вердиктов -
общий блок с треком record; схема и зелень верификатора - общий блок с треками feature и bugfix.

## 4. Переходы

Выход: `{status, where, scaffold, unverified, skipped, corpus, layout, units, derived, covered, unrecorded, conflicts, map, rules,
guards, checks, missed, foreign, secrets, commit, decisions}`; `scaffold` - `commit` скелетника после зелёной верификации, пусто - скелета нет; `unverified` - `commit` скелетника,
не дошедший до зелёной верификации (T5, T6), иначе пусто;
`skipped` - строки скелетника; `corpus` - `corpus-status` составителя (`found` | `deployed`); `derived` - `id` единиц
с `origin: derived`, к приёмке оператором; `decisions` - решения узлов с пометкой узла, кроме составителя; `where` -
нехватки через `; `.

## 5. Инварианты

- **I1.** Продуктовый код и тесты трек меняет только коммитом скелетника и только при поданном `stack` (T3); файл вне
  корпуса, его раскладки и счётчиков в коммите составителя - `blocked` (T13, O9).
- **I2.** Апрува трек не выдаёт: записанная единица - `status: review` (файл составителя), выведенная из кода - в
  `derived`.
- **I3.** Каждый узел вызывается не больше одного раза; правки по вердикту сверщика и по красной верификации нет.
- **I4.** Существующую единицу корпуса и значения существующих ключей его раскладки трек не правит: `covered`, `conflicts` (T15, O7), `layout` (O2). Недостающие ключ раскладки и счётчик составитель дописывает как системные поля нумерации, строкой `layout` они не идут (O14).
- **I5.** Ledger и push трек не трогает.
- **I6.** `where` непуст при `partial` и `blocked`.
- **I7.** Скелет без зелёной верификации до составителя не доходит, его коммит - в `unverified` (T5, T6, O18, O19).
- **I8.** Значения секретов в единицы, `trace` и `decisions` не переносятся, `.env` и ключи составитель не читает; единица с секретом - `contradicted` у сверщика, `secrets` непуст - `blocked` (T13, O22).

## 6. Что делает с исходом команда

Дом - `commands/onboard.md`. Трек зовётся только при чистом дереве репозитория, так что коммиты скелетника,
составителя и `CLAUDE.md` - единственные коммиты вызова; у коммита скелетника трейлер `Dex-Auto-Onboard: scaffold`, у
коммита `CLAUDE.md` - `Dex-Auto-Onboard: flow`, и сверщик их не судит.

- Пустота - факт дерева, решает команда: `git ls-files` без файлов, кроме README, LICENSE, `.gitignore`, `CLAUDE.md`,
  `.docs_layout` и `docs/`; каталог вне репозитория без файлов команда заводит `git init`. Пустой проект -
  `interactive` при любом флаге, если доступен `AskUserQuestion`; стек - только из описания, не назван - скелета нет (O15).
- Блок между маркерами в `CLAUDE.md`: текст `templates/flow.md`, раздел сборки и гейтов (оси - по
  `dex-skill-project-baseline:project-baseline`), разделы карты, правил и запретов из `map`, `rules`, `guards`;
  строка, чей путь в дереве не найден, в блок не идёт. `rules` пуст - строка о своде, у непустого проекта и о
  его сборке `/dex-rulebook-miner:rulebook` (O15).
- `unverified` непуст - команда откатывает этот коммит `git revert`; неотслеживаемые файлы, оставленные сборкой, `git revert` не убирает: команда называет их оператору (`git status --porcelain`), до их удаления повторный вызов остановится на непустом дереве.
- Готовность репозитория - перечень в выходе: каждая ось «есть» либо «нет» с тем, что завести; в непустом проекте
  ничего не заводится.
- `interactive` - оператор принимает дельту либо отклоняет её `git revert` коммитов вызова; исход трека и ответ - в
  выход команды (O15).
