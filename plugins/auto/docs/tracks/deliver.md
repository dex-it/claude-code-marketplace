# Сдача кода `--pr`: спецификация

Эталон для скрипта `dex-auto/tracks/deliver.js`, сценариев `tests/tracks/run.mjs` (префикс `D`) и абзаца
«Сдача кода» `commands/auto.md`, который его вызывает. Скрипт - не трек: ledger не пишет, кода не меняет.
Код и сценарии сверяются с этим документом, не наоборот.

Статус документа: **эталон**, сверен с кодом и сценариями D1-D11 01.10.2026; живым прогоном узел не сверен.
Цель - BR-AUTO-001 (`../brd.md`, MOE: по санкции `--pr` - PR/MR ветки либо названная причина).

## 1. Назначение и граница

Цель feature или bugfix, сданная `complete`, по санкции `--pr` уходит оператору PR/MR своей ветки
`auto/<TASK>`: оператор судит её на хостинге, а не по ledger.

- **Канал выбирает узел** - решение оператора 01.10.2026: что установлено в среде (инструмент хостинга,
  CLI, API), заранее не известно, поэтому push, PR/MR и его описание делает узел, а не скрипт с зашитым CLI.
- **Готовым к ревью, черновиком - по `--draft`**; целевая ветка - `--base`, иначе ветка по умолчанию у
  remote; ревьюер не назначается - решения оператора 01.10.2026.
- **Скрипт решает только по фактам:** форма входа, исход вызова узла, `status`, непустой `url`.
- Вне скрипта: строка `PR:` цели, судьба дерева - главный поток; merge, approve - оператор.

## 2. Вход

`args`: `task, track, branch, base, draft, goal_path, cwd`.

- `track` - `feature` | `bugfix`; файл трека - `01-<track>.md` рядом с `goal_path`.
- `branch` - ветка дерева трека, `auto/<TASK>`; `cwd` - дерево трека на этой ветке.
- `base` - целевая ветка из `--base`, иначе не подаётся; `draft` - `true` по `--draft`.

## 3. Узел

| Узел | Агент | Модель и effort | Выход |
|---|---|---|---|
| сдача | `dex-auto:deliverer`, **без замены** | `sonnet`, effort сессии | `status`, `url`, `channel`, `head`, `missing` (D1, D9) |

Контракт узла - его файл; схема держит форму без описаний (D9). Инструменты - чтение, `Bash` и `ToolSearch`
(инструмент хостинга - отложенный тул), без записи файлов (D9).

## 4. Переходы

Выход скрипта: `{pr, reason, url, channel, head}`; `pr` - `opened` | `not-opened`.

| # | Условие | Действие | Выход | Сценарии |
|---|---|---|---|---|
| T1 | `args` не объект; `task`, `track`, `branch`, `goal_path` или `cwd` пусто либо не строка; `track` не `feature`/`bugfix`; `branch` не `auto/<TASK>` (символы вне `A-Za-z0-9-` - `-`, как `dexauto.branch_of`); `goal_path` не `00-goal.md`; `base` не строка; `draft` не логическое | узел не вызывается | `not-opened`, `reason` «вход сдачи не разобран: ...» | D3, D10 |
| T2 | иначе | узел: TASK, ветка, каталог, целевая ветка либо «не названа», черновик либо «готовым к ревью», пути цели и файла трека | - | D1, D2 |
| T3 | узел упал ошибкой платформы | замены нет | `not-opened`, «узел сдачи <агент> не отработал: <ошибка>» | D4 |
| T4 | узел вернул `null` | - | `not-opened`, «узел сдачи не вернул выход» | D5 |
| T5 | `status` не `complete` | `channel`, `head` узла - в выход | `not-opened`, `missing` узла либо «узел сдачи вернул <status> без нехватки» | D6, D7 |
| T6 | `complete`, `url` пуст | - | `not-opened`, «узел сдачи вернул complete без адреса PR/MR» | D8 |
| T7 | иначе | - | `opened`, `url`, `channel`, `head` узла | D1 |

`reason` - одной строкой: переводы строк заменены на `; ` (D11), он уходит строкой шапки цели.

## 5. Инварианты

- **I1.** Пушится только ветка трека этой цели (T1) и без перезаписи удалённой (файл узла).
- **I2.** `reason` непуст при `not-opened`.
- **I3.** Узел вызывается не больше одного раза; петель нет.
- **I4.** Скрипт не пишет в ledger: исход цели остаётся `complete` при любом `pr`.

## 6. Что делает главный поток с исходом

| `pr` | Действие `/auto` |
|---|---|
| `opened` | `ledger.py set TASK PR <url>` |
| `not-opened` | `ledger.py set TASK PR "не открыт - <reason>"`; `reason` в Output |
| возврата нет | `ledger.py set TASK PR "не открыт - <отказ Workflow>"` |

Повтор: `/auto TASK --pr` по закрытой `complete` цели со строкой `PR:` пустой либо `не открыт` - только сдача, в
дереве, которое `worktree.py path TASK` поднимает от уцелевшей ветки.
