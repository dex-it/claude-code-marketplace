# Трек record: спецификация

Эталон для скрипта `dex-auto/tracks/record.js`, узлов `agents/recorder.md`, `agents/corpus-checker.md` и сценариев
`tests/tracks/run.mjs` (префикс `C`). Ledger трек не пишет, продуктового кода не меняет. Код и сценарии сверяются с
этим документом, не наоборот.

Статус документа: **эталон**, сверен с кодом и сценариями C1-C21 17.10.2026; живым прогоном узлы не сверены.
Цель - BR-AUTO-004 (`../brd.md`).

## 1. Назначение и граница

Правка, доведённая на ветке цели, к сливу описана корпусом проекта: изменение наблюдаемого поведения и решение,
меняющее контракт или устройство, - единицей корпуса в ветке либо названы в сдаче с причиной.

- **Отдельный трек, не шаг feature, и после саморевью** - решение оператора 17.10.2026: треки реализации не
  нагружаются; саморевью судит правку против намерения оператора, фиксация записывает намерение, уже принятое
  оператором и доведённое агентом. Трек зовёт команда `/auto` после сдачи `complete` feature или bugfix и до сдачи
  кода, так что дельта корпуса судится до ревью MR; исход команда пишет в ledger, оттуда он идёт в описание PR/MR (§6).
- **Дельту судит узел, который её не писал** - решение оператора 17.10.2026: сверщик вызывается один раз, правок
  по его вердикту трек не делает; расхождение называется в сдаче, доработку кода либо корпуса инициирует оператор.
- **Скрипт решает только по фактам:** форма входа, исход вызова узла, `status`, перечни выходов.
- Вне трека: апрув единиц, выбор стороны в противоречии, push - оператор.

## 2. Вход

`args`: `cwd` обязателен; постановка - `goal_path` либо `goal`, хотя бы одно; `source`, `base`, `task` - по
желанию. Каждое поданное - строка.

- `goal_path` - файл цели; решения прогонов по ней - файлы `01-*.md` рядом с ним.
- `goal` - текст цели, когда файла нет.
- `source` - источник требований (тикет, файл).
- `base` - ветка, против которой считается дельта; не подана - коммиты ветки, которых нет в других ветках.

| Узел | Агент | Модель и effort | Выход |
|---|---|---|---|
| фиксатор | `dex-auto:recorder`, **без замены** | сессии | `status`, `corpus-status`, `units`, `covered`, `unrecorded`, `conflicts`, `commit`, `decisions`, `missing` |

блок обоих файлов (C16). Сверщик - без записи файлов.

decisions}`; `corpus` - `corpus-status` фиксатора; `derived` - `id` единиц с `origin: derived`, к приёмке оператором; `where` - нехватки через `; `.

## 5. Инварианты

- **I1.** Продуктовый код и тесты трек не меняет: посторонний файл в коммите фиксатора - этого вызова либо с трейлером
  `Dex-Auto-Record: yes` в местах правки - `blocked` (T10, C20).
- **I2.** Апрува трек не выдаёт: записанная единица - `status: review` (файл фиксатора), выведенная из кода - в
  `derived`.
- **I3.** Каждый узел вызывается не больше одного раза; правки по вердикту сверщика нет.
- **I4.** Принятую единицу трек не переписывает: противоречит правке - `conflicts` (T7), описывает её предмет -
  `covered`, сверяемое сверщиком (T8, C18).
- **I5.** Ledger и push трек не трогает.
- **I6.** `where` непуст при `partial` и `blocked`.

## 6. Что делает с исходом команда

Дом - `commands/auto.md`, абзац «Фиксация истины». Исход при любом `status` и отказ `Workflow` - строкой
`Фиксация:` цели в ledger, узел сдачи переносит её в описание PR/MR; исход цели не меняется. `interactive` - решение
оператора 17.10.2026: дельту (`units` либо `commit`) до сдачи кода оператор принимает либо отклоняет (`git revert` коммитов фиксатора),
строка пишется по ответу; единицы остаются `status: review` (C21). Повтор - по закрытой `complete` цели без строки
`Фиксация:`, а с `продолжить` - со строкой на `blocked`, `partial` либо `не состоялась` без ответа оператора;
иначе фиксации нет.
