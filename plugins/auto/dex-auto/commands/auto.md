# /auto

Ведёт одну цель от постановки до сдачи без оператора: заводит ledger, запускает трек скриптом
`Workflow`, сдаёт исход статусом. Два трека: **разработка** (до локальных коммитов, push никогда)
и **ревью** чужого MR/PR (код не правит, треды в MR публикует только по флагу `--post`).

**Goal:** цель закрыта подтверждённым внешним фактом (критерий «готово» из `00-goal.md` исполнен
командой или проверкой) либо остановлена явным статусом `blocked` / `partial` с названной нехваткой
и решением по каждой открытой находке; третьего исхода нет.

**Вход.** Первое слово `review` выбирает трек ревью, иначе - разработка.
- Разработка: `TASK` (ключ тикета или имя задачи), цель одной фразой, критерий «готово» в
  проверяемой форме, граница «чего не делаем», источник (тикет, спека, путь), если назван;
  `--feature` - под-вид feature, дефолт bugfix. `TASK` без цели - цель, критерий, граница, `Вид:` и
  `Источник:` читаются из открытого `00-goal.md` (подготовлен `/dex-auto:goal`); его нет - `blocked`
  с нехваткой «цель не подготовлена».
- Ревью: указатель MR/PR (URL или `owner/repo#N`, `group/project!N`); `TASK` выводится из него
  (`owner-repo-N`); intent (задача или описание), если назван; `--post` - санкция на инлайн-треды в
  чужом MR (без него находки идут перечнем в выход); `--delta SHA` - ревизия дельты от прошлой
  ревизии. Критерий «готово»: каждая находка имеет статус, вердикт вынесен, при `--post` - треды
  опубликованы или названы неопубликованными с причиной.
- `--interactive` - режим с каналом к оператору, дефолт `autonomous`. Критерий или граница не
  выводятся из входа и корпуса проекта: в `autonomous` - `blocked` с `Нехватка:` до первого узла,
  в `interactive` - вопрос оператору и `set TASK Ожидает оператор`.

**Ledger.** Машинные строки ведёт только `ledger.sh` плагина, руками их не править:

```text
${CLAUDE_PLUGIN_ROOT}/hooks/scripts/ledger.sh open|close|set|get|find TASK ...
```

`open TASK [MODE]` заводит `00-goal.md`: машинные строки (под `set` - `Исход:`, `Нехватка:`,
`Ожидает:`), разделы `## Цель`, `## Критерий «готово»`, `## Граница` заполняются прозой по входу до
запуска трека, `## Решения` - по возврату. Цель уже открыта (подготовлена или прошлый прогон) -
`open` её не трогает: `set TASK Режим <режим>` по флагу и `set TASK Ожидает ""` до запуска. Файл
трека в той же папке - `01-development.md` (`track=development>bugfix` или `>feature`) либо
`01-review.md` (`track=review`, при `--delta` - `track=review>delta`): `Статус: открыт|закрыт`,
`## Петли` (счётчики из возврата), `## Исполнители` (след узлов из возврата), `## Решения`. Хуки
плагина поднимают открытую цель на старте, возобновлении и после свёртки и не дают закончить ход
при ней без статуса.

**Прогон.** `Workflow` со `scriptPath` `${CLAUDE_PLUGIN_ROOT}/tracks/development.js` и `args`
`{task, goal, done, boundary, mode, kind, cwd, source}`, либо `${CLAUDE_PLUGIN_ROOT}/tracks/review.js`
и `args` `{task, mr, intent, mode, publish, last_review_sha, cwd}`. Потолки петель, схемы выхода
узлов, выбор узлов по стеку и поверхности, запасной узел при недоступном агенте каталога - внутри
скрипта; главный поток узлы не спавнит. Скрипт на диск не пишет, ledger заполняется до и после.

**Scenarios:**
- Возврат `complete` - критерий «готово» исполнить самому (команда из `00-goal.md`; для ревью -
  сверить, что у каждой находки возврата есть статус `confirmed` / `dropped` / `published` /
  `unpublished`), не пересказ узла; совпал - `## Решения` из `decisions` (для ревью - `dropped` с
  причинами и `questions` автору), по каждой единице `open_findings` - решение как в `partial`, файл
  трека закрыт, `close TASK`. Не совпал - как `partial`.
- Возврат `partial` - по каждой единице `open_findings` (ревью: `unpublished`, `questions`) и по
  причине `where` решение в `## Решения`: `отложено` с владельцем и местом записи либо `блокирует` с
  названием нехватки; при `блокирует` - `set TASK Исход blocked` и `set TASK Нехватка <текст>`.
  Цель остаётся открытой.
- Возврат `blocked` или `null` - `Исход: blocked`, `Нехватка:` из `missing` (нет поля - «узел не
  вернул выход, шаг `where`»).
- Аргумент `продолжить` - `Read` `00-goal.md` и открытого файла трека, новый прогон того же скрипта
  с теми же `args`; узлы переделывают незачтённые в ledger шаги. Резюме по id прогона живёт
  только в той же сессии - на него не рассчитывать.
- Поле `degraded` возврата непустое - перечислить в `## Решения`: какой узел заменён запасным.

**Output:** статус исхода первой строкой (`complete` | `blocked` | `partial`), затем `TASK`, путь
ledger, для разработки `goal_check` возврата (сборка, тесты, коммит, `head`) и
`review.push_recommended` с `push_blockers`, для ревью `verdict`, подтверждённые и снятые находки,
покрытие, треды; счётчики петель, решения по открытым находкам, стоп-линии, на которые прогон вышел
(push, деплой, миграция данных, необратимое удаление, запись в чужой MR без `--post`) - к оператору
поимённо.

**Constraints:** работа только внутри `cwd`; поля возврата брать из значения тула, не из
пересказа; вопрос оператору в `autonomous` не задаётся - он превращается в `blocked` с нехваткой.
