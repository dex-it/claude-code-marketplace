# /goal

Готовит цель трека feature или bugfix и оставляет её в ledger открытой на решении оператора:
`/auto TASK` берёт её оттуда без повторной постановки.

**Goal:** `00-goal.md`, по которому трек идёт без оператора: цель одной фразой, критерий «готово»,
исполнимый командой или проверкой с ожидаемым результатом, граница «чего не делаем», вид,
источник и контекст кода. Каждое утверждение опирается на источник (`файл:строка`, ключ тикета,
раздел спеки) либо помечено «допущение».

**Вход.** Указатель на источник и, если назван, `TASK` первым аргументом (один аргумент -
указатель). Ключ тикета (`PROJ-123`) - трекер через MCP (`ToolSearch`); `owner/repo#N` -
`gh issue view`; URL - `WebFetch`; путь - `Read`; иначе источник - сама формулировка. `TASK` не
назван: ключ тикета из указателя или заголовка источника, иначе `owner-repo-N`, иначе 2-3 слова
предмета в kebab-case. `--feature` - вид feature; без флага вид по источнику: описан дефект
наблюдаемого поведения - `bugfix`, новое поведение - `feature`, неясно - `bugfix` с пометкой
«допущение».

**Steps:**
1. Источник прочитать целиком. Недоступен (нет MCP трекера, `gh` не авторизован, файла нет) -
   назвать нехватку в выходе и остановиться, цель не заводить.
2. Код: по упоминаниям из источника найти файлы, тесты и команды сборки и тестов (манифест
   репозитория, CI-конфиг); корпус документации проекта (`docs/`, ADR, CLAUDE.md) - ограничения,
   которые входят в границу. Продукт шага - раздел `## Контекст`; узел трека его сверяет, не ищет.
3. Черновик разделов по форме ниже. Место, которое не выводится из источника и кода (чем проверить
   «готово», где граница), - вопрос оператору одним пакетом через `AskUserQuestion`; оператора нет
   (headless, `AskUserQuestion` недоступен) - вместо вопроса строка «допущение: ...» в разделе.
4. Цель с таким `TASK` уже есть (открыта или закрыта) - показать её разделы и остановиться, не
   перезаписывать. Иначе
   `ledger.sh open TASK interactive`, разделы прозой в `00-goal.md`, `ledger.sh set TASK Ожидает
   оператор`.

**Форма разделов.**
- `## Цель` - первая строка `Вид: bugfix|feature`, вторая `Источник: <указатель>`, далее одна
  фраза: что должно стать иначе, не как это сделать.
- `## Критерий «готово»` - команда и ожидаемый результат (`npm test` -> exit 0, названный тест
  зелёный) либо наблюдаемый факт со способом проверки. «Работает корректно», «исправлено» -
  не критерий. Для bugfix - тест, красный до правки. В критерий входит локальный коммит, push - нет.
- `## Граница` - файлы и области, которые не трогаем; что не меняется (публичная сигнатура,
  зависимости, схема данных).
- `## Контекст` - строки `файлы:`, `тесты:` (команда), `сборка:` (команда), `корпус:` (пути либо
  «корпуса нет»); у каждой источник (`манифест`, `CI`, `файл:строка`) либо «допущение».

**Output:** путь `00-goal.md`; четыре раздела как записаны; перечень допущений и ответов оператора;
строка запуска `/dex-auto:auto TASK` - с `--interactive`, если допущения остались.

**Constraints:** машинные строки `00-goal.md` пишет только `ledger.sh`; код и тесты не менять; трек
не запускать; в трекер и MR не писать.
