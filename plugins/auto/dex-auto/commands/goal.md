# /goal

Готовит цель трека feature или bugfix и оставляет её в ledger открытой на решении оператора:
`/auto TASK` берёт её оттуда без повторной постановки.

**Goal:** `00-goal.md`, по которому трек идёт без оператора: цель одной фразой, критерий «готово»,
граница «чего не делаем», вид и источник. Каждое утверждение, включая каждый пункт критерия
«готово», несёт якорь источника (`файл:строка`, `AC-N`, ключ тикета, раздел спеки) либо пометку
«допущение».

**Вход.** Указатель на источник и, если назван, `TASK` первым аргументом (один аргумент -
указатель). Ключ тикета (`PROJ-123`) - трекер через MCP (`ToolSearch`); `owner/repo#N` -
`gh issue view`; URL - `WebFetch`; путь - `Read`; иначе источник - сама формулировка. `TASK` не
назван: ключ тикета из указателя или заголовка источника, иначе `owner-repo-N`, иначе 2-3 слова
предмета в kebab-case. `--feature` - вид feature; без флага вид по источнику: описан дефект
наблюдаемого поведения - `bugfix`, новое поведение - `feature`, неясно - `bugfix` с пометкой
«допущение».

**Steps:**
1. Источник прочитать целиком. Недоступен (нет MCP трекера, `gh` не авторизован, файла нет) -
   назвать нехватку в выходе и остановиться, цель не заводить. Цель с таким `TASK` уже есть
   (открыта или закрыта) - показать её разделы и остановиться, не перезаписывать.
2. Код по упоминаниям из источника и корпус документации проекта (`docs/`, ADR, CLAUDE.md)
   прочитать, чтобы не спрашивать выводимое; ограничения корпуса входят в границу. Черновик
   разделов - по форме ниже; требования и критерии приёмки источника против черновика критерия
   «готово» суди вызовом `Skill` `dex-skill-requirement-quality:requirement-quality`.
3. Вид feature - проба черновика (ниже), вид bugfix - проба `n/a`. Каждый домысел `questions` пробы
   раздели. Выводим - если то же решение уже принято в поведении, контракте или соседнем месте кода, в
   документации проекта либо требованием источника, и решение иначе разошлось бы с ним; прежнее поведение,
   которое источник просит изменить, и черновик ответом не служат. У `breaks: true` черновик теряет или
   нарушает требование источника: требуемое источником выводимо из него, развилки внутри - нет. Невыводимый -
   допущение, если случай источник не описывает, а вариант - конвенция проекта (проверка, ветка, тест,
   документ) либо общепринятая практика стандарта или стека; поведение, вышедшее у соседа само (нет
   проверки, порядок обхода), конвенцией не служит; иначе вопрос. Выводимое - строкой с ответом и якорем
   `файл:строка` в проекте либо источнике, допущение - «допущение: <исход, видимый получателю> - <конвенция
   с якорем либо практика>»; решение об исходе или мере - в `## Критерий «готово»`,
   о границе - в `## Граница`, а не в `## Решения`. Очередь вопросов: расхождение оракула - обеими сторонами
   якорями, домыслы-вопросы в порядке выхода, каждый с его `gaps`, `open_items` пробы, место черновика,
   которое не выводится из источника и кода (какое поведение считать готовым, что вне охвата). Ревизия -
   первые четыре вопроса очереди одним вызовом `AskUserQuestion`; ответ - только словами оператора с
   пометкой «ответ оператора», отданное реализации - «на усмотрение реализации: <вопрос>», обе строкой по
   тому же правилу места. Очередь не пуста и остальное реализации не отдано - следующая ревизия, всего не
   больше пяти, по незаданному остатку очереди; у feature перед ней новая проба черновика с ответами, её
   домыслы и `open_items` - за остатком, кроме повторов. Остаток очереди после пятой ревизии и вся
   очередь без оператора (headless, `AskUserQuestion` недоступен) - строками «допущение: ...» в разделе,
   расхождение - строкой «противоречие: <якорь A> против <якорь B>» первым пунктом критерия «готово».
4. `${CLAUDE_PLUGIN_ROOT}/hooks/scripts/ledger.py open TASK interactive`, разделы прозой в `00-goal.md`,
   `ledger.py set TASK Ожидает оператор`.

**Проба.** Каталог `mktemp -d` с `goal.md` (черновик) и `source.md` (текст источника и раздел `## Ответы
оператора` с ответами прошлых ревизий); `Workflow` с `name` `dex-auto:dex-auto-goal` и
`args` `{kind, corpus, cwd}` (`corpus` - каталог, `cwd` - корень проекта). Возврат ждать в том же ходе циклом
`until` в `Bash` по `<Task ID>.output` под `claude-<uid>` временного каталога (первый заданный из
`CLAUDE_CODE_TMPDIR`, `TMPDIR`, `TMP`, `TEMP`, иначе `/tmp`), готов - файл непуст и разбирается как JSON.
`ScheduleWakeup` и конец хода до уведомления - не ожидание: закрытый ход снимает пробу по потолку ожидания
фоновых задач. `Workflow` недоступен, завершился ошибкой либо три повтора без готовности - проба
`unverifiable` с этой причиной. Каталог удалить при любом исходе.

**Форма разделов.**
- `## Цель` - первая строка `Вид: bugfix|feature`, вторая `Источник: <указатель>`, далее одна
  фраза: что должно стать иначе, не как это сделать.
- `## Критерий «готово»` - чем, не читая код правки, отличить сделанное от несделанного: каждое
  запрошенное поведение есть, прежнее не сломано. Локальный коммит входит, push - нет.
- `## Граница` - файлы и области, которые не трогаем; что не меняется (публичная сигнатура,
  зависимости, схема данных).

**Output:** путь `00-goal.md`; три раздела как записаны; исход пробы
(`reason` при `n/a` и `unverifiable`), строки `degraded`; перечень допущений, выведенных домыслов и
ответов оператора; строка запуска `/dex-auto:auto TASK` - с `--interactive`, если допущения остались.

**Constraints:** машинные строки `00-goal.md` пишет только `ledger.py`; код и тесты не менять; трек
не запускать; в трекер и MR не писать.
