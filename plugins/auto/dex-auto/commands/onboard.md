# /onboard

**Goal:** проект готов к циклу `/dex-auto:goal` -> `/dex-auto:auto`: пустой проект со стеком в описании собирается и
проходит тесты одной командой; корпус найден либо развёрнут, назначение продукта и решения устройства, видимые в коде, - единицами корпуса
`status: review` либо названы с причиной, почему единицы нет; `CLAUDE.md` несёт порядок работы, команды сборки,
тестов и гейтов, карту, правила проекта и запреты либо их отсутствие. Непустой проект: продуктовый код, тесты и
конфигурацию сборки команда не меняет. Push не делает.

**Вход.** Описание продукта текстом либо путём к файлу (`Read`); нет - описания нет. `--interactive` - режим с
каналом к оператору, дефолт `autonomous`.

**Каталог.** Корень - `git rev-parse --show-toplevel`; каталог вне репозитория без файлов - `git init` в нём. Иначе не
репозиторий либо `git status --porcelain` непуст - остановка `blocked` с причиной до любой записи. Коммиты - на
текущую ветку.

**Пустой проект.** `git ls-files` не несёт файлов, кроме README, LICENSE, `.gitignore`, `CLAUDE.md`, `.docs_layout` и
`docs/`, - проект пуст, режим `interactive` при любом флаге, если доступен `AskUserQuestion`. Стек -
язык либо рантайм, названный в описании прямо либо фреймворком, который его однозначно задаёт; назван - скелет на
нём, не назван - скелета нет.

**Описание.** Описания нет и режим `interactive` - до трека `AskUserQuestion` блоком: назначение продукта (кому и
зачем), стороны, граница - чего продукт не делает; варианты - из README и кода, без них типовые, у каждого
следствие. Ответы - описание продукта. `autonomous` - вопросов нет, описание выводит узел трека.

**Трек.** `Workflow` с `name` `dex-auto:dex-auto-onboard`, `args` `{cwd, brief, stack, scripts}`: `brief` без описания
не подаётся, `stack` - пустому проекту со стеком, `scripts` - `${CLAUDE_PLUGIN_ROOT}/hooks/scripts`.
Возврат ждёшь в том же ходе циклом `until` в `Bash` по файлу вывода задачи `<Task ID>.output` под `claude-<uid>`
временного каталога (первый заданный из `CLAUDE_CODE_TMPDIR`, `TMPDIR`, `TMP`, `TEMP`, иначе `/tmp`), Task ID - из
текста старта `Workflow`; готовность - файл непуст и разбирается как JSON, возврат - его поле `result`. Таймаут цикла
- новый такой же вызов, пока в `Transcript dir` из текста старта за последние 15 минут изменился хоть один файл; не
изменился ни один - исход `blocked` «возврат Workflow не получен: 15 минут без записи прогона». Закрытый ход
(`ScheduleWakeup`, «до уведомления») прогон убивает. Возврат несёт `unverified` - `git revert` этого коммита до прочих
шагов, в выход sha и причина. После `blocked` трека, отказа `Workflow` либо отката - `git status --porcelain` и назови оператору файлы, которые удалить. `secrets` непусто - коммит составителя оператор убирает из истории ветки до push: `git revert` секрет из неё не убирает.

**CLAUDE.md.** После возврата, кроме `blocked` и отказа `Workflow`:

1. Гейты - вызови `Skill` `dex-skill-project-baseline:project-baseline`, раздел «Что проверять»: по каждой оси -
   команда из манифеста и конфигурации проекта (сборка, проверка типов, линтер, тесты, прогон в CI) либо `нет`.
   Отсутствующий гейт не заводишь: он идёт в выход предложением.
2. Блок - текст `${CLAUDE_PLUGIN_ROOT}/templates/flow.md`, затем разделы строкой на запись, в порядке путей, `what` и `basis` - одна строка до 120 знаков: `## Сборка и гейты` -
   ось и команда; `## Карта` - `map`; `## Правила` - `rules`, пуст - строка «Свода правил нет: ревью судит по
   практике стека», у непустого проекта дальше «; свод из истории ревью MR собирает
   `/dex-rulebook-miner:rulebook`»; `## Запреты` - `guards` с `basis`. Строка, чей путь не найден `git ls-files` либо каталогом в дереве, в блок не идёт, а идёт в выход.
3. Место - между строками-маркерами `<!-- >>> dex-auto: flow -->` и `<!-- <<< dex-auto: flow -->` в `CLAUDE.md` корня. Маркеры есть -
   содержимое между ними заменяешь; нет - блок дописываешь в конец; файла нет - создаёшь. Текст вне маркеров не трогаешь. Маркер есть, а
   пара маркеров не ровно одна - блок не пишешь (непарный, дубль): причина и строки маркеров в выход; маркер в код-блоке не считается.
4. Коммит - только `CLAUDE.md`, с трейлером `Dex-Auto-Onboard: flow`; блок не изменился - коммита нет.

**Готовность.** Трек вернулся - после шагов «CLAUDE.md» либо их пропуска перечень строкой на ось, `есть` либо `нет` с тем, что
сделать; по перечню сам ничего не меняешь.

- Сборка и тесты - одной командой каждое (гейты шага 1).
- CI - прогон гейтов на push и MR.
- `.gitignore` - есть в корне.
- Секреты - `git ls-files` не несёт файла со значением секрета: окружения кроме образца, приватного ключа, хранилища
  ключей (`.env`, `*.pem`, `*.key`, `*.pfx`, `id_rsa`); найденный путь называешь, из истории не вычищаешь.
- `CLAUDE.md` корня - не длиннее 200 строк.
- Корпус - `.docs_layout` есть.
- Свод правил - строка `rules` по ключу `rulebook` раскладки либо `нет` и `/dex-rulebook-miner:rulebook`; у пустого проекта оси нет.

**Приёмка.** `interactive` и у вызова есть неоткаченный коммит - трека, скелета либо `CLAUDE.md` - вопрос: скелет, единицы, `derived`,
`conflicts`, `layout`, вердикты сверщика - принять | отклонить. Отклонить - `git revert` каждого коммита этого
вызова от нового к старому, в выход причина. `autonomous` - приёмка за человеком на MR, вопросов
нет.

**Output:** исход первой строкой - `status` возврата (`blocked` до трека - причина), затем `where`; скелет
(`scaffold`), откат `unverified` и `skipped`; корпус (`corpus`) и `layout`; единицы `units` путями, `derived` - к приёмке оператором;
`covered`, `unrecorded` с причиной, `conflicts` - выбор стороны за оператором; вердикты `checks` не `upheld` и
`missed`; строки `map`, `rules`, `guards`, не нашедшие пути; гейты по осям и отсутствующие - предложением завести;
перечень готовности; коммиты вызова; ответ приёмки; следующий шаг - `/dex-auto:goal`.

**Constraints:** поля возврата брать из поля `result` файла вывода, не из пересказа; правил проекта из кода не
выводишь и свода не собираешь.
