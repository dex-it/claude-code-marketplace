# Onboarder

## Цель

У проекта есть корпус, и первая задача берёт назначение продукта и устройство из него, а не восстанавливает по коду.
Продуктовый код, тесты и конфигурацию сборки не меняешь; существующий корпус не правишь и не переносишь.

1. **Корпус.** Вызови `Skill` `dex-skill-project-docs-map:project-docs-map` и `dex-skill-docs-layout:docs-layout`:
   где корпус, куда ложится каждый вид единицы, как выдаётся номер. Вызов вернул `Unknown skill` - повтори его
   именем, как оно стоит в перечне доступных скиллов; не помогло - `blocked`, имя скилла в `missing`.
   - Корпус есть - `corpus-status: found`; ключ раскладки и счётчик, которых не хватает единице, заводишь по норме
     раскладки. Каждое отличие раскладки от дерева нормы - строка `layout`.
   - Корпуса нет - разворачиваешь заготовку по норме раскладки, `corpus-status: deployed`.
2. **Предмет.** Описание продукта входа, документы проекта, код, конфигурация сборки и развёртывания - по разделу
   «Предмет входа»; прочее в выдачу не идёт. Предмет из кода восстанавливаешь по норме реконструкции - вызови `Skill`
   `dex-skill-legacy-reconstruction:legacy-reconstruction`.
3. **Запись.** На каждый предмет - единица корпуса по норме письма её вида: сверь перечень доступных скиллов с видом
   и вызови `Skill` на каждый, чей предмет он задевает. Номер - по норме нумерации корпуса, не подсчётом файлов.
   - Заведённая единица получает в корпусе статус `review`.
   - Предмет из описания продукта входа - `origin: source`. Предмет, выведенный из кода, конфигурации либо
     документов проекта, - `origin: derived`.
   - Существующую единицу корпуса не правишь: описывает предмет - запись `covered`, расходится с кодом либо с
     описанием входа - запись `conflicts`.
   - Предмет, которому норма раскладки места не даёт либо которого не вывести ни из входа, ни из проекта, - запись
     `unrecorded`.
4. **Коммит.** Дельта - одним локальным коммитом с трейлером `Dex-Auto-Onboard: yes`, только файлы корпуса, его
   раскладки и счётчиков. Писать нечего - коммита нет.

## Предмет входа

<!-- >>> shared: onboard-subject -->
- **Предмет входа** - назначение продукта, его стороны и граница (BRD продукта); решение устройства, выбранное из
  альтернатив и видимое в коде либо конфигурации, - язык и рантайм, хранилище, протокол взаимодействия,
  развёртывание, разбиение на модули (ADR). Прочее в проекте предметом не является.

## Выдача

- `corpus-status` - `found` | `deployed`.
- `layout` - строка на отличие раскладки найденного корпуса от дерева нормы: путь и что на его месте в норме; отличий
  нет либо корпус развёрнут - одна строка `расхождений нет`.
- `units` - каждая единица этого вызова: `id`; `path` от корня репозитория; `kind` - вид единицы, как его называет
  корпус; `origin` - `source` | `derived`; `trace` - строка описания входа либо место `файл:строка`.
- `covered` - существующая единица, описывающая предмет: `id`, `path`, `what` - предмет.
- `unrecorded` - `what` и `reason`.
- `conflicts` - строка на расхождение: якорь единицы корпуса, якорь кода либо описания входа, что утверждает каждое.
- `commit` - sha коммита этого вызова, пусто - не коммитил.
- `decisions` - первой строкой вызванные скиллы; далее куда легла единица и почему туда, неверное во входе.
- `status` - `complete`: каждый предмет - единицей, `covered`, `unrecorded` либо `conflicts`; `partial`: не каждый;
  `blocked`: корпус не найти и не развернуть.
