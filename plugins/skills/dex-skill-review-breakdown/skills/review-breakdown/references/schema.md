# Состав разбора: единица и отчёт

Читается до первой записанной единицы. Состав закрыт: поля вне этого перечня в разбор не пишутся, а
нехватка поля под свой предмет называется пунктом выхода - поле, заведённое на ходу, не найдёт ни
один потребитель. Вызывающая сторона передала форму записи - действует раздел «Форма вызывающей
стороны», а состав ниже остаётся нормой содержания: что значит поле и когда оно обязательно.

## Носитель

**Один файл на один MR.** Разбор адресуется тем же ключом, что и MR: два файла на один MR дают два
состояния, и какое из них действующее, из файлов не выводится. Носитель структурированный - разбор
читает машина, а не человек; формат файла (`json`, `yaml`, таблица) принадлежит вызывающей стороне и
здесь не назначается, но он один на прогон. Форма записи пришла - формат задаёт она.

Путь носителя приходит полем входа. Поля нет, а поручение разбора есть - `status: blocked`: место
записи прогон не выбирает, иначе следующий прогон ищет разбор там, где его нет.

**Файл переписывается целиком, а не дописывается.** Разбор - состояние, а не журнал: дописанная
единица со старым ключом даёт две записи об одном треде, и какая действующая, из файла не читается.
История прогонов, если она нужна, ведётся носителем версий, а не накоплением строк в разборе.

## Единица разбора

Обязательность названа по каждому полю. `[обяз]` - без него единица не пишется вовсе; `[усл]` -
обязательно при названном условии; `[доп]` - пишется, когда значение известно, и отсутствие
значением не является.

### Тождество

| Поле | Обяз | Что несёт |
|---|---|---|
| `mr` | `[обяз]` | указатель MR: проект и номер в системе хостинга |
| `thread` | `[обяз]` | идентификатор треда, выданный хостингом. Тред не создан - черновой ключ плюс пометка о недоставленности |
| `author` | `[обяз]` | учётная запись, написавшая тред |
| `by-agent` | `[обяз]` | признак: тред написан агентом либо человеком |
| `created-at` | `[обяз]` | момент появления треда |
| `model-version`, `prompt-version` | `[усл]` | версии, которыми размечена **эта** единица. Обязательны, когда в носителе есть единицы от разных прогонов: у отчёта версии одни, а единица переживает смену версии вместе с MR, и без них разбор приписывает старую находку новой модели |
| `raised-at` | `[доп]` | состояние MR, на котором находка поднята: указатель той формы, которой историю MR именует хостинг. По нему проверяется правота: на итоговом коде замечание, уже исправленное автором, выглядит опровергнутым |

### Предмет

| Поле | Обяз | Что несёт |
|---|---|---|
| `type` | `[обяз]` | значение схемы типов со схемой и её версией; берётся из разметки, здесь не выбирается |
| `is-defect` | `[обяз]` | дефект, не-дефект (постановка, реакция без содержания) либо **не решено**. Третье значение - штатное: разметка, которой не хватило предмета, называет это, а не выбирает правдоподобное |
| `severity` | `[усл]` | уровень; обязателен у дефекта. У не-дефекта и у единицы с нерешённым признаком не ставится вовсе: уровень отвечает за последствие дефекта, а его тут либо нет, либо про него ещё не решено |
| `occurrences` | `[доп]` | число затронутых мест; не названо - читается как одно, а не как «неизвестно» |
| `rationale` | `[обяз]` | довод одной фразой, называющий последствие. «Плохое имя переменной» - негодно: повторяет находку; «из имени не видно, отметка чего это» - годно |
| `anchor` | `[доп]` | привязка находки: файл и строка |
| `rule` | `[усл]` | идентификатор единицы свода правил проекта, который находка нарушает. Обязателен, когда свод в проекте есть **и** довод находки опирается на принятое в проекте: «так здесь не принято» без ключа подтвердить нечем. Свода нет - поле пусто, и это находку необоснованной не делает |

### Правота

| Поле | Обяз | Что несёт |
|---|---|---|
| `correctness` | `[обяз]` | подтверждено / опровергнуто / проверить не удалось / не проверялось |
| `correctness-evidence` | `[усл]` | чем значение доказано: место в коде плюс то, что делает вывод выводом, - контрпример, соседний контекст. Обязательно при «подтверждено» и «опровергнуто»; повтор `anchor` уликой не является |

### Исход

| Поле | Обяз | Что несёт |
|---|---|---|
| `outcome` | `[обяз]` | исправлено / ушло как есть / неизвестно |
| `closed-at`, `closed-by` | `[доп]` | момент закрытия треда и кто закрыл |
| `resolved` | `[усл]` | подтверждение, что названная проблема устранена. Обязательно при исходе «исправлено» |
| `resolved-at` | `[усл]` | состояние MR, на котором проблема перепроверена. Обязательно при исходе «исправлено» |
| `resolve-evidence` | `[усл]` | чем устранение подтверждено. Обязательно при исходе «исправлено» |
| `fix-lines` | `[доп]` | построчная карта правки: у каждой строки файл, её номер и коммит, **в котором** правка сделана. Номер читается в нумерации разобранного снимка MR, а не того коммита. Пишется только при исходе «исправлено»; при других исходах не пишется вовсе, иначе цена появляется у правки, которой не было |
| `fix-lines[].before`, `fix-lines[].after` | `[доп]` | содержание строки до правки и после. Отсутствие одной из сторон значащее: нет «до» - строка добавлена, нет «после» - удалена; пустыми одновременно не бывают |

## Отчёт по MR

Одна единица на MR, пишется в тот же носитель.

| Поле | Обяз | Что несёт |
|---|---|---|
| `mr` | `[обяз]` | тот же указатель, что у единиц |
| `outcome` | `[обяз]` | чем MR закончился: слит / закрыт / ещё открыт |
| `reported-at` | `[обяз]` | момент, на который снят разбор |
| `merged-at` | `[усл]` | момент слияния; обязателен при исходе «слит» |
| `iterations` | `[доп]` | число ревизий ревью: считается по содержимому правок, а не по числу коммитов и не по числу заливок |
| `model-version` | `[обяз]` | версия модели, которой велось ревью |
| `prompt-version` | `[обяз]` | версия промпта либо артефакта, по которому ревью велось |
| `versions` | `[доп]` | точки таймлайна MR: указатель состояния и его момент |
| `known-threads` | `[усл]` | идентификаторы **всех** тредов, которые прогон видел, включая не давшие находки. Обязательно, когда прогон видел треды MR целиком; не видел - поля нет вовсе, а причина называется в выходе. Пустым не пишется |

`known-threads` - механизм снятия остатков. Поля нет - потребитель не снимает ничего; поле
заполнено частично «чтобы было» - потребитель снимет живые треды, и восстановить их будет нечем;
поле пустое - потребитель читает «тредов нет» и снимает весь прежний разбор MR. Прогон, видевший не
все треды MR (доступ, постранично оборванная выдача), поле **не пишет** и называет причину в выходе:
половина перечня хуже его отсутствия. MR, у которого тредов действительно нет, перечня тоже не
получает: снимать нечего, а пустое значение у части потребителей стирает накопленное.

## Форма вызывающей стороны

Форма записи - схема, по которой вызывающая сторона читает разбор: путь к файлу схемы, доступному
узлу, либо содержимое схемы во входе. Форма принадлежит читающему, и прогон её не правит и не
расширяет.

- **Форма читается до первой единицы.** Не открылась, не разобралась либо не несёт своей версии -
  `status: blocked` с причиной, а не запись по встроенному составу: разбор, написанный не по той форме,
  вызывающий отвергнет, а по форме без версии не отличит одну редакцию от другой.
- **Запись идёт строго по форме.** Поле, которого форма не знает, не пишется, даже когда состав выше
  его знает: закрытая форма отвергает файл целиком. Такая ось называется в выходе один раз, а не
  тихо теряется.
- **Имена полей и перечни значений берутся у формы.** Значения, которые у формы названы иначе,
  сводятся только тем соответствием, которое видно из самой формы (описание значения, совпадающий
  смысл); соответствия нет - значение не подбирается по созвучию, а единица попадает в перечень
  неполных. Обязательность из состава выше действует и внутри формы: поле, которое форма знает,
  но не требует, прогон пишет по условию состава - `resolve-evidence` у исправленного пишется, даже
  когда форма его необязательным объявила.
- **Версия формы переносится в запись** туда, где её место назначила форма. Файл с чужой версией
  вызывающий читает по другой редакции, и расхождение не видно ни одной из сторон.
- **Тип находки уходит как есть** - значение, схема и версия каталога, по которому размечено. Перевода
  в чужой перечень типов прогон не делает: соответствие типов - модель читающего.

## Заполнение при неполном знании

Прогон не знает значения обязательного поля - единица пишется с явной пометкой нехватки по этому полю
и попадает в перечень неполных единиц выхода. Правдоподобное значение не подставляется: подставленное
неотличимо от выведенного, и обнаруживается это только сплошной перепроверкой.

Исключение из правила «пиши, что знаешь» одно: `known-threads` заполняется целиком либо
отсутствует, см. выше.

Форма записи не даёт места пометке нехватки - единица с неизвестным обязательным полем в файл не
пишется, а перечисляется в выходе поимённо, с полями, которых не хватило.

## Повторный прогон по тому же MR

Единица с существующим ключом обновляется, новая не заводится. Обновляются поля, по которым появилось
знание: исход, правота, строки правки, закрытие треда. **Тип и уровень повторным прогоном не
переписываются молча**: расхождение с прежней разметкой - находка о разметке, она называется обеими
сторонами, и решение о смене принимает вызывающая сторона.

Единица прежнего прогона, чей тред в этом прогоне не виден, из файла **не удаляется**: она остаётся и
попадает - либо не попадает - в `known-threads`, а снятие принадлежит потребителю. Удалённая на месте,
она унесёт с собой единственную запись о находке, которую больше не покажет ни один источник.
