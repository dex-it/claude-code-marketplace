# Состав записи прогона

Читается до первой записанной строки. Состав закрыт: поля вне этого перечня в запись не пишутся, а
нехватка поля под свой предмет называется пунктом выхода - поле, заведённое на ходу, не найдёт ни
один потребитель. Вызывающая сторона передала форму записи - действует раздел «Форма вызывающей
стороны», а состав ниже остаётся нормой содержания: что значит поле и когда оно обязательно.

## Носитель

**Один файл на один прогон.** Путь носителя приходит полем входа; повтор той же дельты пишется тем
же путём и замещает прежний файл, другая дельта - другим путём. Прежние записи MR не
переписываются: запись фиксирует факт своего прогона. Носитель структурированный - запись читает
машина; формат файла принадлежит вызывающей стороне и здесь не назначается. Форма записи пришла -
формат задаёт она.

Поля пути нет, а поручение записи есть - `status: blocked`: место записи прогон не выбирает, иначе
следующий прогон ищет журнал там, где его нет.

**Прежние записи MR приходят полем входа, путями по порядку прогонов.** Они - единственный источник
того, что уже записано: по ним решается, какой тред новый и чьё состояние сменилось. Файл из
перечня не открылся - `status: blocked` с его путём: запись, собранная без части истории, повторит
уже записанное.

Обязательность названа по каждому полю. `[обяз]` - без него запись или тред не пишется вовсе;
`[усл]` - обязательно при названном условии; `[доп]` - пишется, когда значение известно, и
отсутствие значением не является.

## Запись

| Поле | Обяз | Что несёт |
|---|---|---|
| `mr` | `[обяз]` | указатель MR: проект и номер в системе хостинга |
| `mr-state` | `[обяз]` | состояние MR на момент прогона: открыт / слит / закрыт |
| `merged-at` | `[усл]` | момент слияния; обязателен у слитого и отсутствует у прочих |
| `run.kind` | `[обяз]` | первичное ревью либо ре-ревью |
| `run.base`, `run.head` | `[обяз]` | дельта прогона: у первичного ревью `base` - база MR у хостинга, у ре-ревью - `head` последнего проведённого прогона; `head` - ревизия, которую ревьюили |
| `run.at` | `[обяз]` | момент прогона |
| `run.outcome` | `[обяз]` | проведён / частично / не проведён |
| `run.reason` | `[усл]` | причина; обязательна у частичного и непроведённого, у проведённого отсутствует |
| `run.diff-lines` | `[доп]` | размер дельты в строках, когда он мерялся |
| `run.model-version`, `run.prompt-version` | `[усл]` | версии, которыми велось ревью; обязательны у проведённого и частичного |
| `threads` | `[усл]` | новые и изменившиеся треды; обязателен у проведённого и частичного (пустой - нового нет), у непроведённого отсутствует |

## Тред

| Поле | Обяз | Что несёт |
|---|---|---|
| `id` | `[обяз]` | идентификатор треда, выданный хостингом. Тред не создан - черновой ключ плюс пометка о недоставленности |
| `state` | `[обяз]` | состояние на `head` прогона: открыт / частично исправлен / исправлен / закрыт без исправления / оспорен / отозван / неприменим |
| `note` | `[обяз]` | чем состояние подтверждено: место в коде и то, что делает вывод выводом, либо реплика треда, если состояние задано ею. Повтор якоря пояснением не является |
| `opened` | `[усл]` | заведение треда; пишется только в записи прогона, в котором тред появился, и только там |
| `fix-lines` | `[усл]` | строки правки; обязательны у «исправлен» и «частично исправлен», у прочих отсутствуют. У «частично исправлен» повторно - только строки, которых нет в прежних записях |

### Заведение треда (`opened`)

| Поле | Обяз | Что несёт |
|---|---|---|
| `author` | `[обяз]` | учётная запись, написавшая тред |
| `by-agent` | `[обяз]` | признак: тред написан агентом либо человеком |
| `created-at` | `[обяз]` | момент появления треда |
| `type` | `[обяз]` | значение схемы типов со схемой и её версией; берётся из разметки, здесь не выбирается |
| `is-defect` | `[обяз]` | дефект, не-дефект либо **не решено**. Третье значение штатное: разметка, которой не хватило предмета, называет это, а не выбирает правдоподобное |
| `severity` | `[усл]` | уровень; обязателен у дефекта, у не-дефекта и нерешённого отсутствует |
| `occurrences` | `[доп]` | число затронутых мест; не названо - читается как одно |
| `rationale` | `[обяз]` | довод одной фразой, называющий последствие. «Плохое имя переменной» - негодно: повторяет находку; «из имени не видно, отметка чего это» - годно |
| `anchor` | `[доп]` | привязка находки: файл и строка на ревизии поднятия |
| `rule` | `[усл]` | идентификатор правила из свода правил проекта, который находка нарушает. Обязателен, когда свод в проекте есть **и** довод опирается на принятое в проекте. Свода нет - поле пусто, и находку необоснованной это не делает |

### Строка правки (`fix-lines[]`)

| Поле | Обяз | Что несёт |
|---|---|---|
| `file`, `line` | `[обяз]` | файл и номер строки в нумерации `head` прогона |
| `commit` | `[обяз]` | коммит, **в котором** правка сделана, а не итоговый коммит ветки |
| `before`, `after` | `[доп]` | содержание строки до правки и после. Нет «до» - строка добавлена, нет «после» - удалена; пустыми одновременно не бывают |

## Состояния из статусов ре-ревью

Статус прежней находки у ре-ревью и состояние треда - разные перечни; соответствие одно:

| Статус находки | Состояние треда |
|---|---|
| `closed` | исправлен |
| `partial` | частично исправлен; на слитом или закрытом MR - тоже, остаток уехал с кодом и назван в пояснении |
| `open` | открыт; тред закрыт без правки либо MR слит или закрыт - закрыт без исправления |
| `disputed` | оспорен; код опровергает замечание на ревизии поднятия - отозван |
| `no-longer-applicable` | неприменим |

Состояние, совпавшее с последним записанным, в запись не входит.

## Форма вызывающей стороны

Форма записи - схема, по которой вызывающая сторона читает запись: путь к файлу схемы, доступному
узлу, либо содержимое схемы во входе. Форма принадлежит читающему, и прогон её не правит и не
расширяет.

- **Форма читается до первой строки.** Не открылась, не разобралась либо не несёт своей версии -
  `status: blocked` с причиной, а не запись по встроенному составу: запись не по той форме
  вызывающий отвергнет, а по форме без версии не отличит одну редакцию от другой.
- **Запись идёт строго по форме.** Поле, которого форма не знает, не пишется, даже когда состав выше
  его знает: закрытая форма отвергает файл целиком. Такая ось называется в выходе один раз, а не
  тихо теряется.
- **Имена полей и перечни значений берутся у формы.** Значения, которые у формы названы иначе,
  сводятся только соответствием, видимым из самой формы (описание значения, совпадающий смысл);
  соответствия нет - значение не подбирается по созвучию, а тред попадает в перечень неполных.
  Обязательность из состава выше действует и внутри формы: поле, которое форма знает, но не
  требует, прогон пишет по условию состава.
- **Версия формы переносится в запись** туда, где её место назначила форма.
- **Тип находки уходит как есть** - значение, схема и версия каталога, по которому размечено.
  Перевода в чужой перечень типов прогон не делает.

## Заполнение при неполном знании

Прогон не знает значения обязательного поля треда - тред пишется с явной пометкой нехватки по этому
полю и попадает в перечень неполных выхода. Правдоподобное значение не подставляется: подставленное
неотличимо от выведенного.

Форма записи не даёт места пометке нехватки - тред с неизвестным обязательным полем в файл не
пишется, а перечисляется в выходе поимённо, с полями, которых не хватило.

## Тип и уровень на следующих прогонах

Заведение треда повторно не пишется, поэтому тип и уровень следующим прогоном не переписываются
вовсе: расхождение с прежней разметкой - находка о разметке, она называется в выходе обеими
сторонами, и решение о смене принимает вызывающая сторона.
