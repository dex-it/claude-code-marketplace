# /resolve-conflicts

Подтянуть актуальную базовую ветку в фича-ветку и свести два набора намерений в один результат без потери функционала ни одной стороны. Финиш - локально разрешённая ветка; push отдельно.

## Goal

Вызови `Skill` -> `dex-skill-merge-conflict-resolution:merge-conflict-resolution` и веди интеграцию по его протоколу; ниже - только цикл с оператором.

## Input

Опционально base-branch (по умолчанию `origin/develop` или `origin/main` по политике проекта), feature-branch (по умолчанию HEAD) и режим merge или rebase (по умолчанию merge). Режим rebase - только для приватной ветки и по политике линейной истории.

## Output

- Якоря, точка отката и карта конфликтов по типам из превью без записи
- План сведения обоих намерений по каждому конфликту; отдельным списком - зоны без маркеров, где база переименовывала или меняла сигнатуры, а фича их зовёт
- После `делай` - реальный merge/rebase и разрешение по одному
- Раздел верификации: обе дельты обойдены, сборка и тесты зелёные на результате
- Финал по `коммить` - merge-коммит или завершённый rebase; push не сделан

## Constraints

- Участок с confidence ниже 80% - вопрос оператору, не компромисс наугад
- Осознанное вытеснение одной стороны - строка с причиной, не тихое решение
- В разрешение попадает только сведение сторон; попутная правка - отдельный коммит вне слияния
- Верификация не зелёная - откат к backup-ref; незакрытое слияние наружу не отдаётся

Команды цикла: `оформляй` (карта конфликтов и план разрешения, дерево не тронуто), `делай` (реальный merge/rebase по одному конфликту), `коммить` (финализировать при зелёной верификации), `откати` (`--abort` или reset к backup-ref), `стоп` (прекратить, дерево и индекс оставить как есть, их состояние назвать в отчёте - откатывает только `откати`). Следующий шаг - `/self-review` перед push.
