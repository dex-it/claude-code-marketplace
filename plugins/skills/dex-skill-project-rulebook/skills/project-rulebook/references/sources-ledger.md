# Реестр источников свода

Читается до первого прогона и при каждом повторном. Реестр - не отчёт о работе, а **состояние зоны на диске**: по нему следующий прогон отличает непросмотренное от просмотренного и не начинает обход заново.

## Зачем исход на каждом источнике

Полнота свода не абсолютна и абсолютной быть не может. Она измеряется относительно названного источника: у каждой просмотренной единицы истории есть исход - дала правило либо помечена «без правила» с основанием. Без этого «просмотрели 200 MR» и «просмотрели 200 MR и ничего не нашли» неотличимы, а второе обычно означает первое.

Отсюда правило: **источник без исхода считается непросмотренным**. Молчание о нём читается следующим прогоном как «сюда не смотрели», и он смотрит туда снова.

## Единица реестра

Единица - не MR целиком, а то, что реально давало или не давало правило:

| Класс | Что записывается |
|---|---|
| MR/PR | идентификатор, дата слияния, число разобранных тредов, исход |
| тред | идентификатор, автор замечания, исход |
| коммит после ревью | sha, что связал с каким тредом, исход |

MR записан, а его треды - нет: тогда исход MR читается как непроверенный, потому что правило живёт в треде, а не в заголовке.

## Перечень исходов - закрытый

| Исход | Когда ставится |
|---|---|
| `rule` | дал единицу; называется её идентификатор |
| `duplicate` | повторил уже принятую единицу; называется её идентификатор |
| `no-rule:unresolved` | тред закончился без исхода: возражение автора не снято и не принято |
| `no-rule:tool-covered` | предмет удерживается инструментом; называется инструмент |
| `no-rule:one-off` | разовое обстоятельство, не переносится на другие случаи |
| `no-rule:out-of-scope` | предмет не относится к практике этого репозитория |
| `no-anchor` | кандидат был, якорь не подтвердился |
| `skipped:no-access` | источник не прочитан; называется причина |

Исхода вне перечня не бывает. Нужен новый - это правка норматива, а не решение прогона: исход, придуманный на ходу, следующим прогоном не читается.

## Окно и повторный прогон

Окно первого прогона задаётся входом либо берётся целиком по доступной истории, и выбор называется допущением.

Повторный прогон **читает реестр и работает с разностью**:

1. источники новее последнего записанного - просматриваются;
2. источники с исходом `skipped:no-access` - пробуются снова;
3. источники с исходом `no-rule:*` повторно не разбираются, пока не изменилось основание: инструмент отключён, предмет вошёл в охват, спор закрыт;
4. источники с исходом `rule` перечитываются только при правке породившей единицы.

Реестра нет, а свод есть - реестр восстанавливается по якорям принятых единиц, и восстановление называется в выходе. Восстановленный реестр знает `rule` и не знает `no-rule`: значит второй прогон пройдёт по тем же тредам, и это честнее, чем считать их разобранными.

## Что в реестр не пишется

- содержание правила - оно в разделе свода, здесь только идентификатор;
- счётчики прогона и время работы - служебное состояние, которое перестанут обновлять;
- имена людей вне того, что уже стоит в истории репозитория.
