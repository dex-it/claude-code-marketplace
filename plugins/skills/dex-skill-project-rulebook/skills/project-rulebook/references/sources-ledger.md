# Реестр источников свода

Читается до первого прогона и при каждом повторном. Реестр - не отчёт о работе, а **состояние зоны на диске**: по нему следующий прогон отличает непросмотренное от просмотренного и не начинает обход заново.

## Зачем исход на каждом источнике

Полнота свода не абсолютна и абсолютной быть не может. Она измеряется относительно названного источника: у каждой просмотренной единицы истории есть исход - дала правило либо помечена «без правила» с основанием. Без этого «просмотрели 200 MR» и «просмотрели 200 MR и ничего не нашли» неотличимы, а второе обычно означает первое.

Отсюда правило: **источник без исхода считается непросмотренным**. Молчание о нём читается следующим прогоном как «сюда не смотрели», и он смотрит туда снова.

## Единица реестра

Единица - не MR целиком, а то, что реально давало или не давало правило:

| Класс | Что записывается |
|---|---|
| MR/PR | идентификатор, дата слияния, число разобранных тредов, исход |
| тред | идентификатор, автор замечания, исход |
| коммит после ревью | sha, что связал с каким тредом, исход |
| тред на MR со сводом | идентификатор, автор, номер круга, исход |

Последний класс - разметка владельца на самом своде. Она источник наравне с историей: «у нас так принято» в ответ на предъявленное правило есть та же норма, высказанная тем же способом, и единица, заведённая с этим якорем, ничем не слабее выведенной из старого треда. Не записав её, прогон теряет единственный источник, который **отвечает**, и следующий круг предлагает владельцу то, что он уже отверг.

MR записан, а его треды - нет: тогда исход MR читается как непроверенный, потому что правило живёт в треде, а не в заголовке.

## Перечень исходов - закрытый

| Исход | Когда ставится |
|---|---|
| `rule` | дал единицу; идентификатор дописывает тот, кто выдал номер, а не тот, кто разобрал тред |
| `duplicate` | повторил уже принятую единицу; называется её идентификатор |
| `no-rule:unresolved` | тред закончился без исхода: возражение автора не снято и не принято |
| `no-rule:tool-covered` | предмет удерживается инструментом; называется инструмент |
| `no-rule:one-off` | разовое обстоятельство, не переносится на другие случаи |
| `no-rule:out-of-scope` | предмет не относится к практике этого репозитория |
| `no-anchor` | кандидат был, якорь не подтвердился |
| `no-rule:no-comments` | MR разобран целиком, замечаний в нём не было; сам по себе кандидат в класс «не удерживается» |
| `no-rule:filtered` | сообщение автора либо бота: тредом ревью не является, в знаменатель полноты не входит |
| `no-rule:rejected-by-owner` | кандидат был, владелец корпуса правило отверг; называется идентификатор отклонённой единицы |
| `skipped:no-access` | источник не прочитан; называется причина |

Исхода вне перечня не бывает. Нужен новый - это правка норматива, а не решение прогона: исход, придуманный на ходу, следующим прогоном не читается.

## Окно и повторный прогон

Окно первого прогона задаётся входом либо берётся целиком по доступной истории, и выбор называется допущением.

Повторный прогон **читает реестр и работает с разностью**:

1. источники новее последнего записанного - просматриваются;
2. источники с исходом `skipped:no-access` - пробуются снова;
3. источники, чья последняя активность новее их записи в реестре, - просматриваются заново: старый MR с дописанным вчера тредом иначе не попадает в разность никогда. Это правило **сильнее правила 4**: новая активность и есть наблюдаемое изменение основания;
4. источники с исходом `no-rule:*` повторно не разбираются, пока не изменилось основание. **Изменение основания сверяет узел на фазе чтения существующего свода**, и наблюдается оно так: `no-rule:tool-covered` - инструмент отключён, правило из его конфига снято, вес понижен до необязывающего, снят переключатель, включающий семейство, либо сменилась версия пакета проверок (её состав и веса по умолчанию меняются между редакциями, и правило может выпасть из покрытия без единой правки конфига); `no-rule:unresolved` - в треде появилась активность после даты записи; `no-rule:no-comments` - к MR добавлен тред. У `no-rule:one-off`, `no-rule:out-of-scope` и `no-rule:filtered` наблюдаемого признака нет, и при отсутствии новой активности они **окончательны**: пересмотр по ним - запрос владельца корпуса, не решение прогона. `no-rule:rejected-by-owner` окончателен всегда, включая новую активность: владелец правило отверг, и повторное предложение его же - шум. `duplicate` и `no-anchor` пересматриваются вместе с породившей их единицей;
5. источники с исходом `rule` перечитываются только при правке породившей единицы.

Состояние зоны действительно там, где лежит свод. Прогон, чей свод ещё не попал в базовую ветку, оставляет реестр в своей ветке: повторный прогон в другом клоне обязан получить путь к ней либо объявить себя первым - иначе он честно начнёт обход заново. Реестра нет, а свод есть - реестр восстанавливается по якорям принятых единиц, и восстановление называется в выходе. Восстановленный реестр знает `rule` и `no-rule:rejected-by-owner` (отклонённая единица остаётся в своде со своим статусом) и не знает остальных `no-rule`: значит второй прогон пройдёт по тем же тредам, и это честнее, чем считать их разобранными.

## Что в реестр не пишется

- содержание правила - оно в разделе свода, здесь только идентификатор;
- счётчики прогона и время работы - служебное состояние, которое перестанут обновлять;
- имена людей вне того, что уже стоит в истории репозитория.
