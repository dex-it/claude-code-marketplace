# Формулирование ADR - норма, а не протокол кода

**ADR - спецификация, по которой пишут код, а не описание того, что код уже делает.**
Каждое правило ниже - частный случай одного отклонения: автор писал ADR *по коду*, имея
код перед глазами. Норма при этом получается нечитаемой как инструкция: по ней нельзя
писать код, её нельзя нарушить, её нельзя проверить.

Правила применяются и при написании ADR, и при ревью чужого.

## 1. Норма отдельно от состояния кода

**Правило.** Раздел «Решение» - только целевая норма. Состояние текущей реализации - в
отдельном разделе-приложении («Расхождения с текущим кодом»), между «Вне рамок» и
«Открытыми вопросами». Не вперемешку.

**Проверка.** Удали раздел «Расхождения» - «Решение» обязано остаться полным и осмысленным.
Норма стала непонятной после удаления -> она опиралась на код.

**Почему.** Приложение протухает с первой правкой кода, норма протухать с ним не должна.
Смешение читается как «ADR писали по коду»: непонятно, норма это или описание, и любое
расхождение становится спорным.

## 2. Норма предписывает, а не констатирует

**Правило.** Каждый пункт - исполнимая инструкция в императиве: что делаю / чего не делаю.
Утверждение о свойстве системы («мапперов девять», «идентичность детерминирована») нормой
не является: из него не выводится действие.

**Проверка.** «Что конкретно я должен написать в коде?» Нет ответа -> не норма, а
наблюдение: переписать в императив или убрать в «Расхождения».

**Почему.** ADR - действующее ограничение на код. Констатацию нельзя ни выполнить, ни
нарушить, значит ограничением она не является.

## 3. Форма пункта - Правило / Проверка / Почему

**Правило.** Пункт нормы состоит ровно из трёх частей в этом порядке: **Правило** (императив,
без упоминаний кода) -> **Проверка** (каким тестом/гейтом/ревью ловится нарушение) ->
**Почему** (обоснование, цитаты источника, цена нарушения).

**Проверка.** Пункт без «Проверки» - пожелание, не норма. «Почему» перед «Правилом» - эссе
с выводом в конце.

**Почему.** Правило первым - читатель сразу знает требуемое и читает обоснование только при
сомнении; обоснование первым заставляет удерживать контекст, не зная, к чему он. «Проверка»
отличает норму от благого намерения: нарушение, которое ничем не ловится, правилом не
охраняется.

## 4. Замкнутость области

**Правило.** ADR покрывает все вопросы внутри своих границ. Знание, без которого код
написать нельзя (контракт границы, эндпоинты, модели сообщений, форматы, структуры данных),
входит в ADR отдельным разделом, а не остаётся отсылкой к коду. Вынесенное за границы -
поимённо в «Вне рамок» со ссылкой на владеющий ADR.

**Проверка.** Инженер без единой строчки кода реализует подсистему по ADR, не задав ни
одного вопроса. Каждый вынужденный вопрос - дыра.

**Почему.** ADR с дырой отправляет читателя в код за недостающим, и код снова становится
источником нормы - правило 1 обходится с чёрного хода.

## 5. Норма формулируется так, будто кода ещё нет

**Правило.** В разделах нормы - ни одного `file:line`, ни одного имени класса/файла как
несущего элемента. Якоря живут в двух местах: карта кода в шапке (навигация) и «Расхождения»
(доказательство факта). Норма - в терминах домена: «тип конфигурации -> формат X», не
«маппер Y -> DTO Z».

**Проверка.** Скрой имена файлов и количества из реализации - норма обязана остаться
формулируемой. Числа вида «9 из 13» в норме - маркер факта о коде, его место в
«Расхождениях».

**Почему.** Имя класса переживает один рефакторинг, норма обязана пережить все. Пункт из
таблицы «триггер -> файл:строка» - карта кода, её место в шапке.

## 6. Источник требования - у каждого пункта явно

**Правило.** Каждый пункт помечен источником требования, источники не смешиваются:
обязательное по внешнему источнику (нарушение ломает контракт платформы/стандарта);
инженерно обязательный фикс (источник прямо не требует, цена реальна и предъявлена);
инженерный инвариант (нужен для предсказуемости); рекомендация (целевая форма, корректность
обеспечивается и без неё).

**Проверка.** Ярлык «обязательное по внешнему источнику» опирается на цитату, где требование
сформулировано явно. Нет цитаты -> это инженерный вывод, не «обязательное».

**Почему.** Смешение обесценивает шкалу: когда всё «обязательное», приоритет не читается.
Разный источник - разная очередь внедрения и разный вес в споре.

## 7. Внешний источник старше нашего кода

**Правило.** Внешний нормативный источник (стандарт, протокол, спецификация платформы)
перечисляется в шапке с сокращениями и цитируется **дословно** в «Почему». Вывод из нашего
кода ему не конкурент. Сверка обязана иметь право опровергнуть ранний собственный вывод:
опровергнутое реверсится и помечается как реверс, не смягчается.

**Проверка.** Каждая ссылка «обязательно по X» несёт цитату, а не пересказ. Вывод,
развернувшийся при сверке, назван реверсом явно («это реверс первоначального вывода») в
«Альтернативах»/журнале, а не заменён тихо.

**Почему.** Практика, наблюдаемая в коде, - не аргумент о должном: она ровно то, что
проверяется. Тихая замена вывода прячет, почему раньше считалось иначе, и вывод возвращается
следующим автором.

## 8. Открытый вопрос - с рабочим дефолтом, не блокирующий

**Правило.** «Открытые вопросы» содержат только не выводимое из кода и источников
(продуктовое/бизнес-намерение). У каждого - принятый рабочий дефолт, обоснование дефолта и
предложение владельцу («принял X, потому что Y; подтверди или поправь»).

**Проверка.** Вопрос без дефолта = блокер, которого быть не должно. Вопрос, ответ на который
выводится из кода/источника, - не открытый вопрос, а невыполненная работа автора.

**Почему.** ADR не должен ждать: ответ владельца уточняет формулировку, но не является
условием принятия решения.

## Грабли процесса (работа с файлом ADR)

| Грабля | Правило |
|---|---|
| Перезапись ADR целиком поверх файла, который могли править другие | Перед перезаписью - fetch + сверка с целевой веткой: правки ревьюера могли уехать в базу, локальная копия - отстать. После перезаписи сверить перенос поимённо по диффу ревьюера, не по памяти. Затёртая правка ревьюера не видна ни в одном тесте |
| Перенумерация пунктов ломает внешние ссылки | Пункты ADR - публичный якорь: на них ссылаются описательные документы, планы, журналы, соседние ADR. Сдвинул нумерацию -> свип по всем документам, включая подпункты (`п.7.4` -> `п.7.3` ловится только точным поиском) |
| DoD-чекбокс отмечен по намерению, а не по факту | Закрывая чекбокс - открыть артефакт и убедиться глазами. Обнаружил фиктивный -> закрыть с пометкой, почему был фиктивным, не тихо доделать |
