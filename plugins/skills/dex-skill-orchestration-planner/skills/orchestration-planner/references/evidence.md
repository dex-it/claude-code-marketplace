# Основания правил

Файл нужен ревью, при планировании не читается. Дата сверки 2026-10-08. Метки: **[док]** -
документация или руководство Anthropic; **[arXiv]** - статья, id сверен по API arXiv, число из
аннотации либо помечено `*` (из полного текста, не перечитано по таблицам); **[практика]** -
открытые репозитории, не измерение; **[замер]** - измерено здесь, с методом; **[гипотеза]** -
решение автора, проверяется прогоном. Правило без метки в списке ниже перечислено в разделе
«Не подтверждено».

## Что на чём стоит

1. **Сначала схема исполнения, оркестрация не по умолчанию.** [док] Оркестратор окупается, когда
   есть «много независимых кусков, в идеале не помещающихся в один контекст»; на зависимой
   цепочке и на работе в одном контексте «модель-координатор одна на пониженном effort
   оказывалась впереди» (Optimizing for cost and intelligence; claude-api, cost-optimization 2.7).
   [arXiv] Многоагентность проигрывает на последовательных задачах (до -70%), на инструментоёмких,
   там, где один агент и так успешен в заметной доле случаев (около 45%*), и при равном бюджете
   токенов; расход токенов выше на 58-515%* (2512.08296*, 2604.02460). Параллельные субагенты в
   кодовых агентах стоят в 1.4-3.3 раза больше токенов (2610.10263*).
2. **Effort раньше тира.** [док] «Tuning effort is often a better lever than switching models»
   (Choosing a model); `low` на знаниеёмкой работе теряет 1-3 пункта за треть-половину цены, на
   длинном кодировании ступень вниз заметнее (Optimizing for cost and intelligence). [arXiv]
   Адаптивный effort на шаг экономит 35-53% токенов рассуждения, равномерно низкий вредит
   (2603.07915, 2604.05164); более длинное рассуждение иногда снижает точность (2507.14417).
3. **План течёт вниз.** [arXiv] План сильной модели поднимает слабого исполнителя, план слабой
   вредит сильному (2506.11578*); назначение тиров на этапе планирования дало -44% цены при -2.9
   пункта (2609.32917, [W]). Отсюда хост планировщика - старшая модель.
4. **Маршрутизатору нужна информация, а не размер.** [arXiv] Роутер на Sonnet 4.6 без приоров 41.4
   против 47.3 у обученного классификатора; с таблицей результатов по категориям 47.7, на новых
   агентных задачах обученные роутеры падали до 8.9-21.4 (2606.22902*); размер энкодера роутера
   почти не помогает (2609.34326); шесть коммерческих роутеров не обогнали случайный выбор между
   двумя хорошо выбранными моделями (2610.02762*). Типовые провалы роутеров: слепота к трудности,
   маршрутизация по категории, почти постоянный тир, растущая к концу агентной задачи
   самоуверенность (2610.02762*, 2608.14641, 2512.24661). Вывод: `haiku` как предлагающий
   триажёр с правилами и приорами оправдан, внешний платный роутер доказательствами не подкреплён;
   единственный судья трудности `haiku` не годится - есть лестница повторов. [док] Haiku 5.5
   назван для «classification, routing, extraction, subagent tasks». Согласие двух прогонов вместо
   заявленной уверенности: DART (2606.23181).
5. **Повтор по сигналу.** [док] Прогон на низком effort и повтор провалов на высоком: около 97%
   прохождения за примерно 60% цены прогона всего на высоком (Optimizing for cost and
   intelligence); исполнители Haiku 5.5 и Sonnet 5.5 с советником Opus не обратились к нему ни
   разу на 198 вопросах. [arXiv] Эскалация по доказательству, а не по самооценке (2607.00053,
   2311.05772). [практика] Потолок попыток и конечное состояние `blocked`: superpowers, GSD, BMAD.
   Ступени лестницы `haiku`/`sonnet`/`opus` по `medium`/`high` - [гипотеза].
6. **Независимость проверки.** [arXiv] Источник свидетельства влияет на 40.9 п.п., разнообразие
   моделей на 11.3 (2609.10969, [W]); ошибки сильных моделей коррелируют сильнее (2502.04313);
   несколько независимых попыток с голосованием часто выгоднее отдельного верификатора
   (2504.01005). [док] Явные указания «проверь субагентом» на Opus 5 дают избыточную проверку
   (Prompting Claude Opus 5) - поэтому независимая проверка назначается точечно (`B=2`, `V=2`).
7. **Брифы и отчёты через файлы.** [док] Субагенту нужны «цель, формат выхода, указания по
   инструментам и источникам, чёткие границы» (Anthropic, multi-agent research system); возврат
   сжатый, порядка 1-2 тыс. токенов (context engineering). [практика] superpowers: диспетчер
   передаёт путь к брифу, исполнитель возвращает статус и пишет отчёт в файл.
8. **Спавн не бесплатен.** [замер] Стартовый контекст субагента Haiku 5.5 в headless-прогоне
   2026-10-08 - около 14.7 тыс. токенов записи кеша до первого слова работы (`claude -p`,
   `modelUsage`); уведомление о завершении трёх простых исполнителей дало 22-26 тыс. токенов на
   каждого. Субагент не читает кеш родителя (code.claude.com, prompt-caching, [док]). [док]
   Opus 5 тянется к субагентам охотнее прежних, поэтому потолок спавнов в плане детерминированный
   (`max_spawn`), а не просьба.
9. **Параллелизм.** [arXiv] Централизованная схема с потолком в 3-4 агента (2512.08296*); основная
   причина провалов параллельных субагентов - запись в общий результат и лишний спавн
   (2610.10263*). `max_parallel` по умолчанию 2 - [гипотеза], выбор ниже границы 3-4 в пользу
   меньшего расхода и стабильности; пользователь поднимает.
10. **Добавки по тирам.** [док] Для Haiku 5.5 и Sonnet 5.5 на агентной работе и низком effort:
    абзац «работай, пока не сделано» и абзац про настоящую проверку изменения (Prompting Claude
    Haiku 5.5, Prompting Claude Sonnet 5.5). Просьба «думай меньше» effort не снижает. Просьба
    выписать рассуждения может быть отклонена как `reasoning_extraction`. Структурный поиск с
    конкурирующими гипотезами для исследования - пример из Prompting best practices.
11. **Платформа.** [док] Алиасы моделей и версия Claude Code (model-config); порядок выбора
    модели субагента, вложенность, предел одновременных (sub-agents); `${CLAUDE_EFFORT}` в теле
    скилла (skills); именованный вызов `Agent` и команды агентов (agent-teams).

## Не подтверждено

- Правила без внешнего основания, [гипотеза]: финальная сборка не ниже `sonnet`; проверяющий
  не ниже автора ([практика]: BMAD, superpowers); `haiku` только при `A=0` и `B<=1`
  ([практика]: superpowers); потолок недоверенного содержимого (смысл - 2501.01818, [arXiv]: инъекции,
  принуждающие к эскалации); границы категорий по `S`; пороги «четыре и больше новых задач»,
  «150 слов», «пять строк журнала».
- Прямого сравнения «промтом управляемый Haiku-роутер против обученного» на агентных задачах нет;
  ближайшее - Sonnet 4.6 в 2606.22902.
- Параметр `effort` в вызове `Agent` виден в схеме инструмента версии 2.1.294 и на странице
  субагентов не описан; пробный запуск 2026-10-08 показал, что вызов с `model` и `effort` проходит
  и меняет объём рассуждения исполнителя (thinking-токены Haiku 5.5: 3.4 тыс. на `low` против 4.8
  тыс. на `max`, один прогон). Приоритет относительно `CLAUDE_CODE_EFFORT_LEVEL` не проверен.
- Числа с `*` перечитаны через сводку страницы, не по таблицам статьи; перед внешним цитированием
  сверять с оригиналом. Статьи [W] - рабочие гипотезы.
- Смены контекста долгого исполнителя (потолок и передача) в версию не вошли: механизм замера и
  остановки исполнителя не подтверждён прогоном.
