# План реализации - форма автора

<!-- skill-type: process -->

План раскладывает принятое решение на шаги. Здесь - что пишет у шага автор плана.

## Поля шага

Шаг записан, когда у него заполнены все поля; поле, которое к шагу не относится, несёт `-` с причиной.

| Поле | Что пишется |
|---|---|
| Закрывает | требования, которые шаг закрывает, их идентификаторами; вспомогательный шаг называет шаг, которому служит. Шапка плана несёт их версии в `derived-from` (`node-contract`, `references/derived-from.md`) |
| Предмет правки | объекты, которые шаг меняет, по имени: какая таблица, модуль, контракт, документ, конфигурация. Категория правки («схема», «индекс», «модуль записи») предметом не является, чтение - тоже |
| Исход | результат, наблюдаемый без автора: тест, запрос, метрика, файл. «Реализовано», «работает», «покрыто тестами» исходом не являются |
| Проверка | что прогоняется сразу после шага и подтверждает его исход |
| Зависит от | шаги, после которых шаг начинается, либо `-` |

## Параллельность

Шаги без зависимости между собой идут параллельно. Шаги, меняющие один объект, параллельными не
объявляются: между ними стоит зависимость, и порядок назван. Объект меняет и шаг, меняющий его схему,
индекс, данные или код записи в него. Шаг-наблюдение (замер, сверка) связан
зависимостью с каждым шагом, меняющим наблюдаемую величину, даже если объекты правки у них разные: база замеряется
до такого шага, сверка идёт, пока она сходится.
