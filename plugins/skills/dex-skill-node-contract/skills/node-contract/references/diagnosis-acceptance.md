# Приёмка диагноза до правки

Материал `node-contract` по требованию; условие чтения - таблица «Материалы по требованию» в
`SKILL.md`.

Диагноз - причина бага и воспроизводящий тест, пришедшие от другого узла. Для правящего это claim:
правка по непроверенному диагнозу чинит не то, а тест, исправленный под свою правку, зеленеет на
любом фиксе.

## Исполнитель правки

До первой правки прогони тест на коде, на котором поставлен диагноз, и сверь прочитанный код с
причиной. Дерево уже несёт правки этой работы (коммиты её ветки, изменённый продуктовый код), а
исхода приёмки во входе нет - тест диагноза прогоняется на продуктовом коде без них; позеленевший
от этих правок тест - не `disputed-test`. Исход - поле `diagnosis-check`:

| Наблюдение | `diagnosis-check` | Действие |
|---|---|---|
| тест красный, падает на проверке симптома через продуктовый путь | `accepted` | правка; тест - твоя проба red->green, своя не пишется |
| тест падает до проверки симптома: setup, импорт, мок, окружение | `harness-fixed` | чинишь обвязку, проверку не трогаешь; что сломано и чем показано - строкой `decisions`; дальше как `accepted` |
| тест зелёный на коде диагноза, проверяет не симптом или обходит продуктовый путь | `disputed-test` | правку не вносишь |
| прочитанный код противоречит причине: правка по ней симптом не снимает, источник в другом месте | `disputed-cause` | правку не вносишь |
| тест утверждает поведение, против которого стоит источник ожидаемого (вход, критерий приёмки, требование) | `disputed-expected` | правку не вносишь |
| теста в диагнозе нет | `n/a` с причиной диагноста | пробу пишешь сам по описанию воспроизведения |

Граница обвязки и проверки - что тест утверждает о продукте: вход, вызываемый путь, ожидаемое.
Правка, меняющая любое из трёх, - спор, а не `harness-fixed`, при любом её объёме.

До первой правки сними тест: `git hash-object -w <путь>`. `harness-fixed` - второй снимок после
починки обвязки, `git diff <первый> <путь>` - строкой `decisions`; действует последний. Перед
каждым коммитом и перед сдачей сверь `git hash-object <путь>` со снимком: расхождение - тест
восстанавливается `git show <снимок> > <путь>`. Исход приёмки пришёл во входе со снимком - приёмку
провёл прошлый исполнитель той же работы: не повторяешь, `diagnosis-check` - пришедший исход, сверка -
с пришедшим снимком. Правке после
приёмки нужна другая проверка - тест не трогаешь, `disputed-*` с уликой, `status: partial`.

`disputed-*` несёт улику полем `dispute`: `файл:строка` или вывод прогона и то, какое звено диагноза
она опровергает. Несогласие без улики спором не считается - исход `accepted`. При споре дерево не
меняется и коммита нет, `status: partial`: развилку закрывает вызывающий, не ты.

## Вызывающий

Правящему идёт только диагноз с установленной причиной: `blocked` и `partial` без причины (гейт
первопричины, нужен runtime) - твой исход, приёмки нет. Следующему исполнителю той же работы
(новая попытка, правка по ревью, субагент) - исход приёмки во входе; спор после неё - твой исход.

Спор разрешается уликой, а не повтором мнений:

1. `disputed-test` / `disputed-cause` до приёмки - один повторный вызов автора диагноза с `dispute` и путём
   прежнего теста во входе: улика - первое направление его фальсификации. Устоявшая причина
   возвращается с тем, чем улика отбита (`файл:строка`); пересмотренная - новым диагнозом.
   Исполнитель правки получает ответ и принимает его заново по таблице выше.
2. Второй `disputed-*` по той же работе - `partial` наверх с обеими позициями и уликами; следующий
   круг начинает только оператор.
3. `disputed-expected` - к автору диагноза не ходит: выбор ожидаемого за владельцем требований,
   исход `blocked` с обеими сторонами.

Тест диагноза, по которому правки не будет (нет причины, пункты 2 и 3), в дереве, где работа
продолжается, не остаётся: снимок `git hash-object -w` и вывод падения - в твой выход, файл
удаляется. Останавливается вся работа в этом дереве - тест остаётся, путь назван в выходе.
