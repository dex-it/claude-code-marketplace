# derived-from: версия источника в шапке выведенного артефакта

Материал `node-contract` по требованию; условие чтения - абзац о `derived-from` в разделе C
`SKILL.md`.

Содержание:
1. Что несёт поле и кто его пишет
2. Версия единицы требований
3. Сверка и исходы
4. Границы

## Что несёт поле и кто его пишет

Артефакт, выведенный из единиц требований (план реализации, дизайн-документ, ADR), несёт в шапке
`derived-from`: перечень `ID@revision` единиц, из которых он выведен. Пишет автор при написании:
по единице на каждую, названную в `Закрывает` плана, `drivers` ADR, ключевых требованиях дизайна.
Источника у артефакта нет -> поля нет, и это не дефект. Источник названен, а поля нет -> дефект
автора (исход ниже).

```
derived-from:
  - FR-012@r3 (9f2c1ab)
  - NFR-004@r1 (c41d07e)
```

## Версия единицы требований

Версия единицы = `revision` документа, который её несёт: значение из записи судьи в
`<документ>.checks.md`, отражённое в шапке документа (`references/revision.md`). Записывается целиком,
как в записи: `rN` и указатель на судимое в скобках. Номер без указателя текст, правленный мимо суда,
от судимого не отличает, а после правки принятого документа счёт идёт с R1 и номер повторяется.

Почему этот носитель: у него один писатель (судья) и наблюдаемое значение на диске. Правка принятой
единицы (`unit-identity`) числа не оставляет - род изменения пишется в `decision-log` без счётчика;
второй счётчик под именем `revision` - дефект (`references/revision.md`). Следствие: версия
у документа, не у единицы. Расхождение говорит «документ судился заново», а не «изменилась именно эта
единица»; ложное устаревание дёшево (автор сверяет формулировку и переподтверждает пин), тихое
пропущенное - нет.

## Сверка и исходы

Приёмник находит единицу по `ID` в корпусе (расположение - сквозное поле), берёт текущий `revision`
документа по старшинству носителей (`references/quality-mark.md`) и сличает с пином до работы по
существу.

| Состояние | Исход |
|---|---|
| все пины совпали | работа идёт; в отчёт строка `derived-from: сверен` |
| пин расходится, либо единицы по `ID` больше нет | `status: partial`; пункт незакрытого со статусом `contradicted`: «источник изменился после написания: `<ID>`: было rN, стало rM» (единицы нет: «было rN, единицы нет»). Части, опирающиеся на эту единицу, в работу не берутся |
| текущий `revision` прочесть нельзя (корпус не пришёл, записи судьи и шапки нет) | `partial`; пункт со статусом `unverifiable` и причиной. Сверка без текущей версии не засчитывается |
| пин без версии или не разбирается | нехватка по п.8 `SKILL.md`: поле пришло, смысл непонятен; возврат автору той же формой |
| поля нет | сверка не выполнена: в отчёт `n/a` с причиной «derived-from не задан», приёмник не блокируется. Тип из первого абзаца с названным источником и без поля - ещё и находка автору, `severity: MEDIUM` |

Возврат автору - по форме `references/finding-return.md`: `anchor` - строка `derived-from`
дословно; `closure` - «сверь формулировку `<ID>` с текущей: смысл не изменился -> обнови пин, изменился
-> перепиши затронутое»; `severity: HIGH` у расхождения пина, `MEDIUM` у отсутствующего поля.
Приёмник артефакт не правит и версию в нём не обновляет: пин подтверждает тот, кто сверил смысл.

## Границы

- Охват первой итерации: план реализации, дизайн-документ фичи, ADR. SAD продукта вне охвата: он один
  на продукт, пины на многие документы давали бы ложные устаревания. Код и тесты шапки не имеют - вне
  охвата; связь «тест -> `FR`» остаётся поиском по `ID`.
- Обратной проверки нет: правка требования не выдаёт перечня задетых производных, их поиск по номеру
  ручной. Поле работает на входе следующего узла.
- Каскад «основание изменено» внутри зоны требований (`references/revision.md`) остаётся как есть.
