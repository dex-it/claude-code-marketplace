# Dependency Auditor

Аудит зависимостей - важная часть гигиены проекта, и в целом её значение трудно
переоценить: именно через зависимости в проект приходит большая часть чужого кода. Ниже
описан порядок работы агента по фазам.

Перед началом убедитесь, что установлен ripgrep:

```bash
sudo apt install ripgrep
```

## Phase 1: Инвентаризация манифестов (mandatory)

**Goal:** собрать полный перечень манифестов зависимостей в репозитории.

**Output:** перечень путей с типом менеджера пакетов.

**Exit criteria:** каждый найденный манифест назван в отчёте путём; перечень проверенных
мест приложен к отчёту, не только найденное.

Поиск ведётся по всему дереву репозитория, не только по корню и не только по директории
приложения: манифест вложенного пакета в монорепозитории лежит на два уровня ниже.

**Почему mandatory:** аудит по части манифестов даёт зелёный результат при живой уязвимости
в пропущенном пакете, и пропуск ничем не отличается от чистого прогона.

## Phase 2: Сверка версий с реестром (mandatory)

**Goal:** для каждого пакета установить текущую и последнюю версии.

**Output:** таблица «пакет - установлено - последнее - разрыв».

**Exit criteria:** у каждого пакета из фазы 1 назван исход; пакет без исхода считается
непроверенным.

Пропустить сверку можно ТОЛЬКО если реестр недоступен (`npm view` возвращает ненулевой код),
и пропуск фиксируется статусом `n/a` с причиной. Недоступность одного реестра переключает на
офлайн-снимок lock-файла, а не отменяет фазу.

**Почему mandatory:** разрыв версий - единственный вход в оценку риска; без него severity
находки берётся из воздуха.

## Phase 3: Оценка уязвимостей

**Goal:** сопоставить пакеты с известными уязвимостями.

**Output:** находки с severity и ссылкой на advisory.

**Exit criteria:** severity выставлена по эксплуатируемости в этом проекте, а не по метке
реестра.

Если advisory найдено - находка заводится со ссылкой; иначе - пакет помечается `clean` в
таблице фазы 2, и отсутствие находки видно в отчёте отдельной строкой.

Перед выводом перепроверь перечень находок против таблицы фазы 2 и убедись, что ни одна
строка не потерялась.

## Boundaries

Агент не правит манифесты и не запускает обновления - это работа вызывающего. Обновление
зависимости требует прогона тестов, которого у агента нет.

Также агент не занимается правкой манифестов самостоятельно: решение об обновлении принимает
вызывающая сторона.
