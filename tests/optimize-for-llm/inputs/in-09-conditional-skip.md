# Data Migration Track

Стоит отметить, что трек ведёт перенос данных от инвентаризации источника до приёмки результата
оператором. Раньше эта процедура жила прямо в теле движка, и мы вынесли её в отдельный носитель,
потому что движок разросся; в целом это оказалось удачным решением, хотя обсуждалось долго.

Установка утилиты сверки: `cargo install checksum-diff --locked`. После установки она доступна
как `checksum-diff` в PATH.

**Режим - из входа (`mode`), дефолт `autonomous`:**

- `interactive` (канал к оператору ЕСТЬ): полномочная ось закрывается явным ответом оператора,
  молчание ответом не считается;
- `autonomous` (канала нет): полномочная ось закрывается **только** выводом из уже принятого;
  основания нет -> пункт остаётся открытым и едет наверх.

**Оператору предъявляется решение, а не список находок.** Находка сортируется по разрешимости:
выводимая закрывается здесь же и предъявляется строкой «принято X, потому что Y» в общем списке;
невыводимая предъявляется вопросом с вариантами и рекомендацией. Оператор подтверждает оба
класса, но разной ценой внимания: невыводимое - поштучно, принятое - списком целиком.

## Обзор фаз

| # | Фаза | Пометка |
|---|---|---|
| 0 | Инвентаризация источника | mandatory |
| 1 | План переноса | mandatory |
| 2 | Перенос схемы | conditional |
| 3 | Перенос данных | mandatory |
| 4 | Сверка и приёмка | mandatory |

## Phase 2: Перенос схемы

**Goal:** привести схему приёмника к виду, который принимает данные источника без потерь.

**Conditional, skip_if:** объявлена ветка «схема совпадает» - структура приёмника уже описывает
все поля источника, включая типы и ограничения. Объявление несёт основание и уходит в журнал
решений: иначе объявление ветки становится способом пропустить сверку схемы.

**Output:** DDL приёмника, перечень несовпадений с источником, решение по каждому.

**Exit criteria:** каждое поле источника имеет адресата в приёмнике либо названо выпадающим с
причиной; полей без исхода не остаётся.

Mandatory: no - фаза пропускается ТОЛЬКО по условию skip_if выше, и пропуск фиксируется статусом
`n/a` с основанием. Почему mandatory-пометка тут «no»: без этой фазы схема разъедется и данные
лягут в чужие колонки, поэтому пропускать её просто так нельзя.

## Phase 4: Сверка и приёмка

**Goal:** доказать, что перенесённое совпадает с источником, и сдать результат оператору.

**Output:** контрольные суммы по каждой таблице с обеих сторон, перечень расхождений, решение по
каждому расхождению.

**ОСТАНОВКА (безусловная, единственная в треке):** приёмка результата целиком - план из Phase 1,
перечень несовпадений схемы и таблица контрольных сумм предъявляются одной пачкой, иначе сверка
становится второй остановкой. Форма предъявления: выводимое - списком принятых решений,
невыводимое - вопросом с вариантами и рекомендацией; полномочная ось вопросом всегда.

**Exit criteria:** оператор ответил явно (в `autonomous` - остановка закрыта выводом из принятого
и список «принято за оператора» предъявлен первым); расхождение контрольных сумм закрыто повторным
переносом либо названо принятым с причиной.

## Boundaries

- Не переносить данные до закрытия Phase 2 - порядок фаз здесь не рекомендация, а условие
  целостности.
- Ветка «схема совпадает» - объявленное условие с основанием, а не способ сократить путь.
- Не сверять по числу строк вместо контрольных сумм: совпавшее число строк при разъехавшемся
  содержимом читается как успех.
