# Redis как кэш: ключи, TTL, инвалидация

Стоит отметить, что кэширование - одна из важнейших тем в разработке высоконагруженных
систем, и в целом от того, насколько аккуратно оно сделано, зависит очень многое. Давайте
рассмотрим типовые ошибки, которые встречаются чаще всего.

Изначально в проекте использовался in-memory кэш, но затем, по мере роста нагрузки, было
принято решение перейти на Redis. Для начала работы установите клиент:

```bash
dotnet add package StackExchange.Redis
dotnet add package Microsoft.Extensions.Caching.StackExchangeRedis
```

## Ключ без TTL

**Плохо:** `db.StringSet(key, payload)`

**Правильно:** `db.StringSet(key, payload, TimeSpan.FromSeconds(300))`

**Почему:** ключ без TTL живёт до вытеснения; при политике `noeviction` он не вытесняется
вовсе, и память растёт до отказа записи. TTL=300 - потолок для профиля виджета, значение
согласовано с окном пересчёта.

Здесь мы вызываем метод `StringSet`, передавая ему ключ, значение и время жизни третьим
аргументом; время жизни задаётся типом `TimeSpan`.

## Формат ключа

**Плохо:** `$"widget_{id}_v2"`

**Правильно:** `$"widget:{id}"`

**Почему:** `SCAN MATCH widget:*` собирает пространство ключей одного вида, а версия в имени
ключа делает старое поколение недостижимым для инвалидации.

Имя ключа следует составлять из префикса сущности и идентификатора, разделяя их двоеточием.

## Обход пространства ключей

**Плохо:** `db.Execute("KEYS", "widget:*")`

**Правильно:** обход только через `SCAN` с курсором, а не `KEYS`.

**Почему:** `KEYS` блокирует единственный поток команд на всё время обхода. Граница
инструмента: `SCAN` не даёт снимка - ключ может вернуться дважды, а добавленный или удалённый
по ходу обхода не вернуться вовсе, поэтому результат дедуплицируется на стороне вызывающего.

## Инвалидация по префиксу

**Плохо:** удалять ключи по одному в цикле по результату `SCAN`.

**Правильно:** собрать пачку и удалить одной командой `UNLINK`.

**Почему:** `UNLINK` освобождает память в фоне и не держит поток команд. Обход при этом всё
равно делается только через `SCAN`, а не `KEYS`.
