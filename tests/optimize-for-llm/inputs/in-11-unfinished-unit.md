# Правила репозитория: фича-флаги

Стоит отметить, что фича-флаги - важная часть нашей культуры поставки, и давайте рассмотрим по
порядку, как мы с ними работаем. Раньше флаги жили в таблице `settings` и правились SQL-ом прямо
на проде, затем переехали в конфиг сервиса, а с прошлого квартала лежат в отдельном сервисе
флагов. Для локального прогона установите клиент: `npm i -g @acme/flags-cli`.

## Значение по умолчанию и раскатка

Новый флаг заводится выключенным. Включается он ТОЛЬКО раскаткой по проценту трафика, а не
рубильником на всех сразу: шаги `1% -> 10% -> 50% -> 100%`, между шагами сутки наблюдения за
ошибками потребителя.

Здесь мы просто читаем значение флага через клиент и сравниваем его с константой, после чего
возвращаем ветку по результату сравнения.

## Недоступность сервиса флагов

Сервис флагов не ответил за 2 секунды -> клиент берёт значение из локального снимка, записанного
последней успешной синхронизацией.

## Когда флаг не годится

Не годятся под флаг: смена формата сообщения в очереди, миграция схемы с удалением столбца,
правка формата файла выгрузки, смена алгоритма подписи вебхука, переход на новую мажорную версию
внешнего API.

## Снятие флага

Флаг несёт дату снятия в момент заведения. Дата прошла, флаг не снят -> задача на снятие заводится
в тот же день, и её приоритет не снижается ниже текущего спринта.

Флаг включается только раскаткой по проценту трафика - рубильником на всех сразу флаг не
включается ни при какой срочности.
