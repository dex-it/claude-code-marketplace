# Правила репозитория: миграции схемы

Файл читается разработчиком и главным потоком; тела агентов его не читают.

## Порядок выкатки миграции

Миграция едет отдельным релизом впереди кода, который её использует: сначала совместимая
схема, затем код, затем удаление старого столбца - тремя раздельными выкатками, а не одной.
Свести две выкатки в одну можно ТОЛЬКО при отсутствии живых читателей старого столбца,
подтверждённом запросом к `pg_stat_user_tables`; при недоступности статистики шаги не
сливаются.

## Обратимость

Каждая миграция несёт `Down`, проверенный прогоном на копии схемы. Проверка не прогнана ->
миграция не выкатывается, и это не смягчается близостью релиза.

## Данные в миграции

Перенос данных живёт отдельным шагом от изменения схемы: одна транзакция на DDL и перенос
миллионов строк держит блокировку таблицы весь перенос.
