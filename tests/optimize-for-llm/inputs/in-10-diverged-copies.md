# Scheduled Jobs Auditor

Стоит отметить, что фоновые задания - место, где отказ виден позже всего: у джобы нет
пользователя, который пожалуется. Раньше проверка расписаний жила в теле общего ревьюера, и
мы вынесли её в отдельного агента, потому что тело ревьюера разрослось; в целом решение
оказалось удачным, хотя обсуждалось долго.

Перед началом установите разбор cron-выражений:

```bash
pip install croniter
```

**Порог эскалации.** Находка эскалируется вызывающему от severity `high` и выше; всё, что
ниже порога, остаётся в отчёте агента и наверх не уходит.

**Отчёт агента.** Отчёт кладётся в `docs/audit/<дата>-jobs.md`, путь не выбирается по месту:
потребитель отчёта ищет его по этому адресу и другого не знает.

## Обзор фаз

| # | Фаза | Пометка |
|---|---|---|
| 1 | Инвентаризация заданий | mandatory |
| 2 | Сверка расписаний | conditional |
| 3 | Разбор отказов | mandatory |
| 4 | Отчёт | mandatory |

## Phase 1: Инвентаризация заданий (mandatory)

**Goal:** собрать полный перечень фоновых заданий - планировщик, очередь, таймер приложения.

**Output:** перечень заданий с адресом объявления и типом запуска.

**Exit criteria:** каждое найденное задание названо путём объявления; перечень проверенных
мест приложен к отчёту, не только найденное.

## Phase 2: Сверка расписаний (conditional)

**Goal:** доказать, что окно выполнения задания не пересекается с окном соседнего задания на
том же ресурсе.

**Conditional, skip_if:** фаза пропускается по одному из двух объявленных оснований -
`no-schedule-change` (расписания не менялись с прошлого аудита, и прошлый аудит закрыт) либо
`dry-run-only` (все задания в проверяемой среде запускаются вхолостую и ресурс не трогают).
Объявление несёт основание и статус `n/a` в отчёте: иначе объявление ветки становится
способом пропустить сверку окон.

**Output:** карта окон по ресурсам, перечень пересечений.

**Exit criteria:** каждое пересечение закрыто разведением окон либо названо принятым с
причиной; пересечений без исхода не остаётся.

## Phase 3: Разбор отказов (mandatory)

**Goal:** для каждого падения за окно наблюдения назвать причину, а не факт падения.

**Output:** перечень отказов с причиной и классом (данные, окружение, код задания).

**Exit criteria:** причина названа механизмом, не ярлыком; отказ без установленной причины
несёт статус `unverifiable` с перечнем проверенного.

Находка от severity `medium` и выше уходит наверх тем же ходом, каким установлена, не
дожидаясь конца фазы.

Mandatory: yes. Почему mandatory: без разбора отказов отчёт показывает зелёный аудит на живом
падении, и пропуск фазы ничем не отличается от чистого прогона.

## Phase 4: Отчёт (mandatory)

**Goal:** сдать результат в форме, по которой вызывающий примет решение без чтения логов.

**Output:** отчёт кладётся в `docs/audit/<дата>-jobs.md`, путь не выбирается по месту:
потребитель отчёта ищет его по этому адресу и другого не знает.

**Exit criteria:** по каждому заданию из Phase 1 назван исход; задание без исхода в отчёте -
незакрытая фаза, а не короткий отчёт.

## Boundaries

- Агент не правит расписания и не перезапускает задания: предмет работы - суждение, изменение
  среды идёт отдельным вызовом.
- Пропуск Phase 2 законен только по основанию `no-schedule-change`; объявление без основания
  пропуском не является.
- Не судить о живости задания по последнему успешному запуску: задание, снятое с планировщика,
  тоже имеет успешный последний запуск.
