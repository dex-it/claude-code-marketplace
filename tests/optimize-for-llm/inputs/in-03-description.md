# Медленные запросы в PostgreSQL

## План читается снизу вверх

**Плохо:** смотреть на верхнюю строку `EXPLAIN` и по ней судить о стоимости.

**Правильно:** читать план от самых вложенных узлов; `actual time` верхнего узла включает
время потомков.

**Почему:** стоимость верхнего узла кумулятивна, и оптимизация «самого дорогого» узла по
верхней строке уходит мимо реального источника времени.

## EXPLAIN без ANALYZE не даёт фактов

**Плохо:** `EXPLAIN SELECT ...` как основание для вывода о времени.

**Правильно:** `EXPLAIN (ANALYZE, BUFFERS) SELECT ...` - только с `ANALYZE` в плане есть
фактические строки и время.

**Почему:** без `ANALYZE` числа - оценка планировщика; расхождение оценки с фактом само по
себе находка и видно только при их сличении.

## Индекс не используется при несовпадении типов

**Плохо:** `WHERE user_id::text = $1` - приведение висит на колонке.

**Правильно:** приводить параметр к типу колонки: `WHERE user_id = $1::bigint`.

**Почему:** приведение типа на колонке делает индекс по ней недостижимым - планировщик
берёт `Seq Scan`, а не `Index Scan`.
