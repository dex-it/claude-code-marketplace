# Прогон: фича с нуля - все три зоны

**Тип прогона:** виртуальный (трассировка белым ящиком по тексту артефактов).

**Дата:** 2026-07-19

**Предмет:** `/feature` -> `requirements-orchestrator` -> `/design` -> `architect` -> движок `autonomous-task`.

**Состояние базы:** после коммита `5e8ccdf` (скилл `project-docs-map` роздан зоне 1). Прогон проверяет в том числе, не осталось ли той же дыры в зоне 2 и в движке.

## Вход (условный)

Сырая тема на brownfield-проекте со стеком из реестра. Кода по теме нет, проект существует. Режим `interactive`.

## Трассировка

### Зона 1: `/feature`

Классификация «сырая тема» -> Phase 2 целиком (шторм + BRD). Погружение в корпус выполняется (Phase 1, после `5e8ccdf`), расположение протаскивается в спавн BA и в handoff.

Оба гейта требуют явного апрува, авто-approve запрещён, молчание апрувом не считается. Трассировка `FR -> AC` замыкается в Phase 3: каждый `FR` покрыт story либо переведён в `non-goals` с основанием.

**Исход:** зона проходится штатно. Дыра доступа к корпусу закрыта предыдущим коммитом.

### Стык зона 1 -> зона 2

Handoff несёт `status`, путь к BRD, `FR`/`NFR`, stories с `[FR-NNN]`, трассировку, `non-goals`, `constraints/risks`, расположение корпуса, `quality-checks`.

**Исход:** стык замкнут. Метка `quality-checks` доезжает, зона 2 не перепроверяет требования заново.

### Зона 2: Phase 0 Codebase Priming

Фаза собирает контекст **о коде**: стек, точки интеграции, компоненты-аналоги, архитектурный стиль. Recall sources - CLAUDE.md / init / прежний диалог.

Принятых требований и ADR в перечне Output **нет**. Архитектор видит, на каком фреймворке проект, но не видит, какие решения уже приняты.

`Skip_if` пропускает фазу целиком, если CLAUDE.md отсутствует и в диалоге не упоминался стек. Вместе с фазой пропадает и шаг сверки с корпусом - которого в ней и так нет.

**Исход:** та же асимметрия, что была найдена в зоне 1, но в зоне 2 и по другому предмету - не «где требования», а «какие решения уже приняты». Ось 6 `codebase-conventions` (ADR поверх соседского кода) архитектору доступна: скилл он грузит. Но Phase 0 не обязывает перечислить ADR до выводов, а `Skip_if` даёт легальный путь мимо.

### Зона 2: Phase 5 Decide

Гейт `interactive` - explicit confirmation перед Deep Dive; `autonomous` - решение с trade-off в Output без ожидания. Формулировка закрыта, лазейки нет.

**Исход:** штатно.

### Стык зона 2 -> движок

Выход зоны 2 несёт implementation plan и ожидаемые выходные артефакты (правка предыдущей сессии на месте).

`[FR-NNN]` прослежен по цепочке: `architect` (3 вхождения) -> `feature-implementer` (2) -> `dotnet-coder` (1) -> `dotnet-test-writer` (1). Нить цела.

**Исход:** стык замкнут.

### Движок

Под-вид определяется до плана; ADR pre-check на месте; тест-DoD = матрица + интеграция + регрессия потребителей; саморевью 3 прохода с обязательным security.

**Исход:** штатно для маршрута «фича».

## Находки

| # | Находка | Сорт | Опора |
|---|---|---|---|
| 1 | Phase 0 architect не фиксирует принятые ADR и требования - только контекст кода | предписывает | Phase 0 Output: стек, интеграции, аналоги, стиль; ADR отсутствует |
| 2 | `Skip_if` Phase 0 даёт легальный путь мимо сверки с корпусом при отсутствии CLAUDE.md | предписывает | Phase 0 `Skip_if` - «все три источника пусты» -> фаза заменяется одной строкой |

Обе - в зоне 2, обе того же класса, что закрытая в зоне 1: узел, порождающий артефакт, не обязан свериться с уже принятым.

## Отрицательный путь: требования без метки

Вход `/design` без `quality-checks`. По `node-contract` C.9 архитектор обязан прогнать оракул сам.

**Проверено:** `architect` несёт возврат `contradicted` + `status: blocked` при находке вопреки метке и требование прогнать оракул при её отсутствии (правки предыдущей сессии). Лазейки «принять на веру» нет.

## Вывод

Маршрут проходится. Зона 1 и стыки замкнуты; движок штатен; нить `[FR-NNN]` цела до тестов.

Открыто: зона 2 не обязана сверяться с принятыми решениями до выводов. Это та же дыра, что чинилась в зоне 1, - `project-docs-map` архитектору не роздан. Правка симметричная: скилл в `architect` / `architect-dotnet` + шаг в Phase 0 с терминалом на ветке `Skip_if` (отсутствие CLAUDE.md не отменяет поиск ADR по стандартным местам).

## Исправлено

Коммит правок: `project-docs-map` роздан `architect` / `architect-dotnet`, «Принятые решения» добавлены в Output Phase 0 обоих, `Skip_if` сужен - отсутствие `CLAUDE.md` фазу не отменяет, поиск ADR по стандартным местам обязателен до вывода «greenfield».
