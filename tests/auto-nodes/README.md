# Узлы dex-auto: сверка с узлом каталога

Предмет - собственный узел трека `dex-auto` (`plugins/auto/dex-auto/agents/`) против узла каталога,
который он заменяет, на одном входе. Метод - [сжатие по свидетельству](../README.md#метод-сжатие-по-свидетельству):
база узла минимальна, контроль - старый узел, провал разбирается до причины, в норму возвращается одна
фраза. Общие меры - следы в файлах после узла, токены и цена; мера по узлу - в разделе его кейсов.

## Кейс

Каталог `<узел>/<кейс>/`:

- `case.json` - цель, критерий «готово», граница, требования, вход от кодера (`red-run`, `uncovered`,
  `dependents`), у bugfix ещё `expected` и `repro` (диагноз); `mines` - засеянные дефекты с файлом,
  строками и признаком `blocking`; `score` - оракул и мутанты кейса кодера. `mines` и `score` узлу не
  подаются. `base` - путь базы от `tests/`, иначе база - `base/`.
- `change/` - правка кодера поверх базы, у кейсов ревьюера.

`setup.sh <кейс> <каталог>` собирает репозиторий: база коммитом на `main`, ветка `auto/<TASK>`, на ней
коммитом правка из `change/`, если она есть, - то, что узел видит в треке.

## Прогон

```
./run.sh <узел> <каталог> rv1-cache-write:old:1 rv1-cache-write:new:1 ...
node score.mjs <каталог>
```

Повтор - число либо диапазон: `rv1-cache-write:new:1..3` раскрывается в три прогона `...-new-1`, `...-new-2`,
`...-new-3`; поштучная запись работает как прежде. `AUTO_NODES_DRY_RUN=1 ./run.sh ...` печатает раскрытые прогоны
и выходит, не требуя `claude` и `timeout` (проверка - `tests/tools/auto-nodes-run.test.sh`, `npm run test:tools`).
Каталоги плагинов, которых нет в профиле запуска (контроль каталога `dex-debugger` либо `dex-self-reviewer`, стековый
скилл кейса), подаются `AUTO_NODES_PLUGINS="<каталог> <каталог>"` - каждый уходит в `claude` как `--plugin-dir`.

Нужен `timeout` из GNU coreutils (на macOS - `brew install coreutils`, годится и `gtimeout`); без него
`run.sh` отказывает до первого прогона. Кейс, который `setup.sh` не собрал, прогона не получает.

`build.mjs` собирает скрипт `Workflow` из источников `plugins/auto/tracks-shared/` и тела
`<узел>/node.js`: промпт узла тот же, что в треке (хвост промпта кодера `build.mjs` сверяет с `feature.js` и при
расхождении отказывает), модель - из таблицы `NODE` трека (`tracks-shared/nodes.js`), варианты узла - таблица
`NODES` в `node.js`. `run.sh` требует `timeout` (GNU coreutils, на macOS - `gtimeout`). Каждый

прогон - свой `claude -p` в своём репозитории с `--plugin-dir` рабочего дерева `dex-auto`. `score.mjs`
печатает выход узла и следы - лишнее рядом с репозиторием и `git status` (у ревьюера с `--ignored`,
у кодера сборочный вывод под `.gitignore` законен). Токены узла (`node-usage`) - по транскриптам субагентов, максимум по `message.id`;
время узла `node-dur` - из прогресса `Workflow`; цена `total_cost_usd` и `dur` - вместе с главной
сессией прогона.

Меры: мина найдена (блокирующая - с severity `P0`/`P1`), ложные `P0`/`P1` на чистом кейсе. `score.mjs`
кладёт находку рядом с миной по файлу и строкам; засчитывает мину судья по тексту находки.

## Кейсы coder

Промпт - шаг 2 трека feature, попытка 1, дерево зелёное до правок. У кейса `ref/` - эталонная
реализация, `oracle/` - скрытые тесты требований и того, что требования не называют, `mutants/<id>/` -
эталон с одним дефектом. Файлы `ref/` и мутантов ложатся поверх дерева кодера по тем же путям.

Меры `score.mjs`:
- оракул (`score.oracle_cmd`) на закоммиченном итоге кодера - исполнены ли требования;
- мутанты под тестами кодера (`score.tests_cmd`): убит, если тест кодера, зелёный на эталоне, красный на
  мутанте, - сила тестов, включая потребителя, которого требования не называют; упали только тесты,
  красные и на эталоне, - не судим: тест закрепил выбор сверх требований;
- выход `FIX` (`red-run`, `uncovered`, `dependents`, `decisions`), коммиты ветки, вызовы `Skill` и
  счёт инструментов из журнала узла.
- форма правки (`score.shape`, если задана кейсом) - команды на итоге кодера: где живёт изменённое поведение, дубли.

|---|---|---|---|

| `cd2-dotnet-bytesize` | dotnet (xUnit) | разбор числа по культуре процесса (`ru-RU`) | m1-m8, `m7-culture` - культура |

## Кейсы debugger

Промпт - шаг 1 трека bugfix, первый прогон без спора, дерево зелёное до правок. В `case.json` у кейса
`cause` - место засеянной причины, `decoys` - места, где симптом виден, но причины нет; оба узлу не
подаются. `ref/` - эталонная правка причины.

Меры `score.mjs`:
- причина: якорь `файл:строка` из `root_cause` в месте `cause` - `ПРИЧИНА`, только в `decoys` - `симптом`;
- тест диагноста: красный на дереве узла и зелёный под `ref/` - падает по причине симптома;
- продукт не тронут: коммитов на ветке нет, в `git status` только тест;
- выход `REPRO` (`falsification` с исходами, `fact-check`, `expected-basis`), вызовы `Skill` и счёт
  инструментов из журнала узла.

| Кейс | Стек | Причина | Где симптом виден |
|---|---|---|---|
| `db1-js-discount` | ts (JS, `node --test`) | `applyDiscount` меняет цены позиций входа на месте | `checkout.js`: второй расчёт по той же корзине |
| `db2-py-duration` | python (pytest) | разбор длительности берёт первую часть строки | `retry.py`: задержка повтора |
| `db3-js-ledger` | ts (JS, `node --test`) | `parseAmount` (`src/bank/import.js`) берёт `Math.trunc(x * 100)`: 4,35 разбирается как 434, копейка теряется при разборе выписки, до `ledger` | `ledger.js:statusOf` (`rest === 0`: счёт на 4,35 с платежом 4,35 - `partial`, остаток 0,01), `report.js`, `summary.js` |

`db3-js-ledger` - кейс на ложный след: в `docs/known-issues.md` лежит правдоподобная правка (допуск в 1 копейку в
`statusOf`, «предположительно округление банка»). Она снимает статус `partial` на примере входа, но не остаток в
`statusLine` и не занижение `summary().paid` - другой путь к тому же симптому. Верный исход: причина в `import.js:2-4`, а не

через продуктовый путь красный на дереве и зелёный под `ref/`; продукт не тронут. Свой узел обязан опровергать причину
попыткой (`agents/debugger.md`: «достижимость места причины», «другой путь к тому же симптому»), контроль - по рецепту
`dex-debugger` Falsify; ожидание кейса - контроль принимает документированную правку за причину. Прогон: контролю и
`requirement-quality` из промпта шага нужны плагины -
`AUTO_NODES_PLUGINS="plugins/specialists/delivery/dex-debugger plugins/skills/dex-skill-node-contract plugins/skills/dex-skill-stack-registry plugins/skills/dex-skill-requirement-quality"`.
