# textkit 0.2: четыре добавления

Библиотека `textkit` (Node, ESM, без зависимостей, тесты - `node --test`, `npm test`). Нужны четыре добавления;
у каждого свой модуль в `src/`, свой файл тестов в `test/`.

Общие требования к каждому добавлению:

- публичные имена экспортируются из `src/index.js` (одна строка `export` на модуль, в конец файла);
- в таблицу API в `README.md` - по строке на публичное имя (в конец таблицы);
- в `CHANGELOG.md` под `## Unreleased` - по строке на добавление (в конец списка);
- тесты в `test/<модуль>.test.js` покрывают поведение, описанное ниже;
- `npm test` зелёный; работа сдаётся локальным коммитом, push не делается.

## 1. `src/duration.js` - длительности

- `parseDuration(text)` -> миллисекунды (целое). Строка - одна или несколько групп `<число><единица>`, между группами
  допустим один пробел. Число - неотрицательное десятичное (`1.5`). Единицы: `d` (86400000), `h` (3600000),
  `m` (60000), `s` (1000), `ms` (1); регистр строчный. Результат округляется `Math.round`. Пустая строка, число без
  единицы, неизвестная единица, отрицательное число, лишние символы - `RangeError`.
  Примеры: `"1h30m"` -> 5400000; `"90s"` -> 90000; `"1d 2h"` -> 93600000; `"1.5h"` -> 5400000; `"250ms"` -> 250; `"0s"` -> 0.
- `formatDuration(ms)` -> строка: ненулевые части от старшей `d` к младшей `ms`, через один пробел; 0 -> `"0s"`.
  Примеры: 5400000 -> `"1h 30m"`; 93600000 -> `"1d 2h"`; 1500 -> `"1s 500ms"`; 61000 -> `"1m 1s"`.
  Не целое, отрицательное число или `NaN` - `RangeError`. Для любого допустимого `ms`:
  `parseDuration(formatDuration(ms)) === ms`.

## 2. `src/lru.js` - кэш LRU

`export class LruCache`:

- `new LruCache(max, options = {})`: `max` - целое > 0, иначе `RangeError`. `options.ttlMs` - число > 0, срок жизни
  записи с момента `set` (чтение срок не продлевает); `options.now` - функция текущего времени в мс (по умолчанию `Date.now`).
- `get(key)` -> значение или `undefined`; попадание делает ключ самым свежим; просроченная запись удаляется, возвращается `undefined`.
- `set(key, value)` -> сам кэш (цепочкой); вставка и обновление делают ключ самым свежим и обновляют срок записи;
  при превышении `max` вытесняется самый давний ключ.
- `has(key)` -> `true`, если запись есть и не просрочена; свежесть ключа не меняет.
- `delete(key)` -> `true`, если запись была. `clear()`. Геттер `size` - число непросроченных записей.
- `keys()` -> массив непросроченных ключей от самого давнего к самому свежему.

## 3. `src/semver.js` - версии

- `parse(text)` -> `{ major, minor, patch, prerelease }` (`prerelease` - массив строк; числовые идентификаторы остаются
  строками). Формат `1.2.3` либо `1.2.3-alpha.1`; ведущая `v` допустима; метаданные `+...` отбрасываются. Иное - `TypeError`.
- `compare(a, b)` -> -1, 0, 1 по приоритету semver 2.0.0: major, minor, patch числом; версия с `prerelease` ниже такой же
  без него; идентификаторы пререлиза слева направо: числовые - числом, прочие - по строке, числовой ниже нечислового, при
  равенстве общего префикса короткий набор ниже.
- `satisfies(version, range)` -> boolean. `range` - наборы через `||`; набор - компараторы через пробел, все должны
  выполняться. Компаратор: `>=1.2.3`, `>1.2.3`, `<=1.2.3`, `<1.2.3`, `=1.2.3` или голая версия; `^1.2.3` (>=1.2.3 <2.0.0;
  `^0.2.3` -> >=0.2.3 <0.3.0; `^0.0.3` -> >=0.0.3 <0.0.4); `~1.2.3` (>=1.2.3 <1.3.0); `1.x`, `1.2.x`, `*`.
  Версия с пререлизом удовлетворяет набору, только если в наборе есть компаратор с пререлизом на тех же major.minor.patch.

## 4. Правка `src/lru.js` после пп. 1 и 2: срок строкой

`LruCache` принимает `options.ttl` - число миллисекунд либо строку длительности, разбираемую `parseDuration` из
`src/duration.js`; `ttlMs` остаётся допустимым (оба заданы - `TypeError`). Геттер `ttl` -> срок в мс либо `undefined`.
Неразбираемая строка - `RangeError` из `parseDuration`, без перехвата.
