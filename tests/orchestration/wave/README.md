# Волна целей `/auto` против одной сессии

Вопрос ревью PR #319: окупается ли режим L3 лестницы - план сильной моделью, цели, по цели свой
процесс `claude -p "/auto"` в своём дереве и ветке, слияние веток волны и полный прогон тестов - против
одной сессии Opus на той же работе. Заодно три проверки, с которых ревью предложило начать:
параллельные `/auto` в одном репозитории (гонки `worktree.py` и ledger), дерево цели от заданной базы,
сквозной замер.

## Фикстура

[`gen.py`](gen.py) строит репозиторий `textkit` (Node, ESM, без зависимостей) с базовым коммитом и
[`TASK.md`](TASK.md): четыре добавления. Три независимых (`src/duration.js`, `src/lru.js`,
`src/semver.js`) и четвёртое, зависящее от первых двух (правка `LruCache`: срок строкой через
`parseDuration`). Общие файлы - `src/index.js`, таблица API в `README.md`, `CHANGELOG.md`: каждое
добавление дописывает в них в конец, поэтому ветки волны гарантированно конфликтуют при слиянии.

Скрытый оракул (31 проверка) лежит в [`oracle/`](oracle/) вне дерева плеча; самопроверка - на эталоне
`oracle/ref/` (31 из 31). `grade.py <дерево>` прогоняет оракул и `npm test` дерева.

## Плечи

| Плечо | Что |
|---|---|
| одна сессия | [`single.py`](single.py): `claude -p --model opus`, одно поручение «выполни четыре добавления из TASK.md» |
| волна | [`wave.py`](wave.py): `plan` - один вызов `opus` со схемой, граф целей; `run` - по уровням графа процессы `/dex-auto:auto <id>` параллельно (главный поток `sonnet`), ветка `auto/<id>` от интеграционной, слияние, `npm test`, финальное ревью общего диффа |

Скрипт волны - тонкий: модель зовётся на план, исполнение цели, разрешение конфликта слияния и
финальное ревью; граф, процессы, чтение исхода из ledger (`ledger.py get <id> Исход`) и слияние -
код.

## Запуск

```text
python3 -I gen.py <каталог>/wave && python3 -I gen.py <каталог>/single
python3 -I wave.py plan <каталог>/wave/repo --task TASK.md --out <каталог>/plan.json
DEX_AUTO_DIR=<плагин dex-auto> python3 -I wave.py run <каталог>/wave/repo --plan <каталог>/plan.json \
    --out <каталог>/wave-out --final-review
python3 -I single.py <каталог>/single/repo --out <каталог>/single.json [--effort medium] [--skill]
python3 -I grade.py <каталог>/wave/repo --branch integration
python3 -I grade.py <каталог>/single/repo
python3 -I probe_race.py 8 25          # без модели: гонки worktree.py и ledger.py, дерево от базы
```

## Результаты

Claude Code 2.1.296, `dex-auto` 8.6.0 (снимок `develop` `ca7356fc`), 2026-10-13; один прогон на плечо.
Сырые данные - [wave-summary.json](../../../docs/research/orchestration-tiers/results/wave-summary.json),
разбор - [RESULTS.md](../../../docs/research/orchestration-tiers/RESULTS.md), раздел 13.

**Без модели** ([`probe_race.py`](probe_race.py), 8 целей x 25 раундов): 200 заведений дерева с четырьмя
записями ledger на цель и 200 снятий - 0 отказов, деревья на своих ветках с верной меткой каталога
запуска, у восьми целей один корень ledger и восемь открытых целей рядом. Дерево заводится от `HEAD`
главного дерева, параметра базы у `worktree.py` нет; ветка `auto/<TASK>`, заведённая заранее от ветки
предшественника, подхватывается: дерево встаёт на её голову (то же, когда главное дерево стоит на ветке
предшественника).

**Работа целиком** (четыре добавления; `sonnet` ведёт `/auto`, `opus` планирует и делает финальное ревью):

| | Одна сессия `opus` | Волна `/auto` |
|---|---|---|
| Оракул (31 проверка) | 31 из 31 | 31 из 31 |
| `npm test` дерева | 30 из 30 | 93 из 93 |
| Цена, $ | 0.71 | 13.79 (план 0.26, цели 12.77, слияния 0.17, финальное ревью 0.60) |
| Время, мин | 2.5 | около 43 (уровень 1: 12.8; возобновление F2: 21; F4: 6.9; ревью: 1.6) |
| Коммитов / дифф | 1 / 598 строк | 9 + 4 слияния / 1532 строки |
| Вмешательства | нет | ответ оператора по F2 (`blocked`: неоднозначное «при превышении max»); F3 `partial`, трек возобновил главный поток; два конфликта слияния (`CHANGELOG.md`, `README.md`, `src/index.js`) |

Цели по одной: F1 2.30 $ и 10.2 мин, F2 2.44 + 3.17 $ (первый прогон `blocked`, возобновление после
ответа) и 11.7 + 21.1 мин, F3 3.07 $ и 12.8 мин, F4 1.80 $ и 6.9 мин. Прерванный запуск F4 без F2
(скрипт тогда не пропускал зависимые цели) в сумму не входит.

**Что следует:**

- **На работе, вмещающейся в контекст, волна проиграла в 20 раз по цене и в 17 по времени** при том же
  исходе по оракулу. Это нижняя граница накладных расходов режима, а не опровержение режима «не
  помещается в окно»: он не достигнут (один Opus на всю работу вмещается с запасом).
- **Механика держится:** восемь параллельных целей скриптами и три живых `/auto` в одном репозитории без гонок, зависимая цель
  стартует от интеграционной ветки (F4 на `5b48e8f`, где F1-F3 влиты), конфликты общих файлов
  разрешает одна модельная сессия за 0.07-0.10 $, `blocked` с нехваткой возвращается оператору и
  возобновляется по ledger.
- **Что `/auto` добавил к исходу:** втрое больше тестов (93 против 30), найденные саморевью дефекты
  (округление через `BigInt`, квадратичный разбор), финальное ревью общего диффа с восемью находками (перечень сохранён в `wave-summary.json` не полностью).
  Часть добавленного - расхождение с буквой ТЗ (округление `BigInt` вместо `Math.round`, ограничение
  `MAX_SAFE_INTEGER`) и тест, зависящий от таймера: оракул их не ловит и не судит.
- **Неоднозначность ТЗ превращает цель в `blocked`:** два прочтения «при превышении max» остановили F2 на
  12 минут работы и потребовали ответа; одна сессия выбрала прочтение и пошла дальше.
- Малая фикстура, один прогон на плечо, одна версия платформы; главный поток `/auto` - `sonnet` (зонд P16:
  дешевле `fable`); `opus` в этой роли не проверялся.

### Скилл `subagent-dispatch` в одной сессии, 2026-10-15

Claude Code 2.1.300, скилл 1.0.0 редакция 3b (см. [`../dispatch/`](../dispatch/README.md)), `opus`
`medium`, `single.py --effort medium` против `single.py --effort medium --skill`, по два прогона.

| Прогон | Цена, $ | Время, с | Раздача | Оракул | `npm test` |
|---|---|---|---|---|---|
| одна сессия 1 / 2 | 0.75 / 0.82 | 166 / 168 | нет | 31 из 31 | 27 |
| со скиллом 1 | 1.07 (`opus` 0.81, `sonnet` 0.24, `haiku` 0.02) | 210 | F1, F2 `haiku` `medium`; F3 `sonnet` `medium`; F4 сам | 31 из 31 | 57 |
| со скиллом 2 | 0.79 | 191 | нет | 31 из 31 | 25 |

- **Исход не пострадал, цена в среднем +19%.** Раздача прогона 1 сократила вывод `opus` с 14 до 11.8
  тыс. токенов, а число ходов выросло с 7 до 15, и чтение кеша `opus` - с 318 до 590 тыс.: сэкономленное
  на письме съели ходы оркестратора, исполнитель `sonnet` на один модуль стоил 0.24 $.
- **Вся работа - около 14 тыс. токенов вывода, около 3.5 тыс. на добавление,** меньше стартовой цены
  исполнителя (около 27 тыс.): по условию скилла верный выбор - сам, прогон 2 так и сделал.
- Работа, на которой раздача обязана выиграть (кусков много, каждый намного больше старта исполнителя,
  у каждого своя проверка), набором не покрыта.
