# textkit 0.2: 13 добавлений

Библиотека `textkit` (Node, ESM, без зависимостей, тесты - `node --test`, `npm test`). Нужны 12 новых модулей
и одна правка, связывающая три из них.

Общие требования к каждому модулю:

- публичные имена экспортируются из `src/index.js` (одна строка `export` на модуль, в конец файла);
- в таблицу API в `README.md` - по строке на публичное имя (в конец таблицы);
- в `CHANGELOG.md` под `## Unreleased` - по строке на модуль, с его именем (в конец списка);
- тесты в `test/<модуль>.test.js` покрывают поведение, описанное ниже;
- `npm test` зелёный; работа сдаётся локальным коммитом, push не делается.


## 1. `src/csv.js` - CSV по RFC 4180

- `parse(text, options = {})` -> массив записей (запись - массив строк); `stringify(rows, options = {})` -> строка.
- `options.delimiter` - строка длины 1, по умолчанию `,`; `"`, CR, LF, не строка или иная длина - `RangeError`
  (в обеих функциях).
- parse: запись кончается LF или CRLF; один перевод строки в самом конце текста новой записи не создаёт; `""` -> `[]`.
- parse: пустая строка внутри текста - запись из одного пустого поля; число полей не выравнивается;
  пробелы не обрезаются.
- parse: поле в кавычках открывается `"` в первой позиции поля; `""` внутри - одна кавычка;
  разделитель, CR и LF внутри кавычек - часть значения.
- parse: после закрывающей кавычки допустимы только разделитель, LF, CRLF или конец текста, иначе `SyntaxError`.
- parse: `"` внутри поля без кавычек и CR без следующего LF вне кавычек - `SyntaxError`;
  незакрытая кавычка - `SyntaxError`.
- Сообщение каждой `SyntaxError` содержит `line N`: N = 1 + число LF в тексте до начала плохого поля
  (LF в кавычках считаются).
- stringify: ячейка не строка -> `String(ячейка)`; в кавычки ячейка берётся только если содержит
  разделитель, `"`, CR или LF; `"` внутри удваивается.
- stringify: записи соединяются CRLF, завершающего перевода строки нет; `[]` -> `""`;
  запись из одной пустой ячейки пишется как `""`.
- Запись без ячеек не определена. Для любой сетки строк (в записи >= 1 ячейки) и допустимого delimiter
  `parse(stringify(rows, o), o)` равно `rows`.
- Примеры (литералы JS): `parse('a,b\r\nc,d\n')` -> `[['a','b'],['c','d']]`; `parse('')` -> `[]`;
  `parse('\n')` -> `[['']]`; `parse('"a ""q"", b",x')` -> `[['a "q", b','x']]`;
  `parse('a,\n\nb')` -> `[['a',''],[''],['b']]`; `parse('x\n"a\nb"c')` -> `SyntaxError` с `line 2`;
  `stringify([['a b','c,d'],[1,'say "hi"',null]])` -> `'a b,"c,d"\r\n1,"say ""hi""",null'`.

## 2. `src/jsonpatch.js` - JSON Pointer и JSON Patch (RFC 6901, 6902)
- `getPointer(doc, pointer)` -> значение. Указатель: `""` - весь документ; иначе начинается с `/`, токены через `/`,
  пустой токен допустим (`"/"` - ключ `""`). Escape за один проход слева направо: `~1` -> `/`, `~0` -> `~`
  (`"/~01"` - ключ `~1`). `~` без `0`/`1` после и непустой указатель без ведущего `/` - `SyntaxError`;
  синтаксис указателя проверяется целиком до обхода.
- Обход слева направо, первая ошибка прерывает его. Токен в объекте - собственный ключ, нет такого - `RangeError`;
  токен при скаляре - `RangeError`. Токен в массиве - индекс `0|[1-9][0-9]*`; иная форма (`01`, знак, дробь, буквы) -
  `SyntaxError`; индекс >= длины - `RangeError`. Токен `-` для массива допустим лишь как последний токен `add`
  (конец массива); везде иначе, включая `getPointer`, - `RangeError`.
- `applyPatch(doc, ops)` -> новый документ; `ops` не массив - `TypeError`. Операции по порядку; при ошибке бросается
  ошибка первой упавшей, ничего не применено. `doc` и `ops` не мутируются (и при ошибке); результат не делит с ними
  ссылок на объекты и массивы. Пустой `ops` -> копия `doc`.
- Операция - объект с `op` и `path` (строки); `add`/`replace`/`test` требуют ключ `value` (`null` ок),
  `move`/`copy` - `from` (строка). Не объект, неизвестный `op`, нет поля, не тот тип - `TypeError`; лишнее игнорируется.
- `add`: родитель `path` существует (скаляр не годится), иначе `RangeError`; `path=""` заменяет документ. В объекте
  задаёт ключ (или заменяет). В массиве: индекс 0..длина вставляет со сдвигом, `-` - в конец, больше - `RangeError`.
- `remove`: цель есть (в массиве индекс < длины, `-` - `RangeError`), иначе `RangeError`; `path=""` - `RangeError`;
  массив сдвигается. `replace`: цель как у `remove`; `path=""` заменяет документ.
- `move`: `path` == `from` -> без изменений (`from` обязан существовать); `path` начинается с `from + "/"` ->
  `RangeError`; иначе `remove from`, затем `add path` в документ после удаления. `copy`: глубокая копия значения
  по `from`, затем `add path`.
- `test`: значение по `path` глубоко равно `value`, иначе `Error` с `name === 'TestFailed'`; равенство: ключи объекта
  без порядка, массивы по порядку, скаляры `===` (`1` != `"1"`). Нет пути - `RangeError`.
- Примеры: `getPointer({"a/b":{"m~n":5}}, "/a~1b/m~0n")` -> `5`; `getPointer([7], "/01")` -> `SyntaxError`;
  `applyPatch([1,2,3], [{op:"move",from:"/0",path:"/2"}])` -> `[2,3,1]`, на `[1,2]` -> `RangeError`;
  `applyPatch({a:{x:1}}, [{op:"copy",from:"/a",path:"/a/b"}])` -> `{a:{x:1,b:{x:1}}}`.

## 3. `src/cron.js` - cron-выражения

- `parseCron(expr)` -> `{ minute, hour, dayOfMonth, month, dayOfWeek }`, каждое поле - отсортированный массив уникальных
  чисел. `expr` - 5 полей (минута, час, день месяца, месяц, день недели), разделитель - пробелы/табы (один или больше),
  по краям пробелы допустимы. Всё в UTC. Диапазоны: 0-59, 0-23, 1-31, 1-12, 0-7 (7 и 0 - воскресенье, в
  результате только 0). Элемент поля: `*`, число (только цифры), диапазон `a-b` (включительно), с шагом `*/n` или
  `a-b/n`; поле - список элементов через `,` (`1,5-7`). Шаг - целое >= 1; `*` развёртывается во весь диапазон поля
  (для дня недели 0-6), шаг отсчитывается от начала диапазона. Шаг при одиночном числе (`5/15`) недопустим.
- Имена (без учёта регистра): месяц `jan`-`dec` (1-12), день недели `sun`-`sat` (0-6); допустимы только в своём поле,
  везде, где допустимо число: в списке, в границах диапазона (`mon-fri`, `jan-dec/3`).
- Ошибки `parseCron` и `nextRun` (разбор идёт первым) - `SyntaxError`: не 5 полей (в т.ч. пустая строка), значение вне
  диапазона поля, шаг 0 или не целое, перевёрнутый диапазон `a>b` (`fri-sun` тоже: `sun` = 0), неизвестное имя или имя
  не в своём поле, пустой элемент списка (`1,,2`, `1,`), любой иной мусор (`-1`, `1.5`, `+1`, `*/5/2`).
- `nextRun(expr, from)` (`from` - `Date`) -> новый `Date`: первая минута строго после `from` (секунды и мс равны 0),
  подходящая под выражение. Минута, час и месяц должны совпасть всегда. День: если и день месяца, и день недели
  ограничены (текст поля не равен в точности `*`; `*/2` и `1-31` - ограничены), он подходит, когда совпал ЛЮБОЙ из двух
  (правило Vixie); иначе должны совпасть оба, неограниченное поле совпадает всегда. Несуществующих дат (31 апреля)
  не бывает, високосный год учитывается. Нет совпадения в пределах 5 лет после `from` -> `RangeError`.
- Примеры: `parseCron("*/15 0 1,15 * mon-wed")` -> `{ minute: [0,15,30,45], hour: [0], dayOfMonth: [1,15],
  month: [1,...,12], dayOfWeek: [1,2,3] }`; `parseCron("0 0 * * 5-7").dayOfWeek` -> `[0,5,6]`;
  `parseCron("0 0 * jan-dec/5 *").month` -> `[1,6,11]`; `nextRun("0 9 * * 1-5", 2025-01-03T10:00Z)` ->
  2025-01-06T09:00Z; `nextRun("* * * * *", 12:00:30.500Z)` -> 12:01:00.000Z;
  `nextRun("0 0 29 2 *", 2025-01-01T00:00Z)` -> 2028-02-29T00:00Z;
  `nextRun("0 0 31 2 *", 2025-01-01T00:00Z)` -> `RangeError`; `parseCron("*/0 * * * *")` -> `SyntaxError`.

## 4. `src/template.js` - шаблонизатор

- `render(template, data)` -> строка; `data` - объект. Шаблон разбирается целиком до подстановки.
- Текст вне тегов копируется как есть (пробелы и переводы строк не трогаются); одиночные `{`, `}` - обычный текст.
- `{{path}}` - значение, HTML-экранированное: `& < > " '` -> `&amp; &lt; &gt; &quot; &#39;` (за один проход).
  `{{{path}}}` - то же без экранирования. Пробелы внутри скобок допустимы: `{{ user.name }}`, `{{{ a }}}`.
- Тег `{{` заканчивается первой `}}`, тег `{{{` - первой `}}}`.
- Путь - имена через `.`; шаг берёт только собственные свойства объекта или массива (`items.1.name`).
  `{{constructor}}` -> пусто. Нет значения, `null`, `undefined` -> пустая строка; иначе `String(value)` (`0`, `false`).
- `{{#if path}}A{{else}}B{{/if}}`: A при истинном значении (как в JS, но пустой массив - ложь), иначе B;
  `{{else}}` необязателен.
- `{{#each path}}...{{/each}}`: тело на каждый элемент массива; `{{this}}` - элемент, `{{this.x}}` - поле элемента,
  `{{@index}}` - 0-based индекс ближайшего `each`. Остальные пути ищутся в элементе, затем в объемлющих `each` (изнутри
  наружу), затем в `data`; `null`/`undefined` считаются "не найдено" (идём наружу), `false` и `0` - найдены.
  `@index` допустим и в `#if`. Блоки вкладываются свободно. После `#` пробела нет, вокруг и перед путём - можно.
- `#each` над отсутствующим значением (`undefined`/`null`) или `[]` -> пусто; над другим не-массивом -> `TypeError`.
- `SyntaxError` со свойством `offset` (0-based индекс `{{` тега): тег без закрытия; закрывающий тег без открытого блока
  или не от ближайшего открытого; `{{else}}`, у которого ближайший открытый блок не `#if`, или вторая `{{else}}`;
  незакрытый блок (тег открытия; при нескольких - самого внутреннего). Ошибка бросается и в невыбранной ветке.
- `render('Hi {{ user.name }}!', {user:{name:'<Bo>'}})` -> `Hi &lt;Bo&gt;!`; `render('{{{a}}}|{{b}}', {a:'<i>'})` -> `<i>|`
- `render('{{#if xs}}y{{else}}n{{/if}}', {xs:[]})` -> `n`
- `render('{{#each xs}}{{@index}}={{this}};{{/each}}', {xs:['a','b']})` -> `0=a;1=b;`
- `render('{{#each r}}{{n}}{{t}}{{/each}}', {t:'T', r:[{n:1},{n:2,t:'x'}]})` -> `1T2x`
- `render('a{{#if x}}b', {})` -> `SyntaxError`, offset 1
- `render('{{#each n}}{{/each}}', {n:5})` -> `TypeError`

## 5. `src/glob.js` - glob-сопоставление путей

- `globToRegExp(pattern)` -> `RegExp`, якорный с обоих концов (совпадает весь путь целиком), без флагов `g` и `y`.
- `isMatch(path, pattern)` -> `boolean`; результат тот же, что у `globToRegExp(pattern).test(path)`. Регистр значим.
- Разделитель путей - `/`. `?` - один любой символ, кроме `/`. `*` - любая последовательность символов (в т.ч. пустая),
  кроме `/`.
- `**` как целый сегмент шаблона (между `/` или краями) - ноль или больше целых сегментов пути: `a/**/b` совпадает
  с `a/b` и `a/x/y/b`; `a/**` - с `a` и `a/x/y`; `**/b` - с `b` и `x/b`. `**` внутри сегмента (`a**b`) работает как `*`.
- Класс `[abc]`, диапазон `[a-z]`, отрицание `[!a-z]` (`!` только первым после `[`). `-` первым или последним в классе -
  литерал. Класс совпадает ровно с одним символом и никогда с `/` (отрицание тоже). Внутри класса `{`, `}`, `,`,
  `*`, `?` - литералы.
- Фигурные скобки `{a,b}` и вложенные `{a,{b,c}}` раскрываются до остального разбора: шаблон равен набору ветвей,
  путь подходит, если подходит любая. Ветка может быть пустой (`a{,b}` - `a` или `ab`) и содержать `/` и `**`
  (`{x/**,y}`). `{a}` равно `a`. Запятая вне скобок - литерал.
- `\` делает следующий символ литералом: `\*`, `\?`, `\[`, `\{`, `\,`, `\\`; внутри класса так же `\]` и `\-`.
- Точечные сегменты: сегмент пути, начинающийся с `.`, совпадает с `*`, `?`, `[...]` или `**` только если сегмент
  шаблона (после раскрытия скобок) начинается с буквального `.` (в т.ч. `\.`). `*` не совпадает с `.env`; `.*` и
  `.env` совпадают; `**` не проходит через сегменты, начинающиеся с `.`. Точка внутри сегмента (`a?b`, `a.b`) свободна.
- `SyntaxError`: незакрытые `[` или `{`, одиночный `\` в конце шаблона, пустой класс `[]` или `[!]`,
  перевёрнутый диапазон `[z-a]`.
- Примеры: `isMatch("a/x/y/b", "a/**/b")` -> `true`; `isMatch("src/.env", "src/*")` -> `false`;
  `isMatch("b.ts", "*.{js,ts}")` -> `true`; `isMatch("a/b", "a?b")` -> `false`;
  `isMatch("a*b", "a\\*b")` -> `true`; `globToRegExp("{a")` -> `SyntaxError`.

## 6. `src/diff.js` - построчный diff (LCS) и unified-формат
- Разбиение на строки: по `\n`; завершающий `\n` лишней пустой строки не даёт; `""` -> 0 строк; `"\n"` -> одна пустая
  строка; `\r` не трогается. Строки сравниваются точно, наличие завершающего `\n` на сравнение не влияет.
- `diffLines(a, b)` -> массив `{ op: 'equal'|'delete'|'insert', line }` в порядке прохода. Число `delete`+`insert`
  минимально (`equal` - наибольшая общая подпоследовательность строк). `a`/`b` не строки - `TypeError`.
- Однозначность. Пусть `L(i, j)` - длина LCS хвостов `a[i..]` и `b[j..]`. Проход с `i = j = 0`: если `a[i] === b[j]` -
  `equal`, оба вперёд; иначе при `L(i, j+1) >= L(i+1, j)` (в том числе при равенстве) - `insert b[j]`, иначе -
  `delete a[i]`; хвост одной стороны дорабатывается `delete` либо `insert`. Затем в каждом непрерывном блоке
  не-`equal` операций все `delete` идут перед всеми `insert`, порядок внутри групп сохраняется.
- `unifiedDiff(a, b, options = {})` -> строка. Равные по строкам `a` и `b` -> `""`. Иначе: `--- <fromFile>`,
  `+++ <toFile>` (`options.fromFile`/`toFile`, по умолчанию `a`/`b`; без меток времени), затем ханки; строки вывода
  соединяются `\n`, в конце один `\n`. Строка ханка: пробел (equal), `-` (delete), `+` (insert) и текст строки.
- `options.context` - число контекстных строк с каждой стороны, по умолчанию 3 (и при `undefined`). Не целое или
  меньше 0 (`1.5`, `-1`, `NaN`, `Infinity`, `"2"`) - `RangeError`. `options` не `undefined` и не объект (в т.ч. `null`)
  - `TypeError`. Аргументы проверяются до вычислений, в том числе при равных `a` и `b`.
- Ханки: блоки изменений, между которыми не более `2 * context` строк `equal`, входят в один ханк; ханк начинается
  за `context` строк до первого изменения и кончается через `context` после последнего, не выходя за текст.
- Заголовок `@@ -S,L +S,L @@` (старая сторона - `a`, новая - `b`), нумерация с 1, `L` - число строк ханка на стороне.
  `L = 1` -> пишется только `S`; `L = 0` -> `S,0`, где `S` - номер строки перед диапазоном (0 в начале), как в GNU diff.
- Примеры: `diffLines("a\nb", "a\nc")` -> `equal a`, `delete b`, `insert c`; `diffLines("a\nb", "b\na")` -> `insert b`,
  `equal a`, `delete b`; `diffLines("", "x\n")` -> `[insert x]`; `diffLines("x\n", "x")` -> `[equal x]`.
- `unifiedDiff("a\nb\nc\n", "a\nX\nc\n")` -> `"--- a\n+++ b\n@@ -1,3 +1,3 @@\n a\n-b\n+X\n c\n"`;
  `unifiedDiff("x", "x\n")` -> `""`; `unifiedDiff("", "p\nq\n")` -> `@@ -0,0 +1,2 @@`; обратно -> `@@ -1,2 +0,0 @@`.
- Строки `1..9`, `2` -> `A`, `8` -> `B`: `context: 2` -> ханки `@@ -1,4 +1,4 @@` и `@@ -6,4 +6,4 @@` (5 `equal` > 4);
  `context: 3` -> один `@@ -1,9 +1,9 @@`.

## 7. `src/expr.js` - вычислитель арифметических выражений
- `evaluate(text, vars = {})` -> число; `vars` - объект `имя -> число`. Итог `-0` возвращается как `0`.
  Пробелы (пробел, `\t`, `\r`, `\n`) между токенами игнорируются и разделяют токены: `1 2` - два числа.
- Число: `цифры`, `цифры.цифры` или `.цифры`, затем необязательно `e|E`, знак, цифры (`12`, `.5`, `2.5E-1`);
  `1.` не число; экспонента без цифр в число не входит: `1e` - число `1`, затем идентификатор `e`.
- Идентификатор `[A-Za-z_][A-Za-z0-9_]*`, регистр значим. Идентификатор, за которым (после пробелов) идёт `(`, -
  вызов функции, иначе переменная: её значение - собственное свойство `vars`, иначе `ReferenceError`.
- Приоритет сверху вниз: `^` (правоассоциативна, `2^3^2` = 512); унарные `-` и `+` (цепочкой: `--2` = 2);
  `* / %`; `+ -` (бинарные левоассоциативны). `^` сильнее унарного знака слева (`-2^2` = -4), показатель может
  нести знак (`2^-1` = 0.5, `2^-3^2` = `2^(-(3^2))`). Скобки группируют.
  `%` - остаток как в JS, знак делимого (`-7 % 3` = -1, `5.5 % 2` = 1.5); `^` - как `Math.pow`, `0^0` = 1.
- Функции: `min(...)`, `max(...)` - 1 и более аргументов; `abs(x)`, `round(x)` - ровно 1; `round` как `Math.round`
  (`round(2.5)` = 3, `round(-2.5)` = -2); аргументы разделяются `,`; `f()` синтаксически допустим.
- `ReferenceError`: неизвестная переменная или функция (имя функции проверяется до вычисления аргументов).
  `TypeError`: неверное число аргументов (проверяется после вычисления всех аргументов).
  `RangeError`: `/` или `%` при делителе 0 (включая -0); любое возникшее число не конечное (`1e999`, `10^400`, `0^-1`).
- Сначала разбирается всё выражение: `SyntaxError` главнее остальных ошибок. Затем вычисление слева направо без
  сокращений (`0 * y` с неизвестной `y` - `ReferenceError`); первая ошибка вычисления побеждает, операнды раньше
  операции: `1/0 + y` -> `RangeError`, `y + 1/0` -> `ReferenceError`.
- `SyntaxError` несёт `pos` - 0-based индекс первого символа первого токена, недопустимого в этом месте при разборе
  слева направо; символ вне токенов (`#`, `.`, `,` вне вызова) - недопустимый токен сам; конец ввода = `text.length`.
- Виды: пустой ввод или одни пробелы -> `text.length`; лишний или пропущенный токен (`2 * * 3` -> 4, `()` -> 1,
  `(1,2)` -> 2, `1 +` -> 3, `1.` -> 1, `max(1,)` -> 6); незакрытая `(` -> `text.length` (`(1` -> 2); лишняя `)` ->
  её индекс (`1)` -> 1); ввод после законченного выражения -> его начало (`1 2` -> 2, `2x` -> 1, `2(3)` -> 1).
- Примеры: `2 + 3*4` -> 14; `max(1, x*2) % 3` при `x = 2` -> 1; `(1` -> `SyntaxError` pos 2; `1/(2-2)` -> `RangeError`

## 8. `src/toposort.js` - топологическая сортировка

- `graph` - простой объект `имя -> массив имён зависимостей`; зависимость, которой нет среди ключей, - узел без
  зависимостей. Узлы - все ключи и все упомянутые зависимости. Дубли в массиве игнорируются. Вход не изменяется.
- `toposort(graph)` -> массив всех узлов, каждая зависимость раньше зависимого. Из узлов, готовых одновременно
  (все зависимости уже выданы), первым идёт наименьший по обычному сравнению строк (`<`): порядок единственный.
- `layers(graph)` -> массив массивов: слой 0 - узлы без зависимостей; слой k - узлы, все зависимости которых в слоях
  меньше k, причём хотя бы одна в слое k-1. Внутри слоя имена отсортированы. Для `{}` обе функции возвращают `[]`.
- Цикл (в том числе узел, зависящий от себя) - обе функции бросают `Error` с `name === 'CycleError'` и свойством
  `cycle`: массив имён, первый и последний равны, каждое следующее - зависимость предыдущего.
- Выбор цикла: DFS стартует по узлам в отсортированном порядке, зависимости обходятся в отсортированном порядке;
  берётся первое найденное обратное ребро u -> v (v лежит на текущем пути DFS); цикл = путь от v до u и затем v.
- `TypeError`: `graph` не простой объект (`null`, массив, строка, число, `Map`, экземпляр класса); значение любого
  ключа не массив; элемент массива не строка. Вход проверяется раньше поиска цикла: невалидный вход - `TypeError`.
- Примеры `toposort`: `{ b: ['a'], a: [] }` -> `['a','b']`; `{ c: ['b','b'], b: ['a'] }` -> `['a','b','c']`;
  `{ x: [], b: ['x'], a: ['x'] }` -> `['x','a','b']`; `{ a: ['z'], m: [] }` -> `['m','z','a']`.
- Примеры `layers`: `{ d: ['b','c'], b: ['a'], c: [] }` -> `[['a','c'],['b'],['d']]`;
  `{ a: ['b'], b: [], c: ['a','b'] }` -> `[['b'],['a'],['c']]`.
- Примеры `CycleError.cycle`: `{ a: ['a'] }` -> `['a','a']`;
  `{ a: ['b'], b: ['c'], c: ['a'] }` -> `['a','b','c','a']`;
  `{ a: ['b','c'], b: [], c: ['d'], d: ['c'] }` -> `['c','d','c']`.
- Примеры ошибок: `{ a: [1] }` -> `TypeError`; `[]` -> `TypeError`.

## 9. `src/router.js` - маршрутизатор путей
`export class Router`; шаблон - `/`-сегменты: статический, `:name` (один непустой сегмент), `*name` (остаток пути).

- `add(method, pattern, handler)` -> сам роутер (цепочкой). `method` регистронезависим. `handler` - любое значение,
  `match` возвращает его как есть. Один завершающий `/` в шаблоне игнорируется (`/a/` == `/a`); корень - `/`.
- `add` бросает `TypeError`: `method` или `pattern` не строка; `pattern` не начинается с `/`; пустое имя (`/a/:`,
  `/a/*`); `*name` не последний сегмент (`/a/*r/b`). Дубль (тот же метод и шаблон после нормализации, имена
  параметров не учитываются: `/u/:id` и `/u/:uid`) - `Error`, но не `TypeError`. `/a/:x` и `/a/*x` - не дубли.
- `match(method, path)`: от первого `?` в `path` всё отбрасывается; один завершающий `/` игнорируется.
- `:name` берёт непустой сегмент, `*name` - весь остаток, в т.ч. пустой (`/f` и `/f/` подходят под `/f/*p`, `p` = `''`);
  остаток - сегменты через `/`. Статический сегмент сравнивается с сегментом пути как есть, без декодирования.
- Приоритет сегмента слева направо: статический > `:name` > `*name`. Если выбранная ветка не дала совпадения глубже
  (в т.ч. нет обработчика метода в конце), поиск откатывается к ветке следующего приоритета.
- Значения `:name` и `*name` проходят `decodeURIComponent`; ветка с некорректной escape-последовательностью
  (`%E0%A4%A`) не совпадает. Остаток `*name` декодируется целиком (`%2F` даёт `/`).
- `HEAD`: сначала ищется совпадение для `HEAD` по всем шаблонам; только если его нет - для `GET`.
- Совпадение: `{ handler, params }`, `params` - обычный объект `{}` (без параметров - пустой).
- Путь не подходит ни под один шаблон (с любым методом) -> `{ status: 404 }`. Путь подходит под шаблоны, но не для
  этого метода -> `{ status: 405, allow }`: отсортированные методы в верхнем регистре из всех подошедших под путь
  шаблонов, без дублей (`HEAD` сам по себе не добавляется).
- Примеры (маршруты `GET`; `a`, `b` - обработчики): `/u/:id`, `match('GET','/u/a%20b?x=1')` -> `{ handler: a, params:
  { id: 'a b' } }`; `/f/*p`: `match('get','/f/x/y/')` -> `{ p: 'x/y' }`, `match('GET','/f')` -> `{ p: '' }`;
  `/a/b/c`, `/a/:x/d`, `/a/*r`: `match('GET','/a/b/d')` -> `{ x: 'b' }` (откат), `/a/b/e` -> `{ r: 'b/e' }`;
  только `POST /p`: `match('GET','/p')` -> `{ status: 405, allow: ['POST'] }`, `match('GET','/q')` -> `{ status: 404 }`;
  `add('GET','/a',h).add('GET','/a/',h)` -> `Error`; `add('GET','a',h)` -> `TypeError`.

## 10. `src/strftime.js` - форматирование даты (strftime)

- `strftime(date, format)` -> строка, всё в UTC, имена английские. `date` не `Date` или невалидная (`NaN`) либо `format`
  не строка - `TypeError` (проверяется раньше разбора формата). Прочие символы `format` копируются как есть.
- Числовые директивы, в скобках ширина по умолчанию (слева нулями): `%Y` год (4), `%y` год mod 100 (2), `%m` (2),
  `%d` (2), `%e` день (2, но ПРОБЕЛАМИ), `%H` 0-23 (2), `%I` 1-12 (2; 0 ч -> 12, 13 ч -> 1), `%M` (2), `%S` (2),
  `%L` мс (3), `%j` день года 1-366 (3), `%u` 1-7, Пн=1 (1), `%w` 0-6, Вс=0 (1), `%G` ISO-год (4), `%V` ISO-неделя
  (2), `%s` Unix-секунды `Math.floor(мс / 1000)` без дополнения (до 1970 - отрицательные).
- Текстовые: `%a` `Mon`, `%A` `Monday`, `%b` `Jan`, `%B` `January`, `%p` `AM` (0-11 ч) / `PM`, `%%` -> `%`.
  Проверяются годы 1-9999: `%Y` и `%G` - минимум 4 цифры (год 42 -> `0042`).
- Флаг сразу после `%`, не более одного: `-` без дополнения (`%-d` -> `5`), `_` пробелы до ширины по умолчанию,
  `0` нули до неё (`%0e` -> `05`). Флаг только у числовых директив; у текстовой (и у `%%`) - `RangeError`.
  У `%s` флаги допустимы и ничего не меняют.
- `RangeError`: неизвестная директива (`%Q`, `%5d`), одинокий `%` в конце, флаг в конце (`%-`), два флага (`%-_d`).
  Ошибка формата бросается, даже если до неё формат был корректен.
- `isoWeek(date)` -> `{ year, week }` по ISO 8601: неделя начинается в Пн, неделя 1 содержит первый четверг года.
  Конец декабря может попасть в неделю 1 следующего года, начало января - в неделю 52/53 предыдущего.
  Невалидный ввод - `TypeError`. `%G` и `%V` равны `year` и `week` из `isoWeek`.
- Примеры (d = 2025-03-05T07:08:09.045Z): `strftime(d, "%Y-%m-%d %H:%M:%S.%L")` -> `"2025-03-05 07:08:09.045"`;
  `strftime(d, "%-d/%-m/%y [%e] [%_m]")` -> `"5/3/25 [ 5] [ 3]"`;
  `strftime(d, "%a %A %b %B %j %u %w")` -> `"Wed Wednesday Mar March 064 3 3"`;
  `0042-01-02T00:30Z` с `"%Y|%I:%M %p"` -> `"0042|12:30 AM"`; `2024-12-30T12:00Z` с `"%G-W%V-%u"` -> `"2025-W01-1"`;
  `strftime(d, "%-A")`, `strftime(d, "50%")` -> `RangeError`; `isoWeek(2021-01-03)` -> `{ year: 2020, week: 53 }`.

## 11. `src/ini.js` - диалект INI
- `parseIni(text)` -> объект; `stringifyIni(obj)` -> строка. Строки разделяет LF или CRLF, номер строки 1-based,
  строка обрезается по краям. Пустая строка и строка, начинающаяся с `;` или `#`, - пропуск.
- Секция `[имя]`: строка начинается с `[` и кончается `]`; имя делится по `.` на сегменты (все обрезаются):
  `[a.b]` -> `obj.a.b`. Ключи до первой секции - в корне. Повторная секция дополняет прежнюю; секция без
  ключей создаёт `{}`. Возврата в корень нет.
- Ключ: `key = value` (по первому `=`, части обрезаются, точка в ключе - обычный символ); `key[] = v` - в массив.
- Голое значение: `true`/`false` -> boolean; маска `-?\d+(\.\d+)?` -> number; иное - строка, пустое - `""`.
  Комментарий: `;` или `#` после пробельного символа (в счёт и пробелы сразу после `=`), отбрасывается до
  типизации; `;`/`#` без пробела перед ним - часть значения.
- Значение в двойных кавычках - всегда строка (`"true"`, `"1"`); `;` и `#` внутри - литералы;
  escape `\"` `\\` `\n` `\t`. После закрывающей кавычки допустимы только пробелы и комментарий (`;`/`#`).
- Повтор простого ключа: побеждает последний. Имя, занятое значением другого вида (скаляр, массив, секция),
  занять нельзя: `x = 1` затем `[x]` или `x[] = 2`; `[a.b]` затем `[a]` с ключом `b`; `k[] = 1` затем `k = 2`.
- Ошибки - `SyntaxError` с `line N` в сообщении (N - строка нарушения): нет `=` и не секция/комментарий;
  `[` в начале без `]` в конце; незакрытая кавычка; неизвестный escape; мусор после кавычки; пустой ключ
  (`= v`); пустое имя секции или сегмента (`[]`, `[a..b]`); коллизия имён.
- stringifyIni: корневые скаляры и массивы идут раньше любой секции; вложенные объекты - секции с точечными
  именами; массивы - строки `key[] = v`; строка в кавычках, только когда иначе прочтётся другим значением.
- Круговой обмен: объекты из строк (без управляющих символов, кроме `\n` и `\t`), конечных чисел (не `-0`,
  `String(n)` без экспоненты), boolean, непустых массивов таких скаляров и вложенных объектов (и пустых);
  ключи непусты, без `= . [ ] ; # "`, без пробелов по краям: `parseIni(stringifyIni(x))` deep-equals `x`.
- Примеры: `parseIni('a = 1\n[s.t]\nb = "x ; y" ; c\nl[] = 1\nl[] = two')` -> `{a:1,s:{t:{b:'x ; y',l:[1,'two']}}}`;
  `parseIni('k = v # c')` -> `{k:'v'}`; `parseIni('k=v#c')` -> `{k:'v#c'}`; `parseIni('x = 1\n[x]')` -> `SyntaxError`
  с `line 2`; `parseIni('k = "true"\nn = 1.5')` -> `{k:'true',n:1.5}`. Точный текст `stringifyIni` не нормируется.

## 12. `src/wrap.js` - перенос строк по ширине
- `wrap(text, width, options = {})` -> строка. `options.indent` (строка, по умолчанию `''`), `options.firstIndent`
  (по умолчанию `indent`), `options.hard` (булево, по умолчанию `false`). Ширина - в `.length`.
- Ошибки: `width` не целое (`Number.isInteger`), либо `width <= indent.length`, либо `width <= firstIndent.length`
  -> `RangeError`; проверка идёт до разбора текста, в том числе для пустого `text`.
- Строки текста делятся по `"\n"`; пустая строка - только из пробельных символов (`\s`, в т.ч. `"\r"`). Абзац - серия
  непустых строк; одна и более пустых подряд разделяют абзацы. В результате между абзацами ровно одна пустая
  строка (`"\n\n"`), в начале и конце пустых строк нет, завершающего `"\n"` нет; текст без слов -> `''`.
- Слова - непустые серии непробельных символов; любая пробельная серия в абзаце равна одному пробелу.
- Жадное заполнение: в строку идёт максимум слов подряд, пока префикс + слова через пробел <= `width`.
  Префикс первой строки абзаца - `firstIndent`, остальных - `indent`; он входит в ширину.
- Длинное слово - длиннее свободного места (`width` минус префикс строки, на которой оно стартует). Оно всегда
  начинает новую строку (текущая закрывается). При `hard: false` оно стоит на строке одно, строка длиннее
  `width`, следующее слово начинает новую строку. При `hard: true` оно режется на куски ровно по свободному
  месту строки (первый кусок - по месту строки старта, остальные - по `width - indent.length`); последний
  кусок остаётся текущей строкой, следующие слова достраивают её жадно.
- `justify(line, width)` -> строка. `width` не целое -> `RangeError` (проверка первая). Слова строки - непустые
  серии непробельных символов. Если слов меньше двух, либо `line.length >= width`, либо слова через один пробел
  занимают `>= width` - вернуть `line` без изменений. Иначе слова соединяются так, чтобы длина была ровно `width`:
  пробелы между словами делятся поровну, остаток по одному идёт в самые левые промежутки; краевых пробелов нет.
- Примеры: `wrap('the quick brown fox', 10)` -> `'the quick\nbrown fox'`;
  `wrap('aa bb\n\n\n  cc   dd ', 5)` -> `'aa bb\n\ncc dd'`;
  `wrap('one two three four', 9, {indent: '  ', firstIndent: ''})` -> `'one two\n  three\n  four'`;
  `wrap('abcdefg hi', 5, {hard: true})` -> `'abcde\nfg hi'`; `wrap('a abcdefgh b', 4)` -> `'a\nabcdefgh\nb'`;
  `wrap('x', 2, {indent: '  '})` -> `RangeError`; `justify('a b c', 8)` -> `'a   b  c'`; `justify('ab', 9)` -> `'ab'`.

## 13. Правка `src/template.js` после пп. 4, 10, 12: фильтры
- Синтаксис: `{{ путь | f1 | f2 арг }}` и `{{{ путь | ... }}}`. Фильтры применяются слева направо к найденному значению
  до экранирования (тройные скобки - без него). Путь - всё до первого `|` (после trim): непустой, без пробелов.
- Теги без `|` работают как раньше. Конец тега прежний (первая `}}` / `}}}`), даже если она внутри строки-аргумента.
- Аргумент: строка в двойных кавычках (внутри `\"` и `\\`, иной `\x` - ошибка; `|` в строке - обычный символ) или
  целое (необязательный `-`, десятичные цифры). Имя фильтра и аргументы разделены пробелами; имена строчные.
- `null`/`undefined` (в т.ч. не найденное) заменяет только `default`; остальные фильтры такое значение пропускают.
  Итог цепочки: `null`/`undefined` -> пусто, иначе `String(value)`, затем экранирование (кроме `{{{`).
- `upper`, `lower` (без аргументов): `String(value)` в верхнем / нижнем регистре.
- `default "text"`: значение `''`, `null` или `undefined` -> `text`; `0`, `false`, `' '` остаются.
- `date "<формат>"`: `Date` или число (мс от эпохи) -> `strftime(дата, формат)`; ошибки `strftime` не меняются.
- `wrap <ширина>`: `wrap(String(value), ширина)` без опций; ошибки `wrap` не меняются.
- `join "<sep>"`: массив -> элементы через `sep` (`null`/`undefined` -> пусто, прочие `String(el)`); иначе `TypeError`.
- `SyntaxError` с `offset` (индекс `{{` тега) при разборе, в т.ч. в невыбранной ветке: неизвестный фильтр, число или
  тип аргументов не те, пустой фильтр (`a | | b`, `a |`), пустой путь, незакрытая строка, мусор после строки,
  любой `|` в `#if`/`#each`.
- `render('{{ n | upper }}!', {n:'<b>'})` -> `&lt;B&gt;!`; `render('{{{ n | upper }}}', {n:'<b>'})` -> `<B>`
- `render('{{ x | default "n/a" | upper }}', {x:''})` -> `N/A`; `{{ xs | join ", " }}` с `['a',1,null]` -> `a, 1, `
- `render('{{ t | date "%Y-%m-%d" }}', {t:86400000})` -> `1970-01-02`; `{{ s | wrap 5 }}` с `'aa bb cc'` -> `aa bb\ncc`
- `render('a{{ x | foo }}', {})` -> `SyntaxError`, offset 1; `render('{{#if a | upper}}{{/if}}', {})` -> offset 0
