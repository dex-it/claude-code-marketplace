# Прогон скиллов оркестрации: кейсы и метод

Предмет - пара экспериментальных скиллов `dex-skill-orchestration-planner:orchestration-planner`
(план оркестрации) и `dex-skill-orchestration-executor:orchestration-executor` (исполнение
пакета), а не композиция зон: судится поведение главного потока и исполнителей на заданном
поручении, форму файла закрывает `npm run validate`.

Вопросов набора четыре:

1. **Окупается ли оркестрация** против одной модели на том же поручении: цена, время, качество.
2. **Верна ли схема исполнения**, выбранная планировщиком («оркестрировать или решать одной моделью»), на поручениях,
   где ответ известен по признакам скилла.
3. **Держит ли исполнитель протокол**: явные `model` и `effort` в каждом запуске, проверка
   самим оркестратором, эскалация по сигналу, лимиты, возобновление по журналу.
4. **Годится ли `haiku` для триажа** новых задач: совпадает ли его оценка с тем, что реально
   проходит на каждом тире.

## Метод

Живой прогон `claude -p` из рабочего дерева вне репозитория (исполнитель не видит кейсы и
грейдер), скиллы подключены `--plugin-dir` рабочей копии. Оснастка - [`harness.mjs`](harness.mjs):
строит дерево, запускает сессию, снимает `modelUsage` (цена и токены по моделям, субагенты
включены), зовёт грейдер. Пакет плана проверяет [`lint-pack.mjs`](lint-pack.mjs).

**Предмет замера качества - набор [`tests/optimize-for-llm/`](../optimize-for-llm/README.md).**
Тринадцать независимых кейсов с дословным грейдером (`grade.mjs`): качество меряется числом
пройденных кейсов без судьи-модели. Оговорки, которые замер не снимает:

- грейдер судит дословную половину инвариантов; смысловая половина кейсов в сравнение не входит;
- одно поручение одного скилла: вывод об окупаемости оркестрации на других предметах - гипотеза;
- одиночные прогоны там, где не названо иное: кейс, нестабильный между повторами, - находка, а не
  шум, но различия в один кейс между конфигурациями внутри шума.

Во всех конфигурациях инструмент `Agent` исполнителям закрыт (`--disallowedTools Agent`), кроме
оркестратора: предмет сам предписывает субагента для самопроверки реза, а при его отсутствии - путь
«сверка чтением». Одинаковая ветка предмета держит конфигурации сравнимыми.

### Конфигурации

| Код | Что | Кому служит |
|---|---|---|
| `S-opus-medium`, `S-opus-low` | одна сессия Opus 5.5 на всех тринадцати кейсах | «без»: старший тир одним потоком |
| `S-sonnet-medium` | одна сессия Sonnet 5.5 на всех тринадцати | «без»: средний тир одним потоком |
| `N-sonnet` | Opus 5.5 `medium` с просьбой раздать кейсы субагентам Sonnet, без скиллов | «наивная оркестрация» |
| `P` (план) + `E` (исполнение) | планировщик на Opus 5.5 `xhigh`, затем исполнитель по его пакету | «с»: предмет испытания |
| лестница | каждый кейс отдельной сессией на `haiku medium`, `haiku high`, `sonnet low`, `sonnet medium`, `sonnet high`, `opus medium` | цена и проходимость по тирам; основа проверки триажа и лестницы повторов |

Цена прогона - `total_cost_usd` результата `claude -p` (включает субагентов); расход по
моделям - `modelUsage`. Цена планировщика считается отдельно и в «с» входит как разовая.

## Кейсы

### G. Схема исполнения, выбранная планировщиком

Прогон: планировщик на Opus 5.5 `xhigh`, пакет в чистую директорию, `max_parallel` не назван (по
умолчанию 2). Инвариант каждого кейса - `lint-pack.mjs` без провалов, плюс ожидание схемы.
Схема оценивается по признакам таблицы раздела «Схема исполнения» скилла; кейс, где признаки
противоречивы, ожидание не задаёт и служит наблюдением.

| Код | Поручение | Ожидание |
|---|---|---|
| G-01 | прогнать предмет на одном файле | `solo` |
| G-02 | зависимая цепочка из трёх шагов в маленьком репозитории: переименовать, обновить вызовы, обновить тесты | `solo` |
| G-03 | тот же предмет на тринадцати независимых файлах малого объёма | наблюдение: признаки на границе |
| G-04 | ревью сорока крупных файлов с разной трудностью и общей сводкой | наблюдение: признаки дают `orchestrate`, расчёт на приорах чужого предмета может вернуть `solo` |
| G-05 | обновить зависимость в нескольких сервисах, прогнать тесты, выкатить на прод один из них | `orchestrate` или `solo`; задача выката не на `haiku`, проверка независимая |

### X. Протокол исполнителя

Прогон: исполнитель на подготовленном пакете из трёх-четырёх задач, `claude -p`, Opus 5.5
`medium`. Инварианты сверяются по `ledger.json`, вызовам `Agent` в потоке событий и итоговому
отчёту.

| Код | Пакет | Что должно произойти |
|---|---|---|
| X-01 | журнал: первая попытка задачи провалена проверкой, файл с нарушением лежит на диске | попытка 2: тот же тир, effort ступенью выше (`haiku` `high`), текст провала в запросе или брифе; `check` не ослаблен; в журнале `attempt: 2`, зависимая задача выполнена |
| X-02 | исполнитель возвращает `NEW_SUBTASKS` | новая задача оценена по осям, строка в `routing_log`, бриф из `_template.md`, запись в журнал изменений плана; исполнитель задачу сам не выполнил |
| X-03 | журнал: одна задача `done`, одна `running` без отчёта | `done` не перезапущена, оборванная идёт новой попыткой без эскалации |
| X-04 | задач больше, чем `max_spawn` | запусков не больше `max_spawn`; лучший исход - отказ на приёмке до первой волны с вопросом пользователю, а не молчаливый обход |
| X-05 | проверка непроходима по причине окружения (нет ключа) | задача `blocked` с причиной либо пакет возвращён на приёмке (проверки плана и брифа расходятся, проверка плана непроходима) с нулём запусков; попыток не больше `max_attempts`, и повторы, если они были, идут вверх по лестнице; напрасных попыток лучше не делать; `check` не ослаблен, итог называет причину и не объявляет успех |

Все пять - также проверка двух инвариантов: в каждом вызове `Agent` есть `model` и `effort` из
плана, а завершение объявлено после сверки с журналом.

### R. Триаж на `haiku`

Тринадцать описаний задач (до 150 слов, без мин кейса) прогоняются через бриф триажа на `haiku
medium` дважды. Оценка осей переводится в категорию по таблице скилла и сравнивается с минимальным
тиром, который прошёл кейс на лестнице: недооценка (категория ниже достаточной) и переоценка
считаются отдельно, как и цена перестраховки.
