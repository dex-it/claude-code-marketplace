# Замер на большом объёме: два корпуса с объективным грейдером

Вопрос: меняется ли вывод «оркестрация не окупается», когда кусков десятки и сотни, а проверка -
настоящие тесты. Исходный предмет набора (`optimize-for-llm`, 13 кейсов) этого не показывает:
кусков мало, а грейдер судит только дословную половину инвариантов.

Оба корпуса собираются скриптом из зерна (`--seed`), грейдер лежит вне рабочего дерева и сравнивает
выход каждой функции с выходом эталона на всех входах; исполнитель его не видит.

| Корпус | Скрипт | Что в нём | Грейдер |
|---|---|---|---|
| Миграция API | [`gen.py`](gen.py) | N модулей со старым `legacy.fmt_amount`; перевести на `money.format_money` так, чтобы выходы остались теми же (умолчания у API разные: стиль, округление, `None`); классы трудности: прямая замена, позиционные аргументы, ловушки (alias, имя в строке и комментарии), `partial` и словари форматтеров, проброс `**kwargs` | линт «нет `legacy` в коде» и расширенные входы против выхода старого кода |
| Дефекты по контракту | [`genfix.py`](genfix.py) | N модулей из 15 шаблонов функций с контрактом в docstring; в части функций засеян дефект: видимый (ловят видимые тесты) или тонкий (только скрытые: граничные входы, дубликаты, пустые значения, типы); `--visible weak\|strong` задаёт силу видимых тестов | выход эталона на типичных и граничных входах; модуль засчитан, если верны все функции |

Проверка грейдера до запуска моделей: `--variant ref` (эталон) даёт 100%, исходный корпус - 0 модулей
по скрытым тестам и лишь часть по видимым (`run_tests.py`); `gen.py --variant half` (стиль учтён,
округление и `None` нет) проходит видимые тесты на 57% модулей и 0% скрытых.

## Запуск

```
python3 -I genfix.py <каталог> --modules 120 --seed 21 --visible weak     # рабочее дерево и <каталог>.hidden
node ../harness.mjs claude <каталог> <каталог>/PROMPT.md --model sonnet --effort medium \
     --budget 10 --no-subject                                            # одна сессия
python3 -I <каталог>.hidden/grade.py <каталог> --json                    # результат
```

План и исполнение: тот же каталог, поручение «Используй скилл orchestration-planner. Предмет: промт
из файла PROMPT.md ...», затем `harness.mjs claude <каталог> <файл с поручением исполнителю>
--agent --plugins dex-skill-orchestration-executor`. Исполнителю и планировщику каталог `.hidden`
не передаётся.

## Что нашли

- **Модели обобщают повторы.** Миграция на 24 модулях и контракты на 40 и 120 модулях решены всеми
  тремя тирами на 100% за секунды и копейки; планировщик на 120 модулях измерил предмет и нашёл
  16 разных контрактов на 430 определений. Цена сессии растёт слабее числа кусков.
- Поэтому корпус из шаблонов не создаёт давления объёма: он проверяет шлюз (`solo` верен) и цену
  оркестрации (проигрывает), но не режим «не помещается в контекст». Окно контекста у всех моделей
  5.5 - 1M токенов (около 2.5 млн символов); корпус таких размеров с настоящими тестами и без
  повторов (например, реальная библиотека с внесёнными мутациями) в набор не вошёл.
