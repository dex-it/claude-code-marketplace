# review-threads: сжатие по свидетельству, группа 1.3

Скилл `dex-skill-review-threads` 1.1.0 ([`inputs/SKILL-1.1.0.md`](inputs/SKILL-1.1.0.md)), эпик #291,
группа 1.3 (#295). Итог - 2.0.0, process-skill ([`inputs/SKILL-2.0.0.md`](inputs/SKILL-2.0.0.md)), строка в
реестре [`tests/README.md`](../../README.md). Вход - общий мини-проект [`_projects/billing`](../_projects/billing/README.md), кейсы
D, N0, C и P группы 1.3; ключ, допустимые решения и сверка кейсов записаны там до первого прогона.

Исполнитель - `claude-sonnet-5-5`, effort `medium` (решение 1 эпика), `claude -p` 2.1.287 из раннера
[`hosting/run.mjs`](../_projects/billing/hosting/run.mjs): `--restricted --strict-mcp-config`, набор MCP
пуст, `--disable-slash-commands`, инструменты `Read, Write, Edit, Glob, Grep, Bash`, без `Skill` и веба.
Прогон со скиллом подаёт копию `SKILL.md` путём через `--add-dir`.

## Среда: хостинг и оператор

Ловушки скилла живут в записи в MR, поэтому прогон без канала к хостингу их не проверяет. Выбран канал-
заглушка, а не вердикт по плану команд: `gh` и `glab` в `PATH` исполнителя - обёртки над
[`fakehost.mjs`](../_projects/billing/hosting/fakehost.mjs), которые пишут журнал вызовов и отдают ответы
по `origin` прогона. Исход - журнал записей: тред, его позиция и SHA, ответ в тред, resolve, общий
комментарий. Поведение заглушки, на котором держится ключ (`--jq` у glab, литеральные ключи со скобками,
422/400 на строку вне диффа), сверено с glab 1.116.0 и gh 2.100.0, таблица - в README мини-проекта.
Настоящий хостинг из прогона недостижим: обёртки первые в `PATH` (раннер сверяет `command -v`), Bash
исполнителя - в песочнице без сети.

Оператор нужен только кейсу P: реплики подаются по ходам через `claude -p --resume`.
Кейс P - вход набора [review-step-by-step](../review-step-by-step/README.md): его потребитель
`review-planner` грузит оба скилла, здесь засчитан только код PR.

Ограничение заглушки: GitLab `repository/compare` и `repository/files/.../raw` не реализованы (404).
Исполнитель уходил за диффом в git (d-c1, d-n2a), исход по ключу этим не задет. Дефект заглушки, найденный
на суде итогового прогона: поля `gh api` вида `comments[][path]` (массив объектов) терялись, review уходил
с `comments: []`. Ответ исполнителю от этого не менялся (200 и id ревью). Разбор исправлен по
`gh api --help` 2.100.0 (пример `properties[][property_name]`), вызов c-v2 повторён на исправленной
заглушке - [`runs/c-v2/replay.txt`](runs/c-v2/replay.txt). Других прогонов с такими полями нет.

## Открыто

- Вердикт хостинга: контроль C ставил `REQUEST_CHANGES` 2/2; со скиллом 2.0.0 вердиктов нет 4/4 - их
  держит гейт «Запись», отдельный запрет в скилле свидетельства не имеет. Решение владельца
  (05.10.2026): запрет в скилл не добавляется; появится провал со скиллом (в том числе у
  `review-planner`) - единица вводится по методу.
- «201 и тред без привязки» у GitLab - допущение заглушки (из 1.1.0); ступень 2 опирается на сверенную
  часть (литеральное имя поля).
- Заглушка без GitLab `repository/compare` и `repository/files` - ограничение, исход не задет
  (исполнитель брал дифф из git). Решение владельца (05.10.2026): заглушка не дописывается, пока
  кейс не потребует этих вызовов.
- Канал native MCP хостинга в прогонах не проверялся (MCP пуст): судится только CLI-фолбэк.
- `dotnet test` в песочнице не стартует (bind сокета) - одинаково во всех режимах.
