# Ревью MR: Pricing.Api

Итого: blocker — 4, major — 4, minor — 3.

## Blocker

1. **src/PriceService.cs:7-15** — комментарий неверен: `IMemoryCache.GetOrCreateAsync` НЕ гарантирует единственный вызов фабрики. При промахе кэша N параллельных запросов на один sku вызывают `supplier.GetPriceAsync` N раз (классический cache stampede).
   Чем кончится: лимит поставщика 5 rps на ключ, превышение — бан ключа на час. Первый же всплеск трафика на «холодный» sku/после истечения 5 минут банит ключ, цены перестают отдаваться для всего сервиса.
   Починить: per-key `SemaphoreSlim`/`Lazy<Task>`, либо `HybridCache.GetOrCreateAsync` (там stampede-защита есть), плюс ограничитель скорости на `ISupplierClient`.

2. **src/PriceService.cs:22** — `discountPercent / 100` — целочисленное деление (int/int). Для 0..99 даёт 0, для 100 даёт 1.
   Чем кончится: скидка не применяется вообще (кроме 100% — тогда цена 0). Клиенты платят полную цену вместо скидочной. Нужно `basePrice * discountPercent / 100m`.

3. **src/SupplierFeedParser.cs:10,14** — regex `//.*$` вырезает «комментарии» и внутри строковых значений. `ImageUrl` по контракту — `https://cdn.supplier.example/...`, всё после `//` отрезается вместе с закрывающей кавычкой и запятой.
   Чем кончится: любой фид с картинкой превращается в невалидный JSON → `JsonException`, разбор фида падает целиком. Также утверждение в комментарии неверно: в System.Text.Json есть `JsonSerializerOptions.ReadCommentHandling = JsonCommentHandling.Skip` (и `AllowTrailingCommas` при необходимости). Regex убрать.

4. **src/CatalogCache.cs:17** — у `HybridCache` нет метода `EvictByTagAsync`; инвалидация по тегу — `RemoveByTagAsync`.
   Чем кончится: код не компилируется (MR не соберётся). Ниже — по смыслу, даже после исправления см. п. 5.

## Major

5. **src/CatalogCache.cs:14, Pricing.Api.csproj:7-8** — в MR нет `Program.cs`/DI-регистрации и нет обработчика события «каталог обновлён», который вызывает `InvalidateAsync`. Не зарегистрированы `AddHybridCache`, `AddMemoryCache`, `ISupplierClient`, `ICatalogRepository`, `PriceService`, `CatalogCache`, именованный клиент "notifications". Redis-пакет подключён, но `IDistributedCache` не настроен.
   Чем кончится: приложение падает на старте/первом запросе (не разрешаются зависимости); заявленная «инвалидация по событию» фактически не работает — страницы каталога остаются устаревшими до истечения TTL по умолчанию. Если Redis всё же будет добавлен, теги в HybridCache инвалидируются только логически, и это нужно проверить для L2.

6. **src/PricesController.cs:12-15** — `sku` произвольный и неограниченный, эндпоинт без аутентификации/rate limit; каждый новый sku — промах кэша и запрос к поставщику, плюс запись в `IMemoryCache` без лимита размера. Исключение поставщика (неизвестный sku) уходит как 500.
   Чем кончится: перебор sku вычерпывает квоту 5 rps и банит ключ на час (DoS на себя), и растёт память кэша. Нужны валидация sku, rate limiting, `SizeLimit`/негативное кэширование, маппинг ошибок поставщика в 404/502.

7. **src/PricesController.cs:22-24** — ответ `PostAsync` игнорируется (нет `EnsureSuccessStatusCode`/проверки статуса), всегда возвращается 202; при отказе сервиса уведомлений вызывается исключение `HttpRequestException` → 500 без политики ретраев.
   Чем кончится: уведомление о смене цены тихо теряется при 4xx/5xx, вызывающий уверен, что всё отправлено; при сетевой ошибке — неуправляемый 500. Нужно проверять статус, логировать, лучше outbox/очередь.

8. **src/PricesController.cs:19-23** — `sku` подставляется в путь без `Uri.EscapeDataString`; эндпоинт открыт и меняет внешнее состояние (рассылка), без авторизации.
   Чем кончится: sku вида `../x` или с `?`/`#` меняет целевой URL запроса к сервису уведомлений (path injection); любой анонимный клиент может спамить уведомлениями.

## Minor

9. **src/PriceService.cs:23** — `Math.Round(x, 2)` использует банковское округление (ToEven). Для денег обычно `MidpointRounding.AwayFromZero`. Итог: расхождение на копейку с ожиданиями бухгалтерии/витрины.

10. **src/PriceService.cs:11-15** — токен отмены первого запроса захватывается фабрикой; отмена клиента прерывает запрос к поставщику, и исключение отмены уходит вызывающему. При общей фабрике (после починки п. 1) отмена одного клиента не должна ломать остальных — использовать независимый токен/таймаут.

11. **Pricing.Api.csproj:7-8** — разные версии пакетов (Hybrid 9.3.0, Redis 9.0.3) и нет ограничения/обоснования; для `HybridCache` нужен совместимый `Microsoft.Extensions.Caching.*`. Минимум — выровнять версии, чтобы не получить конфликт зависимостей. Плюс нет тестов на новый код (парсер, расчёт скидки — п. 2/3 поймали бы тесты).
