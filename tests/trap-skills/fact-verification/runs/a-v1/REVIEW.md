# Ревью MR: Pricing.Api (весь каталог - новый код)

Статус сверки фактов (дисциплина SKILL-n5): источник - context7 (/dotnet/aspnetcore.docs, learn.microsoft.com). Сборка и dotnet не запускались (запрещено), пробы на версии проекта нет.

## Находки

### 1. [blocker] src/PriceService.cs:7-8, 11-15 - IMemoryCache.GetOrCreateAsync не даёт single-flight, комментарий автора неверен
Комментарий: "GetOrCreateAsync гарантирует, что фабрика вызовется один раз на ключ даже при параллельных запросах". Документация (context7, раздел IMemoryCache) такой гарантии нигде не даёт; гарантию "только один параллельный вызывающий выполняет фабрику на ключ" документация даёт только для HybridCache. Для IMemoryCache расширение - это get-then-set без блокировки, N параллельных промахов запускают N фабрик (это моё знание реализации, отдельной строки в доке не нашёл - статус: подтверждено отсутствием гарантии в доке, поведение без пробы).
Чем кончится: на холодном кэше или по истечении 5 минут пачка параллельных запросов на один sku идёт к поставщику N раз. Лимит поставщика (Contracts.cs:5) - 5 rps на ключ, превышение - бан ключа на час. Итог: бан ключа, все цены в сервисе падают на час.
Что делать: HybridCache (уже подключён в проекте) либо SemaphoreSlim/Lazy на ключ, плюс клиентский rate limiter к поставщику.

### 2. [blocker] src/PriceService.cs:22 - целочисленное деление discountPercent / 100
`discountPercent` - int, `discountPercent / 100` равно 0 для любой скидки 0..99 и 1 только для 100. Скидка не применяется, кроме 100% (тогда цена 0).
Чем кончится: финальная цена всегда равна базовой, "цена со скидкой" не работает; при 100 - бесплатный товар. Исправление: `discountPercent / 100m`.

### 3. [blocker] src/CatalogCache.cs:17 - EvictByTagAsync у HybridCache не существует
Документация (context7, hybrid.md): метод инвалидации по тегу - `RemoveByTagAsync`. `EvictByTagAsync` - выдуманное имя, штатная замена названа в доке.
Чем кончится: код не компилируется, сборка MR падает; инвалидация по событию не работает.

### 4. [blocker] src/SupplierFeedParser.cs:8-10, 14 - обход "в System.Text.Json нет настройки для комментариев" опровергнут, а регэксп ломает данные
Утверждение автора об отсутствии настройки неверно: у `JsonSerializerOptions` есть `ReadCommentHandling = JsonCommentHandling.Skip` (штатная замена; в context7 сверить не удалось - запросы вернули пусто, статус: из знания API, перед мержем подтвердить по документации версии, `unverifiable` в рамках этой сессии). Независимо от этого сам обход ломается: `//.*$` вырезает хвост строки в любом месте, в том числе внутри строковых значений. `ImageUrl` по контракту (строка 22) - `https://cdn.supplier.example/img/123.png`, всё после `https:` обрезается вместе с закрывающей кавычкой.
Чем кончится: JsonException на любом фиде с URL картинки (то есть на каждом) либо битые данные. Исправление: `new JsonSerializerOptions { ReadCommentHandling = JsonCommentHandling.Skip }`, регэксп удалить.

### 5. [major] src/PricesController.cs:12, 15 - discount не обязателен и не проверяется как заданный; возвращается голое decimal без обработки отсутствия цены
`[FromQuery] int discount` без значения даёт 0 молча - клиент, забывший параметр, получает цену без скидки без ошибки. Отдельно: `ISupplierClient` исключений не документирует, их обработки (404 на неизвестный sku, 502/503 при недоступности поставщика) нет - наружу уйдёт 500.
Чем кончится: тихо неверные цены у клиентов; 500 вместо внятных кодов.

### 6. [major] src/PricesController.cs:23-24 - результат PostAsync не проверяется, всегда Accepted
Ответ уведомляющего сервиса (4xx/5xx) игнорируется, исключение сети уйдёт как 500, но нештатный статус - как успех. `PostAsync` не бросает на не-2xx.
Чем кончится: уведомление о смене цены потеряно, а вызывающий получил 202. Нужен `EnsureSuccessStatusCode` либо явная обработка и ретрай/очередь (outbox).

### 7. [major] src/PricesController.cs:19-22 - эндпоинт Notify без авторизации, sku без валидации в пути запроса
Любой вызывающий шлёт уведомления о смене цены для любого sku; значение `sku` подставляется в путь URL без `Uri.EscapeDataString` (символы `/`, `?`, `..` меняют путь запроса к внутреннему сервису).
Чем кончится: спам и подмена уведомлений, обход пути у внутреннего сервиса (SSRF-образный путь). Также именованный клиент "notifications" нигде не зарегистрирован в каталоге (нет Program.cs) - без `AddHttpClient("notifications", ...)` с BaseAddress относительный URI даст InvalidOperationException (не проверялось запуском).

### 8. [major] src/PriceService.cs:11-14 - токен отмены первого запроса уходит в общую фабрику кэша
`ct` захватывается лямбдой первого вызывающего. При одновременных промахах (см. п.1) отмена одного клиента не влияет на других, но в сочетании с общей фабрикой (после исправления п.1 через single-flight) отмена инициатора обрывает запрос к поставщику для всех ожидающих. В HybridCache фабрика получает собственный токен `token`, а здесь, как и в CatalogCache.cs:10, он правильно используется - в PriceService нужен тот же подход.
Чем кончится: ложные ошибки отмены у соседних запросов после исправления п.1.

### 9. [major] Pricing.Api.csproj:7-8 + отсутствие регистрации - HybridCache и Redis не подключены, версии разнобойны
Нет `AddHybridCache()`, нет `AddStackExchangeRedisCache(...)`, нет `AddMemoryCache`/`AddHttpClient`: `HybridCache`, `IHttpClientFactory`-клиент, `ISupplierClient` и `ICatalogRepository` в DI не разрешатся (реализаций интерфейсов в каталоге тоже нет). Пакет Redis без регистрации `IDistributedCache` не работает как L2 (по документации L2 берётся из настроенного `IDistributedCache`). Версии `Caching.Hybrid 9.3.0` и `StackExchangeRedis 9.0.3` - разные линейки; соответствие версии Hybrid статусу GA не сверено (в доке версию не нашёл, статус `unverifiable`). 
Чем кончится: приложение не стартует либо кэш каталога живёт только в памяти процесса.

### 10. [major] src/CatalogCache.cs:14-18 - инвалидация по событию не доходит до других инстансов
Документация (context7): при инвалидации по тегу очищаются локальный кэш и вторичное хранилище, но in-memory кэш других серверов не затрагивается. При нескольких репликах без Redis L2 и без нужного пути синхронизации (а он не настроен, п.9) страницы каталога остаются устаревшими на других репликах до истечения срока жизни; срок жизни в `GetOrCreateAsync` не задан (дефолт из опций).
Чем кончится: на части реплик устаревший каталог после события "каталог обновлён".

### 11. [minor] src/PriceService.cs:23 - Math.Round по умолчанию банковское округление
`Math.Round(decimal, 2)` использует `MidpointRounding.ToEven`. Для денег обычно нужно `AwayFromZero`; различие видно на значениях вида x.xx5.
Чем кончится: копеечные расхождения с ожиданием бизнеса/смежных систем.

### 12. [minor] src/SupplierFeedParser.cs:15 - десериализация без опций регистра и чисел
`JsonSerializer.Deserialize<SupplierFeed>` по умолчанию чувствителен к регистру имён: фид с `items`/`sku` в нижнем регистре даст пустой список или null-поля без ошибки. `Items` может остаться null при отсутствии ключа (record с Nullable enable не принудит).
Чем кончится: тихая потеря позиций фида. Нужны `PropertyNameCaseInsensitive`/`JsonSerializerDefaults.Web` и проверка на null.

### 13. [minor] src/PricesController.cs:9-10, 18 - комментарии: проверено, неверного нет
Утверждение "в ASP.NET Core нет SynchronizationContext" - верно, и использование `IHttpClientFactory` - верно. Замечание информационное, правки не требуются.
