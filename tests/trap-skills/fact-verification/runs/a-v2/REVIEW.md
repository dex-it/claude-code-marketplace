# Ревью MR: Pricing.Api

Источники сверки: context7 (/dotnet/aspnetcore.docs, /dotnet/docs). Сборка и dotnet не запускались (запрет задания), проб на версии проекта нет - где факт держится только на документации или не сверен, это помечено.

## Находки

### 1. [blocker] src/PriceService.cs:22 - скидка никогда не применяется
`discountPercent / 100` - целочисленное деление int/int: для 0..99 даёт 0, для 100 даёт 1. `basePrice * 0` = 0, финальная цена = базовая при любой скидке 1..99, а при 100 цена 0. Итог: клиенты платят полную цену вместо скидочной (или бесплатно при 100). Нужно делить в decimal (`discountPercent / 100m`). (Свойство C#, не требует внешней сверки.)

### 2. [blocker] src/SupplierFeedParser.cs:10,14 - regex `//.*$` режет URL внутри строк
Фид содержит `ImageUrl` вида `https://cdn.supplier.example/img/123.png` (SupplierFeedParser.cs:22). Regex видит `//` внутри строкового значения и вырезает всё до конца строки, включая закрывающую кавычку, запятую и скобки. Итог: JSON невалиден, `Deserialize` бросает JsonException на каждом фиде с картинкой, т.е. разбор фида не работает на штатных данных; на однострочном (minified) фиде теряется весь хвост.

### 3. [major] src/SupplierFeedParser.cs:8-10 - отрицательный факт «настройки нет» неверен, самописный обход не нужен
Комментарий: «В System.Text.Json нет настройки, которая позволяет пропускать комментарии». Это ложно. Документация System.Text.Json (invalid-json.md, context7 /dotnet/docs): `JsonSerializerOptions.ReadCommentHandling = JsonCommentHandling.Skip` (+ `AllowTrailingCommas`), штатная замена. Исход: штатная замена названа; обход (п.2) заменить на неё. Версия проекта net9.0; поведение опции на именно 9.0 пробой не проверялось, документация общая (опция существует с .NET Core 3.0 - по документации, не пробой). Также `/* */` комментарии обход не покрывает.

### 4. [blocker] src/CatalogCache.cs:17 - `EvictByTagAsync` не существует у HybridCache
Метод инвалидации по тегу называется `RemoveByTagAsync` (документация HybridCache, aspnetcore.docs, раздел «Remove cache entries by tag»; есть перегрузка с коллекцией тегов). Вызов `EvictByTagAsync` не компилируется - MR не собирается. Даже после переименования: по документации инвалидация логическая (правило «игнорировать записи старше момента инвалидации» для тега), значения физически остаются до истечения срока - допустимо, но надо знать. Версия пакета Hybrid 9.3.0: наличие `RemoveByTagAsync` и работа тегов именно в 9.3.0 документацией версии не подтверждена, по changelog релиза не сверялось - `unverifiable`; при реализации 9.0.0 теги были неполными, поэтому проверить пробой на 9.3.0.

### 5. [major] src/CatalogCache.cs:7-12 и Pricing.Api.csproj:7-8 - HybridCache нигде не зарегистрирован, Redis не подключён
В MR нет `Program.cs`/DI: `AddHybridCache()` не вызывается, `HybridCache` не резолвится - `CatalogCache` упадёт при создании (InvalidOperationException: нет сервиса). `Microsoft.Extensions.Caching.StackExchangeRedis` добавлен, но `AddStackExchangeRedisCache` не вызывается (документация: распределённый слой подключается явно, иначе у HybridCache только in-memory): пакет мёртвый, а при нескольких инстансах инвалидация по событию (п.4) действует только на инстанс, получивший событие, - остальные отдают устаревшие страницы. Аналогично `IMemoryCache` (`AddMemoryCache`), `ISupplierClient`, `ICatalogRepository`, `PriceService`, `CatalogCache` и клиент "notifications" нигде не регистрируются. Если регистрация вне MR - указать где; в диффе её нет.

### 6. [major] src/PriceService.cs:7-8,11 - комментарий «GetOrCreateAsync гарантирует один вызов фабрики» не подтверждён и, вероятно, неверен
У `IMemoryCache.GetOrCreateAsync` в документации такой гарантии нет (в документации single-flight обещает только HybridCache: «stampede protection», context7). Расширение IMemoryCache по моим сведениям делает TryGetValue -> фабрика -> Set без блокировки, т.е. параллельные промахи вызывают фабрику несколько раз; исходник по тегу релиза в этом прогоне не читался - статус по IMemoryCache `unverifiable`, утверждение автора принимать нельзя. Итог при верности: N параллельных запросов на один SKU -> N вызовов поставщика, а лимит поставщика 5 запросов/с на ключ с банном на час (Contracts.cs:5). Вариант: перейти на HybridCache (уже в проекте) либо `SemaphoreSlim` по ключу.

### 7. [major] src/PriceService.cs:11-15 и src/Contracts.cs:5 - нет защиты лимита поставщика
Кэш по ключу `price:{sku}`: разные SKU не объединяются, холодный старт/истечение 5 минут у многих SKU одновременно (каталожная страница из списка SKU) шлёт десятки запросов в секунду. Итог: превышение 5 rps -> бан ключа на час -> все цены недоступны. Нужен ограничитель скорости (rate limiter/очередь) перед `ISupplierClient`, плюс обработка 429. Одновременное истечение у всех ключей по `AbsoluteExpirationRelativeToNow` без джиттера усугубляет.

### 8. [major] src/PriceService.cs:11-14 - токен отмены первого вызывающего живёт в общей фабрике
`ct` запроса, первым вставшего в кэш, передаётся в `supplier.GetPriceAsync`. Если клиент отменил запрос, фабрика бросает OperationCanceledException (в кэш не пишется), а остальные ждущие по тому же ключу получают чужое исключение/отмену либо повторяют вызов (ещё запрос к лимитированному поставщику). Использовать отдельный токен фабрики (в HybridCache фабрике токен выдаётся самим кэшем).

### 9. [major] src/PriceService.cs:11-14 - ошибки поставщика и «нулевая» цена
Нет обработки исключений/таймаута `ISupplierClient`; нет политики ретраев с учётом лимита (п.7). Отрицательные/нулевые цены от поставщика не отсекаются - попадут в кэш на 5 минут и в финальную цену.

### 10. [minor] src/PriceService.cs:23 - округление `Math.Round(x, 2)`
По умолчанию `MidpointRounding.ToEven` (банковское), для денег в рознице обычно `AwayFromZero`; расхождения на 0.005 с ожиданиями бизнеса/бухгалтерии. Поведение по умолчанию сверено по знанию платформы, документацией этого прогона не проверялось.

### 11. [minor] src/PricesController.cs:12-14 - `discount` без значения = 0
`[FromQuery] int discount` без атрибута обязательности: отсутствие параметра даёт 0 и тихо проходит валидацию; невалидная строка даёт 400 от ApiController. Решить, обязателен ли параметр; диапазон проверяется в контроллере, а не в сервисе - `PriceService.GetFinalPriceAsync` публичен и принимает любой процент (отрицательная скидка поднимет цену).

### 12. [major] src/PricesController.cs:19-24 - Notify: URL из пользовательского ввода, результат игнорируется, нет авторизации
- `$"/price-changed/{sku}"`: `sku` не экранируется (`Uri.EscapeDataString`); значения вида `../admin` или со `?`/`#` меняют путь запроса к внутреннему сервису.
- Результат `PostAsync` не проверяется: сервис нотификаций вернул 500 - клиенту всё равно `Accepted()`, уведомление о смене цены теряется молча. Исключение сети уходит как 500.
- Эндпоинт POST без `[Authorize]` и без проверки, что цена действительно менялась: любой аноним может слать уведомления по любым SKU (спам внутреннему сервису).
- Относительный URI требует `BaseAddress` у именованного клиента "notifications"; регистрации в MR нет (п.5). Для незарегистрированного имени фабрика вернёт клиент без `BaseAddress` - `PostAsync` бросит InvalidOperationException (поведение по знанию платформы, документацией не сверялось - `unverifiable`).
- `HttpResponseMessage` не освобождается (`using`).
Комментарий про IHttpClientFactory (строка 18) по существу верен.

### 13. [minor] src/CatalogCache.cs:10 - лишняя обёртка и отсутствие опций
`async token => await repo.LoadPageAsync(page, token)` - лишний async/await; для страниц нет `HybridCacheEntryOptions` (срок жизни по умолчанию), нет проверки `page` (отрицательные/огромные номера создают неограниченное число ключей кэша - рост памяти по запросам клиента, если `page` приходит снаружи).

### 14. [minor] src/SupplierFeedParser.cs:20-23 - модель фида
`Deserialize` в `SupplierFeed` с `IReadOnlyList<SupplierItem>`: при `Items` = null/отсутствии для не-nullable-свойства record исключения нет - NRE позже; регистр имён свойств (`sku` в фиде против `Sku`) требует `PropertyNameCaseInsensitive` либо `JsonSerializerDefaults.Web` - без него поля останутся значениями по умолчанию без ошибки. Формат фида в MR не приложен - проверить по образцу.

### 15. [minor] MR целиком - нет тестов
Ни одного теста на скидку, парсер, кэш; п.1 и п.2 поймались бы любым юнит-тестом.
