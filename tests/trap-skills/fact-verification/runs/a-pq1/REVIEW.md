# Ревью MR (PR 312): Pricing.Api

Итого: **blocker - 3, major - 5, minor - 4** (всего 12).

Факты о библиотеках сверены по context7 (`/dotnet/docs`, `/dotnet/extensions`, DeepWiki по dotnet/extensions). Сборка и проба на версии проекта не запускались (запрещено условиями ревью), поэтому факты, которых документация не подтвердила, помечены `unverifiable`. Документация в context7 относится к актуальной ветке, а не точно к версиям из csproj (Hybrid 9.3.0, net9.0). Расхождения по версиям отдельно не проверялись.

## Blocker

### 1. `src/CatalogCache.cs:17` - метод `EvictByTagAsync` не существует
- **Что не так:** у `HybridCache` инвалидация по тегу называется `RemoveByTagAsync` (в документации есть `cache.RemoveByTagAsync("my-tag")` и перегрузка со списком тегов). `EvictByTagAsync` в API нет.
- **Чем кончится:** проект не компилируется, MR не собирается. Инвалидация кэша каталога по событию, заявленная в описании MR, не работает.
- **Сверка:** context7, `/dotnet/docs`, `core/extensions/caching.md`. На 9.3.0 отдельно не проверялось (`unverifiable` для этой версии).

### 2. `src/SupplierFeedParser.cs:10,14` - regex `//.*$` режет URL внутри строк
- **Что не так:** регулярка вырезает всё от `//` до конца строки, не различая комментарий и содержимое JSON-строки. `ImageUrl` по контракту (`SupplierFeedParser.cs:22`) - абсолютный адрес `https://cdn.supplier.example/img/123.png`. Он превращается в `"https:`, и вместе с ним пропадают закрывающая кавычка, запятая и остальное поле, если фид в одну строку.
- **Чем кончится:** `JsonException` на любом фиде с картинкой, то есть на штатном фиде. Либо, если JSON в одну строку, молча теряется хвост документа.
- **Связанное:** обоснование в комментарии `SupplierFeedParser.cs:8-9` («в System.Text.Json нет настройки, которая пропускает комментарии») неверно. Штатная замена - `JsonSerializerOptions { ReadCommentHandling = JsonCommentHandling.Skip }` (при необходимости ещё `AllowTrailingCommas`). Парсер сам разбирает комментарии и не трогает строки. Regex и `using System.Text.RegularExpressions` убрать.
- **Сверка:** context7, `/dotnet/docs`, `standard/serialization/system-text-json/invalid-json.md`.

### 3. `src/PriceService.cs:22` - целочисленное деление, скидка не применяется
- **Что не так:** `discountPercent / 100` - это `int / int`. Для скидки 1..99 результат 0, для 100 - 1.
- **Чем кончится:** клиент, запросивший скидку 10% или 50%, получает полную цену. Скидка 100% даёт 0. Финальная цена со скидкой, главная функция MR, не работает. Прямые финансовые потери или жалобы.
- **Исправление:** `basePrice * discountPercent / 100m`, либо `basePrice * (100 - discountPercent) / 100m`.

## Major

### 4. `src/PriceService.cs:7-15` - защиты от одновременных вызовов фабрики нет, ключ поставщика под угрозой бана
- **Что не так:** комментарий утверждает, что `IMemoryCache.GetOrCreateAsync` гарантирует единственный вызов фабрики при параллельных запросах. В документации такой гарантии для `IMemoryCache` нет. Эта гарантия (stampede protection) описана только для `HybridCache`. Утверждение автора: `unverifiable` по документации, пробу на версии проекта не запускал. По существу, расширение `GetOrCreate*` не берёт блокировку вокруг фабрики, и параллельные промахи по одному ключу вызывают фабрику несколько раз.
- **Чем кончится:** в момент истечения горячего SKU (TTL 5 минут) параллельные запросы идут к поставщику пачкой. Лимит поставщика (`Contracts.cs:5`) - 5 запросов в секунду на ключ, превышение банит ключ на час. Бан - это час без цен на всём сервисе.
- **Что сделать:** `HybridCache` (уже есть в проекте) либо `SemaphoreSlim` на ключ, плюс общий ограничитель исходящих запросов к поставщику (rate limiter 5 rps с запасом).

### 5. `src/PriceService.cs:11-15`, `src/PricesController.cs:12` - SKU из URL без валидации, кэш без лимита, поставщик без ограничителя
- **Что не так:** любой `sku` из публичного URL идёт ключом `price:{sku}` и запросом к поставщику. Проверки формата и существования нет. У `IMemoryCache` не задан `SizeLimit`. Ошибки поставщика (исключение в фабрике) не кэшируются, и каждый повторный запрос снова идёт в поставщика.
- **Чем кончится:** перебор произвольных SKU - это неограниченный рост кэша (память) и поток запросов к поставщику, то есть бан ключа на час. Сбои у поставщика усиливаются повторами.
- **Что сделать:** валидировать SKU по каталогу или формату, ограничивать размер кэша, кэшировать отрицательный результат на короткий срок, добавить rate limit на эндпоинт и к поставщику.

### 6. `src/PricesController.cs:22-24` - результат уведомления не проверяется
- **Что не так:** `PostAsync` вызывается без проверки статуса. Ответ не освобождается (`HttpResponseMessage` не `Dispose`). `HttpRequestException` и таймаут не обрабатываются. Всегда возвращается `Accepted()`.
- **Чем кончится:** сервис уведомлений ответил 4xx/5xx, а клиент получает 202, то есть уведомление о смене цены потеряно молча. При сетевой ошибке - необработанное исключение, 500.
- **Что сделать:** `EnsureSuccessStatusCode()` или явная обработка статуса, `using var response`, retry/очередь (outbox) для доставки уведомления.

### 7. В MR нет ни регистрации сервисов, ни подписки на событие
- **Что не так:** нет `Program.cs`/DI-композиции. Нигде не вызваны `AddHybridCache`, `AddMemoryCache`, `AddStackExchangeRedisCache`, `AddHttpClient("notifications")`, нет регистрации `PriceService`, `CatalogCache`, `ISupplierClient`, `ICatalogRepository`. Реализаций `ISupplierClient` и `ICatalogRepository` в MR нет. Обработчика события «каталог обновлён», который вызывает `CatalogCache.InvalidateAsync` (`CatalogCache.cs:14`), тоже нет. Пакет `StackExchangeRedis` подключён (`Pricing.Api.csproj:8`), но Redis нигде не настроен.
- **Чем кончится:** приложение не стартует (нет зависимостей в DI), `CreateClient("notifications")` без регистрации клиента даёт клиент без `BaseAddress`, и относительный URI `/price-changed/{sku}` падает. Инвалидация по событию из описания MR не подключена.
- **Примечание:** если всё это живёт в другом MR, это надо указать в описании. Иначе MR нельзя принять как рабочий.

### 8. `src/CatalogCache.cs:7-12,17` - инвалидация между инстансами `unverifiable`
- **Что не так:** при нескольких инстансах сервиса событие «каталог обновлён» придёт на один из них (или на каждый, как настроен брокер, из MR не видно). Документация описывает теги как логическую инвалидацию, синхронизируемую через L2 (при наличии `IDistributedCache`). Как именно инвалидируются L1 других узлов, документация, найденная через context7, не подтверждает. Статус: `unverifiable`.
- **Чем кончится:** без настроенного L2 (Redis в csproj есть, регистрации нет, см. п. 7) и без доставки события на каждый узел страницы каталога на части узлов остаются устаревшими до истечения TTL.
- **Что сделать:** сверить поведение инвалидации L1 между узлами на версии проекта, зафиксировать топологию доставки события.

## Minor

### 9. `src/PriceService.cs:23` - `Math.Round(discounted, 2)` округляет банковским способом
- **Что не так:** `Math.Round(decimal, int)` по умолчанию использует `MidpointRounding.ToEven` (в документации это названо Banker's rounding). Для цен ожидается обычное округление.
- **Чем кончится:** цены с половиной копейки округляются к чётному (2.345 → 2.34), расхождение с ожиданием бизнеса и бухгалтерии на копейку.
- **Что сделать:** `Math.Round(x, 2, MidpointRounding.AwayFromZero)`, если бизнес так считает (уточнить правило).

### 10. `src/PricesController.cs:23` - SKU подставляется в путь без экранирования
- **Что не так:** `$"/price-changed/{sku}"`. SKU пришёл из URL клиента и может содержать `%2f`, `..`, `?`.
- **Чем кончится:** SKU вида `a/../admin` меняет путь запроса к сервису уведомлений (path manipulation во внутренний сервис).
- **Что сделать:** `Uri.EscapeDataString(sku)` и валидация формата SKU (см. п. 5).

### 11. `src/CatalogCache.cs:7-9` - `page` не ограничен
- **Что не так:** номер страницы идёт в ключ `catalog:page:{page}` без проверки. Отрицательные и огромные значения принимаются.
- **Чем кончится:** произвольные номера страниц заполняют кэш пустыми или ошибочными результатами и ходят в репозиторий (БД).
- **Что сделать:** ограничить диапазон страниц на входе.

### 12. `src/SupplierFeedParser.cs:15-20` - `Items` может быть `null`, формат фида не проверяется
- **Что не так:** `SupplierFeed.Items` объявлен как ненулевой, но если в фиде нет поля `items`, значение будет `null` (аннотации nullable рантайм не проверяет). Имена полей без `JsonSerializerOptions` сопоставляются регистрозависимо с PascalCase (`Sku`, `Price`, `ImageUrl`), а формат фида поставщика в MR не зафиксирован. Нет проверки `Price >= 0`, `ImageUrl` - абсолютный https.
- **Чем кончится:** `NullReferenceException` далее по коду. Если поставщик отдаёт `camelCase`, поля останутся пустыми (`Sku = null`, `Price = 0`) без ошибки, и цены в кэше будут нулевыми.
- **Что сделать:** задать `PropertyNamingPolicy`/`PropertyNameCaseInsensitive` под реальный фид, добавить валидацию, `required`-свойства, тест на реальном образце фида.

## Проверено и замечаний нет
- `PricesController.cs:9-10`: утверждение «`ConfigureAwait(false)` не нужен, в ASP.NET Core нет SynchronizationContext» верно, замечаний нет.
- `PricesController.cs:18`: использование `IHttpClientFactory` вместо `new HttpClient()` правильное. Замечание только к отсутствию регистрации клиента (п. 7).
- `CatalogCache.cs:10`: `async token => await ...` приводится к `ValueTask<T>`-фабрике `HybridCache`, к сигнатуре замечаний нет. Сериализация `CatalogPage` на L2 (Redis) через `System.Text.Json` в MR не проверена (`unverifiable`).
