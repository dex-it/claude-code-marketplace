# Review: Pricing.Api (MR "Цены: базовая цена от поставщика с кэшем, финальная цена со скидкой, ...")

Ревью read-only, код не менялся. Дисциплина сверки фактов - по `fact-verification`: утверждения
о поведении фреймворка сверены с источником (см. пометки "Сверено").

## Находки

### 1. `PriceService.cs:9-17` (комментарий на `PriceService.cs:7-8`) - BLOCKER

Что не так: `cache.GetOrCreateAsync($"price:{sku}", async entry => {...})` использует
`Microsoft.Extensions.Caching.Memory.CacheExtensions.GetOrCreateAsync` (обёртка над `IMemoryCache`).
Комментарий утверждает: "GetOrCreateAsync гарантирует, что фабрика вызовется один раз на ключ даже
при параллельных запросах, поэтому отдельная блокировка вокруг поставщика не нужна." Это неверно:
данная перегрузка не держит лок на ключ - при параллельном промахе кэша фабрика выполняется в
каждом потоке независимо (issue dotnet/runtime #71581; официальная документация Microsoft Learn на
`CacheExtensions.GetOrCreateAsync` эту особенность не оговаривает вовсе). Стемпид-защита есть только
у `HybridCache.GetOrCreateAsync` (используется в этом же MR в `CatalogCache.cs`, но не здесь) -
"первый запрос на ключ выполняет фабрику, остальные ждут результат"; для `IMemoryCache` это не так
(проверено: WebSearch, dotnet/runtime issue #71581 + Microsoft Learn API-референс).

Чем кончится: `ISupplierClient` (`Contracts.cs:5`) документирует лимит поставщика - "не больше 5
запросов в секунду на ключ; превышение - бан ключа на час". При параллельных запросах на непрогретый
или истёкший (`AbsoluteExpirationRelativeToNow` 5 минут, `PriceService.cs:13`) ключ `price:{sku}`
каждый параллельный вызов уйдёт к поставщику напрямую, вместо одного - при заметной нагрузке это
превышает 5 rps на ключ и банит ключ поставщика на час, останавливая получение цен.

Severity: blocker.

### 2. `PriceService.cs:22` - BLOCKER

Что не так: `var discounted = basePrice - basePrice * (discountPercent / 100);` - `discountPercent`
и `100` оба `int`, `discountPercent / 100` - целочисленное деление с усечением. Для любого
`discountPercent` в диапазоне 1..99 (тело `discountPercent / 100` == 0) выражение вырождается в
`basePrice - basePrice * 0 = basePrice`.

Чем кончится: скидка не применяется вообще ни при каком значении `discount`, кроме 0 (нет скидки,
корректно по совпадению) и 100 (цена становится 0). "Финальная цена со скидкой" - заявленная в
описании MR фича - не работает ни для одного реального промежуточного значения скидки.

Severity: blocker.

### 3. `SupplierFeedParser.cs:8-10,14` (пример поля - `SupplierFeedParser.cs:22-23`) - BLOCKER

Что не так: комментарий-обоснование верен ("в System.Text.Json нет настройки, которая позволяет
пропускать комментарии"), но выбранное решение - `Regex(@"//.*$", Multiline)` - вырезает от первого
`//` до конца "строки" без учёта того, что `//` внутри JSON-строкового значения не комментарий.
`SupplierItem.ImageUrl` по документированному примеру (`SupplierFeedParser.cs:22-23`) содержит
`https://cdn.supplier.example/...` - `//` сразу после `https:`. Регекс срежет всё после этого `//`
до конца строки в исходном JSON. Для типичного фида поставщика (минифицированный JSON, весь документ
в одну "строку" для regex с `Multiline`, где `$`/`^` привязаны к `\n`) это вырезает остаток всего
документа после первого `ImageUrl`, а не только значение поля.

Чем кончится: `JsonSerializer.Deserialize<SupplierFeed>(clean)` получает обрубленный/невалидный JSON
- либо `JsonException` при разборе, либо (если срез случайно не ломает синтаксис) молча теряет
данные всех элементов фида после первого `ImageUrl`. Функция "разбор JSON-фида поставщика",
заявленная в MR, ломается на нормальных данных с полем `ImageUrl` - не на крайнем случае.

Severity: blocker.

### 4. `CatalogCache.cs:14-18` - MAJOR

Что не так: `InvalidateAsync` существует и комментарий утверждает, что его "вызывает обработчик
события 'каталог обновлён'". В ревьюируемом каталоге (весь MR) такого обработчика/подписчика нет -
ни одного вызова `InvalidateAsync` по всему дереву. Заявленная в описании MR фича "кэш страниц
каталога с инвалидацией по событию" в этом diff не подключена ни к какому источнику события.

Чем кончится: до появления недостающего подписчика на событие обновления каталога
`CatalogCache.GetPageAsync` продолжает отдавать закэшированные страницы каталога без какой-либо
инвалидации - страницы не обновляются вообще (пока не истечёт дефолтный TTL `HybridCache`, который
в вызове не задан явно).

Severity: major.

### 5. `PricesController.cs:19-25` - MAJOR

Что не так: `Notify` только пересылает POST во внешний клиент `"notifications"`
(`client.PostAsync($"/price-changed/{sku}", ...)`) и не трогает собственный кэш базовой цены -
`PriceService` хранит `price:{sku}` в `IMemoryCache` с TTL 5 минут (`PriceService.cs:11-15`), и
`Notify` его не инвалидирует.

Чем кончится: после того как этот сервис узнал об изменении цены (вызов `.../notify`) и переслал
уведомление дальше, его собственный `GetFinalPriceAsync`/`GetBasePriceAsync` для того же sku ещё до
5 минут продолжает отдавать старую (докэшированную) базовую цену - смысл уведомления о смене цены
для потребителей этого же API теряется на срок до TTL.

Severity: major.

### 6. `SupplierFeedParser.cs:15` - MINOR (условно)

Что не так: `JsonSerializer.Deserialize<SupplierFeed>(clean)` вызван без `JsonSerializerOptions` -
без `PropertyNameCaseInsensitive`. По умолчанию `System.Text.Json` матчит имена свойств
регистро-зависимо. Записи `SupplierFeed`/`SupplierItem` названы PascalCase (`Sku`, `Price`,
`ImageUrl`); если реальный фид поставщика присылает camelCase/lowercase ключи (типично для внешних
JSON API - в этих файлах формат ключей фида не зафиксирован, поэтому находка условная), несовпавшие
свойства получат значение по умолчанию (`null`/`0`) без исключения, то есть без сигнала об ошибке.

Чем кончится (если предположение о регистре верно): позиции фида с несовпавшим регистром ключей
приходят с обнулёнными полями (`Price = 0`, `ImageUrl = null`) молча, без наблюдаемой ошибки разбора.

Severity: minor (не подтверждено фактическим форматом фида в данном diff - риск, не доказанный дефект).

### 7. `PricesController.cs:19-23` - MINOR

Что не так: `Notify` не помечен атрибутом авторизации, и значение `sku` из маршрута подставляется в
исходящий путь без валидации/кодирования: `$"/price-changed/{sku}"`. `sku`, содержащий `/`, `..` или
другие спецсимволы, меняет фактический путь запроса к клиенту `"notifications"` относительно
намеченного `/price-changed/{sku}`.

Чем кончится: любой вызывающий эндпоинт может как минимум дёргать пересылку уведомлений с
произвольным содержимым в пути на backend `"notifications"` без проверки прав; при не полностью
предсказуемой обработке пути на стороне `notifications` это путь к переходу на другой маршрут этого
backend, а не только к своему `{sku}`.

Severity: minor.
