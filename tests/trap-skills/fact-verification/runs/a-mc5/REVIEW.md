# Ревью MR: Pricing.Api

Итого: blocker — 4, major — 3, minor — 4.

## Blocker

1. **src/PriceService.cs:22 — целочисленное деление.** `discountPercent / 100` — это `int / int`, результат 0 при любой скидке 0–99 и 1 только при 100. Итог: скидка не применяется (цена = базовая), а при 100% цена становится 0. Финальная цена неверна для всех клиентов. Исправление: `basePrice * discountPercent / 100m`.

2. **src/PriceService.cs:7-15 — комментарий неверен, защиты от stampede нет.** У `IMemoryCache.GetOrCreateAsync` нет гарантии однократного вызова фабрики: при промахе кэша параллельные запросы по одному sku все вызовут `supplier.GetPriceAsync`. У поставщика лимит 5 rps на ключ, превышение банит ключ на час (Contracts.cs:5). Итог: после истечения TTL популярного sku или при пике трафика ключ банят, цены не получить час. Нужны per-key `SemaphoreSlim`/`Lazy<Task>`, `HybridCache` (он уже подключён) или общий rate limiter перед клиентом.

3. **src/SupplierFeedParser.cs:10,14 — regex `//.*$` режет содержимое строк.** `ImageUrl` по контракту имеет вид `https://cdn.supplier.example/...` (строка 22), и регулярка отрежет всё от `//`, включая закрывающую кавычку и остаток строки. Итог: JSON невалиден, `JsonException` на любом фиде с URL, то есть почти всегда. Утверждение в комментарии (строки 8-9) неверно: System.Text.Json пропускает комментарии через `JsonSerializerOptions { ReadCommentHandling = JsonCommentHandling.Skip }` (или `JsonDocumentOptions.CommentHandling`). Regex нужно удалить.

4. **src/CatalogCache.cs:17 — `EvictByTagAsync` не существует.** У `HybridCache` метод называется `RemoveByTagAsync`. Итог: код не компилируется, инвалидация по событию не работает. Видимо, код не собирали.

## Major

5. **src/PricesController.cs:23-24 — результат уведомления не проверяется.** `PostAsync` возвращает ответ, статус не смотрим (нет `EnsureSuccessStatusCode`), ответ не освобождается. Итог: при 4xx/5xx от сервиса уведомлений клиент получает 202, уведомление молча теряется. Нужны проверка статуса, обработка исключений и, возможно, очередь/outbox вместо синхронного вызова.

6. **src/PricesController.cs:23 — `sku` вставляется в путь без экранирования.** Значение вроде `../admin` или со `?`/`#` меняет путь запроса к внутреннему сервису. Нужны `Uri.EscapeDataString(sku)` и валидация формата sku. Тот же `sku` без проверки идёт в ключ кэша и в запрос к поставщику.

7. **Нет Program.cs / регистрации DI.** Нигде не регистрируются `PriceService`, `CatalogCache`, `AddMemoryCache`, `AddHybridCache`, именованный клиент `"notifications"`, реализации `ISupplierClient` и `ICatalogRepository`. Итог: приложение не стартует, а `CreateClient("notifications")` без регистрации вернёт клиент без `BaseAddress`, и относительный URI даст `InvalidOperationException`. Пакет `Caching.StackExchangeRedis` подключён, но Redis нигде не настроен: L2-кэш не работает, а пакет лишний.

## Minor

8. **src/PriceService.cs:14 — `ct` первого запроса попадает в общую фабрику.** Если первый клиент отменит запрос, фабрика бросит `OperationCanceledException`, и все ожидающие этот же ключ получат ошибку. Для общего кэшируемого вызова токен отдельного запроса передавать не стоит.

9. **src/PricesController.cs:12 — `discount` без значения по умолчанию.** Без параметра он равен 0, то есть молча «без скидки». Лучше сделать параметр обязательным или явно задать значение по умолчанию. Тип `decimal` в ответе допустим, но `ActionResult<decimal>` отдаёт голое число — подумайте о DTO с валютой.

10. **src/CatalogCache.cs:9 — `page` не валидируется.** Произвольные значения (отрицательные, огромные) создают отдельные записи кэша; это путь к разрастанию кэша. Нужны границы, а при L2-кэше стоит проверить, что инвалидация по тегу работает между инстансами. Также гонка: загрузка, начатая до события, может записать устаревшую страницу уже после `RemoveByTagAsync`.

11. **src/SupplierFeedParser.cs:15,23 — nullable-контракт не соблюдается.** `Items`, `Sku`, `ImageUrl` могут быть `null` при отсутствии в JSON, хотя типы non-nullable. Десериализация регистрозависима: если поставщик отдаёт `sku`/`price` в нижнем регистре, получатся `null`/`0` без ошибки, то есть цена 0. Нужны `PropertyNameCaseInsensitive`/`[JsonPropertyName]`, `required` и валидация после разбора.
