# Сверка технического факта - чек-лист

Факт о библиотеке, платформе или стандарте, на котором держится вывод, сверяется с документацией версии из манифеста проекта. Каждый такой факт - вызов API в коде, утверждение в комментарии, описании MR, документе, логе, своей памяти - сверяется отдельно, до вывода; несверенное идёт в вывод статусом `unverifiable`, не фактом.

- Имя метода, опции или типа, вызванного в коде или названного в тексте
- Утверждение автора о поведении библиотеки
- Поведение, разное в версии проекта и в latest
- Разрешение нормы (RFC, спецификация, документация) - сверяется весь раздел: каждое условие разрешения и на какие случаи оно распространяется
- Отрицательный факт «такого API / настройки нет» - им обосновывают самописный обход; сверяется поиском штатной замены в документации версии

Источник по порядку: context7 (при отложенной загрузке MCP определение тула добирается через `ToolSearch` по его имени); официальная документация и changelog релиза - статья, блог, форум факт не подтверждают; нет ответа - проба на версии проекта в каталоге вне рабочего дерева или исходник по тегу релиза, в вывод - команда и результат либо файл и тег.
