## Описание MR: SW-260, проверки качества в CI

**Что сделано**
- **ruff:** `line-length = 88`, `target-version = "py312"`, `src = ["src", "tests"]`. Включены правила `E, F, W, I, B, UP`. Каталоги `data` и `artifacts` исключены.
- **mypy:** `files = ["src", "tests"]`, режим `strict`, `python_version = "3.12"`. Заданы `mypy_path = ["src"]` и `explicit_package_bases`, так что голый `mypy` проверяет оба каталога.
- **pytest:** `testpaths = ["tests"]`, `pythonpath = ["src"]`, `--strict-markers --strict-config`. Тесты находят пакет без установки проекта.
- **CI:** джобы `ruff-check`, `ruff-format` (`ruff format --check`), `mypy` (стадия `lint`) и `pytest` (стадия `test`). Образ `python:3.12-slim`.
- **Установка в CI:** `uv sync --only-group dev` ставит только dev-группу. Версии инструментов берутся из `pyproject.toml`. Torch, tensorflow и остальные тяжёлые зависимости не скачиваются.

**Что проверки, скорее всего, найдут в существующем коде** (код не менял)
- `src/shelfwatch/metrics.py:10-12`: `zip()` без `strict=` даст `B905` в `ruff check`. Это три вызова.
- Остальное я по чтению считаю чистым: сигнатуры типизированы, импорты упорядочены, строки короче 88 символов. Форматирование ruff format тоже, скорее всего, не заденет. Подтвердить это может только первый прогон в CI.

**На что обратить внимание**
- Лок-файла нет (это сказано в README), поэтому `uv sync` в CI каждый раз заново разрешает версии. Закреплены они только точными `==` в `pyproject.toml`.
- Когда в `src/` появятся модули, импортирующие torch, pandas и подобное, `mypy` в CI не найдёт эти пакеты, потому что они не установлены. Тогда нужно либо ставить основные зависимости в джобе `mypy`, либо добавить `ignore_missing_imports` для нужных библиотек. Сейчас код их не импортирует.
- `pytest-cov` и `pip-audit` из dev-группы я не подключал, потому что задача о них не просит.
