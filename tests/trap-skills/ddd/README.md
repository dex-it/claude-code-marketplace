([`inputs/SKILL-1.7.0.md`](inputs/SKILL-1.7.0.md)), эпик #291, группа 1.2 (#294). Промежуточная

засчитывания - общие для группы, в протоколе [solid](../solid/README.md#заход-группы-12-2026-10-05).

`runs/a2-*`; A3 - в [removed/microservices](../removed/microservices/README.md).

`a3-n1a`, `a3-n1b`; A2 в n1 прогнан один раз (`a2-n1a`) и по D-o не судился.

**Провалы контроля.** D-r: позиция подписки меняется через свой репозиторий мимо корня - контроль
критикует сохранение, но не репозиторий не-корня. D-d: история использования растёт внутри агрегата -
не поднята. D-f: `ItemsTotalMinor` поднят как «не пересчитан», не как лишнее хранимое производное;
`LastRenewalAttemptAt` без читателя не поднят. D-x: критикуют реализацию признака «цена
зафиксирована», не имя. D-v: `PspReference`, `PaymentEventCode` в `Invoice` не подняты. Названия
берут все шесть 2/2 в n1 и n2; D-v в n2 назван вместе с «полем без читателя» - исход (убрать имена
провайдера из домена) засчитан.

**Без кейса.** «Несколько агрегатов в одной транзакции» (вред - блокировки под нагрузкой),
«один `DbContext` на все контексты» (масштаб 50+ `DbSet`), «specification для простого запроса» (в
Billing нет specification-базы) - мини-проект ситуации не даёт. Без свидетельства единица не
снимается: названия остаются.

**Приманки и охват.** A1: PA, PH, PB, PE - не подняты blocker/major ни в одном наборе; O1, O2 - 2/2.
A2: PQ, PD, PL - не подняты; O1, O2 - 2/2. Единицы `clean-architecture` A2 (снятые по контролю) в n2
взяты 2/2 все 13 - сужения охвата нет.
