## Шаг 0: тип, дом, дубли

16 H3-ловушек, таблица «Выбор техники» и чек-лист из 9 пунктов, повторяющий ловушки названиями. Процедур нет.

- **Доказательство теста и норма узла coder.** Норма «каждый новый и изменённый тест показан красным, причина
  сверена, запись истекает с поведением» живёт в поле `red-run` узла coder dex-auto (`agents/coder.md`, схемы
  `feature.js`, `bugfix.js`) и в Red-gate тестописателей. Дом нормы - узел и агенты: узел берёт скиллы по суждению
  (P98: coder вызвал `test-design` в 4 из 15 прогонов), поэтому поле узла самодостаточно и из скилла не
  наследуется. Скилл держит технику показа для потребителей каталога, которые ссылаются на неё «по технике
  дома». Отсюда устройство кейсов: норма показа подаётся заданием так, как её получает тестописатель (TW), а
  судится техника - мутация целевой ветки, сверка причины, недетерминизм, срок записи (TW, TR, BR).
- **Порог «Negative >= 50%».** Источника нет ни в скилле, ни в стандартах, на которые опирается каталог: порог
  снимается без прогона (несверенный готовый ответ, эпик «Порядок на один скилл», шаг 4). Ситуацию - негативные
  классы входа - держит пункт EP, он судится кейсом TW.
- **Флак.** Дом - этот скилл (язык-независимый дизайн тестов; бриф потока). `bug-reproduction` «Воспроизведение
  завязано на недетерминизм» и «Флапающий принят за детерминированный баг» наследуют вердикт единицы td-flaky
  (кейсы TR-N, BR-N). `testability` `Guid.NewGuid()` - про шов в коде, а не про флак как явление: остаётся в
  `testability` (открыто до своего кейса, протокол [testability](../../testability/README.md)).
- **Граница с #298.** Механика Vitest/Jest (hoisting моков, API fake timers, конфиг окружения) - дом
  `ts-vitest-jest`; мини-проект на `node:test`, кейсы этой механики не задевают.
- **С `dotnet-testing-patterns` (#297).** Не тронут; пересечение - в «Открыто».

## Порядок прогонов (записан до первого прогона)

- Исполнитель и среда - README мини-проекта, раздел «Среда прогона».
- Контроль - без скилла, по 2 прогона на кейс; общий для четырёх скиллов группы. Если в кейсе хотя бы одна
  единица 1/2, кейс получает третий прогон контроля, и он судит все единицы кейса одинаково.
- Единица снимается, если её критерий выполнен во всех прогонах контроля. Единица с несколькими кейсами
  снимается, только если выполнена во всех.
- Редакция со скиллом - пункты в наименьшей форме по лестнице: первая ступень - названия. По 2 прогона на кейсы
  своих единиц и N0. Провал - ревизия по шагу 5 эпика, потолок три ревизии на кейс.
- Засчитывание - по ключу parcel: мутант убит, приёмка прошла, находка в месте ключа с последствием. Слово
  ловушки не требуется. Приманка: P провален, если исполнитель меняет код по ней или называет её дефектом
  blocker/major. O: назван дефект с последствием.

## Открыто

- td-pw: ситуация TW-D - три флага тарифа (8 комбинаций), где полный перебор дёшев. Пространство, в котором
  pairwise соблазнителен (десятки комбинаций для денег), кейс не создавал; единица снята по записанному ключу.
- Узлы dex-auto reviewer, coder, skeptic брали скилл по суждению (P94, P98); текстовых ссылок на него в
  `plugins/auto/` нет, поле `red-run` узла coder и схемы `feature.js`, `bugfix.js` самодостаточны и не тронуты.
  Поведение узлов без скилла здесь не мерилось - контроль меряет исполнителя sonnet на поручениях тестописателя и
  ревьюера.
- Граница с #298 (`ts-vitest-jest`): механика Vitest/Jest (hoisting моков, API fake timers, конфиг окружения) -
  дом `ts-vitest-jest`, кейсы её не задевали; язык-независимый дизайн тестов после снятия дома не имеет - по
  свидетельству он и не нужен.
- С `dotnet-testing-patterns` (#297): не тронут; его пересечение с техниками тест-дизайна и показом красным
  судит #297.
- `testability` `Guid.NewGuid()` - не флак, остаётся в `testability` до своего кейса.
- Порог `branch < 75%` в Coverage-gate тестописателей - вне предмета скилла, не тронут.
- Норма «тест со случайной природой сторожем не называется» (td-flaky) после снятия живёт только в определении
  «Сторож» (`docs/domain/domain-model.md`): ни `node-contract`, ни Red-gate, ни узел coder её не несут. По
  свидетельству так и должно быть (контроль 4/4 на TR-N и BR-N); кейс `tests/_cases/dev-red-run.md` R-05 назвал
  утрату носителя явно.
