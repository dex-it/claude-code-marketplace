# [снят] use-cases: сжатие по свидетельству, группа 3.1

Скилл `dex-skill-use-cases` 1.0.2 ([`inputs/SKILL-1.0.2.md`](inputs/SKILL-1.0.2.md)), эпик #291, группа 3.1
(#300). Итог - скилл снят: 8 ловушек - по контролю, «правила и числа в шаге» перенесена пунктом в
[use-case-quality](../../use-case-quality/README.md), «расширение без исхода» и «цель - действие интерфейса»
слиты с дублями там же, «сценарий списан с работающей системы» - дом в `usecase-analyst`. Строка в реестре
[`tests/README.md`](../../../README.md).

Вход - мини-проект [`_projects/rooms`](../../_projects/rooms/README.md), кейсы w3 (автор сценариев из BRD) и r3
(ревью переработанных сценариев); ключ там же, записан до прогонов. Среда, исполнитель и коды прогонов - в
протоколе [requirement-quality](../../requirement-quality/README.md): прогоны группы общие и лежат там
(`w3-c*`, `r3-c*` - контроль, `w3-s*`, `r3-s*` - с `use-case-quality` 2.0.0). Вердикт слепого судьи по
контролю r3 - [`JUDGE-control.md`](../../requirement-quality/JUDGE-control.md).

## Потребители

`usecase-analyst` (Skill tool в фазе письма: «норма письма сценария»), `requirements-reviewer` (норма класса
судьи на сценариях); бандлы `product-manager`, `system-analyst`; витрина `README.md`; кейс активации
`use-cases-in`; таблица узлов `docs/pipelines/analytics/ARCHITECTURE.md`. `usecase-analyst` теперь грузит
`use-case-quality` самоконтролем, `requirements-reviewer` - его же как норму класса.

## Тип единиц

12 H3-ловушек в трёх разделах. Процедур нет. Шесть единиц дублировали `use-case-quality` 1.0.0 (актор,
интерфейс, предусловие, терминал, трасса, заголовок) - дом дубля один, оракул.
