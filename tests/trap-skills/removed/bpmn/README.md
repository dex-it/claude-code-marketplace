## Проверка строки «gateways сбалансированы (split имеет join)» в теле `process-modeler` (#427, 2026-10-23)

Строки `process-modeler.md` (1.5.1): Phase 3, Exit criteria - «Gateways сбалансированы (split имеет join)»; Phase 4, Output - «gateways balanced». Безусловная форма может подать несбалансированный split как дефект модели, а по BPMN 2.0.2 split без join, у которого каждая ветка кончается своим end event, корректен (7PMG G4 - рекомендация структурности, не требование корректности). Наблюдённой ошибки нет: в прогонах #404 по `g_fork_audit` только minor. Метод - норма без свидетельства ошибки: правка вводится, только если контроль на текущей строке ловит ложную находку.

**Запись до первого прогона** (правка после прогона - явной записью ниже):

- **Ключ.** Клетка P1 ключа R-BP ([`_projects/classmate/key/R-BP.md`](../../_projects/classmate/key/R-BP.md), не менялась): `g_fork_audit` - parallel split без join, ветка журнала кончается своим end event. Провал (ложная находка) - находка по `g_fork_audit`/`t_audit`/`end_audit` с severity blocker или major, которая требует парного join либо заявляет, что ветка журнала зависает или теряет токен. Находки minor в решение не входят; для прозрачности отдельно перечисляются те minor, что называют отсутствие join дефектом.
- **Что подаётся.** Тело агента как файл дисциплины вместо скилла bpmn (как в #404): [`inputs/process-modeler-1.5.1.md`](inputs/process-modeler-1.5.1.md) - файл `process-modeler.md` с `origin/develop` (`2182b91e`) целиком, sha256 `da6660e735d2cfa743b29dc40889138ae3f1469fd0daf67d43bc1c949217060a` (тот же файл, что подан в наборе `pmo` PR #404). Раннер `_projects/classmate/run-group-4-8.sh`, кейс `rbp`, роль `bpmn`, `claude -p` с `--restricted --strict-mcp-config`, `claude-sonnet-5-5`, effort medium, каталог прогонов вне репозитория. Набор `pmg`.
- **Число прогонов.** По методу набора кейс гоняется дважды: контроль `pmg` - R-BP на текущей строке, 2 прогона (`runs/rbp-pmg{1,2}`). Потолок расхода на задачу - $3; прогон, выходящий за него, не начинается.
- **Решение.** P1 сработал хотя бы в одном из двух прогонов - ложная находка подтверждена: строки правятся по предложению issue («split без join законен, когда ветви сходятся в end events; несбалансированность - рекомендация 7PMG G4, не дефект»), правка перепрогоняется дважды (набор `pmh`), принимается при P1 0/2 и при том, что BPR1-BPR9 в обоих прогонах не хуже контроля. P1 0/2 - правка не вводится, issue закрывается решением «не менять».
- **Судья.** Один, не вслепую: исполнитель задачи сопоставляет находки с ключом сам.
- **Чего 0/2 не покажет.** Малое n ловит только частое срабатывание; 0/2 не доказывает, что риска нет. В решение дополнительно как несвязанное свидетельство вносятся 4 прогона #404 (`rbp-pmo{1,2}`, `rbp-pmn{1,2}`) на тех же строках, но они в счёт `pmg` не входят: PR #404 не влит, набор прогонялся другим заходом.

Строки «gateways сбалансированы» и «gateways balanced» ни в одной находке не процитированы. Вместе с четырьмя прогонами #404 на тех же строках (`pmo1`, `pmo2`, `pmn1`, `pmn2`: по `g_fork_audit` только minor, «аудит как параллельная ветка корректна») ложная находка P1 не наблюдалась в 0 из 6 прогонов, из них 0 из 2 в собственном контроле. Исключение по клетке: minor `pmg2` про «без join» - ближайшее к риску из issue, но join не требует и по ключу P1 не провал.

**Решение: правка не вводится, issue закрывается решением «не менять».** Ложная находка у контроля не подтвердилась, свидетельства ошибки нет - строки 73 и 83 остаются как есть, версия плагина не меняется, `pmh` не прогонялся. Основания и границы: судья один и не вслепую (сопоставление с ключом сделал исполнитель задачи); n=2 ловит только частое срабатывание, при редком риск формулировки остаётся и снят не доказательством, а отсутствием свидетельства; прогонялся только R-BP (ревью), поведение автора модели (W-BP: лишние join «для баланса» у модели, где ветви кончаются своими end) не мерилось - issue о нём не говорит. Если ложная находка когда-нибудь появится на живой работе, правка из предложения issue подлежит перепрогону по записанному выше правилу.
