## Решения оркестратора (2026-10-06, до прогонов смены 2)

- **P-gift.** Ключ записан до прогонов: «ложь: дефект», и после прогонов не переписывается. Правило различения
  (записано в ключе до прогонов со скиллом): ложная находка - поле записано пунктом списка расхождений или
  дефектом к исправлению; не ложная - наблюдение без требования правки. Судится одинаково во всех прогонах.
  Двусмысленность формулировки приманки (новое поле без отображения можно прочесть как функциональный пробел) -
  строка в «Открыто» для будущих кейсов, не основание менять ключ.
- **cd-format** - кейс CDT: формат `eta` сменился на одной стороне, веб молча разбирает в другую дату.
- **cd-schema** - `unverifiable`: кейс требует поручения, где исполнитель заводит общую схему контракта, - это
  предмет `api-specification` (#303, группа 4.2, не начата). Название остаётся, «Открыто» с адресом #303.

перечисление безвредных смен. Носитель без пункта - это контроль: скилл снят.

## Открыто

- **cd-schema без носителя - спорное решение оператора.** Решение оркестратора до прогонов: единица без кейса
  остаётся названием, «Открыто» с адресом #303. После прогонов название ухудшило приманки (5 против 4 из 24), а
  инвариант «итоговая редакция не хуже контроля» не допускает этого. Выбран инвариант с прогоном: единица снята с
  носителя, статус - `unverifiable`, не «снята по свидетельству». Предмет - фиксация контракта общей схемой - у
  `api-specification` и `interface-definition-openapi` (#303, группа 4.2): кейс, где исполнитель заводит схему, - там.
  Владельцу: вернуть название (и принять 5 против 4 как шум двух прогонов на ячейку) или оставить снятым.
- P-gift: формулировка приманки двусмысленна - новое поле без отображения читается и как функциональный пробел.
  Контроль поднимал его в CD 4/4. Для будущих кейсов: приманка «новое поле» - поле, которое пользователю показывать не
  нужно (служебное), иначе приманка судит толкование, а не дрейф.
- Пересечения с #303: `api-spec-quality` «Расширение перечня значений сочтено безопасным по умолчанию» (cd-enum),
  «Ломающее изменение выдано за совместимое», `api-specification` «Breaking change без новой версии» - судятся там.
- Сторона автора на стыке (`bug-fixer`, `incident-investigator` при правке на стыке) не мерилась: CD и CDT -
  поручение QA на стенде.
