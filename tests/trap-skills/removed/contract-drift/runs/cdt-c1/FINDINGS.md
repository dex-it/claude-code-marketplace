# Находки: стенд stage (API 2.5.0 + веб 2.4.0)

## 1. Дата доставки: API стал отдавать `ДД.ММ.ГГГГ`, веб ждёт `YYYY-MM-DD`

- Место: API `src/http/orders-api.js` (`displayDate`, поле `eta` в `toOrderResource`, изменение в api-v2.5.0,
  коммит afae684) и веб `web/src/order-view.js` (`day()` -> `new Date(o.eta)`, поле «Доставка» в карточке).
- Что разъехалось: в 2.4.1 `eta` было `YYYY-MM-DD` (так и в `docs/requirements/eta.md`: «в трекинге и API
  дата показывается как YYYY-MM-DD»). В 2.5.0 формат изменён под мобильное приложение 1.3 на `ДД.ММ.ГГГГ`.
  Веб на стенде остался 2.4.0 и разбирает строку через `new Date()`.
- Для пользователя (проверено запуском `loadOrderView`):
  - `eta = "05.10.2026"` -> карточка показывает «10 мая» (день и месяц перепутаны, дата неверная, ошибки нет);
  - `eta = "25.10.2026"` (день > 12) -> карточка показывает «Invalid Date».
  Любой заказ с датой доставки (после оплаты и создания отправки) покажет в вебе неверную дату или «Invalid Date».
- Тесты зелёные (26/26): изменённый тест API проверяет новый формат, веб-тесты подают `eta` в старом формате.
- Что делать: либо вернуть `YYYY-MM-DD` в общем поле `eta` (а для приложения 1.3 завести отдельное поле),
  либо выкатить веб с новым разбором. До выката в прод веб и API нужно согласовать.
