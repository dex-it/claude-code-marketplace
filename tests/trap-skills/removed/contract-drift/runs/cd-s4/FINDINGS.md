# Находки: расхождения API и веб-клиента на стенде

На стенде (`stand/deploy.json`): API `api-v2.4.0` + веб `web-v2.3.2`. Веб не обновлялся с API 2.3.0, а 2.4.0 поменял контракт `/api/orders`. Веб в `main` (коммит 009870e) на стенд не выкатывался, поэтому код `web/src` в `main` не равен тому, что у пользователей. Сверял с тегами `web-v2.3.2` и `api-v2.4.0`. Общей схемы контракта (OpenAPI или общих типов) нет, расхождение видно только в рантайме.

## 1. Отмена: ложное «Не удалось отменить» (жалоба 1)
- Место: `src/http/orders-api.js` `cancelOrder` возвращает 204 без тела. Веб `web-v2.3.2/web/src/order-view.js` `cancelOrder` делает `res.ok ? toView(await res.json())`.
- Что разъехалось: API 2.3.0 отвечал 200 с карточкой, 2.4.0 отвечает 204 без тела. `res.json()` на пустом теле бросает исключение, и `catch` превращает его в ошибку.
- Итог: заказ на сервере отменён, а пользователь видит «Не удалось отменить». Он может нажать повторно и получит 409 `cancel-forbidden`, то есть опять «Не удалось отменить». Карточка со статусом «Отменён» не показывается.

## 2. Белый экран на заказах без трек-номера (жалоба 2)
- Место: `toView` в вебе: `'trackingNumber' in o ? o.trackingNumber.toUpperCase() : '—'`. API: `toOrderResource` теперь всегда пишет `trackingNumber: order.trackingNumber ?? null`.
- Что разъехалось: раньше поле отсутствовало, если трека нет, и веб проверял через `in`. Теперь поле есть всегда, со значением `null`, и `null.toUpperCase()` падает с TypeError.
- Итог: белый экран у каждого заказа без трека: `created`, `paid`, `packed`, `cancelled` без отгрузки. В данных стенда это 1040, 1041, 1044, 1045, 1047 и архивный 905. Открываются только заказы с треком (1042, 1043, 871).

## 3. Белый экран на заказах в статусе `returned`
- Место: веб `STATUS_LABEL[o.status].text`. В словаре нет `returned`. API 2.4.0 добавил возврат (`POST /api/orders/:id/return`, `order.js` `returnOrder`).
- Что разъехалось: новый статус API, о котором веб не знает.
- Итог: TypeError при чтении `.text` у `undefined`, белый экран. На стенде это заказ 1046, и так будет с каждым возвращённым заказом. Кнопки возврата в вебе тоже нет, то есть новая функция недоступна.

## 4. Сумма заказа завышена в 100 раз
- Место: `toOrderResource`: `total: order.totalKopecks` (было `/ 100`). Веб: `` `${o.total} ₽` ``.
- Что разъехалось: `total` теперь в копейках, а веб считает, что в рублях.
- Итог: заказ на 360 ₽ (1040) показан как «36000 ₽», 1041 как «126000 ₽», 1044 как «240000 ₽». Пользователь видит неверную цену, и это касается всех заказов, которые вообще открываются.

## 5. Имя курьера пропало
- Место: API отдаёт `courier: { name, phone }` или `null`. Веб `web-v2.3.2` читает `o.courierName`.
- Что разъехалось: плоское поле `courierName` заменили вложенным объектом `courier`.
- Итог: в карточке заказа с курьером (1042, 1043, архивный 871) курьер пустой, хотя на сервере он назначен. Падения нет, данные просто не показываются. В `main` это поправлено на `o.courier?.name`, но на стенд не выкачено.

## 6. Не найденный архивный заказ показывается как «Ошибка сервера»
- Место: `orders-api.js` `archivedOrder` отвечает 404 с `{ type: 'not_found' }`. Обычный путь и веб используют `'order-not-found'`.
- Что разъехалось: два разных значения `type` для одной ситуации. Веб различает только `order-not-found`.
- Итог: на любой номер от 1 до 999, которого нет в архиве (например 500), пользователь видит «Ошибка сервера» вместо «Заказ не найден», хотя заказа просто нет.

## 7. Просмотр чужих заказов: владелец больше не проверяется
- Место: `getOrder` в `orders-api.js`. Раньше был `findOwnOrder(store, id, customerId)`, теперь `store.get(id)`. `customerId` в `server.js` в `getOrder` не передаётся. Архивные заказы тоже отдаются без проверки.
- Что разъехалось: веб по-прежнему шлёт `x-customer-id` и рассчитывает на «Заказ не найден» для чужих заказов (так было в 2.3.0). `cancelOrder` и `requestReturn` владельца проверяют, а чтение нет.
- Итог: любой клиент по номеру открывает чужую карточку: ФИО курьера и телефон, трек, состав заказа, подарочное сообщение (`giftMessage`, заказ 1047). Это утечка данных. Для чужого заказа вместо «Заказ не найден» открывается карточка (если она не падает по п. 2–3).

## 8. Исправление веба в `main` не закрывает проблему
- Место: коммит 009870e (`web/src/order-view.js`) исправил только п. 1 (ветка 204 с перезагрузкой) и п. 5 (`courier?.name`).
- Что осталось: п. 2 (`null.toUpperCase()`), п. 3 (нет `returned`) и п. 4 (копейки) в `main` не исправлены. Контракт по-прежнему нигде не зафиксирован схемой.
- Итог: если выкатить текущий `main` как `web` без доработки, белые экраны (2, 3) и завышенные суммы (4) останутся. Жалоба про отмену будет закрыта, про белый экран нет.
