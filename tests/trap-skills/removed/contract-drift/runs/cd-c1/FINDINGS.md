# Находки: расхождения API и веб-клиента на стенде

Стенд (`stand/deploy.json`): API 2.4.0 (`api-v2.4.0`) + веб 2.3.2 (`web-v2.3.2`). Анализ — по этим тегам, не по HEAD:
в HEAD веб уже частично исправлен (коммит 9bbfe85), но на стенд он не выкатан.
Корень: API 2.4.0 сменил контракт заказа, веб остался под 2.3.0.

## Две жалобы поддержки

### 1. «Не удалось отменить», хотя заказ отменён
- Место: `src/http/orders-api.js` `cancelOrder` (отдаёт `204` без тела) ↔ `web/src/order-view.js` `cancelOrder`.
- Разъехалось: в 2.3.0 отмена возвращала `200` + ресурс заказа, в 2.4.0 — `204` без тела. Веб делает `res.json()` на пустом теле, получает исключение, которое ловит `catch`.
- Итог: заказ отменён (и деньги возвращены, резерв снят), а пользователь видит «Не удалось отменить» и может нажимать снова. Повтор даёт 409 и то же сообщение. Карточка остаётся в старом статусе до перезагрузки.

### 2. Белый экран карточки
Две независимые причины, обе — необработанный `TypeError` в `toView`.
- **2a. `trackingNumber: null`.** API 2.4.0 всегда отдаёт поле (`trackingNumber ?? null`), раньше при отсутствии его не было. Веб проверяет `'trackingNumber' in o` и вызывает `null.toUpperCase()`.
  Затронуты все заказы без трека: `created`, `paid`, `packed`, `cancelled` без отправки (на стенде 1040, 1041, 1044, 1045, 1047, архивный 905). Открываются только заказы с треком.
- **2b. Статус `returned`.** Возврат добавлен в API 2.4.0 (`POST /return`, статус `returned`), в `STATUS_LABEL` веба его нет. `STATUS_LABEL[o.status].text` падает на `undefined`. Затронуты возвращённые заказы (1046) и любой заказ после запроса возврата.

## Остальные расхождения, видимые пользователю

### 3. Сумма в 100 раз больше
- `total` в API теперь в копейках (`totalKopecks`), было в рублях (`/100`). Веб выводит `${o.total} ₽`.
- Итог: заказ на 360 ₽ показан как «36000 ₽», на всех карточках, которые открываются. В HEAD веба не исправлено.

### 4. Курьер не отображается
- API: `courier: { name, phone } | null`, было плоское `courierName`. Веб 2.3.2 читает `o.courierName`.
- Итог: у отправленных и доставленных заказов (1042, 1043) имени курьера нет. Телефон курьера веб не показывает вовсе. В HEAD исправлено только имя.

### 5. «Ошибка сервера» вместо «Заказ не найден» для архива
- Место: `archivedOrder` в `src/http/orders-api.js` отдаёт `404 { type: 'not_found' }`, остальные места — `order-not-found`. Веб сравнивает только с `order-not-found`.
- Затронуты номера < 1000 (`archive.covers`), которых нет в архиве. Пользователь видит «Ошибка сервера» вместо «Заказ не найден». В HEAD не исправлено.

### 6. Подарочное сообщение не показывается
- API 2.4.0 добавил `giftMessage` (заказ 1047), веб его не знает.
- Итог: текст открытки в карточке не виден. Возможность возврата тоже не доступна из веба (нет кнопки/вызова `/return`): пользователь не может оформить возврат.

### 7. Чужие заказы читаются по номеру
- `getOrder` в 2.4.0 перестал принимать `customerId` и не проверяет владельца: в 2.3.0 чужой заказ давал 404, теперь `GET /api/orders/{id}` отдаёт любой заказ, включая архив. Веб по-прежнему шлёт `x-customer-id`, но он игнорируется.
- Итог: любой пользователь по подбору номера видит имя курьера, трек и состав чужих заказов. Отмена и возврат владельца проверяют, чтение — нет.
