# Находки: расхождения API и веб-клиента на стенде

На стенде (`stand/deploy.json`): API 2.4.0 (`api-v2.4.0`) и веб 2.3.2 (`web-v2.3.2`). Веб остался на контракте API 2.3.0.
Коммит `009870e` (курьер объектом, ответ 204 на отмену) лежит в репозитории, но на стенд не выкатывался.
Проверял по коду тега `web-v2.3.2` (`web/src/order-view.js`) и `src/http/orders-api.js`, `src/http/server.js`, `src/archive.js`, `data/*.json`.
Даже `009870e` закрывает только находки 1 и 5. Остальные в нём не исправлены.

## 1. Отмена: «Не удалось отменить» при успешной отмене (жалоба 1)
- Место: веб `cancelOrder` (`order-view.js`, `res.ok ? toView(await res.json())`); API `cancelOrder` в `orders-api.js` и `send()` в `server.js`.
- Что разъехалось: API 2.4.0 отвечает на `POST /api/orders/:id/cancel` статусом `204` без тела. Веб 2.3.2 ждёт `200` с JSON заказа. `res.json()` на пустом теле бросает исключение, `catch` возвращает ошибку.
- Итог: заказ на сервере уже `cancelled` и деньги возвращены, а пользователь видит «Не удалось отменить». Он может нажать повторно и получит `409`, то есть снова ту же ошибку. Карточка с новым статусом не показывается.

## 2. Белый экран у заказов без трек-номера (жалоба 2)
- Место: веб `toView`: `'trackingNumber' in o ? o.trackingNumber.toUpperCase() : '—'`; API `toOrderResource`: `trackingNumber: order.trackingNumber ?? null`.
- Что разъехалось: веб считает, что у заказа без трека поля нет. API 2.4.0 всегда присылает поле, для таких заказов со значением `null`. Проверка `in` проходит, `null.toUpperCase()` бросает `TypeError`.
- Итог: белый экран у заказов в статусах `created`, `paid`, `packed`, `cancelled`. В данных стенда это 1040, 1041, 1044, 1045, 1047. Открываются только заказы с треком: `shipped`, `delivered`, `returned`.

## 3. Белый экран у возвращённых заказов
- Место: веб `STATUS_LABEL` и `STATUS_LABEL[o.status].text`; API `returnOrder` в `src/order.js` и `POST /api/orders/:id/return`.
- Что разъехалось: API 2.4.0 ввёл статус `returned`. В словаре веба его нет, и `undefined.text` бросает `TypeError`.
- Итог: карточка любого возвращённого заказа (на стенде 1046) открывается белым экраном. Это самостоятельная причина, помимо находки 2. Если исправить только трек-номер, возвращённые заказы по-прежнему не откроются.

## 4. Сумма в копейках показывается как рубли
- Место: веб `total: \`${o.total} ₽\``; API `total: order.totalKopecks`.
- Что разъехалось: API 2.4.0 отдаёт сумму в копейках, веб подписывает её «₽» без деления на 100.
- Итог: пользователь видит сумму в 100 раз больше настоящей. Заказ на 360 ₽ (1040) показан как «36000 ₽», заказ 1044 на 2400 ₽ как «240000 ₽». Это видно в каждой карточке, которая открылась.

## 5. Курьер пропал из карточки
- Место: веб `courier: o.courierName`; API `courier: { name, phone } | null`.
- Что разъехалось: в 2.4.0 плоское поле `courierName` заменено объектом `courier`. Веб читает старое поле.
- Итог: у заказов с курьером (1042, 1043, 1046) поле «курьер» пустое (`undefined`). Имя и телефон курьера пользователь не видит.

## 6. Архивный заказ: «Ошибка сервера» вместо «Заказ не найден»
- Место: веб `loadOrderView` (`body.type === 'order-not-found'`); API `archivedOrder` в `orders-api.js`.
- Что разъехалось: для номеров меньше 1000 (архив), которых нет в архиве, API отвечает `404` с `type: 'not_found'`. Для остальных заказов тип `order-not-found`. Веб знает только второй вариант.
- Итог: при открытии отсутствующего архивного заказа пользователь видит «Ошибка сервера», как при сбое, а не «Заказ не найден».

## 7. Подарочное сообщение не показывается
- Место: API `toOrderResource` (`giftMessage`, добавляется, если оно задано); веб `toView` его не выводит.
- Что разъехалось: API отдаёт поле, веб его игнорирует. Расхождение в контракте незаметное.
- Итог: у заказов с подарочным сообщением (1047) текст пользователю не виден. Сейчас это скрыто находкой 2, потому что у 1047 нет трека и карточка открывается белым экраном. После исправления находки 2 дефект станет виден.

## Не относится к расхождению API и веба, замечено попутно
- `getOrder` (`orders-api.js`) не проверяет `x-customer-id`, и архивный путь тоже. Любой клиент может открыть чужой заказ по номеру. Отмена и возврат владельца проверяют.
