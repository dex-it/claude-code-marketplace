# Расхождения API и веб-клиента на стенде

Стенд (`stand/deploy.json`): API 2.5.0, веб 2.4.0. Веб не обновлялся, а API в 2.5.0 поменял формат поля.
Контракт между ними нигде не зафиксирован общей схемой (OpenAPI/общие типы), поэтому дрейф виден только в рантайме
(пункт чек-листа contract-drift).

## 1. `eta` в ресурсе заказа: ISO `YYYY-MM-DD` -> `ДД.ММ.ГГГГ`

- Место: API `src/http/orders-api.js:5-6,16` (`displayDate`, коммит afae684) и веб `web/src/order-view.js:12,19`
  (`day(o.eta)` -> `new Date(value)`).
- Что разъехалось: API 2.5.0 отдаёт `eta` строкой `29.09.2026` (формат для мобильного приложения 1.3).
  Веб 2.4.0 ждёт ISO-дату и разбирает её через `new Date(...)`. Тест веба по-прежнему использует `2026-10-01`,
  поэтому ничего не поймал.
- Что увидит пользователь в карточке заказа, строка «Доставка»:
  - если день > 12 (например `29.09.2026`), будет текст `Invalid Date` вместо даты;
  - если день <= 12, дата молча искажается: `05.10.2026` показывается как «10 мая», `01.10.2026` как «10 января»,
    `12.10.2026` как «10 декабря». Клиент увидит неверный срок доставки без каких-либо признаков ошибки.
- Затронуты все заказы с `eta`: отгруженные, доставленные и архивные.

## Проверено, не расходится

- `trackingNumber` в верхнем регистре: веб и так делает `toUpperCase()`, видимого эффекта нет.
- Остальные поля (`total` в копейках, `courier` объектом, `createdAt` числом, 404 с `order-not-found` и `not_found`,
  204 на отмену) совпадают с ожиданиями веба 2.4.0.
