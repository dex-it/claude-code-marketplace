# Находки: расхождения API и веб-клиента на стенде (stage)

Развёрнуто: API 2.5.0 (api-v2.5.0), веб 2.4.0 (web-v2.4.0). Версии разные, контракт общей схемой не зафиксирован
(OpenAPI/общие типы нет), поэтому дрейф виден только в рантайме.

## 1. Формат `eta` в ресурсе заказа: API 2.5.0 отдаёт «ДД.ММ.ГГГГ», веб 2.4.0 ждёт ISO

- Место: API — `src/http/orders-api.js`, `toOrderResource` (`eta: displayDate(order.eta)`, коммит afae684);
  веб — `web/src/order-view.js`, `day()` / `toView()` (`new Date(o.eta).toLocaleDateString(...)`).
- Что разъехалось: до 2.5.0 `eta` был `"2026-09-29"`. В 2.5.0 его переформатировали под мобильное приложение 1.3
  в `"29.09.2026"` (тест API тоже поправлен). Веб 2.4.0 не менялся и передаёт строку в `new Date(...)`;
  формат `29.09.2026` JS не разбирает, получается Invalid Date.
- Для пользователя: в карточке заказа в вебе у любого заказа с назначенной датой доставки (после отправки через
  Курьер-Сервис) в поле «Доставка» вместо даты будет «Invalid Date». Заказы без `eta` показывают «—», их это не касается.

## Проверено, расхождений нет

- `trackingNumber` в верхний регистр: веб и так делает `toUpperCase()`, вид не меняется.
- Статус `returned`, суммы в копейках, `courier` объектом, 404 (`order-not-found` / `not_found`), отмена с 204 — API и веб согласованы.
