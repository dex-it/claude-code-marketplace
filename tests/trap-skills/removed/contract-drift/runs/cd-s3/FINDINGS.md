# Находки: расхождения API и веб-клиента на стенде

Стенд (`stand/deploy.json`): API 2.4.0 (`api-v2.4.0`) + веб 2.3.2 (`web-v2.3.2`). Веб 2.3.2 написан под API 2.3.0.
В API 2.4.0 (коммит 4e8c002) контракт ответа изменили, веб не обновили. Общей схемы контракта (OpenAPI / общие типы)
нет, поэтому тесты API и веба зелёные по отдельности, а дрейф виден только в рантайме (дисциплина contract-drift).
Фикс в HEAD (009870e, «курьер из объекта, отмена 204») на стенд не выкачен: тег `web-v2.3.2` указывает на 11c9e6e.
Он же закрывает только п. 1 и 2, остальное остаётся.

## Причины двух жалоб

1. **Отмена: «Не удалось отменить», хотя заказ отменён.**
   Место: API `src/http/orders-api.js:50` (`cancelOrder` возвращает `204` без тела); веб 2.3.2 `web/src/order-view.js:37`
   (`res.ok ? toView(await res.json())`).
   Разъехалось: в 2.3.0 отмена отвечала `200` + JSON заказа, в 2.4.0 стала `204` без тела. Веб на `204` вызывает
   `res.json()`, получает исключение, и `catch` показывает ошибку.
   Итог: заказ отменён на сервере (деньги возвращены, резерв снят), а пользователь видит ошибку. Он нажимает повторно
   и получает `409 cancel-forbidden`, тоже «Не удалось отменить». Карточка не обновляется.

2. **Белый экран у части заказов.** Причин две, обе в `toView` (`web/src/order-view.js`):
   - **2a. `trackingNumber: null`.** API `toOrderResource` (`orders-api.js:12`) всегда отдаёт поле, `null` если трека нет.
     В 2.3.0 поле при отсутствии трека не отдавалось. Веб проверяет `'trackingNumber' in o` (стр. 16) и вызывает
     `null.toUpperCase()`, получая TypeError. Ломаются все заказы без трека: `created`, `paid`, `packed`,
     `cancelled` (в образце 1040, 1041, 1044, 1045, 1047, архивный 905). Заказы с треком открываются.
     Белый экран и после успешной отмены, если бы п. 1 не было.
   - **2b. Статус `returned`.** API 2.4.0 добавил возврат (`POST /api/orders/:id/return`, статус `returned`). В
     `STATUS_LABEL` веба (стр. 1-8) такого ключа нет, `STATUS_LABEL[o.status].text` падает с TypeError. Белый экран у
     всех возвращённых заказов (1046). Эндпоинт возврата в вебе не используется, но статус приходит в карточке.

## Остальные расхождения, видимые пользователю

3. **Сумма в 100 раз больше.** API `orders-api.js:10` отдаёт `total` в копейках (`order.totalKopecks`), в 2.3.0 были рубли
   (`/ 100`). Веб `order-view.js:14` пишет `` `${o.total} ₽` ``. Заказ на 360 ₽ покажется как «36000 ₽», на 2400 ₽ как
   «240000 ₽». Остаётся и в HEAD. Касается всех заказов, включая архивные.

4. **Курьер не показывается.** API 2.4.0 отдаёт `courier: { name, phone }` или `null`, а в 2.3.0 было `courierName`. Веб
   2.3.2 читает `o.courierName` (стр. 15), получает `undefined`, и у отгруженных и доставленных заказов (1042, 1043,
   архивный 871) строка курьера пустая. Телефон курьера веб не выводит вообще. Исправлено только чтением
   `o.courier?.name` в HEAD, на стенде этого нет.

5. **Архивные заказы (id < 1000): «Ошибка сервера» вместо «Заказ не найден».** Для заказа, которого нет в архиве, API
   (`orders-api.js:27`) отвечает `404 { type: 'not_found' }`, остальные 404 отдают `order-not-found`
   (`orders-api.js:3`). Веб (стр. 25) различает только `order-not-found`, поэтому для архивных id показывает «Ошибка
   сервера». Типы ошибок для одной ситуации разные, схемы нет.

6. **Заказ можно открыть чужой (регрессия API, видна в вебе).** `getOrder` в 2.4.0 (`orders-api.js:31-36`) больше не
   проверяет `x-customer-id`: в 2.3.0 заказ чужого клиента отдавал `404`. Теперь любой клиент видит чужую карточку
   (статус, сумма, курьер, трек, состав, `giftMessage`). Для архива (id < 1000) то же. Веб по-прежнему шлёт заголовок и
   ждёт, что чужой заказ будет «не найден». Отмена и возврат владельца проверяют, чтение нет.

7. **`giftMessage` не показывается.** API 2.4.0 добавил необязательное поле `giftMessage` (заказ 1047), веб его не знает.
   Пользователь не увидит подпись к подарку. Мелочь по сравнению с остальным, но это тоже расхождение, не
   зафиксированное в контракте.

## Что общее

Контракт нигде не зафиксирован: изменения 2.4.0 (204 на отмену, копейки, `courier` объектом, `null` вместо отсутствия
поля, статус `returned`, `not_found`) сделаны без общей схемы и без совместного выката. Тесты веба (`web/test`) гоняют
веб против собственных фикстур в формате 2.3.0 и дрейфа не ловят. Выкат на стенд идёт парой «API новее веба» без проверки
совместимости версий.
