# Расхождения API и веб-клиента на стенде (stage)

Развёрнуто: API 2.5.0 (`api-v2.5.0`), веб 2.4.0 (`web-v2.4.0`). Веб с API 2.5.0 не обновлялся.

## 1. Дата доставки (`eta`): API отдаёт `ДД.ММ.ГГГГ`, веб ждёт ISO `YYYY-MM-DD`

- **Место:** `src/http/orders-api.js` (`displayDate`, `toOrderResource`, поле `eta`, коммит afae684) и
  `web/src/order-view.js` (`day()` / `toView`, поле `delivery`). Затрагивает `GET /api/orders/:id`,
  в том числе архивные заказы (они идут через тот же `toOrderResource`).
- **Что разъехалось:** в 2.5.0 API стал отдавать `eta` строкой `29.09.2026` (под мобильное приложение 1.3).
  Раньше было `2026-09-29`, веб 2.4.0 написан под это: `new Date(o.eta)` с форматированием `toLocaleDateString`.
  `new Date('29.09.2026')` - Invalid Date. Проверил в node: в карточке выводится «Invalid Date».
  Тест API в 2.5.0 поправили под новый формат, веб-тест остался на ISO и не ловит проблему.
  Контракт тихо поменяли без повышения версии веба.
- **Для пользователя:** в карточке любого заказа с датой доставки (отгруженные, доставленные, архивные)
  в поле «Доставка» вместо «1 октября» показывается «Invalid Date». Заказы без `eta` (`—`) не затронуты.
