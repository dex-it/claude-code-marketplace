# Расхождения API 2.5.0 и веба 2.4.0 на стенде (stage)

## 1. `eta` в ресурсе заказа: формат даты

- **Место:** API `src/http/orders-api.js:5-17` (`displayDate`, `toOrderResource`, коммит afae684) и веб `web/src/order-view.js` (`day()`, `toView`, поле `delivery`).
- **Что разъехалось:** API 2.5.0 отдаёт `eta` строкой `ДД.ММ.ГГГГ` (например `16.06.2026`), под мобильное приложение 1.3. Раньше (2.4.1) было ISO `ГГГГ-ММ-ДД`. Веб 2.4.0 разбирает значение через `new Date(o.eta)`, рассчитывая на ISO.
- **Чем кончится для пользователя:** в карточке заказа в поле «Доставка» вместо даты будет «Invalid Date». Это для дней больше 12. Для дней 1–12 дата разберётся как `ММ.ДД`, и покажется неверная дата. Например, `05.10.2026` превратится в «10 мая» вместо «5 октября». Затронуты все заказы с рассчитанным сроком доставки. Менять контракт для веба нужно согласованно (веб 2.4.0 нужно обновить, либо отдавать ISO в API и форматировать на клиенте мобильного приложения).

Остальные поля (`total` в копейках, `courier` объектом, `createdAt` числом, статус `returned`, отмена с 204, 404 `order-not-found`/`not_found`, `trackingNumber` в верхнем регистре) с вебом согласованы.
