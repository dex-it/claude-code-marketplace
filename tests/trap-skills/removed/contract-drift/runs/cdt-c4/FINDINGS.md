# Находки: стенд stage (API 2.5.0 + веб 2.4.0)

## 1. Дата доставки (`eta`) в формате ДД.ММ.ГГГГ ломает карточку заказа в вебе

- **Место:** API `src/http/orders-api.js` (`displayDate`, `toOrderResource`, коммит 2.5.0) и веб `web/src/order-view.js` (`day()` в `toView`).
- **Что разъехалось:** API 2.5.0 отдаёт `eta` как `"29.09.2026"` (было `"2026-09-29"`). Веб 2.4.0 разбирает значение через `new Date(o.eta)`, а ожидает ISO `YYYY-MM-DD` (см. `web/test/order-view.test.js`). Строка `ДД.ММ.ГГГГ` не разбирается, получается Invalid Date. Контракт тоже нарушен: `docs/requirements/eta.md` требует «в трекинге и API дата показывается как `YYYY-MM-DD`». Формат поменяли ради мобильного приложения 1.3, а веб не обновили и не проверили. Затронуты все заказы с датой доставки (после оплаты, включая архивные).
- **Что увидит пользователь:** в поле «Доставка» в карточке заказа вместо даты будет «Invalid Date». Сломается ожидаемая дата доставки для всех заказов, у которых она есть.
- **Что делать:** вернуть ISO в поле `eta`, а строку для приложения отдавать отдельным полем. Либо выкатывать вместе с вебом, который понимает новый формат.

## Проверено, расхождений нет

- `trackingNumber` в верхнем регистре: веб и так приводит трек к верхнему регистру, вид не меняется.
- Суммы в копейках, статус `returned`, курьер объектом, отмена с ответом 204 и архивный 404 (`not_found`) веб обрабатывает.
