# Находки: расхождения API и веб-клиента на стенде

Стенд (stand/deploy.json): API 2.5.0, веб-клиент 2.4.0. Общей схемы контракта (OpenAPI/общие типы) нет, поэтому расхождение видно только в рантайме.

## 1. Формат даты доставки `eta`: API отдаёт `ДД.ММ.ГГГГ`, веб ждёт ISO

- Место: `src/http/orders-api.js:4,16` (`displayDate`, поле `eta`) и `web/src/order-view.js:11,20` (`day(o.eta)` → `new Date(value)`).
- Что разъехалось: API 2.5.0 отдаёт `eta` строкой `29.09.2026`, под мобильное приложение 1.3. Веб 2.4.0 и `docs/requirements/eta.md` ожидают `YYYY-MM-DD`. `new Date('ДД.ММ.ГГГГ')` в JS читает строку как `ММ.ДД.ГГГГ`.
- Чем кончится для пользователя:
  - день > 12 (например `25.10.2026`): в карточке заказа «Invalid Date»;
  - день ≤ 12 (например `05.10.2026`): молча неверная дата, «10 мая» вместо 5 октября;
  - заказы без `eta` не затронуты, там «—».
- Проверено запуском в node: `05.10.2026` → 10 мая, `12.10.2026` → 10 декабря, `25.10.2026` → Invalid Date.

## 2. Поле `giftMessage` приходит из API, но веб-клиент его не показывает

- Место: `src/http/orders-api.js:19` и `web/src/order-view.js:14-22` (`toView`).
- Что разъехалось: API отдаёт `giftMessage` для заказов с подарочным сообщением, например заказ в `data/orders-sample.json:169`. `toView` собирает карточку из фиксированного набора полей, `giftMessage` в нём нет.
- Чем кончится для пользователя: подарочное сообщение не показывается. Покупатель не может проверить, что текст сохранён. Получатель подарка его не увидит.
