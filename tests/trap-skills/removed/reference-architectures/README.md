## Шаг 0

- **Нужен ли скилл.** Прогон активации 23.08.2026 ([`tests/README.md`](../../../README.md), «Метод: прогон
  активации») показал: `reference-architectures` стабильно проигрывает `superpowers:brainstorming`, правка поля
  молчание не сняла. Маршрут к потребителю при этом был: императивная загрузка Skill tool в Phase 4 `architect` и
  `architect-dotnet` (условие - область feed / chat / payment / search / notifications / rate-limiter) и у
  `diagram-creator`. Проигрыш активации маршрут не отменяет - поэтому скилл пошёл в кейсы; снят по контролю.
- **Дубль rate-limiter.** Краевой всплеск fixed window на стыке окон - дом `redis` (#304, реализация
  `INCR` + `EXPIRE`). RA6 судился как выбор алгоритма по требованию к всплескам (ровный поток к хранилищу `/export`
  против допустимых всплесков лайков); кейс от стыка окон не зависит.
- **Дубли внутри группы.** RA5 (уведомления, fan-out при горячих авторах) = RA1 (лента, гибрид для крупных авторов):
  одна ситуация fan-out при длинном хвосте подписчиков, дом RA1. RA3 (платежи) раскладывается: (a) уровень
  консистентности по операции = CC3, (d) saga с компенсацией = CC8 - дома в cap-consistency; свои клетки RA3 -
  (b) ключ идемпотентности записи, (c) outbox.
- **Порог без источника** (RA5 «90% users <1K followers») в пункт не писался бы.
