## Описание MR (SW-262: модель оттока магазинов)

**Что сделано**
- Обучение и сравнение двух моделей: случайного леса и XGBoost.
- `train()` читает `data/accounts.parquet`, сохраняет лучшую модель в `artifacts/churn_model.joblib` и печатает цифру для отчёта.
- `predict_next_month(df, model=None) -> pd.Series` возвращает вероятность оттока по каждому `store_id`. Для каждого магазина берётся его последний срез. Если модель не передана, она загружается из сохранённого файла.

**Решения**
- **Дисбаланс (отток около 5%).** Лес обучается с `class_weight="balanced_subsample"`, XGBoost — с `scale_pos_weight = n_neg / n_pos`, посчитанным по обучающей выборке.
- **Метрика.** Для отчёта берётся PR-AUC (average precision) на тесте, рядом печатается доля оттока в тесте как уровень случайной модели. Accuracy не используется: константное «не уйдёт» даёт около 95%.
- **Разбиение по месяцам среза.** Train, valid и test идут в хронологическом порядке (по умолчанию 60/20/20% месяцев). У магазина много срезов, поэтому случайное разбиение строк завысило бы качество.
- **Выбор модели.** Лучшая модель выбирается по valid. Тест считается один раз, для выбранной модели, после обучения на train+valid. Финальная модель обучается на всех данных.
- **Признаки.** Берутся `tenure_months`, `revenue`, `n_tickets` и one-hot от `plan`. `account_id` и `store_id` в признаки не входят.
- **Пропуски в `n_tickets`.** Пропуск означает «обращений не было», поэтому заполняется нулём плюс флаг пропуска. Так делается для обеих моделей, чтобы они сравнивались на одинаковых входах.
- **Воспроизводимость.** Везде `random_state=0`.

**Тесты** (на синтетических данных)
- Разбиение по времени не пересекается.
- Веса классов выставлены в обеих моделях.
- Ошибка, если в обучающей выборке нет одного из классов.
- PR-AUC на тесте больше чем вдвое выше доли оттока.
- В `predict_next_month` ровно одна вероятность на магазин, значения в [0, 1], и используется именно последний срез независимо от порядка строк.

**Допущения, которые стоит проверить**
- Я считал, что `churned = 1` в строке среза означает уход в следующем месяце. В `docs/data.md` это не сказано.
- `predict_next_month` считает и магазины, которые уже ушли. При необходимости их можно отфильтровать.
- Гиперпараметры взяты по умолчанию («от балды»), без подбора через Optuna.
- Тесты и код нужно прогнать в CI. В частности, порог `2 * base_rate` в тесте подобран на глаз.
