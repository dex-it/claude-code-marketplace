## Описание MR: SW-262, модель оттока магазинов

**Что сделано**
- `evaluate(df) -> ChurnReport` обучает случайный лес и XGBoost, выбирает лучшую модель по PR-AUC на valid и возвращает её PR-AUC на тесте. Это и есть одна цифра для отчёта. В отчёте также лежат PR-AUC обеих моделей на valid и доля оттока в тесте.
- `predict_next_month(df) -> pd.Series` возвращает вероятность оттока по каждому `store_id` для строк последнего среза. Для этого модель выбранного типа заново обучается на всех размеченных срезах.

**Решения**
- **Метрика.** PR-AUC, потому что отток редкий (5%). Для сравнения в отчёте есть доля оттока: у случайной модели PR-AUC примерно равен ей.
- **Дисбаланс классов.** У леса стоит `class_weight="balanced_subsample"`, у XGBoost `scale_pos_weight = neg/pos` по train.
- **Ранняя остановка XGBoost.** `n_estimators=1000` и `early_stopping_rounds=30` по отдельной выборке `es`. Она не совпадает ни с valid, ни с test, поэтому выбор модели и итоговая цифра не завышены.
- **Разбиение.** Тест — последние 3 размеченных среза, как в проде (прошлое → будущее). Остальное делится по `store_id` через `GroupShuffleSplit` на train, es и valid: у магазина несколько срезов, и без группировки они утекали бы между выборками.
- **Признаки.** `tenure_months`, `revenue`, `n_tickets` (пропуск заменён на 0 плюс флаг `no_tickets`) и one-hot по `plan`. `store_id` и `account_id` не берутся: это идентификаторы, модель их только запомнит.

**Допущения, которые стоит проверить**
- Я исходил из того, что `churned` в строке означает отток в месяце после этого среза. Поэтому последний срез идёт только на вход прогноза, а не в обучение. Если разметка другая, нужно поменять `_split` и `predict_next_month`.
- `predict_next_month(df)` принимает только датафрейм, поэтому внутри заново запускает `evaluate` и обучение. Для продакшена лучше сохранять обученную модель, но в задаче этого нет.
- Гиперпараметры взяты разумными по умолчанию и не подбирались. Подбор остаётся для `shelfwatch.tune`.

**Тесты** на синтетических данных (400 магазинов, 10 месяцев):
- в разбиении нет пересечений магазинов, тест позже train, а последний срез в нём отсутствует;
- PR-AUC выбранной модели на тесте выше доли оттока;
- прогноз содержит одну вероятность на магазин, значения лежат в [0, 1].

**Не проверено:** запуск `pytest`, ruff и mypy. Порог теста «PR-AUC выше base rate» подобран по синтетике на глаз и может потребовать правки после первого запуска.
