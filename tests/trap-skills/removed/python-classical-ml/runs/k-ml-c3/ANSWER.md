## Описание MR

**SW-262: модель оттока магазинов (случайный лес и XGBoost)**

Что сделано:
- `train_and_evaluate(df)` обучает обе модели, выбирает лучшую и возвращает `ChurnResult`. В нём лежат имя лучшей модели, PR-AUC на valid по каждой модели, итоговая цифра `test_pr_auc` и доля оттока в test для сравнения. Также в результате есть модель, дообученная на всех данных.
- `predict_next_month(df, model=None)` возвращает `pd.Series` с вероятностью оттока, индекс — `store_id`, по одной строке на магазин (по его последнему срезу). Если `model` не передать, она обучится на `df`, а для этого нужен столбец `churned`. Для регулярного прогноза лучше передавать готовую `ChurnResult.model`.

Решения:
- **Разбиение по времени.** Последние 3 месяца идут в test, предыдущие 3 — в valid, остальное — в train. У магазина несколько срезов, и случайное разбиение подмешало бы будущее и те же магазины в train. Модель выбирается по valid, а test используется только для итоговой цифры.
- **Метрика для руководства — PR-AUC на test.** Отток составляет 5%, поэтому accuracy и ROC-AUC здесь вводят в заблуждение. Случайная модель даёт PR-AUC около 0,05, и это значение показывается рядом с цифрой.
- **Признаки.** Это `tenure_months`, `revenue`, `plan` (one-hot), `n_tickets` и флаг `no_tickets`. Пропуск в `n_tickets` означает, что обращений не было: пропуск заполняется нулём, а флаг сохраняет эту информацию. Ещё есть `revenue_change` относительно предыдущего среза магазина, он считается только по прошлому.
- **`store_id` не признак.** Около 1 200 значений, модель запомнила бы магазины. Он нужен только для расчёта лагов.
- **Классы не перевзвешиваются.** Нужны вероятности, а не только ранжирование.

Тесты на синтетических данных проверяют:
- порядок и непересечение частей разбиения и ошибку при слишком малом числе месяцев;
- отсутствие NaN в признаках и корректность флага `no_tickets`;
- что лаг по выручке не зависит от порядка строк и не заглядывает вперёд;
- что `test_pr_auc` выше доли оттока;
- что прогноз содержит одну вероятность из [0, 1] на магазин.

Допущения, которые стоит подтвердить:
- `churned = 1` в строке я трактовал как «магазин ушёл в месяц после `snapshot`». В `docs/data.md` это не описано. Если смысл другой, меняется постановка метки и `predict_next_month`.
- Магазины, которые уже ушли, остаются в прогнозе, если их последний срез есть в данных. При необходимости их нужно отфильтровать.
