## Описание MR: SW-262, модель оттока магазинов

**Что сделано**
- `evaluate(df)` сравнивает случайный лес и XGBoost и возвращает `Report`.
- Цифра для руководства — `test_pr_auc`, то есть PR-AUC лучшей модели на отложенных последних месяцах. Рядом лежат ROC-AUC, доля оттока на тесте (это PR-AUC случайной модели) и PR-AUC обеих моделей на валидации.
- `predict_next_month(df) -> pd.Series` возвращает вероятность оттока на следующий месяц. Индекс — `store_id`.
- Предсказание строится по строкам последнего месяца данных. Уже ушедшие магазины (`churned == 1`) в результат не попадают, как и магазины без строки в последнем месяце.
- Перед предсказанием модель выбирается через `evaluate` и обучается на всех размеченных срезах.
- Запуск `python -m shelfwatch.churn_model` печатает отчёт по `data/accounts.parquet`.

**Решения**
- **Разбиение по времени, а не случайное.** У магазина несколько срезов в разные месяцы, и соседние месяцы почти одинаковы. При случайном разбиении оценка была бы завышена. По умолчанию последние 3 месяца идут в тест, предыдущие 3 — в валидацию, остальное — в обучение.
- **Выбор модели без участия теста.** Лучшая модель выбирается по валидации, затем переобучается на обучении вместе с валидацией и один раз оценивается на тесте.
- **Метрика — PR-AUC.** Отток около 5%, поэтому accuracy не подходит. Разбалансировка учтена через `class_weight="balanced_subsample"` у леса и `scale_pos_weight` у XGBoost.
- **Пропуски `n_tickets`.** Пустое значение значит, что обращений не было. Оно заменяется на 0, плюс добавлен флаг `no_tickets`.
- **Идентификаторы не используются как признаки.** Это `account_id` и `store_id`. План кодируется one-hot с набором столбцов, зафиксированным по обучающим данным.
- **Тесты на синтетике.** Проверяют признаки, то, что PR-AUC выше случайного, ошибку при нехватке месяцев и состав индекса в `predict_next_month`.

**Допущения и ограничения**
- `churned` в строке среза я трактовал как «ушёл после этого среза». Это нужно подтвердить с владельцем данных: от этого зависит, исключать ли `churned == 1` в `predict_next_month`.
- Гиперпараметры взяты по умолчанию и не тюнились, это задача для `shelfwatch.tune`.
- Лаговых признаков по магазину (динамика выручки и обращений) пока нет, их можно добавить следующим шагом.
- Тест на синтетике `test_evaluate_beats_random` случайный, но с фиксированным seed. Если он окажется нестабильным на реальном запуске, надо увеличить размер выборки.
