## Описание MR

**SW-262: модель оттока магазинов (случайный лес vs XGBoost)**

**Что сделано**
- `build_features` строит признаки:
  - текущие `tenure_months`, `revenue`, `n_tickets`, флаг `no_tickets` и one-hot по `plan`;
  - лаги по магазину: `prev_revenue`, `revenue_change`, `prev_tickets`, `tickets_change`, `months_since_prev`, `n_snapshots`.
- `evaluate(df)` сравнивает обе модели на валидации, выбирает лучшую и оценивает её на тесте.
- `predict_next_month(df, model=None) -> pd.Series` возвращает вероятность оттока на следующий месяц с индексом `store_id`. Без `model` она сама выбирает лучшую модель и обучает её на всех размеченных строках.
- Цифра для руководства — `test_average_precision` (PR-AUC выбранной модели на последних 3 месяцах). Рядом выводится доля оттока в тесте как ориентир. Случайная модель получила бы AP около 0,05.

**Решения**
- **Разбиение по времени, не случайное.** У магазина много срезов, случайный сплит подмешал бы будущее и соседние срезы того же магазина в обучение. Период делится на train, val (3 мес.) и test (3 мес.), перед val и test оставлен зазор в 1 месяц.
- **Выбор модели не на тесте.** Модель выбирается по val, переобучается на train+val и один раз оценивается на test.
- **Метрика AP, а не accuracy.** При оттоке 5% константа даёт accuracy 0,95.
- **Дисбаланс** учтён весами классов (`class_weight` у леса, `scale_pos_weight` у XGBoost), без SMOTE.
- **`n_tickets`.** Пустое значение трактуется как 0 обращений (магазин не обращался), плюс отдельный флаг.
- **`store_id` не признак.** Это около 1 200 значений на 30 000 строк, то есть запоминание магазинов, которое не переносится на новые. Вместо него используется история магазина по прошлым срезам, без заглядывания в будущее.
- **Лаги считаются по всему `df`,** поэтому граница выборки не обрезает историю.

**Допущения, которые нужно подтвердить**
- `churned` в строке среза — это отток в месяце после этого среза. В `docs/data.md` это не сказано явно. Если метка относится к самому месяцу среза, зазор и сдвиг прогноза нужно пересмотреть.
- Прогноз строится для магазинов, которые есть в последнем срезе. Строки последнего среза без метки в обучение не попадают.
- `account_id` не используется; «магазин» везде означает `store_id`.

**Тесты** на синтетике проверяют:
- лаги только из прошлого и сохранение индекса;
- обработку пустых `n_tickets`;
- порядок и зазор временного разбиения, а также ошибку на слишком короткой истории;
- что `evaluate` выбирает модель с лучшим AP на val и что AP на тесте выше доли оттока;
- формат и диапазон `predict_next_month`;
- ошибку, если в обучении только один класс.
