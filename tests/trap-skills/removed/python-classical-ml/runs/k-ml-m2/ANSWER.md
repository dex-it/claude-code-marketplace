## Описание MR
**SW-262: модель оттока магазинов (случайный лес vs XGBoost)**

Что сделано:
- `train_and_evaluate(df)` обучает обе модели, выбирает лучшую по PR-AUC на валидации и возвращает `ChurnReport`. В нём одна цифра для отчёта (`test_pr_auc`), метрики обеих моделей на валидации и доля оттока в тесте.
- `predict_next_month(df, model=None) -> pd.Series` возвращает вероятность оттока по каждому магазину. Индекс — `store_id`, берётся последний срез магазина. Если модель не передана, она обучается на `df`.
- Запуск `python -m shelfwatch.churn_model` читает `data/accounts.parquet` и печатает результат.

Решения:
- **Деление по магазинам.** У магазина несколько срезов в разные месяцы, и соседние месяцы почти одинаковы. Случайное деление по строкам утекло бы между обучением и проверкой и завысило бы качество. Выборки: fit / stop / val / test, магазин целиком в одной части.
- **Редкий класс (5%).** У случайного леса стоит `class_weight="balanced_subsample"`, у XGBoost — `scale_pos_weight = neg/pos`.
- **Ранняя остановка XGBoost.** `n_estimators=1000` и `early_stopping_rounds=50` по отдельной выборке stop. Валидация, по которой выбираем модель, и тест в подборе числа деревьев не участвуют, поэтому сравнение моделей честное.
- **Метрика.** PR-AUC вместо accuracy и ROC-AUC. Случайная модель даёт около 0.05, эту базу выводим рядом с цифрой.
- **Признаки.** Пустой `n_tickets` заполняется нулём (магазин не обращался в поддержку) и получает флаг пропуска. `plan` кодируется one-hot, `store_id` и `account_id` в признаки не идут.

Тесты на синтетических данных:
- нет пересечения магазинов между частями;
- структура отчёта;
- веса классов и срабатывание ранней остановки;
- по одной вероятности на магазин.
