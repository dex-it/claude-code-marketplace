## Неточности текста

- «Обычный KFold для классификации: фолды без одного класса» - `cross_val_score(cv=5)` у классификатора берёт `StratifiedKFold` сам (проверено на scikit-learn 1.9.1); контроль приманку CB1 не поднял ни разу.

- «StandardScaler для деревьев - вред» - лишний шаг без вреда; контроль писал minor (приманка CB2).

## Пересмотр по существу (стек на #370)

Вопрос владельца: C9 и C10 в K-ML судил ключ по букве, исполнитель решал допустимо по существу. Ключ не правится (`_projects/shelfwatch/README.md`, раздел «Пересмотр по существу: H2, C9, C10»); правило засчёта записано коммитом до пересчёта и до добора. Контроль добран до n=4 на кейс: `rv-ml-c3`, `rv-ml-c4`, `k-ml-c3`, `k-ml-c4` (раннер без изменений, CLI 2.1.304, `claude-sonnet-5-5`, `skills=[]`, `mcp=[]`, `esc=[]`, $0.48 за четыре прогона).

| Код | Кейс | По ключу | По существу | Основание |
|---|---|---|---|---|
| C9 | K-ML | 2/4 (`c1`, `c4`) | 4/4 | `c1`, `c4`: `class_weight`, `scale_pos_weight`; `c2`, `c3`: веса осознанно не заданы, основание в коде и описании - метрика PR-AUC, вероятности остаются вероятностями |
| C9 | RV-ML | 0/4 (`RandomForestClassifier` в `split_and_fit`; засеянное место) | 4/4 по критерию, из них слепых 2 (`c3`, `c4`); засеянное место 0/4 | в каждом из четырёх ревью находка по `fit_xgb` называет XGBoost без `scale_pos_weight` при 5% оттока |
| C10 | K-ML | 0/4 | 4/4 | во всех четырёх 300 деревьев, `learning_rate=0.05`, `max_depth=4`, выбор модели по PR-AUC на валидации, а не на обучении: «допустимо» по правилу |
| C10 | RV-ML | 4/4 | 4/4 | находка по `n_estimators=10000` без `early_stopping_rounds` во всех четырёх |

**Исход.** C10 снят контролем по существу (4/4 в каждом применимом кейсе); C9 - 4/4 по критерию, снятие на решении владельца («Слабое место счёта» ниже). При снятии C9 пунктов не остаётся - скилл снят целиком (`dex-skill-python-classical-ml` 2.1.0). Синхронизации: ссылки на скилл сняты в `model-trainer`, `ml-experimenter` (1.6.1 -> 1.6.2), из бандла `ml-engineer` (1.9.1 -> 1.10.0) и из `stack-registry` (1.3.2 -> 1.4.0); кейс активации `python-classical-ml-in` снят; плагин удалён из каталога (6.21.0 -> 6.24.0).

**Слабое место счёта.** C9 в RV-ML по существу засчитан по находке про XGBoost, а не про `RandomForestClassifier`, на который указывает ключ. Правка после ревью #379 (ключ и правило выше не тронуты): посылка правила (`_projects/shelfwatch/README.md`, «Счёт»: «у `c1`, `c2` по существу не поднята ни находка, ни обоснование») считала `c1`, `c2` непрошедшими; по букве критерия («находка называет модель без учёта дисбаланса») они проходят: во всех четырёх `rv-ml-c*/REVIEW.md` находка по `fit_xgb` (строка 60) называет XGBoost без `scale_pos_weight` при 5% оттока - посылка ошибочна. Слепых клеток - две (`c3`, `c4`: критерий записан по `c1`, `c2`). Находка по дисбалансу в этих четырёх ревью - оговорка внутри находки про `early_stopping_rounds`, не отдельное замечание. Засеянное место ключа (`RandomForestClassifier` в `split_and_fit`) контроль пропускает 0/4. Исход C9: 4/4 по критерию, из них слепых 2; засеянное место 0/4 - снятие C9 и скилла целиком на решении владельца (тред #379 открыт). Если владелец не принимает - скилл остаётся одним пунктом C9 (название «Редкий класс, а модель обучена без весов классов»). C10 снят независимо: RV-ML 4/4 и K-ML 4/4 по строке «допустимо», из них `c3`, `c4` слепые.

## Дубли (шаг 0)

DDP (`python-pytorch` = `python-ml-optimization`), `no_grad` (тот же двойник), AMP (`python-pytorch`, `python-tensorflow`, `python-ml-optimization`) и GridSearch (`python-ml-optimization`; в `python-classical-ml` единицы нет, есть только слово в `description`) решены до кейсов: единица мерится в одном кейсе, двойник наследует вердикт. Все DDP-, `no_grad`- и AMP-единицы сняты контролем 2/2 (RV-PT, RV-DDP, RV-TF), GridSearch снят (RV-OPT). Заморозка backbone: V8 (`python-computer-vision`) и N8 (`python-nlp-transformers`) сняты контролем 2/2, поэтому противоречие без условия исчезло вместе с пунктами.
