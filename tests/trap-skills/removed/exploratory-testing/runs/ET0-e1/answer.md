Я прогнал около 70 вызовов CLI. Проверил границы `qty` и `price`, регистр SKU, пустой и повторный `--ref`, флаги без значения, фильтры `list`, цепочку `pay`/`ship`/`cancel` и разные неверные `id`. Результат везде совпал со спецификацией, включая коды возврата. Код я не менял.

- **D1 (средний, не в CLI):** в `src/money.js` проверка `n == NaN` всегда ложна. Поэтому `parseMoney('abc')` возвращает `NaN`, а `parseMoney('')` возвращает `0`, хотя должно быть `null`. CLI эту функцию не вызывает.
- **D2 (низкий):** при повреждённом `ORDERS_FILE` CLI печатает сырое сообщение `JSON.parse` и выходит с кодом 1, как и для неизвестной команды. Спецификация этот случай не описывает.
- **D3 (низкий):** запись `--ref=X` не поддерживается, и ошибка выглядит как `missing value for --ref=X`.
- **D4 (низкий):** значение флага, которое начинается с `--`, считается отсутствующим. Из-за этого нельзя создать `--ref --x`.
- **D5 (наблюдения):**
  - `pay` и `ship` в неподходящем статусе дают `bad state <status>` с кодом 3, а спецификация этого не определяет.
  - При повторе флага побеждает последнее значение.
  - `--ref ' '` принимается как валидный.
