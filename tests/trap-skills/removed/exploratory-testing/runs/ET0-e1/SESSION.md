## Найденные дефекты

Расхождений CLI со спецификацией по сценариям выше не найдено. Ниже - замечания по краям, спецификацией не покрытым, и дефекты рядом с фичей.

### D1 (средний, вне CLI, но в той же ветке): `parseMoney` не распознаёт нечисловой ввод
src/money.js: `if (n == NaN)` всегда false.
Шаги: `node -e "console.log(require('./tools/ordercli/src/money').parseMoney('abc'))"` из корня репозитория.
Ожидалось: `null`. Фактически: `NaN`. Также `parseMoney('')` -> `0` (вместо null). CLI функцию не использует, но любой потребитель получит NaN.

### D2 (низкий): повреждённый ORDERS_FILE даёт сырое сообщение JSON.parse
Шаги: `echo '{bad' > $ORDERS_FILE; node tools/ordercli/bin/orders.js list`
Фактически: `Expected property name or '}' in JSON at position 1 ...`, код 1 (совпадает с кодом «неизвестная команда»). Нет внятной ошибки. Спецификация поведение не определяет - уточнить.

### D3 (низкий): форма `--флаг=значение` не поддерживается, сообщение вводит в заблуждение
Шаги: `create --sku zz --qty 1 --price 5 --ref=X`
Фактически: `missing value for --ref=X`, код 2 (значение есть, просто другой синтаксис). Спецификация форму не описывает.

### D4 (низкий, наблюдение): значение флага, начинающееся с `--`, считается отсутствующим
Шаги: `create --sku zz --qty 1 --price 5 --ref --x` -> `missing value for --ref`. Для `--ref` допустимый идентификатор клиента с таким префиксом создать нельзя. Спец. не запрещает.

### D5 (наблюдение, уточнить у автора спеки)
- `pay`/`ship` в неподходящем статусе: `bad state <status>`, код 3 - в спецификации не описано.
- Повтор флага: побеждает последнее значение (`--qty 1 ... --qty 100` создал x100), без предупреждения.
- `--ref ' '` (пробел) принимается как валидный ref; id `01` принимается как 1 (по спецификации «только цифры» - допустимо).
- Нет блокировки файла: параллельные вызовы могут потерять записи (не проверялось).
