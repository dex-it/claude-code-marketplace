Дефекты по убыванию серьёзности:
1. **Гонка при параллельных запусках (высокий):** шесть одновременных `create` напечатали id `1 1 1 2 2 2`, а в `list` остались только два заказа. Читаешь файл, меняешь и записываешь без блокировки, поэтому заказы теряются и id дублируются. Из-за этого `--ref` не гарантирует отсутствие дублей при параллельной отправке.
2. **Лишние форматы чисел (средний):** `--qty` и `--price` принимают `1e1`, `0x10` и `" 5 "`, потому что проверка идёт через `Number()`.
3. **Нет верхней границы цены (средний):** `--price 99999999999999999999` принимается, а в `list` сумма выводится как `5000000000000000000.00`, то есть неверно.
4. **Нестрогий id (низкий):** `pay 0x2` оплачивает заказ №2, а `pay 1e0` и `pay 2.0` срабатывают как id 1 и 2. Ожидалось `not found`.
5. **Флаги без значения (низкий):** `--ref` без значения или с пустым значением молча создаёт новый заказ каждый раз. `create --sku x --qty --price 5` выдаёт `qty must be 1..100`, потому что `--price` съедается как значение `qty`. Спека такого не описывает, так что это вопрос к автору.
6. **Повторный `--ref` с другими параметрами (низкий):** молча возвращает старый id, без предупреждения. Спека это допускает, но стоит уточнить.
7. **Фильтр и битый файл (низкий):** `list --status bogus` печатает `no orders` с кодом 0. Битый JSON в `ORDERS_FILE` даёт сырое сообщение парсера и код 1.

Ещё в `src/money.js` проверка `n == NaN` всегда ложна, поэтому `parseMoney('abc')` вернёт `NaN`, а не `null`. Это нашёл при чтении кода и не запускал. Заказы эта функция не использует.

Остальное по спеке работает: границы `qty`, цена, регистр SKU, `cannot cancel` с кодом 3, идемпотентный `--ref`, `no orders` и справка при неизвестной команде с кодом 1.
