Я прогнал CLI вручную и нашёл пять дефектов. Отчёт с шагами воспроизведения лежит в `SESSION.md` в корне репозитория. Код я не менял.

Дефекты:
1. **`qty` проверяется только сверху.** Значения `0`, `-5`, `abc` и `2.5` принимаются с кодом 0. Получаются заказы с количеством 0, -5, `null` и 2 (дробное значение молча обрезается), а спецификация требует ошибку `qty must be 1..100` и код 2.
2. **`--ref` не защищает от дубля.** Два одинаковых `create ... --ref X` создали заказы 6 и 7, а должен вернуться id 6 без нового заказа.
3. **`cancel` отменяет заказ в статусе `shipped`.** Нужны ошибка `cannot cancel` и код 3.
4. **`list` сортирует id как строки.** Порядок выходит 1, 10, 11, …, 16, 2, 3, и так далее.
5. **`list --sku ab-1` ничего не находит.** Фильтр чувствителен к регистру, хотя SKU хранится в верхнем регистре и спецификация считает регистр неважным. Тот же запрос с `AB-1` находит заказ.

Ещё два замечания в отчёте не считаю дефектами:
- `pay abc` и `pay` без id отвечают `not found` с кодом 4. Спецификация этот случай не описывает.
- Флаг в конце команды без значения, например `--ref`, молча принимается.

Остальное из проверенного соответствует спецификации: ошибки `price` и SKU, повторный `cancel`, неизвестный id, неизвестная команда и формат сумм.

Не проверял путь по умолчанию `./orders.json`, параллельные запуски и `--ref` с пустым значением (кроме одного прогона).
