# SESSION: тестирование orders CLI (ветка feature/et-clean)

## Что и как исследовал
Прочитал `docs/ORDERS-SPEC.md` и код (`bin/orders.js`, `src/orders.js`, `src/money.js`), затем прогнал CLI
с `ORDERS_FILE=<repo>/scratch/t1.json` и `t2.json` (запуск: `node tools/ordercli/bin/orders.js ...`).
Каждый вывод и код возврата сверял со спецификацией.

Проверено (всё соответствует спецификации):
- `create`: успех, SKU в нижнем регистре хранится в верхнем; `qty` 0/101/1.0/1e1/" 1"/огромное число -> `qty must be 1..100`, код 2;
  `price` 0/1000001/огромное -> `bad price`, код 2; `price` 1000000 и `qty` 100 -> ок (итог `1000000.00`);
  плохой SKU (`a_b`, пустой, отсутствует, с `\n`) -> `bad sku`, код 2; пустой `--ref` -> `bad ref`, код 2.
- Идемпотентность `--ref`: повтор с теми же параметрами, с `qty 0`, с другим SKU -> тот же id (проверка ref первой).
  Ref `0` работает. Регистр ref различается (`r1` и `R1` - разные заказы), в спецификации иное не оговорено.
- Флаг без значения (`--price`, `--ref`, `list --sku`) -> `missing value for --флаг`, код 2.
- `list`: пустой -> `no orders`, код 0; порядок по возрастанию id; фильтры `--sku` (без учёта регистра), `--status`;
  `--status ""` и `NEW` -> `bad status`, код 2.
- `pay`/`ship`/`cancel`: переходы new->paid->shipped; `cancel` для shipped и cancelled -> `cannot cancel`, код 3;
  cancel для new допустим; `pay`/`ship` в неверном статусе -> `bad state X`, код 3;
  `id` = `abc`, `-1`, пусто, несуществующий -> `not found`, код 4.
- Неизвестная команда и запуск без аргументов -> справка, код 1.
- Формат сумм (`21.00`, `0.10`, `1000000.00`) верный.

## Найденные дефекты
Функциональных расхождений CLI со спецификацией по проверенным сценариям **не найдено**. Ниже - наблюдения низкой
серьёзности (спецификация по ним неоднозначна или молчит), оценка за командой.

### 1. (низкая) Необработанные ошибки файла состояния: стек вместо сообщения
Шаги:
1. `echo '{bad' > scratch/t2.json; ORDERS_FILE=$PWD/scratch/t2.json node tools/ordercli/bin/orders.js list`
   -> печатается сырое сообщение `Expected property name or '}' ...`, код 1 (без понятного текста).
2. `ORDERS_FILE=$PWD/scratch/nodir/x.json node tools/ordercli/bin/orders.js create --sku a --qty 1 --price 1`
   -> `ENOENT` + стек `node:internal/errors ... throw error`, код 1 (ошибка записи вне try/catch не обрабатывается красиво:
   в `create` она ловится, но вывод содержит трассу; поведение не описано в спецификации).
Ожидание: понятное сообщение об ошибке без стека.

### 2. (низкая, неоднозначность) Значение флага, начинающееся с `--`, считается отсутствующим
`create --sku c --qty 1 --price 5 --ref --x` -> `missing value for --ref`, код 2. Вероятно ожидаемо, но в спецификации
не описано; ref вида `--abc` создать нельзя.

### 3. (низкая, неоднозначность) Лишние/неизвестные аргументы молча игнорируются
`pay 1 --x` -> `missing value for --x`, а `pay --x 1` -> `not found` (код 4, а не 2: `--x 1` съедается как флаг,
id пуст); `list extra`, `pay 3 extra` игнорируют лишнее; повтор флага (`--qty 1 --qty 2`) - побеждает последний.
Спецификация не задаёт поведение.

### 4. (вне объёма CLI, замечено при чтении) `src/money.js: parseMoney`
`if (n == NaN)` всегда ложно, поэтому `parseMoney('abc')` возвращает `NaN`, а не `null`. CLI эту функцию не использует,
в `ORDERS-SPEC.md` её нет. Также `npm test`/`node --test test` в `tools/ordercli` завершается падением
(тесты относятся к pricing/loyalty, не к заказам; не разбирал).

## Не проверено
Параллельные запуски (гонка чтения/записи файла), права доступа к файлу, очень большие файлы.
Код не изменялся; созданы только файлы в `scratch/` и этот отчёт.
