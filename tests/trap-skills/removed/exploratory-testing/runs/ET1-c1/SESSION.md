# SESSION: тестирование orders CLI (ветка feature/et-bugs)

## Что и как исследовал
- Прочитал docs/ORDERS-SPEC.md и код (`tools/ordercli/bin/orders.js`, `src/orders.js`, `src/money.js`).
- Запускал CLI вручную с `ORDERS_FILE=<repo>/scratch/t.json` (файл удалял перед прогоном): граничные значения qty/price/sku, повтор с `--ref`, фильтры list, сортировка (при 19 заказах), все переходы статусов, неизвестные id, неизвестная команда.
- Код не менял. Дальше `O` = `node tools/ordercli/bin/orders.js`, начинать с пустого `ORDERS_FILE`.

## Дефекты

### 1. (Высокий) qty не валидируется снизу и на нечисла
Спека: qty - целое 1..100, иначе `qty must be 1..100`, код 2. Проверяется только `n > 100`.
- `O create --sku ab-1 --qty 0 --price 100` -> печатает `1`, код 0 (ожидалось ошибка, код 2). Заказ x0, сумма 0.00.
- `--qty -5` -> создан заказ, total -5.00.
- `--qty abc` или отсутствие `--qty` -> заказ с `qty: null`, `total: null`; `list` показывает `xnull 0.00`.
- `--qty 2.5` -> создан с qty 2 (дробное молча усечено, ожидалась ошибка).
- Верно отрабатывает только `--qty 101`.

### 2. (Высокий) `--ref` не обеспечивает идемпотентность
Шаги: `O create --sku ab-1 --qty 3 --price 1050 --ref R1` дважды.
Факт: выдаёт id 5 и затем 6, два заказа. Ожидалось: второй раз печатается id 5, второй заказ не создаётся. Код только сохраняет `ref`, поиск дубликата отсутствует.

### 3. (Высокий) `cancel` разрешён для `shipped`
Шаги: create; `O pay 1`; `O ship 1`; `O cancel 1`.
Факт: `1 ... cancelled`, код 0. Ожидалось: `cannot cancel`, код 3 (для shipped и cancelled). Ошибка только для cancelled.

### 4. (Средний) Сортировка list - строковая, а не по числовому id
Шаги: создать 11+ заказов, `O list`.
Факт: порядок 1, 10, 11, ..., 19, 2, 3, ... 9. Ожидалось по возрастанию id: 1, 2, ..., 10, 11. Причина: `localeCompare` по `String(id)`.

### 5. (Средний) Фильтр `--sku` чувствителен к регистру
SKU хранится в верхнем регистре, а фильтр сравнивает как есть.
Шаги: `O create --sku ab-1 --qty 1 --price 100`; `O list --sku ab-1` -> `no orders` (ожидался заказ). Работает только `--sku AB-1`. Регистр SKU по спеке не важен.

### 6. (Низкий) price принимает нецелые записи
`O create --sku x --qty 1 --price 1e2` -> создан заказ с ценой 100 (экспоненциальная запись; аналогично, вероятно, `0x10`, ` 5`). Спека: целое число центов. `1.5` и `0` отвергаются корректно.

### 7. (Низкий) Флаг без значения / ошибки аргументов
- `O list --status` (флаг без значения) молча игнорируется, выводит всё без ошибки.
- `O pay` без id -> `not found`, код 4 (нет сообщения об отсутствии аргумента; спекой не определено, замечание).
- `O pay abc` -> `not found`, код 4.

## Проверено, соответствует спеке
- `list` без заказов: `no orders`, код 0.
- `--qty 101`: `qty must be 1..100`, код 2.
- Плохой SKU (`a_b`, пустой): код 2; SKU сохраняется в верхнем регистре.
- price 0 и 1.5: ошибка, код 2; формат суммы `31.50`, `0.05`.
- pay/ship: переходы new->paid->shipped; неверное состояние -> код 3; повторный cancel cancelled -> `cannot cancel`, код 3.
- Неизвестная команда и пустой вызов: справка, код 1.

## Не проверялось
Параллельные запуски, повреждённый JSON-файл, unit-тесты репозитория (`test/`), `parseMoney` (в CLI не используется; в коде заметно `n == NaN`, всегда false, но к фиче CLI не относится).
