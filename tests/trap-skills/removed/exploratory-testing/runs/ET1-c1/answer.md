Что нашёл, по убыванию серьёзности:
1. **qty проверяется только сверху.** `--qty 0`, `-5` и `2.5` принимаются. `--qty abc` или его отсутствие даёт заказ с `qty: null`. Ошибка `qty must be 1..100` срабатывает только для 101 и больше.
2. **`--ref` не защищает от дублей.** Повторный `create` с тем же `--ref` создаёт второй заказ, а не печатает id первого.
3. **`cancel` разрешён для `shipped`.** По спеке должна быть ошибка `cannot cancel` и код 3.
4. **`list` сортирует id как строки.** Порядок получается 1, 10, 11, …, 19, 2, 3, …
5. **Фильтр `--sku` чувствителен к регистру.** SKU хранится в верхнем регистре, поэтому `list --sku ab-1` выводит `no orders`.
6. **`--price 1e2` принимается.** Спека требует целое число центов (низкая серьёзность).
7. **Флаг без значения и `pay` без id.** `list --status` без значения молча игнорируется. `pay` без id или с `abc` даёт `not found` и код 4, спека это не определяет (низкая серьёзность).

Остальное совпало со спекой: пустой `list`, `qty 101`, плохой SKU, `price` 0 и 1.5, переходы `pay`/`ship`, повторный `cancel` и справка с кодом 1.
