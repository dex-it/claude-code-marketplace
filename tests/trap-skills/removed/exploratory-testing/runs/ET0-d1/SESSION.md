## Дефекты

### D1. Повторный `--ref` с другими (невалидными) параметрами возвращает ошибку вместо id (spec, последний пункт)
Валидация в `create` идёт до поиска дубликата по `ref`.
Шаги:
1. `export ORDERS_FILE=.../scratch/t.json` (файл не существует)
2. `node bin/orders.js create --sku ab-1 --qty 2 --price 1234 --ref A` -> `1`
3. `node bin/orders.js create --sku zz --qty 0 --price 1 --ref A`
Ожидалось: `1`, код 0 («независимо от остальных параметров»).
Фактически: `qty must be 1..100`, код 2. То же с `--qty 500` (код 2) и `--price 0` (`bad price`), а также с отсутствующим/невалидным sku.

### D2. `list --status ""` не даёт `bad status`, фильтр молча игнорируется
Шаги: создать любой заказ; `node bin/orders.js list --status ""`.
Ожидалось: `bad status`, код 2 (статус не из списка).
Фактически: выводятся все заказы, код 0. Причина: `if (status && ...)` — пустая строка falsy. Аналогично `list --sku ""` игнорирует фильтр и выводит всё (спека поведение не определяет, вероятно, тоже стоит считать ошибкой/пустым результатом).

### D3. Повреждённый файл состояния — необработанная ошибка парсинга без внятного кода
Шаги: `echo '{bad' > scratch/c.json; ORDERS_FILE=scratch/c.json node bin/orders.js list`.
Фактически: сообщение движка JSON (`Expected property name or '}'...`), код 1, который совпадает с кодом «неизвестная команда». Спецификация это не описывает; низкий приоритет, замечание.

## Наблюдения (не дефекты по спеке)
- Нули в начале (`pay 01`, `--qty 0000000000000001`) принимаются: это «только цифры», формально допустимо.
- Повтор флага (`--ref A --ref B`) молча берёт последнее значение.
- Побочное: в `src/money.js` `parseMoney` использует `n == NaN` (всегда false) — вне области CLI, но баг (NaN не отсекается). Не проверялось запуском CLI.
