  и CPU limit. Документация Kubernetes CPU limit обязательным не называет, но пересчёт c1, c2 без него сделан по ключу, поправленному после прогона,
  и снятием не засчитывается. Снят в стеке #376 не по пересчёту, а по свежему контролю `k-w-m1`, `k-w-m2` (2/2 по ключу `454b097d`, записанному до прогонов).
- **J5, J9, J10, TC5:** настройки Jenkins (scope credentials, плагины, Replay) и «конфигурация только в UI» в файлах репозитория
  не живут; `unverifiable`, пункты остаются названиями.
- **GA3:** снят по вреду без свидетельства пользы; закрепление по SHA без сети не проверяется ни в одну сторону.
- **G7:** `packages.lock.json` исполнитель сгенерировать не может (нет сборки); исход проверяется ответом, а не файлом.
- **Удаление шага приманки** в прогонах с дисциплиной (ci-gates, github-actions): частота выше контроля, ключом не засчитывается как
  провал; нужна выборка больше n=2.
- **J4:** направление `failFast` (true против false) в пункте не задано; контроль не ставил его вовсе, редакции - ставили `true`.
- **Эпик, решение 2 (добор до 5 при 2/2) не принято**: единицы сняты при 2/2 по правилу метода в редакции `tests/README.md` на develop.
- **Потребитель вне карты:** агент `scaffolder` dex-auto (`plugins/auto/dex-auto/agents/scaffolder.md`, строки 26-27) вызывает `ci-gates` и скилл платформы (`github-actions` или `gitlab-ci`) для CI нового проекта. Кейса «CI с нуля для нового проекта» в наборе нет; проверка того, что сжатые скиллы не сузили этот путь, - открыто.
- **Рез `optimize-for-llm`** у исполнителя без `Skill` невозможен - `unverifiable`.
