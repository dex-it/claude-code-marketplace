Я добавил `Dockerfile` и `.dockerignore`. Ничего не собирал и не запускал: сети и сборки нет. Ничего не закоммичено.

**Что изменено (оба файла новые)**
- `Dockerfile`:
  - Сборка в два этапа. Этап сборки: `dotnet/sdk:8.0`, сначала restore только по `global.json`, `Directory.*.props` и двум csproj (слой с пакетами кэшируется), затем `publish --no-restore` без apphost.
  - Итоговый образ: `dotnet/aspnet:8.0-jammy-chiseled`, то есть минимальный, без shell и пакетного менеджера. Запуск от непривилегированного пользователя (`USER $APP_UID`), порт 8080 по умолчанию, `ENTRYPOINT ["dotnet","Depot.Api.dll"]`.
  - Настроек и секретов в образе нет. `ConnectionStrings__Default` и `Auth__ApiKey` подставляются при запуске.
- `.dockerignore`: исключены `bin/obj`, `.git`, `tests/`, `docs/`, `*.md` и сам Dockerfile. Значения stage из `docs/stage-values.md` в контекст сборки не попадают.

**Замечания**
1. **Теги не закреплены по digest.** В Dockerfile плавающие теги `8.0` и `8.0-jammy-chiseled`, потому что узнать digest без сети нельзя. Для воспроизводимой сборки CI стоит закрепить их по `@sha256`.
2. **Нет лок-файла NuGet.** `packages.lock.json` в репозитории нет, поэтому restore идёт не в locked-режиме, а правило `ci-gates` требует установку по лок-файлу. Версии пакетов зафиксированы только через `Directory.Packages.props`. Нужен отдельный тикет: включить `RestorePackagesWithLockFile`, закоммитить лок-файлы и добавить `--locked-mode`.
3. **Проба для Kubernetes.** Единственный health-маршрут `/health` ходит в БД. По дисциплине его нельзя использовать и как liveness, и как readiness одновременно. Для readiness он подходит. Для liveness нужен отдельный маршрут без обращения к БД, которого в приложении сейчас нет. Docker `HEALTHCHECK` в образ не добавлял: в chiseled-образе нет shell и curl.
4. **Холодный старт.** Он занимает 20–35 секунд (p95) из-за миграций. Платформенной команде нужен `startupProbe` или достаточный `initialDelaySeconds`.
5. **Файловая система и ресурсы.** Приложению нужна запись только в `/tmp`, так что `readOnlyRootFilesystem: true` подойдёт, но `/tmp` должен быть `emptyDir`. Requests и limits надо задать по runbook: около 300 МБ памяти, CPU 50m в простое и до 300m под нагрузкой.
6. **`depot-worker`.** Тот же образ запускается с другой командой: `dotnet Depot.Api.dll --worker`. Её нужно переопределить в манифесте через `args`, потому что `ENTRYPOINT` уже содержит `dotnet Depot.Api.dll`. Экземпляр должен быть ровно один: `replicas: 1` и стратегия `Recreate`. В `Program.cs` флага `--worker` нет, так что приложение запустит обычный API, а не обработку очереди. Это стоит уточнить у разработчиков.
7. **Локальный `docker run`.** Он запустится, только если передать обе обязательные переменные окружения и Postgres будет доступен.
