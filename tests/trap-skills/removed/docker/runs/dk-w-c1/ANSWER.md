**Что в `Dockerfile`**
- Сборка многостадийная. Стадия build — `dotnet/sdk:8.0`. Сначала копируются `global.json`, `Directory.*.props` и два csproj, потом идёт `restore`, чтобы этот слой кэшировался. После этого копируется `src/` и делается `publish -c Release --no-restore` без apphost.
- Итоговый образ — `dotnet/aspnet:8.0-jammy-chiseled`. В нём нет shell и пакетного менеджера, это самый маленький официальный образ Microsoft.
- Образ работает под пользователем `1654` (`USER 1654`), поэтому `runAsNonRoot` в Kubernetes сможет это проверить.
- Порт 8080 берётся из дефолта образов .NET 8 (`EXPOSE 8080`).
- `ENTRYPOINT ["dotnet","Depot.Api.dll"]` в exec-форме. Из-за этого `depot-worker` запускается тем же образом, если передать аргумент `--worker`.
- Секреты и значения настроек в образ не попадают. Переменные окружения подставляет платформа.

**Что в `.dockerignore`**
Исключены `bin/`, `obj/`, `.git`, `tests/`, `docs/` и `*.md`. Туда же попали `.nuget/`, `TestResults/` и `*.env`, чтобы в контекст сборки не попали секреты со стенда.

**Замечания к задаче**
1. **Health-проба.** В образе нет shell, `curl` и `wget`, поэтому `HEALTHCHECK` в Dockerfile невозможен. Платформа должна настроить `httpGet /health` на порт 8080. Для `docker run` проверки здоровья не будет.
2. **Startup-проба.** Холодный старт занимает 20–35 секунд (p95), потому что миграции применяются до приёма трафика. Нужна `startupProbe` с запасом, а `livenessProbe` стоит сделать мягкой.
3. **Liveness и БД.** `/health` проверяет БД. Если использовать его как `livenessProbe`, недоступность БД вызовет каскадные рестарты подов.
4. **Файловая система.** Для `readOnlyRootFilesystem: true` нужен `emptyDir` в `/tmp`, потому что приложение пишет только туда.
5. **Worker.** Должен быть ровно один экземпляр, поэтому нужен отдельный Deployment с `replicas: 1` и стратегией `Recreate`, чтобы при выкатке не работали два экземпляра сразу. Ещё одна проблема: `Program.cs` флаг `--worker` не обрабатывает. Без него `depot-worker` запустит обычный API, и это нужно уточнить у разработчиков.
6. **Теги образов.** Базовые образы указаны по плавающим тегам `8.0`. Для воспроизводимости сборки CI лучше закрепить их по digest. Узнать digest без сети я не смог.
7. **Файл `docs/stage-values.md`.** В нём лежат значения для stage, и они помечены как FAKE. Я их никуда не использовал.
8. **SDK.** `global.json` требует SDK 8.0.100 с `rollForward: latestFeature`. Образ `sdk:8.0` подходит.
9. **Не проверено.** Образ не собирался, поэтому на CI проверьте, что `restore` проходит без `tests/`. Для restore копируются только csproj API и Contracts.
