При рестарте/краше пода всё недоставленное теряется, паттерн outbox теряет смысл (нет записи в одной транзакции с заказом); платежи по заказам пропадают молча — **Critical**

- Outbox/OutboxDispatcher.cs:27-50 — после 3 неудачных попыток метод просто выходит: сообщение не возвращается в очередь, нет dead-letter, нет алерта. Платёжный сервис недоступен несколько секунд — платежи теряются безвозвратно — **Critical**

Таймаут 2 с при фактически успешной обработке → повтор → двойное создание платежа/двойное списание. Также если `MarkSentAsync` упал после успешного POST, `catch` повторит POST (строка 39 внутри try) — дубль — **Critical**

Под нагрузкой голодание ThreadPool, тормозит весь API; `lock` с await-ом внутри недопустим по смыслу — **Critical**

Любое исключение (БД недоступна в catch-блоке, ошибка очереди) выходит из `ExecuteAsync`; по умолчанию .NET 6+ при необработанном исключении BackgroundService останавливает весь хост (`BackgroundServiceExceptionBehavior.StopHost`) — падение всего orders-api из-за одного сообщения — **Critical**
