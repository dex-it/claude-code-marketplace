## Про правило команды (время приложения vs `now()` БД)

Все временные значения в компоненте берутся из БД: `created_at`, `locked_until`, `sent_at` и сравнение `locked_until < now()` считаются на стороне Postgres, часы приложения не участвуют. Перекоса часов между инстансами этот компонент не страдает, находок по этой оси нет. Единственный след времени приложения — поле `CreatedAt` в записи (см. находку выше), оно в БД не попадает.

Код не менялся, сборка и тесты не запускались; всё получено чтением трёх файлов. Схема таблицы `outbox` и настройка клиента «payments» (таймаут, ретраи) в компоненте не определены — выводы по ним предположительные.
