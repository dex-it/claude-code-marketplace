# [снят] ts-patterns: сжатие по свидетельству, группа 2.3

Скилл `dex-skill-ts-patterns` 2.0.1 ([`inputs/SKILL-2.0.1.md`](inputs/SKILL-2.0.1.md)), эпик #291, группа 2.3
(#298). Итог - скилл снят целиком; одна единица (внешние данные без проверки) возвращена названием в ось
агента-потребителя `ts-fullstack-assistant`. Строка в реестре [`tests/README.md`](../../../README.md).

засчитывания, шаг 0 и расход - общие для группы, в протоколе
[ts-nodejs-api](../../ts-nodejs-api/README.md#заход-группы-23-2026-10-06). В контроле скиллов нет, в `n1` и `f` снятый
скилл не подавался: снятие по контролю. Здесь - выходы K0
(«ничего не менять», общий для группы) и прогоны носителя (`d`, `n` на K1, `n` на K0 и K2): `runs/`. Прогоны
K1 и R1 - в [ts-nodejs-api](../../ts-nodejs-api/README.md), K2 и R2 - в [react](../../react/README.md), K3 - в
[ts-vitest-jest](../../ts-vitest-jest/README.md).

## K1-P1: буквальное чтение ключа

Ключ K1-P1 (коммит `caccb0c1`, до прогонов) в колонке «Провал» называет `as`, `any`, присваивание `unknown`
через приведение и guard без проверки `null`. Первая смена засчитала контроль 2/2 по исходу: тело ответа шлюза
приведено `as` к форме со всеми необязательными полями, затем поля `status` и `transaction_id` проверены во
время исполнения. Такое чтение сделано после просмотра ответов и меняет исход снятия скилла.

**Решение оркестратора (06.10.2026).** Мягкое чтение не принимается: K1-P1 судится по ключу буквально и
одинаково во всех прогонах K1, контроль и со скиллом. Записано коммитом `35c47a56` до прогонов носителя.

| Прогон | Разбор тела ответа шлюза | Буквально | Мягко (справка) |
|---|---|---|---|
| `k1-c1` | `(await res.json().catch(() => null)) as {...}` (все поля необязательные), далее `body?.status` | провал | да |
| `k1-c2` | `as typeof body`, проверка `status` и `transaction_id` без проверки `null`: тело `null` - TypeError, ответ 5xx | провал | да |
| `k1-n1a`, `k1-n1b`, `k1-fa`, `k1-fb`, `k1-f2a`, `k1-f2b` | `as typeof body` / `as ChargeResponse` (`ts-patterns` не подан) | провал 0/6 | - |
| `k1-da`, `k1-db` | guard `typeof body === 'object' && body !== null`, затем `as Record<string, unknown>` и `typeof` каждого поля | провал 0/2 | да |
| `k1-na`, `k1-nb` | zod `safeParse` тела ответа | 2/2 | да |

Буквально контроль 0/2 - единица возвращается. Мягкое чтение (справка для владельца): контроль 2/2 и `d` 2/2 -
исполнитель и без названия проверяет поля, но приводит тело `as`; провал проявляется как TypeError на `null`
(`k1-c2`), а не как тихое использование неверных данных. Сторона ревью (R1 K-N7) нашла `parse(...) as
CreateRefund` при опциональной сумме 4/4 - шаг 2 метода снимает единицу и для пишущего, когда ситуация
воспроизведена ревью, но у пишущего здесь свой прямой провал, он перевешивает (как N12 в ts-nodejs-api).

## Возврат названием

Скилл ради одной единицы не восстанавливается: по решению владельца эпика (группа 1, тред #314) дом одной-двух
вернувшихся единиц снятого скилла - ось агента-потребителя. Выбран `ts-fullstack-assistant`: K1 - его поручение
(HTTP-клиент внешнего сервиса в Node API), до снятия он грузил `ts-patterns` в Phase 3, и в его Boundaries уже
стоит строка про `any` и `unknown` + type guard. Название дописано в эту строку (шаг 1 «Формы пункта», без
решения): «Сюда же ответ внешнего сервиса, приведённый `as` к типу без проверки при исполнении».
`ts-test-writer` и `debugger` тела внешних ответов не пишут - название им не добавлялось, кейса у них нет.

Носитель: раннер не исполняет агента целиком (фазы агента требуют `Skill` tool и pre-load `node-contract`,
которых у исполнителя прогона нет), поэтому строки агента поданы файлом, как оси ревьюеров в группе 1.1
(прецедент [owasp-security](../owasp-security/README.md#возврат-названием)): Generate (цель и выход), Validate
(чек-лист проверки, в нём уже есть «Нет `any` / `as` без обоснования») и Boundaries. `d` - строки ветки без
названия ([`inputs/AXES-d.md`](inputs/AXES-d.md)), `n` - с названием ([`inputs/AXES-n.md`](inputs/AXES-n.md));
скиллы - итоговые `ts-nodejs-api`, `react` (с `PAYMENT_URL` в `description`, см. ts-nodejs-api; на P1 не влияет).

| Кейс | `d` | `n` | Остальное |
|---|---|---|---|
| K1 | P1 0/2 | P1 2/2 | мины M1-M6 PASS 4/4, статус ответа шлюза проверен 4/4, env при старте 4/4 |
| K0 | - | дифф только по задаче 2/2 | typecheck, test зелёные |
| K2 | - | - | мины M1-M4 PASS 2/2 |

Строки агента без названия (`d`) провал не снимают: «Нет `any` / `as` без обоснования» исполнитель закрывает
обоснованием `as Record<string, unknown>` после guard. Название поднимает K1-P1 с 0/2 до 2/2, вреда на K0 и K2
не даёт.
