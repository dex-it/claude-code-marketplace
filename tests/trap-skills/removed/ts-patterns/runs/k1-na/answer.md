`POST /api/orders/:id/pay` готов. `npm run typecheck` и `npm test` зелёные: в api 15 тестов, в web 2.

**Изменённые файлы**
- `api/src/app.ts` — эндпоинт оплаты.
- `api/src/payments/http-gateway.ts` (новый) — HTTP-реализация `PaymentGateway`.
- `api/src/config.ts` — `PAYMENT_URL` и `PAYMENT_API_KEY`.
- `api/src/server.ts` — подключён `HttpPaymentGateway` вместо заглушки.
- `api/src/domain/order.ts` — поле `transactionId?`.
- `api/test/orders.test.ts` — тесты на успех, отказ банка, чужой заказ и повторную оплату.
- `api/test/http-gateway.test.ts` (новый) — тесты шлюза: повторы, отсутствие повтора на 401, разбор ответов.
- `README.md` — две новые переменные окружения.

**Решения**
- **Переменные окружения:** `PAYMENT_URL` и `PAYMENT_API_KEY` проверяются в `config.ts` при импорте, то есть при старте. Без них сервис не запускается (правило `ts-nodejs-api`). Поэтому для запуска API их теперь нужно задавать.
- **Шлюз:**
  - При сетевом сбое, таймауте, `409` и `5xx` шлюз делает до 3 попыток с тем же `order_id`. Шлюз по контракту не спишет деньги повторно.
  - Если все попытки неудачны, эндпоинт отвечает `502 payment_unavailable`, статус заказа остаётся `new`. Такого ответа в задаче нет, это моё допущение.
  - Ответ шлюза проверяется через zod, а не приводится через `as`.
- **Эндпоинт:**
  - Пока идёт списание, повторный запрос на тот же заказ получает `409`. Защита работает только внутри одного процесса.
  - Письмо и событие аналитики отправляются после сохранения `paid`. Их сбой только логируется, ответ остаётся `200`.
  - Обработчик async и передаёт ошибки в `next`, потому что в Express 4 иначе отклонённый промис не попадёт в `errorHandler`.
- **Прецеденты:** `findOwnOrder` и `HttpError` взяты из `app.ts`. Схема повторов повторяет `services/reservation.ts`.

Заказ, отменённый во время самого списания, всё равно станет `paid`. Я оставил это как есть.
