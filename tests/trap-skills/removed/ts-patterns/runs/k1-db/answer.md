`POST /api/orders/:id/pay` готов. `npm run typecheck` и `npm test` зелёные (api: 18 тестов, web: 2). Playwright e2e не запускал, браузеров нет.

**Изменённые файлы**
- `api/src/payments/http-gateway.ts` (новый): `HttpPaymentGateway` по `docs/payments-api.md`.
- `api/src/app.ts`: эндпоинт `pay`.
- `api/src/server.ts`: HTTP-шлюз вместо заглушки.
- `api/src/config.ts`: `PAYMENT_URL` и `PAYMENT_API_KEY`.
- `api/src/domain/order.ts`: поле `transactionId?`.
- `api/test/orders.test.ts`: тесты эндпоинта.
- `api/test/http-gateway.test.ts` (новый): тесты шлюза.
- `e2e/playwright.config.ts`: переменные для запуска api.
- `README.md`: описание новых переменных.

**Решения**
- `PAYMENT_URL` и `PAYMENT_API_KEY` проверяются при импорте `config.ts`, то есть при старте, по правилу `ts-nodejs-api`. Без них api не стартует. Поэтому для e2e я прописал фиктивные значения, а для обычного запуска они теперь обязательны. Добавить их в окружения деплоя нужно вам.
- Шлюз повторяет запрос до 3 раз при сетевом сбое, таймауте, `409` и `5xx`. Повтор с тем же `order_id` безопасен: по контракту шлюз вернёт результат первого списания. Паттерн такой же, как в `services/reservation.ts`. Если шлюз так и не ответил, эндпоинт отдаёт `502 payment_unavailable`, а статус заказа остаётся `new`. Это решение вне ТЗ, прецедента в коде нет.
- Сбой письма или аналитики после успешного списания только пишется в лог. Деньги уже списаны, поэтому ответ остаётся `200`.
- Express 4 не ловит ошибки async-обработчиков, поэтому в `pay` ошибки передаются в `next` вручную.
- Если заказ отменили, пока шёл вызов шлюза, эндпоинт отвечает `409` и пишет в лог `transactionId`. В этом случае деньги списаны, но заказ остался отменённым. Автоматического возврата нет, это нужно решить отдельно.
