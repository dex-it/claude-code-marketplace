# [снят] output-hygiene: сжатие по свидетельству, группа 1.1

Скилл `dex-skill-output-hygiene` 1.2.0 ([`inputs/SKILL-1.2.0.md`](inputs/SKILL-1.2.0.md)), эпик #291,
группа 1.1 (#293). Итог - скилл снят целиком, строка в реестре [`tests/README.md`](../../../README.md).

Вход - общий мини-проект [`_projects/billing`](../../_projects/billing/README.md), кейсы S3 и S4.
Вердикт - по перепрогону в чистой среде на `claude-sonnet-5-5`, effort medium (раздел [«Перепрогон по
ревью PR #314»](#перепрогон-по-ревью-pr-314-2026-10-05)), коды `m-H1-c*`, `m-H2-c*`. Первый заход -
справочно: алиас `sonnet`, effort не задан, прогоны `c` - субагент `general-purpose` в сессии оператора
с проектным `CLAUDE.md` (ASCII-пунктуация) и глобальным `CLAUDE.md` оператора, `x` - `claude -p` вне
проектного `CLAUDE.md`, но с глобальным. Со скиллом прогонов нет: снятие по контролю.

## Потребители

Skill tool в фазе: `design-reviewer`, `requirements-reviewer`, `mr-reviewer` (публикация и ответы в
тредах), `mr-check-reviewer`, `review-planner` (черновики ответов), `incident-investigator`,
`self-reviewer`, `stand-reviewer`. Сноска: `optimize-for-llm` (исключение из scope - текст для
человека). Бандлы: `architect`, `bug-lifecycle`, `code-review`, `dotnet-developer`,
`dotnet-fullstack`, `product-manager`, `qa-engineer`, `system-analyst`, `ts-fullstack`.

## Тип единиц

12 ловушек формы текста для человека: визуальные маркеры, мета-речь, объём, содержательность.
Процедур нет. Предмет - форма выхода, поэтому кейсы - выходы для человека, а не засеянные дефекты.

## Промпты

H1 - ревью MR S3 в том виде, в каком оно публикуется автору: «Запиши в REVIEW.md ревью в том виде, в
каком опубликуешь его в MR для автора: общий комментарий и комментарии к строкам. Код не правь. В
ответе - итог для тимлида, который MR не открывал.» Описание MR - как в протоколе
[no-loose-ends](../no-loose-ends/README.md#промпт).

H2 - ответ автору в тред по S4: ревьюер вчера поднял blocker «остаток от деления теряется, копейка
пропадёт» на `MoneySplit.cs:12`, автор возражает «не теряется, остаток в последнем платеже, тест
это проверяет - 333, 333, 334. Закрываю?». Поручение: «Разберись по коду и задаче и напиши ответ
автору в тред - текст ответа запиши в REPLY.md». Ловушка кейса двойная: своё замечание неверно, а
настоящий дефект (остаток по задаче - в первый платёж) закреплён тестом автора.

H2 `x` (первый заход) - тот же промпт через `claude -p --model sonnet` вне проектного `CLAUDE.md`.

## Перепрогон по ревью PR #314 (2026-10-05)

`claude -p` 2.1.287, `--model claude-sonnet-5-5 --effort medium`, `--restricted --strict-mcp-config
--disable-slash-commands`: MCP нет, файлы настроек пользователя и проекта не читаются; каталог прогона
- копия мини-проекта вне репозитория, `CLAUDE.md` нет ни на пути каталога, ни у пользователя
(`~/.claude/CLAUDE.md` отсутствует). Инструменты Bash, Read, Write, Edit, Grep, Glob. Промпты H1, H2 -
прежние (`runs/m-H*/prompt.txt`). Признаки формы - 12 строк вердикта; эмодзи и тире считаются по
символам (U+2014, U+2013, эмодзи-диапазоны) в файле и в ответе, остальные - чтением. Оракул формы
ответа (каким должен быть «итог для тимлида») до прогона не записан.

Содержательный исход H2 вне скилла: оба прогона признали своё замечание неверным и подняли
настоящее расхождение с задачей (остаток в последнем платеже, тест его закрепляет) - 2/2.

Тире вне набора. В той же чистой среде контроль A-D набора performance-review (ревью для автора,
промпт без построчного образца находки) пишет `**файл:строка** — суть`: длинное тире во всех 8
прогонах `m-P*-c*` (3-32 на ревью); со скиллом performance-review на A, B, D - 0 (текст скилла
разделяет дефисом), на C - 15-22. В кейсах H1, H2 и в ревью billing (`m-S*`, `m-E*`) - 0. Ключа формы у
A-D нет, поэтому строка вердикта не меняется, но снятие «длинного тире» держится только на H1, H2.
Решение 2026-10-05 (тред PR #314): снятие остаётся - длинное тире в тексте ревью типографская
конвенция команды, её дом - свод правил проекта (здесь `CLAUDE.md`, «Пунктуация в артефактах -
ASCII»); название его не убирает, а исход или триада на восемь потребителей ради конвенции - готовое
решение вместо вектора. Проба по одному прогону на A и B: одно название
([`inputs/DASH-name.md`](inputs/DASH-name.md), `m-PA-h1`, `m-PB-h1`) - 24 и 26 `—`, не поднимает;
полный скилл 1.2.0 (`m-PA-hs1`, `m-PB-hs1`) - 0 и 0. Текст скилла написан дефисами, как и
performance-review, поэтому неясно, работает ловушка или образец стиля.

Ловушки, оправданные свидетельством на H1, H2, не набираются ни одной - скилл снят целиком;
открыты «Ответ не начинается с результата» (`unverifiable`) и «длинное тире» вне набора. Синхронизации:
запись каталога, девять бандлов и README двух из них, загрузка в восьми агентах и README семи,
сноска `optimize-for-llm` (исключение из scope остаётся без адреса), строка инвентаризации
`docs/migration/claude5-context-inventory.md`, колонка `requirements-reviewer` в
`docs/pipelines/analytics/ARCHITECTURE.md`, кейс активации `output-hygiene-in`, витрина README.
