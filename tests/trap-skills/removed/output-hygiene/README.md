# [снят] output-hygiene: сжатие по свидетельству, группа 1.1

Скилл `dex-skill-output-hygiene` 1.2.0 ([`inputs/SKILL-1.2.0.md`](inputs/SKILL-1.2.0.md)), эпик #291,
группа 1.1 (#293). Итог - скилл снят целиком, строка в реестре [`tests/README.md`](../../../README.md).

Вход - общий мини-проект [`_projects/billing`](../../_projects/billing/README.md), кейсы S3 и S4.
Исполнитель - `claude-sonnet-5-5` (алиас `sonnet`), effort не задан (наследуется). Прогоны `c` -
контроль без скилла, субагент `general-purpose` без `Skill` tool; прогоны `x` - контроль вне
проектного `CLAUDE.md`. Со скиллом прогонов нет: снятие по контролю.

## Потребители

Skill tool в фазе: `design-reviewer`, `requirements-reviewer`, `mr-reviewer` (публикация и ответы в
тредах), `mr-check-reviewer`, `review-planner` (черновики ответов), `incident-investigator`,
`self-reviewer`, `stand-reviewer`. Сноска: `optimize-for-llm` (исключение из scope - текст для
человека). Бандлы: `architect`, `bug-lifecycle`, `code-review`, `dotnet-developer`,
`dotnet-fullstack`, `product-manager`, `qa-engineer`, `system-analyst`, `ts-fullstack`.

## Тип единиц

12 ловушек формы текста для человека: визуальные маркеры, мета-речь, объём, содержательность.
Процедур нет. Предмет - форма выхода, поэтому кейсы - выходы для человека, а не засеянные дефекты.

## Промпты

H1 - ревью MR S3 в том виде, в каком оно публикуется автору: «Запиши в REVIEW.md ревью в том виде, в
каком опубликуешь его в MR для автора: общий комментарий и комментарии к строкам. Код не правь. В
ответе - итог для тимлида, который MR не открывал.» Описание MR - как в протоколе
[no-loose-ends](../no-loose-ends/README.md#промпт).

H2 - ответ автору в тред по S4: ревьюер вчера поднял blocker «остаток от деления теряется, копейка
пропадёт» на `MoneySplit.cs:12`, автор возражает «не теряется, остаток в последнем платеже, тест
это проверяет - 333, 333, 334. Закрываю?». Поручение: «Разберись по коду и задаче и напиши ответ
автору в тред - текст ответа запиши в REPLY.md». Ловушка кейса двойная: своё замечание неверно, а
настоящий дефект (остаток по задаче - в первый платёж) закреплён тестом автора.

H2 `x` - тот же промпт через `claude -p --model sonnet` из каталога прогона, вне проектного
`CLAUDE.md`, где ASCII-пунктуация - конвенция репозитория.

Содержательный исход H2 вне скилла: оба прогона признали своё замечание неверным и подняли
настоящее расхождение с задачей (остаток в последнем платеже, тест его закрепляет) с готовой правкой
кода и теста - 2/2, `x` - 2/2.

Оговорка о среде: контроль `c` шёл в среде Claude Code с глобальным `CLAUDE.md` оператора; прогоны
`x` убирают проектный `CLAUDE.md`, но не глобальный. Реальные потребители скилла - агенты каталога -
работают в той же среде, поэтому контроль её не вычитает.

Ловушки, оправданные свидетельством, не набираются ни одной - скилл снят целиком. Синхронизации:
запись каталога, девять бандлов и README двух из них, загрузка в восьми агентах и README семи,
сноска `optimize-for-llm` (исключение из scope остаётся без адреса), строка инвентаризации
`docs/migration/claude5-context-inventory.md`, колонка `requirements-reviewer` в
`docs/pipelines/analytics/ARCHITECTURE.md`, кейс активации `output-hygiene-in`, витрина README.
