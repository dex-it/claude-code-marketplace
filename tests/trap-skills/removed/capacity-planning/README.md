## Шаг 0

- **Пороги без источника** - CP1 «3-5x от average» и «peak может быть 10x», CP2 «10-100x от внешнего», CP4
  «10:1», «3-5:1», «100:1», CP5 «5-10×», CP6 «100:1», CP7 «80/20» и «10-20% endpoint'ов» - в пункт
  не писались бы. Кейсы порог не проверяют: судится исход по числам входа (ключ: «порог-эвристика скилла
  судится по исходу»).
- **Различие единиц.** CP2 «write amplification» и CP5 «background reads» - разные ситуации: внутренний трафик на
  каждый запрос против фоновых читателей; у каждой своя клетка.
- **Приманка простого случая.** D6 (очередь жалоб на 3 000 в сутки) - верный исход «ничего лишнего»; P2 судит, не
  толкает ли направление скилла к ёмкости, кэшу или денормализации ради нагрузки, которой нет.

  (cap-consistency, capacity-planning, reference-architectures, tech-evaluation) у `architect` и `architect-dotnet`
  Phase 3 остаётся без загрузки скиллов - допустимо как следствие свидетельства. Условие (решение владельца в
  итерации 2) выполнено: проза фазы (Goal, вводная, терминал) снятые скиллы не называет и на них не опирается,
