## Шаг 0

- **Таблица «Storage defaults cheatsheet» (17 строк) и абзацы «Применение в Phase 5», «Когда default не
  подходит» - сняты без прогона.** Это справочник, а не ловушка: строки называют свойства хранилищ, ситуации,
  которую исполнитель не заподозрит, в них нет. Текст ссылается на агента-архитектора и его фазы, а скилл не знает,
  какой агент его загрузит (SKILL_FRAMEWORK,
  [«Дублирование между skills»](../../../../docs/SKILL_FRAMEWORK.md#дублирование-между-skills));
  фаз Phase 5 (Decide) и Phase 6 у агентов к тому же нет - Decide у `architect` и `architect-dotnet` - Phase 3.
  Строка «Kafka acks=1 (default)» неверна: в librdkafka `acks` по умолчанию -1 (all), в Java-клиенте с Kafka 3.0 по
  умолчанию `acks=all` и идемпотентный продюсер (KIP-679). Перенос в `references/` отвергнут: пришлось бы сверять
  каждую строку по версиям хранилищ, а свидетельства, что таблица меняет решение исполнителя, нет.
- **Снятые в группе 1.2.** «Two-Phase Commit через сервисы» и «Saga без компенсирующих транзакций»
  [microservices](../microservices/README.md) - справка; CC1 и CC8 судятся здесь заново, своим кейсом.
- **Дубли внутри группы.** RA3 reference-architectures (платежи) раскладывается: (a) уровень консистентности по
  операции = CC3, дом CC3; (d) saga с компенсацией = CC8, дом CC8. Ловушка «Split-brain не учтён в CP-системах»
  (CC6) судится клеткой CC7 («дом и CC6» в ключе): одна ситуация - аренда истекла, прежний держатель продолжает
  писать; защита - fencing-токен, уникальность в базе, ключ идемпотентности у получателя.
- **Пороги без источника** («replication lag 100-500ms», «NTP даёт ±50-500ms drift») в пункт не писались бы.

- **CC2 в `d2-f1` = 0 (спорная).** Прогон без cap-consistency (набор `f`) назвал цену межДЦ-записи - стр. 88 «из
  второго ДЦ +11 мс», стр. 318, - но с NFR-4 её не сверил: бюджет p95 800 мс (стр. 220) межДЦ-составляющей не
  содержит, а ключ требует «названа ... и сверена». В контроле `d2-c1`, `d2-c2` CC2 = 1. Ещё пара без скилла
  (`h`, решение оркестратора 6) - 2/2, `d2-h1` спорная: «+11 мс» вставлено в бюджет NFR-4, итог «укладывается» не

  владельцу основание при желании поставить на PACELC отдельный кейс.
- **Оракул у `design-reviewer`.** Ревьюер дизайна терял оракул `cap-consistency` - абзац «Арх-оракулы»
  синхронизирован (остался `ddd`). Аспект «консистентность распределённой модели (CAP/PACELC, saga/outbox,
