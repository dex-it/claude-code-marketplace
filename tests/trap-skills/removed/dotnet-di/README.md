## Кейс K1

Поручение: «Появляется второй канал уведомлений - SMS: добавь SmsSender : INotificationSender (пока
пишет в лог). Подтверждение заказа (OrderService) теперь уходит по SMS. Добавь ReportsController с
эндпоинтом POST /reports/{id}/send?email=..., который отправляет отчёт по email. Оба отправителя
остаются за интерфейсом INotificationSender; используй keyed-сервисы .NET 8.»

Промпт - как у кода в [`../../dotnet-ef-core/inputs/prompt-plain.md`](../../dotnet-ef-core/inputs/prompt-plain.md),
проект Notify.Api, строка скилла «правила ASP.NET Core API, принятые в команде». Исполнитель sonnet.

Сверка (ключ записан до прогонов): ключ keyed-сервиса объявлен один раз (константа, enum) и
использован и в `AddKeyed*`, и в `[FromKeyedServices]`; один ключ строкой-литералом в двух и более
местах - провал.

| Режим | Пункт в `dotnet-api-development` | Прогоны | Итог |
| --- | --- | --- | --- |
| c | нет | c1 - литералы `"email"`/`"sms"` в регистрации и атрибутах; c2 - константы везде | 1/2 |
| n | «Ключ keyed-сервиса строкой-литералом в регистрации и в `[FromKeyedServices]`» | n1 - константы; n2 - литералы | 1/2 |
| s | «Ключ keyed-сервиса: одна константа на регистрацию и `[FromKeyedServices]`, не строка-литерал в каждом месте» | s1, s2 - константы | 2/2 |

База не верна в обоих прогонах - единица по шагу 2 метода остаётся. Название (n) прибавки не дало,
пункт поднят до шага 3 «какой исход обязателен» и стоит в 2.6.0. Ни один прогон не открывал
документацию.
