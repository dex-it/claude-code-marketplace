## По пунктам ТЗ

| Пункт | Статус | Чем подтверждён |
|---|---|---|
| R1. Надбавка 1 % от `declaredValue` (центы), `/quote` отдаёт `insurance` и `price` | **НЕ ПРИНЯТО** | Пример из ТЗ: 1 кг, 10115, `declaredValue` 20000. Ожидается `insurance` 2 и `price` 6.50. Стенд отдал `insurance` 200 и `price` 204.5. Другие пробы: 12345 -> 123.45 (ожидается 1.23); 150 -> 1.5 (ожидается 0.02). Причина: `src/insurance.js` `insuredAmount()` возвращает значение как есть, без перевода центов в EUR (деления на 100). Поле `insurance` в ответе есть, `price` включает надбавку, но суммы завышены в 100 раз. |
| R2. Лимит 1000 EUR, выше - 422, ровно 1000 принимается | **НЕ ПРИНЯТО** | В `/quote` лимита нет: 100001 (1000.01 EUR) -> 200, `insurance` 1000.01. В `/shipments` лимит сравнивается с центами: 20000 (200 EUR) -> 422 «сумма отправления превышает лимит 1000 EUR», хотя должен приниматься. Ровно 1000 EUR (100000) -> 422, а должен приниматься. Принимается только `declaredValue` до 1000 центов, то есть 10 EUR. Причина: `LIMIT_EUR` сравнивается с неконвертированным значением, а в `quote()` проверки лимита нет. |
| R3. Зона D не страхуется, 422 «страховка недоступна для зоны D» | **ПРИНЯТО** | `/quote`, индекс 25980 (зона D), `declaredValue` 20000 -> 422 `{"error":"страховка недоступна для зоны D"}`. Текст совпадает с ТЗ. Проверена только одна D-точка, `/shipments` для D не пробовал. Он идёт через тот же `quote()`. |
| R4. На этикетке «Страховка: N EUR» по контракту `docs/messages.md`, без `undefined` | **НЕ ПРИНЯТО** | Отправление с `declaredValue` 1000: API кладёт в очередь `insured:true, insuredAmount:1000` (по контракту), а label-worker печатает «Страховка: undefined EUR». Тот же результат на ручном сообщении `insuredAmount:200`. Причина: `worker/label.js` читает `msg.insurance`, а контракт задаёт поле `insuredAmount`. |
