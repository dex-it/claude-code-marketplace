# Приёмка SHIP-53 (страхование отправления, MR !57) на стенде stage

Стенд: shipping-api и label-worker выкачены на sha 5615aa7b5b53 (merge !57), выкат 2026-10-06T10:30Z. Это тот sha, что указан в ТЗ. Конфигурация стенда: флаг `quote_cache` off, `CARRIER_TIMEOUT_MS=5000`.

Метод: пробы `standctl request` на развёрнутой фиче. Пробы только читающие: `POST /quote` и сообщения в label-worker. `POST /shipments` не вызывался, потому что создаёт отправления в общем стенде (shipping, billing, support, qa), а временных данных я оставлять не хотел. Код читал только для поиска причин, статусы выставлены по пробам.

| Пункт | Статус | Чем подтверждён |
|---|---|---|
| R1. Надбавка 1 %, `/quote` отдаёт `insurance` и `price` | **НЕ ПРИНЯТ** | Проба: 1 кг, 10115, `declaredValue` 20000 (в запросе также `insured: true`) -> `insurance` **200**, `price` **204.5**. По ТЗ ожидалось `insurance` 2, `price` 6.50. Надбавка равна 100 % ценности. Проба с `declaredValue` 20050 -> `insurance` 200.5. Без `declaredValue` -> `insurance` 0, `price` 4.5, это корректно. Причина: `src/insurance.js` `insuredAmount()` возвращает `declaredValue` как есть, без перевода центов в EUR (/100). Поэтому 20000 считается как 20000 EUR. |
| R2. Лимит 1000 EUR, выше - 422, ровно 1000 принимается | **НЕ ПРИНЯТ** | Проба `/quote` с `declaredValue` 100000 (1000 EUR) -> 200 с `insurance` 1000. Это неверно: должно быть 10. Проба со 100001 (1000,01 EUR) -> **200**, `insurance` 1000.01, а ожидался 422. Причины: проверка лимита есть только в `createShipment`, в `/quote` её нет. Кроме того, сравнивается значение в центах с лимитом в EUR (`LIMIT_EUR = 1000`). Поэтому в `/shipments` 422 вернётся уже на 1000,01 **центах** (10,01 EUR), а 1000 EUR будет отклонено. Это выведено из кода, на стенде не проверялось, потому что `/shipments` я не вызывал. |
| R3. Зона D не страхуется, 422 | **ПРИНЯТ** | Проба: 25980 (зона D), 1 кг, `declaredValue` 20000 -> 422 `{"error":"страховка недоступна для зоны D"}`. Текст совпадает с ТЗ. |
| R4. Этикетка: «Страховка: N EUR» без `undefined` | **НЕ ПРИНЯТ** | Проба в label-worker с сообщением по контракту `docs/messages.md` (`insured: true`, `insuredAmount: 200`) -> печатается **«Страховка: undefined EUR»**. Причина: `worker/label.js:10` читает `msg.insurance`, а контракт задаёт поле `insuredAmount`. Сообщение без страховки: строки нет, это корректно. |

## Итог

**Фича не принята.** Из четырёх пунктов выполнен только R3. R1, R2 и R4 не проходят на стенде.

Дефекты:
1. Центы `declaredValue` не переводятся в EUR (`src/insurance.js`). Из-за этого ломаются R1 и R2: надбавка завышена в 100 раз.
2. В `/quote` нет проверки лимита 1000 EUR. В `createShipment` она есть, но сравнивает центы с EUR.
3. label-worker читает `msg.insurance` вместо `insuredAmount`, поэтому на этикетке `undefined`.

Замечание: unit-тесты MR !57 (`test/insurance.test.js`) эти дефекты не поймали. Скорее всего, они проверяют значения в «EUR», а не в центах по `docs/api.md`.

`/shipments` проверять осознанно: он оставляет отправления в общем стенде, лучше согласовать это с командами или использовать тестовые данные, которые потом можно отличить.
