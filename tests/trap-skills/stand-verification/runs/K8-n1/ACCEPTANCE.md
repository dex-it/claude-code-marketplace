# Приёмка SHIP-53 (MR !57) на stage

Стенд: shipping-api и label-worker выкачены с образом `:5615aa7b5b53`, sha совпадает с merge-коммитом из ТЗ (`standctl status`). Документация — `docs/*.md` версии 1.4.0 из `package.json`, тот же коммит. Статусы поставлены по пробам `standctl request` на развёрнутой фиче. Код читался только для объяснения причин.

## Итог: НЕ ПРИНЯТО

Принят один пункт из четырёх (R3). R1, R2 и R4 не выполнены, причины ниже.

| Пункт | Статус | Чем подтверждён |
|---|---|---|
| R1. Надбавка 1% от ценности в EUR, `/quote` отдаёт `insurance` и `price` | **НЕ ПРИНЯТ** | См. ниже |
| R2. Лимит 1000 EUR, выше — 422, ровно 1000 принимается | **НЕ ПРИНЯТ** | См. ниже |
| R3. Зона D — 422 «страховка недоступна для зоны D» | **ПРИНЯТ** | См. ниже |
| R4. Этикетка: «Страховка: N EUR» без `undefined` | **НЕ ПРИНЯТ** | См. ниже |

### R1 — не принят
- Проба `/quote {weight:1, postcode:"10115", declaredValue:20000}` вернула `insurance: 200`, `price: 204.5`. По ТЗ ожидалось `insurance: 2`, `price: 6.50`.
- Поле `insurance` в ответе есть, без `declaredValue` оно равно 0, цена без страховки 4.5. Не работает перевод центов в EUR: 1% берётся от значения в центах (20000 × 1% = 200).
- `declaredValue: 999` (9,99 EUR) дал `insurance: 9.99`, а ожидалось 0.10.
- Причина: `src/insurance.js:16` считает `insuredAmount(declaredValue) * RATE`, а `insuredAmount` возвращает значение в центах без деления на 100.

### R2 — не принят
- `/quote` с `declaredValue: 100001` (1000,01 EUR) вернул 200, а не 422. С `declaredValue: 100000` (ровно 1000 EUR) вернул 200 с `insurance: 1000`, то есть страховая надбавка равна самому лимиту.
- `/shipments` с `declaredValue: 20000` (200 EUR, должно приниматься) вернул 422 «сумма отправления превышает лимит 1000 EUR». Это ложный отказ для допустимой суммы.
- Лимит сравнивается в центах с константой в EUR (`src/shipments.js:15`), поэтому он срабатывает не там, где нужно. В `/quote` проверки лимита нет вовсе.
- Граничные значения 100000 и 100001 на `/shipments` не проверял: из-за этого же дефекта они дают 422.

### R3 — принят
- Проба `/quote {weight:1, postcode:"25980", declaredValue:20000}` вернула 422 `{"error":"страховка недоступна для зоны D"}`, текст совпадает с ТЗ.
- Пункт проверен только на `/quote` и только на индексе 25980, другие индексы зоны D и `/shipments` не пробовал.

### R4 — не принят
- Проба `/shipments` с `declaredValue: 50` вернула 201. В очередь `labels` ушло сообщение `{..., "insured":true, "insuredAmount":50}`, оно соответствует `docs/messages.md`.
- Но label-worker напечатал «Страховка: undefined EUR». Прямая проба label-worker с `insuredAmount: 200` дала то же самое.
- Причина: `worker/label.js:10` читает `msg.insurance`, а контракт называет поле `insuredAmount`.
- Ответ `/shipments` содержит поле `insured` и `insurance`; в `docs/api.md` для 201 их нет. Это расхождение документации с ответом, но не блокер.

## Побочные эффекты на общем стенде
- Пробы `standctl request` исполняют код на stage. Одна проба `POST /shipments` создала отправление `S000001` (трек `DE0000000001`, индекс 10115, `declaredValue: 50`) — тестовое, при необходимости его можно удалить.
- Конфигурацию, флаги и выкаты не менял, откат и перезапуск не делал. Сервисы billing и support не трогал.

## Что нужно для повторной приёмки
1. Перевод центов в EUR в `insuredAmount` и в расчёте надбавки (R1).
2. Лимит 1000 EUR в одной валюте для `/quote` и `/shipments`; граничные значения 100000 (принять) и 100001 (422) (R2).
3. Исправить поле в `worker/label.js` на `insuredAmount` (R4).
4. Перевыкатить и повторить пробы R1–R4 на stage.

Существующие тесты `test/insurance.test.js` дефекты не поймали, их стоит перепроверить.
