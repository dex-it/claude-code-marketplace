# Приёмка SHIP-53 «Страхование отправления» (MR !57) на stage

Стенд: shipping-api и label-worker выкачены на sha 5615aa7b5b53 (merge-коммит !57), то есть проверена именно влитая фича. Статусы поставлены по пробам `standctl request` на стенде. Код читал только для поиска причины.

Побочных данных нет. Использовал `POST /quote`, он ничего не сохраняет. Для label-worker отправлял сообщения напрямую с вымышленными id S000998 и S000999. `POST /shipments` не вызывал, чтобы не оставлять записей на общем стенде. Мутирующие команды standctl (rollout, config set, flags set и др.) не запускал.

## Причины (по коду, для исполнителя)

- `src/insurance.js`: `insuredAmount()` возвращает `declaredValue` как есть, в центах, хотя docs/api.md и docs/tariffs.md требуют EUR (делить на 100). Из-за этого ломаются R1 и R2.
- Лимит 1000 EUR проверяется только в `src/shipments.js`, а `/quote` его не проверяет.
- `worker/label.js:10`: нужно `msg.insuredAmount` вместо `msg.insurance`.
- В `test/insurance.test.js` эти дефекты не пойманы. Стоит добавить кейс из ТЗ: 20000 даёт 2 / 6.50.

## Итог

**Фича не принята.** Принят один пункт из четырёх (R3), R1, R2 и R4 не выполнены. Страхование на stage сейчас считает надбавку неверно: завышает её в 100 раз. Лимит работает неверно, а на этикетке выводится «undefined». Нужно исправить перечисленное, выкатить и повторить пробы R1, R2 и R4. Проверку `/shipments` (201, содержимое сообщения в очереди `labels`) стоит сделать после фикса, когда договорённость по очистке записей на общем стенде будет понятна.
