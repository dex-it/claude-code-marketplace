# testability: сжатие по свидетельству, группа 1.1

Скилл `dex-skill-testability` 1.1.2 ([`inputs/SKILL-1.1.2.md`](inputs/SKILL-1.1.2.md)) -> 1.2.0
([`inputs/SKILL-1.2.0.md`](inputs/SKILL-1.2.0.md)), эпик #291, группа 1.1 (#293). Редакции 1.2.0 по
ходу: [`v1`](inputs/SKILL-1.2.0-v1.md) - один пункт-признак, [`v2`](inputs/SKILL-1.2.0-v2.md) - плюс
пункт `Guid.NewGuid()`, итоговая - плюс случаи файла в признаке (ревизия по провалу TF на S2).

Вход - общий мини-проект [`_projects/billing`](../_projects/billing/README.md), кейсы S2, S4, ключ
там же. Вердикт - по перепрогону на `claude-sonnet-5-5`, effort medium, `claude -p` без MCP и без
`CLAUDE.md` (среда и порядок ключа - [owasp-security, «Перепрогон по ревью PR
#314»](../removed/owasp-security/README.md#перепрогон-по-ревью-pr-314-2026-10-05)); со скиллом промпт
дополнен строкой «Перед работой прочитай <SKILL> - дисциплина, принятая в команде», копия `SKILL.md`
подана путём. Первый заход (алиас `sonnet`, effort не задан - наследовался, субагент
`general-purpose`) - справочно: `s4-c*`, `s2-v1`, `s4-v1`.

Коды: `m-S4-c1`, `m-S4-c2` - контроль S4; контроль S2 общий с группой, `m-S2-c1`..`m-S2-c4` в
протоколе [owasp-security](../removed/owasp-security/README.md); `m-*-te*` - редакция v2, `m-*-tr*` -
итоговая. S4 - ветка под ловушки, которых S2 не покрывал: тесты требует задача, тесты ветки зелёные
только в зоне МСК.

## Потребители

Skill tool в фазе: `mr-reviewer`, `mr-check-reviewer`, `self-reviewer` (ось `regressions`),
`bug-finder`, `discover-reviewer`, `dotnet-coder`, `dotnet-test-writer`; тематическая строка
`stack-registry`; сноска `integration-boundary`. Бандлы: `code-review`, `bug-lifecycle`, `architect`,
`dotnet-developer`, `dotnet-fullstack`, `ts-fullstack`, `qa-engineer`.

## Тип единиц

11 ловушек и чек-лист, повторяющий их названиями. Процедур нет.

## Промпт

Общий с группой 0 ([fact-verification](../fact-verification/README.md#заход-группы-0-звенья-каскада-2026-10-04)).
Описание MR S4: «Рассрочка по счёту по задаче docs/tasks/BILL-25-installments.md: POST
/invoices/{id}/installments, график платежей с переносом на рабочие дни, выборочный контроль
рассрочек письмом в бухгалтерию, unit-тесты графика.» Описание S2 - в протоколе owasp-security.

Четыре ловушки, которые контроль пропустил, - случаи одного признака: логика сама обращается к
внешнему миру без шва для подмены в тесте. 1.2.0 - пункт-название с этим признаком, случаи названы в
нём примерами. `Guid.NewGuid()` признак не покрывает (недетерминизм, а не внешний мир): контроль его
не поднял, но кейс S4 не создаёт ситуацию ловушки - assert на id. Без свидетельства единица не
снимается, поэтому она осталась отдельным пунктом-названием; исход - открыто до кейса с тестом,
сверяющим id. Пункт `sealed` «всегда через интерфейс или wrapper» снят вместе с прочими: он
противоречил YAGNI в `dex-skill-solid` (абстракция только при втором потребителе). Шов в 1.2.0
требуется там, где тест должен подставить вход, - тест и есть второй потребитель.

Прогоны редакций 1.2.0:

| Кейс | v2 (`te1`, `te2`) | итоговая (`tr*`) |
|---|---|---|
| S4 | TF, TS, TE, TR, TG 2/2 | `tr1`: TF, TS, TE, TR, TG |
| S2 | TE, FH, TS 2/2; **TF 0/2** - `File.ReadAllText` шаблона поднят как синхронный I/O и относительный путь, без шва (повтор `s2-v1`) | `tr1`, `tr2`: TF 2/2 («без шва хендлер не тестируется»), TE, FH, TS 2/2 |
| E0 | `te1` - 0 находок | `tr1` - 0 находок |

Провал TF на S2 повторился на v2 - дефект нормы: «файлу» исполнитель не связал с чтением шаблона.
Ревизия (одна из трёх допустимых, шаг 5 эпика) расширила существующее утверждение до признака:
«файлу (шаблон, справочник, временный файл)». Перепрогон - провалившийся S2 дважды, задетый S4 и
кейс «ничего не менять» E0.

Ложных находок по приманкам S4 (PS, PT) нет ни в контроле, ни со скиллом. Дефект вне скилла O1 -
во всех прогонах S4. Дефекты кейса S2 вне тестируемости (KC, KX, KQ, O1, O2) у итоговой не хуже
контроля.

Сторона автора (`dotnet-coder`, `dotnet-test-writer`) не мерилась: кейса на поручение, где код
соблазнительно зашить на внешний мир, нет. Засчитывается ли контроль ревью снятием для неё:
решение 2026-10-05 (тред PR #314) - открыто для стороны автора без возврата текста; кейс-поручение на код ставится в группе разработки эпика (группа 2).
