# ADR - чек-лист

Пункт называет ситуацию, которую ADR проверяет - при письме и при ревью.

- «Решение» описывает состояние кода вместе с нормой, или расхождение кода с нормой не записано нигде
- Пункт нормы без проверки, которая ловит нарушение, или констатация о системе вместо предписания, что делать
- Норма опирается на `file:line`, имя класса или функции
- Открытый вопрос без рабочего дефолта
- Два действующих (`Accepted`) ADR по одному предмету; править существующий ADR или заводить новый - по тому, сменился ли подход; правка не сдвигает номера пунктов, на которые ссылаются

### Источники требований смешаны в одну кучу
Плохо: все пункты одинаково «обязательные»
Правильно: у каждого пункта - источник, источники не смешиваются: обязательное по внешнему источнику (ломает контракт платформы/стандарта) / инженерно обязательный фикс (источник не требует, цена предъявлена) / инженерный инвариант (нужен для предсказуемости) / рекомендация
Почему: когда всё «обязательное», приоритет не читается. Разный источник - разная очередь внедрения и разный вес в споре
