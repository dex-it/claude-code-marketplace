## Шаг 0

- **Вводный абзац и заголовки разделов** («ADR - спецификация, по которой пишут код...», «Норма vs состояние кода»,
  «Границы и полнота», «Обоснование», «Работа с файлом ADR») - не ловушки; сняты без прогона. Строка «Применимо к
  написанию и к ревью чужого ADR» стала шапкой чек-листа: пункт называет ситуацию при письме и при ревью.
- **Дома и наследники.** «ADR описывает код вместо предписания» (AQ1, AQ2) - дом здесь, `doc-standards` (#309)
  наследует. «Нет Supersedes» при письме ADR (AQ13) - дом здесь, `doc-standards` наследует; `codebase-conventions`
  (ось ADR ревьюера) держит другую ситуацию - решение опирается на отменённый ADR при чтении цепочки, не дубль.
- **Первоисточник исхода** - MADR (канон разделов назван в `adr-writer`, Phase 3, вместе с проектным разделом
  «Расхождения с текущим кодом»). Пункты-названия его не пересказывают.
- **Входящие ссылки на правило «править существующий ADR или заводить новый»** - `adr-writer` (стр. 83, 114),
  `doc-standards` (стр. 92), `project-baseline` (стр. 96-98). Смена 1 собиралась снять правило (W2 AQ13a и W3 AQ13b -
  2/2 в контроле) и переписать `adr-writer`; набор `f` показал провал без него (W2 AQ13a 0/2), разделитель вернулся в
  пункт AQ13 (`n2`) - ссылки верны. Перечни ловушек в аннотациях `adr-writer` (стр. 63) и `doc-standards` (стр. 99)
  приведены к пунктам 2.5.0 правкой ревьюера `5b478623` (patch 3.7.1 и 1.7.1).
- **Пороги без источника** - в 2.4.0 их нет (порог AQ5 - перечень задетого, не число).
