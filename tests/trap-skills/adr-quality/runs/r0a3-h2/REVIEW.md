- Решение п.3 / Расхождения с текущим кодом - у всех уже существующих записей `media` и у записей, созданных подами api во время rolling-деплоя (до 12 раз в сутки), `preview_status` пуст; ADR не говорит, что `GET /media/{id}` отдаёт для них, не описывает бэкфилл и не говорит, в каком ключе S3 лежат уже построенные превью (`previews/<media_id>/<размер>` или иначе); клиент получит неопределённое значение контракта, а откат из «Последствий» не сможет вернуть превью старым записям в тот же ключ - major
- Решение п.3 - `no-store` для `pending` и `failed` плюс перезапрос на каждый показ: `failed` терминален, и для него каждый показ поста автора с 1 млн подписчиков уходит мимо кэша в api и на реплику; ADR отверг вариант «на лету» именно из-за такого сходящегося потока, а здесь нагрузку не оценил - реплики (70 000 чтений/с) получат постоянную добавку без верхней границы - minor
- Последствия, «цель - превью в течение минуты» и «воркеры масштабируются по глубине очереди» - норма без проверки в разделе «Проверка» и без порога автоскейла/алерта на глубину очереди и возраст `pending`; источник «минуты» не назван (PL-09 в репозитории нет, 30 мин, 1/5/15 мин - инженерный выбор без пометки); при нехватке воркеров цель молча не выполняется - minor
- Решение п.1 - «простой воркеров не размножает события» неточно: переиздание повторяется каждые 30 минут на каждую `pending`-запись, а воркер (п.2) не пропускает уже `ready`; после долгого простоя очередь содержит несколько копий каждого события и перестраивает превью по 3.9 с зря, восстановление затягивается - minor
- Решение п.4 - статус `failed` в записи и публикация в `media.preview-failed` не связаны ни порядком, ни переизданием (задача п.1 берёт только `pending`), хотя «запись - источник истины»; потерянная публикация оставляет `failed` без события, и дежурный, работающий по очереди, о нём не узнает - minor
- Последствия / Открытые вопросы - ручное переиздание `failed` дежурным media и новый воркер с пятью очередями не соотнесены с Postline Studio (on-prem, без дежурной команды, бинарная поставка на 5 лет); у on-prem-клиентов `failed` останется навсегда, состав поставки не определён - minor
