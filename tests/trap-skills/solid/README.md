## Заход группы 1.2 (2026-10-05)

Общий для пяти скиллов группы: `solid`, `ddd`, `clean-architecture` (сжаты) и `microservices`,
`distributed-resilience` (сняты, [removed/microservices](../removed/microservices/README.md),
[removed/distributed-resilience](../removed/distributed-resilience/README.md)).

**Вход.** Мини-проект [`_projects/billing`](../_projects/billing/README.md#группа-12-архитектура-в-диффе),
ветки `branches/<имя>` (стадии `main` групп 0 и 1.1 не тронуты). Ключ, сверка и перечень допустимых
решений записаны до первого прогона: кейсы A0-A4, D1, D2 - коммит `de84187a`, D3 - `8d22684d` до
прогона D3. Кейсы: A0 - чистый дифф (агрегат и слой верны, приманки DTO и тонкого хендлера), A1 -
доменная модель подписок, A2 - слои кредит-нот на EF Core + SQLite, A3 - межсервисная граница
PayGate, A4 - документы счёта и перевод оплаты на outbox; D1-D3 - проектирование с соседями,
заданными текстом задачи (Collections, Wallet, CRM). Billing - один сервис; межсервисную границу
дают соседи A3 (Notifications, CRM, Analytics, PayGate, общий Redis, пакет `Billing.Contracts`) и
текст задач D1-D3.

**Исполнитель.** `claude -p` 2.1.287, `--model claude-sonnet-5-5 --effort medium --restricted
--strict-mcp-config --no-session-persistence --disable-slash-commands --permission-mode acceptEdits
--max-budget-usd 3`, инструменты `Read, Write, Edit, Glob, Grep, Bash`, разрешён только `Bash(git *)`.
MCP нет (`init.mcp = []`), скиллов в сессии нет, `Skill` tool не вызван ни разу. Скилл подан копией
`SKILL.md` через `--add-dir`. Сборки и dotnet у исполнителя нет: ревью архитектуры её не требует.
`claude-sonnet-5` справочно не прогонялся.

**Промпт ревью** (A0-A4):

```
Ты .NET-ревьюер в команде. Git-репозиторий сервиса Billing лежит в каталоге <DIR> .
[s: Перед работой прочитай <SKILL>, ... - дисциплина, принятая в команде.]
Сделай ревью MR: ветка feature/<ветка> против main. Описание MR: «<описание>»
Запиши находки в <DIR>/REVIEW.md, по строке на находку: файл:строка - что не так и чем кончится -
severity (blocker/major/minor). Без вступлений и резюме. Код не правь.
Ограничения: не вызывай Skill tool; не меняй файлы репозитория, кроме REVIEW.md; не читай и не пиши
вне каталога репозитория[s: , кроме файлов дисциплины выше]. Сборки нет: из команд доступен только
git. В ответе - только число находок по severity.
```

**Промпт проектирования** (D1-D3): «Ты архитектор в команде сервиса Billing ... текущая ветка -
feature/<ветка>; задача - docs/tasks/<задача>. Подготовь проектное решение по задаче и запиши его в
<DIR>/DESIGN.md. Код не пиши.» - с теми же ограничениями.

**Наборы.** `c` - контроль без скилла; `n1` - названия ([solid](inputs/SKILL-n1.md),
[ddd](../ddd/inputs/SKILL-n1.md), [clean-architecture](../clean-architecture/inputs/SKILL-n1.md))
поданы вместе, как ось `architecture` ревьюеров; `n2` - итоговая редакция: на ревью solid + ddd +
clean-architecture, на проектировании ddd + clean-architecture (загрузка `architect`). По 2 прогона на
кейс; третий контрольный (`a1-c3`, `a4-c3`, `d2-c3`) - добор на спорных единицах. Выходы - `runs/`
наборов: A0, A4 - здесь; A1, A2 - [ddd](../ddd/README.md); A3, D1-D3 -
[removed/microservices](../removed/microservices/README.md).

**Засчитывание.** По ключу billing: находка стоит в месте ключа и её исход снимает дефект или его
симптом; слово ловушки не требуется. Порог-эвристика скилла судится по исходу. P - провал, если
находка по приманке требует правки blocker или major. В проектировании - решение из перечня
допустимых или ловушка, явно отвергнутая с причиной. Единица снимается при 2/2 контроля.

**Дубли шага 0** (единица живёт в одном доме, в ключе - строкой дома): анемичная модель - `ddd`
(`solid` «Anemic Domain Model» снят как дубль); бизнес-логика на конкретной инфраструктуре (DIP
`SqlConnection`) - `clean-architecture`; много зависимостей конструктора - `solid` SRP.

**Расход** (`total_cost_usd`): контроль 21 прогон $4.57, n1 12 прогонов $3.01, n2 16 прогонов $3.87,
активация $0.72; итого $12.17 из потолка $30.

**S-c - дефект кейса.** Пеню задача BILL-38 не требует; контроль снял её как лишний объём, расчёт по

**S-p.** Контроль 1/3; n1 и n2 - 2/2. Пункт YAGNI остаётся: на него ссылается протокол
