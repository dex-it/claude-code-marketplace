# Review Step-by-Step

<!-- skill-type: process -->

Замечания ревью своего MR разбираются с оператором по одному: каждый пункт проходит цикл «суть ->
вердикт -> решение оператора -> действие». Решения по скопу и публичным действиям принимает оператор.

## Порядок

1. Все пункты - в список (TaskCreate) в порядке источника до начала разбора. Решение по пункту
   записывается туда сразу: `A` делаем (коммит и ответ), `B` уже исправлено (ответ), `C` followup
   (задача по команде и ответ), `D` не делаем (ответ с причиной), `E` опровержение (доказательство кодом,
   ждём согласия). Повторное касание пункта - по списку, без переспроса.
2. Пункт: суть одной-двумя фразами, затем вердикт ПОДТВЕРЖДАЮ или ОПРОВЕРГАЮ с доказательством кодом,
   затем предложенное решение A-E. Классификация - после чтения кода, не до него.
3. Соседние использования того же механизма вне диффа - оператору находкой вне MR.
4. Стоп до решения оператора по этому пункту.

## Гейты

- Правка, коммит, ответ в MR, followup-задача - только по команде на этот пункт. Команда на один пункт не
  разрешает другие; несколько пунктов разом - только явной командой оператора.
- Молчание и реплика без решения - не апрув: переспросить.
- Опровержение - стоп до согласия оператора или ревьюера.
- Push - только по команде оператора либо после закрытия всех пунктов.

## Финал

На каждый пункт - ответ в его тред: закрыто коммитом X / вынесено в задачу Y / не делаем - причина.
Описание MR дополняется таблицей обработанных пунктов; задача в трекере после push сдвигается на
следующий статус.
