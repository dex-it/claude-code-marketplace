# rulebook-quality: сжатие по свидетельству, группа 4.8

Скилл-оракул `rulebook-quality` плагина `dex-rulebook-miner` 2.3.1 ([`inputs/SKILL-2.3.1.md`](inputs/SKILL-2.3.1.md)),
эпик #291, группа 4.8 (#309). Итог - плагин 3.0.0, вводная оракула с признаком блокирующей находки и одна H3-ловушка
([`inputs/SKILL-3.0.0.md`](inputs/SKILL-3.0.0.md)). Строка в реестре [`tests/README.md`](../../README.md).

Вход, среда, суд - как у [doc-standards](../doc-standards/README.md). Кейсы: RQ1 (вердикт по своду с дефектами),
RQ2 (малый свод: указание ИИ-ассистенту в цитате, пустой реестр), RQ0 (свод без дефекта - верный исход: `passed`,
ни одной блокирующей находки). База - сам потребитель: текст шага 2 команды `/rulebook` и `project-rulebook` с
`references/` в обоих плечах (README мини-проекта). Ключи - `_projects/classmate/key/{RQ1,RQ2,RQ0}.md`. Редакции:
s1 (`s`, название), s2 (`t`, шаг 3 - исход и граница), s4 (`u`, признак расширен), s5 (`v`, шаг 4 - H3), s11 = 3.0.0
(`j`, признак блокирующей во вводной).

## Потребители

Шаг 2 команды `/rulebook` (вердикт оракула по своду); реестр «тип -> оракул» `dex-skill-node-contract:node-contract`
(тип «свод правил проекта»); кейс активации `rulebook-quality-in`, near-miss `rulebook-quality-near-adr`.

## Тип единиц (шаг 0)

20 H3-ловушек в пяти разделах и вводная оракула. Процедур нет. Вводная (предмет, вес HIGH/MEDIUM, сверка с
`project-rulebook`) - контракт оракула, не ловушка: остаётся. Нормы ловушек держит `project-rulebook` базы
(разделы 2-5 и `references/`).

**Признак блокирующей** (`j`). Вводная s5 весила находку «помеченная блокирующей» и признака не давала: пять
блокирующих ловушек 2.3.1 сняты, их признак ушёл вместе с ними, а сам промпт RQ требует пометку у каждой находки.
В 3.0.0 признак собран из этих пяти: единицей нельзя пользоваться (якоря нет или он не открывается, противоречит
другой, не проверяема на ревью диффа, расходится с деревом без квалификации) либо непустой свод при пустом реестре
источников. `j` - RQ1, RQ2 не ниже `v`, RQ0 «-V» 2/2: `!43#t2`, `!48#t2` названы неблокирующими. Заголовок
ловушки - H3 (правило `trap-empty` валидатора), у s5 - H2.

## Открыто

- RQ0 «-V» у `c`-`h`: исход `!43#t2` в реестре источников читается как блокирующий дефект свода; на `j` с
  признаком блокирующей - 2/2, двух прогонов мало, чтобы приписать подъём признаку, а не шуму.
- RQ0 RUL-0005 (`04-signature-convention.md`): таксон `internal:signature-convention@2` у правила о формате
  хранения и передачи дат - `taxonomy.md` относит к значению форму публичной сигнатуры, значения под предмет в
  схеме нет. Блокирующей назвал g2, неблокирующей - v2 и g2 (вместе с RUL-0003). Дефект кейса, не вред редакции:
  «-Kf» его не считает; вход не правлен, чтобы не перемерять наборы `c`-`v`.

- Q13 (секрет в цитате): засеянный ключ RQ1 после прогонов заменён на `sk_live_FAKE-test-only-not-a-key` -
  push protection хостинга отклонял строку формата Stripe-ключа. Наборы `c`-`j` шли на прежней форме, выходы
  цитируют только префикс; новая форма прогоном не мерилась (журнал).
