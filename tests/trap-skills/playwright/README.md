# playwright: сжатие по свидетельству, группа 2.3

Скилл `dex-skill-playwright` 1.0.1 ([`inputs/SKILL-1.0.1.md`](inputs/SKILL-1.0.1.md)) -> 1.1.0
([`inputs/SKILL-1.1.0.md`](inputs/SKILL-1.1.0.md)), эпик #291, группа 2.3 (#298). Промежуточная редакция n1 -
названия единиц, проваливших контроль ([`inputs/SKILL-n1.md`](inputs/SKILL-n1.md)); 1.1.0 - n1 с вводной
строкой чек-листа и двумя открытыми ловушками отладки как написаны.

Вход, исполнитель (`claude-sonnet-5-5`, effort medium, `claude -p` 2.1.291, MCP нет), среда, промпты,
правило засчитывания, шаг 0 и расход - общие для группы, в протоколе
[ts-nodejs-api](../ts-nodejs-api/README.md#заход-группы-23-2026-10-06). Здесь - выходы K4 (три e2e-сценария:
вход и список заказов, отмена нового заказа, ошибка сервера при загрузке) и K5 (e2e в GitHub Actions с
материалами разбора): `runs/`. Роль - инженер автоматизации тестирования. Браузеров Playwright на машине нет:
кейсы судятся по коду и конфигу, оператор проверяет `npm run typecheck` и `npx playwright test --list`. Наборы:
K4 - `c` 6 прогонов (`c3` - добор на W7 в первой смене, `c4`-`c6` - добор на W8 во второй), `n1` 2, `f` 5
(`fc`-`fe` - добор на W1, W7); K5 - `c` 2, `f` 2.

## Потребители

Skill tool в фазе: `test-automator` (sonnet; Playwright / E2E, `[справочно]`), тематическая строка
`stack-registry` «frontend/E2E». Бандлы `qa-engineer`, `ts-fullstack`. Сноска в команде `pw-codegen` утилиты
`dex-playwright-cli`. Кейс активации `playwright-in`.

остальные - `getByRole`, `getByLabel`, `getByText` и `filter({ hasText })`. Фраза «Локаторы по CSS-классам и id
вместо роли, подписи и текста» (шаг 1 формы): n1 2/2, 1.1.0 5/5.

**W7.** Контроль 0/6: вход через форму в каждом тесте (`loginViaUi`/`loginAsAlice` в теле каждого теста или

`storageState` либо вход через `request` и токен через `addInitScript`; форма - только в тесте входа.

**W8 - наблюдение.** Единица снята по контролю: 6/6 (заказ под отмену создаётся тестом через `POST /api/orders`).
Со скиллом 5/7: `k4-n1b` и `k4-fb` отменяют заказ seed #1001 и сами пишут, что повтор на переиспользуемом сервере
упадёт (`k4-n1b` - «эндпоинта создания заказа нет», хотя он есть). Ни n1, ни 1.1.0 про данные теста ничего не
говорят; оба провала - у прогонов, ушедших в setup-проект со `storageState`. Разница 6/6 против 5/7 - в пределах
шума на таком n (точный тест Фишера, двусторонний p = 0.46); добор контроля `c4`-`c6` сделан, чтобы проверить,
не случайны ли первые 3/3, - все три прошли. Итоговая редакция по W8 формально хуже контроля; решение - в
«Открыто».
