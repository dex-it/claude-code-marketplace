Три теста на заказы написаны. Они проходят `typecheck` и видны в `playwright test --list`, но сам браузерный прогон я не запускал, потому что браузеры Playwright не установлены. Критерий «`npx playwright test` проходит локально» остаётся непроверенным.

Изменённые файлы:
- `e2e/playwright.config.ts`: добавлен проект `setup`, `chromium` зависит от него и использует `storageState` alice.
- `e2e/tests/auth.setup.ts` (новый): единственный вход через форму, токен сохраняется в `playwright/.auth/alice.json`.
- `e2e/tests/orders.spec.ts` (новый): три сценария из задачи.
- `e2e/.gitignore` (новый): игнорирует `playwright/.auth`.

Решения:
- Вход через UI выполняется один раз в setup-проекте, а не в каждом тесте. Остальные тесты берут сохранённое состояние.
- Локаторы построены по роли, подписи и тексту. Заказ ищется по номеру («Заказ #1001»), а не по позиции в списке. Ошибку загрузки создаёт `page.route`, который отвечает на `/api/orders` статусом 500.
- Тест отмены меняет данные API (заказ 1001 становится «Отменён»), поэтому повторный прогон на уже запущенном API (`reuseExistingServer`) упадёт. Нужен перезапуск API с чистым `SEED_DEMO=1`. Тест списка проверяет заказы 1002, 1003 и отсутствие 1004, но не статус 1001, поэтому от порядка с тестом отмены не зависит.
