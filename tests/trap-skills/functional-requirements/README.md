# functional-requirements: сжатие по свидетельству, группа 3.1

Скилл `dex-skill-functional-requirements` 1.2.0 ([`inputs/SKILL-1.2.0.md`](inputs/SKILL-1.2.0.md)), эпик
#291, группа 3.1 (#300). Итог - 2.0.0, trap-skill из одного пункта чек-листа
([`inputs/SKILL-2.0.0.md`](inputs/SKILL-2.0.0.md); промежуточная n1 - [`inputs/SKILL-n1.md`](inputs/SKILL-n1.md)),
строка в реестре [`tests/README.md`](../../README.md).

Вход, среда, раннер, наборы прогонов и судьи - общие для группы, описаны в протоколе
[requirement-quality](../requirement-quality/README.md); прогоны и файлы вердикта лежат там же. Скилл
мерится кейсами w2 (FR из сценариев), w2n (сценариев нет), r1 (ревью единиц), c0.

## Потребители

`requirements-analyst` (фаза разбора сценария в правила), `requirements-reviewer` (норма класса).
Бандлы `product-manager`, `system-analyst`. Словарь `docs/domain/domain-model.md` (дом термина `FR`).
Кейс активации `functional-requirements-in`.

## Тип единиц (шаг 0)

12 H3-ловушек в четырёх разделах. Процедур нет. Дубли: метод проверки (две ловушки) - дом
`requirement-quality`; «Расширение закрывают "без правила"», «Правило-догадка», «Правило переписывает
текст расширения» и «Несколько правил в пункте» - Output и Exit criteria фазы разбора
`requirements-analyst` (три исхода шага, «без правила» значит «правила не нужно», пересказ без
результата и несколько правил в предложении запрещены).

## Ревизия 2.1.0: исключение для несценарной единицы (#209, ревью PR #392)

Правка: пункт получил условие «основание «несценарное требование» не объявлено либо объявлено, хотя шаг или
расширение сценария это поведение наблюдает» ([`inputs/SKILL-2.1.0.md`](inputs/SKILL-2.1.0.md), 603 -> 727 символов, 10
строк без изменения). То же условие стоит в строке `traced from` норматива `system-requirements-29148` и в
исключении `requirements-reviewer` (законная несценарная единица дефектом не считается): автор и судья читают один
признак. Срабатывание пункта меняется, поэтому версия minor, 2.1.0. Метод (`tests/README.md`, шаг 6): перепрогон кейсов,
на которых пункт был введён.

Набор `m`: w2 и r1 по 2 на тексте 2.1.0, `nfr` и `requirement-quality` как в `f`, исполнитель и раннер как в наборе `f`
(`claude -p` 2.1.308, `claude-sonnet-5-5`, effort medium, `--restricted --strict-mcp-config`, файлы скиллов подаются
путём). Раннер - [`run-group-3-1.sh`](../_projects/rooms/run-group-3-1.sh) с лимитом $0.6 на прогон (правка копии;
каталог прогона вне репозитория). Критерий, записанный до прогонов: w2 - у каждого `FR` основание шаг или расширение
сценария, `BR` без сценария допустим только у обнуления лимита с объявленным «несценарным требованием»; r1 - FR-2004
названо с основанием `UC-2001 1a`. Суждение - читателем (автором правки) по `DIFF.patch` и `ANSWER.md`, слепого судьи
нет: в бюджет он не входит.

## Открыто

- Вторая половина условия 2.1.0 (основание «несценарное требование» объявлено, хотя шаг или расширение сценария
  поведение наблюдает) прогонами не проверена: нет засева. Кейс заводится отдельной правкой; до того половина держится
  на тексте и на совпадении формулировки в `traced from` норматива и в `requirements-reviewer`.
- Суждение набора `m` без слепого судьи (автор правки, по якорям выше).
- Нет (набор `f`). w2 на тексте 2.0.0 (`f`) взят 2/2 по веткам, D-6 и D-8, основанию и методу; провал контроля w2 по
  основанию `BR` и по допущению на D-6 со скиллом не повторился. Своих решений сверх журнала оба прогона
  `f` не скрывают: резерв лимита (`w2-f1`) и автоматический возврат (`w2-f2`) вынесены открытыми записями.
