Скилл `dex-skill-ts-nodejs-api` 2.0.1 ([`inputs/SKILL-2.0.1.md`](inputs/SKILL-2.0.1.md)) -> 2.1.0
([`inputs/SKILL-2.1.0.md`](inputs/SKILL-2.1.0.md)), эпик #291, группа 2.3 (#298). Промежуточные редакции:
n1 - только названия единиц, проваливших контроль ([`inputs/SKILL-n1.md`](inputs/SKILL-n1.md)); f1 - итоговая
первой смены ([`inputs/SKILL-f1.md`](inputs/SKILL-f1.md)): тело как у 2.1.0, в `description` было имя
переменной кейса `PAYMENT_URL` - подсказка K1, снята во второй смене, K1 перепрогнан на 2.1.0 (`f2`).

## Заход группы 2.3 (2026-10-06)

Общий для пяти скиллов группы: `ts-nodejs-api`, `react`, `playwright`, `ts-vitest-jest` (сжаты) и `ts-patterns`
(снят, [removed/ts-patterns](../removed/ts-patterns/README.md)). Протоколы соседей - [react](../react/README.md),
[playwright](../playwright/README.md), [ts-vitest-jest](../ts-vitest-jest/README.md).

**Вход.** Мини-проект [`_projects/shopdesk`](../_projects/shopdesk/README.md): монорепо npm workspaces, `api`
(Express 4.22.3, zod, TypeScript 5.9.3, Vitest 4.1.7 + supertest), `web` (React 19.2.7, Vite 7), `e2e`
(Playwright 1.63.0, браузеров нет). Ключ, сверка и перечень допустимых решений записаны до первого прогона:
коммит `caccb0c1` (08:31:23), первый прогон - 08:31:42. Буквальное чтение K1-P1 и носитель названия
`ts-patterns` - коммит `35c47a56` до прогонов носителя; чтение снято ревью #318 (протокол `removed/ts-patterns`). Express 4 выбран по ключу: на 5.x отклонённый промис
обработчика сам уходит в `next(err)`, и ловушка N1 невозможна.

Кейсы: K0 - «ничего не менять» (поле `currency` у товара); K1 - эндпоинт оплаты и HTTP-шлюз по
`docs/payments-api.md`, мины M1-M6; K2 - поиск заказов по мере ввода, мины M1-M4; K3 - unit-тесты модуля
резерва с повторами, мины shuffle и мутанты MU1-MU4; K4 - три e2e-сценария; K5 - e2e в GitHub Actions;
R1 - ревью MR админки возвратов (API); R2 - ревью MR дашборда заказов (web). Имя ловушки в поручениях не
звучит. Приманки - B1-B6 ключа, дефекты вне скиллов - O1-O4 и K*-O*.

**Исполнитель.** `claude -p` 2.1.291, `--model claude-sonnet-5-5 --effort medium --restricted
--strict-mcp-config --no-session-persistence --disable-slash-commands --permission-mode acceptEdits
--max-budget-usd 3 --max-turns 150`, инструменты `Read, Write, Edit, Glob, Grep, Bash`. MCP нет
(`init.mcp = []`), скиллов в сессии нет (`init.skills = []`), `Skill` tool не вызван ни разу; модель в `init` -
`claude-sonnet-5-5` во всех прогонах. Скилл подан копией `SKILL.md` через `--add-dir`. `claude-sonnet-5`
справочно не прогонялся.

**Среда.** Каталог прогона - копия развёрнутого шаблона `setup.sh` под `<work>/scratch/runner/runs/<id>` (`<work>` - рабочий каталог потока вне репозитория),
вне репозитория: проектного `CLAUDE.md` на пути нет, `~/.claude/CLAUDE.md` на машине нет. Bash исполняется в
песочнице Claude Code (`--settings`: `sandbox.enabled`, `allowedDomains: []`, `allowLocalBinding: true`,
`allowUnsandboxedCommands: false`). Проба до кейсов ($0.04): `tsc` - код 0, vitest зелёный, bind 127.0.0.1
(supertest) работает; `curl`, `fetch` и `npm view` наружу - отказ песочницы; `CLAUDE.md` и память в контексте
сессии нет. Зависимости ставятся `npm ci --offline` из локального кэша. Мины K1-K3 и судейские `typecheck`,
`test`, `playwright test --list` исполняет оператор после прогона (`grade.sh`), исполнителю они не подаются.

**Промпт поручения** (K0-K5):

**Промпт ревью** (R1, R2): «Ты TypeScript-ревьюер в команде ... Сделай ревью MR: ветка feature/<ветка> против

**Наборы.** `c` - контроль без скилла, по 2 прогона (добор: `r1-c3`, `r1-c4`, `k3-c3`, `k3-c4`, `k4-c3`; во второй смене `k4-c4`..`c6` - на W8);
`n1` - названия единиц, проваливших контроль; `f` - итоговая редакция первой смены; `f2` - перепрогон после

([removed/ts-patterns](../removed/ts-patterns/README.md#возврат-названием)). Скиллы на кейс - по загрузке
потребителя: K0 - ts-patterns + ts-nodejs-api + react; K1, R1 - ts-patterns + ts-nodejs-api; K2, R2 -
ts-patterns + react; K3 - ts-vitest-jest + ts-patterns; K4, K5 - playwright. Снятый скилл в `n1`, `f` не
подаётся. Выходы: K1, R1 - здесь, `runs/`; K2, R2 - [react](../react/README.md); K3 -
[ts-vitest-jest](../ts-vitest-jest/README.md); K4, K5 - [playwright](../playwright/README.md); K0 и носитель -
[removed/ts-patterns](../removed/ts-patterns/README.md).

**Засчитывание.** По ключу shopdesk: в поручении - исход в выходе (код, тест, конфиг, исполнение мин), в ревью
- находка в месте ключа, исход которой снимает дефект или называет его последствие; слово ловушки не
требуется, severity не судится. Приманка - провал, если находка по ней требует правки blocker или major.
Каждая единица судится одинаково во всех прогонах набора. Единица снимается при 2/2 контроля.

**Шаг 0: дубли и границы.** Единицы, снятые группой 1.1, не дублируются: синхронный блокирующий вызов в
async (N14) и последовательные независимые await (`ts-patterns` P6) - дом `performance-review`, где сняты
контролем 2/2; клиент на вызов (N15) - дубль снятого там же «клиент на вызов»; безмолвный fallback
(`ts-patterns` P9) - `no-loose-ends`, снят в 1.1. Механика Vitest/Jest - дом `ts-vitest-jest`, язык-независимый
дизайн тестов - `test-design` (#299, PR #317): единицы на границе не сжимались, см.
[ts-vitest-jest](../ts-vitest-jest/README.md#открыто). С `dotnet-async-patterns` (#296) и
`dotnet-testing-patterns` (#297) пересечение только по предмету (async-ошибки, изоляция тестов) - в «Открыто».

**Расход** (`total_cost_usd`): смена 1 - контроль 21 прогон $2.61, n1 12 прогонов $1.70, f 21 прогон $2.46,
