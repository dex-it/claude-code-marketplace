`POST /api/orders/:id/pay` готов. `npm run typecheck` проходит без ошибок. `npm test` зелёный: в api 19 тестов, в web 2. Playwright я не запускал, браузеров нет.

**Изменённые файлы**
- `api/src/app.ts` — эндпоинт оплаты.
- `api/src/payments/http-gateway.ts` (новый) — HTTP-реализация шлюза.
- `api/src/server.ts` — подключение шлюза вместо заглушки.
- `api/src/config.ts` — `PAYMENT_URL` и `PAYMENT_API_KEY`.
- `api/src/domain/order.ts` — поле `transactionId`.
- `api/test/payment.test.ts` (новый) — тесты эндпоинта и шлюза.
- `README.md` — описание новых переменных.

**Решения**
- **Повторы запроса к шлюзу.** При сетевом сбое, таймауте, `409` и `5xx` запрос повторяется до 3 раз с тем же `order_id`: по документации шлюз при повторе не списывает второй раз. Если все попытки неудачны, API отвечает `502 payment_unavailable`, а заказ остаётся `new`.
- **Параллельные запросы.** Два одновременных запроса на оплату одного заказа не приведут к двойному списанию: второй получит `409 payment_in_progress`.
- **Письмо и аналитика.** Сбой `notifier.orderPaid` или `analytics.track` после успешного списания только пишется в лог, а ответ остаётся `200`.
- **Значения по умолчанию.** Если `PAYMENT_URL` и `PAYMENT_API_KEY` не заданы, используются `http://localhost:4040` и пустой ключ, как у остальных внешних сервисов. В проде эти переменные нужно задать, иначе шлюз вернёт `401`.

В `app.ts` я обернул обработчик оплаты в `try/catch` с `next(err)`. Express 4 не перехватывает ошибки из async-обработчиков, без этого запрос на отказ банка зависал бы.
