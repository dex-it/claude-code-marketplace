`POST /api/orders/:id/pay` готов. `npm run typecheck` и `npm test` зелёные: в api 11 тестов, в web 2. Тесты `HttpPaymentGateway` я не писал. Он проверен только типами. Prettier в проекте нет, форматирование не проверялось.

**Изменённые файлы**
- `api/src/app.ts` — эндпоинт оплаты
- `api/src/payments/http-gateway.ts` — новый, HTTP-клиент шлюза
- `api/src/payments/gateway.ts` — добавлена `PaymentUnavailableError`
- `api/src/domain/order.ts` — у заказа появилось поле `transactionId`
- `api/src/config.ts` — `PAYMENT_URL` и `PAYMENT_API_KEY`
- `api/src/server.ts` — вместо заглушки подключён `HttpPaymentGateway`
- `api/test/orders.test.ts` — 4 теста: успех, отказ банка (402), чужой заказ (404), оплата уже оплаченного (409)

**Решения**
- **Переменные окружения.** По практике команды `PAYMENT_URL` и `PAYMENT_API_KEY` проверяются при старте: без них сервис не запускается. Из-за этого для локального запуска теперь нужно задать обе переменные.
- **Повторы запроса к шлюзу.** Шлюз идемпотентен по `order_id`, поэтому сетевые сбои, таймаут, 5xx и 409 повторяются до 3 раз тем же запросом. Если все попытки неудачны, эндпоинт отвечает `502 payment_unavailable`, и заказ остаётся `new`.
- **Параллельные оплаты.** Повторный параллельный запрос на оплату того же заказа получает 409.
- **Письмо и аналитика.** Сбои `notifier` и `analytics` после списания только логируются и не ломают ответ `200`.
- **Обработчик в Express 4.** Он не передаёт ошибки из async-обработчиков в `errorHandler`, поэтому я обернул обработчик оплаты в `.catch(next)`.
