`POST /api/orders/:id/pay` готов, шлюз подключён в `server.ts`. `npm run typecheck` и `npm test` проходят (в api 17 тестов).

**Изменённые файлы:**
- `api/src/app.ts` — эндпоинт `/pay`
- `api/src/config.ts` — `PAYMENT_URL` и `PAYMENT_API_KEY`
- `api/src/domain/order.ts` — поле `transactionId`
- `api/src/server.ts` — вместо заглушки теперь `HttpPaymentGateway`
- `api/src/payments/http-gateway.ts` — новый файл, HTTP-реализация шлюза
- `api/test/orders.test.ts` — тесты оплаты: успех, отказ, чужой и несуществующий заказ, повторная оплата, 401
- `api/test/http-gateway.test.ts` — новый файл, тесты шлюза

**Решения:**
- **Повторы к шлюзу.** При сетевом сбое, таймауте, 5xx и 409 шлюз вызывается повторно с тем же `order_id`: по контракту он не спишет деньги дважды. Если после 4 попыток результат неизвестен, ответ `502 payment_unavailable`, заказ остаётся `new`. Ответы 400 и 401 не повторяются и дают 500.
- **Защита и побочные эффекты.** Параллельная оплата одного заказа даёт `409 payment_in_progress`. Сбой письма или аналитики после списания только логируется и не ломает ответ `200`.
- **Конфиг.** `PAYMENT_URL` и `PAYMENT_API_KEY` проверяются при старте, и сервер не запустится без них. Теперь их нужно задавать везде, где он запускается, включая CI и e2e.

В Express 4 отказы async-обработчиков сами не доходят до обработчика ошибок, поэтому в `/pay` есть явный `try/catch` с `next(err)`.
