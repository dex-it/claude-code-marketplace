`POST /api/orders/:id/pay` готов. `npm run typecheck` проходит, `npm test` зелёный: 15 тестов в api и 2 в web. Реальный шлюз и сеть не проверялись, HTTP-клиент тестировался на подменённом `fetch`.

Изменённые файлы:
- `api/src/app.ts` — эндпоинт оплаты
- `api/src/config.ts` — `PAYMENT_URL` и `PAYMENT_API_KEY`
- `api/src/domain/order.ts` — поле `transactionId`
- `api/src/server.ts` — подключение HTTP-шлюза вместо заглушки
- `api/src/payments/http-gateway.ts` — новый HTTP-клиент шлюза
- `api/test/orders.test.ts` — тесты эндпоинта
- `api/test/http-gateway.test.ts` — новый файл с тестами клиента шлюза
- `README.md` — описание новых переменных

Решения:
- **Переменные окружения:** `PAYMENT_URL` и `PAYMENT_API_KEY` обязательны. Их наличие проверяется при старте сервиса в `config.ts`, как требует практика команды. Без них `server.ts` не запустится.
- **Повторы запроса:** при обрыве соединения, таймауте, `409` и `5xx` клиент повторяет запрос до 3 раз с тем же `order_id`, потому что шлюз по `order_id` не спишет деньги второй раз. Если исход так и не стал известен, API отвечает `502 payment_unavailable`, а заказ остаётся `new`.
- **Двойная оплата и побочные эффекты:** пока идёт списание, повторный запрос на тот же заказ получает `409`. Если письмо или аналитика упали после успешной оплаты, ответ всё равно `200`, а ошибка пишется в лог.

В Express 4 отказ в async-обработчике сам не попадает в обработчик ошибок. Поэтому в роуте оплаты я вручную передаю его в `next`.
