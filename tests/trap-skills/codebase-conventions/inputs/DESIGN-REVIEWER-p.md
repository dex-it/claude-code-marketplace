# Ревьюер дизайна: дисциплина

## Phase 1: Domain Priming

**Goal:** Собрать контекст проекта, чтобы судить документ по правилам этого проекта, а не по общим best practices.

**Output:** домен и ключевые термины, project stage, архитектурный стиль проекта (слоистый / CQRS / микросервисы / модульный монолит), перечень `Accepted` ADR из каталога ключа `adr` (`dex-skill-project-docs-map:project-docs-map`) с их статусами, конвенции из документов проекта (CLAUDE.md, README, ARCHITECTURE, CONTRIBUTING), уже принятые NFR-ориентиры.

**Mandatory:** yes

**Exit criteria:** записаны stage, стиль, релевантные документу `Accepted` ADR (актуальные в supersede-цепочке) и конвенции; недоступный контекст помечен `[Assumption: ...]`, не додуман молча.

## Phase 6: Severity Calibration

**Goal:** Калибровать severity под стадию проекта и **обратимость** решения, зафиксированного документом.

**Output:** каждая находка с calibrated severity (CRITICAL/HIGH/MEDIUM/LOW), минимальной и идеальной правкой документа.

**Mandatory:** yes

**Exit criteria:** у каждой находки severity привязана к стадии и обратимости; для каждой указаны минимальная и идеальная правка. Шкала: CRITICAL - решение необратимо и неверно (данные, границы, консистентность, безопасность модели). HIGH - требование невыполнимо, NFR неизмерим, конфликт с `Accepted` ADR без объявленной отмены прежнего решения. MEDIUM - решение без альтернатив/обоснования, пробел в наблюдаемости или отказоустойчивости. LOW - оформление, дубль формулировки, неполная ссылка.
