# codebase-conventions: сжатие по свидетельству, группа 0

Скилл `dex-skill-codebase-conventions` 1.10.0 ([`inputs/SKILL-1.10.0.md`](inputs/SKILL-1.10.0.md)),
эпик #291, группа 0 (#292). Вход - общий мини-проект [`_projects/billing`](../_projects/billing/README.md),
ключ там же. Исполнитель - sonnet (нижний тир потребителей: `dotnet-coder`, `self-reviewer`),
субагент без `Skill` tool, сборка и dotnet разрешены. Прогон со скиллом подаёт копию `SKILL.md` путём.

## Промпты

Ревью - общий с набором [fact-verification](../fact-verification/README.md#заход-группы-0-звенья-каскада-2026-10-04);
описания MR:

- R1: «Напоминания о просрочке: ежедневно в день срока оплаты и после него клиенту уходит письмо через
  Mailer; за каждый день просрочки начисляется пеня 0,1% суммы счёта и проводится в Ledger. Повторное
  выставление счёта клиенту на ту же дату обновляет сумму. Повторная оплата оплаченного счёта -
  ошибка. Заодно: повтор проводки в Ledger при таймауте, допустимые валюты счёта - из конфигурации.»
- R0: «Котировка счёта с НДС страны клиента: GET /invoices/{id}/quote?currency=&country= возвращает
  нетто, НДС и итог в валюте котировки; ставка НДС - из налогового сервиса.»
- R2: «Повторное выставление счёта клиенту на ту же дату заменяет прежний неоплаченный счёт, а не
  создаёт второй.»

Фича F1:

```
Ты .NET-разработчик в команде. Git-репозиторий сервиса Billing лежит в каталоге <DIR> .
[s: Перед работой прочитай <SKILL> - дисциплина, принятая в команде.]
Поручение: «Добавь частичный возврат по оплаченному счёту: POST /invoices/{id}/refunds с суммой в
минорных единицах. Сумма всех возвратов по счёту не больше суммы счёта. Возврат проводится в Ledger.»
Код пиши в репозиторий, не коммить. Ограничения: не вызывай Skill tool; не читай и не пиши вне
каталога репозитория и <TMP>, кроме [s: файла дисциплины выше и] кэша NuGet и SDK, которыми
пользуется dotnet. В ответе - только список изменённых файлов.
```

Коды в `runs/`: `c` - контроль без скилла (общий с fact-verification на R1, R0), `n1` - редакция
[`SKILL-n1.md`](inputs/SKILL-n1.md) (вводная и два названия: doc-комментарий, имя вслед за
поведением), `v11` - 1.11.0, чек-лист названий ([`SKILL-1.11.0.md`](inputs/SKILL-1.11.0.md)) по прогону на кейс; R2 - `r2b-v11`, `r2b-v11b` с пунктом об имени названием (F1), `r2b-v11c`, `r2b-v11d` - названием с исходом (F4); `v11e` - итоговая редакция с названиями-ситуациями (R1, R0). `r2` - R2 первой
редакции, `r2b` - после исправления кейса.

Оговорка: репозиторий кейсов мал, все ADR и свод читаются одной командой, поэтому контроль не мерил
поиск источника - то, ради чего ось 6, гейт и свод существуют. Снять их по такому свидетельству
нельзя, поэтому они стоят названиями по форме пункта (дефолт лестницы), а ступень выше решит кейс
на большом репозитории.

Пункт об имени: контроль на R2 не назвал расхождение имени `AddAsync` с поведением ни в одном из 4
прогонов, `n1` с одним названием - 4/4. Пункт doc-комментария `n1` не дал (`r2b-n1b` пропустил,
контроль 2/2), в 1.11.0 его нет.

## Дефекты кейсов

- R1: `CreateInvoiceHandler` стал upsert, doc-комментарий `NotificationRequest` назвал Mailer. Ключ
  спорный: create-or-update заявлен в описании MR, тип - проводной контракт Mailer. Из ключа R1
  выведены, предмет перенесён в R2.
- R2: doc-комментарий `Invoice` называл несуществующего потребителя («выгрузка в отчёт финансового
  отдела»), находка смешивала предмет ловушки с ложностью утверждения. Заменён реальными хендлерами,
  перепрогон - `r2b`.

шаг выше. Исход называет оба верных варианта (имя сменено либо поведение вынесено из метода), чтобы
второй не объявлялся дефектом; с ним 2/2. Прочие пункты остаются названиями: F1 прошёл R1, R0, F1.

Accepted ADR»), а не ситуацию, которую проверяет код или находка; переписаны ситуацией-ошибкой
(«Решение или находка опирается на отменённый ADR»). Перепрогон `v11e`: R1 5/5, P3 и P4 не
подняты; R0 без находок против ADR-0005 и ADR-0007.
