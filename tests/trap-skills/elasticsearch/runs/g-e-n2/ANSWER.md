Задача FUL-15 выполнена в рабочем дереве, без коммита. Сборки и тестов не было: недоступны, API клиента 9.5.3 писал по памяти. Первая сборка в CI может показать расхождения в именах типов.

**Изменённые файлы** (всё новое, кроме `Program.cs`):
- `src/Fulfil/Program.cs`: подключены `AddProductSearch()` и `MapProductSearch()`.
- `src/Fulfil/Search/ProductDoc.cs`: документ индекса и модели запроса и ответа.
- `src/Fulfil/Search/ProductIndexer.cs`: создание индекса, загрузка, переключение алиаса.
- `src/Fulfil/Search/ProductSearchService.cs`: поиск, фасеты категорий, выгрузка.
- `src/Fulfil/Search/CatalogReindexService.cs`: ночная пересборка и пересборка при старте.
- `src/Fulfil/Search/SearchEndpoints.cs`: регистрация клиента ES (по ADR-0001) и маршруты `/search`, `/search/export`.

**Решения**
- **Дисциплина:**
  - Русский текст идёт в поле `name`/`description` с анализатором `russian`, английский — в подполя `.en` с `english`. Поиск идёт по обоим, вес названия ×3.
  - Загрузка: один читатель каталога, 4 параллельных bulk по 2000 документов, retry. Для нового индекса `refresh_interval=-1` и 0 реплик, потом refresh и `1s`.
- **Пересборка без остановки поиска:**
  - Каждый раз строится новый индекс `products-v{N}-{время}`, затем атомарно переключается алиас `products`, старый индекс удаляется. При ошибке недостроенный индекс удаляется, старый продолжает работать.
  - При смене схемы нужно увеличить `SchemaVersion`: сервис пересоберёт индекс при старте.
  - Реплик сервиса три, поэтому исполнитель выбирается блокировкой-документом в индексе `fulfil-locks` (TTL 3 часа).
- **Категории и выгрузка:**
  - Категория идёт в `post_filter`, а счётчики считаются по запросу и цене. Так в списке остаются все категории, а не только выбранная.
  - Страница ограничена окном в 10 000 записей (при странице 20 это 500 страниц), дальше — 400.
  - `/search/export` читает через PIT и `search_after` по `sku`, отдаёт массив потоком, максимум 200 000 товаров.

**Что ещё нужно:** в репозитории нет реализации `ICatalogSource`, и я её не регистрировал. Пока она не добавлена в DI, `ProductIndexer` не создастся и сервис упадёт при старте.
