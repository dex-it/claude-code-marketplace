# Decision Log

<!-- skill-type: process -->

`decision-log` - дом оснований набора требований: решение человека, допущение, открытый пункт, закрытая развилка с отклонёнными вариантами. Ход работы и служебное состояние прогона в него не пишутся. Один `decision-log` на фичу, лежит в корпусе фичи и едет с MR. Термин пиши дословно - `decision-log`, без синонимов.

## Владелец журнала

Заводит и пишет его владелец журнала - команда зоны, оркестратор или оператор, ведущие фичу и передающие путь узлам полем `decision-log`; кем владелец бывает среди узлов и ветки по входу узла - `dex-skill-node-contract`, `references/decision-log-ownership.md`. До первого спавна владелец разрешает журнал:

| Состояние | Действие |
|---|---|
| файл по адресу корпуса есть | передать путь |
| файла нет, а артефакты фичи ссылаются на его записи | утрата (ниже), файл не заводится |
| файла нет и ссылок нет | завести файл, передать путь |
| корпуса с фичей нет | узлам `decision-log: n/a (корпуса нет)`, решения - перечнем в выходе владельца |

Остальные узлы в файл не пишут: строки решений возвращают в выходе (своего решения нет - пустой перечень), владелец дописывает их тем же действием, каким закрывает фазу, не дублируя записанную развилку. Набор допущен -> владелец дописывает черту ревизии («набор допущен, ревизия N»); продолжение читает действующие записи, отменённые и закрытые - адресно по номеру.

## Запись

Решение - сначала записью, потом числом в требовании; основание единицы несёт номер записи. Смена решения - пересмотр: прежняя запись помечается отменённой со ссылкой на новую, зависимые ищутся по номеру записи. Находка гейта с исходом - записью, не только вердиктом в `quality-checks`.

**Неизвестное - запись открытого пункта, а не пометка в тексте единицы.** Запись называет, что неизвестно и чей ответ; единица ссылается на неё. Допущение, принятое за постановщика, - запись с исходом «открыто», пока его не подтвердили. Открытые пункты прогон не закрывает молча - перечнем наверх. Журнал правится вместе с правкой требований: поручение без правки корпуса (вопрос, справка) журнал не трогает, замеченное неизвестное идёт в ответ.

Правка мимо конвейера: текст единицы расходится с ревизией, по которой судили, - дефект: правка проводится заново либо вердикт снимается.

## Утрата

Файла нет, а основания единиц ссылаются на его записи - утрата объявляется в выходе. Основания задетых единиц - «поднять заново» списком к принявшему решения; спавненный узел возвращает список наверх со `status: partial`. Записи не воссоздаются ни по тексту требований, ни по памяти сессии (выведенное из текста - допущение, не решение), номера утраченных записей новым решениям не выдаются.

После свёртки контекста продолжение начинается с чтения `decision-log`: развилка ищется в нём до того, как её предъявят человеку.
