## Ревизия 3 по ревью владельца (PR #368)

Два пункта переписаны по замечаниям mmx003 (`inputs/SKILL-1.1.0.md`, прежняя редакция - `SKILL-1.1.0-r1.md`): J4 вернул условие
«когда провал одной ветки обесценивает остальные» (в 1.0.1 оно было, при сжатии выпало: пункт требовал `failFast` для любого `parallel`);
J5 назван признаком ширины видимости («Credentials, видимые всем пайплайнам контроллера»), а не «в global scope»: в терминах Jenkins
global - как раз scope для пайплайнов, System видит только контроллер, а ловушка 1.0.1 была про хранилище уровня Jenkins против
хранилища папки. Ключ `j-w` не меняется (J4 судится по ключу `failFast true` у `parallel` unit/integration; J3, J8 - как раньше; J5, J9, J10
`unverifiable`). Правило набора записано до прогонов: `j-w` с шестью итоговыми редакциями (`g1`, `g2`), оценка не хуже контроля
(0/2 на J3, J4, J8) и не хуже редакции 1 (2/2).

Итог `g1`, `g2` (2026-10-20, CLI 2.1.303, `skills=[]`, `esc=[]`, $0.33 за два запуска): J3 2/2 (`beforeAgent true` у `when` стадий со своим `agent`;
`when` внутри стадии без своего `agent` и у `input` не затронуты), J4 2/2 (`failFast true` у `parallel` unit/integration), J8 2/2 (`cleanWs`);
J5 в `g2` выведен в верном направлении (credentials ограничены папкой или job, не видны всему контроллеру), в `g1` не затронут. Не хуже
редакции 1 и контроля. Вердикт J3, J4, J8 - как в таблице группы.

Кейс «ничего не менять» `n-ci` на шести итоговых редакциях ревизии 3 (`n-ci-r31`, `n-ci-r32`, ревью mmx003, раунд 3): правки только в `src/` и `tests/`,
приманки не названы, `/version` за ключом с тестом - 2/2, не хуже контроля; подробности в [протоколе группы](../removed/docker/README.md#итоговая-редакция-и-ревизии).
