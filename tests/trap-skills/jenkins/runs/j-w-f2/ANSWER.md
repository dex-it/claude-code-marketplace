**Замечания к задаче**
1. **Лок-файлов нет.** `packages.lock.json` в репозитории нет, а без `dotnet` я их создать не мог. Пока кто-то не выполнит `dotnet restore` и не закоммитит лок-файлы, стадия Restore упадёт на `--locked-mode`. В `Dockerfile` restore тоже без locked-режима и без копирования лок-файлов, его я не менял.
2. **`deploy.sh` нет.** Скрипта в репозитории нет. В задаче не сказано, как он узнаёт тег образа. Я `IMAGE_TAG` ему не передаю, и деплой-стадии идут на другом агенте, а не там, где собран образ. Нужен контракт, например аргумент `--image`.
3. **Токен виден в процессах.** Токен передаётся аргументом, поэтому он виден в `ps` на общем агенте. Лучше, чтобы `deploy.sh` читал его из окружения.
4. **Форки.** Integration-тесты из PR запускают чужой код с доступом к Docker на постоянных агентах. В job нужно оставить доверие к форкам только для участников и включить обнаружение тегов (иначе тег образа не вычислится). Тесты PR не получают секретов: push и деплой только для `main`.
5. **Required checks.** Обязательность проверок в защите ветки GitHub (требование `ci-gates`) настраивается вне репозитория. Это нужно сделать отдельно.
6. **Плагины.** Нужен плагин MSTest для публикации trx.
7. **Подтверждение prod.** Для `input` не задан `submitter`: в задаче не указано, кто «лид». Стоит ограничить подтверждение его учёткой или группой.
