Я написал `Jenkinsfile` в корне репозитория. Запустить и проверить его нельзя: Jenkins, сборки и сети здесь нет. Ничего не закоммичено.

**Изменённые файлы:** `Jenkinsfile` (новый).

**Что в нём сделано**
- **Структура:** declarative, на верхнем уровне `agent none`. Сборка, анализ, тесты, образ и push идут в одной стадии `CI` на ноде `dotnet-linux`, а после неё `cleanWs`. Деплои идут каждый на своей ноде `dotnet-linux` и тоже с `cleanWs`.
- **Тесты:** unit (`Category=Contracts`) и integration (`Category=Integration`) идут параллельно с `failFast true`. Для trx используется `xunit(MSTest(...))`.
- **Подтверждение prod:** `input` стоит в отдельной стадии без агента, таймаут 3 дня. Нода на время ожидания не занята, а лид может ответить на следующий день.
- **Агенты и `when`:** у стадий деплоя со своим `agent` стоит `when { beforeAgent true; branch 'main' }`.
- **Библиотека:** `@Library('depot-pipeline-lib@v1.4.0')`, закреплена на релизном теге. `main` и `-rc1` не берутся. `notifySlack(currentBuild.currentResult)` вызывается в `post always`.
- **Тег образа:** `git fetch --tags`, затем фильтр `^v\d+\.\d+\.\d+$` и `sort -V | tail -1`, затем `-<BUILD_NUMBER>`. Пререлиз-теги в расчёт не берутся.
- **Секреты:** `registry-creds` и `deploy-token` подключаются через `withCredentials`, только в push и в деплоях, а они идут только на `main`. Поэтому PR из форков до секретов не доходят. Логин в Docker идёт через `--password-stdin` во временный `DOCKER_CONFIG`, после пуша делается `logout`.
- **Гейты по `ci-gates`:** добавил стадии `dotnet format --verify-no-changes` и аудит уязвимых зависимостей. `dotnet list package --vulnerable` всегда возвращает 0, поэтому я ищу уязвимости в его отчёте и валю сборку.

**Замечания к задаче**
1. **Лок-файлов нет.** В репозитории нет `packages.lock.json`, поэтому `restore` идёт без `--locked-mode`, а это нарушает `ci-gates`. Нужно сгенерировать лок-файлы (`RestorePackagesWithLockFile`) и добавить `--locked-mode`. Без `dotnet` я этого сделать не мог.
2. **Required checks.** Обязательные проверки для мержа настраиваются в защите ветки `main` на GitHub, а не в репозитории. Это нужно сделать отдельно.
3. **Форки.** В настройках GitHub Branch Source нужно поставить доверие «только от пользователей с правом записи». Иначе форк может подменить `Jenkinsfile` и вытащить секреты. Кроме того, integration-тесты из форка запускают Docker на постоянной ноде. Если origin в PR-сборке указывает на форк, `git fetch --tags` может не получить теги, и тогда стадия `Образ` упадёт. Это надо проверить на первом PR.
4. **Credentials.** `registry-creds` и `deploy-token` нужно создать в folder scope, а не в global (дисциплина `jenkins`).
5. **Токен в аргументах.** `./deploy.sh --token` передаёт токен в аргументах процесса. Его видно в `ps` на общей ноде, и лучше научить скрипт читать токен из окружения. Jenkins токен в логе маскирует.
6. **Тег в `deploy.sh`.** `deploy.sh` не получает тег образа, поэтому непонятно, что именно он деплоит. Нужно уточнить его контракт.
7. **Кто подтверждает prod.** Я не знаю, кто из команды имеет право подтвердить prod, поэтому `submitter` у `input` не задан. Подтвердить сможет любой, у кого есть права на job.
8. **Плагины.** Нужны плагины xUnit и Pipeline Utility Steps/Workspace Cleanup (`cleanWs`). Плагины на рабочем Jenkins массово обновлять не стоит.
9. **Push только с `main`.** Образы из остальных веток собираются, но не пушатся. Если нужно пушить и их, это правка одного `when`.
10. **Тестов мало.** Интеграционный тест в `StockTests.cs` сейчас заглушка: Postgres он не поднимает и ничего не проверяет.
