# nfr: сжатие по свидетельству, группа 3.1

Скилл `dex-skill-nfr` 1.2.0 ([`inputs/SKILL-1.2.0.md`](inputs/SKILL-1.2.0.md)), эпик #291, группа 3.1
(#300). Итог - 2.0.0, trap-skill из трёх пунктов чек-листа ([`inputs/SKILL-2.0.0.md`](inputs/SKILL-2.0.0.md)),
строка в реестре [`tests/README.md`](../../README.md).

Вход, среда, раннер, наборы прогонов и судьи - общие для группы, описаны в протоколе
[requirement-quality](../requirement-quality/README.md); прогоны и файлы вердикта лежат там же. Скилл
мерится кейсами w2 (FR/NFR из сценариев), w2n (NFR без сценариев), r1 (ревью единиц), r2 (ревью набора).
Набор `v` по nfr не гонялся: первый черновик (`s`) прошёл, текст 2.0.0 = n1.

## Потребители

`requirements-analyst` (фаза меры), `domain-analyst` (сквозная мера `NFR-P`), `requirements-reviewer`
(норма класса), `design-reviewer`; ревьюеры кода `mr-reviewer`, `self-reviewer`, `mr-check-reviewer`,
`security-reviewer` и `diagram-creator` в строках загрузки больше его не называют - их предмет
(security NFR, SLA) снят; скилл `idea-forming`. Бандлы `architect`, `dotnet-developer`,
`dotnet-fullstack`, `product-manager`, `system-analyst`. Кейс активации `nfr-in`. Словарь
`docs/domain/domain-model.md`: дом термина `NFR` - `requirements-analyst` (ветка меры), как у `FR`; 2.0.0
определения термина не несёт (ревью PR #335).

## Тип единиц (шаг 0)

15 H3-ловушек в трёх разделах. Процедур нет. Security-раздел (IDOR, multi-tenant, секреты, аудит)
проверен на r1 и w2 как остальные.
