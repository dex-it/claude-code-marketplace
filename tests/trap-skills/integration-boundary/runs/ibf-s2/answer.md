Поиск для поддержки (PAR-31) сделан: `GET /api/support/orders?q=…` работает, `npm test` проходит (43 теста, 0 падений).

**Что сделано**
- **Эндпоинт.** `searchOrders` в `src/http/orders-api.js` и маршрут в `src/http/server.js`. Строка короче 2 символов или отсутствующий `q` дают `400 { "type": "query-too-short" }`. Иначе возвращается массив ресурсов заказа через `toOrderResource`, то есть в том же виде, что `GET /api/orders/:id`. Заказы идут новые сверху, не больше 50.
- **SQLite-хранилище (`src/db/sqlite-store.js`).** Поиск делается в базе, заказы в память не выгружаются: `searchByCustomerName(query, limit)` с `instr(...) LIMIT`. Штатный `LIKE` и `lower()` в SQLite приводят регистр только у ASCII и кириллицу не находят. Поэтому имя в нижнем регистре, приведённом в JS, хранится в новом столбце `customer_name_lc`. У баз, созданных до этой задачи, столбец добавляется и заполняется при старте. `%` и `_` в запросе ищутся как обычные символы.
- **Хранилище в памяти (`src/store.js`).** Тот же метод для тестов. README обновлён.
