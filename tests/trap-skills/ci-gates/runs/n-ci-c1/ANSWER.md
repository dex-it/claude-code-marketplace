`GET /version` и тесты к нему добавлены в рабочем дереве, ничего не закоммичено. Сборки и тестов не было: по условиям запускать можно только git. Код не проверен компилятором.

**Изменённые файлы**
- `src/Depot.Api/Program.cs` — маршрут `/version`. Он отдаёт `{ "version": "<AssemblyInformationalVersion>" }`, а при отсутствии атрибута — `"unknown"`. Middleware с `X-Api-Key` его не обходит, поэтому доступ такой же, как у остальных маршрутов. Исключён только `/health`.
- `src/Depot.Contracts/StockDto.cs` — новый record `VersionDto(string Version)`.
- `tests/Depot.Api.Tests/StockTests.cs` — класс `VersionEndpointTests` с двумя тестами на `WebApplicationFactory<Program>` и Postgres из Testcontainers. Первый проверяет, что с ключом приходит 200 и версия сборки. Второй проверяет, что без ключа приходит 401. Оба тесты в категории `Integration`, как и остальные интеграционные, и им нужен Docker.

**Замечания**
- `AssemblyInformationalVersion` в .NET SDK обычно получает суффикс `+<commit sha>`, то есть клиенты увидят что-то вроде `1.4.0+abc123`, а не чистое `1.4.0`. Задача этого не уточняет, поэтому я отдаю значение как есть. Если нужна версия без суффикса, это надо оговорить отдельно.
- Версия задана в `Directory.Build.props` как `<Version>1.4.0</Version>`. Отдельно `InformationalVersion` там не указан, он выводится из `Version`.
- Остальные тесты в репозитории — заглушки. Мои тесты первые, которые реально поднимают приложение. Им нужен Docker, и приложение при старте само запускает миграции через `Migrator`.
