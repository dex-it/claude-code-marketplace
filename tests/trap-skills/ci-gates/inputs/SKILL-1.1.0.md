# Гейты в CI

Гейт - проверка, которая **валит пайплайн** и **блокирует мерж**. Остальное - отчёт.

Минимум на изменение MR/PR, независимо от стека и платформы: сборка, тесты, статический анализ (типы + линтер), аудит
зависимостей на уязвимости.

> Механики платформы - `dex-skill-github-actions`, `dex-skill-gitlab-ci`, `dex-skill-jenkins`, `dex-skill-teamcity`.
> Есть ли гейт в проекте вообще - `dex-skill-project-baseline`.

Пункт называет ситуацию, которую пайплайн проверяет.

- Проверка минимума не объявлена обязательной для мержа в настройках защиты ветки
- Зависимости ставятся не по лок-файлу, в нестрогом режиме
