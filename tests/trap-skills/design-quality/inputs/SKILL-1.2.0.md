# Design Quality - чек-лист

Судит дизайн-документ целиком - выход архитектора: драйверы, альтернативы, выбранное решение, deep dive.
Выбор оракулом не судится. План реализации - отдельный артефакт со своим оракулом (`dex-skill-plan-quality`).

Вход - дизайн-документ и набор требований, из которого он вырос. Грузит судья, не автор (`node-contract`
п.7 раздела B): ревьюер дизайна либо потребитель. Автор прогоняет его самоконтролем, результат кладёт в
`self-check`, метку `quality-checks` не ставит.

Пункт называет ситуацию, которую дизайн проверяет.

- Решение с длинным следом (формат хранения, внешняя зависимость, контракт наружу), у которого способ и цена отката не названы
