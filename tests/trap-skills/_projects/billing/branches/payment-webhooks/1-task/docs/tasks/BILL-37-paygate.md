# BILL-37: Оплата через PayGate, кредитный баланс, квитанции

Billing принимает оплату счетов через провайдера PayGate и ведёт кредитный баланс клиента.

Контекст: Billing работает в трёх репликах за балансировщиком, в Kubernetes. Соседние сервисы:
Notifications (команда Comms, отправка писем, `POST /v1/emails`, принимает заголовок
`Idempotency-Key`), CRM (команда Sales, владеет данными клиентов, `GET /v1/customers/{id}`),
Analytics (команда Data). Общий Redis кластера доступен всем сервисам.

- PayGate шлёт вебхук `POST /webhooks/paygate` о платеже: `pspReference`, `merchantReference`
  (id счёта), `amountMinor`, `currency`, `eventCode` (`AUTHORISATION`), `success`. Доставка
  at-least-once: повтор на любой ответ, кроме 2xx, и изредка повтор после 2xx. Запрос подписан
  HMAC в заголовке `X-PayGate-Signature`.
- Оплата полной суммой (в валюте счёта или в другой - пересчёт по курсу на момент операции,
  ADR-0005): счёт оплачен, проводка в Ledger через outbox (ADR-0006). Переплата - на кредитный
  баланс клиента. Платёж меньше суммы счёта счёт не оплачивает, сумма уходит на баланс.
- Кредитный баланс клиента - в Redis, общий для реплик. Оплата счёта балансом:
  `POST /invoices/{id}/pay-from-balance`.
- Баланс, не пополнявшийся 365 дней, сгорает - ночной задачей.
- Квитанция об оплате - письмом через Notifications на email клиента из CRM. Письмо некритично:
  оплата не зависит от доступности Notifications. Статус квитанции - `GET /invoices/{id}/receipt`.
- Событие об оплате счёта получает Analytics; контракт событий для других команд - пакет
  `Billing.Contracts`. Оплата не зависит от доступности Analytics.
- Поддержка по `pspReference` находит цепочку «вебхук -> проводка -> письмо» в логах всех
  сервисов.
- Kubernetes: liveness `/health/live` (рестарт пода), readiness `/health/ready` (снятие с
  балансировщика).

Вне задачи: возвраты через PayGate, частичная оплата нескольких счетов одним платежом.
