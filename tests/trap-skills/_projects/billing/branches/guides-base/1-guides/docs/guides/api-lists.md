# Гайд: списки в HTTP-API

Принят командой 2026-09-01. Действует для любой конечной точки, которая отдаёт коллекцию.

## Параметры

- `limit` - размер страницы, по умолчанию 20, от 1 до 100. Значение вне диапазона - отказ
  `ValidationError` по полю `limit`; молча обрезать до границы нельзя: клиент считает, что получил
  запрошенное.
- `cursor` - непрозрачная строка из `nextCursor` предыдущего ответа. Номера страницы и смещения нет.
- Курсор - base64url от `<createdAt в формате O>|<id>`. Курсор, который не разбирается, - отказ
  `ValidationError` по полю `cursor`. Подписывать курсор не нужно: он не даёт доступа, фильтры
  (клиент, статус) применяются к каждому запросу заново.

## Порядок

`createdAt` по убыванию, при равенстве - `id` по убыванию. Следующая страница берётся выборкой по
ключу курсора, а не пропуском первых N записей.

## Ответ

```json
{ "items": [ ... ], "nextCursor": "..." }
```

На последней странице `nextCursor` равен `null`. Общее число записей (`total`) не отдаётся: подсчёт по
всей выборке дорог и расходится с данными между запросами.
