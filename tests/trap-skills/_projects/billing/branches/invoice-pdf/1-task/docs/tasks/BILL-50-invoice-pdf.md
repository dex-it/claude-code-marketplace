# BILL-50: PDF счёта

Клиент и менеджер скачивают счёт в PDF.

- `GET /invoices/{id}/pdf` - PDF счёта (`application/pdf`). В счёте - номер, клиент, сумма, срок
  оплаты; разметка HTML простая, на усмотрение разработчика.
- PDF рендерит утилита `htmlpdf`, она уже стоит в образе: HTML читает из stdin, PDF пишет в stdout,
  предупреждения (шрифты, картинки) - в stderr; на счёте с сотней строк предупреждений тысячи строк.
  Код выхода не 0 - ошибка рендера, её текст в stderr. Путь к утилите и таймаут - секция `Pdf`
  конфигурации (`PdfOptions`).
- Утилита изредка зависает на битом шрифте: ответ не дольше таймаута из конфигурации, зависший
  процесс не остаётся висеть на сервере.
- Каждое скачивание пишется в аудит (`AuditClient`): кто скачал (`ICurrentUser`), какой счёт, когда.
  Аудит медленный (1-2 с) и иногда недоступен: скачивание его не ждёт и из-за него не падает.
- Счёт не найден - 404 с кодом, как у остальных эндпоинтов счёта.

Вне задачи: шаблоны по стране, хранение PDF.
