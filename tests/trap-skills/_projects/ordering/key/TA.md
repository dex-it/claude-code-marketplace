## Ключ TA1 / TA0 (`tech-audit` 1.0.2)

Единицы дублей наследуют вердикт: «Подход без альтернатив» - `design-quality` DQ5 (снята 2/2), «только плюсы» - DQ6 (снята), deprecated - `tech-evaluation` TE5 (снята).
Собственные единицы:

| Код | Единица | Верно (TA1) |
|---|---|---|
| T1 | аудит без анализа идеи | AUDIT.md начинается с проблемы и цели («что, зачем, для кого»), называет, что RFC их не формулирует |
| T2 | нет «что будет если не делать» | названа цена бездействия или её отсутствие в RFC |
| T4 | нет матрицы было - стало | названа смена семантики доставки (at-least-once -> at-most-once, потеря при разрыве подписчика) по сценариям |
| T5 | breaking changes без доказательств | «обратная совместимость сохранена» оспорена: названы потребители из `docs/services.md` (`billing-worker`, `audit-sink`), которым нужна гарантия |
| T6 | компонент без проверки лимитов | у Redis Pub/Sub названо отсутствие хранения / доставки при отключении подписчика |
| T7 | совместимость компонентов | Dapper рядом с EF Core: две транзакции |
| T8 | вердикт без impact | для рисков - вероятность, последствие, митигация |
| T9 | APPROVE с блокерами | вердикт CONCERN или REJECT; APPROVE - провал |
| T10 | нет явного Out of Scope | AUDIT.md называет, что не проверялось |
TA0: верный исход - APPROVE либо CONCERN без блокирующих; блокирующая находка по приманкам - провал: D1 «срок поддержки RabbitMQ» - довод, не дефект; D2 раздел «Вне рамок RFC» полон; D3 отсутствие нагрузочного теста названо в «Вне рамок».
