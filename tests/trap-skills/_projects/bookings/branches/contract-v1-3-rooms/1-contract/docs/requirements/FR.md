# Функциональные требования: Bookings

Сервис бронирования переговорных. Участник (сотрудник с ключом доступа) бронирует комнату на время;
администратор управляет любыми бронями. Время в API - UTC.

| ID | Требование |
|---|---|
| FR-01 | Участник видит перечень комнат офиса (название, вместимость 1..50, этаж, оснащение) и карточку комнаты. В офисе до 200 комнат. |
| FR-02 | Участник видит брони комнат за период: по комнате или по всем комнатам, постранично. |
| FR-03 | Участник бронирует комнату на время: комната, название встречи (до 120 символов), начало, длительность, необязательный комментарий (до 500 символов). Владелец брони - участник, создавший её. |
| FR-04 | Участник видит бронь по её идентификатору; чужие брони видны всем участникам. |
| FR-05 | Бронь начинается в будущем и не дальше 90 дней от текущего момента. |
| FR-06 | Владелец переносит бронь на другое время; перенос по устаревшим данным (бронь изменилась после чтения) отклоняется. |
| FR-07 | Владелец отменяет бронь; отменённая бронь остаётся в истории со статусом «отменена» и не занимает комнату. |
| FR-08 | Длительность брони - от 15 минут до 4 часов включительно, кратно 15 минутам. |
| FR-09 | Две активные брони одной комнаты не пересекаются по времени. |
| FR-10 | Переносить и отменять бронь может её владелец или администратор. |
| FR-11 | Повторная отмена уже отменённой брони безвредна: результат тот же, что у первой. |
| FR-12 | Любой запрос к сервису - только с ключом доступа участника или администратора. |
| FR-13 | Участник видит свободное время комнаты на выбранную дату; дата и границы суток - в часовом поясе комнаты. |
