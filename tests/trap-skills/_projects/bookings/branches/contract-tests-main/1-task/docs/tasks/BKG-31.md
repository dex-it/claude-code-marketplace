# BKG-31. Интеграционные тесты API по контракту

**Тип:** задача · **Приоритет:** высокий · **Автор:** QA (М. Соколова) · **Исполнитель:** разработчик сервиса

## Контекст

Перед выпуском мобильного клиента QA просит закрыть API бронирований интеграционными тестами.
Источник истины о поведении - контракт `api/openapi.yaml` (1.2.0) и требования
`docs/requirements/FR.md`. Тестов в репозитории сейчас нет.

## Что сделать

- Завести тестовый проект и покрыть интеграционными тестами операции комнат (`/api/v1/rooms...`) и
  броней (`/api/v1/bookings...`) по контракту: успешные ответы и ответы ошибок, которые контракт
  описывает.
- Пакеты - из одобренного перечня `Directory.Packages.props`, без внешних источников.

## Готово, когда

- `dotnet test` зелёный локально;
- расхождения реализации с контрактом, если тесты их найдут, перечислены в описании MR - по одному
  на строку: операция, что ждёт контракт, что отвечает сервис.
