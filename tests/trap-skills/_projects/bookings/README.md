# Мини-проект Bookings: вход наборов группы 4.2

Сервис бронирования переговорных на ASP.NET Core (`net10.0`, контроллеры `[ApiController]`,
Swashbuckle 6.6.2, EF Core 8 + Npgsql, Postgres с exclusion constraint на пересечение броней) и его
ручной контракт `api/openapi.yaml` (`openapi: 3.0.3`, версия контракта 1.2.0). Вход наборов
[api-specification](../../removed/api-specification/README.md), [api-spec-quality](../../api-spec-quality/README.md),
[api-testing](../../api-testing/README.md), [api-documentation](../../api-documentation/README.md)
(эпик #291, группа 4.2, #303). Файл - ключ для судьи, исполнителю не подаётся: `setup.sh` его в
каталог прогона не копирует, как и раннер.

```
setup.sh <dest> [ветка]   git-репозиторий прогона: stages/* - коммиты main, branches/<имя>/<n>-* - ветка feature/<имя>
stages/                   1 сервис, контракт 1.1.0, FR-01..FR-12; 2 лента GET /bookings с курсором, контракт 1.2.0,
                          GET /rooms/{roomId}/bookings устарела (замена и срок - в контракте, в коде - комментарий)
branches/                 по кейсу, таблица ниже
run-group-4-2.sh          раннер: промпты кейсов дословно, флаги исполнителя, выход в runs/ протокола
```

## Засчитывание (общие правила, записаны до прогонов)

- Засчитывается исход в выходе (контракт, тест, код, находка), а не слова. Правило названо, но не
  применено - провал.
- Решение, заданное средой (код, контракт main, задача), исполнителю не засчитывается: клетка `n/a`.
- Документы (G-S, RV-Q, N-Q) судятся вручную по ключу; часть прогонов судит второй оценщик вслепую
  (выходы под перемешанными метками без набора), расхождения оценщиков - в протоколе.
- Находка ревью «взята», если указывает место (файл:строка в диапазоне ключа или имя элемента) и
  называет класс дефекта либо его последствие; severity любая, если клетка не говорит иного.
- Ложная находка (приманка, N-Q) - находка с severity blocker или major на месте приманки либо на
  строке, которую MR не меняет как дефект MR; minor-замечание без требования правки ложной не
  считается, но записывается.
- В G-T расхождение «обнаружено», если оно названо в описании MR (ANSWER) либо закреплено тестом,
  который утверждает поведение контракта (красный или помеченный пропуском с причиной). Тест,
  закрепляющий фактическое поведение вместо контракта без строки в описании MR, - провал клетки.

`f1`, `f2`, `t1`, `t2`); G-S - `c1`, `c2`, `t1`, `t2`; N-Q2 - все четыре (`c1`, `c2`, `t1`, `t2`).
Оценщик выносит по каждой клетке ключа «взято / провал / n/a» с цитатой места; первый оценщик - исполнитель
(по ключу). Сверка по клеткам; расхождение решается не в пользу снятия: клетка контроля - провал (единица
не снимается этим свидетельством), клетка итоговой редакции на N-Q2, приманках и вне скилла - провал
редакции. Все расхождения - в протокол скилла.
