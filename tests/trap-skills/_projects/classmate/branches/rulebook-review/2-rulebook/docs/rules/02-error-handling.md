# error-handling

## RUL-0007
- Формулировка: Сравнивай строго, через `===`; `==` не используй.
- Таксон: `internal:error-handling@2`
- scope: `src/**/*.js`
- Статус: proposed
- Принуждение: manual
- Якорь: !43#t2 - «Используй строгое сравнение `===`, `==` у нас запрещён: на `null == undefined` уже было падение в шаблонах писем.»
- Контрпример: `src/notify/format.js` в коммите «CM-15: форматирование уведомлений о брони (!43)».

## RUL-0009
- Формулировка: Из доменной функции возвращай отказ результатом `{ ok: false, code }`, исключение не бросай.
- Таксон: `internal:error-handling@2`
- scope: `src/**`
- Статус: proposed
- Принуждение: manual
- Якорь: !42#t1 - «Не бросай Error из доменных функций - возвращай `{ ok: false, code }`, как в refund.js.»
- Контрпример: `src/booking/slots.js` в коммите «CM-14: свободные слоты репетитора (!42)».

## RUL-0010
- Формулировка: На некорректный вход доменной функции бросай `Error` с кодом причины.
- Таксон: `internal:error-handling@2`
- scope: `src/**`
- Статус: proposed
- Принуждение: manual
- Якорь: коммит «CM-14: свободные слоты репетитора (!42)» - `if (!(end > start)) throw new Error('bad window');`
- Контрпример: `src/billing/refund.js` - отказ `not_paid` возвращается результатом.
