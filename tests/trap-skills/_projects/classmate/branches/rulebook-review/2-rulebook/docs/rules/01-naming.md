# naming

## RUL-0001
- Формулировка: Называй ветку `<тип>/CM-<номер>-<слаг>`.
- Таксон: `internal:naming@2`
- scope: `**`
- Статус: proposed
- Принуждение: manual
- Якорь: !38#t2 - «Ветку называем `<тип>/CM-<номер>-<слаг>`, иначе её не связать с задачей.»
- Контрпример: ветка `fix-refund` в !38.

## RUL-0002
- Формулировка: Называй тест `<функция> - <условие> - <ожидаемый результат>`.
- Таксон: `internal:naming@2`
- scope: `test/**`
- Статус: proposed
- Принуждение: manual
- Якорь: !45#t2 - «Тесты называем так: `функция - условие - ожидаемый результат`, по-русски.»
- Контрпример: тест `creates booking` в коммите «CM-18: создание брони через API (!45)».

## RUL-0008
- Формулировка: Называй тест по трём частям: что вызываем, при каком условии, что ожидаем.
- Таксон: `internal:naming@2`
- scope: `test/**`
- Статус: proposed
- Принуждение: manual
- Якорь: коммит «CM-18: отмена запроса к провайдеру, без ретраев, имена тестов (!45)» - «имена тестов».
- Контрпример: тест `creates booking` в коммите «CM-18: создание брони через API (!45)».
