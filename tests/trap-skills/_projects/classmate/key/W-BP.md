### W-BP - CM-40 модель бронирования по заметкам (выход - DIFF.patch, `docs/process/booking.bpmn`, `docs/process/booking.md`)

Вход: `docs/process/booking-notes.md`. Первоисточник клеток - BPMN 2.0.2: где скилл расходится со спецификацией,
засчитывание по спецификации (BP10 - ниже).

| Код | Класс | Ситуация во входе | Засчитано, если | Провал |
|---|---|---|---|---|
| BP1 | K bpmn | «одновременно: запрос оплаты и уведомление репетитору ... подтверждаем, только когда сделано и то и другое» | parallel gateway расщепляет запрос оплаты и уведомление, обе ветки сходятся (parallel join или эквивалентная синхронизация) до подтверждения брони | exclusive gateway на этом месте; последовательность без указания, что ждать не надо, засчитывается |
| BP2 | K bpmn | «ждём, что придёт раньше: подтверждение от PayFlow или 15 минут» | event-based gateway (подтверждение-сообщение, таймер 15 мин), либо receive task / catch event с прерывающим boundary timer | exclusive gateway с условиями на исходящих потоках «оплачено / время вышло» |
| BP3 | K bpmn | «дороже 3 000 ₽ - репетитор подтверждает вручную, иначе сразу» | exclusive gateway с двумя взаимоисключающими условиями по цене | parallel или inclusive на этом месте |
| BP4 | K bpmn | «памятка новичка ... промокод гасится. Бывает и то, и другое, бывает ни одного» | inclusive gateway с путём «ни одного» (default flow или условие), либо два последовательных exclusive gateway | один exclusive на оба условия, или parallel |
| BP5 | K bpmn | «PayFlow ответил ошибкой - холд снимается сразу, ученику "оплата не прошла"» | путь ошибки оплаты в модели: снять холд -> сообщение -> конец «оплата не прошла» | путь отсутствует |
| BP6 | K bpmn | «15 минут прошли - холд снимается ... "время на оплату вышло"» | путь тайм-аута: снять холд -> сообщение -> конец | путь отсутствует |
| BP7 | K bpmn | участники - ученик, платформа, PayFlow, репетитор | PayFlow отдельным пулом (или чёрным ящиком); между пулами только message flow | sequence flow между пулами |
| BP8 | K bpmn | - | задачи названы действием и объектом («Поставить холд на слот»), без «Обработать», «Сделать действия» | хотя бы одна задача без объекта или с безликим глаголом |
| BP9 | K bpmn | «Конец: подтверждена, холд снят (тайм-аут), оплата не прошла» | три исхода - три именованных end event | исходы слиты в один безымянный end |
| BP10 | K bpmn | ветка уведомления репетитору ждёт на join, а оплата может кончиться тайм-аутом или ошибкой | ни один путь тайм-аута или ошибки не оставляет токен ветки уведомления ждущим на parallel join: join стоит до ожидания оплаты, либо путь тайм-аута/ошибки кончается terminate end, либо ожидание внутри sub-process с boundary | parallel join после подтверждения оплаты, к которому ветка уведомления приходит при любом исходе, а пути тайм-аута и ошибки обычным end event кончают только свою ветку: экземпляр процесса не завершается |
| O1 | O | заметки не говорят, что делать, если репетитор при ручном подтверждении отказывает | отказ репетитора вынесен открытым вопросом либо смоделирован с явной пометкой допущения | - |

**BP10 и спецификация.** По BPMN 2.0.2 end event необязателен, а активность без исходящего потока штатно кончает
свой путь. Поэтому «ветка без end event» сама по себе не дефект и строкой не засчитывается. Дефект - parallel join,
который ждёт токен, не приходящий ни на одном пути (экземпляр не завершается), - это BP10. «Парный join на каждом
split» - стиль, не клетка.
