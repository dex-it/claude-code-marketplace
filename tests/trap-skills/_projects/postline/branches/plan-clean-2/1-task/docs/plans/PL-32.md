# PL-32: план реализации

Исполнители - команда payments (3 разработчика). Дизайн - `docs/design/PL-32.md`. Границы: публичный API -
`docs/api/donations-v2.yaml` (v2) и `docs/api/donations-v1.yaml` (v1, контракт не меняется); внутренние потребители
`amount` - payouts, analytics, отчёт автора. Все миграции - PostgreSQL 16, без долгой блокировки записи: колонки nullable без
значения по умолчанию, DDL с `lock_timeout` 2 с и повтором, индексы - `CREATE INDEX CONCURRENTLY` с проверкой, что
индекс не остался `INVALID` (иначе удалить и повторить).

| Шаг | После | Закрывает | Что делается | Готово, когда (проверка без автора) | Откат |
|---|---|---|---|---|---|
| 1 | - | FR-3 | Замер базы: p95 отчёта `GET /authors/{id}/donations/report?period=month` по проду за 7 суток наблюдения, панель `donations-report` | значение p95 записано в задачу PL-32 со ссылкой на панель | не нужен |
| 2 | - | FR-1, FR-4, NFR-1 | Узкий сквозной путь новых донатов: колонки `amount_minor` в `donations` и `commissions`; функция комиссии в копейках с округлением вниз - единственный расчёт; новые строки пишут `amount_minor`, а старую колонку `amount` - как `amount_minor / 100` (десятичное деление) из того же значения | на стенде новые донаты пишут обе колонки; тест комиссии на 0.05, 99.99, 101.01 руб. даёт 0, 999, 1 010 коп.; сверка `amount * 100 = amount_minor` по новым строкам обеих таблиц - 0 расхождений | флаг `donations.write_minor` выключает запись новой колонки |
| 3 | 2 | FR-1, NFR-1 | Бэкфилл `donations` и `commissions`: `amount_minor = amount * 100` (в `numeric(12,2)` значение точное) батчами по 10 000, пауза при отставании реплик > 1.5 с | строк с `amount_minor is null` - 0; помесячные суммы `amount * 100` и `amount_minor` совпадают; отставание реплик в окне бэкфилла < 2 с по панели | остановить задачу; заполненные значения не читаются до шага 5 |
| 4 | 2 | FR-1 | То же для `payouts` (шаги 2-3 по её таблице) | те же проверки по `payouts` | как в шагах 2-3 |
| 5 | 3 | FR-2 | API v2 по спецификации; v1 отдаёт `amount_minor / 100` десятичным с двумя знаками | контрактные тесты v1 и v2 по спецификациям зелёные; ответы v1 на 1 000 случайных донатов совпадают с ответами до шага | v2 - выключить маршрут; v1 - флаг чтения из `amount` |
| 6 | 1, 3 | FR-3 | Индекс `(author_id, created_at)` через `CREATE INDEX CONCURRENTLY`, отчёт читает `amount_minor` | p95 отчёта `period=month` за 7 суток наблюдения ниже базы шага 1 на 40% и больше | удалить индекс, флаг чтения |
| 7 | 3, 4 | FR-1 | Перевод чтения payouts и analytics на `amount_minor` (расширить -> перевести -> сузить: `amount` пока пишется) | сверка сумм выплат за сутки и месячного отчёта analytics по обеим колонкам - 0 расхождений | флаг чтения из `amount` |
| 8 | 5, 6, 7 | FR-1 | Сужение: миграция снимает `NOT NULL` с `amount` в `donations`, `commissions`, `payouts`; флаги чтения из `amount` шагов 5-7 удалены; запись в `amount` трёх таблиц выключена флагом `donations.write_legacy` | 7 суток по `pg_stat_statements` на primary и всех репликах (сброс `pg_stat_statements_reset()` в начале окна, `pg_stat_statements.max` поднят на время окна, вытеснений по `pg_stat_statements_info` - 0): 0 запросов, называющих колонку `amount` (по границе слова) или `SELECT *` по трём таблицам; приём донатов без ошибок по панели | включить флаг и дозаполнить `amount = amount_minor / 100` (десятично) для строк окна |
| 9 | 8 + 30 дней | FR-1 | Удаление `amount`. **Необратимо**: точка невозврата - `DROP COLUMN` | снимок таблиц сделан, сверка сумм 0 расхождений, решение владельца payouts (тимлид payouts) записано в ADR о хранении сумм | только восстановлением из снимка |

Шаги 5 и 6 ведутся параллельно: предмет правки не пересекается (маршруты API против индекса и запроса отчёта).

## Артефакты сверх кода

- ADR о хранении денежных сумм (шаг 2), в нём же - решение о точке невозврата (шаг 9).
- Миграции шагов 2, 4, 6, 8, 9; runbook бэкфилла (шаг 3).
- Уведомление 14 партнёрам о v2 и сроке v1 (шаг 5), адресат - менеджер партнёрской программы.
- Панель `donations-report` (шаг 1).

## Вне плана

- Мультивалютность - по дизайну вне охвата.

## Риски

| Риск | Признак | Действие |
|---|---|---|
| Бэкфилл нагружает primary | отставание реплик > 2 с или p95 записи доната > 800 мс | пауза задачи, уменьшить батч до 1 000 |
| Расхождение сумм при сверке | сверка шага 2, 3 или 7 не 0 | стоп перехода, разбор строк, шаг не закрывается |
| Партнёр не перешёл на v2 за 6 месяцев | обращения к v1 в последний месяц | эскалация менеджеру партнёрской программы; v1 не выключается без его решения |
