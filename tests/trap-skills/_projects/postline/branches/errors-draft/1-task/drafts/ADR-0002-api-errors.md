# ADR-0002: Формат ошибок API

Статус: Accepted (2026-02-02)

<!-- черновик правок, снят с main 2026-09-20 -->

## Контекст

Клиенты (мобильные, веб, партнёры) разбирают ошибки по-разному: где-то строка, где-то код.

## Решение

1. Ошибки API отдаются телом `application/problem+json` (RFC 9457): `type`, `title`, `status`, `detail`.
2. `type` - URI вида `https://postline.example/errors/<код>`, список кодов - в спецификации API.
3. Ошибки валидации несут поле `errors` - объект «поле -> список объектов `{code, message}`»; `code` - машинный код правила.
4. Текст исключения и стек в тело не попадают.
5. Поле `instance` несёт идентификатор трассы запроса (`trace_id` OpenTelemetry).

## Проверка

Контрактные тесты api проверяют `Content-Type` и поля на каждый код ошибки из спецификации.
