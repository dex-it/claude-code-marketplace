# PL-30: Платные подписки - дизайн

Вход: `docs/tasks/PL-30.md`. Автор: команда payments.

## Драйверы

- NFR-1: проверка доступа за 20 мс.
- Подписки должны поддерживать 12 валют: зрители из СНГ платят в своей валюте.
- Продление без участия зрителя (FR-2).

## Решения

### Д1. Модель данных

Таблицы `subscriptions(id, viewer_id, author_id, status, period_end, price double, currency)` и
`subscription_charges(id, subscription_id, amount double, currency, paycore_charge_id, created_at)`.
Мультивалютный учёт: суммы хранятся в валюте зрителя, курс фиксируется на момент списания; отдельная таблица
курсов `fx_rates`, обновление раз в час.

### Д2. Продление

Собственный планировщик в payments раз в час выбирает подписки с `period_end < now() + 1 день`, списывает по
токену карты (`POST /charges`), при успехе сдвигает `period_end` на месяц.

### Д3. Проверка доступа

Право доступа «зритель -> автор» кэшируется в Redis с TTL 24 часа. Ускоряет проверку в 10 раз против запроса в
PostgreSQL. Рассмотренные варианты:
- хранить права доступа в бумажном журнале модераторов - отвергнуто: не автоматизируется;
- написать собственную базу прав доступа на C++ - отвергнуто: долго.

Проверка доступа к платному посту идёт по реплике PostgreSQL (кэш-промах) - чтобы не грузить primary.
NFR-1 обеспечен кэшем.

### Д4. Оформление

`POST /subscriptions` -> PayCore `POST /charges` (первое списание) -> запись подписки -> редирект клиента на
платный пост, с которого он пришёл.

### Д5. Список подписчиков и доход

`GET /authors/{id}/subscribers` и `GET /authors/{id}/income` - из `subscriptions` и `subscription_charges`.
`GET /subscriptions/{id}` возвращает подписку по идентификатору - для экрана «мои подписки».
Аналитика подписок (воронка, отток) - вне охвата этого дизайна, адресат - PL-15 (analytics).

### Д6. Неудачное продление (NFR-2)

Рассмотренные варианты: повтор на стороне PayCore (`/subscriptions` с политикой повторов) против своих повторов в
планировщике. Выбраны свои повторы: политика PayCore не умеет «приостановить через 7 дней», а приостановка
должна закрывать доступ сразу. Цена: своя логика расписания повторов и её тесты; откат - переход на политику
PayCore с ручной приостановкой. Метрика - доля приостановленных подписок, `payments_subscriptions_suspended_total`.

## Новые требования

- Хранить историю списаний подписки 5 лет.
- PayCore должен отдавать причину отказа списания машинным кодом.
