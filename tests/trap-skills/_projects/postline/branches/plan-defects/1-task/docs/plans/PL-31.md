# PL-31: план реализации

Исполнители - команда payments (3 разработчика). Дизайн - `docs/design/PL-31.md`.

## Шаги

1. **Схема.** Миграция: `amount_minor bigint` во все три таблицы; колонку `amount` переименовать в `amount_rub`.
   Готово: миграция написана.
2. **Бэкфилл.** `UPDATE donations SET amount_minor = amount_rub * 100` одной транзакцией, затем то же для `payouts`
   и `commissions`. Готово: выполнено.
3. **Домен.** Расчёт комиссии в копейках, запись в обе колонки. Готово: реализовано, покрыто тестами.
4. **Отчёт автора.** Индекс `(author_id, created_at)`, чтение `amount_minor`. Готово: работает.
5. **Замер.** Замерить p95 отчёта автора для FR-3.
6. **API v2.** Эндпоинты `/v2/donations`; формат ответа - по ходу реализации, с партнёрами согласуем после выхода.
7. **Потребители.** Перевести payouts и analytics на `amount_rub` / `amount_minor`.
8. **Мультивалютность.** Поле `currency` и таблица курсов, чтобы второй раз не мигрировать.
9. **Очистка.** Удалить колонку `amount_rub`.

Шаги 3 и 4 ведут параллельно два разработчика: оба меняют миграцию `0042_amount_minor` и модель `Donation`.

## Проверка

Сквозной прогон всех сценариев донатов на стенде после шага 9.

## Риски

- Бэкфилл может нагрузить primary.
- Партнёры могут не успеть перейти на v2.
