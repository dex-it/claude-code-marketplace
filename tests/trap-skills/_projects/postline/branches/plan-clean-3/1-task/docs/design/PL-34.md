# PL-34: Суммы донатов в копейках и API v2 - дизайн

Статус: принят ревьюером дизайна 2026-10-06.

## Требования

- FR-1. Суммы донатов, комиссий и выплат хранятся целым числом копеек. Сейчас - `numeric(12,2)` в рублях,
  а комиссия считается в `double` в коде и даёт расхождения до 1 копейки на донат.
- FR-2. Публичный API `/v2/donations` отдаёт суммы полем `amount_minor` (копейки, целое). `/v1/donations`
  (рубли, `amount` с дробной частью) работает ещё 6 месяцев после выхода v2: им пользуются 14 партнёров-интеграторов.
- FR-3. Отчёт автора по донатам за месяц (`GET /authors/{id}/donations/report`): p95 снизить на 40% от текущего.
  Текущее значение не замерено в разрезе отчёта.
- FR-4. Комиссия 10% считается в копейках, округление - вниз, в пользу автора.
- NFR-1. Приём донатов не останавливается на время перехода.

## Решение

1. Новые колонки `amount_minor bigint` в `donations`, `payouts`, `commissions`; бэкфилл батчами по 10 000 строк
   (400 млн строк в `donations`) в фоне с паузой между батчами по отставанию реплик.
2. Переходный период: запись в обе колонки (старая и новая), чтение - из старой; после бэкфилла и сверки -
   чтение из новой. Потребители `amount`: payouts, analytics, отчёт автора.
3. Комиссия - функция в копейках в домене payments, округление вниз; единственное место расчёта.
4. API v2 - по спецификации `docs/api/donations-v2.yaml`; v1 отдаётся из `amount_minor`, делённого на 100 в десятичной арифметике (два знака).
5. Отчёт автора - индекс `(author_id, created_at)` и чтение `amount_minor`.
6. Старая колонка `amount` удаляется через 30 дней после перевода всех чтений на `amount_minor`. Удаление необратимо:
   до него - снимок таблицы и сверка сумм.

## Вне охвата

- Мультивалютные донаты - отдельная работа после PL-34.

## Последствия

- Партнёры переходят на v2 в течение 6 месяцев; уведомление партнёрам - вместе с выходом v2.
- ADR о хранении денежных сумм - новый, ADR-0001 не затрагивается.
