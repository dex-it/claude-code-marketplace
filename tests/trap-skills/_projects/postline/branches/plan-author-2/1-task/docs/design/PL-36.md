# PL-36: Кабинет автора, осенний пакет - дизайн

Статус: принят ревьюером дизайна 2026-10-06.

## Требования

- FR-1. Письмо автору о новом донате показывает сумму и имя донатера. Сейчас письмо - «Вам пришёл донат» без
  подробностей.
- FR-2. Дашборд автора показывает число донатов за последние 7 дней.
- FR-3. Первая страница ленты (`GET /feed`, без курсора): p95 снизить на 30% от текущего. Текущее значение не
  замерено: метрика `feed_request_duration_seconds` есть, разреза «первая страница» у неё нет.

## Решение

1. FR-1 - сервис notifications: шаблон письма `donation-received` выводит `amount_minor` (рубли с копейками) и
   `donor_display_name`. Оба поля уже есть в событии `donation.created` (схема v3); схема события не меняется.
2. FR-2 - сервис analytics: колонка `donations_7d integer NOT NULL DEFAULT 0` в таблице `author_daily_stats`
   (база analytics, 600 тыс. строк), счёт - в потребителе `donation.created` сервиса analytics; виджет дашборда
   читает колонку. Пересчёт истории не нужен: окно 7 суток заполнится само.
3. FR-3 - сервис feed: метка `page="first"` у `feed_request_duration_seconds`, база - ряд 7 суток по метке; затем
   кэш первой страницы ленты в Redis (ключ `feed:first:{user_id}`, TTL 30 с, без инвалидации - задержку до 30 с
   продукт принял). Цель - p95 по той же метке 7 суток после включения кэша.

notifications, analytics и feed - разные сервисы с отдельным деплоем, у каждого своя база; `donation.created`
notifications и analytics только читают. Redis кэша ленты notifications и analytics не используют.

## Вне охвата

- Инвалидация кэша ленты при новой публикации - отдельная работа, если 30 с окажутся заметны.
