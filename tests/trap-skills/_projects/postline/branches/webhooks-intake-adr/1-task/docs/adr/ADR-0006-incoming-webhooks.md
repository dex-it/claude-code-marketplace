# ADR-0006: Приём входящих вебхуков PushGate и PayCore

Статус: Accepted (2026-10-05)
Карта кода: `src/webhooks/` (обработчики), `src/webhooks/journal.ts` (журнал).

## Контекст

Входящие вебхуки: статусы доставки PushGate (`docs/sources/pushgate-delivery.md`) и статусы платежей PayCore.
Сейчас каждый обработчик написан по-своему.

## Рассмотренные варианты

- Общий приёмник вебхуков с журналом и дедупликацией по идентификатору события.
- Свой приёмник на каждого провайдера - отвергнут: дедупликация и журнал повторялись бы в каждом.

## Решение

1. Обязательно: обработка вебхуков идемпотентна.
2. Обязательно: дедупликация - как в `src/webhooks/pushgate.ts:41` (множество `seenIds`); сейчас так сделано
   в 2 обработчиках из 3, обработчик PayCore пока без дедупликации.
3. Обязательно по документации PushGate: журнал полученных статусов хранится 90 дней.
4. Обязательно: входящий вебхук пишется в лог целиком - тело и заголовки - для разбора инцидентов.
5. Обязательно: 2xx отправляется после полной обработки события; обработка статуса платежа - до 30 с.
6. Обязательно: формат записи журнала - см. `src/webhooks/journal.ts`.

| Событие | Обработчик |
|---|---|
| `pushgate.status` | `src/webhooks/pushgate.ts:12` |
| `paycore.payment` | `src/webhooks/paycore.ts:8` |

## Открытые вопросы

- Сколько хранить идентификаторы событий для дедупликации. Принял 7 суток: PushGate повторяет доставку до 24 часов
  (`docs/sources/pushgate-delivery.md`, 4.2), запас на ручной перезапуск очереди. Продукт, подтверди или поправь.
- Повторяет ли PushGate доставку статуса? Уточнить у провайдера; до ответа ADR не применяется.

## Последствия

- Один приёмник на всех провайдеров, журнал в одном месте.
