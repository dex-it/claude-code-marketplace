# PL-31: план реализации

Исполнители - команда payments (3 разработчика). Дизайн - `docs/design/PL-31.md`. Границы: публичный API -
`docs/api/donations-v2.yaml` (v2), v1 - без изменения контракта; внутренние потребители `amount` - payouts, analytics.

| Шаг | Закрывает | Что делается | Готово, когда (проверка без автора) | Откат |
|---|---|---|---|---|
| 1 | FR-3 | Замер базы: p95 `GET /authors/{id}/donations/report` за 7 дней на проде, панель `donations-report` | значение p95 записано в задачу PL-31 со ссылкой на панель | не нужен |
| 2 | FR-1, FR-4, NFR-1 | Узкий сквозной путь на `donations`: колонка `amount_minor` (nullable), комиссия в копейках с округлением вниз, запись в обе колонки | новые донаты на стенде пишут обе колонки, тест комиссии на 99, 101, 9 999 руб. зелёный, сверка `amount*100 = amount_minor` по новым строкам - 0 расхождений | выключить запись новой колонки флагом `donations.write_minor` |
| 3 | FR-1, NFR-1 | Бэкфилл `donations` батчами по 10 000, пауза при отставании реплик > 2 с | `select count(*) where amount_minor is null` = 0; отставание реплик в окне бэкфилла < 2 с по панели | остановить задачу; заполненные значения не мешают |
| 4 | FR-1 | То же для `payouts`, `commissions` (шаги 2-3 по их таблицам) | те же проверки по таблицам | как в шагах 2-3 |
| 5 | FR-2 | API v2 по спецификации; v1 отдаёт из `amount_minor / 100` | контрактные тесты v1 и v2 по спецификациям зелёные | v2 - выключить маршрут; v1 - флаг чтения из `amount` |
| 6 | FR-3 | Индекс `(author_id, created_at)`, отчёт читает `amount_minor` | p95 отчёта за 7 дней ниже базы шага 1 на 40% и больше | удалить индекс, флаг чтения |
| 7 | FR-1 | Перевод чтения payouts и analytics на `amount_minor` (расширить -> перевести -> сузить: `amount` пока пишется) | сверка сумм выплат за сутки по обеим колонкам - 0 расхождений | флаг чтения из `amount` |
| 8 | FR-1 | Удаление `amount` через 30 дней после шага 7. **Необратимо**: точка невозврата - `DROP COLUMN` | снимок таблиц сделан, сверка сумм 0 расхождений, решение владельца payouts в журнале решений | только восстановлением из снимка |

Шаги 5 и 6 ведутся параллельно: предмет правки не пересекается (маршруты API против индекса и запроса отчёта).
Шаг 4 обслуживает шаг 7 (подготовительный).

## Артефакты сверх кода

- ADR о хранении денежных сумм (шаг 2).
- Миграции шагов 2, 4, 6, 8; runbook бэкфилла (шаг 3).
- Уведомление 14 партнёрам о v2 и сроке v1 (шаг 5), адресат - менеджер партнёрской программы.
- Панель `donations-report` (шаг 1).

## Вне плана

- Мультивалютность - по дизайну вне охвата.

## Риски

| Риск | Признак | Действие |
|---|---|---|
| Бэкфилл нагружает primary | отставание реплик > 2 с или p95 записи доната > 800 мс | пауза задачи, уменьшить батч до 1 000 |
| Расхождение сумм при сверке | сверка шага 2, 3 или 7 не 0 | стоп перехода, разбор строк, шаг не закрывается |
| Партнёр не перешёл на v2 за 6 месяцев | обращения к v1 в последний месяц | эскалация менеджеру партнёрской программы; v1 не выключается без его решения |
