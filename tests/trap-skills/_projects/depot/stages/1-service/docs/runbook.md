# Depot.Api: паспорт сервиса для эксплуатации

- Рантайм: ASP.NET Core 8 (`net8.0`), приложение слушает **8080** (`ASPNETCORE_URLS=http://+:8080`, дефолт образов .NET 8).
- Настройки приложения - только переменные окружения:
  - `ConnectionStrings__Default` - строка подключения к Postgres 16 (в ней пароль БД), обязательна;
  - `Auth__ApiKey` - ключ клиентов API, обязателен;
  - `Logging__LogLevel__Default` - необязательна (по умолчанию `Information`).
  Без обязательных настроек процесс не стартует (исключение при запуске).
- Старт: при запуске приложение применяет миграции БД и только после этого принимает трафик. Холодный старт на
  кластере - 20-35 секунд (p95), на ноутбуке быстрее.
- Здоровье: `GET /health` - 200, если БД отвечает (`select 1`), иначе 503 с исключением. Других health-маршрутов нет.
- Ресурсы по замерам на stage: рабочий набор около 300 МБ, в простое CPU около 50m, под нагрузкой до 300m.
- Файловая система: приложению нужна запись только в `/tmp` (выгрузки по запросу); остальное - чтение.
- Логи - в stdout. Метрик и трассировки нет.
- Рядом работает `depot-worker` (обработка очереди поступлений): образ тот же, запуск `dotnet Depot.Api.dll --worker`,
  **ровно один экземпляр** - два экземпляра обработают очередь дважды. Настройки те же.
