# PRC-11: прайс-листы поставщиков

Сейчас цена поставщика берётся из Supplier API на каждый запрос. Закупка хочет вести прайс-листы у нас.

**Что храним.** Прайс-лист: поставщик (`supplierId`), номер листа (целое, уникален в пределах
поставщика), валюта, статус, период действия (`validFrom`, `validTo`), позиции (SKU и цена),
себестоимость закупки по листу (`purchaseCost`) и плановая маржа (`marginPercent`). Себестоимость и
маржа - коммерческая тайна: их видят только закупщики в ERP.

**Статусы.**
- `Draft` - лист заведён, не проверен.
- `Published` - лист действует.
- `Suspended` - поставщик временно снял лист; вернёт его сам, публиковать повторно нельзя.
- `Retired` - лист снят навсегда; закупщик может опубликовать новый лист на его основе.

Портал поставщиков по статусу решает, показывать ли кнопку «опубликовать заново», - интеграторы
портала должны понимать разницу статусов из Swagger, кода нашего сервиса они не видят.

**API.**
1. Загрузка листа из ERP. ERP присылает документ (пример ниже) и ждёт в ответ адрес созданного листа.
2. Получение листа поставщика по номеру.
3. Поиск листов для портала поставщиков: по статусу, валюте и дате (лист действует на дату),
   постранично. У крупных поставщиков - десятки тысяч листов. Портал показывает в списке номер,
   валюту, статус, период действия и число позиций.
4. Пересчёт базовых цен каталога по опубликованному листу. Вызывает только наш планировщик по
   расписанию; порталу, ERP и витрине этот вызов не нужен.

Хранилище - в памяти, как у товаров.

Пример документа ERP:

```json
{
  "supplierId": "sup-7",
  "number": 42,
  "currency": "RUB",
  "status": "Draft",
  "validFrom": "2026-10-01",
  "validTo": "2026-12-31",
  "items": [ { "sku": "SKU-1", "price": 120.50 }, { "sku": "SKU-2", "price": 75.00 } ],
  "purchaseCost": 81000.00,
  "marginPercent": 18.5,
  "erpDocumentId": "ERP-2026-00042",
  "erpUser": "ivanova",
  "erpExportedAt": "2026-09-10T08:15:00+03:00"
}
```
