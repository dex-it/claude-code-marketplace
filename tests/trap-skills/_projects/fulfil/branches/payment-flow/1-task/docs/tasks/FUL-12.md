# FUL-12: Платежи и процесс исполнения заказа

## Требования

1. Заказ исполняется процессом из шагов: резерв товара на складе -> списание денег -> отгрузка.
   Каждый шаг - команда в RabbitMQ (`ReserveStock`, `CapturePayment`, `ShipOrder`); процесс
   стартует по событию `OrderSubmitted`. Шаги могут не удаться (платёж отклонён, товара
   нет). Деньги списывает `IPaymentGateway` (внешний сервис, иногда
   падает).
2. Обработчик `CapturePayment` на MassTransit. Пик - 10 тысяч команд в минуту.
3. `POST /orders/{id}/submit` сохраняет заказ в MongoDB (коллекция `orders`) и публикует
   `OrderSubmitted`.
4. Интеграция со складом: чужая система кладёт сообщения о приходе товара в очередь
   `warehouse.inbound` (формат не MassTransit, JSON `{ "sku": "...", "qty": 5, "messageId": "..." }`).
   Сервис читает её напрямую через `RabbitMQ.Client` и увеличивает `stock` товара в MongoDB.
   Обратно сервис отправляет подтверждение в обменник `warehouse.outbound`.
5. Платформа: RabbitMQ 4.3, один узел; перезапускается при обновлении стенда.

## Вне задачи

Тесты, Kubernetes-манифесты, формат платёжного шлюза.
