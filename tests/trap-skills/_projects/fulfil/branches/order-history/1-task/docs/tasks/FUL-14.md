# FUL-14: Хранилище заказов в MongoDB

## Требования

1. Заказы лежат в коллекции `orders`, ожидается 50 млн документов. Основной запрос -
   «заказы клиента в заданном статусе за период, сначала новые», страница по 50.
2. В заказе хранится адрес доставки (читается всегда вместе с заказом, не меняется после
   размещения) и данные клиента для письма: имя и email. Клиент может сменить email; у
   постоянных клиентов до 10 тысяч заказов.
3. Лента событий заказа (смена статуса, комментарии менеджера) показывается на странице заказа.
   У крупных B2B-заказов событий бывают тысячи.
4. Страница «мои заказы» показывает только номер и статус заказа.
5. Черновики корзин (коллекция `cart_drafts`) не нужны через 30 дней после последнего изменения.
6. Перенос остатков между складами: `stock` у склада-источника уменьшается, у склада-приёмника
   растёт, оба изменения атомарно (две записи в коллекции `warehouse_stock`).
7. Когда заказ получает статус `Shipped`, сервис должен узнать об этом и отправить письмо
   (отправка - существующий `IMailer.SendShippedAsync(orderId)`).
8. Класс заказа в коде будет расти полями; документы в базе остаются старыми.
9. MongoDB - один узел из `docker-compose.yml`.

## Вне задачи

Тесты, API, письма как таковые.
