# FUL-11: Учёт заказов из потока Kafka

Витрина публикует размещённые заказы в топик `orders.placed` (JSON, контракт - `OrderPlaced`
в `src/Fulfil/Contracts`). Нужен фоновый учёт.

## Требования

1. Сервис читает `orders.placed` и ведёт проекцию клиента в MongoDB, коллекция `customers`:
   количество заказов `ordersCount` и сумма `totalSpent` растут на каждый размещённый заказ.
2. После учёта заказа сервис публикует событие `OrderStatusChanged` (статус `Placed`) в топик
   `orders.status-changed`, его читает склад.
3. Ночной импорт: топик `orders.import` содержит до миллиона заказов. Сервис читает его пачками
   по 100 сообщений и пишет заказы в коллекцию `orders` одним `InsertMany` на пачку.
4. Витрина добавляет в `OrderPlaced` поле `giftWrap` (bool, подарочная упаковка). Три смежные
   команды ещё публикуют старый формат без него, переходят постепенно. Сервис должен принимать
   оба формата.
5. Топики и группы потребителей создаёт платформа: `orders.placed` (6 партиций), группа
   `fulfil-orders`.

## Вне задачи

Эндпоинты API, тесты, Kubernetes-манифесты.
