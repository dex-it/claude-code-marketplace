# FUL-13: Redis - цены, фоновые расчёты, ограничение запросов

## Требования

1. `GET /products/{sku}/price` читается до 500 запросов в секунду, в основном по сотне
   популярных товаров. Источник - `IPriceSource` (около 300 мс). Нужен кэш в Redis. Ценовой
   сервис сообщает об изменении цены вызовом `POST /internal/price-changed` с телом `{ "sku": "..." }`.
2. Раз в минуту пересчитываются остатки (`StockRecalculator`, один проход - 10-40 с). Все три
   реплики запускают задачу по таймеру; одновременно её должна выполнять ровно одна.
   Пересчёт меняет данные в MongoDB.
3. Публичный API (`/api/*`): не больше 100 запросов в минуту на ключ клиента (заголовок
   `X-Api-Key`), сверх лимита - 429.
4. Корзина покупателя хранится в Redis: позиции и промокод; позиции меняются по одной, промокод
   отдельно, корзина читается целиком.
5. Рассылка писем: API кладёт задание в очередь, воркеры забирают и отправляют. Воркеры
   перезапускаются при деплое.
6. Redis - один узел из `docker-compose.yml`, `maxmemory` не задан.

## Вне задачи

Тесты, метрики, Kubernetes-манифесты.
