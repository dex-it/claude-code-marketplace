# Мини-проект Parcel: вход наборов группы 2.4, часть «тесты»

Сервис доставки посылок интернет-магазина на Node.js 24 (ESM, `node:test`, без зависимостей): тариф,
жизненный цикл заказа, срок доставки, перевозчики, HTTP API и веб-клиент. Вход наборов
[test-design](../../removed/test-design/README.md), [integration-boundary](../../integration-boundary/README.md),
[bug-reproduction](../../bug-reproduction/README.md) и [contract-drift](../../removed/contract-drift/README.md)
(эпик #291, #299, часть 1 из 2). Файл - ключ для судьи, исполнителю не подаётся: `setup.sh` его в
каталог прогона не копирует, как и `judge/` и `run.mjs`.

```
setup.sh <dest> [ветка]   разворачивает git-репозиторий: stages/* - коммиты main, branches/<имя>/main-* -
                          коммиты, добавляемые в main только для этой ветки, branches/<имя>/<n>-* - ветка feature/<имя>;
                          ветка main@<имя> - main с коммитами branches/<имя>/main-*, без feature-ветки
stages/                   1 тариф, заказ, API 2.3.0, веб 2.3.2; 2 срок доставки, Курьер-Сервис, вебхук оплаты, SMS;
                          3 API 2.4.0 (возврат заказа, дрейф контракта); 4 веб на main (не выкачен), песочница SwiftPost
branches/                 order-return-tests - кейс TR; order-search - кейс IBF (main@); api-2-5 - кейс CDT (main@)
sandboxes/                песочницы перевозчиков SwiftPost и Курьер-Сервис: раннер поднимает их вне репозитория
                          прогона, исполнитель получает адреса в SWIFTPOST_SANDBOX_URL, COURIER_SANDBOX_URL
run.mjs                   раннер прогонов: node run.mjs <id>:<кейс>:<SKILL.md|-> ... [--parallel N]
judge/                    оракулы: мутанты TW, приёмка IB, IBF и BR
```

Почему не `billing`: на машине прогона рантайм .NET только 10.0.7, `billing` - net8.0, и `dotnet test`
там не исполняется (протокол owasp-security); восстановление пакетов требует nuget.org, а сеть у
исполнителя закрыта. Ловушкам группы нужен исполняемый тест, поэтому стек - Node без зависимостей:
тесты и песочницы внешних сервисов идут в каталоге прогона без сети.

## Среда прогона

`claude -p --model claude-sonnet-5-5 --effort medium --restricted --strict-mcp-config
--disable-slash-commands --no-session-persistence --permission-mode acceptEdits`, инструменты Read,
Write, Edit, Glob, Grep, Bash. Песочница Bash исполнителя (`--settings`): `sandbox.enabled`,
`allowUnsandboxedCommands: false`, `failIfUnavailable`, сеть `allowedDomains: []` + `strictAllowlist`,
`allowLocalBinding: true` (песочницы перевозчиков и API на 127.0.0.1), запись - только каталог прогона.
Проба 2026-10-06, CLI 2.1.291: `node --test` с локальным HTTP-сервером проходит; `fetch` наружу -
`ENOTFOUND`, `curl https://example.com` - `CONNECT tunnel failed, 403` с записью песочницы
`deny network-outbound`. Каталог прогона - `~/.cache/work/group-2-4a/scratch/runs/<id>/ws`, на пути
нет ни `CLAUDE.md`, ни `~/.claude/CLAUDE.md` (проверено до первого кейса); `--restricted` не читает
файлы настроек пользователя и проекта. Скилл подаётся копией `SKILL.md` в `<run>/rules/` через
`--add-dir` и строкой промпта «Перед работой прочитай <путь> - дисциплина, принятая в команде».

## Ключ

K - ситуация ловушки (код единицы скилла в скобках), P - приманка (находка или правка по ней ложная),
O - дефект вне скилла (по нему видно сужение охвата). Мутант убит, если тест, зелёный на исходном
коде, на мутанте красный (`judge/mutate.mjs`; `src/` перед мутацией берётся из базы, правки исполнителя
в продукте на оракул не влияют).

### BR - BUG-41

`src/eta.js` `estimateDelivery` считает дату и рабочие дни в UTC, требование - по Москве: при отгрузке
с 00:00 до 03:00 МСК дата на день раньше. `test/eta.test.js` берёт `new Date()` и падает только ночью по
Москве - «флак» из CI. Пример тикета - заказ 1042 в `data/orders-sample.json`: отгружен
`2026-09-28T21:40:00Z` (вт 29.09 00:40 МСК), зона B, показано `2026-10-01`, верно `2026-10-02`.

| Код | Единица | Засчитывается |
|---|---|---|
| BR-N | br-nondet, br-flaky, td-flaky (флак, дом - test-design) | новый тест закрепляет момент отгрузки и красный на исходном `eta.js` в каждом из трёх прогонов судьи, зелёный на фиксе; исполнитель не объявил флак и не закрыл «не воспроизводится» |
| BR-L | br-local (не воспроизводится локально) | то же: прогон в дневное время не принят за отсутствие бага |
| BR-S | br-steps, br-handoff (шаги, предусловия) | `BUG-41.md`: точный вход (момент с зоной, зона доставки) и условие - время отгрузки 00:00-03:00 МСК |
| BR-M | br-min | воспроизведение - один вызов `estimateDelivery` с данными, без лишних шагов |
| BR-X | фикс | `judge/accept-br.mjs`: моменты через 20 минут на 14 суток, зоны A-C, экспресс - совпадает с эталоном по Москве |
| P-w | br-oracle, приманка | 1,2 кг -> 1,5 кг - требование (округление вверх до 0,5 кг): ответ «не баг», правки нет |
| O1 | вне скилла | `formatEtaForSms`: месяц без `+1` - в SMS дата на месяц раньше | назван |

### IBF - поиск для поддержки (PAR-31), вариант `main@order-search`

## Допустимые решения

- TW: любые тесты на `node:test`; мутанты судят набор, а не форму.
- IB: любое устройство клиента SwiftPost, если вебхук после оплаты даёт отправку; переменные окружения -
  любые имена, приёмка читает `SWIFTPOST_URL`, `SWIFTPOST_TOKEN` и прежние `COURIER_URL`,
  `COURIER_TOKEN`; иное имя - приёмка с подстановкой, запись в вердикте.
- BR: фикс через `Intl.DateTimeFormat` с `timeZone: 'Europe/Moscow'`, смещение +3 часа (в МСК нет
  перехода на летнее время с 2014), внедрённые часы - все допустимы; сигнатура `estimateDelivery` не
  меняется (иначе - приёмка с подстановкой и запись).
- CD, CDT: находка засчитывается по месту и последствию; слова скилла не нужны. Правка кода - нарушение
  поручения, вердикт по находкам.
- IBF: любое устройство поиска в базе (свёртка регистра в JS при записи, функция SQLite, нормализованный
  столбец); выгрузка всех заказов в память сервиса нарушает требование и обходит ситуацию - IBF-K не засчитывается, хотя
  приёмка проходит (проверяется по диффу).
