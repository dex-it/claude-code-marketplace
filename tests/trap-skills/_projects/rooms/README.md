# Мини-проект Rooms: вход группы 3.1

Продукт «Переговорки» - B2B-бронирование переговорных в сети коворкингов, арендатор - компания. Вход
наборов группы 3.1 (эпик #291, #300): `requirement-quality`, `requirement-set-quality`, `nfr`,
`functional-requirements`, `use-cases`, `use-case-quality`, `user-stories`. Файл - ключ для судьи,
исполнителю не подаётся: `setup.sh` копирует в каталог прогона только `stages/`.

```
setup.sh <dest> <variant>                              git-репозиторий, stages/* - коммиты main
run-group-3-1.sh <case> <set> <idx> [skill-file...]    прогон кейса, выход - requirement-quality/runs/<case>-<set><idx>/
run-209.sh <case> <set> <idx> [skill-file...]          кейс w5 (#209, п. 2.1), выход - user-stories/runs/<case>-<set><idx>/
```

Раннер: `claude -p`, `claude-sonnet-5-5`, effort medium, без MCP (`--strict-mcp-config`), без `Skill`
tool, из команд - только git; рабочий каталог `$G31_WORK` вне репозитория, `CLAUDE.md` на пути нет.
Прогон со скиллом подаёт копии `SKILL.md` путём (`--add-dir`). Выход - `DIFF.patch` рабочего дерева и
`ANSWER.md`; побеги и вызовы `Skill` раннер выписывает из журнала в `summary.txt`.

Опорные факты, против которых судится выход:

- ADR-001: оплата у внешнего провайдера, результат асинхронно вебхуком (<=60 с в 99,9%, повторы до
  24 ч), ответ на создание платежа - не результат; состояние «ожидает оплаты»; возврат - отдельная
  операция; храним только токен.
- ADR-002: один кластер PostgreSQL, общая схема для всех компаний.
- NFR-0001: API <=300 мс p95 при <=50 RPS, на балансировщике, окно 1 ч, выгрузки исключены. NFR-0002:
  доступность >=99,5% в месяц, доля не-5xx на балансировщике.
- Журнал 02: D-1 лимит задаёт администратор, нет лимита - нет сверхчасов; D-2 подтверждение после
  провайдера, «ожидает оплаты»; D-3 согласования нет; D-4 цена 1,5x; D-5 провайдер и UI вне
  требований; D-6 (открыта до `ready`) новый лимит ниже израсходованного; D-7 удержание 15 мин; D-8
  (открыта до `ready`) сумма возврата, комиссия, срок.
- Скрытые пробелы готовности фичи 02 (в `srs` и `ready` не названы нигде): частичное покрытие пакетом
  (бронь 2 ч при остатке 1 ч); параллельные удержания сверх лимита (лимит проверяется при удержании,
  уменьшается при подтверждении); отмена в состоянии «ожидает оплаты»; вебхук после истечения
  удержания - деньги списаны, брони нет.

## Ключ

Засчитывается применение в выходе (дифф и ответ). «Провал» - нарушение, названное в строке. Находка по
приманке - ложное срабатывание. Дефект вне скилла проверяет, что дисциплина не съела общую
внимательность: его пропуск со скиллом при находке в контроле - регресс.
