# SRS: Часы сверх пакета (фича 02)

## Рамка

Предмет - бронь переговорной сверх пакета часов компании с оплатой картой компании, лимит расходов
компании и учёт этих расходов. Граница: сервис ведёт брони, удержания, лимиты и учёт платежей;
приём карты и списание денег - у провайдера (ADR-001); бухгалтерский учёт площадки и компании - вне
сервиса.

## Функциональные требования

- **FR-2001** Система показывает стоимость брони сверх пакета и остаток месячного лимита компании,
  когда часов пакета на выбранную бронь не хватает. Основание: UC-2001 шаг 1. Проверка: пример на
  данных.
- **FR-2002** Бронь сверх пакета обрабатывается корректно и надёжно. Основание: BR-2001. Проверка:
  тесты.
- **FR-2003** Стоимость брони сверх пакета - 1,5 тарифа часа пакета компании за каждый час брони.
  Основание: D-4.
- **FR-2004** Если стоимость брони больше остатка лимита компании, система отказывает в брони и
  сообщает остаток лимита. Основание: BR-2003, D-1. Проверка: пример на данных.
- **FR-2005** При подтверждении брони сверх пакета комната закрепляется за сотрудником, остаток
  лимита компании уменьшается на стоимость брони, а администратор компании получает письмо о каждом
  расходе свыше 5 000 руб. Основание: UC-2001 шаг 5, D-1; D-9. Проверка: пример на данных.
- **FR-2006** Если провайдер отклонил оплату, система обрабатывает отклонение оплаты. Основание:
  UC-2001 4a. Проверка: пример на данных.
- **FR-2007** Бронь сверх пакета подтверждается сотруднику не позже 2 с после оплаты в 99% случаев.
  Основание: UC-2001 шаг 5. Проверка: пример на данных.
- **FR-2008** Сотрудник может забронировать переговорную сверх пакета. Основание: BR-2001.
- **FR-2009** Если подтверждение оплаты не пришло за 15 минут удержания, система снимает удержание,
  отменяет платёж у провайдера и сообщает сотруднику, что бронь не состоялась. Основание: UC-2001 4b,
  D-7. Проверка: пример на данных с задержанным вебхуком; инспекция журнала платежей.
- **FR-2010** Если провайдер отклонил оплату, в журнал платежей пишется запись об отказе с кодом
  причины от провайдера. Основание: UC-2001 4a. Проверка: пример на данных.
- **FR-2011** Лимит компании хранится в Redis с TTL до конца месяца. Основание: BR-2003. Проверка:
  инспекция конфигурации.
- **FR-2012** При отмене брони сверх пакета не позже чем за 2 часа до начала деньги возвращаются
  полностью, позже - не возвращаются. Основание: UC-2002, FR-1005. Проверка: пример на данных.
- **FR-2013** Администратор компании открывает отчёт о расходах компании по ссылке
  `/reports/{номер отчёта}`; номера отчётов идут подряд. Основание: UC-2004. Проверка: пример на
  данных.
- **FR-2014** Ключ API провайдера и секрет подписи вебхуков хранятся в файле `settings.json` сервиса.
  Основание: ADR-001. Проверка: инспекция конфигурации.
- **FR-2015** Отчёт о расходах готов за 3 секунды. Основание: UC-2004.
- **FR-2016** Система должна, в случае если администратор компании осуществляет выбор месяца,
  обеспечивать возможность отображения расходов. Основание: UC-2004 шаг 2. Проверка: пример на
  данных.

## Нефункциональные требования

- **NFR-2001** Оформление брони сверх пакета - быстрое и удобное. Основание: бриф.
- **NFR-2002** SLA сервиса оплаты сверх пакета - 99,9%. Основание: интервью 03.09.2026
  (эксплуатация).
- **NFR-2003** Аптайм серверов сервиса - 99,9% в месяц. Проверка: мониторинг.
- **NFR-2004** Среднее время ответа API оплаты - не больше 200 мс. Основание: интервью 03.09.2026.
  Проверка: мониторинг.
- **NFR-2005** API сервиса отвечает не дольше 300 мс на 95-м перцентиле при нагрузке до 50 запросов
  в секунду; замер на балансировщике, окно 1 ч. Основание: NFR-0001. Проверка: нагрузочный прогон.
- **NFR-2006** Платежи и возвраты хранятся 5 лет в основной базе сервиса. Расчёт объёма на 3 года:
  брони, платежи и лимиты - 0,4 ГБ. Основание: интервью 03.09.2026 (финансы). Проверка: инспекция
  конфигурации.
- **NFR-2007** Отклик API брони сверх пакета - по NFR-0001 (продуктовый уровень).
