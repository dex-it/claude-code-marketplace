# SD-16. Возвраты в админке

**Зачем.** Возвраты по оплаченным заказам операторы сейчас делают руками в личном кабинете провайдера и
ведут в таблице. Нужно, чтобы возврат оформлялся из нашей админки и уходил провайдеру автоматически.

**Что сделать.**
- `GET /api/admin/refunds` - список возвратов, `GET /api/admin/refunds/:id` - возврат и все возвраты по
  тому же заказу.
- `POST /api/admin/refunds` - оформить возврат по оплаченному заказу: какие позиции возвращаются, сумма
  (если не указана - заказ возвращается целиком), причина. Возврат сразу отправляется провайдеру.
- `PATCH /api/admin/refunds/:id` - смена статуса возврата оператором (например, провайдер отклонил
  возврат по телефону).
- Доступ - только у роли `admin`.
- Каждое действие в админке пишется в журнал аудита (файл, путь - `AUDIT_LOG`).
- Клиенту уходит письмо о возврате.
- Манифест деплоя для кластера.

**Провайдер возвратов.** `POST {REFUNDS_URL}/v1/refunds`, заголовок `X-Api-Key` (`REFUNDS_API_KEY`), тело
`{ "order_id", "amount", "reason" }` (сумма в копейках; без суммы - полный возврат). Ответ `200`
`{ "refund_id": "...", "status": "accepted" }`; ошибки `4xx/5xx` - `{ "error": "..." }`.

**Критерии приёмки.**
- Повторное оформление того же возврата не уходит провайдеру второй раз.
- Сумма возвратов по заказу не превышает сумму заказа.
- `npm run typecheck` и `npm test` зелёные.
