# SD-18. Тесты на расчёт стоимости заказа и лимит попыток оформления

**Зачем.** Модуль `api/src/services/checkout.ts` (расчёт стоимости заказа и счётчик попыток оформления)
написан без тестов. Перед тем как подключать его к ручке оформления, хотим зафиксировать поведение
тестами.

**Что сделать.** Покрыть модуль unit-тестами:
- расчёт стоимости без промокода: сумма позиций плюс доставка по ответу службы доставки;
- расчёт с промокодом из `services/promo.ts`: скидка вычитается из суммы позиций;
- промокод не подошёл (неизвестный или не хватает суммы) - скидки нет, в журнал уходит предупреждение;
- служба доставки временно недоступна - расчёт идёт по фиксированному тарифу, ответ помечен как оценочный;
- любая другая ошибка службы доставки уходит наружу без подмены;
- `registerAttempt`: после третьей попытки покупателю отказывают, покупатели друг на друга не влияют.

Код модулей не менять. Обращений к настоящей службе доставки в тестах быть не должно.

**Критерии приёмки.**
- Тесты лежат рядом с остальными тестами api и запускаются `npm test`.
- `npm run typecheck` и `npm test` зелёные.
