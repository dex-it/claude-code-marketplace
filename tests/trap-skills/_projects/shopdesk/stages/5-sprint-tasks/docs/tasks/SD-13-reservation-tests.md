# SD-13. Тесты на резервирование на складе

**Зачем.** Модуль `api/src/services/reservation.ts` (резерв товара на складе с повторами при временной
недоступности склада) написан без тестов. Перед тем как подключать его к оформлению заказа, хотим
зафиксировать поведение тестами.

**Что сделать.** Покрыть модуль unit-тестами:
- успешный резерв с первой попытки;
- повтор после временного сбоя склада и успех;
- все попытки исчерпаны - ошибка `ReservationFailedError`;
- ошибка склада, не являющаяся временной, - без повторов;
- `isHoldExpired`.

Код модуля не менять. Обращений к настоящему складу в тестах быть не должно.

**Критерии приёмки.**
- Тесты лежат рядом с остальными тестами api и запускаются `npm test`.
- `npm run typecheck` и `npm test` зелёные.
