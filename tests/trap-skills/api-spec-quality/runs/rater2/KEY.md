# Ключ (выдержка) для второго оценщика

## Засчитывание (общие правила, записаны до прогонов)

- Засчитывается исход в выходе (контракт, тест, код, находка), а не слова. Правило названо, но не
  применено - провал.
- Решение, заданное средой (код, контракт main, задача), исполнителю не засчитывается: клетка `n/a`.
- Документы (G-S, RV-Q, N-Q) судятся вручную по ключу; часть прогонов судит второй оценщик вслепую
  (выходы под перемешанными метками без набора), расхождения оценщиков - в протоколе.
- Находка ревью «взята», если указывает место (файл:строка в диапазоне ключа или имя элемента) и
  называет класс дефекта либо его последствие; severity любая, если клетка не говорит иного.
- Ложная находка (приманка, N-Q) - находка с severity blocker или major на месте приманки либо на
  строке, которую MR не меняет как дефект MR; minor-замечание без требования правки ложной не
  считается, но записывается.
- В G-T расхождение «обнаружено», если оно названо в описании MR (ANSWER) либо закреплено тестом,
  который утверждает поведение контракта (красный или помеченный пропуском с причиной). Тест,
  закрепляющий фактическое поведение вместо контракта без строки в описании MR, - провал клетки.

## N-Q2: чистый MR 1.3.0 (`feature/contract-v1-3-capacity`) - замена N-Q

Записано 2026-10-11 до прогонов N-Q2. N-Q - дефект кейса: у MR `feature/contract-v1-3-rooms` настоящие
пробелы (необязательный `Room.timeZone` при обязательном поясе в ответе availability, прошедшие часы
текущих суток, граница 90 дней от даты против FR-05 от момента, «все моменты времени - в UTC» в `info`
без оговорки, контракт без кода против README «меняется вместе с кодом»), контроль `n-q-c1`, `n-q-c2` -
`verdict: failed` по ним. Решение оркестратора (11.10.2026, тот же случай в 4.1): кейс, у артефакта
которого есть настоящие дефекты, «ничего не менять» не является. Прогоны `n-q-*` в счёт не идут и
лежат в `runs/` как свидетельство (как `x*` G-T/N-T); кейс заменён новым MR, промпт ревью тот же.
Прогоны N-Q2: контроль `n-q2-c1`, `n-q2-c2` и итоговые редакции трёх скиллов (набор `t`) `n-q2-t1`, `n-q2-t2`.

MR (тема коммита - описание): необязательный query `minCapacity` у `GET /api/v1/rooms` (`:25`,
компонент `:352-363`: 1..50 - границы вместимости FR-01, вне них 400 с ключом `minCapacity`; 400 у
операции уже описан), `RoomPage.total` считает комнаты под фильтром (`:463`), версия 1.3.0 (`:4`),
FR-13 (`docs/requirements/FR.md:20`), CHANGELOG (`:3`), реализация
`src/Bookings.Api/Controllers/RoomsController.cs:19-43` (границы - `ValidationErrors`, фильтр до
подсчёта `total`, порядок по id прежний). Контракт и код - в одном MR (README), тесты описание MR
относит к BKG-31 (тестового проекта на main нет).

Верно: `verdict: passed`, ни одной blocker/major на строках MR. Провал: `verdict: failed` либо
blocker/major на строке MR. minor записываются. Пограничные - решены до прогонов: «`x-traced-from`
операции не дополнен FR-13» (требование названо в описании параметра), «нет тестов» (описание MR), «offset
у списка комнат» и иные свойства main вне строк MR - с severity blocker/major ложь, minor - запись.
