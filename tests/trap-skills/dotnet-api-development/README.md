# dotnet-api-development: сжатие по свидетельству, группа 2.2

Скилл `dex-skill-dotnet-api-development` 2.6.1 ([`inputs/SKILL-2.6.1.md`](inputs/SKILL-2.6.1.md)),
эпик #291, группа 2.2 (#297). Итог - 2.7.0 ([`inputs/SKILL-2.7.0.md`](inputs/SKILL-2.7.0.md)): девять
пунктов из 20 ловушек.

## Заход

Вход, исполнитель и расход группы - протокол
[dotnet-resilience](../dotnet-resilience/README.md#заход-группы-22). Кейсы скилла: G-A (код), RV-A
(ревью); приманка RV0 (P0-D) - её прогоны всех наборов лежат здесь, в `runs/rv0-*`.

**Фикстура RV0.** Первые два входа давали справедливые blocker/major: нет фолбэка на базовую цену,
которого требует задача (`runs/rv0-c*-input1`); фолбэк глотал 4xx, пояс магазина без теста
(`runs/rv0-c*-input2`). Вход исправлен до прогонов со скиллом; на третьем контроль - 0 blocker/major.

## Потребители

Бандлы `dotnet-developer`, `dotnet-fullstack`; Skill tool в фазе: `dotnet-coder`, `architect-dotnet`
(и README); `security-reviewer` - пример маршрута; сноска в `dex-skill-api-documentation`. Кейс
активации `dotnet-api-dev-in`.

**D10, D14 - сужение.** Контроль RV-A держал обе клетки 4/4 (`c1`-`c4`), со скиллом `n1` - D10 1/4,

поднимал ни код ответа, ни расхождение схемы с `api/products`. Реакция - ревизия 2: оба пункта
возвращены названиями. `p` и `f` - D10, D14 2/2 в каждом кейсе.

**D1 в G-A `f` спорно.** В обоих прогонах action сверяет `request.SupplierId` с путём и отвечает 400 -
проверка согласованности входа, загрузка, поиск и пересчёт в сервисе `Pricing.Application`. Засчитано
плюсом; та же сверка есть в контроле `g-a-c1`.

**D20 - K1 перемерен.** Пункт пришёл в 2.6.0 по кейсу K1 протокола
[removed/dotnet-di](../removed/dotnet-di/README.md): контроль там 1/2 (литералы в `c1`). На исполнителе
группы K1 перемерен тем же поручением и ключом: контроль 2/2 (`k1-c1`, `k1-c2` - константы
`NotificationChannels` в `AddKeyed*` и `[FromKeyedServices]`), редакция с возвращённым пунктом
([`SKILL-k1.md`](inputs/SKILL-k1.md)) - 2/2. Клетка держится без пункта в обоих кейсах - пункт снят.

**D20 - перемер ревью #327.** На дату записи не выгружено в репозиторий: промпт и флаги `k1-c1`,
`k1-c2`, `k1-f1`, `k1-f2` и чем подан скилл в `k1-f*`. Кейс внесён в раннер
[`run-group-2-2.sh`](../_projects/pricing/run-group-2-2.sh) (`k1`): проект `removed/dotnet-di/inputs/code`,
поручение - дословно из [протокола K1](../removed/dotnet-di/README.md#кейс-k1), промпт кода - по его
шаблону `dotnet-ef-core/inputs/prompt-plain.md` (без сборки, ответ в `_answer.md`), строка скилла
«правила ASP.NET Core API, принятые в команде». Набор - контроль K1 `c3`, `c4` без скилла, ключ -
«Сверка» K1. Пограничное, записано до прогонов: место потребления - `[FromKeyedServices]` или
`Get(Required)KeyedService`; ключ, объявленный константой или enum, но в любом месте регистрации или
потребления записанный литералом, - провал. Снятие D20 стоит, если контроль 2/2; иначе D20
возвращается названием. Исход: `k1-c3`, `k1-c4` - 2/2, константы `NotificationChannels` в обоих
`AddKeyedSingleton` и в обоих `[FromKeyedServices]`; `[FromKeyedServices("sms")]` в `_answer.md` `c4` -
проза ответа, не место регистрации или потребления. Снятие D20 держится на этом перемере (среда - в
[«Среда и порядок»](../dotnet-resilience/README.md#заход-группы-22)).
