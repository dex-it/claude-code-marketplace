**Решения:**
- **Формат без `giftWrap`:** старые сообщения читаются как `giftWrap = false`, отдельной ветки для них нет.
- **Идемпотентность:** доставка at-least-once, продьюсер идемпотентный (`acks=all`).
  - **Клиенты:** id учтённых заказов лежат в документе клиента, последние 1000, и условие с `$inc` выполняются одним `UpdateOne`. Повтор не удваивает `ordersCount` и `totalSpent`. Транзакции не нужны, они на одиночном узле Mongo недоступны.
  - **Импорт:** вставка идёт по `_id` заказа, `InsertMany` без порядка, дубли ключей не считаются ошибкой.
- **Смещения и ядовитые сообщения:** автокоммита нет. Смещение фиксируется синхронно после каждого сообщения, для импорта — после каждой пачки, так что при ребалансе обработанное не перечитывается.
  - **Повторы:** после `MaxProcessingAttempts` попыток (по умолчанию 5), а битый JSON сразу, сообщение уходит в `<топик>.DLT` с телом, ключом и причиной в заголовках.
  - **Продвижение смещения:** смещение двигается только после того, как брокер принял сообщение в DLT.
  - **Пачка импорта:** если пачка не вставляется, сообщения вставляются по одному, неудачные уходят в DLT.

**Что нужно от платформы:** для импорта я завёл отдельную группу `fulfil-orders-import`, потому что в задаче названа только `fulfil-orders`. Платформе нужно создать эту группу, а также топики `orders.import`, `orders.status-changed` и обе `*.DLT`. Имена настраиваются в `FulfilOptions`.
