**Решения:**
- **Формат заказа:** `GiftWrap` в `OrderPlaced` и `Order` — необязательный параметр со значением `false`, поэтому старый формат без поля читается без ошибок. Смещения Kafka сохраняются только после обработки, при сбое сообщение читается заново. Нечитаемый JSON пропускается с записью в лог.
- **Дубли:** заказ в `customers` учитывается один раз. Для этого сначала пишется маркер в `processedOrders`, потом `$inc` с `Decimal128` для `totalSpent`. Это нужно, потому что реплик 3 и доставка повторяется. Если сервис упадёт между маркером и `$inc`, один заказ не будет учтён. Полная защита потребует транзакций, а стенд — одиночный узел MongoDB без набора реплик. При повторной доставке `OrderStatusChanged` может уйти дважды, склад должен это терпеть.
- **Импорт:** пачки по 100 сообщений, один неупорядоченный `InsertMany` на пачку. Неполная пачка записывается, если поток молчит секунду. Дубликаты ключей при повторе пачки игнорируются.

**Нужно уточнить у платформы.** Для импорта я взял отдельную группу `fulfil-orders-import`, потому что в `fulfil-orders` реплики подписаны на другие топики. Топики `orders.status-changed` и `orders.import` в задаче не перечислены, автосоздание топиков я отключил. Название группы и наличие топиков надо подтвердить.
