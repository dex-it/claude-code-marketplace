## Шаг 0

Stampede (C4) похож на `dotnet-caching` H1 (пункт `dotnet-resilience`), но тот - `IMemoryCache` внутри процесса; дубль не доказан, C4 возвращён в `redis` ревизией `r` (ниже). Fixed window (C12) - дом `redis` по записи
`reference-architectures`, остальные дубли - [таблица группы](../kafka/README.md#шаг-0). Кейсы: G-C (код, `docs/tasks/FUL-13.md`: кэш цен,
лок пересчёта, лимит 100 в минуту, корзина, очередь писем, StackExchange.Redis 3.4.5), RV-C (ревью `catalog-cache`: C1-C12,
приманки P1 короткий TTL флага «в обработке» и P2 префикс версии `v2:cart:`, вне скилла O1 `Math.Round` цены в кэше, O2 ключ API
в логе). Дефект кейса G-C: ADR-0001 задаёт RabbitMQ для команд, поэтому оба прогона делали очередь писем на MassTransit -
клетка C11 в коде `n/a`, судится ревью.

## Ревизия r по ревью mmx003 (20.10.2026)

Правило записано до прогонов ([`_projects/fulfil`](../_projects/fulfil/README.md), правило 10, коммит `dbe89e56`); набор `r`, по два прогона (`r1`, `r2`), `claude-sonnet-5-5`, effort medium, файл [`inputs/SKILL-1.2.0-r.md`](inputs/SKILL-1.2.0-r.md); таблицы судьи - [`judge/judge-r.md`](judge/judge-r.md). **C4 возвращён пунктом** «Конкурентные промахи горячего ключа идут в источник каждый». Основание: дубль с `dotnet-resilience` H1 не доказан - тот пункт про `IMemoryCache.GetOrCreate` внутри процесса ([протокол](../dotnet-resilience/README.md)), а `redis` стек-нейтрален, `dotnet-resilience` не едет в `dex-bundle-infrastructure` и не грузится `redis-specialist`; контроль RV-C был 0/2. Итог: RV-C C4 2/2 (контроль 0/2), G-C C4 2/2 (single-flight в процессе; повторной проверки кэша внутри загрузки нет, по ключу допустимо), остальные единицы G-C и RV-C (включая C2, C9, C12, P1, P2, O1, O2) 2/2. Аннотация потребителя `dotnet-performance-analyst` - «промахи горячего ключа». Шаг 0: C4 больше не «дубль, дом `dotnet-resilience`», а единица `redis` с пунктом; доноров `dotnet-resilience` это не отменяет (там H1 про процесс).

- **C9, G-C:** `c2` без fencing-токена принят как допустимое решение (продление с проверкой владения и требование

- **C12:** решение (скользящее окно, token bucket, GCRA) выводит исполнитель, в пункте только название.
