**Решения**
- **Недоступный Redis.** Сервис стартует и без него: подключение не обрывается при старте, а команды при разрыве падают сразу. Кэш цен при этом читает из источника, лимит запросов пропускает всё, воркеры ждут и пробуют снова.
- **Кэш цен.** На каждый sku в процессе уходит один запрос к источнику, а TTL получает разброс. Запись в кэш идёт только если версия sku не изменилась за время запроса, так что поздний ответ источника не затрёт инвалидацию.
- **Лок пересчёта остатков.** Лок продлевается каждую треть TTL. Если владение не подтверждается дольше 2/3 TTL или ключ перехвачен, пересчёт отменяется. Лок отдаёт fencing-токен, который передаётся в `IStockRecalculator`. Реализации нужно делать записи в MongoDB условными по этому токену.
- **Лимит запросов.** Скользящее окно на sorted set и Lua-скрипт, время берётся из Redis. Это убирает всплеск на границе окон. Без `X-Api-Key` ответ 401, сверх лимита 429 с `Retry-After`.
- **Корзина и письма.** Корзина лежит в hash с TTL 30 дней. Очередь писем сделана на Redis Streams: задание остаётся в pending, пока отправка не подтверждена, зависшие задания забираются через 2 минуты, а после 5 неудач уходят в `mail:dead`. Доставка гарантирована минимум один раз, поэтому `IEmailSender` должен быть идемпотентным по `MailJob.Id`.

**Что осталось доделать**
- В репозитории нет `StockRecalculator` и реализации отправки писем. Пока `IStockRecalculator` и `IEmailSender` не зарегистрированы, соответствующие воркеры при старте пишут предупреждение и не работают.
- `/internal/price-changed` пока не защищён аутентификацией. В задаче этого не было.
