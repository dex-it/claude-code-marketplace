**Принятые решения**
- **Redis недоступен:** сервис стартует и без него (`AbortOnConnectFail=false`), а ошибки Redis обрабатываются на месте. Цена читается из источника. Лимит запросов в этом случае не применяется. Пересчёт остатков пропускается, а `price-changed` отвечает 503, чтобы ценовой сервис повторил вызов.
- **Цены:** промахи по одному sku на реплике сливаются в один запрос к источнику. TTL равен 5 минутам с разбросом ±20%. Инвалидация увеличивает счётчик версии sku, поэтому загрузка, начатая до смены цены, не запишет старую цену в кэш.
- **Пересчёт остатков:**
  - Лок берётся на 30 с и продлевается каждые 10 с. Если продлить не удалось, проход отменяется.
  - Каждому проходу выдаётся возрастающий fencing-токен, потому что отмена может прийти позже, чем лок будет потерян.
- **Лимит запросов:** скользящее окно на sorted set с Lua и серверным временем, так что на границе минут всплеска нет. Ключ клиента проверяется на длину (не больше 128 символов).
- **Корзина:** один hash на корзину. Позиции лежат в полях `i:{sku}`, промокод в поле `promo`, читается всё одним `HGETALL`, TTL 30 дней.
- **Письма:** Redis Stream с consumer group, ack после отправки и повторная выдача зависших заданий через 2 минуты. Доставка at-least-once.
- **`docker-compose.yml`:** добавлены `maxmemory 512mb`, политика `volatile-lru` (вытесняются только ключи с TTL, очередь не вытесняется) и `appendonly yes`.

**Что нужно доделать**
- В репозитории нет `StockRecalculator` и реализации `IEmailSender`. Без их регистрации в DI сервис не стартует. `StockRecalculator` должен реализовать `IStockRecalculator`, и его запись в MongoDB должна отвергать токен меньше уже записанного.
- Нет ограничения числа повторов для письма, которое не отправляется. Такое письмо будет повторяться бесконечно.
- Для `/api/*` запрос без заголовка `X-Api-Key` получает 401. Задача этого не требовала.
