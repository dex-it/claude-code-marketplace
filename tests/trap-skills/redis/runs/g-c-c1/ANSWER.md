Задача FUL-13 сделана в рабочем дереве, ничего не закоммичено. Сборки и запуска не было, поэтому код не проверен компиляцией.

**Изменённые файлы**
- Изменены: `src/Fulfil/Program.cs`, `src/Fulfil/Ports/Ports.cs` (добавлены `IStockRecalculator` и `IEmailSender`), `docker-compose.yml`.
- Добавлены: `src/Fulfil/Redis/PriceCache.cs`, `src/Fulfil/Redis/RedisLock.cs`, `src/Fulfil/Redis/RateLimitMiddleware.cs`, `src/Fulfil/Redis/RedisCart.cs`, `src/Fulfil/Jobs/StockRecalcJob.cs`, `src/Fulfil/Contracts/SendEmail.cs`, `src/Fulfil/Mail/SendEmailConsumer.cs`.

**Решения**
- **Цены:** кэш цен с TTL 5 минут плюс случайные до 60 секунд. Параллельные промахи по одному SKU в рамках реплики сводятся к одному обращению к источнику. `POST /internal/price-changed` удаляет ключ. Если инвалидация разминётся с загрузкой, устаревшее значение живёт не дольше TTL.
- **Пересчёт остатков:** блокировка в Redis берётся через `SET NX` с арендой 30 с, продлевается в фоне, снимается скриптом по токену. Fencing-токен передаётся в `IStockRecalculator.RunAsync`. Сам `StockRecalculator` в репозитории отсутствует, поэтому я описал для него порт. Он должен проверять токен при записи в MongoDB, иначе блокировка в Redis одна не гарантирует «ровно одну» реплику.
- **Лимит запросов:** фиксированное окно в минуту, атомарный скрипт `INCR` + `EXPIRE`. Без `X-Api-Key` отвечаем 401, сверх лимита — 429 с `Retry-After`. Если Redis недоступен, запросы пропускаются (fail-open).
- **Корзина:** один hash на покупателя. Позиции меняются через `HINCRBY`, промокод хранится отдельным полем, читается всё одним `HGETALL`. TTL 30 дней.
- **Рассылка писем:** очередь сделана на RabbitMQ через MassTransit (по ADR-0001), а не на Redis. Задание подтверждается только после отправки, поэтому перезапуск воркера при деплое его не теряет. Реализации `IEmailSender` нет, и эндпоинта постановки письма в очередь тоже нет.
- **Redis в compose:** добавлены `maxmemory 256mb`, политика `volatile-lru` и `appendonly yes`. Вытесняются только ключи с TTL, а все ключи сервиса создаются с TTL. Корзины при нехватке памяти тоже могут вытесняться.
- **`/internal/price-changed`:** у эндпоинта нет аутентификации. Его нужно закрыть на уровне сети или ingress.
