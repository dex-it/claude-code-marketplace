# dotnet-validation: сжатие по свидетельству, группа 2.1

Скилл `dex-skill-dotnet-validation` 1.2.1 ([`inputs/SKILL-1.2.1.md`](inputs/SKILL-1.2.1.md)), эпик #291,
группа 2.1 (#296).

## Заход группы 2.1

Общий для пяти скиллов: `dotnet-async-patterns`, `dotnet-validation`, `dotnet-logging`,
`dotnet-resources`, `dotnet-code-quality`.

**Вход.** Мини-проект [`_projects/billing`](../_projects/billing/README.md#группа-21-net-скиллы-кода),
ветки `branches/<имя>`. Ключ, коды единиц и допустимые решения записаны до первого прогона. Кейсы
набора: G3, RV-V; приманки G0, RV0.

**Исполнитель.** `claude -p`, `--model claude-sonnet-5-5 --effort medium --restricted
--strict-mcp-config --no-session-persistence --disable-slash-commands --permission-mode acceptEdits
--max-budget-usd 3`, инструменты `Read, Write, Edit, Glob, Grep, Bash`, разрешён только `Bash(git *)`
(кодовым кейсам - и `Bash(dotnet *)`). Скилл подан копией `SKILL.md` через `--add-dir`, `Skill` tool
не вызывается.

## Потребители

Skill tool в фазе: `dotnet-coder`; by-stack через `stack-registry`: ревьюеры, `debugger`, `bug-fixer`. Бандлы: `dotnet-developer`, `dotnet-fullstack`. Кейс активации `dotnet-validation-in`.

**V14 - пункт снят.** В `g3-n2` название «ручной вызов валидатора в каждом обработчике» привело к
`ValidationFilter<TBody>` через `AddEndpointFilter` вместо принятого в проекте `BillingValidator.Check`
в хендлере - провал клетки V14-P. Контроль конвенцию держал 2/2: пункт ничего не добавляет и толкает
против свода проекта. Редакция `SKILL-n2.md` - без пункта и без «вызов валидатора» в `description`;
`m`: G3 - V1, V2, V10, V12 2/2, `validator.Check` в обоих; RV-V - все K 2/2, V14-P не провален.

**V12.** Контроль клетки не имел; со скиллом `SetInheritanceValidator` выбран 4/4 - без контроля это не
свидетельство. Название остаётся.

**Охват и приманки.** RV0: O1 (фильтр только по `PaidAt is null`) - `n` 1/2, `m` 2/2, шум. PW
(`LogWarning` для штатного пропуска дайджеста) поднят minor в `n` и `m` - название L11, не провал.
RV-V `m2`: minor «тестовый csproj без `TreatWarningsAsErrors`» - название Q4 вне предмета MR, не провал.
PL (константы `PartnerLimits`) не поднят.

**RV0 `m1`** (по ревью PR #320): `rv0-m1:6` - major «хендлер в Application напрямую зависит от
InMemoryStore ... зависимость не ловится сборкой». Находка верна (соседи ходят через
`IInvoiceRepository`), в контроле она minor (`rv0-c2:10`), в `rv0-n1:10` - minor. Severity major - в
предмете названий `dotnet-code-quality` «Слои без контроля графа зависимостей», «Нарушение зависимости
слоёв не роняет сборку» (Q11, Q13); строго по ключу RV0 («ни одной blocker/major в предмете скиллов
группы») это провал 1/4 прогонов со скиллом. Решение владельца эпика: Q11, Q13 сняты по вреду без
свидетельства пользы (протокол `dotnet-code-quality`).

**Набор `f` (1.3.0: V1, V10, V12).** G3: V1, V10 2/2, `SetInheritanceValidator` (V12) 2/2,
