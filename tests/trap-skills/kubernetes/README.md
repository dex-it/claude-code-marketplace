## Ревизия 3 по ревью владельца (PR #368): K4

Тело скилла не менялось. Ключ K4 (`_projects/depot/README.md`) требовал `requests` и `limits` по памяти и CPU; документация
Kubernetes (Resource Management for Pods and Containers, раздел о requests и limits) CPU limit обязательным не называет: он работает
через throttling, и его часто опускают. Требование CPU limit в ключе - сверх нормы. Вердикт по ключу как записан (до прогонов): K4 в `k-w` 0/2. Пересчёт c1, c2 по ключу, поправленному после прогона, - наблюдение, снятием не засчитывается до решения владельца; снятие K4 - прогоном по ключу, записанному до него (стек #376). Пункт «без requests и limits» остаётся в теле как признак (по замечанию владельца пункт не трогаем). Пересчёт построен на ответе без перепрогона: основание - правка ключа вниз, а не новая оценка исполнителя; после просмотра ответов правило 3 набора такое чтение не принимает. Снятие K4 держится не на этом пересчёте, а на свежем контроле ревизии 4 (ниже).
