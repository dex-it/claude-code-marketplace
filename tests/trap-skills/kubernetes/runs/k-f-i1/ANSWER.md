Изменения в рабочем дереве, ничего не закоммичено. Ничего не проверял: сборки и кластера нет, манифесты не прогонял.

**Причина 503.** В `service.yaml` были две ошибки, из-за которых endpoints пуст:
- Селектор был `app: depot-api`, а у подов метка `app.kubernetes.io/name: depot-api`. Исправил на метку подов.
- `targetPort` был 80, а приложение слушает 8080. Исправил на 8080.

**Изменённые файлы**
- `deploy/k8s/service.yaml`: исправления выше.
- `deploy/k8s/deployment.yaml`:
  - **Проверки.** Раньше liveness и readiness обе ходили в `/health`, который обращается к БД, с `periodSeconds: 1` и `failureThreshold: 1`. Любой сбой БД или медленный ответ перезапускал бы все поды, а холодный старт (20–35 с) не пережил бы ни один под.
    - liveness теперь `tcpSocket :8080`, без обращения к БД;
    - readiness остаётся на `/health`;
    - добавил `startupProbe` на `tcpSocket`, запас около 155 с. Порт открывается только после миграций.
  - **Выкат без простоя.** `RollingUpdate` с `maxUnavailable: 0` и `maxSurge: 1`.
  - **Ноды и drain.** Добавил `topologySpreadConstraints` по нодам с `ScheduleAnyway` и `PodDisruptionBudget` с `maxUnavailable: 1`. PDB лежит в том же файле после `---`.
  - **Ресурсы.** requests 100m CPU и 384Mi, limits 500m и 512Mi, по замерам из runbook.
  - **Безопасность.** `runAsNonRoot` с uid 1654, `allowPrivilegeEscalation: false`, `readOnlyRootFilesystem`, `drop ALL`, и `emptyDir` в `/tmp`, потому что туда приложение пишет выгрузки.
- `deploy/k8s/secret.yaml`: удалён. В нём лежали значения секретов в base64 (строка подключения с паролем БД и ключ API), а по дисциплине их в репозитории быть не должно.

**Замечания**
1. **Секрет `depot-secrets` нужно создать вне репозитория.** Это либо `kubectl create secret generic` из значений в `docs/stage-values.md`, либо внешний менеджер секретов. Без этого поды не стартуют. Значения в stage-манифесте были фейковыми, но для прода нужны свои. Файл `docs/stage-values.md` с этими значениями остался в репозитории. Раз он помечен «только stage», я его не трогал.
2. **Путь для liveness.** Лучше добавить в приложение маршрут вроде `/live`, который не обращается к БД, и перевести liveness на него. Пока он не появился, liveness проверяет только то, что порт открыт.
3. **`depot-worker`.** Я его не менял. У него нет проб и нет `readOnlyRootFilesystem` с `/tmp`. PDB для него не добавлял: при `minAvailable: 1` и одной реплике drain ноды с воркером зависнет. Recreate допускает короткий простой воркера при выкате и drain, и это нормально для очереди.
4. **Прочее.**
   - Образ закреплён по тегу `1.4.0`, не по digest.
   - Для Ingress `depot-tls` и секрет `regcred` должны существовать в кластере.
   - NetworkPolicy и HPA не добавлял, их в задаче нет.
