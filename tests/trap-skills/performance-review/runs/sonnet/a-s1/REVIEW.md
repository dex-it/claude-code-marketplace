# Ревью MR: отчёты по клиентам и счета (Orders.Api)

Масштаб: 40 тыс. клиентов, 3 млн заказов. Формат: файл:строка - что не так - чем кончится - severity.

## Blocker

1. **Controllers/OrderExportController.cs:15** - SQL-инъекция: `status` из query подставляется в `FromSqlRaw($"...")` конкатенацией. Результат: `status=' OR 1=1 --` отдаёт все заказы, `'; DROP TABLE ...` исполняется под учёткой приложения. Нужен `FromSql($"... {status}")` или LINQ `Where(o => o.Status == status)`. blocker.
2. **Controllers/OrderExportController.cs:15** - в сыром SQL идентификаторы без кавычек (`orders`, `status`). Модель EF для Npgsql без naming convention создаёт таблицу `"Orders"` и колонку `"Status"` (регистр сохраняется), Postgres сворачивает неквотированные имена в нижний регистр. Результат: `42P01 relation "orders" does not exist`, эндпоинт всегда отдаёт 500. Лечится переходом на LINQ. blocker.
3. **Controllers/CustomerReportsController.cs:25-26** - `db.Orders.ToListAsync()` без фильтра грузит все 3 млн заказов в память с change tracking и lazy-прокси, а потом `Count` в памяти. Результат: гигабайты на каждый запрос сводки, OOM / GC-паузы, падение процесса. Нужен `CountAsync(o => o.CustomerId == customerId && o.CreatedAt >= from)`. blocker.
4. **Controllers/CustomerReportsController.cs:28** - (a) интерполяция в `LogDebug` вычисляется всегда, даже при выключенном Debug, поэтому сериализация `orders` выполняется на каждом запросе; (b) `JsonSerializer.Serialize` по прокси-сущностям: цикл `Order.Customer -> Customer.Orders -> Order` даёт `JsonException` (cycle detected), плюс сериализация триггерит ленивую загрузку `Lines`. Результат: сводка падает 500 для любого клиента с заказами; при включённом Debug в лог уходят ПДн (email/имя). Убрать, либо шаблон `{CustomerId}` и счётчик. blocker.
5. **Services/CurrencyConverter.cs:15-17** - singleton держит глобальный `lock`, а внутри блокирующий `GetAwaiter().GetResult()` на HTTP-вызов внешнего сервиса курсов. Результат: все конвертации сериализуются, пропускная способность = 1/latency внешнего API, потоки пула блокируются, при таймауте (100 с по умолчанию) очередь запросов встаёт, thread pool starvation, каскад на весь API. Нужны async-метод без lock и кэш курса с TTL. blocker.

## Major

6. **Controllers/CustomerReportsController.cs:19-22** - N+1 на ленивой загрузке: `order.Lines` в цикле по заказам клиента даёт по запросу на заказ, плюс трекинг всех сущностей. Результат: у клиента с сотнями заказов сотни round-trip'ов, секунды на ответ. Считать суммой в БД одним запросом: `db.OrderLines.Where(l => l.Order.CustomerId == id).SumAsync(l => l.Quantity * l.UnitPrice)`. major.
7. **Controllers/CustomerReportsController.cs:43-49** - для списка рассылки грузятся целые `Customer` (включая `Photo` byte[] и `Notes`) с трекингом и lazy-прокси, нужен только `Email`. Результат: страница на 500 клиентов тянет сотни МБ, лишняя нагрузка на БД и сеть. Нужен `.Select(c => c.Email)` в запросе. major.
8. **Controllers/CustomerReportsController.cs:41-46** - `pageSize` и `page` не ограничены: `pageSize=100000000` снимает пагинацию, `page*pageSize` переполняет int (отрицательный Skip -> 500). Результат: DoS через параметр. Ввести потолок и валидацию. major.
9. **Controllers/OrderExportController.cs:14-24** - выгрузка без пагинации/стриминга: список заказов, затем `StringBuilder`, затем `string`, затем `byte[]` (3-4 копии, LOH). При статусе с миллионами заказов - сотни МБ на запрос, OOM. Нужен `AsAsyncEnumerable` + запись прямо в `Response.Body`, проекция только нужных колонок. major.
10. **Controllers/InvoiceController.cs:22** - `rates.GetRateAsync("EUR").Result`: блокировка потока пула в async-экшене, курс запрашивается у внешнего API на каждый счёт без кэша. Результат: starvation под нагрузкой, латентность счёта = латентность внешнего сервиса. `await` + кэш. major.
11. **Controllers/InvoiceController.cs:24-33** - `rows` типизирован `IEnumerable<InvoiceRow>`, это отложенный запрос: `rows.Sum` (стр. 28) выполняет его, `Render` (стр. 33) выполняет повторно. Результат: два запроса, итог и строки могут разойтись при параллельной правке заказа (сумма в PDF не равна сумме строк). Материализовать один раз (`ToListAsync`). major.
12. **Controllers/InvoiceController.cs:30-31** - `Directory.EnumerateFiles(attachmentsDir)` бросает `DirectoryNotFoundException`, если у заказа нет каталога вложений (типичный случай); `config[...]!` даёт NRE при пустой настройке. Результат: счёт для заказа без вложений - 500. Дополнительно `.ToList().Count > 0` материализует листинг ради проверки наличия: `Any()`. major.
13. **Services/Checksum.cs:12-18** - P/Invoke `crc32` по одному байту с выделенным `byte[1]`: вызов нативной границы на каждый байт (маршалинг, pinning), вместо одного вызова на весь буфер/срез. Результат: на PDF в сотни КБ - сотни тысяч native-вызовов, десятки мс-секунды CPU на счёт. Кроме того: `uLong` в zlib это `unsigned long` (32 бита на Windows, 64 на Linux), `ulong` в сигнатуре неверен на Windows; `DllImport("libz")` без версии на Linux часто не находит `libz.so` в runtime-образе (`DllNotFoundException`). Заменить на `System.IO.Hashing.Crc32` с `ReadOnlySpan<byte>`. major.
14. **Services/PdfRenderer.cs:14-21** - выдаётся не PDF: префикс `%PDF-1.7` без перевода строки + голый текст, без `obj/xref/trailer`. Результат: Acrobat/браузер покажут "файл повреждён", бухгалтерия счёт не откроет; контрольная сумма считается над невалидным файлом. Числа форматируются культурой сервера (`{r.UnitPrice}`), а не инвариантной. Использовать PDF-библиотеку. major.
15. **Program.cs:9** - `UseLazyLoadingProxies()` на всё приложение: скрытые синхронные запросы при любом обращении к навигации (источник п.6 и п.4), не видны в ревью. Результат: N+1 повторяется в любой следующей правке. Отключить и использовать явные `Include`/проекции. major.
16. **Controllers/*.cs (все экшены)** - нет `[Authorize]`: список email рассылки, выгрузка заказов и счета доступны анонимно. Результат: утечка ПДн и коммерческих данных. major.

## Minor

17. **Controllers/CustomerReportsController.cs:36-37** - `CountAsync(...) > 0` вместо `AnyAsync`: подсчёт всех заказов клиента ради булева. Результат: лишнее чтение строк индекса. minor.
18. **Controllers/InvoiceController.cs:35-37** - `Array.Copy` копирует тело PDF в новый массив только чтобы отрезать 8 байт заголовка; `Checksum.Compute(byte[])` не принимает срез. Результат: лишняя копия буфера на запрос. `ReadOnlySpan<byte>`/`pdf.AsSpan(HeaderSize)`. Там же `Task.Run` для CPU-работы в запросе: смена потока без выигрыша. minor.
19. **Controllers/CustomerReportsController.cs:16,30** - `FirstOrDefaultAsync` грузит целого клиента (с `Photo`) ради `Id`/`Name`; `(int)linesTotal` усекает денежную сумму, а поле названо `LinesTotal` (количество или деньги - неясно). Результат: лишние МБ и искажённая сумма. Проекция + `decimal`. minor.
20. **Services/CurrencyConverter.cs:19** и **Controllers/InvoiceController.cs:26** - деление на курс без проверки нуля/null; `currency` без валидации. Результат: `DivideByZeroException`/500. minor.
21. **Services/RateService.cs:14-15** - `currency` вставляется в путь без `Uri.EscapeDataString` (`../` меняет целевой URL на хосте курсов), 404 превращается в исключение, `dto!` даёт NRE при `null`, нет CancellationToken. minor.
22. **Services/CurrencyConverter.cs:8,18** - счётчик пишется `++` под lock, читается через `Interlocked.Read` без lock: смешение механизмов (достаточно `Interlocked.Increment`). Scope создаётся на каждый вызов singleton'а вместо хранения кэша курсов. minor.
23. **Controllers/OrderExportController.cs:22** - CSV: `Number` без экранирования `;`/переводов строки (CSV-инъекция формул в Excel), `o.Total` форматируется культурой сервера (запятая/точка зависит от окружения). Результат: поломанная выгрузка у бухгалтерии. minor.
24. **Controllers/CustomerReportsController.cs:14,24** - `DateTime? since` приходит с Kind=Unspecified; при переносе фильтра в БД (по п.3) с Npgsql 6+ сравнение с `timestamptz` потребует Utc, иначе исключение/сдвиг. Нужно нормализовать на входе. Также ни один экшен не принимает `CancellationToken`: отменённый запрос продолжает нагружать БД. minor.
