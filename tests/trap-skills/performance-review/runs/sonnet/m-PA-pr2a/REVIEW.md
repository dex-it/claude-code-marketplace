# REVIEW: Orders.Api, отчёты по клиентам и счета

Масштаб: 40 тыс. клиентов, 3 млн заказов. Включены lazy proxies.

## Blocker

1. **Controllers/OrderExportController.cs:15**: в `FromSqlRaw` передана интерполированная строка (`$"...'{status}'"`). `FromSqlRaw` не параметризует интерполяцию, поэтому это SQL-инъекция из query-параметра. Итог: утечка или порча данных всей БД, например `status=' OR 1=1; DROP TABLE orders;--`. Нужно `FromSql($"...")` или `FromSqlInterpolated`, либо LINQ `Where(o => o.Status == status)`.
2. **Controllers/CustomerReportsController.cs:25-26**: `db.Orders.ToListAsync()` без фильтра грузит все 3 млн заказов в память ради подсчёта по одному клиенту. Итог: сотни МБ или ГБ на запрос, OOM или GC-шторм, а при нескольких параллельных запросах отказ сервиса. Нужно `CountAsync(o => o.CustomerId == customerId && o.CreatedAt >= from)` в БД.
3. **Services/CurrencyConverter.cs:15-17** (вызов из InvoiceController.cs:48): singleton держит `lock` и внутри него синхронно ждёт HTTP (`GetAwaiter().GetResult()`). Итог: все конвертации по всему приложению идут строго по одной, и каждая занимает поток пула на время внешнего вызова. При медленном сервисе курсов возникает thread-pool starvation, и встаёт весь API, а не только этот эндпоинт. Нужен async-метод без lock; курсы стоит кэшировать (`IMemoryCache` с TTL); `_conversions` обновлять через `Interlocked.Increment`.
4. **Controllers/CustomerReportsController.cs:28**: `LogDebug($"... {JsonSerializer.Serialize(orders)}")` вычисляется всегда, даже при выключенном Debug, потому что интерполяция идёт до проверки уровня. С lazy proxies сериализация обходит `Order.Customer`, `Customer.Orders` и `Lines` (это N+1 и загрузка графа), а для proxy-типов и циклических ссылок даёт `JsonException` (cycle) или огромную строку. Итог: эндпоинт падает с 500 или тормозит, а в логи уходят заказы и ПДн. Нужно убрать, либо логировать id и количество через шаблон `{CustomerId}`.

## Major

5. **Controllers/CustomerReportsController.cs:19-22**: N+1 через lazy loading. `order.Lines` на каждом заказе даёт отдельный запрос, при клиенте со 1000 заказов это 1000 запросов, и всё это синхронно внутри async-метода. Заказы грузятся целиком только ради суммы. Нужно считать в БД: `db.OrderLines.Where(l => l.Order.CustomerId == id).SumAsync(l => l.Quantity * l.UnitPrice)`. Выражение `Quantity * UnitPrice` нужно проверить на переполнение. Если нужны сущности, то `Include`/`AsNoTracking`.
6. **Controllers/CustomerReportsController.cs:30**: `(int)linesTotal` обрезает денежную сумму до целого и молча переполняется (в unchecked-контексте). Итог: неверные суммы в отчёте. `LinesTotal` должен быть `decimal`.
7. **Controllers/InvoiceController.cs:22**: `rates.GetRateAsync("EUR").Result` блокирует поток пула в async-методе, а курс запрашивается по HTTP на каждый счёт. Итог: starvation под нагрузкой, и сбой сервиса курсов превращается в `AggregateException`. Нужно `await` и кэш курса. Также нет проверки `eurRate == 0` (деление на ноль).
8. **Controllers/InvoiceController.cs:24-33**: `rows` типизирован как `IEnumerable<InvoiceRow>`, но это незавершённый запрос. `rows.Sum` (стр. 28) исполняет его один раз, а `Render` (стр. 33) при `foreach` исполняет второй раз. Итог: два обращения к БД, а между ними заказ может измениться, и тогда итог в PDF не совпадёт со строками. Нужно материализовать один раз: `var rows = await ....ToListAsync()`. Сумма считается по округлённым строкам; нужно согласовать это с бухгалтерией.
9. **Controllers/InvoiceController.cs:31**: `Directory.EnumerateFiles(...)` бросает `DirectoryNotFoundException`, если у заказа нет каталога вложений, то есть в типичном случае. Итог: 500 на счёт для заказа без вложений. Нужно сначала `Directory.Exists`, а для проверки наличия использовать `.Any()`: `.ToList().Count > 0` перечисляет все файлы. Синхронный файловый ввод-вывод тоже не нужен в запросе.
10. **Services/Checksum.cs:13-18**: P/Invoke `crc32` вызывается по одному байту, и каждый вызов делает маршалинг массива. Для PDF в несколько МБ это миллионы нативных вызовов (в десятки-сотни раз медленнее, чем нужно). Нужно считать один раз по всему буферу (`Crc32(0, buf, len)`) или взять `System.IO.Hashing.Crc32.Hash(ReadOnlySpan<byte>)`. Кроме того, `DllImport("libz")` зависит от окружения: в образе может не быть `libz.so`, тогда `DllNotFoundException`. Тип `ulong` для `uLong` и `uint` для `uInt` корректен на Linux x64, но на Windows `uLong` 32-битный.
11. **Controllers/InvoiceController.cs:35-37**: `Array.Copy` копирует весь PDF минус заголовок в новый массив ради контрольной суммы. Нужен срез `pdf.AsSpan(HeaderSize)` и `Checksum.Compute(ReadOnlySpan<byte>)`. `Task.Run` вокруг CPU-работы лишний: запрос и так на потоке пула, а лишнее переключение ничего не даёт.
12. **Controllers/OrderExportController.cs:14-24**: выгрузка без фильтра по дате и без пагинации. По статусу, например `completed`, это могут быть миллионы заказов, которые целиком материализуются в `List`, затем в `StringBuilder`, затем в `byte[]` (три копии в памяти, LOH). Итог: OOM и таймаут. Нужно стримить через `AsAsyncEnumerable` в `Response.Body`, с проекцией только нужных колонок.
13. **Controllers/CustomerReportsController.cs:36-37**: `CountAsync(...) > 0` вместо `AnyAsync`. На 3 млн заказов у крупного клиента это полный подсчёт вместо остановки на первой строке.
14. **Controllers/CustomerReportsController.cs:43-49**: список рассылки грузит сущности `Customer` целиком, включая `Photo` (byte[]) и `Notes`, ради одного `Email`. Итог: лишние мегабайты трафика и памяти на странице; сущности ещё и отслеживаются ChangeTracker. Нужна проекция `.Select(c => c.Email)` в запросе (и `AsNoTracking`). `pageSize` не ограничен сверху (`pageSize=100000000`), `page` и `pageSize` отрицательные дают исключение в `Skip`/`Take`, а `Skip` на глубоких страницах деградирует. Лучше keyset-пагинация по `Id`.
15. **Services/RateService.cs:14 и Controllers/InvoiceController.cs:44-48**: параметр `currency` не валидируется и подставляется в URL (`rates/{currency}`) без экранирования, а `null` в `string currency` не отсекается. Возможен path-injection на сервис курсов, а при неизвестной валюте падает `HttpRequestException` (500). `dto!.Rate` при пустом ответе даёт NRE, нулевой курс даёт `DivideByZeroException`. Нужно белый список валют, `Uri.EscapeDataString` и проверка `rate > 0`.

## Minor

16. **Controllers/OrderExportController.cs:22**: CSV собирается без экранирования (`Number` может содержать `;`, перевод строки, ведущий `=`/`+`: CSV-инъекция в Excel). `{o.Total}` форматируется текущей культурой, и в ru-RU выйдет запятая, которая сломает формат с разделителем `;`. Нужно `CultureInfo.InvariantCulture`, экранирование полей и фиксированный набор колонок.
17. **Controllers/CustomerReportsController.cs:16**: `FirstOrDefaultAsync` на `Customer` тянет `Photo` и `Notes` ради `Id` и `Name`, а сущность отслеживается. Нужна проекция или `AsNoTracking`. Здесь же `DateTime.UtcNow` и `since` без `Kind`: `since` из query приходит с `Kind=Unspecified`, а Npgsql для `timestamptz` может бросить исключение. Нужна нормализация в UTC.
18. **Controllers/InvoiceController.cs:19, 46**: заказ читается с отслеживанием, хотя только читается. Нужен `AsNoTracking`. Выбирается весь `Order`, а нужны `Number` и `Total`.
19. **Program.cs:11-12**: у типизированного `HttpClient` нет `Timeout` и политик retry/circuit breaker (`AddStandardResilienceHandler`). Сервис курсов по умолчанию ждёт 100 с и держит запросы. Нет авторизации на эндпоинтах с ПДн (`mailing-list`, `export`, `summary`) и нет `[Authorize]`.
20. **Data/OrdersDbContext.cs:20,28,32**: поля `virtual` вместе с `UseLazyLoadingProxies` делают любое обращение к навигации скрытым запросом (источник п. 4-5). Для отчётного кода нужно явные проекции; индексов на `Orders.CustomerId`, `Orders.Status`, `OrderLines.OrderId` в модели нет (нет `OnModelCreating`), и без миграций их наличие неизвестно. На 3 млн строк это полные сканы.

## Итого

blocker: 4, major: 11, minor: 5. Всего 20.
