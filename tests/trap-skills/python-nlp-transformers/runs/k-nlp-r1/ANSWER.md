**Описание MR: SW-261, тональность отзывов и сводчик**

*Классификатор*
- `train_classifier` дообучает `DeepPavlov/rubert-base-cased` на `data/reviews.parquet`, используя готовую колонку `split`. Метрика — `macro_f1` из `metrics.py`.
- Каждая часть данных токенизируется одним вызовом, паддинг динамический.
- Тексты обрезаются до 512 токенов, потому что у BERT больше позиций нет, а отзывы бывают до 600. Хвост длинных отзывов теряется.
- Прогрев задаётся как `warmup_steps=0.1`. Поля `warmup_ratio` в transformers 5.x нет.
- Модель и токенизатор сохраняются в `artifacts/sentiment/`.
- `classify(texts)` грузит модель с `local_files_only=True` на CPU и обрабатывает тексты пачками по 32. Для пустого списка возвращает `[]`, не загружая модель.
- Для CPU веса `nn.Linear` переводятся в int8 собственным модулем `Int8Linear` (веса int8, масштаб по выходному каналу). Я не взял `torch.ao.quantization.quantize_dynamic`, потому что в torch 2.14 он deprecated, а `torchao` в зависимостях нет. Веса в памяти хранятся в int8, но при каждом вызове разворачиваются обратно, так что выигрыш по памяти, а по скорости не обязательно. Задержку нужно замерить.

*Сводчик*
- `train_summarizer` делает QLoRA на `Qwen/Qwen2.5-7B-Instruct`: база в 4-битном NF4, LoRA r=16 на всех проекциях, bf16, gradient checkpointing, батч 1 с накоплением 16. Это помещается в 24 ГБ.
- В обучении промпт исключён из потерь (метки -100), считается только ответ.
- После обучения адаптер вливается в неквантованную bf16-базу на CPU (`merge_adapter`), а результат сохраняется в `artifacts/summarizer/` как обычная модель.
- Благодаря этому `summarize` грузит её через `AutoModelForCausalLM` без `peft`. `peft` и `bitsandbytes` импортируются только внутри функций обучения.
- Генерация жадная, но с ограничением повторов: `repetition_penalty=1.1`, `no_repeat_ngram_size=4`, `max_new_tokens=200`. Паддинг слева.
