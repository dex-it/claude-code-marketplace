## Описание MR (SW-261: тональность отзывов и сводчик)

**Тональность**
- `train_sentiment()` дообучает `DeepPavlov/rubert-base-cased` на `data/reviews.parquet` и использует готовую колонку `split`.
- Лучшая эпоха выбирается по macro-F1 (берётся `macro_f1` из `metrics.py`).
- Модель и токенизатор сохраняются в `artifacts/sentiment/` (путь берётся из `paths.py`).
- `classify(texts) -> list[int]` грузит модель на CPU с `local_files_only=True`, без интернета, и кеширует её в процессе. Тексты идут пачками, пустой список возвращает `[]`.
- Отзывы длиннее 512 токенов обрезаются: это предел BERT, а в данных до 600.

**Сводчик**
- `train_summarizer()` — QLoRA: база в 4 бита (nf4), адаптеры LoRA на всех линейных проекциях, batch 1 с накоплением 16, gradient checkpointing, 8-битный paged AdamW. Это нужно, чтобы уложиться в 24 ГБ.
- Loss считается только по сводке, токены промпта замаскированы.
- Сервис разметки не должен тянуть `peft`, поэтому после обучения адаптер сливается в базу.
  - Слияние делается на отдельно загруженной базе в bf16, не на 4-битной: слияние в квантованные веса теряет точность.
  - Полная модель сохраняется в `artifacts/summarizer/`, адаптер отдельно в `artifacts/summarizer_adapter/`.
- `summarize(reviews) -> list[str]` использует только `transformers`: жадная генерация, левый паддинг, bf16, `cuda` если есть, иначе CPU.
- Все импорты `torch`, `transformers` и `peft` сделаны внутри функций, так что модуль импортируется без них. В инференсных функциях `peft` нет.

**Тесты (без весов)**
- Разбиение по `split`.
- Маскирование промпта и обрезка по длине (на фейковом токенизаторе).
- Пустые входы не грузят модели.
- Проверка по AST, что на уровне модуля и в инференсе нет `peft`.
