## Шаг 0 и решения

- **Сборка в кейсе разрешена.** Шаг 6 протокола («сборка и тесты прогнаны заново») требует сборки, обвязка группы её запрещала; здесь `npm test` в `tools/ordercli` без сети
  исполняется в песочнице (проба 2026-10-19), поэтому шаг 6 исполним, и `T` в сверке - обязательная клетка. Сборка C# и установка зависимостей без сети не исполняются.
- **Протокол - процедура.** Порядок шагов (якоря и backup-ref, `zdiff3`, `merge-tree`, две дельты, верификация, терминал) - база process-skill, провалом контроля не снимается (норма
  эпика); по транскриптам `bash.txt` прогонов `c` исполнитель сам ставит backup-ref, гоняет `merge-tree`/`zdiff3` и прерывает пробный `merge` через `--abort` - справочно.
- **Номера обеих сторон = `unit-identity`** (адрес `unit-identity/README.md` стр. 40 к #308). Принцип единицы с номером - `unit-identity`, порядок перенумерации корпуса требований -
  `project-docs-map` п.6 (SKILL уже ссылается). Здесь мерится механика слияния: REQ промокодов перенумерован вместе со ссылками (M5).
- **Версия стека** слита с переименованием символа (один механизм: правки в разных строках сливаются чисто, вызов указывает в пустоту; проверяется `rg` по старому имени, M2).
- **Не засеяно / невозможно в среде:** `--cc` как единственная проверка, `rerere` с ошибочным разрешением, rename/rename (1to2), lock-файл (регенерация без сети невозможна) -
  `unverifiable`, пункты остаются названиями до свидетельства.
