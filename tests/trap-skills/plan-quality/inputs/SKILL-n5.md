# Plan Quality - чек-лист

Судит план реализации целиком - раскладку принятого решения на шаги: инкременты зоны дизайна и edit-план
P1..Pn зоны разработки. Выбор пути судит `design-quality` и оператор, не этот оракул.

Вход - план, набор требований и решение, из которых он вырос. Грузит судья, не автор (`node-contract`
п.7 раздела B): ревьюер дизайна либо потребитель плана. Автор прогоняет его самоконтролем, результат кладёт
в `self-check`, метку `quality-checks` не ставит.

Пункт называет ситуацию, которую план проверяет.

- Шаг без закрываемых требований или требование без шага
- Порядок слоями: работающий результат появляется только после последнего шага; параллельны шаги, которые меняют одну таблицу - её схему, данные или запись в её колонки
