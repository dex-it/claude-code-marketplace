**Что в пайплайне**
- **Стадии:** build, test, image, deploy.
- **Запуск:** пайплайн идёт на MR, включая MR из форков, и на ветках `main` и `develop`.
- **Раннеры:** build, test и image идут на общих раннерах без тегов. Деплой идёт на раннере с тегом `depot-deploy`.
- **Тесты:** сервис `postgres:16` с алиасом `postgres`, строка подключения `Host=postgres;…` задана в `ConnectionStrings__Default`. Покрытие считает `reportgenerator` с `TextSummary` и `Cobertura`. Regex `Line coverage: N%` показывает покрытие в MR, а Cobertura-отчёт подключён как `coverage_report`.
- **Образ:** собирается через docker-in-docker и пушится в `$CI_REGISTRY_IMAGE` с тегами `$CI_COMMIT_SHA` и `latest`. Джоба идёт только на `main`, потому что у MR из форков нет прав на registry проекта.
- **Деплой:** `deploy-stage` идёт автоматически на `main`, затем `deploy-prod`, для которого я поставил ручной запуск. Обе джобы делают `kubectl set image deployment/depot-api api=<образ>` и ждут `rollout status`. Namespace: `depot-stage` и `depot`.
- **Логи деплоя:** в лог попадают окружение, namespace, образ, коммит, имена переменных окружения контейнера и его ресурсы. Значения переменных я не выводил, потому что в них пароль БД и ключ API. Kubeconfig пишется в файл и удаляется в `after_script`.

**Замечания к задаче**
1. **Ручной запуск prod.** В задаче написано «после stage» без уточнения. Я сделал его ручным. Если нужен автоматический, достаточно убрать `when: manual` в правилах `deploy-prod`.
2. **Testcontainers.** README и комментарий в тестах говорят, что интеграционным тестам нужен Postgres через Testcontainers, то есть Docker. Сейчас тест — заглушка и к БД не обращается. Если тесты станут настоящими, они проигнорируют service-контейнер и потребуют Docker в джобе. Тогда нужно либо читать `ConnectionStrings__Default`, либо добавить dind в `test`.
3. **`DB_MIGRATION_PASSWORD` не используется.** По `runbook.md` миграции приложение применяет само при старте, используя настройки из кластера. Как пароль для миграций должен попадать в деплой, из задачи не ясно. Я не стал придумывать и только отметил в комментарии, что он не должен попасть в лог.
4. **Переменные доступны только на защищённых ветках.** Они protected, поэтому `main` должна быть protected branch. В MR из форков они недоступны, и деплоя там нет.
5. **`depot-worker` не обновляется.** Он работает на том же образе, но в задаче деплоится только `depot-api`. После деплоя worker останется на старой версии.
6. **Версии зафиксированы мной.** Это `bitnami/kubectl:1.31`, `docker:27` и `reportgenerator 5.3.11`. Образ SDK `8.0.404` взят из Dockerfile. Проверьте, что они подходят.
7. **Лишний коммит.** Коммит `DPT-21: CI на GitLab CI` уже есть в ветке, но `.gitlab-ci.yml` в нём не отслеживался. Возможно, он был пустым или неполным.
