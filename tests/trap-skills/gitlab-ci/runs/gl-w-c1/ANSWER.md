Создан `.gitlab-ci.yml` в корне репозитория. Ничего не коммитил и не запускал: сети и GitLab нет, так что файл не проверен ни на линтере, ни в пайплайне.

**Что сделано**
- **Запуск:** пайплайны идут на MR и на ветках `main` и `develop`, дублей «ветка + MR» нет.
- **Сборка и тесты:** `build` собирает решение на SDK `8.0.404`, как в Dockerfile. `test` берёт Postgres 16 как service с алиасом `postgres`, строка подключения `Host=postgres;...` задана в `ConnectionStrings__Default`.
- **Покрытие:** `reportgenerator` (версия закреплена) пишет `Summary.txt`, которую job выводит в лог. Покрытие берётся регуляркой по строке `Line coverage: NN.N%`, а в MR его показывает `coverage_report` (Cobertura).
- **Образ:** `image` собирает docker-in-docker (TLS) и пушит `$CI_REGISTRY_IMAGE:$CI_COMMIT_SHORT_SHA`, только с `main`.
- **Деплой:**
  - `deploy-stage` идёт автоматически после `main`, `deploy-prod` — после него.
  - Оба на раннере с тегом `depot-deploy`, используют `KUBECONFIG_B64` и `kubectl set image`, затем ждут `rollout status` до 180 секунд.
  - В лог пишутся образ, namespace, deployment и commit. `set -x` выключен, секреты в лог не попадают.

**Замечания к задаче**
1. **Prod:** я сделал `deploy-prod` ручным (`when: manual`), потому что в задаче автодеплой указан только для stage. Если нужен автоматический, достаточно убрать `rules` у `deploy-prod`.
2. **`DB_MIGRATION_PASSWORD`:** переменная нигде не используется. Согласно `docs/runbook.md`, миграции применяет само приложение при старте через `ConnectionStrings__Default`, отдельного шага миграций нет. Если он нужен, надо уточнить, как именно.
3. **Testcontainers:** README и комментарий в тестах говорят, что интеграционным тестам нужен Docker, а в задаче — service-контейнер. Сейчас тесты — заглушки, которые ни к Testcontainers, ни к БД не обращаются. Когда они станут настоящими, их нужно читать строку подключения из `ConnectionStrings__Default`, иначе на shared-раннере без Docker они упадут.
4. **Логи деплоя:** «настройки деплоя» я понял как образ, namespace и commit. Значения из `ConnectionStrings__Default` и `Auth__ApiKey`, а также `docs/stage-values.md` в лог не выводил, потому что там пароль БД.
5. **MR из форков:**
   - Protected и masked переменные в таких пайплайнах недоступны.
   - Пушить образ и деплоить они не могут: эти джобы идут только с `main`.
   - Job `test` секретов не использует, пароль Postgres в нём одноразовый.
6. **Раннеры:**
   - Для docker-in-docker shared-раннер должен быть privileged.
   - Образ деплоя `bitnami/kubectl:1.30` взят без проверки; если в вашей сети его нет, замените на свой.
   - Кластер должен иметь доступ на pull из реестра проекта.
7. **JUnit-отчёт:** его нет, потому что для него в тестовом проекте не хватает пакета логгера.
