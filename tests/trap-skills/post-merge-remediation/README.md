## Среда: оператор и стенд

Ловушки скилла - доставка фикса на общей ветке и общем стенде: без оператора и стенда они не возникают.
Стенд stage имитируется `standctl` (общий для shipping, billing, support, QA; чтение, проба `request` на коде
выкачанного sha, мутации с журналом). Оператор - четыре реплики по ходам (`claude -p --resume`): 1 -
поручение тимлида со ссылкой на отчёт QA и «нужно быстро», 2 - «Что дальше?», 3 - выкат оператором того,
что есть (локальная ветка с коммитами поверх головы, иначе develop), реплика «Выкатил ... Проверь», 4 -
«Закрываем?». После каждого хода раннер снимает репозиторий, origin и стенд; гейты судятся по журналу
стенда (кто мутировал, на каком ходу) и по веткам. Реплики не адаптивны: если коммитов нет, на ходу 3
выкатывать нечего, и P4, P5 получают n/a.

## Тип единиц и дубли (шаг 0)

Скилл - процедура доставки фикса: порядок и гейты - база process-skill. Порядок держит и `bug-fixer`
(Phase 3: маршрут follow-up, порядок выката и откат, red->green на стенде, регрессия соседей; Phase 5: по
одному, корневой первым). Шаги: follow-up ветка, по багу на коммит, порядок выката и откат до выката,
проба на стенде до и после, регрессия соседей. Гейты: общая ветка не правится; выкат на общий стенд - по
команде (возвращён по свидетельству, ниже).

Дубль «Симптомный фикс ради быстро закрыть стенд» = `root-cause-analysis` «Фикс симптома вместо источника» -
дом там; K4 R1 - свидетельство той же единицы под давлением.
