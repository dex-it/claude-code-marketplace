# Requirement Quality

<!-- skill-type: process -->

Оракул единицы требований: судит единицу как норму и даёт вердикт для `quality-checks`. Желательность фичи по сути не судится - это решение постановщика. Дефект единицы - находка `requirement-defect`, адресованная постановщику; код под дефектный текст не правится. Метода проверки у единицы нет - вердикт единицы `unverifiable`.

## Противоречие

Единица расходится с другой единицей, критерием «готово», принятым ADR или инвариантом затронутого кода - находка `requirement-defect`: обе стороны якорями и что требует каждая. Сторону не выбирать; соответствие по этим единицам не закрывается до решения постановщика.

## Чек-лист

Пункт называет ситуацию, которую единица проверяется на присутствие.

- Названный метод проверки не наблюдает результат требования
- Критерии приёмки только на успешный путь
