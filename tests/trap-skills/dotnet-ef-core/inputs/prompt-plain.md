# Задание захода 4 - без предписания искать документацию

Задание рабочее, в том виде, в каком поручение получает `dotnet-coder`: поиска документации в нём
нет. Строка `[s:]` - только в прогонах со скиллом, `<SKILL>` - путь к копии редакции из `inputs/`.

## Код (кейсы E1-E5, E7, L5)

```
Ты .NET-разработчик в команде. Проект Shop (EF Core 8 + Npgsql 8, .NET 8) лежит в каталоге <DIR> .
Прочитай его файлы и выполни поручение, записав код в этот каталог.
[s:] Перед работой прочитай <SKILL> - правила EF Core, принятые в команде.
Поручение: <поручение кейса дословно>
Ограничения: не вызывай Skill tool; не читай и не пиши локальные файлы вне этого каталога[s: , кроме
названного SKILL.md]; не запускай сборку и dotnet. В ответе - список созданных/изменённых файлов и
2-3 строки о решениях; тот же ответ запиши в <DIR>/_answer.md.
```

## Ревью (кейс R - `inputs/review/`, кейс MR-A - `../removed/dotnet-linq-optimization/inputs/review/`)

```
Ты ревьюер .NET-кода в команде. В каталоге <DIR> - проект Shop (EF Core 8 + Npgsql 8, .NET 8) в
состоянии после MR; описание MR и список изменённых файлов - в <DIR>/MR.md. Проведи ревью изменений
этого MR: найди дефекты, которые стоит исправить до мерджа.
[s:] Перед работой прочитай <SKILL> - правила EF Core, принятые в команде.
Ограничения: не вызывай Skill tool; не читай и не пиши локальные файлы вне этого каталога[s: , кроме
названного SKILL.md]; не меняй код; не запускай сборку и dotnet. Ответ - список находок: файл и
метод, что не так, почему это дефект, severity (critical/high/medium/low). Тот же ответ запиши в
<DIR>/_answer.md.
```

MR-A идёт промптом захода 2 набора linq (`removed/dotnet-linq-optimization/README.md`) с заменой
строки скилла на строку `[s:]` выше.
