# BUG-41: дата доставки на день раньше

## Воспроизведение
Заказ 1042 (`data/orders-sample.json`): зона B, стандарт (3 раб. дня), `shippedAt = 2026-09-28T21:40:00Z`
= 29.09 00:40 МСК (вторник). По ТЗ (`docs/requirements/eta.md`) дата доставки 2026-10-02.

    node -e "import('./src/eta.js').then(m=>console.log(m.estimateDelivery('2026-09-28T21:40:00Z','B')))"
    # было: 2026-10-01 (в выгрузке eta тоже 2026-10-01), ожидается 2026-10-02

Воспроизводится при любой TZ сервера: `estimateDelivery` отсчитывал дни от даты по UTC, а не по Москве.
Ошибка проявляется, когда отгрузка приходится на 21:00-24:00 UTC (00:00-03:00 МСК) - дата по UTC на день раньше.

## Это не флак
`test/eta.test.js` «отгрузка сейчас» берёт `new Date()` и сравнивает с эталоном по Москве. Он падает только
если CI запущен в окно 21:00-24:00 UTC; перезапуск позже проходит. Тот же баг, что у клиентов.
Добавлены тесты с фиксированными моментами.

## Найдено попутно
- `formatEtaForSms`: `getMonth()` 0-based -> `02.09` вместо `02.10`; парсинг без зоны зависел от TZ сервера.
- `zoneForPostcode`: `startsWith('1')` проверялся раньше `19`, поэтому СПб (19xxxx) попадал в зону A,
  а 15xxxx-18xxxx - тоже в A (по ТЗ A = 10-14xxxx, B = 19xxxx, остальное C). Занижало срок/стоимость.

## 1,2 кг -> 1,5 кг
Не баг: по `docs/requirements/tariff.md` вес округляется вверх до 0,5 кг (1,2 -> 1,5). Код соответствует ТЗ,
добавлен тест. Клиенту нужно объяснить правило округления.

## Исправления
`src/eta.js`, `src/tariff.js`; тесты `test/eta.test.js`, `test/tariff.test.js`.
