# Review Evidence

<!-- skill-type: process -->

## Намерение

Находки двух классов. Корректностные (деньги в double, гонка, утечка, контракт-дрифт, недостижимая ветка, нарушенный инвариант) доказываются из кода, источник намерения им не нужен. Соответствие намерению («корректно, но не то») доказуемо только против источника намерения; его отсутствие корректностные находки не глушит.

Источник ищется по убыванию авторитетности:

1. Аналитический корпус проекта: сценарии `UC` с расширениями, `FR`/`NFR` с методом проверки, истории с `AC`, `non-goals`, `INV-NNN` конституции. Адрес приходит сквозным полем «расположение корпуса»; не пришёл - вызови `Skill` `dex-skill-project-docs-map:project-docs-map` и найди корпус им; состав и терминал недостижимого корпуса - `node-contract`, `references/oracle-precedence.md`.
2. Задача в трекере по ссылке из MR, ветки или коммита.
3. Описание и заголовок MR/PR.
4. Критерии приёмки и Definition of Done.
5. План или спецификация: `docs/`, вложение, тикет.
6. Тест, кодифицирующий ожидаемое поведение.
7. Для своей ветки - план реализации.

Место постановки, которое называет проект (CLAUDE.md, README, CONTRIBUTING), читается до вывода об отсутствии источника. Описание MR, расходящееся с принятым требованием, - находка, а не источник.

Источник найден - каждое требование сверяется с реализацией явно, расхождение «корректно, но не то» - находка. Ни одно место не дало постановки - ось соответствия получает `intent: n/a (источник не предоставлен)` и не оценивается, остальные оси работают. Источник, не приложенный к diff, основанием для `n/a` не служит.

## Порог уверенности

Два прохода. Первый собирает всё найденное без отсева по уверенности. Второй раскладывает: доказанное (файл прочитан, путь пройден) - в основной список, неуверенное - в раздел «перепроверить» с пометкой. Находка снимается только опровержением, низкая уверенность её не снимает.
