Наблюдаемость для `services/orders-api` написана в рабочем дереве, ничего не закоммичено. Сборки в окружении нет, поэтому код не компилировался и не запускался.

**Что сделано**
- **Пакеты:** в `OrdersApi.csproj` добавлены пять пакетов зафиксированных версий (OpenTelemetry Hosting, AspNetCore, OTLP, Prometheus и Serilog.Enrichers.Span).
- **Трассы:** есть span `CreateOrder` в `OrderService` и трассировка обращений к БД через источник `Npgsql`. Экспорт идёт по OTLP, адрес берётся из переменных `OTEL_EXPORTER_OTLP_*`.
- **Метрики:**
  - `orders.created` считает заказы по каналу и итоговому статусу.
  - `orders.create.duration` — время создания в секундах.
  - Канал вне `web`/`mobile`/`partner` пишется как `other`, чтобы клиент не раздувал число меток.
  - Статус сейчас `new` при успехе и `failed` при любом исключении, включая пустой заказ.
  - Метрики отдаёт `/metrics`.
- **Проверки для Kubernetes:** `/health/live` ничего не проверяет, `/health/ready` проверяет Postgres и Redis. У каждой проверки свой дедлайн 3 секунды.
- **Логи:** `Enrich.WithSpan()` добавляет `TraceId` и `SpanId`, а вывод в консоль теперь JSON (`RenderedCompactJsonFormatter`), иначе эти поля в консоли не видны.

**По правилам команды из SKILL.md**
- Исключение в span записывается через `RecordException` и ставит статус `Error`. То же включено для ASP.NET Core.
- Запросы к `/health*` и `/metrics` не попадают в трассы.
- Дедлайн есть у каждой проверки состояния.
- Логи связаны с активной трассой.

**Что учесть**
- Формат консольных логов изменился с текста на JSON. Если платформа или Seq ждут прежний формат, это придётся согласовать.
- Для Redis проверка каждый раз открывает новое соединение.
