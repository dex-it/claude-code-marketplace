Наблюдаемость для `services/orders-api` написана, но не собиралась и не запускалась: сборки в окружении нет. Ничего не закоммичено.

**Что сделано**
- **Пакеты** (`OrdersApi.csproj`): добавлены пакеты из зафиксированного стека, версии те же.
- **Трассы:**
  - Включены ASP.NET Core и OTLP-экспорт.
  - Для создания заказа добавлен span `CreateOrder` с тегами `order.channel` и `order.id`.
  - Обращения к БД идут через источник `Npgsql`: Npgsql 8 сам пишет span-ы, отдельный пакет не нужен.
- **Метрики** (`Observability/OrdersTelemetry.cs`):
  - Счётчик `orders.created` с тегами `channel` и `status`. Статус `new` ставится при успехе, `failed` при исключении.
  - Гистограмма `orders.create.duration` в секундах с заданными границами.
  - Канал нормализуется до `web`, `mobile`, `partner` или `other`, чтобы клиентские значения не раздували число серий.
  - Метрики отдаются Prometheus на `/metrics`.
- **Health** (`Observability/Health.cs`):
  - `/health/live` не проверяет зависимости.
  - `/health/ready` проверяет Postgres (`select 1`) и Redis (ping).
- **Логи:** подключён `Enrich.WithSpan()`, а в шаблон консоли добавлены `TraceId` и `SpanId`.

**Правила команды (SKILL.md)**
- Если создание заказа падает, span получает статус `Error` и запись об исключении. Для входящих запросов включён `RecordException`.
- Запросы к `/health*` и `/metrics` отфильтрованы из трасс.
- У каждой health-проверки свой дедлайн: 3 с внутри проверки и 5 с в регистрации.
- Результат проверок кэшируется на 10 с (`CachedHealthCheck`), поэтому частые пробы не нагружают Postgres и Redis.
- Логи содержат `TraceId` и `SpanId` активной трассы.

**Что проверить при первой сборке**
- Метод `RecordException` для `Activity` взят из `OpenTelemetry.Trace` из памяти, без проверки по документации. Если сборка его не найдёт, сначала смотрите на него.
- Endpoint OTLP и параметры Serilog из конфигурации берутся из настроек окружения. Конфигурационных файлов в проекте нет, я их не добавлял.
- Redis-проверка создаёт собственное подключение к Redis, потому что в сервисе общего подключения нет.
