Задача OB-1 выполнена в рабочем дереве `services/orders-api`, без коммита. Сборки в окружении нет, поэтому код не компилировал и не запускал.

**Что сделано**
- **Пакеты:** в `OrdersApi.csproj` добавлены пакеты из зафиксированного стека с нужными версиями.
- **Трассировка:**
  - Спаны `orders.create`, `orders.db.insert` и `orders.db.select` создаются через общий `ActivitySource`.
  - ASP.NET Core инструментирован.
  - OTLP-экспорт включён через `UseOtlpExporter()` и настраивается стандартными переменными `OTEL_EXPORTER_OTLP_*`.
- **Метрики:** счётчик `orders.created` с тегами `channel` и `status`, гистограмма `orders.create.duration` в секундах, метрики ASP.NET Core. Всё отдаётся на `/metrics` для Prometheus.
- **Health:** `/health/live` не проверяет зависимости, чтобы сбой БД не перезапускал под. `/health/ready` проверяет Postgres (`select 1`) и Redis (ping).
- **Логи:** в Serilog добавлен `Enrich.WithSpan()`, а в шаблон консоли выведены `TraceId` и `SpanId`.

**Правила из SKILL.md**
- **Ошибки в спанах:** при исключении спан получает статус `Error` и событие `exception`. На .NET 8 нет `Activity.AddException`, поэтому событие добавляется вручную в `RecordError`. Для ASP.NET Core включён `RecordException`.
- **Пробы вне трасс:** пути `/health*` и `/metrics` исключены из трасс фильтром.
- **Дедлайн проб:** у каждой проверки свой таймаут 2 с, у регистрации — 3 с.
- **Кэш проб:** результат проверки хранится 10 с через `CachedHealthCheck`, повторные пробы не ходят в зависимости.

**Решения, которые я принял сам**
- Значение `channel` в метриках берётся из тела запроса. Всё, кроме `web`, `mobile` и `partner`, пишется как `other`, чтобы не раздувать кардинальность.
- Статус заказа в метриках — `new` при успехе и `failed` при любой ошибке, включая пустой заказ.
- Отдельного пакета Npgsql OpenTelemetry в стеке нет, поэтому спаны БД написаны вручную в репозитории.

Если TTL кэша (10 с) или таймаут (2 с) нужны другие, они заданы в `Program.cs` переменными `probeCacheTtl` и `probeTimeout`.
