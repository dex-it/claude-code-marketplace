## Шаг 0

- **Liveness / readiness** (W5, W6; ловушки «Liveness проверяет внешние зависимости», «Один endpoint для liveness и readiness») - дом `kubernetes` K1 (PR #368, решено в группе 4.4); второго
  дома в observability не заводится, единицы снимаются со ссылкой. В OBSW они 2/2, в OBSR R10 2/2 - справочно.
- **TraceId** (W13) - в `dotnet-logging` (2.5.0) `TraceId`/`WithSpan` нет, дом остаётся здесь.
- **Пороги без источника** (`~5 значений`, `~10 значений` у меток, `timeout: 2 с`, `Period = 10 с`) в пункты не пишутся.

## Вердикт

Форма: ступень «название» (прогон `n`, 4 пункта плюс «результат health не переиспользуется между пробами»), затем итоговая редакция `m` (4 пункта). Прогоны со скиллом - редакция подана
копией `SKILL.md` через `--add-dir`.

| Единица | Кейс | Контроль | `n` | `m` (1.3.0) | Исход |
|---|---|---|---|---|---|
| Span без статуса `Error` и записи исключения | OBSW:W2, OBSR:R2 | 0/2, 2/2 | 2/2, 2/2 | 2/2, 2/2 | пункт-название |
| Health-пробы в трассах | OBSW:W4, OBSR:R4 | 2/2, 0/2 | 2/2, 2/2 | 2/2, 2/2 | пункт-название |
| Проверка health без своего дедлайна | OBSW:W7, OBSR:R9 | 0/2, 2/2 | 2/2, 2/2 | 2/2, 2/2 | пункт-название |
| Логи не связаны с активной трассой | OBSW:W13, OBSR:R11 | 2/2, 0/2 | 2/2, 2/2 | 2/2, 2/2 | пункт-название |
| Результат health не переиспользуется | OBSW:W9 | 0/2 | OBSW 2/2 (OBS0 major 2/2) | - | снят по вреду, возвращён с границей в стеке на #374 (`b`, «Добор W9») |

- **W9 снят по вреду (до добора).** Название в `n` даёт запись 2/2 в OBSW, но в OBS0 (в MR которого кэша нет) оба прогона `n` ставят «результат не кэшируется» как **major** (контроль `d1`, `d2` -
  ни одной находки по кэшу). Решение о кэше пробы - выбор проекта, а не ловушка; правило эпика «вред без свидетельства пользы» (решение 1 итерации 2) здесь применено, хотя польза на
  написании есть. Альтернатива «вернуть пункт с границей» проверена в стеке на #374 - ниже.
- **Формулировка W13.** В `n` пункт требовал `TraceId` **и** `SpanId`: оба прогона OBS0 ставят major на шаблон консоли без `{SpanId}` (в `d1`, `d2` и в ключе W13 достаточно идентификатора
  трассы). Формулировка исправлена на «не связаны с активной трассой» до `m`; в `m` major по логам нет.
- **Не хуже контроля (`m`).** OBSW `m1`, `m2`: W2 (`SetStatus` + запись исключения), W4 (фильтр `/health` и `/metrics`), W7 (`timeout` регистрации проверок), W13 (`Enrich.WithSpan()`) 2/2;
  `static readonly` `ActivitySource`/`Meter`, единица `s`, метки `channel`/`status` - как в контроле. OBSR `m1`, `m2`: R1-R5, R8, R9, R11 найдены обоими, R6, R7 - minor, приманки D1, D2 не
  подняты. OBS0 `m1`, `m2`: blocker/major только вне предмета (порт `/metrics`, валидация канала); по W1-W13 ноль.

## Добор W9

Стек на #374 (`feat/compress-group-4-7-open-items`), прогоны 2026-10-20, раннер и песочница те же, CLI 2.1.304 (базовые прогоны - 2.1.303; клетки из обеих версий сведены без перепрогона). Правило набора, размер клетки n=4 и условия решения записаны **до прогонов** коммитом `800b3466`
(раздел «Добор открытых решений #374» в [README мини-проекта](../_projects/ordering/README.md)). Редакции: `u` - 1.3.0 плюс пункт без границы ([`inputs/SKILL-w9-u.md`](inputs/SKILL-w9-u.md)), `b` - пункт с границей
«при написании кода; в ревью отсутствие переиспользования выше minor не находка» ([`inputs/SKILL-w9-b.md`](inputs/SKILL-w9-b.md)). «Без пункта» - уже имеющиеся прогоны без пункта W9 (`c1`, `c2`, `m1`, `m2`;
для OBS0 ещё `d1`, `d2`; все на CLI 2.1.303, а `u` и `b` - на 2.1.304: сравнение «без пункта» с `u`/`b` смешивает версию и пункт, сравнение `u` с `b` - нет, обе на 2.1.304).

| Клетка | Без пункта | `u` (без границы) | `b` (с границей) |
|---|---|---|---|
| Польза `B`: OBSW, W9 в коде (снимок/кэш результата проверки) | 0/4 | 4/4 | 4/4 |
| Вред `H`: OBS0, blocker/major про отсутствие кэша результата | 0/6 | **4/4** | **0/4** |
| Вред `H`: OBSR, blocker/major про отсутствие кэша (вне засеянного R8) | 0/2 (`m`) | 0/2 (кэш упомянут только внутри засеянной находки R8 `count(*)`) | 0/2 |
| OBSR: R1-R5, R8, R9, R11, OF1 найдены, D1, D2 не подняты | как в `m` | 2/2 | 2/2 |
| OBS0: blocker/major по W1-W13 | 0 | 4 находки про кэш | 0 (остаются находки вне предмета: порт `/metrics`, валидация канала) |

- **Решение по записанному правилу.** `B(b)` = 4/4 >= 3 при 0/4 без пункта, `H(b)` = 0 на OBS0 (4) и OBSR (2): допустима `b`. `u` недопустима: `H(u)` = 4/4 (каждый из четырёх прогонов OBS0 с `u` ставит
  «результат не кэшируется» как major; в `b` ни одного). По правилу возвращается `b`: **пункт W9 возвращён с границей, 1.3.0 -> 1.4.0**. Первая пара `n` (прогоны выше) и `u` согласуются: вред давала
  безграничная формулировка, а не само наличие пункта.
- **Что граница делает и чего не доказывает.** Граница сужает пункт до написания кода: в ревью чужого кода отсутствие переиспользования выше minor не находка. Кейс «ревью MR, где кэш действительно нужен»
  (засеянный дефект уровня major) в наборе не заводился: что пункт `b` не прячет такой дефект в ревью, - `unverifiable`. Где кэш результата нужен (число реплик, частота и стоимость пробы), пороги источника
  не имеют и в пункт не пишутся.
- **Отброшенное.** Прогоны `u` и `b` OBS0 читал оператор по тексту `REVIEW.md`; неоднозначных клеток не было (формулировки `u` про кэш однозначны, у `b` строк про кэш нет), второй оценщик по W9 не привлекался.
- Расход добора W9: $2.03 (20 прогонов в `runs/`: `OBSW-u1..4`, `OBSW-b1..4`, `OBS0-u1..4`, `OBS0-b1..4`, `OBSR-u1`, `OBSR-u2`, `OBSR-b1`, `OBSR-b2`).
