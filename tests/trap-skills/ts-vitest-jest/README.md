# ts-vitest-jest: сжатие по свидетельству, группа 2.3

Скилл `dex-skill-ts-vitest-jest` 2.0.1 ([`inputs/SKILL-2.0.1.md`](inputs/SKILL-2.0.1.md)) -> 2.1.0
([`inputs/SKILL-2.1.0.md`](inputs/SKILL-2.1.0.md)), эпик #291, группа 2.3 (#298). Промежуточная редакция f1
([`inputs/SKILL-f1.md`](inputs/SKILL-f1.md)) - итоговая первой смены: при снятии заголовка «Чек-лист» его
пункты остались хвостом последней ловушки и повторяли снятые V2, V4, V6. Во второй смене хвост снят, K3
перепрогнан на 2.1.0 (`f2`).

Вход, исполнитель (`claude-sonnet-5-5`, effort medium, `claude -p` 2.1.291, MCP нет), среда, промпты,
правило засчитывания, шаг 0 и расход - общие для группы, в протоколе
[ts-nodejs-api](../ts-nodejs-api/README.md#заход-группы-23-2026-10-06). Здесь - выходы K3 (unit-тесты модуля
резерва с повторами и паузами 1 с и 2 с; мины `mines/K3`: прогон тестов, shuffle seed 1-5, мутанты MU1-MU4,
время файла): `runs/`. Роль - разработчик unit-тестов; подаются `ts-vitest-jest` и `ts-patterns` (загрузка
`ts-test-writer`), в `f`, `f2` - только `ts-vitest-jest`. Наборы: `c` - контроль, 4 прогона (`k3-c3`, `k3-c4` -
добор на V1: в `c1` `vi.mock` не возник); `f` - f1, 2 прогона; `f2` - 2.1.0, 2 прогона. n1 не было: контроль
не провалил ни одной измеренной единицы.

Проба оператора до прогонов (Vitest 4.1.7): невыжданный `expect(...).rejects` сам помечает тест failed;
`clearMocks` в конфиге по умолчанию `false`. Jest в проекте и в локальном кэше npm нет.

## Потребители

Skill tool в фазе: `ts-test-writer` (Generate: фабрика мока и hoisting, мок против spy, общий стейт, проверка
вызовов мока), `debugger` (by-stack, flaky-тест). Бандл `ts-fullstack`. Кейс активации `ts-vitest-in`.
`debugger` кейса не получил.

прогона закрыта. H3 оставлена как написана.
