Я добавил unit-тесты на `reservation.ts` в новый файл `api/test/reservation.test.ts`. `npm run typecheck` и `npm test` проходят (15 тестов). Код модуля не менялся.

Тесты покрывают все пункты задачи:
- успех с первой попытки;
- повтор после временного сбоя и успех;
- исчерпание попыток с `ReservationFailedError`;
- ошибка склада без повторов;
- `isHoldExpired`, включая границу и связку с `holdUntil`.

- **Склад:** настоящий склад не вызывается, подменён только `inventory.reserve` (`vi.spyOn`). `TemporaryInventoryError` и логика повторов остаются настоящими. Ошибки склада, кроме временной, в тесте — обычный `Error`.
- **Время:** паузы между попытками идут на fake timers (`runAllTimersAsync`), поэтому тесты не ждут реальные секунды. В `afterEach` возвращаются настоящие таймеры и снимаются spy. `logger.warn` заглушён, чтобы не засорять вывод.
- **Проверки:** в основном проверяются результат и ошибка. Число вызовов `reserve` проверяется только там, где это и есть поведение: 3 вызова при исчерпании попыток и 1 вызов без повторов.
