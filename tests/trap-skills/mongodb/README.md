## Открыто

- **M9 в коде** (спорно): решение «outbox + опрос воркером» названо провалом по букве ключа; допустимого решения
  `Change Streams` исполнитель контроля не выбрал ни разу, потому что одиночный `mongod` стенда их не поддерживает - ключ
  требует править compose; вопрос владельцу - засчитывать ли outbox-опрос.
- **M7:** TTL-индекс назван в одном прогоне контроля из двух (второй - по последствию).
- **P1:** ключ приманки (дефект кейса), см. выше. **O2:** закрыто вердиктом выше («Ревизия r»: шум при n=4, решение владельца эпика). **M11:** вердикт «Ревизии r» (пункт не добавляется) пересмотрен добором правила 11 - просадка подтверждена, пятое название ревизии `s`.
- **M4:** закрыто правилом 4 набора (`_projects/fulfil/README.md:61`, записано до прогонов): находка в месте ключа с последствием, снимаемым исправлением, засчитывается без корня; `r5`, `r6` 2/2 (см. «Раунд 3»). «Строгое чтение» (нужен корень) - граница после просмотра ответов, правило 3 набора её не принимает.
- **M11:** после ревизии `s` 2/2 в RV-M и G-M при n=2; подтверждение на n=4 не набиралось (потолок расходов).
- Рантайм (ошибка транзакции на одиночном `mongod`, Change Streams) не наблюдался: compose не поднимался; M11 судится по
  compose и коду.
