**Принятые решения:**
- **Заказы и клиент:**
  - Адрес встроен в заказ.
  - Имя и email клиента в заказ не копируются. Они меняются, а у постоянного клиента до 10 тысяч заказов. Письмо берёт их по `CustomerId` при отправке.
  - Лента событий лежит в отдельной коллекции `order_events`, потому что событий тысячи.
  - Индекс заказов: `CustomerId, Status, PlacedAt↓`, страницы по 50 через keyset.
  - «Мои заказы» читают только `Id` и `Status` через проекцию.
  - Документы читаются с игнорированием лишних элементов и значениями по умолчанию для новых полей.
- **Остальные коллекции:**
  - У `cart_drafts` TTL-индекс на 30 дней по `UpdatedAt`.
  - Перенос остатков идёт в транзакции и не даёт уйти в минус.
  - Для транзакций и change streams MongoDB в compose теперь работает как однонодовый replica set `rs0`. В строку подключения добавлен `directConnection=true`.
- **Письмо о `Shipped`:** change stream с сохранением resume token вместо опроса. Реплик 3, и каждая видит событие, поэтому письмо защищено атомарным захватом через `ShippedMailClaimedAt`. При ошибке отправки захват снимается, и событие обработается повторно.

**Что проверить:**
- `IMailer` в репозитории не нашёлся, хотя в задаче он назван существующим. Я объявил его в `Ports.cs` с сигнатурой `SendShippedAsync(Guid orderId)`. Если он есть в другом месте, мой вариант нужно убрать.
- В коде нет источника данных клиента и самих документов клиента: это вне задачи, письмо берёт их внутри `IMailer`.
- `EnsureIndexesAsync` вызывается только из `ShippedMailWatcher` при старте. Этого достаточно, пока watcher зарегистрирован.
