# user-stories: сжатие по свидетельству, группа 3.1

Скилл `dex-skill-user-stories` 1.2.1 ([`inputs/SKILL-1.2.1.md`](inputs/SKILL-1.2.1.md)), эпик #291,
группа 3.1 (#300). Итог группы 3.1 - 2.0.0, trap-skill из четырёх пунктов чек-листа
([`inputs/SKILL-2.0.0.md`](inputs/SKILL-2.0.0.md); промежуточные n1 - [`inputs/SKILL-n1.md`](inputs/SKILL-n1.md), ревизия 1 - [`inputs/SKILL-v.md`](inputs/SKILL-v.md)),
строка в реестре [`tests/README.md`](../../README.md). Задача #119 (INVEST): 2.1.0, пятый пункт чек-листа, раздел «INVEST и
задача #119» ниже ([`inputs/SKILL-m.md`](inputs/SKILL-m.md)).

Вход, среда, раннер, наборы прогонов и судьи - общие для группы, описаны в протоколе
[requirement-quality](../requirement-quality/README.md); прогоны и файлы вердикта лежат там же. Скилл
мерится кейсами w4 (истории из SRS) и r4 (ревью историй и бэклога), всегда вместе с
`requirement-quality` - так его грузят составитель и судья.

## Потребители

`user-story-analyst` (норма историй), `requirements-reviewer` (норма класса). Бандлы `product-manager`,
`system-analyst`. Словарь `docs/domain/domain-model.md` (дом термина Story / `AC`). Кейс активации
`user-stories-in`.

## Тип единиц (шаг 0)

18 H3-ловушек в четырёх разделах и чек-лист, повторяющий их названиями. Процедур нет. Дубли с телом
`user-story-analyst`: критерий рождается при нарезке, обратный порядок «правило из критериев» запрещён,
метка правила у каждого критерия, примеры - техниками тест-дизайна, полнота с двух сторон, догадка
вместо вопроса - всё это Output, Exit criteria и запреты агента.

Остаток задачи #119 решён так: чек-лист шести букв не вводится (пять букв из шести контроль берёт 5/5, Independent - в явной форме и
как зависимость от следующего спринта; Valuable уже пункт 2.0.0); возвращён один пункт - круг, который контроль не увидел (1/5). Набор `m` (2.1.0): r7 круг 4/4,
ST-2106 AC-5 -> ST-2104 4/4, ST-2105 4/4, приманки (ST-2101 зависит от выпущенной ST-1001, ST-2104 одна цель при
трёх ветках) чисты; r4 `m1`, `m2` - все строки ключа на месте, круг не придуман, приманки ST-2008 и ST-2009 как у
контроля; w4 `m1`, `m2` - D-8 не досочинена, негативные ветки и NFR ссылкой. Тело `user-story-analyst` и
`requirements-reviewer` не менялись. Чем судья проверяет часть, что остаётся за агентом: перечисление шести букв в
выходе фазы Validate скиллом не измеряется (прогон скилла не запускает агента) - см. «Открыто».

## Открыто

- Concurrent access на w4: со скиллом одновременный расход назван открытым вопросом, критерия нет -
  это верный исход при неразрешённом правиле во входе, но AC так и не появляется.
- Агент как узел с фазами (задача #119, остаток 3): прогон Validate `user-story-analyst` не ставился - нужен живой
  прогон зоны 1 ([`tests/_cases/zone-1.md`](../../_cases/zone-1.md)) с инвариантом «в выходе результат проверки каждой
  буквы INVEST по каждой истории, согласованный с историей». Не вводить сейчас: дорого, предмет другого метода
  (исполнение агентом собственной фазы, а не ловушки скилла). Обоснование - протокол
  [requirement-quality](../requirement-quality/README.md), «Остаток 3».
- Круг историй стоит на одном засеве (двое историй, оба в одном спринте); круг из трёх и косвенный через бэклог не
  мерились. Кейса «ничего не менять» у скилла нет.
