# Симптом

После релиза обработчик orders-worker (`dotnet app/OrdersWorker.dll slow`) стал медленнее: p50 вырос с 0.2 до 3 мс. Процесс держит около 190% CPU: два рабочих потока по ~90–99%. Остальные потоки простаивают. Диск и сеть не задействованы. RSS стабилен (~68 МБ), так что утечки нет.

# Причина

`/work/src/Program.cs:162`, метод `TextUtils.Slugify`. На каждый вызов создаётся новый `Regex` (`new Regex(@"[^\p{L}\p{Nd}]+(?:[\s\p{P}]*)")`). Вызов идёт из горячего цикла `Modes.Slow` (`Program.cs:98`). Каждый раз заново разбирается и оптимизируется шаблон с Unicode-классами. Регулярное выражение не вынесено в `static readonly` поле и не кэшируется. Статический `Regex.Replace` с кэшем тоже не используется.

# Улики

1. `top -H -b -n1 -p 11` (процесс перед перезапуском): CPU занимают только два рабочих потока.
```
PID 19  93.8%  dotnet
PID 20  87.5%  dotnet
(остальные 0.0%)
```
2. `strace -f -c -p 11`: syscalls почти нет, только futex. Время тратится в пользовательском коде, а не в I/O.

3. `perf record -g -p 68` показал, что 79% семплов приходятся на JIT-код (`memfd:doublemapper`), 16% на `libcoreclr.so` (GC/аллокации), а `__memset_zva64` стоит на первом месте. Это признак интенсивных аллокаций. Managed-символы perf не разрешил.

4. `dotnet-trace collect -p 68 --profile dotnet-sampled-thread-time --duration 00:00:06 --format speedscope`. Я посчитал инклюзивное время по кадрам, сумма по 5 потокам равна 100%. Два рабочих потока дают 40%:
```
40.0  OrdersWorker!Modes+<>c.<Slow>b__6_1()
39.9  OrdersWorker!TextUtils.Slugify(string)
30.2  System.Text.RegularExpressions!Regex..ctor(...)
30.1  RegexParser.Parse(...)
29.0  RegexNode.FinalOptimize()
28.9  List`1[__Canon].Insert(int32,!0)
```
`Slugify` занимает 39.9 из 40.0, то есть ~99.8% времени рабочих потоков. Конструктор `Regex` занимает 30.2 из 40.0, то есть ~75%. Остаток приходится на прочий код внутри `Slugify`; я его отдельно не разбирал.

5. `/work/logs/worker.log`: ~0.5 млн операций/с суммарно по двум потокам (~1 млн за 2 с).

# Что предлагаю

- Создавать `Regex` один раз: `static readonly Regex Rx = new(@"[^\p{L}\p{Nd}]+(?:[\s\p{P}]*)", RegexOptions.Compiled);`. Либо использовать `[GeneratedRegex]`. `Slugify` должен вызывать `Rx.Replace(s, "-")`.
- После правки повторить замер p50 и профиль `dotnet-trace`. `Regex..ctor` и `RegexParser` должны исчезнуть из профиля.
- Добавить в бенчмарк или нагрузочный тест горячего пути проверку, которая ловит создание `Regex` в цикле.
- Код в рамках этой диагностики не менялся. Сервис я перезапустил один раз с `DOTNET_PerfMapEnabled=1` ради профилирования. Эту переменную стоит убрать из рабочего запуска.
