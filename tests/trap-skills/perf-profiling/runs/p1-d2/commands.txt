# Отчёт: orders-worker (режим slow)

## Симптом
После релиза p50 обработчика вырос с 0.2 до 3 мс. Процесс `dotnet app/OrdersWorker.dll slow` держит ~175% CPU на двух рабочих потоках. Узких мест по IO нет: `strace -c` показывает в основном futex и ожидание, диска и сети почти нет. Это CPU-bound.

## Причина
`TextUtils.Slugify` (`/work/src/Program.cs:160`) на каждый вызов создаёт новый объект `Regex` (строка 162):
`new Regex(@"[^\p{L}\p{Nd}]+(?:[\s\p{P}]*)")`. Метод вызывается из горячего цикла (`Program.cs:98`, `Modes.Slow`).
Каждый вызов заново разбирает и компилирует шаблон (RegexParser/RegexWriter), а затем прогоняет интерпретатор. Кэш не используется, `RegexOptions.Compiled` не задан. Классы Unicode `\p{L}`, `\p{Nd}`, `\p{P}` ещё и дороги при сопоставлении.

## Улики
Профиль `perf` с `DOTNET_PerfMapEnabled=1 DOTNET_EnableWriteXorExecute=0` (иначе JIT-символы не разрешаются), 8 с, 499 Гц, 7153 сэмпла:

    perf record -F 499 -g -p <pid> -- sleep 8
    perf report --children --sort sym -g none

    99.72%  Modes+<>c::<Slow>b__6_1()
    97.65%  TextUtils::Slugify(string)
    47.90%  Regex.RegexReplacement::ReplaceSimpleText
    45.17%  Regex::RunAllMatchesWithCallback
    36.17%  Regex::.ctor(string, CultureInfo)        <- конструктор Regex на каждый вызов
    28.60%  RegexParser::Parse
     6.86%  RegexWriter::Write

Self-время (`--no-children`): `RegexInterpreter::TryMatchAtCurrentPosition` 7.4%, `RegexCharClass::CharInCategoryGroup` 6.9%, `CharInClassRecursive` 5.6%, `TryFindNextStartingPositionLeftToRight` 5.1%. Всё это внутри System.Text.RegularExpressions.

`dotnet-counters collect` завершился без файла и данных не дал.

## Что предлагаю
- Вынести регулярное выражение в `private static readonly Regex`, чтобы оно создавалось один раз. Либо использовать `[GeneratedRegex]`, либо `RegexOptions.Compiled`. Это уберёт примерно 36% (конструктор и разбор шаблона).
- Заменить `\p{L}`/`\p{P}` на более простые проверки, например на ручной проход по символам, если допустим ASCII или упрощённая семантика. Это убрало бы и остальные ~45% на сопоставление.
- Проверить, не перенесло ли релиз `Slugify` в горячий путь. Если результат зависит только от `title`, его можно кэшировать.
- После правки повторить замер: p50 и профиль `perf` тем же способом.

Код и конфигурацию я не менял. Сервис перезапускался, сейчас он работает с `DOTNET_PerfMapEnabled=1` и `DOTNET_EnableWriteXorExecute=0`, это замедляет его. Для штатного режима его нужно перезапустить без этих переменных.
