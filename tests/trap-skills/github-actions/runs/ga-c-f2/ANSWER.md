В шаг `actions/setup-dotnet@v4` добавлены `cache: true` и `cache-dependency-path` со значениями `Directory.Packages.props` и `**/*.csproj`. Кэш `~/.nuget/packages` теперь восстанавливается между прогонами, и ключ меняется при смене версий пакетов или проектов. Набор проверок не менялся: по-прежнему только `dotnet test -c Release`.

Замечания:
- **Нет лок-файлов NuGet.** В репозитории нет `packages.lock.json`, а `setup-dotnet` по умолчанию строит ключ кэша именно по ним. Поэтому ключ у меня строится по `Directory.Packages.props` и `*.csproj`.
- **Установка не по лок-файлу.** Это нарушает `ci-gates` («зависимости ставятся не по лок-файлу»). Исправить можно так: включить `RestorePackagesWithLockFile`, закоммитить `packages.lock.json` и добавить `--locked-mode` в restore. Лок-файлы нужно сгенерировать через `dotnet restore`, а здесь dotnet недоступен. Включать locked-mode без них нельзя: CI упадёт. Предлагаю отдельную задачу.
- **Actions закреплены тегами** (`checkout@v4`, `setup-dotnet@v4`), а по дисциплине нужен SHA коммита. Я их не трогал: без сети SHA не узнать, а выдумывать его нельзя.
- **В CI нет статического анализа и аудита зависимостей** (`dotnet list package --vulnerable`), которые требует минимум `ci-gates`. Это вне рамок DPT-24, где просили не менять то, что CI проверяет.
