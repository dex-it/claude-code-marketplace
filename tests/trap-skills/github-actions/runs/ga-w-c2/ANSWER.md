Я добавил два workflow для задачи DPT-20. Ничего не запускал и не коммитил: валидировать YAML и гонять сборку здесь нечем.

**Новые файлы**
- `.github/workflows/ci.yml`
- `.github/workflows/pr-size-label.yml`

**Что в `ci.yml`**
- **Триггеры:** запускается на каждый PR и на push в `main`.
- **Тесты:**
  - Тесты `Contracts` идут на `ubuntu-latest` и `windows-latest`.
  - Тесты `Integration` идут на `ubuntu-latest`, где есть Docker для Testcontainers.
  - Результаты (trx) и покрытие (coverlet) сохраняются артефактами.
- **Форматирование:** `dotnet format --verify-no-changes` стоит с `continue-on-error`, отчёт сохраняется артефактом. Релиз он не блокирует.
- **Лицензии:** вызывается reusable workflow `license-check.yml@v2` после тестов.
- **Образ:** на `main` собирается и пушится `registry.example.com/depot/api` с тегами `${{ github.sha }}` и `latest`. Логин берётся из `REGISTRY_USER` и `REGISTRY_PASSWORD`.
- **Деплой:** после образа вызывается `gh workflow run deploy.yml --repo dex/depot-infra`.

**Метка размера**
- `pr-size-label.yml` работает на `pull_request_target`, чтобы метка ставилась и на PR из форков.
- Код PR он не выкачивает, а берёт число строк из метаданных PR.

**Замечания к задаче**
1. **Токен для деплоя.** Штатный `GITHUB_TOKEN` не может запускать workflow в другом репозитории. Я использовал секрет `DEPOT_INFRA_TOKEN`: PAT или токен GitHub App с правом Actions: write на `dex/depot-infra`. Его нужно завести, в задаче он не указан.
2. **Параметры деплоя.** В задаче не сказано, какие inputs принимает `deploy.yml` (тег образа, окружение). Сейчас он вызывается без них, так что stage получит то, что у него по умолчанию. Если нужен конкретный образ, надо добавить `-f`-параметры с `${{ github.sha }}`.
3. **Self-hosted раннеры не использованы.** П.7 допускает их, но п.1 требует GitHub-hosted, а PR принимаются из форков. Код из форка на раннере внутри сети компании запускать небезопасно. Если нужны быстрые сборки, их можно включить только для `push` в `main`.
4. **Пороги размера выбраны мной.** S — меньше 50 изменённых строк, M — меньше 250, L — остальное. Считаются добавленные плюс удалённые строки. В задаче границ нет, при необходимости поправьте.
5. **Лицензии и секреты.** Секреты в `license-check` не передаются, потому что в задаче про них ничего нет. Если reusable workflow их ждёт, нужен `secrets: inherit`. Блокировать ли им образ, тоже не оговорено: я сделал образ зависимым от лицензионной проверки.
6. **Версии actions.** Они закреплены на мажорных тегах. Для надёжности их можно прибить к SHA.
