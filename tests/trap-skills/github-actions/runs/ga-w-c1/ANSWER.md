Я добавил два workflow в `.github/workflows/`. Ничего не запускал и не проверял: сети и сборки нет, YAML не валидировал. Ничего не коммитил.

**Изменённые файлы (оба новые, не закоммичены):**
- `.github/workflows/ci.yml`
- `.github/workflows/size-label.yml`

**Что сделано в `ci.yml`:**
- **Триггеры:** запускается на каждый PR и на push в `main`. Лишние прогоны PR отменяются, когда приходит новый коммит.
- **Тесты:**
  - Все тесты идут на `ubuntu-latest`, там есть Docker для Testcontainers.
  - Тесты с категорией `Contracts` идут ещё и на `windows-latest`.
  - Результаты (trx) и покрытие (coverlet) сохраняются артефактами.
- **Форматирование:** `dotnet format --verify-no-changes` с `continue-on-error`, отчёт сохраняется артефактом. Релиз не блокируется.
- **Лицензии:** вызывается `ci-shared/.github/.github/workflows/license-check.yml@v2` после тестов.
- **Публикация:** только на push в `main`, после тестов и проверки лицензий. Образ собирается и пушится в `registry.example.com/depot/api` с тегами `${{ github.sha }}` и `latest`, логин через `REGISTRY_USER` и `REGISTRY_PASSWORD`. Затем `gh workflow run deploy.yml --repo dex/depot-infra`.

**Что сделано в `size-label.yml`:** метка `size/S`, `size/M` или `size/L` ставится по сумме добавленных и удалённых строк из события PR. Триггер `pull_request_target`, потому что у PR из форков обычный токен только на чтение. Код PR не выкачивается и не исполняется. Нужных меток в репозитории может не быть, поэтому workflow создаёт их сам.

**Замечания:**
1. **Self-hosted раннеры (`depot-linux`) не использованы.** Мы принимаем PR из форков, и на таких раннерах в сети компании выполнялся бы чужой код. Это небезопасно, пока форки допускаются. Их можно использовать для сборок на `main`, если решите.
2. **Нужен новый секрет `DEPOT_INFRA_DISPATCH_TOKEN`.** Стандартный `GITHUB_TOKEN` не может запускать workflow в другом репозитории. Нужен PAT или токен GitHub App с правом `actions:write` на `dex/depot-infra`. Без него шаг деплоя упадёт.
3. **Входные параметры `deploy.yml` в задаче не описаны.** Я запускаю его без параметров. Если ему нужен образ или тег, их надо передать через `-f`.
4. **Пороги размера в задаче не заданы.** Я взял S меньше 50 строк, M меньше 250, L от 250. Скажите, если нужны другие.
5. **Версии actions** указаны тегами (`@v4`, `@v3`, `@v6`), а не SHA. Если политика безопасности требует закрепления по SHA, это нужно сделать отдельно. То же относится к `@v2` у license-check.
6. **Windows-тесты** не требуют Docker, поэтому там идёт только фильтр `Category=Contracts`.
7. **Образ с тегом `latest`** публикуется при каждом push в `main`. Если для stage нужен только SHA-тег, `latest` можно убрать.
