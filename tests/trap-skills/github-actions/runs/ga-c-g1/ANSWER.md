Я добавил в `.github/workflows/ci.yml` шаг `actions/cache@v4` для `~/.nuget/packages`, перед `dotnet test`. Ничего не запускал: сборки и сети нет, так что ускорение не проверено. Не коммитил.

Ключ кэша строится из хэша `*.csproj`, `Directory.Packages.props`, `Directory.Build.props` и `global.json`, плюс `runner.os`. Есть и `restore-keys` по префиксу. При смене версий пакетов закэшируется новый набор, а скачано будет только недостающее. Набор проверок остался прежним: `dotnet test -c Release`.

Замечания:
- **Лок-файла нет.** В репозитории нет `packages.lock.json`. Из-за этого я не стал использовать `cache: true` в `setup-dotnet` (ему нужен лок-файл), а взял `actions/cache` с ключом по файлам проекта. Установка идёт не по лок-файлу, а это нарушение `ci-gates`. Предлагаю отдельной задачей включить `RestorePackagesWithLockFile`, закоммитить лок-файлы и запускать restore с `--locked-mode`. Тогда ключ кэша можно будет строить по `**/packages.lock.json`. Здесь я этого не делал, потому что генерировать лок-файлы нечем и это уже выходит за рамки «не менять то, что проверяет CI».
- **Не хватает гейтов.** В CI нет статического анализа (линтер, `dotnet format --verify-no-changes`) и аудита зависимостей (`dotnet list package --vulnerable`). Нет и подтверждения, что проверка `test` объявлена обязательной в защите ветки `main` (это настраивается вне репозитория). Я ничего из этого не добавлял, чтобы не расширять задачу.

Изменён один файл: `.github/workflows/ci.yml`.
