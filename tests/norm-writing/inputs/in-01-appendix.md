# Правила репозитория: выкатка миграций

## Порядок выкатки

Миграция едет отдельным релизом впереди кода, который её использует: сначала совместимая схема,
затем код, затем удаление старого столбца - тремя раздельными выкатками, а не одной. Свести две
выкатки в одну можно ТОЛЬКО при отсутствии живых читателей старого столбца, подтверждённом
запросом к `pg_stat_user_tables`.

При этом отдельно отметим, что при недоступности статистики шаги не сливаются: решение о слиянии
принимается по факту подтверждения, а не по оценке дежурного.

Также в случаях, когда релиз близко, слияние шагов всё равно не разрешается - близость релиза
основанием не является.

## Обратимость

Каждая миграция несёт `Down`, проверенный прогоном на копии схемы. Проверка не прогнана ->
миграция не выкатывается.
