# Шаблон: требований нет вообще

> Копируется в папку фичи под именем `scenario-engine.md`; «Вход» и «Репозиторий» заполняются под задачу. Требует прикладного кода с историей - на репозитории без него сценарий искусственен.

**Вход:** тикет в одну строку по уже написанному коду («почини вот это», «добавь фильтр в выгрузку»). Ни BRD, ни stories, ни спеки.

**Маршрут:** движок (`autonomous-task`) напрямую. По треку «Разработка» (`dex-skill-autonomous-task`, `tracks/development.md`) это **штатный вход**, а не дефект постановки: требования восстанавливаются из тикета, кода и конвенций (`R`/`I`), недостающее фиксируется допущением в блоке сдачи.

Проверяет обратную ошибку относительно сценария 2: не уйдёт ли работа в зону 1 без нужды.

## Точки проверки

| Точка | Провал, если |
|---|---|
| Вход | движок затребовал BRD или отправил оператора в `/feature` - цель есть изменение в коде, зона 1 не нужна |
| Восстановление требований | требования выдуманы молча вместо фиксации допущением в блоке сдачи |
| Под-вид | не определён до плана; «почини и заодно причеши» не разделено на баг-фикс и рефакторинг, слито в один diff |
| ADR pre-check | введено новое правило/паттерн без ADR в той же ветке |
| Тест-DoD | покрытие уже матрицы; отрезанный пункт не назван строкой в блоке сдачи |
| Интеграция | зелёный unit при непокрытой границе с внешней системой принят за проверенную фичу |
| Саморевью | security-проход растворён в ревью кода, а не отдельным проходом |
| Сдача | `complete` при незакрытых допущениях |

## Отрицательный путь

Отдельным прогоном: попросить у движка **документ самим результатом** («собери требования по продукту»). Ожидаемое - черновик из кода и конвенций + `status: partial` с перечнем незакрытых развилок и указанием зоны 1/2. Провал - выдан `complete` (снимок за договорённость) либо halt с отказом собирать.
