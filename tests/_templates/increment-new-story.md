# Шаблон: инкремент - новая стори к принятому набору

> Копируется в папку фичи под именем `scenario-increment.md`; «Вход» заполняется под задачу.

**Вход:** BRD эпика уже принят (гейты пройдены, метки `quality-checks` проставлены). Нужна новая user story, тянущая за собой новое требование.

**Модель работы:** старый BRD **не меняется**. Порождается новый BRD под инкремент, ссылающийся на связанные BRD, в рамках которых планируется фича. Неизменяемость старого сохраняет валидность его меток - перепроверять принятый набор незачем, правка чужого артефакта (запрещена Boundaries дирижёра) не возникает.

## Известный дефект маршрута

Классификация Phase 1 `requirements-orchestrator` - **закрытый перечень из трёх значений**: сырая тема / проработанная идея / чужой готовый BRD. Инкремента среди них нет; `/feature` объявляет те же три входа.

Ожидаемое поведение при прогоне «как есть»: вход приземлится в «чужой готовый BRD» -> Phase 2 пропускается по `skip_if` -> новый `FR` записать некуда -> стори либо осиротеет, либо будет натянута на чужой `FR`. Дефект всплывёт на гейте Phase 3 как находка трассировки, а не на входе как корректная классификация.

Прогон подтверждает или опровергает этот прогноз. Опровержение (дирижёр справился иначе) - тоже результат, фиксируется.

## Точки проверки

| Точка | Провал, если |
|---|---|
| Классификация входа | инкремент молча приравнен к «чужому BRD»; Phase 2 пропущена и новый `FR` некуда записать |
| Ссылки на связанные | новый BRD не ссылается на связанные, читается как самостоятельный и неполный |
| Нумерация | нумерация `FR` начата с чистого листа вместо продолжения сквозной по связанным BRD |
| Старый BRD | изменён - нарушена неизменяемость, метки принятого набора обесценены |
| Оракул набора | `requirement-set-quality` прогнан только по новому BRD; источник лежит в двух документах, полнота против него не устанавливается по одному |
| Согласованность | новое требование конфликтует со старым `FR` или дублирует его, конфликт не найден |
| Трассировка | стори без `FR`-источника; `FR` нового BRD без покрытия и без перевода в `non-goals` |
| Гейты | те же три гейта, что и в сценарии 1 (BRD, набор `FR`/`NFR`, stories), пройдены по дельте формально - находки не предъявлены |
| Стадия | у нового BRD не проставлен `stage`, либо выдан `baselined` без апрува оператора или при открытых вопросах |

## Открытый вопрос к решению по итогам

Оракул набора судит полноту против источника. При инкременте источник распределён по нескольким BRD - оракул об этом не знает. Нужно ли ему правило «набор = новый BRD + связанные», или достаточно, чтобы дирижёр подавал объединённый набор на вход. Решать после прогона, не до.
