# Шаблон: фича с нуля

> Копируется в папку фичи под именем `scenario-e2e.md`; «Вход» и «Репозиторий» заполняются под задачу.

**Вход:** сырая тема на существующем проекте со стеком из реестра (.NET или TS). Кода по теме нет.

**Репозиторий:** `<заполнить>` - нужен прикладной код, маркетплейс не годится (движку негде приземлиться).

**Маршрут:**

```
идея --> /feature --> BRD (BR-NNN) --> FR/NFR --> stories --> /design --> дизайн-док --> задача --> autonomous-task --> MR
```

Проходит все три зоны и обе границы. Самый информативный из трёх - при разрыве стыка зона 1 -> зона 2 остальные сценарии об этом не скажут.

Зона 1 - **четыре звена и две безусловные остановки оператора**: `business-requirements-analyst` (BRD с `BR-NNN` и MOE) -> остановка 1 -> `usecase-analyst` (сценарии `UC` с трассой к `BR`) -> `requirements-analyst` (`FR` из шагов и расширений сценария, `NFR` своей веткой от `BR` и ограничений среды) -> `user-story-analyst` (истории с `AC` `[FR-NNN]`, критерии рождаются при нарезке) -> остановка 2, приёмка набора. Гейты качества стоят на каждом звене, но человека не останавливают: третья остановка снята решением схемы.

## Точки проверки

| Точка | Провал, если |
|---|---|
| Phase 1 дирижёра | классификация не выставлена либо «непонятно»; сырая тема принята за проработанную идею (шторм пропущен) |
| Остановка 1: BRD | апрув не запрошен; запрошен формально, без предъявления находок set-оракула; молчание принято за апрув; полнота состава BRD не сверена с нормативом `business-analysis-29148` (судится «по памяти») |
| Звено `UC` | сценарий выведен из темы напрямую, минуя `BR`; расширение оставлено без исхода; несценарная ветка (`BR` -> `FR` минуя `UC`) объявлена без проверки условия и без основания |
| Нумерация | номер взят максимумом по корпусу вместо инкремента файла ключа в `.req_counter`; счётчик правится не тем же действием, каким заведена единица; на пустом проекте `.docs_layout` и счётчик заведены молча, без строки в выходе |
| Звено `FR`/`NFR` | системный уровень выведен не из `BR-NNN`, а из темы напрямую; требование без `traced from`; `BR` без единого выведенного `FR`/`NFR` и без явного исхода |
| Гейт набора `FR`/`NFR` | находка «снизу» (требование, не возводимое ни к одному `BR`) закрыта дописыванием трассировки задним числом, а не правкой бизнес-уровня |
| Звено stories | вход пришёл только бизнес-уровнем (`BR-NNN` без `FR`/`NFR`), а составитель всё равно начал писать истории вместо halt + возврата оркестратору |
| Остановка 2: приёмка набора | AC без метки `[FR-NNN]`; осиротевший AC закрыт правкой истории, а не системного уровня |
| Выход зоны 1 | нет `quality-checks` с записями всех слоёв; нет нумерации `FR-NNN`; `FR` без явного исхода (не покрыт story и не переведён в `non-goals`); в шапке артефакта зоны не проставлен `status` |
| Вход `/design` | architect не проверил входную метку, начал проектировать поверх непроверенных требований; вход только BRD (без системного уровня) засчитан за полный набор зоны 1 - выведенные `FR`/`NFR` не помечены допущениями |
| Phase 5 architect | решение выбрано без подтверждения оператора |
| Выход зоны 2 | нет пункта «Ожидаемые выходные артефакты»; новый паттерн введён без ADR |
| Движок, под-вид | под-вид не определён до плана |
| Движок, трассировка | `[FR-NNN]` не дошёл до тестов - нить рвётся на кодерах |
| Сдача | `complete` при незакрытых допущениях |

## Отрицательный путь

Отдельным прогоном: дать `/design` требования **без метки** `quality-checks`. Architect обязан прогнать оракул сам (`node-contract` C.9), а не довериться. Провал - принял на веру либо остановился.
