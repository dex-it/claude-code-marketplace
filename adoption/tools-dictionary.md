# Словарь проверенных решений: инструмент -> интеграция

> **Инструмент планировщика, не анкеты.** Анкета собирает факт «какой инструмент у
> клиента»; этот словарь - маппинг собранного факта на наш плагин/решение и на способ
> включения в контекст агента. Маппинг - решение планировщика (отдельная работа), не
> фаза сбора. Анкета на словарь не ссылается.

Карта «инструмент клиента -> проверенное решение -> как включить в контекст агента».
Шире каталога плагинов: не под каждый инструмент есть `dex-*-cli`. Наполняется только
проверенными записями по мере встречи инструментов у клиентов; пустая строка честнее
выдуманной (ложная уверенность на клиенте дороже пробела).

## Два шага установки любого инструмента

1. Поставить бинарь/плагин (в PATH).
2. Внести в контекст агента, чтобы он про инструмент знал. Иначе бинарь стоит, а агент
   его не применяет. Где внести (проектный CLAUDE.md клиента / глобальный CLAUDE.md
   консультанта) - решает оператор по месту. Важно не забыть сам шаг.

Плагины `dex-*-cli` несут slash-команды - самоописательны, шаг 2 закрыт установкой.
Голый бинарь без плагина - шаг 2 вручную.

## LSP-серверы (по стеку, не по инфре)

Type-resolved навигация для типизированных языков. Выбирается по языку.

| Стек | LSP-сервер | Шаг 2 |
|---|---|---|
| .NET / C# | `csharp-ls` | обычно в контексте LSP-тула; проверить доступность в PATH |
| TypeScript / JS | `typescript-language-server` | то же |
| Go / Rust / Python | сервер не заведён -> `tldr` / `rg` / `ast-grep` | - |
