# Профиль команды клиента

Заполняется консультантом по ходу интервью (см. `../01-assessment.md`). На каждую ось -
два слоя: **сырой ответ** (факт клиента) и **ВЫВОД** (точка встраивания по таблице
анкеты). Два слоя, чтобы видеть, на каком ответе основан вывод, и пересматривать вывод
без переспроса клиента. Оси - в порядке внедрения (быстрый вход первым).

Клиент: __________  Дата обследования: __________  Консультант: __________

## 1. Быстрый вход

- Ревью MR: [обязательно / неформально / нет]
- Автотесты + покрытие: [есть с метрикой / без метрики / нет]
- must-разрывы (git / доступ к diff): [нет / есть - какие]
- **ВЫВОД:** [гейты есть -> mr-reviewer/тестеры усиливают | нет -> self-reviewer +
  тестеры встают сразу, риск зеркалирования до постановки помечен | must-разрыв -> вход
  невозможен, закрыть первым]

## 2. Постановка

- BRD (бизнес-требования): [есть / отрывочные / нет]
- Критерии приёмки: [оракул (до кода, не правятся) / зеркало (после кода) / нет]
- NFR: [фиксируются / всплывают постфактум / нет]
- Валидация требований на полноту/конфликты: [есть / нет]
- Схема хранения постановки: [git общий / git выделенный репо / трекер (Jira/Issues) /
  гибрид / вразнобой] -> карта путей в CLAUDE.md
- **ВЫВОД:** [цепь цела (must закрыт) -> кодеры можно | первая разорванная ступень ->
  ВОЛНА 0: business-analyst (BRD) / user-story-writer (критерии) / architect (NFR) /
  requirements-analyst (валидация) | legacy -> legacy-reconstruction + гейт человека |
  схема хранения не зафиксирована -> записать карту «где что лежит» в CLAUDE.md до кодеров]

## 3. Разработка

- Локальная сборка/тесты: [воспроизводимы / только CI]
- DoD инкремента: [есть отдельный / неформальный / нет]
- Legacy без тестов: [есть / нет]
- **ВЫВОД:** [оба must закрыты (постановка + локальная сборка) -> кодеры (dotnet/ts)
  включаемы | пробел среды -> наладить до кодеров | legacy -> legacy-reconstruction до TDD]

## 4. Процесс

- Методология: [Scrum / Kanban / waterfall / нет]
- Приёмка после деплоя: [есть на стенде / нет]
- Где фиксируются критерии приёмки: [до разработки, где именно / дозревают по ходу]
- **ВЫВОД:** [куда вешать гейт готовности требований | гейт приёмки: stand-reviewer |
  пробелы гейтов]

## 5. Инструменты

- Трекер: __________  -> решение: __________  -> в контекст: [плагин / вручную]
- Хостинг репо: __________  -> решение: __________  -> в контекст: [плагин / вручную]
- CI: __________  -> решение: __________  -> в контекст: [плагин / вручную]
- Инфра для диагностики: __________  -> решения: __________  -> в контекст: [плагин / вручную]
- E2E: __________  -> решение: __________  -> в контекст: [плагин / вручную]
- **ВЫВОД:** [список решений под установку + для каждого «как в контекст» | пробелы
  интеграции (инструмент без проверенного решения); см. `tools-dictionary.md`]

## 6. Стек

- Языки: __________
- Фреймворки: __________
- LSP-сервер: __________ (csharp-ls / typescript-language-server / нет)
- **ВЫВОД:** [профильные агенты (dotnet/ts) + by-stack скиллы + LSP-сервер | общий стек
  -> общие агенты, глубина by-stack и LSP недоступна]

## 7. Люди и власть (заметки, без вывода-точки)

- Спонсор и полномочия: __________
- Владельцы CI/инфры (для доступа): __________
- Ожидаемое сопротивление: __________
- Команда для пилота: __________
- **Влияние на порядок раскатки:** [с какой команды начать, кого не трогать сразу]
