# adoption - playbook внедрения агентного SDLC

Каталог продукта внедрения (консалтинг с активом). Читатель - консультант, ведущий
внедрение у клиента. Отличается от `docs/` (там нормативка для авторов плагинов).

## Граница: анкета собирает, план решает

Анкета и профиль - фаза **сбора данных** о клиенте (процесс, инструменты, стек, люди,
цель). Точки встраивания (какой агент на какой слот, какой плагин под инструмент, где
гейты, волна 0) - фаза **решения**, её делает планировщик (отдельная работа) по
заполненному профилю. Клиент участвует только в сборе.

## Состав (текущий)

- `01-assessment.md` - анкета обследования: собрать данные о процессе и целях клиента.
  Ведёт консультант на интервью. Только сбор фактов, без точек встраивания.
- `templates/company-profile.md` - шаблон профиля-снимка: собранные факты + цель. Выход
  обследования, вход планировщика.
- `tools-dictionary.md` - словарь «инструмент -> проверенное решение -> как включить в
  контекст». **Актив планировщика** (маппинг собранных фактов на плагины), не анкеты.
- `cases/` - заполненные профили реальных обследований.

## Порядок работы

1. Провести интервью по `01-assessment.md`.
2. Заполнить `templates/company-profile.md` -> положить копию в `cases/<клиент>.md`.
3. Передать заполненный профиль планировщику (отдельная работа) для определения точек
   встраивания.

Остальные файлы playbook (планировщик, матрица зрелости, пилот, метрики) - следующие
работы, здесь пока нет.
