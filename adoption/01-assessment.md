# Анкета обследования клиента

## Блок 1. Цель клиента

1.1. Что хотите улучшить внедрением агентов? Где сейчас болит?

1.2. Какой измеримый эффект ждёте? По чему поймёте, что сработало?

1.3. Какие ограничения и сроки? (бюджет, дедлайны, что нельзя трогать, регуляторные
ограничения)

## Блок 2. Постановка

2.1. Кто и как ставит бизнес-требования (BRD)? (есть аналитик/PO, BRD с целями и
границами / постановка отрывочная / «тикет = описание», BRD нет)

2.2. Фиксируются ли проверяемые критерии приёмки (acceptance criteria)? (критерии
проверяемы, до разработки, не правятся / есть, но расплывчатые или после кода / критериев
нет)

2.3. Фиксируются ли нефункциональные требования (NFR)? (фиксируются и сверяются с
архитектурой / всплывают постфактум / не задаются)

2.4. Кто проверяет требования на полноту и противоречия? (есть роль/ритуал проверки на
пробелы и конфликты / не проверяются / работа по legacy без постановки)

2.5. Где физически хранится постановка (BRD, критерии, NFR)? (git общий репо / git
выделенный под требования / трекер (какой) / гибрид (что где) / вразнобой)

## Блок 3. Разработка

3.1. Воспроизводится ли сборка и прогон тестов локально одной командой? (сборка + тесты
воспроизводятся локально / только в CI)

3.2. Модель ветвления? (trunk-based, короткоживущие ветки / feature-branches до мерджа /
долгоживущие ветки, редкие слияния)

3.3. Есть ли DoD инкремента, отдельный от продуктовых критериев? (есть, отдельный от
критериев / неформальный / нет)

3.4. Есть ли код без тестов и без постановки (legacy)? (код покрыт или есть постановка /
legacy без тестов и постановки, объём)

## Блок 4. Ревью и тесты

4.1. Есть ли обязательное ревью MR перед мерджем? (обязательно / неформально по желанию /
мерж без ревью)

4.2. Есть ли автотесты и измеряется ли покрытие? (автотесты есть, покрытие измеряется /
тесты есть, покрытие не меряется / автотестов нет); тесты против требований или после
кода?

4.3. Есть ли доступ к репозиторию и diff? (git есть, diff доступен / нет)

## Блок 5. Процесс и доставка

5.1. По какой методологии идёт работа? (Scrum / Kanban / waterfall / нет формального
процесса)

5.2. Есть ли CI/CD как практика - что происходит автоматически на коммит/мердж? (ничего,
сборка вручную / автосборка / автосборка + автотесты / + автодеплой на стенд (CD))

5.3. Где в вашем потоке проходит приёмка после деплоя? (приёмка на стенде после мерджа
есть / приёмки после деплоя нет)

## Блок 6. Инструменты

6.1. Трекер задач? (Jira / GitHub Issues / GitLab / YouTrack / другое / нет)

6.2. Где хостится репозиторий? (GitHub / GitLab / Bitbucket / self-hosted)

6.3. Чем гоняется CI/CD? (GitHub Actions / GitLab CI / Jenkins / TeamCity / нет)

6.4. Инфраструктура, к которой агентам нужен доступ для диагностики? (PostgreSQL / Redis /
Kafka / RabbitMQ / Kubernetes / AWS S3 / нет)

6.5. Observability - логи, метрики, трейсинг? (Grafana / Prometheus / Sentry / ELK/OpenSearch
/ OpenTelemetry / нет)

6.6. E2E/браузерные тесты? (Playwright / Cypress / нет)

## Блок 7. Стек

7.1. Основные языки? (C#/.NET / TypeScript/JS / Python / Go / другое)

7.2. Ключевые фреймворки/библиотеки? (напр. ASP.NET Core, EF Core; React, Node)

7.3. Менеджер пакетов и команда сборки/тестов? (напр. NuGet + dotnet build/test;
npm/pnpm/bun + скрипты)

## Блок 8. Люди и власть

8.1. Кто спонсор внедрения и есть ли у него полномочия менять процесс?

8.2. Кто владеет CI/инфрой - кого нужно подключить, чтобы агенты получили доступ?

8.3. Есть ли команда-доброволец для первого пилота?
