# Анкета обследования клиента

## Блок 1. Ревью и тесты

1.1. Есть ли обязательное ревью MR перед мерджем? (обязательно / неформально по желанию /
мерж без ревью)

1.2. Есть ли автотесты и измеряется ли покрытие? (автотесты есть, покрытие измеряется /
тесты есть, покрытие не меряется / автотестов нет); тесты против требований или после
кода?

1.3. Есть ли доступ к репозиторию и diff? (git есть, diff доступен / нет)

## Блок 2. Постановка

2.1. Кто и как ставит бизнес-требования (BRD)? (есть аналитик/PO, BRD с целями и
границами / постановка отрывочная / «тикет = описание», BRD нет)

2.2. Фиксируются ли проверяемые критерии приёмки (acceptance criteria)? (критерии
проверяемы, до разработки, не правятся / есть, но расплывчатые или после кода / критериев
нет)

2.3. Фиксируются ли нефункциональные требования (NFR)? (фиксируются и сверяются с
архитектурой / всплывают постфактум / не задаются)

2.4. Кто проверяет требования на полноту и противоречия? (есть роль/ритуал проверки на
пробелы и конфликты / не проверяются / работа по legacy без постановки)

2.5. Где физически хранится постановка (BRD, критерии, NFR)? (git общий репо / git
выделенный под требования / трекер (какой) / гибрид (что где) / вразнобой)

## Блок 3. Разработка

3.1. Воспроизводится ли сборка и прогон тестов локально одной командой? (сборка + тесты
воспроизводятся локально / только в CI)

3.2. Есть ли DoD инкремента, отдельный от продуктовых критериев? (есть, отдельный от
критериев / неформальный / нет)

3.3. Есть ли код без тестов и без постановки (legacy)? (код покрыт или есть постановка /
legacy без тестов и постановки, объём)

## Блок 4. Процесс

4.1. По какой методологии идёт работа? (Scrum / Kanban / waterfall / нет формального
процесса)

4.2. Где в вашем потоке проходит приёмка после деплоя? (приёмка на стенде после мерджа
есть / приёмки после деплоя нет)

4.3. Куда в потоке ложится момент «acceptance criteria зафиксированы»? (есть точка
фиксации критериев до разработки (какая) / критерии дозревают по ходу)

## Блок 5. Инструменты

5.1. Трекер задач? (Jira / GitHub Issues / GitLab / YouTrack / другое / нет)

5.2. Где хостится репозиторий? (GitHub / GitLab / Bitbucket / self-hosted)

5.3. CI? (GitHub Actions / GitLab CI / Jenkins / TeamCity / нет)

5.4. Инфраструктура, к которой агентам нужен доступ для диагностики? (PostgreSQL / Redis /
Kafka / RabbitMQ / Kubernetes / AWS S3 / нет)

5.5. E2E/браузерные тесты? (Playwright / Cypress / нет)

## Блок 6. Стек

6.1. Основные языки? (C#/.NET / TypeScript/JS / Python / Go / другое)

6.2. Ключевые фреймворки/библиотеки? (напр. ASP.NET Core, EF Core; React, Node)

6.3. Менеджер пакетов / сборка?

## Блок 7. Люди и власть

7.1. Кто спонсор внедрения и есть ли у него полномочия менять процесс?

7.2. Кто владеет CI/инфрой - кого нужно подключить, чтобы агенты получили доступ?

7.3. Где ожидается сопротивление (страх замены, «у нас и так работает»)?

7.4. Есть ли команда-доброволец для первого пилота?

## Блок 8. Цель клиента

8.1. Что хотите улучшить внедрением агентов? Где сейчас болит?

8.2. Какой измеримый эффект ждёте? По чему поймёте, что сработало?

8.3. Какие ограничения и сроки? (бюджет, дедлайны, что нельзя трогать, регуляторные
ограничения)
