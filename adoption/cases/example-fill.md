# Профиль команды клиента (ПРИМЕР - проверка анкеты)

> Выдуманный клиент для проверки, что анкета заполняет профиль без дыр. Не реальное обследование.

Клиент: Acme (пример)  Дата: 2026-07-15  Консультант: (пример)

## 1. Быстрый вход
- Ревью MR: обязательно
- Автотесты + покрытие: есть без метрики
- must-разрывы (git / доступ к diff): нет
- **ВЫВОД:** гейты частично -> mr-reviewer усиливает ревью; тестеры добавляют branch coverage по diff сразу; must закрыт (git есть)

## 2. Постановка
- BRD: отрывочные
- Критерии приёмки: зеркало (пишутся после кода)
- NFR: всплывают постфактум
- Валидация требований: нет
- Схема хранения постановки: вразнобой (часть в Jira-тикетах, часть в головах) -> карта путей в CLAUDE.md
- **ВЫВОД:** цепь рвётся на критериях (must-разрыв) -> ВОЛНА 0: user-story-writer (критерии) + architect (NFR) + requirements-analyst (валидация); business-analyst на BRD; кодеров не включать до этого; схему хранения зафиксировать (карта в CLAUDE.md: критерии -> где)

## 3. Разработка
- Локальная сборка/тесты: воспроизводимы
- DoD инкремента: неформальный
- Legacy без тестов: есть частично
- **ВЫВОД:** локальная сборка (must) закрыта, но постановка (must) неполна -> кодеров ждать до волны 0; architect на DoD; legacy-reconstruction на непокрытые модули

## 4. Процесс
- Методология: Scrum
- Приёмка после деплоя: нет
- Где фиксируются критерии: дозревают по ходу спринта
- **ВЫВОД:** гейт готовности требований ставить искусственно на входе в разработку; включить stand-reviewer на приёмку

## 5. Инструменты
- Трекер: Jira -> `dex-jira-cli` -> в контекст: плагин
- Хостинг репо: GitLab -> `dex-gitlab-cli` -> в контекст: плагин
- CI: GitLab CI -> `dex-gitlab-cli` -> в контекст: плагин
- Инфра: PostgreSQL, Redis -> `dex-psql-cli`, `dex-redis-cli` -> в контекст: плагины
- E2E: нет
- **ВЫВОД:** ставить dex-jira-cli, dex-gitlab-cli, dex-psql-cli, dex-redis-cli (все плагины, шаг 2 закрыт); пробелов нет

## 6. Стек
- Языки: C#/.NET
- Фреймворки: ASP.NET Core, EF Core
- LSP-сервер: csharp-ls
- **ВЫВОД:** dex-dotnet-coder, dex-dotnet-tester, dex-architect-dotnet; dex-skill-dotnet-*; LSP csharp-ls

## 7. Люди и власть
- Спонсор: CTO, полномочия есть
- Владельцы CI/инфры: DevOps-команда
- Сопротивление: senior-разработчики (страх замены)
- Команда для пилота: команда биллинга (доброволец)
- **Влияние на порядок раскатки:** начать с биллинга; senior подключать через демонстрацию, не директиву
