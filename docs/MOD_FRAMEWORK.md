# Mod Framework

Нормативный дом четвёртого класса артефакта каталога - **мода**. Skill, специалист и команда меняют то, что модель читает; мод меняет то, что делает и показывает сам Claude Code. Устройство остальных классов - `SKILL_FRAMEWORK.md`, `AGENT_FRAMEWORK.md`, `COMMAND_FRAMEWORK.md`; общие конвенции каталога - [CLAUDE.md](../CLAUDE.md).

## Что такое мод

Мод - плагин, поведение которого несёт **модуль function hooks**: TypeScript, который платформа исполняет внутри собственного процесса. Хук - функция `($, e, next)`, подписанная на событие движка: `$` - разрешённые эффекты (`$.process.run`, `$.http.fetch`, `$.ui.*`, `$.store`, `$.clock`), `e` - аргумент события, `next` - продолжение цепочки вниз. Моды вкладываются как middleware: зарегистрированный раньше оборачивает остальных, а `next(e)` отдаёт управление тому, кто ниже.

Источники (сверено 15.09.2026): анонс и справочник аффордансов - [anthropics/claude-code#91870](https://github.com/anthropics/claude-code/issues/91870); исходники трёх встроенных модов и контракт типов - [anthropics/claude-code/mods](https://github.com/anthropics/claude-code/tree/main/mods).

**Ранний доступ.** Модуль хуков грузится только при `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1`; сборка без флага ключ `modules` в `hooks/hooks.json` игнорирует, и плагин ставится «пустым». API объявлен меняющимся между релизами без предупреждения - отсюда обязанность моду держать версию контракта типов (ниже) и не обещать в описании того, что перестанет работать молча.

### Мод против утилиты

| Признак | Мод | Утилита |
| --- | --- | --- |
| Носитель | `hooks/hooks.json` с ключом `modules`, TypeScript в `hooks/` | `commands/*.md` и/или `hooks/hooks.json` с ключом `hooks` |
| Где исполняется | в процессе Claude Code | отдельный процесс оболочки на событие |
| Что может | перехватить вызов инструмента, промпт, рендер; рисовать панели и строки | напечатать, вызвать бинарь, вернуть текст |
| Чем проверяется | `tsc`, `node --test`, `claude plugin validate` | валидатор команд, `bash -n` |

Классический хук-команда и мод в одном плагине не запрещены платформой, но **в каталоге не смешиваются**: категория выводится из дерева одним признаком, и плагин с обоими ключами читался бы как мод, пока автор считает его утилитой. Нужны оба поведения - два плагина.

## Где лежит и как попадает в каталог

- **Дерево** - `mods/<имя>/` в корне репозитория, рядом с `plugins/`. Класс артефакта другой (исполняемый TypeScript, не текст для модели), и общий `mods/tsconfig.json` с контрактом типов покрывает дерево целиком. Форма повторяет `mods/` в репозитории Anthropic.
- **Имя** - `dex-{name}`, как у утилиты (конвенция именования - [CLAUDE.md](../CLAUDE.md), «Именование»).
- **Категория записи каталога** - `mod`. Признак выводится из содержимого, а не из места: `hooks/hooks.json` с массивом `modules` -> `mod` (ветка стоит до `hooks/` -> `utility`). Держит `catalog-category-mismatch` в `tools/validate-bundle.js`, охват которого включает `mods/` наравне с `plugins/` - вместе с ним мод судят `version-mismatch` и `description-mismatch`.
- **Витрина** - раздел «Mods» в [README.md](../README.md); плагин, не названный там, роняет `readme-plugin-unnamed`.
- **Версии** - те же правила, что у плагина: `plugin.json` и `marketplace.json` синхронно, новый мод бампает minor версии каталога ([plugin-changes.md](../.claude/rules/plugin-changes.md)).
- **Бандлы** мод не берут: установка бандла ставит текстовые артефакты роли, а мод меняет поведение клиента и включается адресно, по решению разработчика.

## Состав мода

```
mods/dex-<имя>/
├── .claude-plugin/plugin.json   # манифест: витрина + userConfig
├── hooks/
│   ├── hooks.json               # { "description": ..., "modules": ["./register.tsx"] }
│   ├── register.tsx             # точка входа: export const register: Register
│   └── *.ts                     # части модуля
├── tests/*.test.ts              # прогон чистой половины
└── README.md                    # установка, использование, пределы
```

`hooks.json` называет **один** модуль-точку входа; остальные файлы - его импорты. Точка входа экспортирует `register(on, options)`: `on` регистрирует хуки, `options` - значения полей `userConfig` манифеста с подставленными дефолтами.

**Относительный импорт внутри мода несёт расширение `.ts` (`.tsx`).** Это не стиль, а условие проверяемости: `node --test` резолвит относительные импорты по правилам Node, без расширения не находит цепочку и валится с `ERR_MODULE_NOT_FOUND`, - поэтому прогоном закрывались бы только модули, не импортирующие ничего вовсе. Форма проверена живым прогоном мода на 2.1.282 (`claude --plugin-dir`, модуль грузится) и разрешена компилятору флагом `allowImportingTsExtensions` в `mods/tsconfig.json`. Модуль, которому нужен `Api` или другой тип соседа, берёт его `import type` - типовой импорт стирается и цепочки не создаёт.

### `userConfig`: настройки мода

Поля объявляются в `plugin.json`, редактируются через `/config`, приезжают в `register` вторым аргументом. Форма поля (прогон `claude plugin validate --strict` на 2.1.282, 25.09.2026, сверено с [plugins/manifest-reference](https://code.claude.com/docs/en/plugins/manifest-reference#user-configuration)): `type` (`string` / `number` / `boolean` / `directory` / `file`), **обязательный** `title`, `description`, `default`, `options` (список допустимых значений строки - `/config` рисует их выбором), `multiple` (строка становится массивом строк), `required` (пустое значение не принимается), `min` и `max` (границы числа), `sensitive` (значение уезжает в защищённое хранилище). Отсутствие `title` - ошибка валидации манифеста.

Границу числа лучше держать полем, а не одной прозой README: `min` отсекает значение на вводе, а зажим в коде (`Math.max`) сообщает о себе только поведением. Мод с периодическим опросом объявляет и то и другое - поле бережёт пользователя от опечатки, зажим бережёт от значения, приехавшего не из `/config`.

Поля `sensitive` и `multiple` панель `/config` не рисует - их значения задаются иначе, и мод не вправе считать, что пользователь увидит их в списке настроек.

Секрет в `userConfig` - не единственный путь: токен читается и из окружения (`$.env.get`), и это предпочтительный вход там, где он уже есть у CLI. Поле нужно, когда окружения нет.

### Граница: что мод делает сам, а что отдаёт модели

Мод не заменяет агента и не «умничает»: он приносит факты и рисует их. Решение, что с фактами делать, остаётся человеку и модели. Практический критерий: **всё, что мод показал человеку, он обязан уметь отдать текстом** - командой, которая печатает то же в транскрипт, или контекстом промпта. Иначе модель работает вслепую рядом с панелью, на которую смотрит человек.

## Инструментарий

| Проверка | Команда | Что ловит |
| --- | --- | --- |
| Типы | `npm run typecheck:mods` | разъезд с контрактом API; входит в `npm run validate` |
| Прогон | `npm run test:mods` | чистую половину мода (разбор, сборка ответа, дельта) |
| Манифест и модуль | `claude plugin validate mods/<имя>` | форму `plugin.json`, `userConfig`, перечень хукнутых событий, вызовов `$` и читаемых переменных окружения |
| Живой прогон без установки | `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1 claude -p "/<команда>" --plugin-dir mods/<имя>` | путь целиком: загрузку модуля, выбор источника, ответ хостинга, текст для модели - без интерактивного терминала |
| Живая сессия | `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1 claude --plugin-dir mods/<имя>` | всё остальное: отрисовку строки и панели, таймер, кнопки |

Прогон чистой половины идёт под Node с разбором TypeScript на лету (`--experimental-strip-types`, с 22.6), поэтому `engines` репозитория подняты до этой версии - до модов цепочка обходилась чистым JavaScript.

**Контракт типов** - `mods/types/claude-code.d.ts`: его пишет встроенная команда `/plugin-types` (в том числе headless: `claude -p "/plugin-types"`), первая строка называет версию Claude Code, которой он написан. Файл **генерируется**, руками не правится; обновление клиента - повод перегенерировать и прогнать `npm run typecheck:mods`, потому что разъезд API иначе всплывёт только в сессии.

Тесты живут на чистых функциях: разбор remote и ссылок, сборка ответа API, вычисление дельты между опросами, тексты для модели, состав опроса на подменённом источнике. Хуки, которым нужен живой `$`, прогоном каталога не покрыты - их проверяет сессия; у платформы для этого объявлен набор `claude-code/testing` в контракте типов, но подкоманды `claude plugin test` нет ни в 2.1.272, ни в 2.1.282 (прогон `claude plugin --help` 15.09.2026 и 25.09.2026), поэтому тесты каталога написаны под `node --test`.

Граница покрытия задаётся не вкусом, а двумя фактами инструментария. Первый: модуль, который трогает `$`, прогоном не берётся - живого `$` у прогона нет. Второй: **`.tsx` прогон не берёт вовсе** - Node не знает такого расширения и падает с `ERR_UNKNOWN_FILE_EXTENSION` ещё до разбора типов (прогон 25.09.2026 на Node 24.20), а `--experimental-strip-types` снимает типы, не JSX. Отсюда правило состава: в `.tsx` держать только отрисовку и точку входа, а решения - в `.ts` без `$`, включая состав опроса (какие запросы и в каком порядке) и тексты, которые читает модель. Отрисовка остаётся на живой сессии, и это единственная поверхность мода, которую прогоном не закрыть.

## Self-check перед коммитом мода

- [ ] `hooks.json` называет ровно одну точку входа, и она экспортирует `register`
- [ ] Каждый вызов `$`, который перечислил `claude plugin validate`, мод действительно делает - лишний вызов в перечне значит мёртвый код, который админская политика всё равно учтёт
- [ ] Ошибка источника данных попадает на экран **фактом, который можно исправить** («glab не установлен», «нет токена»), а не молчанием пустой панели
- [ ] Первый опрос ничего не объявляет: иначе взятый под наблюдение объект вываливает историю целиком
- [ ] Чужой текст (заголовки, комментарии, имена веток) чистится от управляющих символов до отрисовки - он приходит в терминал как есть
- [ ] Периодический опрос имеет нижний порог периода и не ходит в сеть в headless-прогоне (`-p`), где рисовать некому
- [ ] Всё показанное доступно текстом (👁 ручная проверка)
- [ ] Относительные импорты несут расширение `.ts` (`.tsx`), и прогон берёт каждый `.ts`-модуль без `$`; в `.tsx` осталась только отрисовка
- [ ] `npm run typecheck:mods`, `npm run test:mods`, `claude plugin validate --strict mods/<имя>` - без ошибок
- [ ] Живой прогон `claude -p "/<команда>" --plugin-dir mods/<имя>` отвечает данными, а не причиной
- [ ] Запись каталога, витрина README, версия мода и версия каталога синхронны ([plugin-changes.md](../.claude/rules/plugin-changes.md))
