## Story 1. Экспорт полной отфильтрованной выборки за одно действие

**As a** инициатор (HR-администратор или руководитель подразделения) на экране списка сотрудников,
**I want to** получить единым файлом все строки, отобранные текущими фильтрами экрана, за одно действие,
**So that** не переносить данные вручную постранично.

### Acceptance Criteria

- **AC1 `[FR-001]`.** Given инициатор применил фильтры, которым соответствуют 137 сотрудников, отображаемые постранично (50 на страницу), When инициатор запускает экспорт, Then формируется один файл, содержащий ровно 137 строк - по одной на каждого сотрудника выборки, без повторного действия на каждую страницу.
- **AC2 `[FR-001]`.** Given число отобранных сотрудников кратно размеру страницы отображения (например, 100 при странице 50), When экспорт запущен, Then файл содержит все 100 строк в одном файле - граница страницы не обрезает и не дублирует строки.
- **AC3 `[FR-002]`.** Given сформированный файл, When он открыт, Then каждая строка соответствует ровно одному сотруднику отобранной выборки, и каждое значение находится строго под заголовком своего столбца, без потери строк и без смещения значений.
- **AC4 `[FR-002]`.** Given значение поля содержит запятую, двойную кавычку или перенос строки (например, подразделение «Продажи, EMEA» или ФИО с внутренней кавычкой), When файл экспортирован, Then значение экранировано/заключено в кавычки по CSV-конвенции так, что последующие столбцы не смещаются.
- **AC5 `[FR-001]`.** Given инициатор запускает экспорт дважды подряд с одинаковыми фильтрами, When оба действия завершены, Then каждое даёт собственный полный независимый файл с одинаковым числом строк - без смешения между двумя запусками.

### Technical Notes
Данных о стеке/эндпоинтах нет (Phase 2 пропущена, корпус `unverifiable`). Известное ограничение: `C-002` - состав полей согласован с ИБ, не пересматривается в рамках этой истории.

### Definition of Done
- [ ] AC1-AC5 покрыты автотестами (в т.ч. на нескольких масштабах выборки и на спецсимволах в значениях полей)
- [ ] Ручная проверка на выборке, пересекающей границу страницы отображения
- [ ] Код-ревью пройдено

**Story Points:** 5 | **Priority:** Must | **Dependencies:** нет

## Story 2. Ролевой охват и авторизация вызова

**As a** инициатор,
**I want to** получать в файле только сотрудников своей зоны ответственности (или получать отказ вызова, если у меня нет права на экспорт),
**So that** данные вне моей зоны ответственности не покидают систему через экспорт.

### Acceptance Criteria

- **AC1 `[FR-005]`.** Given инициатор имеет роль HR-администратор, When экспорт запущен, Then файл содержит всех сотрудников компании, соответствующих применённым фильтрам, без ограничения по подразделению.
- **AC2 `[FR-005]`.** Given инициатор имеет роль руководитель подразделения с двумя уровнями подчинённых подразделений, When экспорт запущен, Then файл содержит только сотрудников собственного подразделения и всех подчинённых подразделений по иерархии, и ни одного сотрудника вне этой зоны.
- **AC3 `[FR-006]`.** Given инициатор имеет роль руководитель подразделения без подчинённых подразделений, When экспорт запущен, Then файл содержит только сотрудников собственного подразделения инициатора, без ошибки и без отдельного видимого поведения по сравнению с AC2.
- **AC4 `[NFR-006]`.** Given пользователь аутентифицирован с ролью, отличной от HR-администратор и руководитель подразделения, When он вызывает функцию экспорта, Then вызов отклоняется.
- **AC5 `[NFR-006]`.** Given неаутентифицированный пользователь, When он вызывает функцию экспорта, Then вызов отклоняется.

### Technical Notes
Ролевая модель существует, новая не проектируется (`C-001`). Технический механизм проверки роли и структура иерархии подразделений - решение реализации, не задано входом.

### Definition of Done
- [ ] AC1-AC5 покрыты автотестами на тестовой иерархии с несколькими уровнями вложенности
- [ ] Выборочная сверка журнала после первого релиза (см. Story 8)
- [ ] Код-ревью пройдено

**Story Points:** 8 | **Priority:** Must | **Dependencies:** нет (функционально предшествует остальным - без прохождения AC4/AC5 экспорт недостижим, но разрабатывается и тестируется независимо)

## Story 3. Ограниченный состав полей

**As a** инициатор,
**I want to** получать в файле ровно согласованный с ИБ набор полей,
**So that** зарплатные и иные чувствительные данные не покидают систему через экспорт.

### Acceptance Criteria

- **AC1 `[FR-004]`.** Given инициатор экспортирует любую отфильтрованную выборку, When файл сформирован, Then он содержит ровно семь полей: ФИО, табельный номер, подразделение, должность, дата приёма, статус, корпоративный email.
- **AC2 `[FR-004]`.** Given сформированный файл, When он проверен, Then в нём нет зарплатных данных, личного телефона, домашнего адреса, паспортных данных и любого иного поля вне согласованного состава.

### Technical Notes
Состав полей согласован с ИБ и не пересматривается в рамках фичи (`C-002`).

### Definition of Done
- [ ] AC1-AC2 покрыты автотестом, фиксирующим точный набор колонок
- [ ] Код-ревью пройдено

**Story Points:** 2 | **Priority:** Must | **Dependencies:** нет

## Story 4. Соответствие содержимого файла видимому срезу

**As a** инициатор,
**I want to** получать в файле ровно тех сотрудников, которых вижу на экране при применённых фильтрах, включая умолчание «только действующие сотрудники»,
**So that** файл совпадает с ожиданием без дополнительной сверки.

### Acceptance Criteria

- **AC1 `[FR-008]`.** Given инициатор не менял фильтр статуса (умолчание «только действующие»), When экспорт запущен, Then файл содержит только сотрудников со статусом «действующий», совпадая с отображаемым на экране.
- **AC2 `[FR-008]`.** Given инициатор применил фильтры по подразделению и должности, When экспорт запущен, Then файл содержит ровно тех сотрудников, что удовлетворяют всем применённым фильтрам - тот же набор, что виден на экране.

### Разграничение со Story 1 (снимает `S-4` источника)
Story 1 отвечает за **полноту и целостность переноса** отобранной выборки (все строки за одно действие, без потери/смещения при постраничности). Story 4 отвечает за **корректность состава** этой выборки относительно применённых фильтров экрана, включая умолчание статуса. AC между историями не дублируются: AC1/AC2 здесь не переиспользуют формулировки AC1/AC2/AC5 Story 1 и наоборот.

### Definition of Done
- [ ] AC1-AC2 покрыты автотестами на комбинациях фильтров, включая нетронутый умолчательный фильтр статуса
- [ ] Код-ревью пройдено

**Story Points:** 3 | **Priority:** Must | **Dependencies:** Story 1 (общий механизм формирования файла)

## Story 5. Пустая выборка без ошибки

**As a** инициатор,
**I want to** получать предсказуемый неошибочный результат, если применённые фильтры не дали ни одной строки,
**So that** отсутствие данных не выглядит как сбой.

### Acceptance Criteria

- **AC1 `[FR-011]`.** Given инициатор применил фильтры, которым не соответствует ни один сотрудник, When экспорт запущен, Then операция завершается без видимого инициатору состояния ошибки (нет сообщения об ошибке, нет провала запроса).

### Требует решения постановщика (не закрыто AC, `Q-002` источника)
Точная форма файла при нулевой выборке не решена: файл с заголовками колонок и нулём строк данных (предложение, перенесённое из BRD, не подтверждённое) - или иная форма. AC1 покрывает только факт «без ошибки», не форму файла. AC на форму файла не написан - домысливать нельзя.

### Definition of Done
- [ ] AC1 покрыт автотестом
- [ ] Форма файла при пустой выборке - blocked до решения постановщика по `Q-002`

**Story Points:** 2 | **Priority:** Must | **Dependencies:** нет

## Story 6. Включение уволенных только по явному переключению

**As a** инициатор,
**I want to** видеть уволенных сотрудников в выгрузке только тогда, когда я явно переключил фильтр статуса,
**So that** данные уволенных не попадают в файл случайно.

### Acceptance Criteria

- **AC1 `[FR-009]`.** Given инициатор не менял фильтр статуса от умолчания, When экспорт запущен, Then файл не содержит ни одного сотрудника со статусом «уволен».
- **AC2 `[FR-009]`.** Given инициатор явно переключил фильтр статуса на включение уволенных, When экспорт запущен, Then файл включает сотрудников со статусом «уволен», соответствующих этому фильтру.

### Требует решения постановщика (не закрыто AC, `Q-008` источника)
Глубина охвата уволенных - весь справочник или ограничение по дате увольнения - бизнес-решением не задана. AC1/AC2 покрывают только факт «по явному переключению», не глубину охвата.

### Definition of Done
- [ ] AC1-AC2 покрыты автотестом
- [ ] Глубина охвата - blocked до решения постановщика по `Q-008`

**Story Points:** 3 | **Priority:** Must | **Dependencies:** Story 4 (общий механизм соответствия срезу фильтров)

## Story 7. Пригодность файла к открытию в Excel и Google Sheets

**As a** получатель файла,
**I want to** открыть выгруженный файл в Excel или Google Sheets и сразу работать с данными,
**So that** не тратить время на переформатирование или восстановление читаемости текста.

### Acceptance Criteria

- **AC1 `[NFR-003]`.** Given файл с кириллическими значениями ФИО и подразделения, When он открыт в Excel (русскоязычная локаль) или Google Sheets, Then кириллические символы отображаются корректно (без «кракозябр»).
- **AC2 `[NFR-003]`.** Given сформированный файл, When он открыт в Excel (RU-локаль) или Google Sheets, Then каждое значение находится в собственном столбце - без схлопывания всех данных в один столбец.
- **AC3 `[FR-003]`.** Given получатель получил файл, When он открывает его и работает с данными в Excel или Google Sheets, Then дополнительный шаг переформатирования или восстановления кодировки не требуется.

### Technical Notes
Конкретная кодировка и разделитель (например, UTF-8 BOM, `;`) - решение реализации, не зафиксированы входом (`NFR-003` намеренно не диктует «как»).

### Definition of Done
- [ ] AC1-AC3 проверены на реальных Excel (RU-локаль) и Google Sheets, не только на машине разработчика
- [ ] Код-ревью пройдено

**Story Points:** 5 | **Priority:** Must | **Dependencies:** Story 1 (формат файла)

## Story 8. Журнал выгрузок

**As a** комплаенс/ИБ,
**I want to** видеть отдельную запись журнала по каждой попытке выгрузки с инициатором, временем, числом строк и применёнными фильтрами,
**So that** каждая выгрузка прослеживаема при проверке.

### Acceptance Criteria

- **AC1 `[FR-007]`.** Given инициатор выполняет экспорт, When действие завершено, Then создаётся запись журнала, фиксирующая: идентификатор и роль инициатора, момент времени, число выгруженных строк, применённые фильтры.
- **AC2 `[FR-007]`.** Given инициатор выполняет два экспорта подряд с одинаковыми фильтрами, When оба завершены, Then существуют две отдельные записи журнала (не объединённые в одну).
- **AC3 `[NFR-004]`.** Given запись журнала, созданная в момент выгрузки, When она запрошена спустя до 3 лет, Then запись остаётся доступной для проверки комплаенсом.

### Требует решения постановщика (не закрыто AC)
- Входит ли значение строки поиска по ФИО в состав фиксируемых журналом фильтров - не решено (`Q-004` источника). AC1/AC2 покрывают состав «применённые фильтры» без этой детали.
- Доступ на чтение журнала (кто вправе смотреть записи) не специфицирован (`G-b` источника, гэп унаследован без решения) - AC на это не пишется.

### Definition of Done
- [ ] AC1-AC3 покрыты автотестами
- [ ] Ручная проверка доступности записи на исторических данных (или её симуляция)
- [ ] Код-ревью пройдено

**Story Points:** 5 | **Priority:** Must | **Dependencies:** Story 1, Story 2 (данные для записи журнала)

## Story 9. Неудержание файла на сервере

**As a** ИБ,
**I want to** быть уверенным, что сгенерированный файл выгрузки не остаётся ни в каком серверном хранилище дольше времени передачи,
**So that** PII-данные не накапливаются на сервере сверх необходимого.

### Acceptance Criteria

- **AC1 `[NFR-005]`.** Given экспорт завершён и файл возвращён инициатору в ответе, When серверное хранилище (диск, БД, временный кэш, лог) проверено немедленно после этого, Then копия выгруженного файла не найдена.
- **AC2 `[NFR-005]`.** Given проверка ИБ проведена в произвольный момент времени, When серверное хранилище проверено, Then обнаружено 0 хранимых файлов выгрузки сверх окна передачи ответа.

### Technical Notes
Ограничение `C-003`: файл не хранится на сервере, отдаётся только в ответ.

### Definition of Done
- [ ] AC1-AC2 покрыты автотестом (проверка отсутствия артефактов после запроса)
- [ ] Проверка ИБ включена в регламент не реже раза в квартал (эксплуатационный процесс, вне разработки истории)
- [ ] Код-ревью пройдено

**Story Points:** 3 | **Priority:** Must | **Dependencies:** Story 1

## Story 10. Готовность файла в пределах временного бюджета на заявленном объёме

**As a** инициатор,
**I want to** получать готовый файл в пределах ожидаемого времени ожидания даже на верхней границе объёма выборки,
**So that** экспорт остаётся пригодным к использованию при заявленном объёме данных, не подвешивая интерфейс инициатора.

> Значение сформулировано напрямую из текста `NFR-001`/`NFR-002`, без приписывания родительского `BR` - у обоих требований трасса к бизнес-уровню отсутствует и оформлена явным статусом во входе (`S-1`), домысливать бизнес-обоснование запрещено.

### Acceptance Criteria

- **AC1 `[NFR-001]`.** Given отфильтрованная выборка ровно 1200 строк (заявленная верхняя граница), When экспорт запущен, Then файл готов к передаче инициатору в пределах 10 секунд от запроса.
- **AC2 `[NFR-002]`.** Given численность компании на граничных значениях 400 и 1200 действующих сотрудников, и одиночная выгрузка на граничных значениях 50 и 1200 строк, When экспорт запущен на каждой из границ, Then он завершается без потери строк и без нарушения целостности строк/столбцов (`FR-001`/`FR-002`).

### Definition of Done
- [ ] AC1-AC2 покрыты нагрузочным/граничным тестом на заявленных значениях объёма
- [ ] Код-ревью пройдено

**Story Points:** 5 | **Priority:** Must | **Dependencies:** Story 1

## Story 11. Отсутствующие значения полей сотрудника

**As a** инициатор,
**I want to** видеть в файле сотрудника с отсутствующим значением поля (например, без корпоративного email или без даты приёма) как строку с пустой ячейкой, а не как выпавшую из выгрузки строку,
**So that** одно недостающее поле не приводит к исчезновению сотрудника из выгрузки.

### Acceptance Criteria

- **AC1 `[FR-010]`.** Given у сотрудника отобранной выборки нет записанного корпоративного email, When он экспортирован, Then строка включена в файл с пустой ячейкой в столбце email (строка не исключена).
- **AC2 `[FR-010]`.** Given у сотрудника отобранной выборки нет записанной даты приёма, When он экспортирован, Then строка включена с пустой ячейкой в этом столбце.

### Technical Notes
Требование основано на допущении `A-002` источника (постановщик случай явно не оговаривал) - Should-приоритет.

### Definition of Done
- [ ] AC1-AC2 покрыты автотестом
- [ ] Код-ревью пройдено

**Story Points:** 2 | **Priority:** Should | **Dependencies:** Story 1
