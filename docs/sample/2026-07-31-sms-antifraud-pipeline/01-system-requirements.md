# Требования системного уровня: антифрод для SMS-регистрации

| | |
|---|---|
| Уровень | системный (`FR`/`NFR`), выведен из `BR-1`..`BR-9` |
| Источник | итоговый BRD ([00-brd.md](00-brd.md)) |
| Стадия | `complete` |
| Режим | `interactive` |

## Классификация и приоритет

MoSCoW проставлен по волнам источника: волна 1 -> Must, волна 2 -> Should. Единственное
требование, живущее в обеих волнах (FR-8), несёт волну на каждом случае применения отдельно -
общей метки у него нет намеренно, иначе половина требования уезжает вместе с меткой.

## Функциональные требования

### Вычислительная цена попытки

**FR-1.** Сервис отправляет SMS с кодом подтверждения только после успешной серверной проверки
доказательства работы (proof-of-work), предъявленного клиентом вместе с запросом на отправку.
*traced from BR-1. Must. Волна 1.*

**FR-2.** Запрос без валидного доказательства работы отклоняется без отправки SMS; ответ не
раскрывает, существует ли номер в системе. *traced from BR-1. Must. Волна 1.*

**FR-3.** Клиент, не способный выполнить доказательство работы (среда без поддержки требуемого
механизма), получает вместо него видимый барьер FR-8 и при его прохождении получает отправку.
*traced from BR-1, BR-4. Must. Волна 1.* Решением оператора на гейте 2 (D-7) барьер как запасной
путь отнесён к волне 1 - ветка перестала упираться в механизм волны 2.

**FR-19.** Доказательство работы одноразово и имеет конечный срок жизни: предъявленное повторно
либо выданное за пределами срока - невалидно. *traced from BR-1. Must. Волна 1.* Возведено из AC
на гейте 3: без одноразовости стоимость кампании падает до одного решения челленджа, то есть BR-1
достигается формально и обходится фактически.

### Лимиты и задержки

**FR-4.** Сервис ограничивает число и темп отправок независимо по четырём осям: адрес источника,
номер получателя, сессия, отпечаток клиента. Превышение по любой оси оценивается отдельно от
остальных. *traced from BR-2. Must. Волна 1.*

**FR-5.** Запрос, превысивший лимит хотя бы по одной оси FR-4, отклоняется без отправки -
независимо от состояния нарастающей задержки FR-6. *traced from BR-2. Must. Волна 1.*
Разводит общую зону BR-2 и BR-3 решением оператора на гейте BRD: лимит старше задержки.

**FR-6.** Повторная отправка на тот же номер откладывается нарастающе: задержка увеличивается с
каждой попыткой внутри окна наблюдения. *traced from BR-3. Must. Волна 1.*

**FR-7.** Счётчик задержки FR-6 по номеру сбрасывается по истечении окна наблюдения без попыток,
без действия оператора. *traced from BR-3, BR-8. Must. Волна 1.*

### Видимый барьер

**FR-8.** Запрос получает видимый барьер (капчу) перед отправкой; прохождение барьера человеком
приводит к отправке. Барьер применяется в двух случаях, с разной волной у каждого:
запрос из FR-3 (клиент не выполнил доказательство работы) - *Must, волна 1*; запрос, подпадающий
под правило подозрения FR-9, - *Should, волна 2*. *traced from BR-4.*

**FR-20.** Результат прохождения видимого барьера одноразов: предъявленный повторно - невалиден.
*traced from BR-4. Must. Волна 1* (вместе с запасным путём FR-3). Возведено из AC на гейте 3: без
одноразовости барьер обходится единственным прохождением, как и доказательство работы (FR-19).

**FR-9.** Правило подозрения вычисляется из признаков запроса и данных наблюдаемости FR-13; состав
и веса признаков задаются конфигурацией. *traced from BR-4, BR-7. Should. Волна 2.*

### Аварийный режим

**FR-10.** Дежурный включает аварийный режим одной операцией; режим применяет ужесточённый профиль
лимитов FR-4 и расширяет применение барьера FR-8. *traced from BR-5. Must. Волна 1.*

**FR-11.** Сервис уведомляет дежурного о превышении утверждённого порога расхода или темпа.
*traced from BR-5. Must. Волна 1.* Значение порога - Q-1, не закрыт источником.

**FR-12.** Аварийный режим снимается операцией дежурного, а при её отсутствии истекает
автоматически по таймауту и возвращает штатный профиль. *traced from BR-5, BR-8. Must. Волна 1.*

**FR-22.** Одновременные операции переключения режима дают определённое итоговое состояние, единое
для всех экземпляров сервиса. *traced from BR-5. Must. Волна 1.* Возведено из AC на гейте 3:
расхождение состояния между экземплярами означает, что часть трафика идёт по штатному профилю во
время аварийного режима - MOE BR-5 при этом выглядит достигнутой.

### Наблюдаемость

**FR-13.** Расход на SMS и конверсия регистраций наблюдаемы с разбивкой по сегментам признаков
запроса и по исходу каждого барьера (доказательство работы, лимит, задержка, видимый барьер).
*traced from BR-7. Must. Волна 1.*

**FR-14.** Время прохождения регистрации в штатном режиме наблюдаемо и разложено по шагам.
*traced from BR-7. Must. Волна 1.* Порождено решением оператора на гейте BRD: anti-metric без
наблюдаемости не работает как ограничитель.

### Обратимость

**FR-15.** Любое ограничение, наложенное сервисом на источник или номер (лимит, задержка, режим),
имеет конечный срок действия и снимается по его истечении без действия человека.
*traced from BR-8. Must. Волна 1.*

### Поведение при отказе антифрода

**FR-18.** При недоступности компонента антифрода (проверка доказательства работы, счётчики
лимитов, источник конфигурации) запрос на отправку обрабатывается **без проверки**: SMS
отправляется. Факт и длительность деградации фиксируются наблюдаемостью FR-13, дежурный
уведомляется тем же каналом, что и о превышении порога (FR-11).
*traced from BR-1, BR-2; порождено решением оператора D-6. Must. Волна 1.*
Сигнал - не украшение решения, а его условие: при fail-open расход в окне деградации не ограничен
ничем, и без уведомления дежурный узнаёт о нём из счёта провайдера.

### Управляемость

**FR-16.** Пороги, значения лимитов и состав правила подозрения изменяются через конфигурацию без
выкладки кода. *traced from BR-6. Should. Волна 2.*

**FR-21.** Значение конфигурации FR-16 проверяется при применении: некорректное (не того типа, вне
допустимого диапазона) отклоняется, и продолжает действовать прежнее. *traced from BR-6. Should.
Волна 2.* Возведено из AC на гейте 3: без проверки ошибка в конфигурации снимает лимиты быстрее,
чем их снял бы отказ антифрода, - и без сигнала, в отличие от FR-18.

**FR-17.** Изменение конфигурации FR-16 откатывается к предыдущему значению одной операцией.
*traced from BR-6. Should. Волна 2.* Порождено находкой единицы BR-6: ошибочный порог, выкаченный
без релиза, режет конверсию мгновенно, и путь отката источником не задан.

## Нефункциональные требования

**NFR-1.** Доказательство работы: время решения на типовом клиенте - не более 1.5 с (p95); время
серверной проверки - не более 5 мс (p99). *traced from BR-1 (незаметность, раздел 13 BRD).*
**[Assumption A-5]** - числа выведены составителем из «незаметно для человека», источником не
заданы.

**NFR-2.** Начальные значения лимитов FR-4 по каждой оси выводятся из перцентилей наблюдаемого
трафика (FR-13) и хранятся в конфигурации. До появления данных лимиты выставляются заведомо
широкими - отсекающими только явную массовость. *Решение оператора D-8.* **Следствие для порядка
работ:** FR-13 предшествует FR-4 внутри волны 1; обратный порядок даёт числа, взятые из воздуха.

**NFR-3.** Задержка FR-6: первый повтор доступен не позднее 60 с после предыдущей попытки; потолок
задержки - не более 15 мин; окно сброса FR-7 - 1 ч. **[Assumption A-6]** - числа выведены из «
настоящему пользователю хватает одного-двух повторов» (A-1 BRD), источником не заданы.

**NFR-4.** Доля настоящих пользователей, получающих видимый барьер FR-8, - **открытый вопрос Q-3**
источника; закрывается по данным FR-13 и до их появления числом не задана.

**NFR-5.** Время от операции дежурного FR-10/FR-12 до вступления режима в силу - не более 60 с.
*traced from BR-5 (MOE «минуты, не часы»).*

**NFR-6.** Данные FR-13 удерживаются не менее 90 дней. *traced from BR-7.* **Ограничение,
названное явно:** ретроспективы «до начала атаки» на уровне отдельных запросов не существует
(раздел 8 BRD), поэтому сравнительные MOE G-1 и G-2 измеримы только от момента включения
наблюдаемости, а не от доатакового состояния. Вопрос Q-9.

**NFR-7.** Изменение конфигурации FR-16 вступает в силу не более чем за 60 с с момента применения.
*traced from BR-6 (MOE «минуты»). Волна 2.*

**NFR-8.** Каждое изменение конфигурации FR-16 и каждое переключение режима FR-10/FR-12
фиксируются в журнале: кто, когда, прежнее и новое значение. *traced from BR-6, BR-5. Волна 2 для
конфигурации, волна 1 для режима.*

**NFR-9.** Номер телефона классифицируется как PII: в журналы, метрики и сегменты FR-13 попадает
только в необратимо преобразованном виде; сырой номер не покидает контур отправки. Удержание
событий антифрода - 90 дней (NFR-6), по истечении удаляются.
*traced from BR-9. Must. Волна 1.*

**NFR-10.** Привилегированные операции (включение и снятие режима FR-10/FR-12, изменение
конфигурации FR-16) разграничены по ролям: дежурный - режим, владелец продукта - пороги.
*traced from BR-9 (P-4 BRD - правило о полномочиях; требованием стало на гейте 2). Must. Волна 1.*

**NFR-11.** Ключ подписи челленджа доказательства работы хранится в секрет-хранилище и ротируется
без простоя эндпоинта. *traced from BR-9. Must. Волна 1.*

**NFR-12.** Доля успешных отправок для запросов, прошедших все барьеры, - не менее 99.5% за
календарный месяц (SLI: успешные отправки / запросы, прошедшие барьеры; SLO: 99.5%).
*traced from BR-2 (предсказуемость расхода) косвенно;* **[Assumption A-7]** - число выведено
составителем.

**NFR-13.** Добавка антифрода ко времени ответа эндпоинта отправки - не более 50 мс (p99), не
считая времени решения доказательства работы на клиенте. *traced from BR-1, раздел 13 BRD.*
**[Assumption A-5]**.

### Оси `nfr`, закрытые статусом `n/a`

| Ось | Статус | Причина |
|---|---|---|
| Multi-tenant, `tenant_id` в схеме | `n/a` | Сервис однотенантный, разделения арендаторов нет |
| IDOR, scope-проверка ресурса по ID | `n/a` | Эндпоинт анонимный и не отдаёт ресурс по идентификатору; читаемых объектов нет |
| Audit log в оценке хранилища | покрыт | NFR-8 + NFR-6; объём событий антифрода на порядок ниже бизнес-данных сервиса |

| `BR` | Раскрыто | Исход |
|---|---|---|
| BR-1 | FR-1, FR-2, FR-3, FR-18, FR-19, NFR-1, NFR-13 | покрыто |
| BR-2 | FR-4, FR-5, FR-18, NFR-2, NFR-12 | покрыто; NFR-2 привязан к FR-13 решением D-8 |
| BR-3 | FR-6, FR-7, NFR-3 | покрыто |
| BR-4 | FR-8, FR-9, FR-20, NFR-4 | покрыто; NFR-4 несёт незакрытый Q-3 источника |
| BR-5 | FR-10, FR-11, FR-12, FR-22, NFR-5, NFR-8 | покрыто; FR-11 несёт незакрытый Q-1 источника |
| BR-6 | FR-16, FR-17, FR-21, NFR-7, NFR-8 | покрыто, волна 2 |
| BR-7 | FR-13, FR-14, NFR-6 | покрыто; NFR-6 несёт ограничение базы измерения |
| BR-8 | FR-15, FR-7, FR-12 | покрыто |
| BR-9 | NFR-9, NFR-10, NFR-11 | покрыто; возведено снизу на гейте 2 (D-5) |

Нераскрытых `BR` нет; осиротевших `FR`/`NFR` нет.

**Как закрылась осиротевшая тройка.** NFR-9, NFR-10, NFR-11 не возводились ни к одному `BR`:
бизнес-уровень не выразил ни обращения с PII (система обрабатывает номера телефонов), ни
разграничения полномочий как требования (P-4 - правило о полномочиях, а не о поведении системы),
ни обращения с секретом, на котором держится FR-1. Дыра **бизнес-уровня**, найденная снизу,
предъявлена оператору на гейте 2 и закрыта требованием BR-9 (D-5), а не пометкой в наборе.

## Конфликты и пробелы, найденные на системном уровне

| # | Что | Статус |
|---|---|---|
| C-1 | Поведение при недоступности самого антифрода (проверка PoW, конфигурация, счётчики) не задано ни на одном уровне: отправлять без проверки (деньги текут) или отказывать (регистрации встают) | **закрыт** решением D-6 (fail-open) -> FR-18; цена решения названа в дельте |
| C-2 | FR-3 задаёт ветку «клиент не может выполнить PoW» допущением A-4 | **закрыт** решением D-7: ветка подтверждена оператором, A-4 перестало быть допущением составителя |
| C-3 | Волна 1 требует FR-8 как запасной путь FR-3, а сам FR-8 отнесён к волне 2 | **закрыт** решением D-7: барьер как запасной путь - волна 1, по правилу подозрения - волна 2 |
| C-4 | Сравнительные MOE G-1 и G-2 опираются на разные базы («до атаки» и «до внедрения мер»), а данных доатакового состояния на уровне запросов нет | **остаётся ограничением**: устранить нельзя - доатаковой ретроспективы не существует физически; отсчёт от включения FR-13, Q-9 |
