# Образцы выходных артефактов: прогоны нормативов этапов

Здесь лежат артефакты, порождённые прогонами process-skills этапов SDLC на тестовых задачах.
Назначение двойное: **ручная проверка** (норматив читается как текст, но работает ли он - видно
только по выходу) и **история** (правка норматива оценивается по разнице между прогонами до и
после неё).

Файл здесь - не постановка и не образец для копирования в проект. Задачи вымышленные, продукты не
существуют.

## Схема именования

`<дата>-<тема>-<режим>.md`, где режим - `interactive` (норматив собирал содержание вопросами) либо
`autonomous` (закрывал допущениями). Один и тот же прогон темы в двух режимах даёт два файла:
разница между ними и есть проверка того, что режим вообще на что-то влияет.

Прогон **конвейера** (несколько звеньев с гейтами между ними) даёт не файл, а папку
`<дата>-<тема>-pipeline/` с пакетом артефактов одной задачи и своим `README.md`: выход каждого
звена - отдельный файл, потому что предмет проверки здесь - стыки между звеньями, а не один
артефакт.

## Реестр прогонов

Версия записывается по каждому нормативу, участвовавшему в прогоне, а не только по узлу-дирижёру:
состав артефакта задаёт норматив этапа, и по версии дирижёра отставание состава не читается - BRD
прогона 2026-07-31 несёт 18 разделов, потому что §9.3.1 появился в `business-analysis` 1.3.0, уже
после прогона.

Прогон - снимок выхода на момент своей нормы, а не редактируемый документ: расхождение с текущей
нормой правится в норме и снимается новым прогоном, задним числом снимок не дописывается. Отсюда
колонка «Статус»: `актуальный` - снимок отвечает действующей норме и валидируется ею строго;
`исторический: <причина>` - норма после прогона изменилась, находки валидатора образцов по этому
пакету понижаются до предупреждений. Причина обязательна и называет, что именно разошлось: без неё
понижения нет и пакет судится как актуальный.

## Как читать образец

Ценность не в содержании задачи, а в том, что видно на выходе. Общее для любого прогона:

- **конфликты целей вскрыты явно**, а не усреднены - у каждого названа цена;
- **сравнительная MOE без базы измерения** порождает enabler-требование, а не остаётся
  декларацией;
- **незаполненный раздел закрыт статусом с причиной**, а не молчанием;
- **допущения отделены от ответов постановщика** - видно, где документ опирается на решение
  человека, а где на догадку составителя.

Для прогона конвейера к этому добавляется предмет проверки самих стыков (не перепрыгнут ли
уровень, доехала ли находка нижнего звена до верхнего) - см. `README.md` внутри папки прогона.

Прогон, где ничего из этого не видно, - сигнал, что норматив не сработал, а не что задача была
простая.
