# Системные требования: экспорт списка сотрудников в CSV из админ-панели

> Нумерация `FR`/`NFR` **локальная** (с `FR-001`/`NFR-001`): корпус документации проекта недостижим
> - прогон выполняется вне проекта, сверка с принятыми `FR`/`NFR` и ADR не проводилась
> (`unverifiable`, причина: "прогон вне проекта, корпус недостижим за пределами scratchpad"). При
> включении набора в корпус нумерацию перевести в сквозную и повторить сверку на дубли и
> противоречия с уже принятыми `FR`/`NFR`.

Источник: `docs/brd/employee-csv-export.md` (`BR-001`...`BR-010`, `status: approved`) +
`docs/brd/gate-log.md` (находки гейта N-1, N-2, N-3 и их разрешение). Материал использован целиком;
находки гейта учтены как директивы, не как открытые вопросы (см. раздел «Находки гейта»).

## 3. Функциональные требования (`FR`)

| ID | Требование | Приоритет | traced from | Метод верификации | Уровень |
|---|---|---|---|---|---|
| FR-001 | Система должна предоставлять пользователю с ролью HR / администратора кадров действие "выгрузить в CSV" для списка сотрудников, отображаемого в админ-панели | Must | BR-001 | Demonstration | Acceptance |
| FR-002 | Система должна включать в выгружаемый файл только поля: ФИО, должность, подразделение, рабочий email - и не должна включать иные поля карточки сотрудника | Must | BR-002 (P-1, P-2) | Test | System |
| FR-003 | Система должна разрешать выполнение действия "выгрузить в CSV" только пользователю с ролью HR / администратора кадров; для пользователя без этой роли операция должна быть недоступна независимо от способа вызова (не только скрытие элемента интерфейса) | Must | BR-003 (P-3) | Test | System |
| FR-004 | При каждой успешной выгрузке система должна создавать запись в журнале выгрузок с полями: автор (идентификатор пользователя), дата и время, число выгруженных записей, применённый фильтр | Must | BR-004 (P-4) | Test | System |
| FR-005 | Если запись в журнал выгрузок не может быть создана, система не должна выполнять выгрузку (не отдавать файл) и должна сообщить пользователю причину отказа | Must | BR-004 (P-5); сценарий S-6 | Test | System |
| FR-006 | Состав строк выгружаемого файла должен в точности совпадать с составом сотрудников, видимых пользователю на экране на момент выгрузки с учётом применённых им фильтров и сортировки - не шире и не уже | Must | BR-005 (P-7, A-3) | Test | System |
| FR-007 | По умолчанию система должна выгружать только действующих сотрудников; уволенные должны попадать в выгрузку только по явному выбору пользователя перед выгрузкой | Must | BR-006 (P-6) | Test | System |
| FR-008 | Система не должна включать в выгрузку данные сотрудника, уволенного более 3 лет назад (включительно) от даты выгрузки, даже если пользователь явно выбрал включение уволенных | Must | BR-006 (P-9) | Test | System |
| FR-009 | Имя выгружаемого файла должно включать дату и время выгрузки с точностью, исключающей совпадение имён при двух разных выгрузках одного пользователя в течение одного дня | Should | BR-010 (A-5); сценарий S-7 | Test | System |
| FR-010 | Если применённый фильтр даёт пустой результат (0 сотрудников), система должна явно сообщить пользователю, что выгружать нечего, и не должна формировать пустой файл | Should | BR-005; сценарий S-4 (собственная элаборация - см. «Собственные решения», п.3) | Demonstration | System |
| FR-011 | Если число сотрудников, подпадающих под фильтр, превышает пороговое значение (`NFR-001`), система не должна выполнять выгрузку частично и не должна отдавать усечённый файл; пользователю должна быть названа причина отказа и предложено сузить фильтр | Must | BR-005; сценарий S-5; находка N-2 | Test | System |
| FR-012 | Выгружаемый файл должен быть кодирован в UTF-8 с BOM и использовать `;` в качестве разделителя полей | Should | BR-007 (A-2) | Test | System |
| FR-013 | Запись в журнале выгрузок не должна содержать значения полей выгруженных сотрудников (ФИО, должность и т.д.) - только метаданные операции (автор, время, число записей, фильтр). Исключение: значения, введённые пользователем в фильтр, сохраняются в записи как есть, даже если являются персональными данными (решение постановщика на гейте Phase 3, находка M-4) | Must | BR-004 (P-8) | Inspection | System |
| FR-014 | Перед выполнением выгрузки система должна показывать пользователю число записей, которые будут выгружены, соответствующее текущим применённым фильтрам | Should | BR-005; раздел 14 BRD ("Предсказуемость объёма") | Demonstration | System |

|---|---|---|---|---|---|---|

| NFR-008 | Защита выгружаемого файла от внедрения формул (CSV formula injection) | значение поля, начинающееся с `=`, `+`, `-`, `@`, попадает в файл в виде, не интерпретируемом табличным редактором как формула | Must | BR-002, BR-007; введено на гейте Phase 4 (находка K-2) | Test | System |
| NFR-007 | Неухудшение отзывчивости списка сотрудников на экране | время отклика списка в админ-панели при появлении возможности выгрузки не ухудшается относительно замера до внедрения | Should | anti-metric BRD «скорость и отзывчивость самого списка на экране не ухудшается ради возможности выгрузки» | Analysis + Test (сравнение с базой до внедрения) | System |

## 5. Non-goals системного уровня

| BR | Основание |
|---|---|
| BR-008 (владелец, регламент просмотра журнала выгрузок) | организационное требование в части владельца и порядка просмотра: это не поведение системы. Находка N-1, принята дирижёром. **Уточнено на гейте Phase 3 (находка M-1):** `non-goal` покрывает не весь `BR-008` - срок хранения распался на две части, и системная часть («запись доживает до 6 месяцев») вынесена в `NFR-006`, иначе цель G-3 не валидируется ничем в наборе. Организационными остаются владелец, регламент просмотра и решение об удалении записей по истечении срока |
| BR-009 (замер базы трудоёмкости до внедрения) | организационная задача-замер, предшествующая и внешняя по отношению к системе; требований системы не порождает. Находка N-1, принята дирижёром |

## 9. Conflicts

Прямых противоречий между `FR`/`NFR` не найдено. Унаследованное из BRD напряжение `FR-001` (самостоятельность) vs `FR-003`/`FR-011` (ограничение роли, отказ при превышении порога) - уже разрешено на бизнес-уровне (находки C-1, R-3 BRD), на системном уровне повторно не открывается.

## 10. Собственные решения (assumptions) - выведены узлом, подтверждаются пакетом

| # | Решение | Из чего выведено | Цена ошибки, если неверно |
|---|---|---|---|
| 1 | `NFR-001`: порог синхронной выгрузки = 2000 записей | округление до верхней границы допущения A-4 BRD ("~2000"); точный замер отсутствует (Q-7, закрыт через `BR-009`, который не реализован до этой работы) | если фактический штат близок к порогу или превышает его - пользователи регулярно получают отказ (`FR-011`) и возвращаются к обходным путям (риск R-3 BRD); если порог завышен относительно реальной пропускной способности синхронного пути - риск деградации отклика. Требует пересмотра по факту замера `BR-009` |
| 2 | `NFR-002`: p95 <= 5с для синхронной выгрузки до порога | отраслевой ориентир приемлемого синхронного ожидания в вебе при отсутствии числового SLA от постановщика (раздел 12 BRD даёт только качественное "в рамках пользовательского ожидания") | завышенное требование вынуждает к преждевременному усложнению архитектуры (асинхронная генерация - явный non-goal раздела 3 BRD); заниженное - к ощущению "зависания" и, как следствие, недоверию к функции |
| 3 | `FR-010`: явный сигнал "нечего выгружать" вместо пустого файла | сценарий S-4 BRD называет желаемый эффект ("предотвращает ложный вывод «сотрудников нет»"), но не называет конкретный механизм | низкая: `BR-005` формально не нарушается ни при каком варианте реализации (0 видимых строк = 0 выгруженных строк); элаборация только усиливает бизнес-намерение сценария |
| 4 | `FR-008`: граница 3 лет трактуется включительно (уволенный ровно 3 года назад - недоступен) | P-9 BRD не задаёт правило округления границы | незначительная: затрагивает единичный пограничный день низкочастотного сценария |
| 5 | `NFR-003`: проверка роли выполняется на сервере, а не только скрытием элемента интерфейса | стандартная инженерная практика; UI-only проверка тривиально обходится и обесценивает `BR-003`/риск R-1 | по сути безальтернативное инженерное решение, а не бизнес-выбор; риск отсутствия - высокий, но это не решение постановщика, поэтому оформлено как собственное, а не как вопрос |
| 6 | `FR-004`: фильтр в записи журнала хранится в структурированном виде (поле+значение на момент выгрузки), не свободным текстом | MOE `BR-004` требует восстановимости фильтра по обращению; структурированная форма надёжнее произвольного текстового слепка | низкая: деталь схемы хранения, не меняет наблюдаемый результат для оракула `BR-004` |
| 7 | `FR-009`: точность метки времени в имени файла - до секунд | A-5 BRD говорит "дата и время" без точности; секундная точность выбрана как минимально достаточная против коллизий в рамках одного дня | низкая; теоретическая коллизия при двух выгрузках в одну секунду остаётся, риск признан пренебрежимым |
| 8 | Раздел «Integration» и security-подпункт IDOR/scope закрыты как `covered через унаследованный контроль`, а не как новая граница доступа | допущение A-3 BRD ("выгружается то, что на экране") явно переносит существующую границу видимости на экспорт, не создавая новую | если унаследованная граница видимости уже избыточна - дефект существующей системы, не этой работы; выгрузка его не создаёт, но и не устраняет |

## 11. Вопросы составителя - разрешение на гейте Phase 3

Четыре вопроса, поднятые составителем, разобраны дирижёром на гейте. Три закрыты как выводимые из
материала, один - как недостижимый факт; наверх постановщику не ушёл ни один.
