## requirements R/I

`FR-001..FR-020` и `NFR-001..NFR-011` - `docs/requirements/webhooks-requirements.md` (rev.4), каждое
с `traced from BR-NNN`, verification и уровнем проверки. `BR-NNN` в это поле не подставляются:
бизнес-цель с MOE реализуется не напрямую, ею раскрывается зона требований.

Предмет работы - платформа, оповещающая внешние системы (интеграторов) о событиях по подписке:
доставка оповещений с повторными попытками, управляющий API подписок, эксплуатация доставки,
объявленное обещание и переход с опроса, жизненный цикл контракта событий.

**Два контракта, которые зона 2 обязана спроектировать раздельно:** исходящий webhook (доставка
оповещения получателю: состав тела, метаданные доставки, признак подлинности) и управляющий API
подписок (создание, изменение, приостановка, удаление, замена секрета, перечни недоставленного и
пропущенного). Предметы разведены на уровне требований и не должны сливаться в одну спецификацию.

## acceptance criteria

`docs/stories/webhooks-stories.md` (rev.2): 29 историй по пяти epic'ам, AC в Given-When-Then, каждый
с меткой источника `[FR-NNN]`/`[NFR-NNN]`. Покрытие без сирот: все 20 `FR` и 11 `NFR` закрыты
минимум одной историей, историй без источника нет.

## success criteria

Числовые обещания (дом - требования, значения продублированы здесь как критерий «готово»):

- `NFR-001` своевременность: p95 <= 5 с от наступления события до отправки;
- `NFR-002` полнота: доля доставленного за сутки >= 99.5%; безвозвратно утраченных в пределах срока
  хранения - 0%;
- `NFR-003` глубина повторов: >= 8 попыток за 24 ч, интервал неубывающий;
- `NFR-004` ёмкость: 500 000 событий в сутки при 50 одновременно активных подписках без деградации
  `NFR-001`/`NFR-002`;
- `NFR-005` изоляция: отказ одной подписки не даёт измеримой деградации p95 остальных;
- срок хранения недоставленного и пропущенного - 7 суток (П-7);
- срок уведомления о прекращении поддержки - не короче 90 суток (П-11), с единственным исключением
  для меры безопасности (P-30).

## non-goals

- Внутренняя шина событий платформы - предмет внутренней архитектуры, не обещания интегратору.
- Гарантия порядка доставки - отклонена постановщиком (P-01) как непропорционально дорогая;
  получатель обязан быть устойчив к перестановке (П-2).
- Фильтры подписки по содержимому события - только по типу (P-06).
- Повторное проигрывание истории глубже срока хранения (7 суток).
- Полный снимок сущности в теле оповещения - раскрытие сужено до идентификаторов (P-02).
- Заведение подписок сотрудником поддержки по заявке - отклонено в пользу самообслуживания (P-03).
- Публичное предъявление интегратору способа счёта доли доставленного (P-20); внутреннее
  предъявление продукту и эксплуатации входит в охват (`FR-020`).

## key decisions

Полный перечень с отклонёнными альтернативами и ценой - в журнале. Задевающие дизайн напрямую:

| Решение | Существо | Следствие для зоны 2 |
|---|---|---|
| P-01 | at-least-once без гарантии порядка; недоставленное хранится отдельно | получатель обязан быть идемпотентен по идентификатору события (П-1); DLQ - часть выбранной гарантии, не опция |
| P-02, P-26, `BR-008` | тело оповещения раскрывает ровно пять полей: идентификатор события, тип, идентификатор сущности, момент, версия схемы | закрытый список ограничен **активной версией схемы**, нижняя граница версионно-независима |
| P-28, П-10 | согласования безопасности требуют любые данные, видимые получателю и несущие сведения о событии, сущности или интеграторе, независимо от носителя | признак содержания, а не место размещения: перенос поля в заголовок обязанности не снимает |
| P-29, П-11 | версия схемы охватывает контракт доставки целиком - и тело, и метаданные доставки | несовместимое изменение метаданных выпускается новой версией схемы наравне с изменением тела |
| P-30 | единственное исключение из 90 суток - мера устранения подтверждённой уязвимости либо компрометации механизма подтверждения подлинности; применимость оценивает безопасность | срочный выпуск без записи оценки безопасности исключением не покрыт |
| P-31 | объявление условий изменения контракта выведено из-под порядка среза объёма | документационный deliverable переживает полный срез epic'а E-4 |
| P-32 | конкурентное изменение подписки поверх устаревшего представления отклоняется с причиной; тихая потеря запрещена | **механизм выбирает зона 2** (условный запрос по версии, сериализация, иное) - требованием не назначен |
| P-33 | плановая и экстренная ветви уведомления действуют независимо на одном предмете | связывающего механизма нет; аудит фиксирует обе записи раздельно, без замещения |
| P-34 | недоступность канала уведомления не откладывает основное действие платформы; вырожденный знаменатель доли предъявляется явным признаком, не 0%/100% | уведомление - асинхронный побочный путь, не барьер |
| P-35 | до подтверждения владения новым адресом доставка идёт по прежнему подтверждённому | приостановка на время верификации отклонена |
| P-36 | удаление подписки удаляет накопленные записи недоставленного и пропущенного без восстановления | |
| P-37 | T-shirt-оценка epic'а после декомпозиции самостоятельной мерой не служит | действующая мера объёма - сумма story points, `docs/stories/webhooks-stories.md` раздел 8 |

Иллюстративные механизмы, принятые как допущения зоны 1 и **не связывающие** дизайн: подтверждение
владения адресом через challenge-response с токеном 24 ч (`A-RA4`), подпись HMAC-SHA256 над телом с
меткой времени и идентификатором доставки (`A-RA5`), окно перекрытия при смене секрета 24 ч
(`A-RA6`). Зона 2 вправе выбрать иной механизм, назвав решение и цену.

## constraints / risks

- Сроки и бюджет на этапе требований не назначены (P-09) - это принятое состояние, не пробел.
- Число интеграторов - десятки (P-04); ёмкость по `NFR-004`.
- Адрес получателя - недоверенный ввод: обязательна защита от обращения во внутренние и частные
  диапазоны, включая повторную проверку на момент отправки (`FR-011`, `SW-3`).
- Транспорт HTTP POST с JSON-телом задан допущением A1 как доменное значение вебхука; иные
  транспорты не рассматривались, потому что меняют контракт целиком.
- Риск C-11 (разрешён с ценой): выпуск по исключению с нулевым периодом сосуществования способен
  вызвать одновременное автоотключение всех подписок; следствие названо ожидаемым, не дефектом.
