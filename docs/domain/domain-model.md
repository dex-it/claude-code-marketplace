# Доменная модель каталога: словарь

**status:** review
**дата:** 2026-09-01
**назначение:** одно имя - один смысл во всех артефактах каталога. Термин, употреблённый в skill,
агенте, команде или нормативном документе, имеет ровно одну запись здесь.

**Как читать колонки.** «Дом» - файл, где живёт нормативное определение; словарь его не дублирует, а
адресует. Пустой дом означает, что термин в обиходе есть, а нормативного определения нет: такая
строка - долг, и она названа в разделе «Термины без дома». «Не путать с» отделяет термин от
соседнего, с которым его смешивают на практике.

**«Синонимы» - имена того же смысла, встречающиеся в корпусе**, с обязательной пометкой статуса:
`канон` - равноправное имя, употребляется наравне с основным; `к вытеснению` - имя, которое при
правке текста заменяется на основное. Пометка обязательна: колонка без неё узаконивает разнобой
вместо того, чтобы его закрыть. Имя вида-подмножества синонимом не является - норматив этапа есть
вид process-skill, а не второе имя для него.

Расхождения между носителями сведены не молча: то, что нельзя свести без решения, вынесено в раздел
«Расхождения, требующие решения» - в тексте словаря на их месте стоит ссылка на пункт `D-N`.

## Исполнение: как ведётся работа

| Термин | Значение | Синонимы | Дом | Не путать с |
|---|---|---|---|---|
| Движок | цикл доведения до конца: стоп-линия, леджер, режимы, возобновление, делегирование узлам. Агностично правило-тело: порядок зоны движок не несёт, но справочник зон для резолва голого входа принадлежит ядру (`references/zone-registry.md`) | - | `dex-sdlc:engine` | трек |
| Трек | порядок конкретной зоны: фазы, гейты, состав узлов, DoD; носитель - `dex-skill-<зона>-track` | трек зоны `канон` | `plugins/ai-sdlc/dex-sdlc/README.md`, «Три слоя» | движок, зона; дирижёр (исполнитель, который трек ведёт) |
| Узел | агент, которого вызывает трек либо другой агент: handoff приходит от вызывающей стороны, и выход читает она же, а не человек. Стандартный вход и выход обязательны всякому агенту; узла сверх того касается контракт стыка, и он pre-load'ит `node-contract` через `skills:` | - | `docs/AGENT_FRAMEWORK.md`, глоссарий; рантайм-контракт - `dex-skill-node-contract:node-contract` | сорт агента; агент, работающий по прямому вызову человека |
| Зона | область работ со своим порядком; носитель порядка - `dex-skill-<зона>-track`. Называется именем предмета (`требований`, `дизайна`), номера не несёт | - | `dex-sdlc:engine`, «Костяк» | уровень артефакта |
| Фаза | отрезок работы внутри носителя - трека или агента - как контракт: Goal / Input / Output / Exit criteria / Gate. Уровень называется явно: фаза трека, фаза агента | фаза трека `канон`; фаза агента `канон` | `docs/AGENT_FRAMEWORK.md`, глоссарий | этап (ось документа); шаг движка; процедура, шаг инструкции |
| Шаг движка | звено универсального цикла `dex-sdlc:engine` (1..8), проходится на каждой цели независимо от зоны. Имя отлично от фазы намеренно: цикл движка внешний и треку, и агенту | фаза движка `к вытеснению` | `dex-sdlc:engine`, «Универсальный цикл» | фаза трека; этап |
| Этап | звено оси информационного элемента: какой документ выпускается на этом месте конвейера и что в нём должно быть. Этапы зоны требований нумерованы 0-6 | звено конвейера `канон` | `docs/pipelines/analytics/NORMS.md`, раздел 2 | стадия (ортогональная ось, `D-5`); этап ГОСТ (подразделение стадии); фаза |
| Стадия | ось совмещения со стандартом: когда, какими порциями и с каким рубежом ведутся работы (8 стадий создания АС, ГОСТ Р 59793-2021). Оси этапа и стадии ортогональны, соответствие не «один к одному» | - | `docs/pipelines/analytics/NORMS.md`, раздел 1 | этап (`D-5`); принятость (`status` документа) |
| Handoff | передача работы между узлами: сигнатура в `description` + словарь полей выхода | стык `канон` | `docs/AGENT_FRAMEWORK.md`, «Inter-agent handoff»; поля - `node-contract` | вызов инструмента |
| Режим (`mode`) | `interactive` - оператор в петле; `autonomous` - его нет. Поля нет -> `autonomous`; `interactive` включает поле `mode` в handoff либо явное указание оператора, позиция вызова узлом не выводится. Вниз наследуется планкой эскалации, но не каналом: спавненный узел невыводимое возвращает вызвавшему, а не спрашивает оператора | - | `node-contract`, п.11 | право пропустить бизнес-решение |
| Планка эскалации | уровень, с которого невыводимое не закрывается собственным решением. Наследуется вниз при спавне вместе с `mode`: `interactive` у узла значит «не решай за оператора», а не «спроси оператора» | - | `node-contract`, п.11 | канал к оператору (планка едет вниз, канал нет) |
| Канал к оператору | возможность предъявить вопрос человеку и получить ответ в том же прогоне. Есть только у яруса, чьё тело исполняет главный цикл (вход вне стыка - `claude --agent` либо команда-обёртка); спавненному узлу не передаётся ни в каком режиме | - | `node-contract`, п.11 | планка эскалации; остановка оператора (событие, а не возможность) |
| Статус исхода (`status`) | `complete` / `blocked` / `partial` - первое поле выхода узла, машинно различимый исход | статус узла `канон` | `node-contract` | вердикт оракула; `status` в шапке документа - имя одно, носители разные, читается по носителю |
| Возврат наверх | передача нехватки вызывающему; для субагента это всегда оркестратор, а не пользователь | эскалация наверх `канон` | `docs/AGENT_FRAMEWORK.md` | вопрос оператору |
| Стоп-линия | граница автономии по «обратимость x радиус действия»: необратимое или массовое (force-push в общую ветку, перезапись данных стенда, ротация секретов) требует подтверждения даже в `autonomous`; обратимое точечное идёт без спроса | - | `dex-sdlc:engine`, «Стоп-линия» | остановка оператора (там развилка решения, здесь необратимость действия) |
| Дирижёр | исполнитель, ведущий порядок зоны: ставит метку на гейте, пишет журнал решений, выдаёт номера, считает ревизии. Через движок дирижёр ведёт трек зоны, вне движка это оркестратор или главный поток | - | `node-contract`, преамбула «Правило стыка» | трек (порядок, который дирижёр ведёт: сам трек не судит и метки не ставит); узел (исполняет одну работу); ревьюер (судит артефакт, зоной не ведёт) |
| Оркестратор | вызывающая сторона узла: та, что решила его запустить, читает его выход, выдаёт санкции (`approve` / `revoke` / `deploy`) и принимает возврат наверх. Роль относительна вызову, не сорт исполнителя: им бывает дирижёр зоны, другой агент или главный поток | вызывающая сторона `канон` | `node-contract`, преамбула «Правило стыка» | дирижёр (ведёт порядок зоны; всякий дирижёр - оркестратор своих узлов, обратное неверно) |
| Auto-ledger | состояние прогона движка вне рабочего дерева; живёт один прогон, контракт - буквальные строки статуса | - | `dex-sdlc:engine` | decision-log; прочие носители с корнем `ledger` (`D-7`) |
| `DoR` / `DoD` | условие старта и наблюдаемый выход единицы работы движка: `DoR` - что верно, чтобы начинать (входные артефакты взяли порог допуска, факты сверены, потребители разведаны, тест-инфра есть), `DoD` - чеклист наблюдаемых фактов, которыми работа закрыта | для `DoD`: `success criteria` `канон` - то же в поле handoff узла | `dex-sdlc:engine`, шаг 3 | порог допуска артефакта; `DoR` спринта в `dex-skill-agile`; `acceptance criteria` (продуктовый оракул, техническим критерием не поглощается) |
| Decision-log | журнал принятых решений в корпусе проекта, версионируется вместе с ним | журнал решений `канон` | `node-contract`, «Журнал решений» | auto-ledger |
| Журнал исполнителей | раздел `auto-ledger`, отвечающий на вопрос «кто работал»: строка *исполнитель · шаг · модель · исход · канал* за каждый привлечённый шаг, пишется в момент смены фазы и сводится в блок сдачи «Задействованы». Аудит исполнителей и стоимости; на вопрос «какие нормы в силе» не отвечает - это раздел `## Действующие нормы` | трейл `к вытеснению` | `dex-sdlc:engine`, `references/ledger-and-recovery.md` | decision-log (что решили, а не кто делал); раздел действующих норм |
| Graceful degradation | продолжение работы по запасному пути с называнием недоступности в выходе; проверку не отменяет | - | `node-contract` | молчаливый пропуск шага |

## Суждение: чем меряется качество

| Термин | Значение | Синонимы | Дом | Не путать с |
|---|---|---|---|---|
| Оракул | skill вида `{тип}-quality`, судящий готовый артефакт названного типа и дающий вердикт | - | реестр «тип -> оракул» в `node-contract` | ревьюер-агент; норматив этапа (держит состав, не содержание) |
| Судья | тот, кто может проверить утверждение об артефакте: человек либо инструмент. Требование к нему задаёт предмет суда - проверенность судит тот, кто не писал артефакт; принятость - тот, у кого есть полномочие (оператор либо оркестратор с санкцией `approve`) | проверяющая сторона `канон` | `node-contract`, п.7; предметы суда - `docs/pipelines/analytics/NORMS.md`, раздел 6 | автор (свой артефакт не судит); оракул (инструмент суда, не его субъект) |
| Вердикт | исход суда над артефактом: `passed` / `failed` / `unverifiable`; едет в записи `quality-checks` | - | `node-contract`, п.7 | статус исхода узла |
| Ревизия | состояние судимого между двумя судами: круг суда над артефактом или MR (R1 - первый суд, дальше суды после правок). Номер ведёт судящая сторона, а носитель номера задаёт дом - запись метки плюс шапка артефакта в зонах, счётчик трека на ревью MR. Потолок - три ревизии на артефакт внутри зоны, пять на ревью своего MR внешним ревьюером | круг правок `к вытеснению`; раунд `к вытеснению` | `node-contract`, `references/quality-and-review.md` разд. 9; для ревью MR - `dex-skill-followup-track:followup-track` | версия судимого текста или кода (SHA, снимок): она вторая половина значения поля `revision`, но не сама ревизия (`D-6`) |
| Гейт | условие перехода к следующей фазе; hard - блокирует, soft - фиксирует и пропускает. Исполняет инструмент, человека не требует | - | `docs/AGENT_FRAMEWORK.md`, глоссарий | остановка оператора |
| Остановка оператора | точка маршрута зоны, где работа ждёт решения человека, потому что цена ошибки лежит вне артефакта; в `autonomous` неисполнима - развилка едет наверх | - | `docs/AGENT_FRAMEWORK.md`, глоссарий; назначает трек зоны | гейт качества |
| `quality-checks` | метка `{artifact, check, verdict, revision}`, которую ставит судья - узел, не писавший артефакт | метка качества `канон` | `node-contract`, п.7 | самопроверка составителя |
| `self-check` | самоконтроль автора перед сдачей: какой оракул прогнан по своему артефакту и что по его находкам починено. Вердиктом не является | - | `node-contract`, словарь полей | `quality-checks` (её ставит судья, не автор) |
| `pending-judgement` | ожидаемая, но не состоявшаяся проверка, объявленная автором до суда: `{check, reason, by: author}` | - | `node-contract`, словарь полей | `unverifiable` (вердикт судьи, а не заявка автора) |
| Проверенность | прогнан ли оракул типа: запись `quality-checks` с `verdict` | - | `docs/pipelines/analytics/NORMS.md` | принятость |
| Принятость | `status` документа: `draft` -> `review` -> `approved` -> `archived`; судит сторона с полномочием | - | `docs/pipelines/analytics/NORMS.md` | проверенность; статус исхода узла |
| Порог допуска | проверяемое условие на входных артефактах узла: запись `quality-checks` с `verdict: passed` по типу, плюс `status: approved` для BRS и ADR; оракула для типа нет -> `unverifiable` с причиной и заполненный состав | - | `node-contract`, п.5 | принятость; `DoR` единицы работы; порог достаточности |

## Принятые решения по расхождениям

Пункты `D-1..D-6`, `D-8` и `D-9` закрыты; записи оставлены, потому что называют, что именно было
сведено и куда смотреть при следующем употреблении термина.

**`D-1`. Зона и уровень артефакта - разные ряды; нумеруется только уровень.** Зоны называются именем
предмета (`зона требований`, `зона дизайна`), номер зоны изъят из нормативных текстов. Дом
определения - `dex-sdlc:engine`, раздел «Костяк». Исторические коды прогонов `Z1-*` / `Z2-*` и имена
файлов кейсов в `tests/` сохранены: это идентификаторы записей журнала, а не термины; легенда - в
`tests/README.md`.

**`D-2`. Узел - роль агента в цепочке, не сорт агента.** Узлом агент становится там, где его вызывает
трек или другой агент, передавая handoff, и его выход читает вызывающий, а не человек. Граф
потребителей открыт - агенты собираются в цепочку произвольно, поэтому узловость это способность, а
не сегодняшний вызов: «не назван ни в одном маршруте» не означает «не узел». Прежний проверяемый
признак («назван в маршруте либо спавнится другим агентом») снят замером 01.09.2026: ему не отвечает
заметная часть агентов, причём строгое и широкое чтение дают разные списки - «спавнится» читается и
с вызовом командой, и без него. Расхождение двух прочтений одного признака - сам по себе аргумент
против него; каталог по нему не строился ни при одном из прочтений. Стандартный вход и выход обязательны всякому агенту и узла не определяют;
pre-load `node-contract` через `skills:` несут все агенты каталога - контракт стыка исполняет сам
агент, а не вызывающий, и присутствие pre-load держит правило `frontmatter-skills-missing`.
Дом - глоссарий `docs/AGENT_FRAMEWORK.md`.

**`D-3`. Гейт и остановка оператора - разные вещи.** Гейт исполняет инструмент и человека не
требует; остановку назначает трек зоны там, где цена ошибки лежит вне артефакта, и в `autonomous`
она неисполнима. Оба термина определены в глоссарии `docs/AGENT_FRAMEWORK.md`.

**`D-4`. Судья - один термин; различается предмет суда, а не природа судьи.** Судить может и человек,
и инструмент: принятость поднимает оператор либо оркестратор с санкцией `approve`. Требование к судье
задаёт предмет - проверенность судит тот, кто не писал артефакт, принятость - тот, у кого есть
полномочие. Дом - `node-contract` п.7, предметы суда - `docs/pipelines/analytics/NORMS.md` раздел 6.

**`D-5`. Этап и стадия - ортогональные оси; имя «этап» остаётся за нашей.** Стадия нормирует, когда и
с каким рубежом ведутся работы (ГОСТ Р 59793-2021), этап - какой документ выпускается (15289 /
29148). Соответствие не «один к одному»: этап 3 отображается в стадии 4-5, этап 5 - в стадию 3 и в
7.6/7.8, а порядок осей не совпадает (этап 0 идёт в стадию 2, этап 1 - в стадию 1). Внутри ГОСТ слово
«этап» означает подразделение стадии - в цитатах стандарта оно помечается «этап ГОСТ», чтобы чужой
смысл не читался как наш. Дом - `docs/pipelines/analytics/NORMS.md`, разделы 1-2.

**`D-6`. Круг суда над артефактом называется ревизией на всех уровнях.** Имена «круг правок» и
«раунд» вытесняются. Версия судимого текста или кода ревизией не называется: в поле `revision` она
вторая половина значения (номер ревизии плюс указатель на судимое), в прозе - SHA либо снимок.
Носитель номера различается по дому - запись метки плюс шапка артефакта в зонах, счётчик трека на
ревью MR, - и это два носителя одного термина, а не два термина: механику несёт дом, значение здесь.
Дом - `node-contract`, `references/quality-and-review.md` разд. 9.

**`D-8`. Замечание и находка - один предмет на двух сторонах стыка, оба имени законны.** Входящий
claim ревьюера до сверки с кодом зовётся замечанием, после сверки становится находкой либо
отклоняется с уликой; замена «замечания» на «находку» стёрла бы границу, на которой стоит фаза
классификации `followup-track`. Поэтому синоним помечен `канон`, а не `к вытеснению`: имя выбирается
по стороне стыка, и обратное употребление (называть находкой непроверенный claim) - дефект.

**`D-9`. Ось - родовой термин, виды не сводятся друг к другу.** Ось ревью берётся из закрытого
перечня носителя (шесть обязательных у артефакта каталога, по характеру diff у MR), ось решения
называется при разборе и из перечня не берётся. Одно слово на оба вида законно, потому что вид
всегда назван рядом; голая «ось» в нормативном тексте - дефект формулировки.

## Расхождения, требующие решения

**`D-7`. Система носителей с корнем `ledger` не сведена.** Их три - `auto-ledger` (состояние цели у
движка), `feature-ledger` (состояние прогона зоны требований), ledger оркестратора (прогресс цепочки
узлов), - и они расходятся по границам, месту хранения и писателю; Boundaries трека требований при
этом прямо запрещают носитель, который конвейер той же зоны предписывает. Родовой термин и строки на
каждый носитель заводятся по итогам ревью:
[issue #230](https://github.com/dex-it/claude-code-marketplace/issues/230).

## Термины без дома

Употребляются в артефактах, нормативного определения нет. Строка закрывается либо заведением дома,
либо признанием термина обиходным и изъятием из нормативных текстов.

| Термин | Где употребляется | Чем закрывается |
|---|---|---|
| `ledger` (родовой) | движок, конвейер требований, оркестраторы цепочек | `D-7`, ревью системы носителей |
| Прогон, дельта-прогон | треки зон, движок, реестр прогонов `tests/` | дом у трека зоны либо признание обиходным |
| Составитель | реестр «тип -> оракул», треки зон | дом в `node-contract` рядом с судьёй: составитель - автор артефакта и свой судить не может |
| Потребитель | пороги допуска, реестр оракулов, конвейер требований | дом в `node-contract`: сторона, читающая артефакт как вход своей работы |
| Приёмник | стыки узлов | сведение с «потребитель» либо изъятие |
| Конвейер | зоны, `docs/pipelines/` | дом в `NORMS.md` рядом с этапом |
| Контейнер | конвейер требований (BRD, файл сценария, SRS, story) | дом в `PIPELINE.md`, раздел о классах и контейнерах |
| Класс единицы | конвейер требований (`BR` / `UC` / `FR` / `NFR` / story) | дом в `PIPELINE.md` |

| Род изменения | ревизия, правка принятого | дом в `references/quality-and-review.md` разд. 9 |
| Фальсификация | ревьюеры, диагносты, security | дом в skill доказательности ревью |
