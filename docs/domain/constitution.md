# Конституция каталога: инварианты и сквозные меры

**status:** review
**дата:** 2026-08-22
**назначение:** нормы, действующие поверх любой правки каталога, независимо от фичи и зоны.
`INV-NNN` - инвариант: утверждение, истинное во всех состояниях корпуса; его нарушение - дефект, а
не компромисс. `NFR-P-NNN` - сквозная мера качества артефакта с методом проверки.

Единицы этого документа выводятся из целей `docs/product/brd.md` и из уже принятых норм каталога -
у каждой названы источник и метод проверки. Нормативный текст самих норм здесь не повторяется:
источник - дом, эта запись - обязательство.

## Инварианты

**INV-001. Один факт живёт в одном нормативном доме; остальные носители ссылаются.**
- источник: `.claude/rules/docs-changes.md`; `traced from` BR-002
- проверка: перед добавлением правила - поиск по `docs/`, `CLAUDE.md`, `.claude/rules/`; найденная
  копия сводится к ссылке. Ручная (👁).

**INV-002. Нормативная формулировка читается одним способом.**
- источник: `CLAUDE.md`, «Формулировка правила / ловушки / фазы должна быть однозначной»;
  `traced from` BR-009
- проверка: «может ли добросовестный исполнитель прочесть это так, что правило к его случаю не
  относится или противоречит соседнему?» - если да, единица не готова. Ручная (👁).

**INV-003. Уход от проверки закрывается явным статусом с причиной, не молчанием.**
- источник: `CLAUDE.md`, «Формулировки фаз / гейтов / правил»; словарь статусов - `node-contract`;
  `traced from` BR-005, BR-006
- проверка: в отчёте прогона у каждой непройденной проверки стоит `n/a` + причина, `unverifiable`
  либо `contradicted`. Ручная (👁).

**INV-004. У каждой ветки правила есть терминал.**
- источник: `CLAUDE.md`, признаки лазейки («если X -> Y» без «иначе -> что»); `traced from` BR-005
- проверка: ветвление без названного исхода на второй ветке - дефект ревью. Ручная (👁).

**INV-005. Обязательный шаг оставляет продукт в выходе.**
- источник: норма выведена из практики - безупречно сформулированный шаг без требования предъявить
  его продукт пропускается молча и пропуск ненаблюдаем; `traced from` BR-005
- проверка: у каждого mandatory-шага в агенте назван артефакт или строка отчёта, по которой видно,
  что шаг исполнен. Ручная (👁).

**INV-006. Утверждение о платформе, библиотеке или валидаторе несёт источник и дату сверки.**
- источник: `.claude/rules/docs-changes.md`; анти-паттерн №11 `docs/SKILL_FRAMEWORK.md`;
  `traced from` BR-008
- проверка: ссылка + дата рядом с утверждением либо пометка «не задокументировано»; заявление «это
  проверяет валидатор» сверяется с кодом `tools/validate-*.js`, ручная проверка помечается 👁.
  Частично автоматическая (`npm run validate:agents` ловит неполный fact-check каскад), остальное
  ручное.

**INV-007. Композиция skills существует только как предписание исполнителю.**
- источник: `CLAUDE.md`, «Механизмы композиции»; `traced from` BR-002
- проверка: формулировка «загружает / активирует / подключает» без «предписывает вызвать `Skill`» -
  ложь и переписывается; упоминание имени skill в теле другого skill - сноска, не механизм.
  Ручная (👁).

**INV-008. Правило артефакта обобщено: имён конкретного продукта в нём нет.**
- источник: `CLAUDE.md`, «Skill = обобщённое правило»; анти-паттерн №10 `docs/SKILL_FRAMEWORK.md`;
  `traced from` BR-009
- проверка: «убери имена проекта - правило всё ещё читается и применяется?». Имена API стека в
  стековом skill допустимы, имена продукта - нет. Ручная (👁).

**INV-009. Установленный набор замкнут: у каждого установленного агента установлены skills, которые
он грузит.**
- источник: `CLAUDE.md`, «Состав bundle живёт в `bundle.json`»; `traced from` BR-001
- проверка: `npm run validate:bundles` (by-stack skills из проверки исключены). Автоматическая.

**INV-010. Адрес документа каталога из тела плагина - абсолютный URL канала поставки.**
- источник: `CLAUDE.md`, «Адрес документа каталога из тела плагина»; `traced from` BR-001
- проверка: отступы вверх ловятся поиском по телам плагинов; существование цели и якоря сверяется в
  снапшоте канала поставки. Ручная (👁), поиск скриптуем.

**INV-011. Числа состояния каталога в нормативный текст не попадают.**
- источник: `.claude/rules/docs-changes.md`; `traced from` BR-008
- проверка: количество плагинов, агентов, строк - либо без числа, либо там, где число бампается
  вместе с состоянием. Ручная (👁).

**INV-012. Метку качества артефакта ставит судья, не его автор.**
- источник: `node-contract`, п.7; `traced from` BR-006, BR-010
- проверка: запись `quality-checks` несёт того, кто судил; самопроверка составителя меткой не
  является. Ручная (👁).

**INV-013. Решение, принятое за отсутствующего человека, объявлено явным пунктом.**
- источник: `node-contract`, п.5 («решение без следа = тихое допущение, запрещено и в
  `autonomous`»); `traced from` BR-004
- проверка: в выходе прогона есть список принятых решений с основанием; пустой список при наличии
  развилок - дефект. Ручная (👁).

**INV-014. Апрув не выдаётся себе.**
- источник: `docs/pipelines/analytics/PIPELINE.md`, разведение гейта качества и остановки оператора;
  `traced from` BR-007
- проверка: фаза, закрывшаяся без вопросов, не помечается как согласованная стороной; принятость
  (`status: approved`) ставит уполномоченная сторона, а не инструмент. Ручная (👁).

**INV-015. Апрувом замораживается то, что дорого переделать, а не то, что дёшево перегенерировать.**
- источник: принцип, принятый при разборе модели артефактов - апрув нужен там, где цена ошибки
  уходит за пределы артефакта; `traced from` BR-007
- проверка: у каждой остановки оператора названа цена ошибки вне артефакта; остановка без такой
  цены снимается. Ручная (👁).

**INV-016. Линейность порядка работ - ограничение конкретного трека, а не свойство процесса.**
- источник: принцип, принятый при разборе модели артефактов - линейная цепочка импортирована из
  человеческой практики и сама по себе нормой не является; `traced from` BR-004, BR-007
- проверка: возврат к предыдущему артефакту не трактуется как отказ прогона и не требует нового
  апрува уже принятого; трек, требующий строгого порядка, называет причину. Ручная (👁).

**INV-017. Число вопросов к оператору - измеряемая величина, а не признак тщательности.**
- источник: принцип, принятый при разборе модели артефактов; `traced from` BR-007
- проверка: рост числа остановок в треке обосновывается невыводимостью пунктов, а не полнотой
  разбора; выводимое предъявляется списком, не вопросом. Ручная (👁).

**INV-018. Смена имени или удаление артефакта идёт версией, а не молчаливой заменой.**
- источник: `.claude/rules/plugin-changes.md`; `CLAUDE.md`, «Имя агента»; `traced from` BR-001
- проверка: переименование агента - мажорный бамп; версия плагина и запись в `marketplace.json`
  синхронны. Частично автоматическая (`npm run validate`), синхронность версий - ручная (👁).

**INV-019. Продолжение прерванной работы идёт из записанного состояния, не из памяти и не из
сводки.**
- источник: `dex-sdlc:engine`, `P-auto-ledger` и раздел «Возобновление»; `traced from` BR-012
- проверка: у узла, который может быть прерван, назван носитель состояния и процедура подъёма
  действующих норм; продолжение, опирающееся на сводку или память, - дефект. Ручная (👁).

## Сквозные меры качества

**NFR-P-001. Пунктуация артефакта - ASCII.**
- источник: `CLAUDE.md`, «Пунктуация в артефактах»
- метод проверки: поиск Unicode-пунктуации в тронутом файле; единица миграции - файл целиком,
  сквозного прохода по каталогу не делаем. Исключения перечислены в источнике.

**NFR-P-002. Размер артефакта - в пределах потолка своего типа.**
- источник: потолки - `docs/SKILL_FRAMEWORK.md` («Размер skill»), `docs/COMMAND_FRAMEWORK.md`
  («Размер»), `.claude/rules/docs-changes.md` (ориентир объёма файла правил)
- метод проверки: валидаторы `tools/validate-*.js` по своему типу. Число здесь не дублируется -
  дом один.

**NFR-P-003. `description` артефакта работает как поле срабатывания, а не как пересказ тела.**
- источник: `docs/SKILL_FRAMEWORK.md`; для агента - сигнатура handoff, `docs/AGENT_FRAMEWORK.md`
- метод проверки: у skill - технология и аспекты плюс формулировки запроса разработчика; у агента -
  что принимает и что отдаёт. Валидатор проверяет наличие и форму, соответствие смыслу - ручное (👁).

**NFR-P-004. Артефакт перед сдачей прогоняется через `optimize-for-llm`.**
- источник: `CLAUDE.md`, «Формулировки в артефактах пишутся для LLM»
- метод проверки: прогон скилла на изменённом артефакте; режется подача, не нормативная сила -
  статусы, лазейки и обоснования сокращению не подлежат (`INV-003`).

**NFR-P-005. Изменение каталога проходит пять осей ревью артефакта.**
- источник: `CLAUDE.md`, «Ревью артефактов»; дом механики - `dex-skill-artifact-review:artifact-review`
- метод проверки: соответствие фреймворку, fact-check, полезность, лаконичность, сверка с гайдом
  объявленной модели; «всё валидно по фреймворку» ревью не закрывает.

**NFR-P-006. Правка проходит валидаторы до коммита.**
- источник: `.claude/rules/plugin-changes.md`
- метод проверки: `npm run validate`. Автоматическая; что валидаторы не закрывают - перечислено в
  источнике и проверяется вручную (👁).

**NFR-P-007. Язык артефактов - русский.**
- источник: сложившаяся норма каталога; открытый вопрос OQ-2 в `docs/product/brd.md`
- метод проверки: ручная (👁). Пока вопрос открыт, мера действует как есть.

**NFR-P-008. Каркас процесса не вытесняет материал задачи из окна.**
- источник: `traced from` BR-009, anti-metrics BRD
- метод проверки: `unverifiable` - базы измерения (доля окна под каркасом) в каталоге нет,
  заведение базы - открытый вопрос OQ-1. Мера объявлена, чтобы рост нормативного текста не проходил
  как безусловное улучшение; численный порог появится вместе с базой.
