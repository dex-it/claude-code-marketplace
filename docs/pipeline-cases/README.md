# Кейсы прогона конвейеров: регрессия поведения, а не текста

Кейс - воспроизводимый вход в конвейер плюс перечень того, что обязано произойти с контуром.
Проверяется поведение (где встал, с каким статусом, что попало в метку), не содержание артефакта:
текст порождается моделью и от прогона к прогону не совпадает, поэтому эталона текста здесь нет и
быть не может.

Отношение к соседнему дому: [`docs/sample/`](../sample/README.md) держит **снимки выходов** - что
получилось на конкретную дату при конкретных версиях нормативов; снимок стареет вместе с нормой.
Кейс держит **вход и инварианты** - он не стареет, пока не изменилась сама норма, и именно он
гоняется после правки. Прогон кейса может дать снимок, снимок кейсом не является.

## Из чего состоит кейс

| Поле | Что задаёт |
|---|---|
| `вход` | класс входа + сам материал (тема, идея, чужой артефакт, возврат снизу) |
| `режим` | `autonomous` или `interactive`; для `interactive` - кто исполняет канал оператора |
| `среда` | что доступно: корпус проекта, нормативы этапов, оракулы; чего намеренно нет |
| `ожидается` | где контур обязан встать и с каким `status` |
| `инварианты` | проверяемые утверждения о выходе - каждое либо истинно, либо кейс провален |
| `запрещено` | исходы, наличие которых проваливает кейс независимо от остального |
| `покрывает` | какие нормы кейс держит: без этой строки кейс нечем защитить при чистке |

Инвариант формулируется так, чтобы его проверяли по выходу, а не по впечатлению. Годится: «в
`quality-checks` есть запись с `check: requirement-set-quality` и `verdict` из закрытого перечня».
Не годится: «BRD хорошего качества».

## Ось «запрещено» важнее оси «ожидается»

Конвейер ломается не тем, что выдаёт мало, а тем, что выдаёт гладко. Отсюда общий для всех кейсов
запрет, который не переписывается в каждом:

- `complete` поверх шага, который упёрся;
- проверка, закрытая молчанием, вместо статуса с причиной (`n/a`, `unverifiable`, `contradicted`);
- фактура, которой не было во входе, поданная как факт постановки, а не как помеченное допущение;
- апрув гейта, выданный самим контуром без оператора;
- пропуск уровня требований (`BR` -> stories мимо `FR`/`NFR`).

Кейс, прошедший «ожидается» и нарушивший «запрещено», считается проваленным.

## Как гонять

1. **Синхронизировать установку с рабочей копией.** Маркетплейс каталога указывает на директорию
   репозитория, но кеш установки сам не обновляется: без `claude plugin marketplace update
   dex-claude-marketplace` прогон проверяет ту версию, что осела в
   `~/.claude/plugins/cache/`, а не рабочую копию. Расхождение молчаливое - агент рассуждает по
   снятой норме и выглядит убедительно. Версию установленного узла фиксировать в результате
   прогона.
2. **Спавнить узел субагентом**, вход подавать по кейсу дословно. Отсебятина во входе делает
   прогон невоспроизводимым.
3. **Канал оператора держит вызывающий.** У субагента канала к человеку нет: апрув гейта приходит
   отдельным сообщением от того, кто прогон ведёт. Автоапрув запрещён нормой - кейс, где контур
   апрувит сам себя, провален.
4. **Сверить выход с инвариантами кейса**, каждый - явным «да / нет», без «в целом похоже».
5. **Результат прогона** - строка в журнале ниже. Артефакты, если они интересны как форма, уходят
   пакетом в `docs/sample/` по тамошней схеме.

Недетерминированность лечится повтором: кейс, прошедший один раз из трёх, не пройден - он
нестабилен, и нестабильность сама по себе находка.
