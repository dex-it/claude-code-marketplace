Есть ТЗ или тикет. Нужен код в стиле проекта, тесты и локальные коммиты, без push.

| | |
|---|---|
| **Ставлю** | `dotnet-developer` или `ts-fullstack` |
| **Запускаю** | `/dex-implement:implement`, затем `/dex-test:test` |

```bash
./install-bundle/install-bundle.sh dotnet-developer     # или ts-fullstack
```

:::caution[Нужен кодер вашего стека]
Команды сами не пишут код: они вызывают специалиста под ваш стек. Если стек определён, а кодера или тестописателя под него не установлено, работа остановится статусом `blocked` с именем недостающего плагина. В каталоге они есть для .NET и TypeScript; бандлы `dotnet-developer` и `ts-fullstack` их ставят.
:::

## Реализация

```text
/dex-implement:implement "экспорт сделок в CSV с учётом фильтров списка" develop feature/csv-export
```

Аргумент - ТЗ или ссылка на тикет; необязательно - базовая и feature-ветки. Стек определяется по манифесту затронутой папки.

1. Команда сама выводит из ТЗ критерии успеха и границы, делает инвентаризацию архитектуры по коду и составляет план правок. План она проверяет оракулом качества плана.
2. По команде `делай` кодер вашего стека вносит правки по одной, с проверкой после каждой.
3. Тесты пишет тестописатель стека. ADR появляется, когда решение выходит за пределы модуля.
4. Перед сдачей идёт саморевью дельты. Финиш - локальные коммиты; push и MR отдельно.

## Тесты

```text
/dex-test:test src/Billing
```

Аргумент - путь или diff-scope; по умолчанию незакоммиченные и добавленные в индекс изменения ветки. Команда не запускает существующие тесты ради отчёта, а добирает покрытие по осям: happy-path, негатив, краевые значения, все ветки. Оси, которые остались незакрытыми, попадают в выход перечнем, а не молчанием.
