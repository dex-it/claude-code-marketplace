---
title: Отдать задачу целиком
description: Автономная работа dex-auto - подключить проект, поставить цель, получить коммиты с тестами и открыть PR.
---

Вы формулируете задачу, агенты проектируют, пишут код с тестами, ревьюят свою правку и записывают сделанное в документацию проекта. Готовность подтверждает прогон сборки и тестов, а не слово модели.

| | |
|---|---|
| **Ставлю** | бандл `auto` |
| **Запускаю** | `/dex-auto:onboard`, `/dex-auto:goal`, `/dex-auto:auto` |
| **Нужно** | `git` и `python3` в `PATH`; для PR или MR - `gh`, `glab` или MCP-сервер хостинга |

```bash
./install-bundle/install-bundle.sh auto
```

:::note
Ставьте бандл, а не плагин `dex-auto` отдельно: без skills своих агентов плагин запустится, но агент вернёт `blocked` или `partial`.
:::

## 1. Подключить проект (один раз)

В корне репозитория с чистым рабочим деревом:

```text
/dex-auto:onboard "CRM для отдела продаж: сделки, контакты, воронка"
```

Команда находит документацию проекта или разворачивает для неё раскладку, пишет по коду и описанию BRD продукта и ADR на решения, видимые в коде (оба со статусом `review`, то есть черновик), и дописывает в `CLAUDE.md` блок между маркерами: порядок работы, команды сборки и тестов, карту репозитория, запреты. Остальной текст файла она не трогает. Результат коммитится в текущую ветку; код существующего проекта не меняется, push не делается.

Затем прочитайте созданные документы и переведите принятые в `status: approved`: с этого момента они обязывают агентов.

## 2. Поставить цель

```text
/dex-auto:goal PROJ-123                    # тикет трекера (через его MCP)
/dex-auto:goal owner/repo#42               # GitHub issue
/dex-auto:goal docs/spec/export.md         # файл спецификации
/dex-auto:goal "экспорт сделок в CSV ломает кириллицу"
```

Команда пишет цель: что должно стать иначе, критерий «готово» в проверяемой форме, границу «чего не трогаем» и вид - `feature` или `bugfix`. У каждого утверждения есть ссылка на источник или пометка «допущение». Что из источника и кода не вывести, команда спрашивает. Код она не трогает.

## 3. Разработка

Из своей ветки с чистым деревом:

```text
git switch -c feature/csv-export
/dex-auto:auto PROJ-123
```

- **feature**: проектирование, код с тестами, сборка и тесты (до трёх попыток), саморевью (серьёзные находки проверяет второй агент), правка по найденному.
- **bugfix**: сначала воспроизведение красным тестом и поиск первопричины, затем лечение причины и те же проверки.

Итог - локальные коммиты. После `complete` изменение поведения и принятые решения записываются в документацию проекта той же веткой и сверяются с кодом.

## 4. Открыть PR

```text
/dex-auto:auto PROJ-123 --pr
```

Флаг `--draft` открывает черновик, `--base develop` задаёт целевую ветку. Команда пушит ветку задачи и открывает PR с описанием из цели и прогона. Ревьюера она не назначает, merge остаётся за вами.

## Ревью через dex-auto

```text
/dex-auto:auto review owner/repo#7          # находки списком
/dex-auto:auto review owner/repo#7 --post   # и треды у строк MR
/dex-auto:auto review --local               # своя ветка до MR
```

Перед ревью чужого MR получите его ветку локально, например `gh pr checkout 7`: иначе ревью выйдет `partial`. Код MR команда не меняет, approve и merge не делает.

## Чем кончается прогон

Первая строка ответа называет исход. Что довести не удалось, названо статусом с причиной. Подробности и все флаги - в [README плагина на GitHub](https://github.com/dex-it/claude-code-marketplace/blob/main/plugins/auto/dex-auto/README.md).
