Есть идея, тема или чужой документ, а нужен набор, по которому разработчик не будет ничего додумывать.

| | |
|---|---|
| **Ставлю** | бандл `system-analyst` (или `product-manager`) |
| **Запускаю** | `/dex-business-analyst:feature`, затем `/dex-requirements-reviewer:feature-check` |

```bash
./install-bundle/install-bundle.sh system-analyst
```

## Собрать набор

```text
/dex-business-analyst:feature "личный кабинет клиента"
```

Аргументом может быть сырая тема, проработанная идея, путь к чужому документу, путь к уже реализованному коду без постановки либо правка принятого требования. Ветка выбирается по тому, насколько вход проработан.

Команда ведёт работу звено за звеном, не перепрыгивая:

| Класс | Что несёт |
|---|---|
| `BR` | цель стороны с мерой успеха |
| `UC` | сценарий: кто, при каких условиях, что происходит и что если не так |
| `FR` | правило: случай, субъект, наблюдаемый результат |
| `NFR` | мера с методом и условиями замера |
| `AC` | пример на конкретных данных, в историях |

В конце идёт проба готовности: отдельный агент читает набор как программист и показывает, что ему пришлось бы додумать.

## Что нужно от вас

Безусловная остановка одна: финальная приёмка набора. Апрув - явный ответ; молчание апрувом не считается. Бизнес-решения (объём, приоритет, нужность требования) принимаете вы. Если из принятого всё выводится, команда обойдётся без вопросов.

Результат помечается `complete` только когда остановка закрыта и открытых пунктов нет.

## Проверить набор

```text
/dex-requirements-reviewer:feature-check
```

Команда проверяет **свой** собранный набор: качество единиц и набора, готовность к разработке и две сверки - текста с тем, что судили, и требований с решениями оператора. Итог - перечень доработок, а не «принять или вернуть». Чужой документ проверяет другая команда: `/dex-requirements-reviewer:review-requirements`.

## Ограничения и частые ошибки

- **Молчание не апрув.** Без явного ответа на финальную приёмку результат не получит статус `complete`.
- **Своё и чужое проверяют разные команды.** `feature-check` судит набор, который собрали вы этой командой; чужой документ принимает `review-requirements`.
- **Бизнес-решения за вами.** Объём, приоритет и нужность требования команда не выбирает: что из принятого не выводится, она вернёт вопросом.
- **Звенья не перепрыгиваются.** Сколько звеньев пройти, зависит от проработанности входа: сырая тема идёт с начала, готовая идея - с середины.
