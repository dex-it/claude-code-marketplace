Нужно решить, как строить, и записать это так, чтобы решение можно было проверить: с альтернативами, компромиссами и планом.

| | |
|---|---|
| **Ставлю** | бандл `architect` |
| **Запускаю** | `/dex-architect:design` |

```bash
./install-bundle/install-bundle.sh architect
```

## Шаги

Бизнес-задача в свободной форме:

```text
/dex-architect:design "нужен сервис уведомлений: письма, push, повторы при сбое"
```

Либо путь к принятым требованиям (`FR` и `NFR` системного уровня, истории). Без аргумента команда первым сообщением запросит постановку.

## Что вы получите

- Требования с оценкой нагрузки (capacity) таблицей.
- Дизайн-документ: сравнение с готовыми решениями, минимум две жизнеспособные альтернативы с диаграммами, решение с компромиссами (CAP и PACELC), разбор хранилища, API, кэша, отказов, безопасности и наблюдаемости. Решение принимает специалист-архитектор, а не сама команда.
- План реализации файлом: от каркаса через вертикальные срезы к масштабированию.
- ADR, спецификации API и диаграммы там, где решение трудно отменить или пересекается граница контракта.
- Приёмка: `design-reviewer` судит и дизайн, и план. Пока оба вердикта не `passed`, результат считается не сданным.

Если вход .NET-проект, подключается специалист `architect-dotnet`.

:::note[Когда команда остановится]
Бюджетная рамка и приоритет между конфликтующими нефункциональными требованиями - вопрос к вам, работа встаёт до ответа. Выбор между технически равными альтернативами команда предъявит и пойдёт дальше.
:::
