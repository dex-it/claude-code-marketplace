title: Проверить свою ветку перед push
description: Саморевью ветки с реальным прогоном сборки и тестов - чеклист правок до push.
---

Вы закончили работу в ветке и хотите поймать то, что иначе поймает CI, ревьюер или прод.

| | |
|---|---|
| **Ставлю** | бандл `code-review` (подходит для любого языка) |
| **Запускаю** | `/dex-self-reviewer:self-review` |
| **Нужно** | git-репозиторий с вашей веткой |

## Шаги

```bash
./install-bundle/install-bundle.sh code-review
cd путь/к/вашему/проекту
claude
```

В сессии:

```text
/dex-self-reviewer:self-review
```

Необязательный аргумент - базовая ветка для сравнения. Без него база определяется по upstream: `origin/main` или `origin/develop`.

## Что произойдёт

- Команда сравнит ветку с базой. Закоммиченные, добавленные в индекс и незакоммиченные изменения ревьюятся наравне.
- Она реально запустит сборку, проверку типов, линтер и тесты и покажет фактический вывод команд.
- Результат - чеклист правок до push, разделённый на блокеры, важное, замечания и мелочи. Находки помечены цветными метками.
- TODO, заглушки, моки в проде, отладочный вывод, `.only`, выключенные тесты и зашитые секреты - всегда блокер или важное.

Пока вы не сказали `делай`, рабочее дерево не меняется. Дальше цикл идёт командами:

| Слово | Что делает |
|---|---|
| `делай` | исправить пункт чеклиста |
| `ещё раз` | новый проход по дельте |
| `пушь` | push; разрешён только когда вердикт `APPROVE`, прогон зелёный и в чеклисте нет красных пунктов |

## Ограничения и частые ошибки

- **Прогон идёт у вас.** Сборка, типы, линтер и тесты запускаются на вашей машине, поэтому SDK и зависимости проекта должны быть установлены. Фактический вывод команд попадает в отчёт, а `пушь` разрешён только при зелёном прогоне.
- **База не определилась.** Если upstream не найден, передайте базу аргументом: `/dex-self-reviewer:self-review origin/develop`.
- **Незакоммиченное перед push.** Рабочее дерево с незакоммиченными правками команда сама не коммитит, не прячет и не сбрасывает: commit, stash или discard вы выбираете явно.
- **Править может только команда.** Специалисту-ревьюеру инструменты записи не выданы; правки идут по вашему `делай` в основной сессии.
- **Тип дефекта у находки.** Флаг `--classify` необязателен: с ним у каждой находки в строке появляется тип по схеме классификации. Без флага форма чеклиста не меняется.
