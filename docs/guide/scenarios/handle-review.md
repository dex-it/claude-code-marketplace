---

На ваш MR или PR пришли замечания. Нужно понять, какие из них справедливы, что править первым и как ответить.

| | |
|---|---|
| **Ставлю** | бандл `dotnet-developer` или `ts-fullstack`: в них есть кодер вашего стека |
| **Запускаю** | `/dex-review-planner:review-plan` |
| **Нужно** | `gh` или `glab` (либо MCP-сервер хостинга) |

## Шаги

```bash
./install-bundle/install-bundle.sh ts-fullstack      # или dotnet-developer
```

В сессии:

```text
/dex-review-planner:review-plan owner/repo#42
```

## Что произойдёт

- Команда читает все комментарии ревизии целиком, а не выборкой, и классифицирует их: что исправить, что уточнить, с чем можно не согласиться. Перед тем как снять замечание, она проверяет его чтением кода.
- Дальше идёт план правок с приоритетами P0-P3: файлы, радиус влияния и риск регрессии.
- По команде `делай` правки вносит кодер вашего стека. Замечания по безопасности идут не ему, а ревьюеру безопасности.
- По команде `отвечай` публикуются ответы в треды с sha исправления. Тред закрывается только после подтверждённого исправления.
- В конце повторное ревью дельты называет статус каждой находки прошлой ревизии. У каждой находки есть явный исход: исправлено, оспорено, уточнить или вне объёма.

:::note
Без кодера вашего стека правки не вносятся: команда остановится и назовёт недостающий плагин. План и разбор замечаний при этом остаются доступны. В каталоге кодеры есть для .NET и TypeScript.
:::
