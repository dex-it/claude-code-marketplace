Сайт собран на [Starlight](https://starlight.astro.build/) (Astro). Страницы - обычный Markdown в репозитории, а каталог плагинов строится из метаданных при каждой сборке.

## Где что лежит

| Путь | Что там |
|---|---|
| `docs/guide/` | Страницы сайта: Markdown и MDX. Правится руками |
| `site/` | Проект Starlight: конфиг, стили, компоненты, скрипт каталога, `package.json` |
| `site/site.config.mjs` | Адрес сайта (организация и имя репозитория), базовый путь и название бренда: единственное место, откуда их читают конфиг и проверка сборки |
| `site/scripts/build-catalog.mjs` | Генератор страниц каталога из `.claude-plugin/marketplace.json` и манифестов плагинов |
| `assets/` | Баннеры бренда: светлый для светлой темы, тёмный для тёмной |

Остальное содержимое `docs/` (фреймворки, протоколы, корпус) на сайт не попадает: сайт публикует только `docs/guide/`.

## Собрать локально

```bash
cd site
npm ci
npm run build       # собрать сайт в site/dist
npm run preview     # открыть собранное, с базовым путём /claude-code-marketplace/
npm run dev         # режим разработки
```

Если после правки конфига или стилей вид страниц не поменялся, удалите кэш Astro: `rm -rf .astro node_modules/.astro`.

`npm run build` сначала запускает генератор каталога, затем сборку Astro и индексацию поиска Pagefind. Корневой `npm ci` сайту не нужен, и корневые проверки сайт не затрагивают: зависимости сайта лежат в своём `site/package.json`.

## Писать страницы

- Страница - файл в `docs/guide/` с frontmatter (`title`, `description`). Нужны компоненты Starlight (карточки, шаги, вкладки) - файл называется `.mdx`.
- Внутренние ссылки пишутся от корня сайта без базового пути: `[Установка](/start/install/)`. Базовый путь добавляется при сборке.
- Новую страницу нужно добавить в боковое меню в `site/astro.config.mjs`.
- Числа состояния каталога на страницы не выносятся: количество плагинов и их описания берутся из метаданных.
- Название бренда - `DEX AI KIT` в заголовках и шапке, `AI KIT` в тексте, как в README и на баннерах.
- Утверждение о поведении Claude Code пишется только со сверкой по [документации](https://code.claude.com/docs/en/overview): рядом названа страница-источник и дата сверки, как в разделе [Основы](/basics/). Чужой текст не копируется, его пересказывают своими словами.
- Имена сущностей берутся из [словаря](https://github.com/dex-it/claude-code-marketplace/blob/main/docs/domain/domain-model.md).

## Публикация

Pull Request, который трогает сайт, собирает его и проверяет ссылки, но ничего не публикует. Публикация на GitHub Pages идёт при слиянии в `develop` или `main`: деплой разрешён только этим веткам в окружении `github-pages`.

## Адрес сайта

Адрес GitHub Pages задаёт имя репозитория: `https://<организация>.github.io/<репозиторий>/`. Поэтому «красивый» адрес вроде `/ai-kit/` появится только после переименования репозитория или при собственном домене в настройках Pages. Оба шага меняют настройки репозитория и решаются владельцем. После переименования в коде меняется одна константа `REPO_NAME` в `site/site.config.mjs`; ссылки на сайт, canonical, sitemap и проверка `check-dist.mjs` подтянутся сами.
