Плагин поставлен. Откройте проект и запустите команду.

## Проверьте, что плагины видны

В терминале:

```bash
claude plugin list
```

В сессии Claude Code начните вводить `/` и имя плагина: skills и команды плагина показываются под его именем в форме `/плагин:команда`. Например, у плагина `dex-self-reviewer` команда называется `/dex-self-reviewer:self-review`.

Если плагин поставлен при открытой сессии, перезапустите её или выполните `/reload-plugins`.

## Вызов команды

Команды каталога вызываются полной формой `/плагин:команда` и принимают аргументы:

```text
/dex-mr-reviewer:mr-review owner/repo#42
/dex-debugger:root-cause "после деплоя 500 на /orders, в логах NullReferenceException"
```

Какие аргументы принимает команда, видно на её странице в каталоге, например [dex-mr-reviewer](/catalog/plugins/dex-mr-reviewer/). Если аргумента не хватает, команда спросит его или скажет, чего не хватает, и работу не начнёт.

В сценариях и в каталоге команды записаны полным именем. Короткое имя без префикса платформа даёт только skills; на него каталог не рассчитывает.

## Что делает команда

Команда ведёт порядок шагов: вызывает специалистов, останавливается там, где нужно ваше решение, и сводит результат. Чаще всего у команды есть явные «стоп»-точки с короткими словами-ответами. Например, у `/dex-self-reviewer:self-review` это `делай` (исправить пункт чеклиста), `ещё раз` (новый проход по дельте) и `пушь` (push после зелёного чеклиста).

Пока вы не сказали «делай», файлы в рабочем дереве не меняются. Слова-ответы у каждой команды свои.

## Skills работают без команд

Skills подключаются сами, когда в разговоре появляется их тема: Entity Framework, Kafka, Kubernetes и так далее. Claude Code держит в контексте название и описание skill и загружает полный текст, только когда он понадобился. Отдельно вызывать их не нужно.
