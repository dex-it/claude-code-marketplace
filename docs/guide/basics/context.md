Каждая сессия Claude Code начинается с чистого контекстного окна. Знание между сессиями переносят два механизма: файлы CLAUDE.md, которые пишете вы, и автоматическая память, которую ведёт сам Claude. Источники: [Memory](https://code.claude.com/docs/en/memory), [MCP](https://code.claude.com/docs/en/mcp), сверено 23.10.2026.

## CLAUDE.md

Это инструкции проекта простым текстом: команды сборки и тестов, соглашения, архитектурные решения. Файл грузится в начале каждой сессии.

| Уровень | Где лежит |
|---|---|
| Организация | управляемый путь ОС, для всех пользователей организации |
| Личный | `~/.claude/CLAUDE.md`, для всех ваших проектов |
| Проект | `./CLAUDE.md` или `./.claude/CLAUDE.md`, делится через git |

Документация советует держать один файл в пределах 200 строк: длиннее - выше расход контекста и ниже следование инструкциям. Что нужно только части дерева, выносят в правила: файлы `.md` в `.claude/rules/`. Если в начале правила указано поле `paths` со списком glob-шаблонов, оно подгружается лишь когда Claude работает с подходящими файлами; без `paths` правило грузится при старте.

Главное предупреждение: Claude воспринимает CLAUDE.md как контекст, а не как принудительную настройку. Чтобы действие нельзя было сделать вообще, используйте хук `PreToolUse` ([Хуки и моды](/basics/hooks-mods/)).

В AI KIT: `dex-auto:onboard` дописывает в `CLAUDE.md` вашего проекта блок между маркерами, а ревьюер читает договорённости оттуда как норму ([Автономная работа](/concepts/auto/)). Сам каталог держит правила разработки в [CLAUDE.md репозитория](https://github.com/dex-it/claude-code-marketplace/blob/main/CLAUDE.md).

## MCP: доступ к внешним системам

MCP (Model Context Protocol) - открытый стандарт, по которому Claude Code подключается к внешним инструментам, базам и API. Сервер добавляют командой:

```bash
claude mcp add --transport http notion https://mcp.notion.com/mcp
claude mcp list
```

Область сервера: local (по умолчанию, только текущий проект, хранится у вас), project (файл `.mcp.json` в корне, коммитится, Claude Code просит подтвердить), user (все ваши проекты). Серверы плагина стартуют, когда плагин включён. Инструменты MCP по умолчанию находятся по требованию, поэтому большое число серверов не раздувает контекст сразу.

В AI KIT готовые конфигурации лежат в [mcp/README.md](https://github.com/dex-it/claude-code-marketplace/blob/main/mcp/README.md), ключи - в [CREDENTIALS.md](https://github.com/dex-it/claude-code-marketplace/blob/main/CREDENTIALS.md). Для диагностики часто хватает CLI-утилит каталога: они легче и используют уже настроенный вход (`/dex-kubectl-cli:kube-pods`, [Утилиты](/catalog/utilities/)).

## Почему контекст нужно беречь

Всё перечисленное делит одно окно: CLAUDE.md, названия и описания skills, агентов и команд включённых плагинов, инструменты MCP, история беседы. Лишнее вытесняет полезное. Практика: ставить плагины под роль, держать CLAUDE.md коротким, подробности выносить в правила по путям и skills. Как это выглядит для плагинов - [Как Claude Code подхватывает плагины](/concepts/loading/).

## Ограничения и ошибки

- **Противоречивые инструкции.** Если два правила спорят, Claude может выбрать любое. Пересматривайте файлы и правила время от времени.
- **Секреты в `.mcp.json`.** Документация предлагает подстановку переменных окружения `${VAR}`, чтобы не хранить токены в файле.
- **Автопамять не заменяет CLAUDE.md.** Её пишет Claude; договорённости команды лучше фиксировать самим.
