Skill - это каталог с файлом `SKILL.md`: инструкции, которые Claude берёт в работу, когда они подходят к задаче, или которые вы вызываете вручную по имени. В отличие от CLAUDE.md, тело skill попадает в контекст только когда он используется. Источник: [Skills](https://code.claude.com/docs/en/skills), сверено 23.10.2026.

## Где лежит

| Где | Путь | Кому доступен |
|---|---|---|
| Личные | `~/.claude/skills/<имя>/SKILL.md` | вам, во всех проектах |
| Проект | `.claude/skills/<имя>/SKILL.md` | всем, кто работает в репозитории |
| Плагин | `<плагин>/skills/<имя>/SKILL.md` | там, где включён плагин; вызывается как `/плагин:имя` |

Есть ещё уровень организации через управляемые настройки. Если имена совпали, побеждает уровень выше: организация, затем личные, затем проект.

## Как попадает в контекст

- Название и описание лежат в контексте всегда, чтобы Claude знал, что skill существует.
- Полный текст загружается, когда запрос подходит под описание или когда вы вызвали `/имя`.
- Описание в списке skills обрезается по длине (в документации назван предел 1536 символов вместе с `when_to_use`), поэтому главное пишите в начале.

Отсюда практический вывод для авторов: описание - это условие срабатывания. Размытое описание значит, что skill не сработает, когда нужно, или сработает не к месту.

## Поля в начале файла

Все поля необязательны, но `description` рекомендован. Те, что встречаются чаще других:

| Поле | Что делает |
|---|---|
| `name` | Имя команды; по умолчанию имя каталога |
| `description` | Что делает и когда нужен: по нему Claude решает, загружать ли skill |
| `disable-model-invocation: true` | Только вы можете вызвать skill, Claude сам не станет |
| `user-invocable: false` | Скрывает skill из меню `/`, его вызывает только Claude |
| `allowed-tools` | Инструменты, которые можно использовать без запроса, пока идёт ход со skill |
| `context: fork` | Запустить skill в отдельном субагенте |

Полный перечень полей меняется от версии к версии, смотрите страницу документации.

## Как это выглядит в AI KIT

Skill каталога - тот же `SKILL.md`, но он следует своим правилам: это список ловушек, а не справочник. Так начинается skill `kafka` (плагин `dex-skill-kafka`):

```yaml
---
name: kafka
description: Kafka - идемпотентность продьюсера, несохранённые смещения потребителя при ребалансе, ядовитое сообщение в партиции. Активируется при kafka, producer, consumer, topic, partition, offset, ...
---
```

В описании названа тема и перечислены слова, по которым skill нужен. Значит, достаточно спросить Claude про consumer group и ребаланс, и памятка подгрузится сама. Вручную ничего вызывать не нужно. Установка и состав: [dex-skill-kafka](/catalog/plugins/dex-skill-kafka/); как каталог устроил свои skills - [Skills](/concepts/skills/).

## Ограничения и ошибки

- **Skill не запускает другой skill сам.** Упоминание имени в тексте ничего не загружает; нужен явный вызов инструмента `Skill`. Это правило репозитория, в котором такая ошибка уже случалась ([CLAUDE.md](https://github.com/dex-it/claude-code-marketplace/blob/main/CLAUDE.md), раздел «Механизмы композиции»).
- **Ключевых слов отдельным полем нет.** Слова для срабатывания пишутся в `description`.
- **Много skills - много описаний в контексте.** Ставьте нужные, а не все.
