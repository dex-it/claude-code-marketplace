---
title: Устранение неполадок
description: Что делать, если установка не прошла, команда не найдена, специалист ведёт себя странно или мод не работает.
---

Здесь только то, что можно подтвердить по коду скриптов и документации Claude Code. Общие проблемы плагинов - в [документации Claude Code](https://code.claude.com/docs/en/plugins/troubleshooting).

## Скрипт: «jq is required but not installed»

`install-bundle.sh` и другие скрипты на bash требуют `jq` и `claude` в `PATH`. Поставьте `jq` (`brew install jq`, `sudo apt install jq`) и убедитесь, что команда `claude` доступна в терминале. PowerShell-версии `jq` не требуют.

## Скрипт: «Bundle not found»

Имя бандла - аргумент без префикса `dex-bundle-`. Список доступных: `./install-bundle/install-bundle.sh --list`. Скрипт нужно запускать из актуального клона: он читает бандлы из `plugins/bundles/` рядом с собой.

## Скрипт: «Not declared in marketplace.json»

Скрипт сверяет состав бандла с `.claude-plugin/marketplace.json` вашего клона и нашёл в бандле плагин, которого там нет. Начните с обновления клона: `git pull`.

## Установка плагина падает

Плагины ставятся из каталога `dex-claude-marketplace`, поэтому он должен быть подключён. Проверьте список и подключите при необходимости:

```bash
claude plugin marketplace list
claude plugin marketplace add dex-it/claude-code-marketplace
```

## Плагин поставлен, но команды не видно

Плагины подхватываются при старте сессии. Запустите новую или выполните `/reload-plugins` в уже открытой. Проверьте, что плагин в списке: `claude plugin list`. Команды вызываются полной формой `/плагин:команда`.

## Команда остановилась со статусом `blocked` и названием плагина

Команда не пишет код и тесты сама, а вызывает специалиста вашего стека. Если нужного специалиста нет в установке, она останавливается и называет недостающий плагин. Для `/dex-implement:implement` и `/dex-test:test` поставьте бандл `dotnet-developer` или `ts-fullstack`.

## Специалист работает, но «слабо»

Специалист без нужных ему skills запустится, но будет работать без них: установка плоская, и недостающее не подтягивается. Покажите, чего не хватает, и доставьте:

```bash
./install-bundle/sync-plugins.sh            # отчёт
./install-bundle/sync-plugins.sh --fix      # поставить недостающие skills
```

Скрипт запускается из клона и анализирует то, что у вас поставлено. Или поставьте бандл целиком.

## Старые или переименованные плагины продолжают загружаться

Установщики снятые плагины не удаляют. `./install-bundle/sync-plugins.sh` (в PowerShell - `sync-plugins.ps1`) называет поставленные плагины, которых в каталоге клона больше нет, и команду снятия (сам он ничего не снимает). Замену ищите по имени в таблице «Renamed and removed plugins» файла [install-bundle/README.md](https://github.com/dex-it/claude-code-marketplace/blob/main/install-bundle/README.md) и удалите вручную: `claude plugin uninstall <имя>`.

## После удаления бандла пропали плагины другого бандла

`uninstall-bundle.sh` удаляет все плагины бандла, не проверяя, нужны ли они другим. Поставьте оставшийся бандл заново: недостающее вернётся.

## Мод ничего не показывает

Моды требуют Claude Code 2.1.287 или новее. На более старой версии мод ставится, но ничего не делает. Для трекеров PR и MR нужен доступ к хостингу: у GitHub-мода это залогиненный `gh` либо токен в `GH_TOKEN`; сессия должна быть открыта в клоне репозитория. Подробности - в README мода: [dex-github-pr-tracker](https://github.com/dex-it/claude-code-marketplace/blob/main/mods/dex-github-pr-tracker/README.md).

## Команда над CLI говорит, что программы нет

CLI-плагины ставят только команды, а программы (`kubectl`, `psql`, `kaf` и другие) должны быть на машине. Проверить и доставить: `./install-bundle/install-cli-tools.sh --check`, затем `--all`.
