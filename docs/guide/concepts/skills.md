Skill - короткая памятка по теме или стеку. Она говорит не «как устроена технология» (это модель и так знает), а «на что здесь наступают и как делать правильно».

## Как выглядит

Skill - это markdown-файл `skills/<имя>/SKILL.md` внутри плагина. Содержание - чеклист ловушек: каждый пункт называет ситуацию, которую исполнитель сам не заподозрит. Например, из skill по Kafka:

> Ядовитое сообщение блокирует партицию потребителя: после ограниченного числа попыток оно уходит на разбор (топик `*.DLT` или иное хранилище) с содержимым и причиной, смещение движется дальше; повтор на месте без предела партицию не освобождает

Здесь нет справочника API и туториала. Только то, что приводит к дефекту, если о нём не знать.

## Когда подключается

Есть два пути, и оба работают без вашего участия:

- **По теме.** В начале файла skill есть описание со списком слов, по которым он нужен («Активируется при kafka, producer, consumer, offset, rebalance ...»). Когда тема появляется в разговоре, Claude Code подгружает skill целиком. В контексте постоянно лежат только название и описание, полный текст загружается по мере надобности.
- **По поручению специалиста.** Агент в нужной фазе сам вызывает нужный skill. Общие специалисты определяют стек по манифесту проекта и берут skills с префиксом стека: `dex-skill-dotnet-*`, `dex-skill-ts-*`, `dex-skill-python-*`.

## Два типа

| Тип | Отвечает на вопрос | Примеры |
|---|---|---|
| **Ловушки** (по умолчанию) | Какие грабли в области X | `dotnet-ef-core`, `kafka`, `react`, `kubernetes` |
| **Правило процесса** | Как действовать, что грузить, в каком порядке | `stack-registry`, `project-baseline` |

## Имена и поиск

Плагин skill называется `dex-skill-<имя>`; у стековых skills имя начинается со стека (`dotnet-ef-core`, `ts-nodejs-api`, `python-pytorch`). Все skills сгруппированы по темам в [каталоге](/catalog/skills/).

## Как поставить

Skills ставятся поштучно (`claude plugin install dex-skill-kafka@dex-claude-marketplace`) или входят в бандлы. Если skill нужен специалисту, берите бандл: специалист сам skills не подтягивает.

Полное устройство skill для авторов: [SKILL_FRAMEWORK.md на GitHub](https://github.com/dex-it/claude-code-marketplace/blob/main/docs/SKILL_FRAMEWORK.md).

## Пример

Спросите Claude, как настроить потребителя Kafka после ребаланса, и в ответе появятся пункты чек-листа `kafka`: про несохранённые смещения и ядовитое сообщение. Вызывать `/kafka` не нужно, skill подхватывается по теме. Если нужно проверить, что плагин вообще поставлен, `claude plugin list` покажет `dex-skill-kafka@dex-claude-marketplace`.

## Ограничения и частые ошибки

- **Skill - контекст, а не запрет.** Памятка повышает шанс, что Claude учтёт ловушку, но не гарантирует; жёсткие запреты делают хуками и правами ([Основы](/basics/context/)).
- **Не сработал.** Почти всегда причина в теме без ключевых слов из `description` либо в том, что плагин не поставлен. Назовите технологию в запросе прямо.
- **Skill не документация.** Справочник API и туториал в нём не ищите: каталог держит там только ловушки.
- **Лишние skills тратят контекст.** Каждый включённый skill добавляет в сессию своё описание.

Как skills устроены в самой платформе: [Основы, Skills](/basics/skills/).
