# Process-skill `artifact-review` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Вынести правило ревью артефактов (5 обязательных осей) из `CLAUDE.md` в process-skill `artifact-review`, чтобы субагент читал правило, а не пересказывал по памяти.

**Architecture:** Новый плагин-скилл `dex-skill-artifact-review` несёт механику пяти осей целиком; `CLAUDE.md` сохраняет суть + ссылку («один факт - один нормативный дом»). Скилл типа process: маркер в теле + регистрация в allowlist валидатора. Вызывается императивно по имени в основном потоке; агенты каталога не правятся.

**Tech Stack:** Markdown-артефакты, JSON-манифесты, Node-валидаторы (`tools/validate-skill.js`), `npm run validate`.

Спека: [docs/superpowers/specs/2026-07-27-artifact-review-skill-design.md](../specs/2026-07-27-artifact-review-skill-design.md). Issue: #132.

## Global Constraints

- **Пунктуация ASCII:** `-` вместо `—`/`–`, `->` вместо `→`, `<=`/`>=`/`!=` вместо `≤`/`≥`/`≠`, `...` вместо `…`. НЕ трогать: кавычки «», эмодзи-статусы, `№`, `×`, Unicode внутри inline code. Единица миграции - файл целиком.
- **Скилл не называет числовых порогов объёма.** Пороги строк для skill/команды - `SKILL_FRAMEWORK.md` / `COMMAND_FRAMEWORK.md`, проверяет `npm run validate`. Любое число в теле создаёт второй дом.
- **Валидаторные пороги не меняются:** `PROJECT_TARGET_MAX = 120`, `PROJECT_RECOMMENDED_MAX = 250`, `CLAUDE_CODE_HARD_LIMIT = 500`, `SIZE_HARD_LIMIT = 200`. Задача их не трогает.
- **`description` <= 750 символов** (проектный потолок, error), <= 500 рекомендация (warning). Ключевые слова - по запросам разработчика, не по терминам из тела.
- **Версии в двух местах одновременно:** `.claude-plugin/plugin.json` плагина И `.claude-plugin/marketplace.json`. Новый плагин = `1.0.0` + minor-bump версии каталога.
- **Code fence <= 12 строк** (`code-fence-too-long`, error).
- **Формулировки для LLM:** механизм / условие / исход. Уход от проверки - явный статус, не молчание. Ветвление без терминала - дефект.

```markdown
# Ревью артефакта каталога

<!-- skill-type: process -->

Предмет - артефакт каталога: `SKILL.md`, `agents/*.md`, `commands/*.md`. Ревью кода - не сюда
(`/code-review`, `mr-reviewer`).

Ревью = прогон по 5 осям, каждая обязательна. «Всё валидно по фреймворку» ревью не закрывает:
`npm run validate` отвечает на «формат соблюдён», не на «стоит ли держать это в каталоге».

Предусловие: оси 2 и 4 закрываются прогоном профильного скилла и требуют `Skill` tool у
исполнителя. Нет его - ось закрывается статусом `n/a` + причина, не молчанием.
```

- [ ] **Step 5: Написать таблицу-реестр осей**

Таблица закрывает правило валидатора `process-empty` (нужна таблица-реестр или >= 2 H2) и служит якорем при беглом чтении.

```markdown
## Оси (все обязательны)

| Ось | Отвечает на вопрос | Чем закрывается |
| --- | --- | --- |
| 1. Соответствие фреймворку | Формат, обобщённость, композиция - по правилам? | Сверка с `SKILL_FRAMEWORK.md` / `AGENT_FRAMEWORK.md` / `COMMAND_FRAMEWORK.md` |
| 2. Fact-check | Техфакты верны на текущей версии API? | Прогон `dex-skill-fact-verification` |
| 3. Полезность | Стоит ли держать единицу в каталоге? | Вывод: держать / переформулировать / убрать |
| 4. Лаконичность | Есть ли текст, не меняющий поведение исполнителя? | Прогон `dex-skill-optimize-for-llm` |
| 5. Сверка с гайдом модели | Приём не вреден для модели из `model:` артефакта? | Гайд объявленной модели, актуальная версия |
```

- [ ] **Step 6: Написать оси 1-3**

Ось 3 несёт бинарный проверочный вопрос с терминалом на каждой ветке - без него вывод невоспроизводим и читается как вкусовщина.

```markdown
### 1. Соответствие фреймворку

Формат, обобщённость, версии, композиция по `SKILL_FRAMEWORK.md` / `AGENT_FRAMEWORK.md` /
`COMMAND_FRAMEWORK.md`. Правила устройства агента (источник факта в шаге верификации, критерий
делегирования скептика) проверяются здесь: в своём доме они безусловны, к модели не привязаны.

### 2. Fact-check

Закрывается прогоном `dex-skill-fact-verification` на техфактах артефакта. Не прогнан - ось не
пройдена.

Сверять КАЖДЫЙ факт в «Правильно» / «Почему», не только целевой. Симметрично дописанная half
(write-факт к read-факту) - красный флаг. Уход от сверки - статус из реестра, не молчание.

Артефакт ссылается на внешний стандарт (ISO/IEEE и т.п.) -> строка в реестре
`docs/standards/README.md` со статусом сверки; полные тексты платных стандартов в репо не
коммитятся.

### 3. Полезность

Вывод по каждой единице: держать / переформулировать / убрать. Единица без вывода - ось не пройдена.

Проверочный вопрос: «что сломается у исполнителя, если этой единицы нет?»

| Ответ | Вывод |
| --- | --- |
| Названо конкретное неверное действие | держать |
| Названо, но правило не читается из текста единицы | переформулировать |
| Ответа нет или «ничего» | убрать |

Признаки «убрать», каждый - самостоятельное основание: модель делает правильно и без единицы;
косметика без последствий; тематически выбивается из скоупа артефакта; дублирует соседа в этом же
артефакте; конфликтует с другим skill (сначала решить, какой из двух прав). Качество выше
количества - слабую убрать, не тащить ради числа.
```

- [ ] **Step 7: Написать ось 4**

Прогон скилла - нормативный шаг, не сноска: `skill -> skill` загрузки в Claude Code нет, поэтому «дом там» без прогона было бы мёртвой строкой.

```markdown
### 4. Лаконичность

Закрывается прогоном `dex-skill-optimize-for-llm` на теле артефакта. Не прогнан - ось не пройдена.

Режем подачу, не нормативную силу: лазейки, статусы, escape-условия и грабли под сокращение не
попадают никогда.

Проверочный вопрос на фрагмент: «убери его - изменится ли поведение исполнителя?» Нет -> вырезать.
Да -> оставить, даже если длинно.

Признаки реза: «Почему» растёкся в абзац вместо одной причины; одно следствие сказано дважды в
разных словах; приписка «это проверяется при ...» вместо самого механизма; словесное описание
дублирует код-блок ловушки; пересказ того, что модель знает и так (синтаксис, дефолты языка).

Пороги объёма - `SKILL_FRAMEWORK.md` / `COMMAND_FRAMEWORK.md`, проверяет `npm run validate`. Здесь
не дублируются.
```

- [ ] **Step 8: Написать ось 5**

Три уровня: против чего сверяться, как заходить в источник, перечень пунктов с охватом. Уровень 1 - та самая формулировка, чей пересказ по памяти разошёлся с оригиналом (повод issue #132).

```markdown
### 5. Сверка с гайдом модели артефакта

Артефакт - вход модели, и часть привычных приёмов на новых моделях вредна. Гайды
модель-специфичны: приём, вредный на одной модели, на другой может быть не подтверждён или обратен.

Против чего сверяться: гайд ТОЙ модели, что объявлена во frontmatter артефакта (`model:`), в
актуальной на момент ревью версии. Перенос выводов с соседней модели запрещён.

Как заходить: через корень [Prompting best
practices](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices),
не сразу на лист - состав модель-специфичных страниц меняется. Модель артефакта своей страницы не
имеет (сверено 27.07.2026: `haiku` страницы не имеет) -> кросс-модельная часть корня + статус
`unverifiable` по модель-специфичным пунктам.

Перечень открыт: он собран из гайдов на дату сверки, а не выведен из принципа. Новая
модель-специфичная страница -> новая строка сюда.

#### Пункты

Кросс-модельные проверяются всегда. Модель-специфичный - только когда `model:` артефакта совпадает,
иначе `n/a` + причина.

| Пункт | Охват | Что ловит | Дом |
| --- | --- | --- | --- |
| Консервативный фильтр | кросс-модельный | «Только high-severity», «будь консервативен» модель исполняет буквально: разбирает так же глубоко, конвертирует в находки меньше. Правильно: покрытие на шаге поиска, фильтр отдельным проходом по `confidence`/`severity` | `dex-skill-review-evidence` |
| Скоуп задан явно | кросс-модельный | Границы узкой задачи названы: модель инструкцию с пункта на соседний молча не переносит | - |
| Объём письменного результата | кросс-модельный | Артефакт, порождающий документ, задаёт калибровку длины по материалу; без неё документы раздуваются филлером | `dex-skill-doc-standards` |
| `effort` по характеру работы | кросс-модельный (значения и дефолт модель-специфичны) | Выставлен осознанно, не унаследован по инерции; дефолт платформы и поведение на низких уровнях - по гайду своей модели | `AGENT_FRAMEWORK.md` «Глубина рассуждения» |
```

- [ ] **Step 9: Написать хвостовые секции**

Реестр статусов - отдельная секция, потому что до выноса `unverifiable`/`contradicted` жили внутри оси 2, а `n/a` - внутри оси 5: два места вместо одного реестра.

```markdown
## Дедупликация: пересечение != дубль

Разный ракурс (вход vs выход, разные контексты одного API) - разные грабли, дедуп не нужен.
Реальный дубль (одна грабля в двух skills) - чинить по `SKILL_FRAMEWORK.md` «Дублирование между
skills»: вынос в базовый skill предпочтительнее сноски, `skill -> skill` загрузки нет.

## Особые случаи

Авто-ловушки `/mr-analyze` -> `/mr-apply` - строже по осям 2 и 3: формально валидны, но часто слабы
по сути или с перевёрнутой причинностью.

## Реестр статусов ухода от проверки

| Статус | Когда | Что писать |
| --- | --- | --- |
| `n/a` | Пункт неприменим к артефакту (модель-специфичный при другой `model:`, нет `Skill` tool) | Причина неприменимости |
| `unverifiable` | Источник недоступен или не покрывает вопрос | Что искал и где |
| `contradicted` | Источник противоречит утверждению артефакта | Утверждение источника + ссылка |

Молчание вместо статуса - ось не пройдена.

## Критерий завершённости

По каждой оси x каждой единице вынесен вывод. Непройденная ось или единица без вывода - ревью не
завершено.
```
