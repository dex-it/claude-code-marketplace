## Шесть сдвигов S1: что следует для нас

| Сдвиг S1 | Что это значит | Применимость к репозиторию |
|---|---|---|
| Правила -> суждение | Жёсткое правило заменяется описанием намерения | **Применимо частично.** Канонический пример S1 (правило про комментарии -> «пиши как соседний код») у нас уже реализован целым скиллом `dex-skill-codebase-conventions`. Остаточные случаи - чек-листы-развилки в агентах |
| Примеры -> дизайн интерфейса | Few-shot сужает пространство решений; лучше самоописательный интерфейс | **Применимо.** Проверять: примеры «вот так пиши» в агентах. Не трогать: примеры формата/схемы/контракта |
| Всё наперёд -> прогрессивное раскрытие | Детали переезжают в подгружаемые по необходимости материалы | **Уже сделано на уровне механизма:** условные skills грузятся императивно в фазах, pre-load только у безусловного `node-contract`. Остаточное - длинные `SKILL.md`, не разбитые на вход + дерево |
| Повторение -> одно упоминание | Инструкция живёт в одном слое | **Главная находка аудита.** Правило fact-verification пересказано в 37 агентах при наличии skill-дома на 40 строк |
| Память в CLAUDE.md -> авто-память | Ставка на авто-память и артефакты | **Не применимо напрямую.** Наш `CLAUDE.md` не журнал состояния, а нормативный дом правил разработки плагинов. Авто-память сессии его не заменяет: правила нужны каждому контрибьютору, а не одной машине |
| Простые спеки -> богатые референсы | Тестовый набор, рабочий код, рубрика вместо плоского текста | **Применимо ограниченно.** Референс-реализации у нас уже названы (`dex-mr-reviewer` как референс рецепта Reviewer). Полноценные тестовые наборы - за рамками задачи |

## Поведенческие отличия Opus 5 (S2, S4)

| Поведение | Источник | Что делать |
|---|---|---|
| Ответы пользователю длиннее, чем у прошлых Opus; `effort` видимую длину не регулирует | S2 «Response length and verbosity», S4 «Model behavior differences», S6 | Просить краткость промтом явно |
| Чаще комментирует ход работы в агентских сессиях | S2 «User-facing progress updates», S4 | Задать каденцию: что до первого вызова, когда промежуточный апдейт, чем начинать финал |
| Письменные артефакты на диск выходят длиннее | S2 «Written deliverable length», S5 п.5 | Калибровка длины по существу задачи |
| Проверяет свою работу сам; унаследованные инструкции верификации дают переверификацию | S2 «Task scope and over-verification», S4, S3 («Ask Claude to self-check» с оговоркой про Opus 5) | **Удалять** такие инструкции, а не переписывать |
| Расширяет объём задачи, добавляет незаказанные шаги | S2 «Task scope and over-verification» | Для узких агентов зафиксировать границу объёма |
| Делегирует сабагентам охотнее прошлых моделей | S2 «Controlling subagent spawning», S4, S3 «Subagent orchestration» | Делегирование только на крупных независимых треках; не для проверки своей же работы |
| Чаще проговаривает исправления своих прежних утверждений | S2 «Self-correction» | Оговаривать правку, только если она меняет решение читателя |
| Ревью: «сообщай только критичное» / «будь консервативен» исполняется буквально и снижает охват | S2 «Capability improvements», раздел Code review | Просить полный список, фильтровать отдельным проходом |

Оговорка про сабагентов: S2 и S4 одновременно называют координацию команд сабагентов сильной стороной Opus 5, с эффективными writer-verifier паттернами. То есть резать надо **безусловный** спавн и делегирование мелочи, а не writer-verifier как приём.

## Effort (S6, S4, S5)

- Полная лестница на Opus 5: `low`, `medium`, `high` (дефолт), `xhigh`, `max`. Дефолт API - `high`; `high` эквивалентен неуказанию параметра (S6).
- Рекомендация Opus 5: старт с `high`, вверх `xhigh`/`max` для тяжёлой агентской и кодинговой работы, **`low` и `medium` использовать свободно как основной рычаг стоимости и времени ответа там, где эвалы показывают, что качество держится** (S6 «Recommended effort levels for Claude Opus 5»).
- Настройки, перенесённые с прошлой модели, требуют свежего прогона effort sweep на своих эвалах, а не переиспользования (S6, S5 чек-лист).
- Effort влияет на все токены ответа, включая вызовы инструментов: на низком уровне модель делает меньше вызовов (S6 «How effort works», «Effort with tool use»).
- Effort управляет объёмом размышления, **не видимой длиной ответа** - длину задавать промтом (S6, S2).
- Смена effort между запросами инвалидирует кеш префикса: внутри одной кешируемой сессии уровень держать постоянным (S6 «Changing effort mid-conversation»).
- В Claude Code `effort` - штатное поле frontmatter субагента, перекрывает уровень сессии, дефолт - наследование (S9). В списке полей, игнорируемых у плагинных субагентов (`hooks`, `mcpServers`, `permissionMode`), его нет.

**Следствие для нас:** в `run-claude/` и конфигурациях уровни effort не зашиты (проверено грепом, см. инвентаризацию) - подкручивать нечего. Ось effort у агентов вводится как возможность, значения без замеров не проставляются.

## Прочие API-факты, к артефактам не применимые

Зафиксированы, чтобы не всплывали как «а вдруг надо»:

- Thinking включён по умолчанию на Opus 5; отключение допустимо только при effort `high` и ниже, иначе 400 (S4, S5). Нас не касается: плагины не формируют HTTP-запросы, `thinking` наследуется от сессии Claude Code (S9).
- Минимум кешируемого промта снижен до 512 токенов, mid-conversation tool changes, fallbacks `"default"`, fast mode (S4). Уровень API-интеграции, у нас его нет.
- 1M контекст как дефолт и максимум, 128k max output (S4). На правила написания артефактов не влияет, кроме общего вывода: экономия контекста перестала быть выживанием и стала гигиеной.

## Верификация через skills (S8)

S8 описывает, как **намеренно** проектировать петли верификации скиллами (standalone / embedded / chained / PR-wide) и приводит внутренний пример Anthropic: `/code-review` ищет баги, `/simplify` чистит дифф, `/verify` подтверждает поведение end-to-end.

S8 **не** утверждает, что верификация на новых моделях не нужна. Противоречия с S2 нет, если развести:

- **Инструкция модели перепроверить себя** («убедись ещё раз», «добавь финальный шаг верификации») - складывается с собственным поведением Opus 5, даёт переверификацию. Убирать (S2, S4).
- **Петля верификации с внешней опорой** (прогон тестов, линтер, сверка с источником, отдельный проход по диффу) - остаётся приёмом и по S8 оформляется скиллом.

Рабочий критерий, выведенный из пары S2 + S8: **какой факт извне появляется по итогу шага?** Нет ответа - это самоперечитывание, режем. Есть - это петля верификации, оставляем.

## Что искали и не нашли

- Более свежих материалов Anthropic по context engineering после 24.07.2026 не обнаружено: поиск отдаёт публикацию S1 и её пересказы. Между выходом источников и этой сверкой один день.
- Независимых воспроизведений эксперимента с урезанием 80% не найдено. Сторонние разборы (charlesjones.dev, explainx.ai, the-decoder) пересказывают S1 и первоисточником не являются; в правки не идут.
- В S1-S9 нет утверждения, что доменные знания, грабли и договорённости команды следует сокращать. S1 прямо противоположен: skills - место для мнений и практик команды, `CLAUDE.md` - для того, что не выводится из репозитория.

## Главный вывод для объёма правок

Резали продуктовый слой «как быть агентом»: как звать инструменты, как форматировать, как не лениться (S1). Артефакты каталога - другой слой: грабли предметной области, workflow-контракты, конвенции репозитория. Пропорциональный рез здесь удалил бы то, ради чего каталог существует.

Поэтому целевая метрика миграции - **не процент удалённого текста**, а число снятых дублей между слоями, снятых конфликтов и удалённых инструкций, компенсирующих слабости прошлого поколения.
