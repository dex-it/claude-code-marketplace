# ADR-0001: адрес рабочего состояния движка (auto-ledger)

- **Status:** Proposed
- **Revision:** 5 (номер ведёт судья; записи ревизий - служебный след прогона, в репозиторий не едут)
- **Реализация:** код по решению написан (движок, хук, тест, шаг CI). Что предъявлено долгом -
  в «Открытом»; состояние кода относительно нормы - приложение в конце.
- **Date:** 2026-08-31
- **quality-checks:** входных записей нет - ADR создан с нуля. Записи судьи по этому ADR в
  репозитории не лежат - это служебный след прогона; `verdict: passed` не выдан, поэтому потолок -
  `review` (`node-contract`, «Готовность артефакта»).
- **Апрув:** оператор каталога, 31.08.2026 - апрув на предмет решения зафиксирован.
- **Предмет:** где лежит файл, по которому движок `dex-sdlc:engine` возобновляет работу после свёртки
  контекста и после подъёма прежней сессии, и как этот же файл находит хук `dex-sdlc-resume`.

## Контекст

Движок ведёт цель до сдачи в одном прогоне, который переживает авто-компакт и паузы. Единственный
якорь возобновления - auto-ledger: файл состояния с целью, треком, чеклистом и разделом действующих
норм. Требования к его адресу заданы не вкусом, а тремя ограничениями среды:

1. **Состояние не должно ехать в MR.** Прежний носитель `docs/autonomous/plan-<тикет>.md` лежал в
   рабочем дереве и попадал в диф; папка удалена из репозитория и внесена в `.gitignore`.
2. **Платформенные Task-tools использовать нельзя.** `TaskCreate`/`TaskList`/`TaskUpdate` недоступны
   по умолчанию на новых моделях (Claude Code changelog 2.1.233, 14.08.2026: убраны для Sonnet 5 и
   новее, включаются `CLAUDE_CODE_ENABLE_TODO_TOOLS=1`), а движок флага не требует. Дословной цитаты
   записи changelog в ADR нет - это инженерное ограничение среды по наблюдению, не требование
   внешнего источника; появится цитата - пункт перемаркировать.
3. **Адрес читают два носителя с разными возможностями.** Движок - модель, знающая только то, что
   названо ей в системном промпте, и умеющая выполнить команду. Хук - shell-скрипт, которому
   доступны поля stdin события `SessionStart` (код читает `transcript_path`, `cwd`, `source`) и
   файловая система; закрытость перечня полей по документации платформы здесь не проверялась и
   решением не используется. Разъезд двух носителей деградирует тихо: хук просто не находит файл, и
   это неотличимо от «ledger закрыт».

**Почему ADR, а не запись журнала решений.** Отмена адреса тянет согласованную правку двух плагинов,
которые ставятся по отдельности (`dex-sdlc` и `dex-sdlc-resume`), и обесценивает ledger'ы, уже
открытые в сессиях пользователей: старая пара «движок + хук» и новая друг друга не находят. Это цена
уровня публично зафиксированного формата хранения, а не правки одного модуля.

## Рассмотренные варианты

**1. Файл в рабочем дереве (`docs/autonomous/plan-*.md`).** Отвергнут: служебное состояние видно
ревьюеру и едет с MR, а `.gitignore` под него - обязанность каждого проекта-потребителя.

**2. Платформенный task-флаг, привязанный к `session_id`.** Однозначен по построению, но опирается
на Task-tools (ограничение 2). Отвергнут.

**3. `.git/auto-ledger/`.** Один адрес, одна команда у обоих носителей, в git не попадает по
построению, общий для главной репы и её worktree. Отвергнут решением оператора; механизм за
решением: `.git` - рабочая область самого git, и файл в ней исчезает при операциях, потерей данных
не считающихся (снос и повторный клон рабочей копии, перенос дерева без `.git`), плюс попадает под
инструменты, которые вправе чистить служебный каталог. Долговечность отделяет вариант 3 от
вариантов 5-7, но не от принятого по сроку жизни: тот не переживает и смены сессии («Цена»).

**4. Каталог проекта по slug главной репы** (`git rev-parse --path-format=absolute --git-common-dir`
без `/.git`). Отвергнут: расходится с каталогом, который Claude Code заводит сам (тот именуется по
cwd), то есть с папкой, где лежит `memory/`. В worktree и при запуске из подкаталога движок и хук
смотрели бы в разные места, а движку пришлось бы держать формулу вместо «возьми названное».

**5. Каталог проекта по cwd** (рядом с `memory/`). Совпадает с домом, который host уже завёл, и
формула нужна только в фолбэке. Отвергнут не по адресу, а по ключу: файл именован задачей и не
несёт признака владельца, поэтому при параллельных целях в одном проекте хук вынужден перечислять
кандидатов и перекладывать выбор на модель.

**6. Каталог проекта + строка `session:` в файле.** Снимает неоднозначность и, в отличие от
принятого, сохраняет находимость ledger в следующей сессии - ровно то, что уходит в «Цену» решения.
Отвергнут ценой второго машинно-читаемого контракта внутри файла: признак владельца пишет движок,
парсит хук, разъезд деградирует так же тихо, как разъезд адреса, но ловится хуже - файл на месте, а
поле прочитано неверно. Находимость между сессиями оценена дешевле: она нужна только при подхвате
цели в новом окне, где уже действует «Восстановление между прогонами» (тикет, ветка, MR, статусы),
тогда как парсинг признака владельца работал бы на каждом срабатывании хука.

**Реверс прежней нормы.** До этого решения `P-auto-ledger` запрещал ровно выбранное место, и его
текст дословно таков: «Пиши в `auto-ledger/`, **не** в сессионные `<session>/*`: те чистит штатная
уборка (`cleanupPeriodDays`, дефолт 30 дней) по закрытому перечню путей, произвольного подкаталога в
нём нет». Запрет снят сознательно - это реверс, а не уточнение. Что именно опровергнуто: не факт об
уборке (он в обеих редакциях один и тот же - в перечне названы `<session>.jsonl`,
`<session>/subagents/`, `<session>/tool-results/`, произвольного подкаталога в нём нет), а вывод из
него. Прежняя редакция несла факт и запрет рядом, хотя из этого факта запрет не следует: писать в
`<session>/auto-ledger/` он не мешает. Другого основания прежняя редакция не записала - почему запрет
стоял при этом факте, из её текста не восстанавливается. Цена ошибки, если запрет был прав по
существу: ledger исчезает через
`cleanupPeriodDays` вместе с прочим сессионным, и потеря неотличима от закрытого ledger - тот же
режим отказа, что у разъезда адреса. Основание реверса - вывод из перечисления, не цитата об
исчерпывающести (см. «Что проверено»); появится цитата, объявляющая уборку сессионной папки
сплошной, - решение пересматривается в пользу варианта 5 или 6, не правится по краям.

**7. Папка сессии** - принято.

## Решение

Адрес auto-ledger - `<config>/projects/<slug>/<session>/auto-ledger/<TASK>.md`: папка сессии, рядом
с её транскриптом `<session>.jsonl`. `<config>` - `$CLAUDE_CONFIG_DIR`, не задан -> `~/.claude`.
`<slug>` - рабочий каталог сессии, где каждый символ вне `[A-Za-z0-9-]` заменён на `-` (ведущий `/`
даёт ведущий `-`); каталог заводит host, вычислять его нужно только в запасной ветке хука. `<TASK>` -
ключ тикета либо имя задачи, та же замена символов.

- **Движок** *(источник: инженерный инвариант - адрес обязан читаться обоими носителями одинаково)*.
  Возьми `<session>` из пути скретчпада, названного в начале сессии, и сверь: рядом с папкой
  `<session>` обязан лежать `<session>.jsonl`. Скретчпад не назван либо сверка не сошлась - клади
  файл в папку проекта `<config>/projects/<slug>/auto-ledger/<TASK>.md` (каталог, где лежит
  `memory/`); это запасная дверь, не второй дом, другого места не подбирай. Ledger ведёт главный
  поток; узел-субагент своего ledger не заводит. Проверка - см. «Чем удержано».
- **Хук** *(источник: инженерно обязательный фикс - у хука нет ничего, кроме stdin и файловой
  системы (ограничение 3), цена обхода предъявлена там же)*.
  Стой на `SessionStart` с матчером `compact|resume`. Бери адрес из `transcript_path`: путь без
  `.jsonl` - папка сессии, его каталог - папка проекта. Сканируй `auto-ledger/` папки сессии; пусто
  - сканируй `auto-ledger/` папки проекта. Поля `transcript_path` нет - папку сессии не угадывай:
  считай папку проекта из `<config>` и `<slug>` от `cwd`. Значение `source` вне `compact` (либо
  пустого, трактуемого как компакт) и `resume` - выходи молча. Git не вызывай: триггер -
  существование незакрытого ledger, а не рабочее дерево.
- **Признак открытости** *(источник: инженерно обязательный фикс; цена - хук молчит, и это
  неотличимо от закрытого ledger)*. Пиши отдельной строкой в шапке файла ровно `Статус: открыт`
  (шаг 1 цикла) либо `Статус: закрыт` (шаг 8). Синонимов и падежных форм не вводи. Позиция строки
  внутри шапки нормой не закреплена: состав шапки - дом формата движка
  (`references/ledger-and-recovery.md`), там же остальные разделы файла.

**Вынесено за границы этого ADR** (поимённо, с домом): состав самого файла ledger - шапка, чеклист,
раздел действующих норм, журнал исполнителей - живёт в `references/ledger-and-recovery.md` движка; текст и тон
напоминания, которое хук инжектит на каждом из двух событий, - в `resume-reminder.sh` и README
плагина хука. Адрес и признак открытости от них не зависят и меняются независимо.

## Последствия

**Хорошее.** Найденный ledger принадлежит текущей сессии по построению - неоднозначность «чей
файл» исчезла для случая параллельных сессий в одном проекте. Хук лишился и вызова git, и
вычисления slug на основном пути. Компакт и `--resume` идентификатор сохраняют, то есть оба события,
на которых хук стоит, попадают в ту же папку.

**Цена.** Новая сессия ledger прежней не видит: подхват той же цели в новом окне идёт не поиском
старого файла, а «Восстановлением между прогонами» - от тикета, ветки, MR и статусов трекера.
Идентификатор сессии движок узнаёт косвенно, из пути скретчпада: канал недокументированный, и сверка
по `<session>.jsonl` ловит отсутствие файла, но не подмену идентификатора - у главного потока и его
субагентов путь скретчпада один, так что сверка сойдётся и там, и там. Неоднозначность остаётся
внутри сессии, если в ней открыто несколько целей: хук перечисляет кандидатов и оставляет выбор
модели. Запасная дверь стоит на `<slug>`, и оба носителя обязаны считать его одной формулой:
норма движка несёт её дословно, ориентир «каталог, где лежит `memory/`» оставлен там сверкой, а не
способом поиска. Остаточный риск - не разъезд двух наших текстов, а расхождение формулы с тем, как
каталог именует host: наблюдается это молча и с тем же исходом, ради которого написан ADR (файл
лежит, хук его не видит), а ловца нет - в тесте host'а не существует, проверка 7 пиннит только
литерал в прозе. Режим не гипотетический: в `~/.claude/projects/` лежит каталог того же проекта со
`<slug>` без ведущего `-` и открытым ledger от 26.08.2026 внутри, не поднятым ни одним
напоминанием; чем именно вычислен этот слаг, по артефактам не восстанавливается. Ledger,
попавший в запасную дверь, лежит в папке проекта и переживает свою сессию: любая
следующая сессия этого проекта с пустой папкой сессии подхватит его как свой. Файлы auto-ledger
штатной уборкой не удаляются никогда - то же свойство, которым решение держится, оставляет в
каталоге данных все ledger'ы, включая незакрытые - перечень штатной уборки их не покрывает
(исчерпывающесть перечня - вывод, см. «Что проверено»).

**Чем удержано.** Адрес живёт в трёх носителях: норма движка (`P-auto-ledger` в `SKILL.md`), код
хука и README плагина хука. `tests/hooks/resume-reminder.test.sh` держит обе половины: проверки 1-6
гоняют скрипт на временном `CLAUDE_CONFIG_DIR` (папка сессии из `transcript_path`, изоляция соседней
сессии, приоритет папки сессии над запасной, запасная дверь при пустой папке сессии и при
отсутствии `transcript_path`, несколько кандидатов, закрытый ledger, чужой `source`), проверка 7
пиннит к константам теста литералы адреса и строки статуса в прозе движка и README;
в коде хука сверяются имя подкаталога `auto-ledger` и префикс `Статус:` - остальной адрес хук
получает из `transcript_path` и литералом не хранит. Правка адреса
в одном носителе роняет прогон; шаг CI - `validate-agents.yml`, job `shell-syntax`.

## Расхождения с текущим кодом (приложение; протухает с первой правкой кода, норму не отменяет)

- Норма требует ровно два значения статуса (`открыт` / `закрыт`) отдельной строкой в шапке. Хук
  берёт `^Статус:[[:space:]]*открыт` в любой строке файла и принимает любой суффикс после слова
  (регистр не важен по обеим сторонам - это норма, не зазор). Зазор в сторону мягкости: код
  принимает больше, чем разрешает норма; выравнивать его не требуется, пока движок пишет строку по
  норме.
- Оба непокрытых пункта нормы вынесены в «Открытое» («Предъявлено долгом») - здесь их не
  дублируем: приложение протухает с первой правкой кода, а долг живёт до решения.

## Открытое

- `Accepted` требует по `node-contract` («Публикационный цикл», переход `review -> approved`) трёх
  условий сразу: запись судьи `quality-checks` с `verdict: passed` по типу ADR, зафиксированный
  апрув уполномоченной стороны и отсутствие открытых вопросов по артефакту. Апрув получен
  31.08.2026 (шапка), открытых вопросов сверх этого пункта нет; недостаёт записи судьи
  `verdict: passed` по итоговому тексту. Ревизии 1-3 дали `failed`; находки ревизий 1-2 закрыты, из
  ревизии 3 закрыты все, кроме двух, названных долгом в приложении. Лимит ревизий по `node-contract`
  исчерпан, находок выше `medium` нет - документ остаётся под потолком `Proposed`, а подъём требует
  либо продления ревизий решением вызывающей стороны, либо принятия долга с условием пересмотра
  (условия названы при каждом долге). Дефолт: работаем по решению как по действующему.
- Запасная дверь исчезнет, если появится документированный способ узнать `session_id` изнутри
  сессии; до тех пор она обязательна - без неё ledger при неназванном скретчпаде негде хранить.
- **Предъявлено долгом** (решение вызывающей стороны по обоим пунктам не принято; до него оба
  остаются открытыми вопросами, а не принятым долгом):
  1. «Ledger ведёт главный поток» ловца не имеет: ledger субагента лёг бы в ту же папку сессии и
     стал бы кандидатом наравне. Условие пересмотра проверяемое: появится ledger, чей журнал
     исполнителей (состав файла - дом формата движка) не содержит записей главного потока, - норма
     не удерживает, и признак автора переносится в сам файл.
  2. Соответствие формулы `<slug>` имени каталога, который заводит host, не наблюдается ничем: в
     тесте host'а нет. Условие пересмотра: появится документированный способ спросить имя каталога
     у host'а - сверка встаёт в движок; либо наблюдение покажет второй каталог того же проекта с
     расходящимся слагом, заведённый после этой ревизии, - тогда формула неверна и решение идёт в
     пересмотр целиком.
