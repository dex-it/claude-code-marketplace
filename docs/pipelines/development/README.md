# Конвейер разработки: зона «требования -> открытый MR»

Следующая зона после [конвейера требований](../analytics/README.md) и зоны дизайна. Документы зоны,
разные предметы:

- [PIPELINE.md](PIPELINE.md) - **устройство работы**: вход и границы, один дом порядка работ, режимы
  и кто ведёт переходы, порядок шагов, состояние между шагами, сверка ветки. Отвечает на вопрос «как
  это работает».
- [IMPLEMENTATION.md](IMPLEMENTATION.md) - **состав реализации**: какими командами запускается, какие
  узлы выполняют шаги, какие скиллы нормируют, где лежит состояние. Отвечает на вопрос «чем это
  исполняется».

`NORMS.md` и `ARCHITECTURE.md` у зоны нет намеренно: нормативная основа здесь не внешние стандарты, а
движок и `node-contract`, а схема вызовов совпадает с картой слотов - второй дом того же завёл бы
расхождение.

Карта «слот процесса разработки -> агент, который его закрывает» - в
[../../DEV_PROCESS_COVERAGE.md](../../DEV_PROCESS_COVERAGE.md): здесь порядок и стыки, там перечень
исполнителей по слотам и стекам.

Нормативный дом порядка работ - не эти документы, а движок
`dex-skill-autonomous-task:autonomous-task` и его трек `development`: описание расходится с движком -
правится описание.
