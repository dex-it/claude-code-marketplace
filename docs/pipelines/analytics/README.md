# Конвейер требований: зона «идея -> допуск к разработке»

Документы зоны, разные предметы:

- [NORMS.md](NORMS.md) - **нормативная основа**: на какие стандарты опирается цепочка этапов, какой
  информационный элемент выпускается на каждом, какие атрибуты несёт его выход. Отвечает на вопрос
  «чем это подпёрто».
- [PIPELINE.md](PIPELINE.md) - **устройство работы**: какими единицами она идёт, в каком порядке,
  что проверяется на стыках, когда останавливается ради решения человека. Отвечает на вопрос «как
  это работает». Требования к самому конвейеру - в его шапке, `R-1..R-10`.
- [IMPLEMENTATION.md](IMPLEMENTATION.md) - **состав реализации**: какой набор артефактов получается
  на выходе, какими командами это запускается, кто выполняет шаги, где лежит знание. Отвечает на
  вопрос «чем это исполняется».
- [ARCHITECTURE.md](ARCHITECTURE.md) - **архитектура исполнения**: кто кого вызывает, какие
  служебные скиллы держат каркас, что едет по каждому ребру, что остаётся на диске. Отвечает на
  вопрос «как это собрано». Читается после `PIPELINE.md` и ему не противоречит: разойдутся -
  правится описание, а не схема.

Дом фактов и статусов сверки - [реестр стандартов](../../standards/README.md): здесь дизайн, там
источники и их статусы. Утверждение из первоисточника несёт пометку реестра там, где его повторяет.

Проверяются кейсами [pipeline-basic.md](../../../tests/_cases/pipeline-basic.md): у каждого кейса
названы раздел схемы и требование `R-N`, которые он держит.
