# Итог исследования: форма пункта trap-skill - вектор или решение

Сводка выводов. Числа, метод и разбор по стадиям - [README.md](README.md); предрегистрации -
[PREREG.md](PREREG.md) и [PREREG-blind.md](PREREG-blind.md); линия идеи и первоисточники -
[SOURCES.md](SOURCES.md).

**Вопрос.** Держит ли качество trap-skill пункт-вектор (название ситуации, идея Макса из PR #280)
вместо пункта-решения (триада «Плохо / Правильно / Почему» с готовым ответом)?

**Ответ.** Ни то, ни другое в чистом виде. Готовое решение, не сверенное с документацией версии,
вредит. Одного названия хватает не везде. Лучшая из проверенных форм - название, при нужде факт
версии и обязательный исход, сверенный с документацией. Для opus вопрос формы почти снят: на
калиброванных кейсах EF Core 8 пробела знания у него нет, и скилл любой проверенной формы ему не
нужен, но и не вредит.

## Что не подтвердилось

- **H1 (название не хуже триады)** опровергнута: названия не хватает в классе A на sonnet и в A и C
  на opus и haiku.
- **H3 (класс по признаку предсказывает форму)** опровергнута: в A названия не хватило, в B хватило.
  Обе провалившиеся единицы A - не «пробел узнавания», а неверное решение модели в узнанной ситуации.
  Класс до прогона определяет форму только для конвенции (C) и неверной триады (D).
- **Выигрыш F4b к работе без скилла на sonnet** не доказан: +25 п.п., интервал [-0.6; +46.5].
- **Форма записи исхода - не главный рычаг**: исход-свойство F6 дал 12/28 против 15/28 у F4b при
  длине на 7% меньше, правило P1 - «не решено».
- **Сужение ревью скиллом** (9-18 п.п. в основной части) на opus не воспроизвелось на кейсах с
  нетривиальными дефектами (E8); на sonnet и haiku и на прочих родах кейсов вопрос не перепроверялся.

## Что это значит для каталога

Рекомендации; норма «Форма пункта» в `docs/SKILL_FRAMEWORK.md` в этой ветке не правится.

1. **Готовый ответ, не сверенный с документацией версии, в пункт не пишется.** Здесь норма и идея
   Макса правы, и это единственный вывод, подтверждённый на всех тирах.
2. **Шаг 3 нормы разделить: исход раньше проверки.** Сейчас шаг 3 - «что сверить или какой исход
   обязателен» как равные варианты; замер различает их (0/4 против 4/4).
3. **Исход не запрещает допустимых вариантов.** Исход, назвавший один из двух корректных вариантов,
   дал вред на haiku (5/24, корректный `Clear()` объявлен дефектом); исход с обоими - 1/24.
4. **Исход покрывает механизм ловушки, а не подслучай темы.** Из пяти строк, не сдвинутых ни одной
   формой, в четырёх исход механизма не содержал. Ключевые слова темы - в названии: модель отбирает
   пункт по названию, а не по хвосту исхода (наблюдение, не замер).
5. **Название снимает триаду только после прогона F1 на кейсе.** Ни одну из четырёх целевых единиц
   лестницы название не взяло полностью (1/4, 3/4, 1/4, 0/4).
6. **Конвенция команды в каталожный скилл не входит** - её держит свод правил проекта (решение
   пользователя 02.10.2026).
7. **Тир потребителя решает, нужен ли скилл вообще.** Opus на проверенной теме закрывает пробел без
   скилла; sonnet получает от исходов прибавку по счёту, но до opus без скилла не дотягивает (15/28
   против 80/80 на тех же строках); haiku без исходов почти ничего не берёт.
8. **Эпик #264**: пачки с потребителем на sonnet сжимать по лестнице с F4 вместо F3 и прогоном F1
   до снятия триады; пачки с потребителем на haiku - только с обязательными исходами.
9. **Модель ревьюера не менять**: ревьюеры каталога на opus, гибрид «часть opus, часть sonnet» не
   собирать - поиск дефектов на sonnet теряет 23 из 80 строк, и потерю ниже по потоку никто не ловит.

## Открытые вопросы

- Второй независимый проход sonnet поверх opus (объединение находок) на кейсах, где opus ошибается, с
  учётом ложных находок.
- Сужение ревью на sonnet при нетривиальных дефектах вне скилла и средство от него: строка «сначала
  ревью целиком, затем список» (F4b2) мерилась только на opus, где лечить было нечего.
- Перенос за пределы EF Core и .NET: все кейсы, кроме одного (Python), - .NET, ловушки - из наборов
  PR #280.
- Исход, не запрещающий допустимых вариантов, и ключевые слова в названии - гипотезы под отдельный
  замер.

## Ограничения

- n=4 на ячейку, 4-7 единиц на класс: различимы разности порядка 40 п.п., а 10-20 п.п. - нет.
  Интервалы считают строки одного прогона независимыми, граничные выводы хрупкие.
- Авторы кейсов, исходов и судья - одно семейство моделей; общие пробелы знания могут совпасть.
- Среда упрощена: `--restricted`, сборка запрещена, effort зафиксирован (sonnet high, opus medium).
- Haiku в слепой стадии - описательно, в выводы о формате не входит.
