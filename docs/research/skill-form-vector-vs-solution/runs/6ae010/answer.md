Нашёл 8 проблем. Перед мерджем обязательно нужно исправить первые три. Сборку и тесты я не запускал, выводы сделаны только по чтению кода. Ответ также записан в `_answer.md`.

1. **CRITICAL: `ProcedureService.CalculateDoseMlAsync`, доза в 1000 раз больше нужной.**
   - `doseMg = weightGrams * drugMgPerKg`: вес в граммах умножается на дозировку в мг/кг, деления на 1000 нет, хотя комментарий рядом говорит «кг».
   - Пример: кошка 4000 г, 2.5 мг/кг, 10 мг/мл. Правильно 0.1 мл, метод вернёт 1000 мл.
   - По этой цифре персонал готовит инфузию, ошибка может убить животное.
   - Исправление: `weightGrams / 1000m * drugMgPerKg` и тест на известный пример.

2. **HIGH: `Pet.WeightGrams` (`int`, не nullable) вместе с `CalculateDoseMlAsync`.**
   - Миграция добавит колонку существующим питомцам со значением 0.
   - Невзвешенный питомец получит объём 0 мл молча, без ошибки.
   - Исправление: сделать поле `int?`, а при `null` или `<= 0` выбрасывать ошибку.

3. **HIGH: `ProcedureSheetService.GetDaySheetAsync`, пропадает первая страница.**
   - Страницы по контракту нумеруются с 1, а в коде `Skip(page * PageSize)`. При `page=1` первые 30 процедур пропускаются, в обычный день лист будет пустым.
   - Номер страницы не проверяется: при отрицательном значении запрос падает с ошибкой 500.
   - Исправление: `Skip((page - 1) * PageSize)` и проверка `page >= 1`.

4. **MEDIUM: `ClinicDbContext.OnModelCreating`, каскадное удаление.**
   - Связи обязательные, поэтому по умолчанию стоит `ON DELETE CASCADE`.
   - Удаление питомца сотрёт все его процедуры, включая закрытые, вместе с расходниками и заметками. Это нарушает правило README о неизменности закрытого списания и задним числом меняет отчёт по расходу.
   - Исправление: `DeleteBehavior.Restrict`.

5. **MEDIUM: `ProcedureService.RemoveConsumableAsync`, гонка и лишняя загрузка.**
   - Статус проверяется в памяти, а токена конкурентности нет. Если процедуру параллельно закроют, строку удалят уже из закрытого списания.
   - Ради удаления одной строки загружаются все строки процедуры, а у инфузий их сотни.
   - Исправление: удалять одним запросом через `ExecuteDeleteAsync` с условием на статус либо добавить токен конкурентности (`xmin`).

6. **LOW: `ProcedureSheetService.SearchNotesAsync`, нет индекса.**
   - Нет GIN-индекса под `to_tsvector`, поэтому каждый поиск проходит по всей таблице, и с ростом журнала он будет тормозить.
   - Нужно уточнить требование: заметки персонала (`StaffNotes`) поиск не просматривает, ищет только по `Procedure.Notes`.

7. **LOW: `ProcedureService.GetCardAsync`, порядок расходников.** Строки не сортируются, поэтому при каждом открытии карточки порядок может быть разным.

8. **LOW: нет проверки входных данных, вместо 400/404 будет ошибка 500.**
   - В `ScheduleAsync`: нет `title` (падение на `Trim`), пустой заголовок не отклоняется, заголовок длиннее 200 символов, несуществующий `PetId`.
   - В `GetConsumptionAsync`: `sort == null`.
