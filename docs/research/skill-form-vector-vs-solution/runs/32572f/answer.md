# Ревью MR !214: Motorpool.Fleet

Нашёл 16 дефектов: 2 critical, 6 high, 5 medium, 3 low. Код не менял, сборку и тесты не запускал, всё найдено чтением кода. Тот же ответ записан в `_answer.md`.

## Critical

1. **`Migrations/...DriverDisplayNameAndTripRoute.cs`, метод `Up`: ФИО всех водителей будут удалены.**
   - **Что не так:** вместо переименования колонки миграция делает `DropColumn("full_name")` и затем `AddColumn("display_name", default "")`.
   - **Почему это дефект:** pipeline выкатит её на prod без вмешательства. У всех водителей останется пустое имя, вернуть данные можно только из бэкапа. Локальная проверка этого не показала, потому что импорт, поиск и отчёт ФИО не читают.
   - **Как исправить:** использовать `RenameColumn`.

2. **`TripService.SearchAsync` + `SqlText.LikeContains`: SQL-инъекция.**
   - **Что не так:** параметр `route` из query string вставляется в SQL-строку `'...'` через `FromSqlRaw`. `LikeContains` не экранирует одинарную кавычку.
   - **Почему это дефект:** запрос вида `?route=x' OR 1=1 --` выполнится в базе. Даже обычный адрес с апострофом приведёт к ошибке 500.
   - **Как исправить:** передавать шаблон параметром или через `EF.Functions.ILike`.

## High

3. **`TripService.MileageAsync`: отчёт по пробегу всегда падает.**
   - **Что не так:** вызов `WorkCalendar.IsWorkingDay(t.StartedAt)` стоит внутри запроса перед `SumAsync`, EF Core не может перевести его в SQL.
   - **Почему это дефект:** будет `InvalidOperationException`, эндпоинт всегда отвечает 500.

4. **`TripService.MileageAsync`: деление на ноль.**
   - **Что не так:** `totalKm / count` считается без проверки `count == 0`.
   - **Почему это дефект:** если за период у машины не было закрытых поездок, отчёт падает. Для отчёта это частая ситуация.

5. **`TripService.ImportWaybillsAsync`: московское время не переводится в UTC.**
   - **Что не так:** после `ParseExact` у даты `Kind=Unspecified`, конвертации нет.
   - **Почему это дефект:** Npgsql 8 при записи такой даты в `timestamptz` бросает исключение, и импорт падает целиком. Если включён legacy-режим, время сохраняется со сдвигом на 3 часа. Тогда поездки попадают не в тот день, а выходные определяются неверно.

6. **`TripService.GetVehicleByPlateAsync`: `SingleAsync` без фильтра по списанным машинам.**
   - **Что не так:** уникальный индекс по госномеру частичный (только для действующих машин). Значит, списанная и новая машина могут иметь один номер.
   - **Почему это дефект:** на таком номере `SingleAsync` бросит исключение и уронит весь импорт. Если в базе осталась только списанная машина, поездка запишется на неё. Кроме того, это N+1: один запрос на каждую строку CSV.

7. **`Program.cs`, `PUT /drivers/{id}/permits`: нет политики `Hr`.**
   - **Что не так:** работает только общий `RequireAuthorization()`, хотя соседний `PUT /drivers/{id}/name` закрыт политикой `Hr`.
   - **Почему это дефект:** любой сотрудник может выдать себе допуск к грузовикам или продлить истёкший. Это прямой риск для безопасности.

8. **`DriverService.ReplacePermitsAsync`: замена допусков падает, если они уже есть.**
   - **Что не так:** `Permits.Clear()` вызывается при обязательном внешнем ключе и связи `DeleteBehavior.NoAction`.
   - **Почему это дефект:** EF не удаляет «осиротевшие» допуски сам и при сохранении бросит `InvalidOperationException` («association has been severed»). Замена работает только при первом заполнении.
   - **Как исправить:** удалять старые допуски явно через `RemoveRange`.

## Medium

9. **`ImportWaybillsAsync`: повторная загрузка файла создаёт дубли.** Проверки на уже загруженные поездки нет, при повторе пробег в отчётах удвоится.

10. **`ImportWaybillsAsync`: хрупкий разбор CSV и нет валидации.**
    - `Split(';')` не учитывает кавычки CSV, поэтому `;` внутри маршрута сдвигает колонки.
    - Пустая строка в конце файла, неизвестный табельный номер, незакрытая поездка или маршрут длиннее 500 символов приводят к 500 на весь файл. Номер плохой строки не сообщается.
    - Кодировка не задана, а выгрузки 1С часто в Windows-1251.
    - Не проверяется, что у водителя есть действующий допуск к классу машины.

11. **`MileageAsync` и `WorkCalendar`: сутки и выходные считаются по UTC, а не по Москве.** Ночные поездки в выходные засчитываются как рабочие, и наоборот.

12. **`WorkCalendar`: праздники зашиты в код только на 2026 год.** Перенесённые рабочие субботы не учтены. Насколько я помню, в списке нет 9 января и 31 декабря 2026, но это стоит сверить с официальным календарём.

13. **В MR нет `.Designer.cs` и обновлённого снапшота модели.** Без атрибута `[Migration]` миграцию не найдёт ни EF, ни bundle. Возможно, файлы просто не попали в список, но их наличие в коммите нужно проверить.

## Low

14. **`RenameAsync`: нет валидации.** `null` в имени, имя длиннее 200 символов и несуществующий водитель дают 500 вместо 400/404.

15. **`ReplacePermitsAsync`: дубли молча отбрасываются.** `DistinctBy(p => p.Class)` оставляет первый допуск по порядку, а не с самым поздним сроком. Невалидные значения класса не проверяются.

16. **`SearchAsync`: поиск `ILIKE '%...%'` без индекса.** Таблица поездок будет сканироваться целиком. Нужен индекс pg_trgm на `route`.
