**Решения:**
- **(а) и (б)** — чтение без отслеживания (`AsNoTracking`) и выборка сразу в DTO. Так не срабатывает ленивая загрузка через прокси и нет лишних запросов (N+1).
  - Карточка одного заказа грузится одним запросом с JOIN, без `AsSplitQuery`.
  - Выгрузка тысяч заказов клиента идёт через `AsSplitQuery`, чтобы позиции и платежи не перемножались в одном ответе. Сортировка уникальная: `CreatedAt, Id`.
- **(в)** `GetProductBySku(string sku, string? warehouse)`:
  - если склад передан — `SingleOrDefault` по паре (Sku, Warehouse), она уникальна;
  - если склад `null` — `FirstOrDefault` со стабильной сортировкой по `Warehouse`. С `Single` метод упал бы, как только SKU появится на втором складе.
  - Какой склад выбирать, когда он не передан, должен решить бизнес. Уникальный индекс `(Sku, Warehouse)` стоит добавить отдельной миграцией.
- **(г)** Дата последней отгрузки (`MAX(ShippedAt)`) считается на сервере, заказы без даты отгрузки отфильтрованы. Если у клиента нет отгруженных заказов, метод бросает `InvalidOperationException`: тип результата не nullable, а подставлять `default(DateTime)` нельзя.
