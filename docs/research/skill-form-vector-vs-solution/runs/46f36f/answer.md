# Ревью MR «Списание баллов лояльности»

Нашёл 11 дефектов, три из них критические. Код не менял, сборку и тесты не запускал. Ответ записан в `work/_answer.md`.

**Как сверял поведение pydantic 1.10.13:** context7 в сессии недоступен, поэтому проверял по официальной документации и по исходнику тега v1.10.13 (`pydantic/fields.py`, `docs/examples/models_required_field_optional.py`). Пересказ HTML-страницы документации сначала выдал пример кода, противоречащий исходнику. Вывод поэтому опирается на сырые файлы из тега, а не на этот пересказ.

## Находки

1. **[critical] `schemas.py` `RedeemRequest.confirm_amount` + `redeem.py` `redeem`.** В pydantic 1.10 `Optional[Decimal]` без значения по умолчанию — необязательное поле со значением `None`, вопреки комментарию. Обязательным оно было бы в v2. Запрос без поля пройдёт валидацию и спишет **весь баланс**. Под удар попадают именно старые клиенты. Исправление: `= ...` или `Field(...)`.
2. **[critical] `RedeemRequest`, конфиг модели.** По умолчанию действует `Extra.ignore`, а не запрет лишних полей. Опечатка в имени поля у клиента → поле молча отбрасывается → `None` → списывается весь баланс. Исправление: `extra = Extra.forbid`.
3. **[critical] `redeem`: сумма не ограничена снизу.** При `confirm_amount=-100` строка `points -= int(-1000)` **начисляет** баллы. Ноль тоже проходит. Исправление: `gt=0`.
4. **[high] `redeem` / `repo.get_member` / `save_member`: гонка.** Чтение и запись идут в разных транзакциях без `FOR UPDATE`, а `UPDATE` пишет абсолютное значение. Два параллельных запроса потратят одни и те же баллы дважды.
5. **[high] `POINT_VALUE = 0.1` (float).** `Decimal(0.1)` = `0.1000000000000000055…`. Из-за этого `int(amount / …)` усекает: при сумме 0.3 ₽ списывается 2 балла вместо 3. В ответе при этом суммы с длинным хвостом.
6. **[medium] `RedeemRequest.points`.** Поле обязательное, но нигде не используется. Непонятно, в каких единицах идёт списание.
7. **[medium] `save_member` + `write_audit`.** Это две отдельные транзакции. Если запись в аудит упадёт, баллы уже списаны, а записи нет.
8. **[medium] `write_audit(req.dict())`.** Пишется сырой запрос; при полном списании там `null`. Фактическая сумма и остаток в аудит не попадают.
9. **[medium] `valid_until`.** Срок нигде не сохраняется, истечение баллов не проверяется. Заявленная в описании MR фича фактически не реализована.
10. **[low] Ошибка на единицу в сроке.** Код даёт 366 дней, если считать сегодняшний день, как сказано в комментарии. К тому же `date.today()` берёт часовой пояс сервера.
11. **[low] Нулевой баланс.** Полное списание при нулевом балансе проходит как успешная операция на 0 ₽ и пишется в аудит.
