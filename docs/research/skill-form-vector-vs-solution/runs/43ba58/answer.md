# Ревью MR !87: экспертиза заявок, рейтинг и выгрузка для совета

Нашёл 13 дефектов: 2 critical, 7 high, 1 medium, 3 low. Код я не менял, сборку и тесты не запускал, так что находки основаны только на чтении кода. Тот же ответ записан в `_answer.md`.

## Critical

**1. `Controllers/ContestsController.cs`: `Ranking` и `RankingCsv` теперь видны экспертам**
- **Что не так:** чтобы открыть экспертам `GET /api/contests/{id}`, роль `Expert` добавили в `[Authorize]` на уровне всего класса. Из-за этого эксперту стали доступны и `GET {id}/ranking`, и `GET {id}/ranking.csv`.
- **Почему это дефект:** в рейтинге видны баллы всех заявок, число экспертиз и решения о грантах, причём пока экспертиза ещё идёт. Эксперт видит, как оценили его заявки коллеги, то есть экспертиза перестаёт быть слепой. В MR предлагалось открыть экспертам только карточку конкурса.
- **Как исправить:** на классе оставить только `Coordinator`, а `Expert` добавить в атрибут только у метода `Get`.

**2. `Services/ConflictOfInterest.cs`, метод `Find`: проверка конфликта интересов неполная**
- **Что не так:** проверяется только `ApplicantId == expert.Id`, то есть заявка, поданная экспертом лично.
- **Почему это дефект:** по п. 4.3 положения эксперт не оценивает и заявки организации, где он работает. Это сравнение `OrganizationInn`, и поля для него в модели уже есть. Сейчас `AssignAsync` и `ReassignAsync` спокойно назначают эксперту заявки его работодателя. При этом MR обещает, что систему проверяет сама, и координатор перестанет проверять это вручную.

## High

**3. `Models/Contest.cs`, метод `AcceptsReviews`: приём оценок закрывается на день раньше**
- **Что не так:** приём закрывается в 00:00 UTC в начале дня дедлайна, а по MR должен закрываться после этого дня.
- **Почему это дефект:** именно в последний вечер, когда эксперты досылают оценки, они получат 409 «Приём оценок закрыт».
- **Как исправить:** сравнивать с `ReviewDeadline.AddDays(1)`. Конец дня нужно считать в часовом поясе фонда, а не по UTC.

**4. `Services/RankingService.cs`, метод `BuildAsync`: равные баллы упорядочены не по дате подачи**
- **Что не так:** при равном балле сортировка идёт по `CreatedAt`, то есть по времени создания черновика. По положению нужен `SubmittedAt`, время подачи.
- **Почему это дефект:** заявка, черновик которой завели раньше, обойдёт заявку, поданную раньше. На границе фонда это решает, кто получит грант.
- **Попутно:** сортировка идёт по неокруглённому среднему, а в отчёт выводится округлённое. Две заявки с одинаковым баллом в отчёте могут встать не по дате подачи.

**5. `Services/RankingCsvWriter.cs`, метод `Write`: числа в CSV ломают колонки**
- **Что не так:** `Score` и `RequestedAmount` форматируются в текущей культуре. `UseRequestLocalization` ставит `ru-RU`, поэтому выходит `85,33` без кавычек.
- **Почему это дефект:** запятая совпадает с разделителем CSV, колонки сдвигаются. Google Sheets показывает неверные данные, скрипт фонда их так же неверно разбирает.
- **Как исправить:** форматировать числа через `CultureInfo.InvariantCulture`.

**6. `Controllers/ReviewsController.cs`, метод `Mine`: два запроса параллельно на одном контексте**
- **Что не так:** `ToListAsync` и `CountAsync` запускаются одновременно через `Task.WhenAll` на одном `DbContext`.
- **Почему это дефект:** параллельная работа с одним `DbContext` запрещена. Будет `InvalidOperationException` («A second operation was started…»), и эндпоинт «мои назначения» стабильно отдаёт 500.

**7. `Controllers/ApplicationsController.cs`, метод `Search`: поиск по региону падает**
- **Что не так:** `string.Equals(..., StringComparison.OrdinalIgnoreCase)` EF не переводит в SQL.
- **Почему это дефект:** как только задан регион, запрос падает с ошибкой трансляции. Поиск по региону без учёта регистра, обещанный в MR, не работает вообще.
- **Как исправить:** `EF.Functions.ILike`, или `ToLower()` с обеих сторон, или колонка `citext`.

**8. `Services/AssignmentService.cs`, метод `ReassignAsync`: новому эксперту достаётся чужой черновик**
- **Что не так:** назначения в статусе `Draft` передаются вместе с баллами (`Scores`), `Comment` и `Total` прежнего эксперта.
- **Почему это дефект:** новый эксперт видит чужую оценку, что нарушает слепую экспертизу. К тому же он может отправить её под своим именем.
- **Как исправить:** при передаче сбрасывать баллы, комментарий и итог, а статус возвращать в `Assigned`.

**9. `Services/ReviewService.cs`, метод `SaveAsync` (а также `ReassignAsync` и `CloseReview`): гонки при правке одной оценки**
- **Что не так:** у `Review` нет проверки конкурентного изменения (concurrency token), а состояние проверяется на ранее прочитанной копии.
- **Почему это дефект:** возможны молчаливые перезаписи:
  - параллельно сохранённый черновик затирает уже отправленную оценку;
  - `Draft` или `Submitted` записывается поверх `Expired` после закрытия экспертизы;
  - отправляемая в этот момент оценка уходит другому эксперту при передаче.
- **Как исправить:** concurrency token (`xmin` или `Status`) с обработкой `DbUpdateConcurrencyException`, либо условный `ExecuteUpdate`, либо `FOR UPDATE` в транзакции.

## Medium

**10. `Services/RankingCsvWriter.cs`, метод `Escape`: формулы в CSV**
- **Что не так:** название заявки и имя заявителя попадают в CSV как есть.
- **Почему это дефект:** значения, начинающиеся с `=`, `+`, `-` или `@`, Google Sheets выполнит как формулу у членов совета. Так можно вытащить данные или подменить отображаемое значение.
- **Как исправить:** перед такими значениями ставить `'`.

## Low

**11. `Services/AssignmentService.cs`, метод `AssignAsync`**
- Не проверяется, открыта ли экспертиза: можно назначить заявки в уже закрытом конкурсе, и назначения повиснут в `Assigned`.
- Если две заявки назначают одновременно, срабатывает уникальный индекс, и координатор получает 500 вместо 409.

**12. `Services/ReviewService.cs`, метод `SaveAsync`: лишняя загрузка**
- Две коллекции (`Scores` и `Criteria`) загружаются в одном запросе без явного режима split или single. EF пишет предупреждение, строки перемножаются.
- Конкурс и критерии попадают в отслеживание изменений, хотя не меняются.

**13. `Controllers/ApplicationsController.cs`, метод `Get`: загружается больше, чем отдаётся**
- Загружается вся сущность заявки (с ИНН и `ApplicantId`) и все отзывы, даже для эксперта, которому отзывы не показываются.
- Нужна выборка только нужных полей в DTO, а отзывы стоит загружать только для координатора.
