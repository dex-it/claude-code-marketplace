## Critical

**1. `Controllers/ContestsController.cs`: `Ranking` и `RankingCsv` теперь доступны экспертам**
- **Что не так:** чтобы эксперты могли открыть `GET /api/contests/{id}`, роль `Expert` добавили в `[Authorize]` на уровне всего класса. Из-за этого экспертам открылись и `ranking`, и `ranking.csv`.
- **Почему это дефект:** экспертиза перестаёт быть слепой. Во время приёма оценок эксперт видит средний балл и число отправленных экспертиз по каждой заявке, в том числе по своим. Нужно повесить `[Authorize(Roles = Roles.Coordinator)]` на оба метода рейтинга.

## High

**2. `Services/ConflictOfInterest.cs`, `Find`: не проверяется организация эксперта**
- **Что не так:** проверяется только `ApplicantId == expert.Id`. Сравнения по `OrganizationInn` нет.
- **Почему это дефект:** п. 4.3 положения запрещает эксперту оценивать и заявки организации, где он работает. Ручную проверку отменили, так что такие назначения пройдут без предупреждения. Ошибка попадает и в `AssignAsync`, и в `ReassignAsync`.

**3. `Models/Contest.cs`, `AcceptsReviews`: приём оценок закрывается в начале дня дедлайна, а не после него**
- **Что не так:** условие `utcNow < ReviewDeadline 00:00 UTC` перестаёт выполняться в начале дня дедлайна.
- **Почему это дефект:** по MR приём закрывается после дня дедлайна, а эксперты досылают оценки как раз в последний вечер. Сейчас в этот вечер они получат 409. Граница должна быть `ReviewDeadline + 1 день` в часовом поясе фонда (например, Europe/Moscow), переведённом в UTC.

**4. `Services/RankingService.cs`, `BuildAsync`: при равном балле сортировка идёт не по дате подачи**
- **Что не так:** стоит `ThenBy(x => x.CreatedAt)`, а это дата создания черновика.
- **Почему это дефект:** по положению при равном балле выше заявка, поданная раньше, то есть нужен `SubmittedAt`. На границе фонда это меняет, кто получит грант. Нужна сортировка по `SubmittedAt`, затем по `Id`.

**5. `Services/RankingCsvWriter.cs`, `Write`: числа пишутся в культуре ru-RU, поэтому CSV ломается**
- **Что не так:** `Score` и `RequestedAmount` выводятся как `85,5` и `150000,00`, а разделитель полей тоже запятая.
- **Почему это дефект:** в каждой строке с дробным числом появляется лишняя колонка, и столбцы съезжают. Google Sheets и скрипт фонда получают искажённые данные. Нужно форматировать через `CultureInfo.InvariantCulture`.

**6. `Controllers/ReviewsController.cs`, `Mine`: два параллельных запроса на одном `DbContext`**
- **Что не так:** `ToListAsync` и `CountAsync` запускаются одновременно через `Task.WhenAll` на одном экземпляре `DbContext`.
- **Почему это дефект:** `DbContext` не потокобезопасен. Второй запрос падает с `InvalidOperationException` («A second operation was started…»), и endpoint отвечает 500. Запросы нужно выполнять последовательно или посчитать `Submitted` по уже полученному `items`.

**7. `Controllers/ApplicationsController.cs`, `Search`: условие по региону не транслируется в SQL**
- **Что не так:** EF Core 8 не умеет переводить в SQL `Region.Equals(r, StringComparison.OrdinalIgnoreCase)`.
- **Почему это дефект:** любой запрос с параметром `region` падает с 500, и поиск без учёта регистра из MR не работает. Нужно использовать `EF.Functions.ILike` с экранированием, `ToLower()` с обеих сторон или `citext`/collation.

**8. `Services/AssignmentService.cs`, `ReassignAsync`: новый эксперт получает черновик прежнего эксперта**
- **Что не так:** при передаче назначений в статусе `Draft` остаются `Scores`, `Comment`, `Total` и статус прежнего эксперта.
- **Почему это дефект:** новый эксперт видит оценку коллеги, то есть слепота нарушена, и может отправить её под своим именем. Передаваемое назначение нужно сбрасывать до `Assigned` и очищать оценки.

## Medium

**9. `Services/ReviewService.cs`, `SaveAsync`: параллельные сохранения одной оценки молча перезаписывают друг друга**
- **Что не так:** у оценки нет concurrency token, а проверка «уже отправлено» выполняется в памяти.
- **Почему это дефект:** если одновременно идут отправка и сохранение черновика, отправленная оценка может вернуться в `Draft` и выпасть из рейтинга. Это нарушает правило «отправку изменить нельзя». Так же конфликтуют `ReassignAsync` и `CloseReview`. Нужен токен `xmin` с обработкой `DbUpdateConcurrencyException` → 409 или условное обновление в SQL.

**10. `Services/RankingCsvWriter.cs`, `Escape`: формулы из полей заявителя попадают в CSV как есть**
- **Что не так:** `Title` и `ApplicantName` вводит заявитель, и значения, начинающиеся с `=`, `+`, `-`, `@`, пишутся без обработки.
- **Почему это дефект:** Google Sheets выполнит их как формулы (CSV/formula injection). Таким значениям нужен префикс `'`.

## Low

**11. `Services/AssignmentService.cs`, `AssignAsync`: нет проверки закрытия экспертизы, гонка даёт 500**
- **Что не так:** не проверяется, что конкурс существует и экспертиза не закрыта (`ReviewClosed`). Два одновременных назначения одной пары упираются в уникальный индекс.
- **Почему это дефект:** после закрытия можно создать назначения, которые нельзя ни заполнить, ни истечь. Двойной клик заканчивается ошибкой 500 вместо понятного ответа.

**12. `Controllers/ApplicationsController.cs`, `Get`: отзывы загружаются полными сущностями, даже если результат выбрасывается**
- **Что не так:** `Include(a => a.Reviews…)` грузит полные `Review` для всех ролей, хотя эксперту они не нужны.
- **Почему это дефект:** лишняя нагрузка на БД. Данные коллег эксперту сейчас не уходят, но эта защита держится только на ветке `if`. Лучше делать проекцию в DTO и загружать отзывы только для координатора.
