Решения:
- **(а) и (б):** позиции и платежи загружаются в том же запросе (`Include` + `AsSplitQuery` + `AsNoTracking`). Так в SQL не перемножаются позиции и платежи и нет отдельного запроса на каждый заказ. Метод (б) отдаёт заказы потоком (`IAsyncEnumerable<Order>`) и читает их пачками по 500: каждая следующая пачка начинается после последнего `Id`, поэтому тысячи заказов не лежат в памяти целиком.
- **(в) `GetProductBySku(string sku, string? warehouse)`:** если склад указан, ищем по паре sku + склад. Если склад `null`: нет продукта — возвращаем `null`, один — возвращаем его, несколько — бросаем `InvalidOperationException` («укажите warehouse»). Первый попавшийся продукт с чужого склада не возвращаем.
- **(г):** если у клиента нет отгруженных заказов, метод бросает понятное `InvalidOperationException`. Тип `DateTime` без null не позволяет вернуть «нет даты», а просто упасть на пустом результате было бы хуже. Удалённые заказы отсекает фильтр, который уже есть в модели.

Проблема в модели, не исправлял: в опциях включено `UseLazyLoadingProxies`, а для него все навигационные свойства должны быть `virtual`. `Customer.Orders`, `Order.Items` и `Order.Payments` не virtual, поэтому EF, скорее всего, упадёт при построении модели.
