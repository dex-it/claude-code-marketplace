**Решения:**
- **Сортировка (а):** значение `sort` сверяется со списком допустимых столбцов, в SQL пользовательская строка не попадает. Неизвестное значение даёт сортировку по дате по убыванию. Добавлена досортировка по номеру заявки, чтобы строки не перескакивали между страницами. Статус сортируется по этапам работы с заявкой, а не по алфавиту.
- **Лицевой счёт (в):** в БД уже есть дубли счетов после переноса из старого биллинга в 2023 году, и на них ссылаются заявки. Обычный уникальный индекс на таких данных уронил бы миграцию при выкатке, а удалять эти записи нельзя. Поэтому миграция помечает старые дубли флагом, а актуальной остаётся последняя запись — то же правило, что уже есть в `FindByAccountAsync`. Если два одновременных запроса проскочат проверку в коде, второй отсечёт индекс в БД.
- **План обслуживания (г):** работы сопоставляются по коду: существующие обновляются, новые добавляются. Те, которых нет в присланном плане, уходят в архив, а не удаляются: удаление каскадом стёрло бы отметки о выполнении и номера актов. Повторяющиеся коды и периодичность ≤ 0 дают ответ 400.

**Что учесть перед релизом:**
