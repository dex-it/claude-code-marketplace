Провёл ревью MR !238. Нашёл 4 критичных дефекта, которые ломают основную функциональность задач спринта, плюс ряд менее серьёзных проблем. Полный список сохранён в `_answer.md`.

## Критичные (блокируют мердж)

1. **`VehicleService.cs` — `ReplaceEquipmentAsync`**: `FindVehicleAsync` не делает `Include(Equipment)`, поэтому `vehicle.Equipment.Clear()` чистит пустой список, а старые записи `vehicle_equipment` в БД не удаляются. Комплектация не заменяется, как требует FLEET-104, а при совпадении кодов вставка упадёт на уникальном индексе.

2. **`VehicleService.cs` — `GetLastInspectionAsync`**: сортировка по `CreatedAt` (время приёма сервером) вместо `InspectedAt` (время самого осмотра). Из-за офлайн-синхронизации планшетов это может "подсунуть" диспетчеру старый чистый осмотр вместо актуального с блокирующим замечанием — машина уедет на линию, хотя не должна. Критично для безопасности (FLEET-107).

3. **`TripService.cs` — `OffDayTripsAsync`**: `WorkCalendar.IsWorkingDay` внутри `Select`, после которого навешаны `Where`/`OrderBy`, не транслируется EF Core в SQL — метод будет падать с исключением при каждом вызове. Весь отчёт FLEET-109 неработоспособен, и похоже, что его не тестировали.

4. **`TripService.cs` — `GetOpenWaybillsAsync`**: в `FromSqlRaw` оставлена точка с запятой в конце SQL. Пока фильтра по машине нет — работает; как только передан `vehicleId`, EF оборачивает запрос в подзапрос, и точка с запятой внутри скобок — синтаксическая ошибка Postgres. То есть именно фильтр по машине (FLEET-112) не работает, а в MR протестирован только вариант без фильтра.

## Остальное

5. Off-by-one в проверке допуска (`StartTripAsync`): `ValidUntil > today` должен быть `>=` — противоречит описанию "действует включительно" (high).
6. У `PUT /api/vehicles/{id}/equipment` в `Program.cs` не задана ролевая политика авторизации, в отличие от всех остальных мутирующих эндпоинтов (high).
7. Миграция уменьшает `Vehicle.Model` до 40 символов без очистки данных — упадёт на проде, если есть более длинные значения (high).
8. Нет проверки на уже открытый путевой лист при выпуске машины/водителя на линию (medium).
9. Индекс `Inspection(VehicleId, CreatedAt)` рассчитан на неверное поле сортировки, связано с п.2 (medium).
10. Тихий `DistinctBy` по коду оборудования без диагностики дублей (low).
11. Нет ограничения на неотрицательность `Qty` (low).
