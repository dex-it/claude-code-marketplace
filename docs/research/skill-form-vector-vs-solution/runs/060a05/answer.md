**Решения**
- **Миграция.** Создаёт «Теплицу №1» и добавляет `sensors.greenhouse_id` сразу как `NOT NULL DEFAULT <id этой теплицы>`. Так старые датчики привязываются к ней без перезаписи таблицы. Ещё это нужно потому, что в pipeline миграция идёт раньше выкатки: старая версия приложения какое-то время работает с новой схемой и всё равно должна регистрировать датчики. `DEFAULT` нужно снять отдельной миграцией в следующем релизе. Площадь «Теплицы №1» неизвестна, поэтому колонка допускает NULL; для новых теплиц площадь обязательна. `ModelSnapshot` в репозитории нет, поэтому атрибуты `[DbContext]`/`[Migration]` прописаны прямо в файле миграции; snapshot стоит пересоздать.
- **Время приёма.** `TakenAt` хранится в местном времени площадки, поэтому время приёма переводится из UTC в часовой пояс из нового ключа конфигурации `Monitoring:SiteTimeZone`. Если ключ не задан, такие показания отклоняются с понятной ошибкой, а остальные показания пакета принимаются. Ключ нужно добавить в конфигурацию production до выкатки. Конструктор сервиса теперь принимает ещё `IConfiguration`.
- **Отчёт.** Переписан с сырого SQL на LINQ. Фильтр по метке сделан через `ILIKE`, а `%`, `_` и `\` во введённом фрагменте экранируются, чтобы он искался как обычный текст. Попутно убрана подстановка значений в SQL-строку, и сортировка теперь гарантированно сохраняется. `RegisterSensorAsync` и `ReportRow` изменили сигнатуру, поэтому места их вызова нужно обновить.
