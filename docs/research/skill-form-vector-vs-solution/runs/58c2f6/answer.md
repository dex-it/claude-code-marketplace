## Critical

**1. `Controllers/ContestsController.cs` — `Ranking`, `RankingCsv`: эксперты видят рейтинг.**
- **Что не так:** роль Expert добавили на весь класс, чтобы открыть экспертам `GET /api/contests/{id}`. Вместе с этим экспертам стали доступны `ranking` и `ranking.csv`.
- **Почему это дефект:** любой эксперт видит баллы всех заявок, в том числе пока экспертиза ещё идёт. Это ломает слепую экспертизу.

**2. `Controllers/ReviewsController.cs` — `Mine`: два запроса параллельно на одном `DbContext`.**
- **Что не так:** два запроса к одному `DbContext` запускаются одновременно через `Task.WhenAll`.
- **Почему это дефект:** EF Core такого не допускает и бросает `InvalidOperationException` («A second operation was started…»). Список «мои назначения» будет отдавать 500. Это нарушает правило SKILL «Время жизни DbContext».
- **Исправление:** выполнять запросы по очереди или считать `Submitted` по уже загруженному списку.

## High

**3. `Services/ConflictOfInterest.cs` — `Find`: не проверяется организация эксперта.**
- **Что не так:** код проверяет только, что эксперт не сам заявитель. Сравнения `OrganizationInn` эксперта и заявки нет.
- **Почему это дефект:** по п. 4.3 положения эксперт не оценивает и заявки своего работодателя. MR обещает, что конфликт система проверяет сама, так что такие заявки будут назначаться без проверки.

**4. `Models/Contest.cs` — `AcceptsReviews`: приём закрывается в начале дня дедлайна.**
- **Что не так:** граница стоит на 00:00 UTC дня дедлайна, это около 03:00 МСК.
- **Почему это дефект:** эксперты, которые досылают оценки в последний вечер, получат отказ.
- **Исправление:** граница на `ReviewDeadline.AddDays(1)`, по московскому времени.

**5. `Services/RankingService.cs` — `BuildAsync`: при равном балле сортировка не по дате подачи.**
- **Что не так:** используется `ThenBy(CreatedAt)`, то есть дата создания черновика.
- **Почему это дефект:** по положению выше та заявка, которая подана раньше. На границе фонда это меняет, кто получит грант.
- **Исправление:** `ThenBy(SubmittedAt)`, затем `ThenBy(Id)`.

**6. `Services/RankingCsvWriter.cs` — `Write`: числа ломают CSV.**
- **Что не так:** `Score` и `RequestedAmount` форматируются по культуре ru-RU, которую задаёт `UseRequestLocalization`. Получается `87,50` без кавычек.
- **Почему это дефект:** колонки сдвигаются, и Google Sheets и скрипт фонда получат неверные суммы.
- **Исправление:** форматировать с `CultureInfo.InvariantCulture`.

**7. `Controllers/ApplicationsController.cs` — `Search`: поиск по региону падает.**
- **Что не так:** `string.Equals(..., StringComparison.OrdinalIgnoreCase)` не переводится в SQL.
- **Почему это дефект:** любой поиск по региону завершится ошибкой (`InvalidOperationException`, 500). Это правило SKILL «Нетранслируемое условие фильтра».
- **Исправление:** `EF.Functions.ILike` или `ToLower()` с обеих сторон.

**8. `Services/AssignmentService.cs` — `ReassignAsync`: черновик переходит новому эксперту целиком.**
- **Что не так:** в `Draft` переносятся `Scores`, `Comment` и `Total` прежнего эксперта.
- **Почему это дефект:** новый эксперт видит чужие баллы, что ломает слепую экспертизу, и может отправить чужую оценку как свою.
- **Исправление:** при передаче очищать оценки и возвращать статус `Assigned`.

**9. `ReviewService.SaveAsync`, `AssignmentService.ReassignAsync`, `ContestsController.CloseReview`: одновременные правки одной оценки молча перезаписываются.**
- **Что не так:** у `Review` нет concurrency token. Возможные гонки:
  - передача назначений может увести уже отправленную оценку другому эксперту;
  - оценка эксперта может записать `Submitted` поверх `Expired`, который поставило закрытие экспертизы;
  - двойная отправка или черновик одновременно с отправкой может затереть отправленную оценку или дать `DbUpdateConcurrencyException` (500).
- **Почему это дефект:** нарушается правило SKILL «Параллельная правка одной записи».
- **Исправление:** concurrency token `xmin` и ответ 409 на конфликт, либо условный `ExecuteUpdate` с проверкой статуса.
