Нашёл 9 дефектов. Самые важные: доза препарата в `CalculateDoseMlAsync` получается в 1000 раз больше нужной, а в листе дня пропадает первая страница. Код не менял, сборку и тесты не запускал. Ответ записан в `_answer.md`.

## 1. `Services/ProcedureService.cs` — `CalculateDoseMlAsync`: доза в 1000 раз больше нужной — **critical**
Код считает `doseMg = weightGrams * drugMgPerKg`: вес берётся в граммах, а доза задана в мг на килограмм. Перевода граммов в килограммы нет, хотя в комментарии написано «вес, кг × мг/кг».
- **Пример:** кот весом 4000 г при дозе 2,5 мг/кг и концентрации 10 мг/мл получит 1000 мл вместо 1 мл.
- **Почему это дефект:** персонал набирает инфузию по этому числу, то есть ошибка прямо вредит пациенту.
- **Исправление:** `weightGrams / 1000m * drugMgPerKg`, плюс тест на известных значениях.

## 2. `Domain/Pet.cs` (`WeightGrams`) и `CalculateDoseMlAsync`: если веса нет, доза молча равна 0 — **high**
`WeightGrams` — обязательный `int`, поэтому миграция создаст колонку `NOT NULL DEFAULT 0`.
- У всех существующих питомцев вес станет 0. То же будет у новых, которых ещё не взвешивали.
- Метод вернёт 0 мл без ошибки, и врач не узнает, что веса нет.
- **Исправление:** сделать поле `int?`; при `null` или `<= 0` бросать понятную ошибку («питомец не взвешен»).

## 3. `Services/ProcedureSheetService.cs` — `GetDaySheetAsync`: первая страница теряется — **high**
По контракту страницы считаются с 1, а код пропускает `page * PageSize` строк.
- При `page=1` пропадают первые 30 процедур дня. В обычный день, когда процедур меньше 30, лист дня пустой.
- Значение `page < 1` не проверяется.
- **Исправление:** `Skip((page - 1) * PageSize)` и проверка `page >= 1`.

## 4. `Services/ProcedureService.cs` — `RemoveConsumableAsync`: гонка с закрытием процедуры и загрузка всех строк — **medium**
- **Гонка:** статус проверяется в памяти, а удаление происходит позже, в `SaveChanges`. Защиты от параллельной правки нет. Если процедуру в это время закрыли, строку всё равно удалят из закрытого списания, хотя README это запрещает.
- **Лишняя загрузка:** `Include(p => p.Consumables)` поднимает все строки расходников, чтобы удалить одну. У инфузий их сотни.
- **Исправление:** удалять одним запросом `ExecuteDeleteAsync` с условием `ProcedureId == procedureId && Procedure.Status != Closed`. Если удалено 0 строк, отдельно различить «не найдено» и «закрыта». Другой вариант — токен конкурентности на `xmin` у `Procedure`.
- Сам `Remove` при каскаде по умолчанию работает корректно и исключения не бросает.

## 5. `Data/ClinicDbContext.cs` и `RescheduleAsync`: нет защиты от параллельной правки — **medium**
У `Procedure` нет токена конкурентности.
- Если между проверкой `Status == Scheduled` и сохранением процедуру начали, закрыли или отменили, перенос всё равно применится.
- Два одновременных переноса молча перезапишут друг друга.
- **Исправление:** токен на `xmin` (`[Timestamp] public uint Version`) и обработка `DbUpdateConcurrencyException`. Другой вариант — `ExecuteUpdate` с проверкой статуса в `WHERE`.

## 6. `Data/ClinicDbContext.cs` — связь `Procedure → Pet`: каскадное удаление истории — **medium**
Связь обязательная, поэтому EF создаёт внешний ключ с `ON DELETE CASCADE`.
- Удаление карточки питомца удалит все его процедуры, а за ними строки списания и заметки персонала, в том числе по закрытым процедурам.
- Сломаются отчёт по расходу за прошлые месяцы и журнал кабинета.
- **Исправление:** `.OnDelete(DeleteBehavior.Restrict)`.

## 7. `Services/ProcedureSheetService.cs` — `SearchNotesAsync`: ищет не там и без индекса — **low**
- Метод ищет только по полю `Procedures."Notes"`. Заметки персонала лежат в `StaffNotes.Text` и в поиск не попадают, хотя MR обещает поиск по заметкам. Требование стоит уточнить.
- Полнотекстовый поиск идёт без GIN-индекса, поэтому каждый запрос читает всю таблицу.
- Инъекции нет: значение передаётся параметром.

## 8. `Services/ProcedureService.cs` — `GetCardAsync`: случайный порядок расходников и лишние поля — **low**
- Расходники выводятся без сортировки, и в карточке строки будут менять порядок. Нужен `OrderBy(c => c.Id)`.
- `Include(Pet)` загружает всю карточку питомца ради одного имени. Проекция в DTO прямо в запросе была бы дешевле.
- Раздельные запросы (`AsSplitQuery`) для двух коллекций здесь оправданы.

## 9. `RescheduleAsync`, `RemoveConsumableAsync`, `CalculateDoseMlAsync`: «не найдено» отдаёт 500 — **low**
`SingleAsync` по несуществующему id бросает `InvalidOperationException`, и клиент получит 500 вместо 404. Лучше `SingleOrDefaultAsync` плюс `KeyNotFoundException`, как уже сделано для строки расходника.

В чек-листе сказано помечать прочитанное значение как `Utc`, но здесь этого делать нельзя: время по часам кабинета исказится. `CreatedAt` записывается в UTC в колонку с поясом — это верно.
