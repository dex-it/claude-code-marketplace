## Ревью MR «Списание баллов лояльности»

**1. Отрицательный/нулевой `confirm_amount` не валидируется** — `app/redeem.py:20-28`. Клиент может передать `confirm_amount = -100`, проверка `amount > balance` не сработает, и вычитание отрицательного числа **увеличит** баланс баллов. **critical**

**2. Гонка между чтением и записью баланса (TOCTOU)** — `app/redeem.py:16-29`, `app/repo.py:16-29`. `get_member`/`save_member` — два независимых соединения без блокировки строки или оптимистичной блокировки → возможно двойное списание при параллельных запросах. **critical**

**3. Списание и запись аудита не атомарны** — `app/repo.py:24-37`. `save_member` и `write_audit` — два отдельных commit'а; при сбое между ними баллы спишутся без аудиторского следа, что противоречит требованию MR. **high**

**4. `confirm_amount` фактически необязателен в pydantic v1** — `app/schemas.py:8-18`. Комментарий предполагает поведение pydantic v2; в закреплённой версии `pydantic==1.10.13` `Optional[X]` без `Field(...)` даёт `default=None`, т.е. поле необязательно. Пропуск поля клиентом приведёт к молчаливому списанию **всего** баланса. **critical**

**5. `POINT_VALUE = 0.1` (float) обёрнут в `Decimal`** — `app/redeem.py:11`. `Decimal(0.1)` содержит бинарную погрешность; нужно `Decimal("0.1")`. Влияет на все денежные расчёты. **high**

**6. Усечение (`int(...)`) при пересчёте суммы в баллы** — `app/redeem.py:28`. Дробная часть отбрасывается в сторону нуля, а в ответе возвращается запрошенная `amount`, а не фактически списанная — расхождение между ответом API и реальным состоянием. **medium**

**7. Неиспользуемое обязательное поле `points`** — `app/schemas.py:10`, `app/redeem.py`. Объявлено, но не участвует в логике — несогласованный контракт API. **medium**

**8. Комментарий про отклонение лишних полей не соответствует реальности** — `app/schemas.py:16-17`. По умолчанию в pydantic v1 лишние поля игнорируются (`Config.extra` не задан как `forbid`), а не отвергаются. **medium**

**9. Срок действия баллов не хранится и не проверяется** — `app/redeem.py:32-38`, `app/repo.py` (`Member`). `valid_until` только вычисляется и возвращается, expiry нигде не enforced — заявленная в MR фича фактически не реализована. **high**

**10. Аудит фиксирует только входной запрос, без результата операции** — `app/repo.py:32-37`. Нет данных о фактически списанной сумме и балансе до/после — недостаточно для финансового аудита. **medium**

**11. `HTTPException(status_code=404)` без `detail`** — `app/redeem.py:18`. **low**

**12. Отсутствие идемпотентности запроса** — `app/redeem.py`. Повтор запроса (retry после таймаута) приведёт к повторному списанию. **medium**
