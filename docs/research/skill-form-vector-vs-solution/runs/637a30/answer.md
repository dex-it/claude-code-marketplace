**Решения:**
- **Чтение заказов.** Результат проецируется в DTO, поэтому отслеживания изменений нет и прокси ленивой загрузки наружу не попадают; фильтр soft-delete применяется.
  - Карточка одного заказа (а) грузится одним запросом (`AsSingleQuery`): позиций и платежей у одного заказа немного.
  - Выгрузка по клиенту (б) идёт через `AsSplitQuery`, иначе на тысячах заказов строки позиций и платежей перемножаются. Но части такого запроса не читают один снимок данных, так что при параллельных изменениях выгрузка может разойтись.
- **(в) `GetProductBySku`.** Склад объявлен как `string?`.
  - Если склад передан, ищется одна запись по паре SKU и склада.
  - Если склад `null` и товар есть только на одном складе, возвращается он. Если на нескольких, метод бросает `AmbiguousSkuException`, чтобы не отдавать случайный.
  - Уникального индекса по SKU и складу в модели нет. Его стоит добавить отдельной миграцией после проверки данных.
- **(г) Дата последней отгрузки.** Максимум считается в базе.
  - Если у клиента нет отгруженных заказов, метод бросает `InvalidOperationException`: тип `DateTime` не допускает null, а подставлять значение по умолчанию было бы неверно. Стоит обсудить с бизнесом, не сделать ли тип `DateTime?`.
  - У `ShippedAt` не задан тип колонки, поэтому Npgsql 8 хранит её как `timestamp with time zone` и возвращает дату в UTC. У `CreatedAt` тип `without time zone`.
