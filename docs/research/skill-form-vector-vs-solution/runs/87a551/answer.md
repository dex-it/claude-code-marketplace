- `FreezeService.cs` — новый файл: заморозка и снятие заморозки, проверка «заморожен ли абонемент в момент X», отдельное исключение для заморозки.
- `Models.cs` — новая сущность `MemberFreeze` (заморозки абонемента).
- `StudioDbContext.cs` — добавлены `DbSet<MemberFreeze>` и индекс.
- `ScheduleService.cs` — запись на занятие отклоняется с 409, если абонемент заморожен на момент начала занятия; добавлен выбор случайного занятия для «тайного гостя».
- `TurnstileWorker.cs` — при заморозке проход не засчитывается: запись остаётся «записан», в журнале пометка «абонемент заморожен». Плюс отдельный DbContext на каждую пачку проходов.
- `Program.cs` — endpoints `POST /members/{id}/freeze` и `DELETE /members/{id}/freeze`, `GET /quality/random-session`, ответ 409 при записи.

**Решения**
- **Заморозки хранятся отдельной таблицей с историей.** При досрочном снятии конец заморозки сдвигается на текущий момент. Турникет проверяет заморозку на время прохода, а запись — на время начала занятия, поэтому проход, обработанный с задержкой, оценивается правильно.
- **Срок и ошибки заморозки.** Срок считается как «сейчас + N дней», N от 1 до 365, а не по календарным суткам. Повторная заморозка — 409, снятие несуществующей — 404.
- **Случайное занятие выбирается в два шага: сначала Id, потом данные по нему.** В проекте для всех запросов включён режим split query. Если загружать всё одним запросом, случайная сортировка выполнилась бы дважды, и вернулись бы записавшиеся другого занятия. Берутся только опубликованные курсы, отменённые записи исключаются.
- **Исправил ошибку в обработчике турникета, которую нашёл по ходу.** Раньше он держал один DbContext всё время работы. Из-за этого он мог отметить как «посетил» запись, которую уже отменили через API.
