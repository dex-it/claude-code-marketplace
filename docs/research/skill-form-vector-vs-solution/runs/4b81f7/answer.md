Ревью MR !231 готово: 9 находок, из них критическая — ошибка в расчёте дозы. Код не менял, сборку и тесты не запускал. Тот же текст записан в `_answer.md`.

1. **critical** — `Services/ProcedureService.cs`, `CalculateDoseMlAsync`
   - **Что не так:** `weightGrams * drugMgPerKg` — вес в граммах подставлен вместо килограммов.
   - **Почему дефект:** объём инфузии выходит в 1000 раз больше. Кошка 4 кг, 2,5 мг/кг, концентрация 10 мг/мл → 1000 мл вместо 1 мл. Это прямой риск для животного.
   - **Исправление:** `weightGrams / 1000m * drugMgPerKg` и тест на известное значение.

2. **high** — `Domain/Pet.cs` (`WeightGrams`) и `CalculateDoseMlAsync`
   - **Что не так:** поле `int` без null, поэтому «не взвешен» неотличимо от веса 0.
   - **Почему дефект:** миграция поставит 0 всем уже заведённым питомцам, и расчёт молча вернёт 0 мл.
   - **Исправление:** `int?` и ошибка при `null` или `<= 0`. Миграцию в MR не показали, её нужно проверить отдельно (в том числе перенос веса, если он уже где-то хранится).

3. **high** — `Services/ProcedureSheetService.cs`, `GetDaySheetAsync`
   - **Что не так:** по контракту страницы нумеруются с 1, а код делает `Skip(page * PageSize)`.
   - **Почему дефект:** `page=1` пропускает первые 30 процедур дня. В обычный день, когда процедур меньше 30, лист вообще пустой. Отрицательный `page` не проверяется и роняет запрос.
   - **Исправление:** `(page - 1) * PageSize` и проверка `page >= 1`.

4. **medium** — `ProcedureService.RemoveConsumableAsync`
   - **Что не так:** статус проверяется в памяти, а удаление идёт отдельным шагом, без concurrency token и без блокировки.
   - **Почему дефект:** если процедуру закроют параллельно, строка удалится из уже закрытого списания. Это нарушает правило из README.
   - **Исправление:** одним `ExecuteDeleteAsync` с условием `Procedure.Status != Closed`, либо `FOR UPDATE` в явной транзакции, либо токен `xmin`. Попутно уйдёт лишняя загрузка всех расходников, а у инфузий их сотни.

5. **medium** — `ProcedureService.RescheduleAsync`
   - **Что не так:** на `Procedure` нет concurrency token.
   - **Почему дефект:** из двух одновременных переносов последний молча затирает первый. Перенос проходит, даже если процедуру параллельно начали или отменили.
   - **Исправление:** `xmin` с обработкой `DbUpdateConcurrencyException`, либо `ExecuteUpdateAsync` с условием `WHERE Status = Scheduled`.

6. **medium** — `Data/ClinicDbContext.cs`, связь `Procedure → Pet`
   - **Что не так:** связь обязательная, по умолчанию `ON DELETE CASCADE`.
   - **Почему дефект:** удаление питомца сотрёт его процедуры, списания расходников и заметки персонала, то есть медицинский учёт и данные отчёта по расходу.
   - **Исправление:** `OnDelete(DeleteBehavior.Restrict)`.

7. **low** — `SingleAsync` по id в `RescheduleAsync`, `RemoveConsumableAsync`, `CalculateDoseMlAsync`
   - **Что не так:** для несуществующего id бросается `InvalidOperationException`.
   - **Почему дефект:** это то же исключение, что и для бизнес-ошибок по статусу, и клиент получит 500 вместо 404.
   - **Исправление:** `SingleOrDefaultAsync` и `KeyNotFoundException`, как уже сделано для строки расходника.

8. **low** — `ProcedureSheetService.SearchNotesAsync`
   - **Что не так:** ищется только `Procedure.Notes`, заметки персонала (`StaffNotes`) в поиск не попадают. Индекса для полнотекстового поиска нет.
   - **Почему дефект:** в MR заявлен «поиск по заметкам» — стоит уточнить, входят ли туда заметки персонала. Без индекса запрос читает всю таблицу процедур.
   - **Исправление:** уточнить требование; добавить GIN-индекс по выражению.

9. **low** — `ProcedureSheetService.GetConsumptionAsync`
   - **Что не так:** при `sort = null` бросается `ArgumentNullException` вместо ожидаемого `ArgumentException`.
   - **Почему дефект:** клиент получит 500 вместо понятной ошибки о неверной сортировке.
   - **Исправление:** проверка на null/пустую строку или значение по умолчанию. Белый список для `ORDER BY` и параметры запроса сделаны корректно.
