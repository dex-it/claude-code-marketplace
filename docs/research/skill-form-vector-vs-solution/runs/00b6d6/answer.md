Провёл ревью, ответ записан в `_answer.md`. Основные находки:

**Critical**
1. `schemas.py: RedeemRequest.confirm_amount` — комментарий про обязательность поля неверен для Pydantic v1 (`Optional[X]` без default автоматически = `Optional[X] = None`), поэтому поле фактически необязательное — старый клиент без этого поля получит полное списание баланса, а не 422.
2. `redeem.py: redeem()` — нет проверки `confirm_amount > 0`; отрицательное значение проходит проверку баланса и **увеличивает** баланс баллов вместо списания.
3. `redeem.py`/`repo.py` — гонка (race condition): чтение и запись баланса в разных соединениях/транзакциях без блокировки строки → возможен double-spend при параллельных запросах.
4. `redeem.py: redeem()` — `save_member` и `write_audit` выполняются в двух разных транзакциях, не атомарно: сбой между ними даёт списание без аудиторской записи, что нарушает главное требование MR.

**High**
5. `redeem.py: POINT_VALUE = 0.1` (float) → `Decimal(POINT_VALUE)` тянет бинарную погрешность float в денежные расчёты; нужно `Decimal("0.1")`.
6. `redeem.py: write_audit` пишет сырой `req.dict()`, а не фактическую сумму/баланс до-после — при `confirm_amount=null` в аудите останется `null` вместо реально списанной суммы.
7. Срок действия баллов нигде не персистится и не используется — `valid_until` только вычисляется на лету и возвращается в ответе, фича по факту не реализована.
8. Отсутствует авторизация на `/redeem` — любой может списать баллы по произвольному `member_id` (потенциальный IDOR).

**Medium**
9. `schemas.py` — комментарий про отклонение лишних полей неверен (Pydantic v1 по умолчанию `Extra.ignore`, не `forbid`), `Config.extra="forbid"` не задан.
10. `schemas.py: RedeemRequest.points` — обязательное поле нигде не используется в `redeem()`.
11. `redeem.py` — усечение (`int(...)`) при обратной конвертации суммы в баллы без явного округления.

**Low**
12. Нигде не найдено создание `FastAPI()`/`include_router` — приложение может быть не смонтировано (возможно, вне диффа).
