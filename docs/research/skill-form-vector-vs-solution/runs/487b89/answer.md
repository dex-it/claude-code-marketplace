Решения:
- **Загрузка клиентов.** Входной список id читается один раз, дубли убираются. Клиенты загружаются пачками по 5000: один запрос на пачку, а не на каждого клиента. Npgsql передаёт пачку в запрос одним параметром-массивом (`= ANY(@array)`). Из базы берётся только `Email`, без отслеживания изменений (`AsNoTracking`).
- **Кому уходит письмо.** Каждый email получает одно письмо: пустые адреса и повторы (без учёта регистра) пропускаются. Id, которых нет в базе, пропускаются без ошибки.
- **Сигнатура.** Метод асинхронный (`Task`, `CancellationToken`), потому что `IEmailSender.SendAsync` асинхронный.
- **Тема и ошибки.** Тема в поручении не указана, поэтому стоит константа `"Shop"`. Письма уходят по одному. Если отправка одного письма падает, рассылка останавливается: повторных попыток нет, остальные письма не уходят.
