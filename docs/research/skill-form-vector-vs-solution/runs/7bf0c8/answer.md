## Результаты ревью MR !87

Проанализировал изменения согласно правилам EF Core команды (SKILL.md). Найдены **4 дефекта**, из них 2 критических:

### 🔴 CRITICAL (2)

**1. BatchService.cs:49 — Сломана пагинация в ListAsync**
- Используется `Skip(page * pageSize)` вместо `Skip((page - 1) * pageSize)`
- При page=1 пропустит первые 20 элементов вместо показа первой страницы
- Это делает непригодной функцию LAB-141 (постраничный вывод партий)

**2. BatchService.cs:105 — Нетранслируемое условие в CompliancePercentAsync**
- `.All()` на коллекции `s.Results` в SQL-запросе
- Results не загружена через Include, поэтому будет исключение InvalidOperationException
- Нужна переделка логики: либо `!s.Results.Any(r => r.Value > r.Limit)`, либо другой подход

### 🟠 HIGH (1)

**3. BatchService.cs:107 — Целочисленное деление**
- `compliant / total * 100` вернёт 0 для любого значения < 100%
- Нужно: `(compliant * 100) / total` или приведение к decimal
- Также не обработан случай `total = 0`

### 🟡 MEDIUM (1)

**4. LabDbContext.cs:25 — Неправильная конфигурация DateTime для PlannedLocal**
- Поле хранит местное время объекта, но при чтении из БД будет помечено как Utc
- Нарушает правило 18 про DateTime и типы колонок в Npgsql
- Нужна ValueConverter для явного указания Kind=Unspecified при чтении

Детальный отчёт записан в `_answer.md`. Рекомендация: **исправить критические дефекты перед мержем** — код упадёт в runtime.
