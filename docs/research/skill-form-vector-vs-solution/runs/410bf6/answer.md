## Решения
- **Поиск.** Для каждого значения `scope` своя фиксированная SQL-ветка, текст поиска передаётся параметром. Выражения поиска написаны в точности как в индексах из README, иначе индексы не используются. Для диагноза это `coalesce`, для препаратов — выборка через `IN` по `Prescriptions`, чтобы визиты не повторялись. Если `scope` не передан, поиск идёт по жалобе, как раньше; неизвестное значение даёт 400. Добавил сортировку по Id, чтобы страницы не «плавали» при нескольких визитах в одном слоте.
- **Карточка.** Все данные берутся одним запросом. В `Program.cs` глобально включена загрузка коллекций отдельными запросами, но для одного визита явно задан один запрос: анализов и назначений немного, а три запроса дали бы лишние обращения к базе. Время выводится по местному времени клиники.
- **CSV.** Местные даты переводятся в диапазон UTC от начала `from` до начала дня после `to` и попадают в индекс `(VetId, SlotStart)`. Строки читаются из базы потоком и сразу пишутся в ответ, так что 100 тыс. приёмов не собираются в памяти. Число назначений считается в SQL.

## Что стоит подтвердить
- **Какой визит считать последним.** Я беру визиты в статусе «идёт» или «завершён», без запланированных и отменённых. Если в одном слоте у питомца несколько визитов (совместный приём), берётся визит с большим Id.
- **Какие приёмы выгружать бухгалтерии.** Выгружаются только завершённые; запланированные, отменённые и текущие не попадают.
- **Формат CSV.** Разделитель `;` и UTF-8 с BOM — чтобы русский Excel открыл файл сразу. Значения в кавычках, где нужно. Если текст жалобы или диагноза начинается с `=`, `+`, `-` или `@`, перед ним ставится апостроф, чтобы Excel не выполнил его как формулу. Побочный эффект: жалоба вида «- рвота» выгрузится с апострофом в начале.
