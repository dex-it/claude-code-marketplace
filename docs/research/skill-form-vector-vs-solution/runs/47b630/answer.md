Нашёл 18 дефектов: 2 critical, 6 high, 8 medium и 2 low. Код я не менял, сборку и тесты не запускал, поэтому все находки сделаны по чтению кода. Тот же список записан в `_answer.md`.

## Critical

**1. `Migrations/20260915120000_DriverDisplayNameAndTripRoute.cs`, `Up`: ФИО всех водителей будут потеряны**
- **Проблема:** переименование сделано как `DropColumn("full_name")` + `AddColumn("display_name", defaultValue: "")`. EF при `migrations add` не распознаёт переименования и генерирует такую пару сам, а автор её не поправил.
- **Почему дефект:** на prod колонка `full_name` со всеми данными удаляется, у всех водителей остаётся пустое имя. `Down` тоже не возвращает данные.
- **Как исправить:** `RenameColumn("full_name", "drivers", "display_name")`.

**2. `TripService.cs`, `SearchAsync`: SQL-инъекция через параметр `route`**
- **Проблема:** значение подставляется в SQL через интерполяцию строки и `FromSqlRaw`. `SqlText.LikeContains` экранирует `\`, `%` и `_`, но не одинарную кавычку.
- **Почему дефект:** запрос вида `?route=x' OR 1=1 --` исполняется в БД. Это доступно любому пользователю с ролью fleet-manager.
- **Как исправить:** передавать значение параметром: `FromSql($"...{pattern}")` или `EF.Functions.ILike(t.Route, pattern, "\\")`.

## High

**3. `Program.cs`, `PUT /api/drivers/{id}/permits`: нет политики `Hr`**
- **Проблема:** у этого endpoint'а нет `.RequireAuthorization("Hr")`, хотя у соседнего `/name` она есть.
- **Почему дефект:** любой аутентифицированный пользователь, в том числе сам водитель, может выдать себе допуск к любому классу техники.

**4. `DriverService.cs`, `ReplacePermitsAsync` (+ `FleetDbContext`): замена допусков падает**
- **Проблема:** связь обязательная (`DriverId` типа `int`) и настроена с `DeleteBehavior.NoAction`. При таком поведении EF Core не удаляет допуски, удалённые из коллекции через `Permits.Clear()`, а бросает `InvalidOperationException` («relationship ... has been severed»).
- **Почему дефект:** метод работает только для водителя без допусков, для остальных будет 500. Основной сценарий FLEET-97 не работает.
- **Как исправить:** `RemoveRange(driver.Permits)` или `Cascade`/`ClientCascade` для этой связи.

**5. `TripService.cs`, `MileageAsync`: пользовательский метод внутри LINQ-запроса**
- **Проблема:** `WorkCalendar.IsWorkingDay` вызывается внутри `IQueryable.Where`.
- **Почему дефект:** EF не может перевести его в SQL, и отчёт всегда падает с «could not be translated».
- **Как исправить:** считать выходные в памяти или передавать в запрос список нерабочих дат.

**6. `TripService.cs`, `ImportWaybillsAsync`: московское время записывается без перевода в UTC**
- **Проблема:** время разбирается `ParseExact` с `Kind=Unspecified` и пишется как есть.
- **Почему дефект:** в Npgsql с EF Core 8 `DateTime` по умолчанию идёт в `timestamptz`, и запись `Unspecified` туда запрещена, так что импорт падает. В legacy-режиме все поездки сдвинутся на 3 часа.
- **Как исправить:** конвертировать из `Europe/Moscow` в UTC.

**7. `MileageAsync` / `WorkCalendar.IsWorkingDay`: дни и выходные считаются по UTC, а должны по Москве**
- Субботняя поездка в 01:00 МСК (пятница 22:00 UTC) считается рабочей. Это именно ночные выезды, ради которых сделан контроль личного использования.
- Поездки с 00:00 до 03:00 МСК первого дня выпадают из периода, а поездки последнего дня после 21:00 МСК попадают в соседний период.

**8. `TripService.cs`, `GetVehicleByPlateAsync`: `SingleAsync` без фильтра по списанию**
- **Проблема:** уникальный индекс по госномеру действует только для несписанных машин, так что номер списанной машины может повторно числиться за новой.
- **Почему дефект:** для такого номера `SingleAsync` бросит «more than one element» и уронит импорт.
- **Как исправить:** фильтровать по `DecommissionedAt == null` и выдавать понятную ошибку, если машина не найдена.

## Medium

**9. `TripService.cs`, `MileageAsync`: деление на ноль**
- `totalKm / count` при отсутствии поездок бросает `DivideByZeroException`, и клиент получает 500.
- Три отдельных запроса без транзакции могут дать несогласованные цифры. Нет проверки `from <= to`.

**10. `TripService.cs`, `ImportWaybillsAsync`: одна плохая строка роняет весь файл с 500 и без номера строки**
- Причины:
  - госномер не найден;
  - табельного номера нет в справочнике (`drivers[c[1]]`);
  - в строке меньше 8 полей, в том числе пустая строка в конце файла;
  - пустая дата возврата;
  - маршрут длиннее 500 символов.
- `Split(';')` не учитывает CSV-кавычки, так что `;` внутри маршрута сдвигает колонки.
- Не проверяется, что одометр на возврате не меньше одометра на выезде.

**11. `TripService.cs`, `ImportWaybillsAsync`: импорт не идемпотентен**
- Нет ключа дедупликации, поэтому повторная загрузка файла удваивает поездки и пробег.

**12. `TripService.cs`, `ImportWaybillsAsync`: кодировка выгрузки**
- `StreamReader` по умолчанию читает UTF-8, а 1С обычно выгружает в Windows-1251.
- Маршрут и цель сохранятся нечитаемыми, и поиск по маршруту (FLEET-91) по ним не работает.

**13. `Infrastructure/WorkCalendar.cs`: календарь заведён только на 2026 год и, по-видимому, неполон**
- Для других лет праздники молча игнорируются.
- По памяти, 9 января и 31 декабря 2026 — нерабочие дни (перенос с 3 и 4 января), а в списке их нет. Это нужно сверить с официальным производственным календарём.

**14. Миграция: не видно `.Designer.cs` и обновлённого `ModelSnapshot`**
- Без атрибутов `[Migration]` и `[DbContext]` bundle миграцию не найдёт.
- Без обновлённого snapshot следующая миграция повторит те же изменения.

**15. `DriverService.cs`, `GetAsync` / `DriverDto`: ломающее изменение API**
- JSON-поле `fullName` стало `displayName` без версии и без переходного периода, существующие клиенты перестанут показывать имя водителя.

**16. `RenameAsync` / `ReplacePermitsAsync` + `Program.cs`: 500 вместо 404 и 400**
- `KeyNotFoundException` не превращается в 404.
- В `RenameAsync` нет проверки входных данных: `null` даёт NullReferenceException, пустое имя принимается, имя длиннее 200 символов вызывает `DbUpdateException`.

## Low

**17. `DriverService.cs`, `ReplacePermitsAsync`: при дубле класса берётся первая запись**
- `DistinctBy(p => p.Class)` оставляет первую запись, а не с самым поздним `ValidUntil`, поэтому допуск может оказаться короче реального.

**18. `TripService.cs`, `SearchAsync`: поиск `ILIKE '%...%'` без индекса**
- Без trigram-индекса каждый такой поиск полностью сканирует `trips`, и таблица растёт с каждым ежедневным импортом.
