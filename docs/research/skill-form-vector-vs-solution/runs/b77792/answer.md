Посмотрел все восемь изменённых файлов из `MR.md` и нашёл 13 дефектов, которые стоит исправить до мерджа: 3 critical, 6 high, 2 medium, 2 low. Код не запускал и не собирал. Тот же список записан в `_answer.md`.

## Critical
1. **`Services/ReviewService.cs`, `SaveAsync`**: оценка ищется только по id, а `review.ExpertId == expertId` не проверяется. Любой эксперт может сохранить или отправить чужую оценку, перебирая id. Отправленную оценку потом менять нельзя, поэтому порча останется навсегда.
2. **`Controllers/ApplicationsController.cs`, `Get`**: эксперт получает все отправленные оценки коллег: имя, балл, комментарий. Это нарушает требование слепой экспертизы. Полный список оценок нужно отдавать только координатору.
3. **`Services/RankingService.cs`, `BuildAsync`**: два запроса к одному `DbContext` запускаются параллельно через `Task.WhenAll`. `DbContext` этого не допускает и выбросит `InvalidOperationException`, рейтинг будет отвечать ошибкой 500.

## High
4. **`RankingService.BuildAsync`**: средний балл считается по всем назначениям, включая черновики, а также `Assigned` и `Expired` с баллом 0. По описанию MR нужно учитывать только отправленные экспертизы.
5. **`RankingService.BuildAsync`**: условие `SubmittedReviews > MinReviews` требует четыре экспертизы вместо трёх. Заявки ровно с тремя экспертизами выпадают из рейтинга.
6. **`RankingService.BuildAsync`**: после первой заявки, на которую не хватило денег, флаг `budgetExhausted` оставляет без гранта все следующие. По описанию остаток должен переходить к следующим заявкам.
7. **`ReviewService.SaveAsync` / `ScoreItem`**: балл ограничен только диапазоном 0–10 без учёта `MaxScore` критерия. По 5-балльному критерию можно поставить 10, и итог эксперта превысит 100.
8. **`Controllers/ReviewsController.cs`, `Save`**: результат `Invalid` попадает в ветку по умолчанию и возвращает 204. Эксперт видит «успешно», хотя оценка не сохранена и не отправлена.
9. **`ApplicationsController.Search`**: `Equals(..., StringComparison.OrdinalIgnoreCase)` EF Core с Npgsql в SQL не переводит. Поиск по `?region=` будет падать с ошибкой. Вместо этого подойдёт `ToLower()`, `ILike` или `citext`.

## Medium
10. **`ReviewService.SaveAsync`, `ContestsController.CloseReview`**: нет контроля одновременных запросов.
    - Отправка, начатая до закрытия экспертизы, перезапишет статус «истёкшая» на «отправлена».
    - Два одновременных сохранения одной оценки проходят оба.
    - Два одновременных закрытия экспертизы тоже проходят оба.
11. **`ContestsController.Assign`**: признак закрытой экспертизы не проверяется, поэтому после закрытия можно создать новые назначения. Для несуществующего конкурса возвращается 422 вместо 404.

## Low
12. **`ContestsController.Assign`**: два одновременных назначения одной заявки одному эксперту упираются в уникальный индекс, и второй запрос получает 500.
13. **`ReviewService.CalculateTotal`**: если у всех критериев вес 0 (или максимальный балл 0), происходит деление на ноль и ответ 500.
