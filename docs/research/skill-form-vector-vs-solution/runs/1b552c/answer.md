**Решения:**
- **Повторная загрузка.** Строка пропускается, если её `BankRef` уже есть среди платежей или неразобранных; повторы внутри одного файла тоже пропускаются. Вся выписка загружается в одной транзакции. Баланс увеличивается одним атомарным `UPDATE`, поэтому одновременные изменения баланса не теряются. Если ту же выписку загружают параллельно, второй запрос откатывается и получает 409.
- **Возврат в Active.** После зачисления абоненты в статусе Suspended с неотрицательным балансом переводятся в Active, время записывается в `ReactivatedAt`. Платежи по закрытым договорам и с суммой ≤ 0 я тоже отправляю в неразобранные с указанием причины — это моё решение, в задаче этого не было.
- **Поиск по телефону.** Телефоны записаны в разном формате, поэтому в базе есть колонка с цифрами телефона в обратном порядке. Тогда поиск «заканчивается на 4518» идёт по индексу как поиск по началу строки. Для существующих абонентов колонка заполнится сама. Принимается от 4 до 15 цифр, не больше 20 результатов, сортировка по Id.
