Изменённые файлы:
- `Model.cs` — поле `Order.Complexity`, конвертер для `CreatedAt`, проверка в БД для `Complexity`, связи Order -> Items и Order -> Payments
- `OrderRepository.cs` — метод `ClearItems(Guid orderId)`
- `_answer.md` — этот ответ

Решения:
- **Complexity** — обычное поле `int` с проверкой в БД на диапазон 1..5, без отдельного типа из одного поля. Существующим заказам нужно значение по умолчанию или заполнение отдельной миграцией данных, иначе миграция с проверкой не пройдёт. Какое значение ставить — решает бизнес.
- **CreatedAt**: колонка остаётся `timestamp without time zone`. При записи время в UTC уходит с `Kind=Unspecified`, потому что Npgsql не даёт писать `Kind=Utc` в такую колонку. При чтении ставится только метка UTC, время не сдвигается в локальное.
- **Мягкое удаление**: в БД каскадного удаления нет. Для Items стоит `ClientCascade`: с `Restrict` EF бросил бы исключение на `Items.Clear()`, потому что ссылка на заказ у позиции обязательная. Для Payments стоит `Restrict`.
- **ClearItems** загружает заказ вместе с позициями (удалённые заказы отсекает фильтр `IsDeleted`), очищает список и сохраняет. EF удаляет позиции из БД. Если заказа нет или он удалён, метод бросает `KeyNotFoundException`.
