Решения:
- **Заказы.** Все методы отдают DTO, а не сущности, поэтому нет трекинга и лишней подгрузки связанных данных. Карточка одного заказа читается одним запросом: позиций и платежей у одного заказа мало. Выгрузка всех заказов клиента читается отдельными запросами по коллекциям (`AsSplitQuery`) с сортировкой по дате и Id. Так при тысячах заказов позиции и платежи не перемножаются в одной выборке.
- **`GetProductBySku`.** Если склад передан, продукт ищется по паре SKU + склад. Если склада нет, а SKU лежит на нескольких складах, метод выбрасывает исключение, а не возвращает случайный склад. Полный список по складам можно получить через добавленный метод `GetProductsBySku`. Советую добавить уникальный индекс по SKU и складу отдельной миграцией.
- **Дата последней отгрузки.** Максимальная дата считается в БД, заказы без даты отгрузки отфильтрованы. Если у клиента нет отгруженных заказов, метод выбрасывает исключение: по условию он возвращает не nullable `DateTime`, а иначе пришлось бы молча вернуть пустую дату. Удалённые заказы (soft-delete) в расчёт не попадают.
