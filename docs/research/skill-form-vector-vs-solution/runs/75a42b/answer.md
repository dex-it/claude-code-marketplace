Я посмотрел все файлы из MR вместе с README и `.gitlab-ci.yml`. Код не менял, сборку и тесты не запускал. Нашёл 14 дефектов: 1 critical, 7 high, 4 medium, 2 low. Тот же список записан в `_answer.md`.

## Critical

**1. `Services/InpatientReportService.cs` — `GetOccupancyAsync`: SQL-инъекция.**
- **Что не так:** параметры `ward` и `sortBy` приходят из query string и вставляются в текст запроса для `FromSqlRaw` (`'{ward}'`, `s."{sortBy}"`).
- **Почему это дефект:** любой вошедший пользователь, включая администратора ресепшена, может выполнить свой SQL под ролью `vet_app`: прочитать, изменить или удалить данные.
- **Как исправить:** `ward` передавать параметром через `FromSql($"...")`. Сортировку делать через LINQ `OrderBy` по списку разрешённых столбцов.

## High

**2. `Data/ClinicDbContext.cs` — глобальный фильтр `HasQueryFilter(!IsDecommissioned)` на `Box`.**
- **Что не так:** у госпитализации бокс обязателен, поэтому EF присоединяет таблицу боксов с этим фильтром. Госпитализации в выведенных боксах выпадают из результатов.
- **Почему это дефект:** по README пациенты выведенного бокса должны оставаться в списках, пока их не выписали. Сейчас они пропадают:
  - из списка отделения (`GetWardPatientsAsync`);
  - из списка на обход главврача (`GetLongStaysAsync`);
  - из отчёта о занятости (`GetOccupancyAsync`).
- **Самое серьёзное:** `DischargeAsync` для такого пациента падает с ошибкой, то есть его нельзя выписать. Карточка такого бокса (`GetBoxCardAsync`) отвечает 404.
- **Как исправить:** убрать глобальный фильтр и исключать выведенные боксы явно только при выборе бокса для поступления.

**3. `Services/WardService.cs` — `DischargeAsync`: неверный расчёт стоимости.**
- **Что не так:** не хватает `+1` при подсчёте дней. По README считаются и день поступления, и день выписки.
- **Почему это дефект:** каждый счёт занижен на один суточный тариф, а выписка в день поступления стоит 0.

**4. `Api/InpatientEndpoints.cs` — эндпоинт выписки (`/discharge`): нет проверки, что это врач.**
- **Что не так:** стоит `RequireAuthorization()` без политики `Vet`.
- **Почему это дефект:** выписать пациента может администратор ресепшена, хотя по README это разрешено только врачу.

**5. `Services/WardService.cs` — `ReplaceMedicationPlanAsync`: смена плана назначений.**
- **Что не так:** `MedicationOrders.Clear()` отвязывает старые назначения, а удаление для этой связи запрещено (`Restrict`).
- **Почему это дефект:** при сохранении EF бросает `InvalidOperationException`, поэтому план с существующими назначениями поменять нельзя (500). Если «починить» это каскадным удалением, назначения начнут физически удаляться, а по README они остаются в медкарте и только помечаются `CancelledAt`.
- **Как исправить:** проставлять `CancelledAt` действующим назначениям и добавлять новые.
- **Чего ещё не хватает:**
  - проверки, что пациент не выписан;
  - проверки входных данных: при пустом `Drug` будет NullReferenceException, `TimesPerDay` и `DoseMg` могут быть ≤ 0, `Route` не сверяется со списком.

**6. `Services/WardService.cs` — `GetLongStaysAsync`: запрос не выполняется.**
- **Что не так:** `DaysInWard` — вычисляемое свойство в C#, EF не может перевести его в SQL.
- **Почему это дефект:** `/long-stays` всегда отвечает 500.
- **Как исправить:** сравнивать `AdmittedOn` с датой, вычисленной заранее.
- **Попутно:** `DaysInWard` считает дни не так, как счёт (без дня поступления), и берёт дату по UTC, поэтому около полуночи «сегодня» сдвигается.

**7. `Services/WardService.cs` — `GetBoxCardAsync`: несколько пациентов в боксе.**
- **Что не так:** используется `SingleOrDefaultAsync`, а по README в боксе может лежать несколько животных (помёт, питомцы одного владельца).
- **Почему это дефект:** если в боксе больше одного пациента, карточка отвечает 500. Ответ с одним полем `PetName` тоже не подходит — нужен список.

**8. `Program.cs` — миграции при старте приложения (`MigrateAsync`).**
- **Нет прав:** в проде приложение работает под `vet_app` без прав менять схему. Если образ с новой миграцией окажется в кластере раньше, чем выполнена `db-migrate` (откат, повторный деплой), приложение упадёт при старте и будет перезапускаться по кругу.
- **Гонки:** три реплики при rolling update запускают миграцию одновременно, а в EF Core 8 нет блокировки миграций.
- **Обход процесса:** миграция применяется мимо ревью DBA и джобы `db-migrate`.
- **Как исправить:** убрать или оставить только для Development.

## Medium

**9. `Services/WardService.cs` — `GetLatestStayAsync`: «последняя» госпитализация выбирается неоднозначно.**
- **Что не так:** сортировка только по дате поступления, без времени.
- **Почему это дефект:** при повторной госпитализации в тот же день врач может увидеть утреннюю, уже закрытую.
- **Как проявляется с `AsSplitQuery`:** назначения и наблюдения могут загрузиться неконсистентно.
- **Как исправить:** добавить `ThenByDescending(s => s.Id)`.

**10. `Services/InpatientReportService.cs` — `GetOccupancyAsync`: сортировка теряется.**
- **Что не так:** EF оборачивает написанный вручную SQL в подзапрос, а `ORDER BY` внутри подзапроса не задаёт порядок итогового результата.
- **Почему это дефект:** сортировка по столбцу с экрана не работает.

**11. `Data/ClinicDbContext.cs` — каскадное удаление медданных.**
- **Что не так:** для связей госпитализации с питомцем и боксом и наблюдения с госпитализацией правило удаления не задано, поэтому миграция создаст каскадное удаление.
- **Почему это дефект:**
  - удаление бокса или питомца удалит госпитализации и наблюдения, если у госпитализации нет назначений;
  - если назначения есть, удаление упадёт — поведение ещё и разное.
- **Как исправить:** задать для этих связей `Restrict`.

**12. `Services/WardService.cs` — `DischargeAsync`: нет защиты от параллельных запросов.**
- **Что не так:** нет проверки конкурентных изменений (например, `xmin` в Npgsql).
- **Почему это дефект:** две одновременные выписки обе пройдут проверку «уже выписан», и последняя перезапишет дату и сумму.
- **Попутно:** дату выписки в будущем никто не отклоняет.

## Low

**13. `Services/WardService.cs` — `FindBoxByCodeAsync`: выведенные боксы не находятся.**
- **Что не так:** глобальный фильтр скрывает выведенные боксы, а уникальность кода в БД действует и на них.
- **Почему это дефект:** если метод используют для проверки уникальности кода, он скажет «свободно», а сохранение упадёт на уникальном индексе.

**14. `WardService` — `DecommissionBoxAsync`, `ReplaceMedicationPlanAsync`, `DischargeAsync`: 500 вместо 404/400.**
- **Что не так:** при несуществующем id `SingleAsync` бросает исключение, и клиент получает 500 вместо 404.
- **Почему это дефект:**
  - повторный вывод уже выведенного бокса тоже даёт 500;
  - ошибки проверок в `DischargeAsync` («уже выписан», «дата раньше поступления») не превращаются в 400/409.
