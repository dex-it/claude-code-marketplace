**Решения:**
- **(а) и (б):** данные загружаются через `AsNoTracking` + `Include(Items)` + `Include(Payments)` + `AsSplitQuery`. Если грузить обе коллекции одним запросом, строки перемножаются (Items × Payments). В (б) сначала берутся только Id заказов клиента, затем заказы грузятся пачками по 500 и отдаются потоком через `IAsyncEnumerable`. Так тысячи заказов со всеми позициями не лежат в памяти одновременно.
- **(в):** параметр `warehouse` сделан nullable. Если склад не передан и SKU есть на нескольких складах, метод выбрасывает `InvalidOperationException`, а не возвращает случайную запись. Советую добавить уникальный индекс `(Sku, Warehouse)`. Я его не добавлял, потому что для этого нужна миграция.
- **(г):** берётся `Max` по `(DateTime?)ShippedAt`, чтобы не получить ошибку «Sequence contains no elements». Если у клиента нет отгруженных заказов, выбрасывается `InvalidOperationException`, а не возвращается `DateTime.MinValue`. Удалённые заказы отсекаются глобальным фильтром `IsDeleted`.

**Проблема в модели:** включён `UseLazyLoadingProxies`, но `Items`, `Payments` и `Customer.Orders` не объявлены `virtual`. Прокси требуют virtual-навигации, поэтому при построении модели, скорее всего, будет исключение. Это стоит исправить отдельно: либо сделать навигации `virtual`, либо отказаться от прокси.
