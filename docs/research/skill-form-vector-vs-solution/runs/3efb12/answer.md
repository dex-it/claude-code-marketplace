Решения:
- **Заморозка хранится как интервал.** Досрочное снятие ставит `FrozenUntil = now`. Повторная заморозка поверх действующей даёт 409, `DELETE` идемпотентен. Для турникета проверка идёт по времени прохода, а не обработки, для записи — по началу занятия.
- **Ошибка в воркере.** Раньше он держал один DbContext всё время работы, и уже загруженный `Member` не перечитывался из БД. Без исправления заморозка и разморозка через API до турникета не доходили бы.
- **«Тайный гость».** Занятие выбирается через `ORDER BY random()` среди будущих занятий опубликованных курсов на 7 дней вперёд; если таких нет — 404.

Что осталось сделать:
- **Миграция:** в проекте нет каталога Migrations, а новые колонки в `Members` нужно добавить в БД (`dotnet ef migrations add MemberFreeze`).
- **Доступ:** авторизации в проекте нет, поэтому эндпоинты заморозки и `/quality` сейчас доступны всем.
