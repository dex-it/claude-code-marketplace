**Critical**
1. **`TripService.cs` - `OffDayTripsAsync`: отчёт FLEET-109 не работает.**
   - **Что не так:** значение `OffDay` вычисляется в C# через `WorkCalendar.IsWorkingDay`, и EF не может перевести его в SQL. Пока такая проекция стоит последней в запросе, EF вычисляет её на клиенте. Но здесь после неё идут `.Where(r => r.OffDay)` и `.OrderByDescending(r => r.Km)`, и запрос падает с `InvalidOperationException ... could not be translated`.
   - **Последствие:** эндпоинт всегда отвечает 500.
   - **Как исправить:** загрузить поездки за месяц, а фильтровать и сортировать в памяти.
2. **`Migrations/...VehicleEquipmentAndModelLength.cs` - `Up` и `FleetDbContext` (`Model` 200 -> 40): миграция упадёт на prod.**
   - **Что не так:** PostgreSQL при `ALTER ... TYPE varchar(40)` не обрезает строки, а падает с ошибкой `22001`. Длинные названия на prod точно есть: в описании MR сказано, что принтер их обрезал. На dev их, видимо, нет, поэтому там миграция прошла.
   - **Последствия:** смена типа переписывает таблицу под полной блокировкой. После миграции новые названия длиннее 40 символов будут давать 500.
   - **Как исправить:** 40 символов - это ограничение печатной формы, обрезать надо при печати, а колонку оставить на 200.

**High**
3. **`VehicleService.cs` - `ReplaceEquipmentAsync`: комплектация не заменяется.**
   - **Что не так:** машина загружается без `Include(v => v.Equipment)`, поэтому `Clear()` очищает пустой список и старые записи остаются в БД.
   - **Последствие:** уже второй запрос с тем же кодом нарушает уникальный индекс `(vehicle_id, code)` (500). С другими кодами старые позиции просто накапливаются. В `ReplacePermitsAsync` для допусков `Include` есть.
   - **Мелочи (low):** дубликаты кодов молча отбрасываются с учётом регистра, `Qty` никак не проверяется.
4. **`Program.cs` - `PUT /vehicles/{id}/equipment`: нет политики авторизации.**
   - **Что не так:** у остальных изменяющих эндпоинтов политика есть, а здесь комплектацию может перезаписать любой вошедший пользователь.
   - **Как исправить:** нужен `RequireAuthorization("Mechanic")`.
5. **`VehicleService.cs` - `GetLastInspectionAsync`: «последний осмотр» выбирается неверно.**
   - **Что не так:** сортировка идёт по `CreatedAt`, то есть по времени приёма сервером, а не по времени осмотра. Планшеты отправляют осмотры пачкой в одной транзакции, а `now()` возвращает время начала транзакции, поэтому у всей пачки `CreatedAt` одинаковый.
   - **Последствие:** «последним» может оказаться ранний чистый осмотр вместо свежего с блокирующим замечанием, и неисправная машина уйдёт на линию. Пачка, пришедшая с опозданием, тоже собьёт выбор.
   - **Как исправить:** сортировать по `InspectedAt`, затем по `Id`, и добавить индекс под эту сортировку.
6. **`TripService.cs` - `GetOpenWaybillsAsync`: фильтр по машине ломает запрос.**
   - **Что не так:** в сыром SQL есть `ORDER BY` и `;` в конце. Если добавить `.Where`, EF оборачивает этот SQL в подзапрос, и из-за `;` получается синтаксическая ошибка (500). Даже без `;` сортировка внутри подзапроса не гарантирована.
   - **Почему не заметили:** вариант без фильтра работает, его и проверяли («по всему парку»).

**Medium**
7. **`StartTripAsync`: в последний день срока допуск считается недействительным.** В коде `ValidUntil > today`, а по требованию допуск действует включительно, то есть нужно `>=`.
8. **`StartTripAsync`: нет проверки, что машина или водитель уже в рейсе.**
   - **Что не так:** одну машину можно выпустить дважды, например при повторном нажатии или работе двух диспетчеров одновременно.
   - **Как исправить:** частичный уникальный индекс по поездкам с `finished_at IS NULL` (для машины и для водителя) и ответ 409 при нарушении.

**Low**
9. **`/trips/off-days`: параметры не проверяются.** При некорректных `year` или `month` (например, `month` = 13) клиент получает 500 вместо 400.
