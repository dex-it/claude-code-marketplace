## Critical

**1. `Services/InpatientReportService.cs` → `GetOccupancyAsync` — SQL-инъекция через `ward` и `sortBy`.**
- `ward` и `sortBy` приходят из query string и через интерполяцию C# вставляются прямо в текст SQL для `FromSqlRaw`. Как параметры (`DbParameter`) они не передаются.
- Например, `ward=' OR 1=1 --` выполнится как SQL. Эндпоинт доступен любому авторизованному пользователю.
- **Исправление:** `ward` передавать параметром или переписать запрос на LINQ. `sortBy` сопоставлять с белым списком через `switch` → `OrderBy(...)`, на неизвестное значение отвечать 400.

## High

**2. Фильтр `HasQueryFilter(!IsDecommissioned)` на `Box` прячет пациентов выведенного бокса.**
- Затронуты `ClinicDbContext.cs`, `WardService.GetWardPatientsAsync` / `GetLongStaysAsync` / `DischargeAsync` / `GetBoxCardAsync` и `InpatientReportService.GetOccupancyAsync`.
- Связь `Stay → Box` обязательная, поэтому EF делает INNER JOIN с уже отфильтрованной таблицей `Boxes`.
- В итоге пациенты из выведенного бокса пропадают из списков отделения и отчёта. README прямо запрещает это: они должны оставаться в списках до выписки.
- В `DischargeAsync` `Include(Box)` + `SingleAsync` бросает исключение, то есть такого пациента нельзя выписать.
- Карточка такого бокса отдаёт 404.
- **Исправление:** фильтровать `!IsDecommissioned` только в запросе выбора бокса при поступлении. Другой вариант — `IgnoreQueryFilters()` во всех запросах через `Stay`.

**3. `WardService.GetLongStaysAsync` — эндпоинт всегда падает.**
- `DaysInWard` — вычисляемое свойство, которого нет в БД. EF Core 8 не может перевести его в SQL и бросает `InvalidOperationException`, так что обход главврача не работает.
- **Исправление:** сравнивать дату поступления с границей: `AdmittedOn < today.AddDays(-14)`.

**4. `WardService.ReplaceMedicationPlanAsync` — `Clear()` по обязательной связи с `Restrict`.**
- Если в плане есть хотя бы одно назначение, `SaveChanges` бросает `InvalidOperationException`. Автор проверял сценарий на новом питомце, поэтому это не всплыло.
- Переключать связь на Cascade тоже нельзя: по README назначения не удаляются физически, отменённым ставится `CancelledAt`.
- **Исправление:** ставить активным назначениям `CancelledAt = DateTime.UtcNow` и добавлять новые, коллекцию не очищать.

**5. `WardService.DischargeAsync` — счёт занижен на один день.**
- По README считаются дни включая день поступления и день выписки, значит нужно `+1`.
- Сейчас каждый счёт меньше на суточный тариф, а при выписке в день поступления счёт равен 0.

**6. `Api/InpatientEndpoints.cs` → `/stays/{id}/discharge` — выписать может кто угодно.**
- Стоит `.RequireAuthorization()` без политики. По README выписку оформляет только врач.
- **Исправление:** `.RequireAuthorization("Vet")`.

**7. `WardService.GetBoxCardAsync` — `SingleOrDefaultAsync` на неуникальном условии.**
- Условие «текущий пациент бокса» не уникально: в бокс помещается до `Capacity` животных.
- Если в боксе два пациента или больше, получаем исключение и 500.
- **Исправление:** вернуть список пациентов через проекцию (только нужные поля) и поменять `BoxCardDto`.

**8. `Program.cs` — `MigrateAsync()` при старте приложения.**
- В проде приложение работает под ролью `vet_app` без прав на DDL. Если найдётся неприменённая миграция, поды уйдут в бесконечный рестарт.
- Это обходит принятый процесс: SQL-скрипт, просмотр DBA, ручной `db-migrate`.
- 3 реплики стартуют одновременно, а в EF 8 нет блокировки миграций, поэтому возможны гонки.
- Мотивация «не забывать `db-migrate`» не работает: `deploy` и так зависит от `db-migrate`.
- **Исправление:** убрать блок или оставить его только для Development.

## Medium

**9. `DischargeAsync` и `ReplaceMedicationPlanAsync` — нет защиты от одновременной правки.**
- Два параллельных запроса на выписку оба пройдут проверку «уже выписан», и последний молча перезапишет `TotalCost`.
- Два врача, одновременно меняющие план, получат перемешанный набор назначений.
- **Исправление:** токен конкурентности на `xmin` и ответ 409 на `DbUpdateConcurrencyException`. Для выписки подойдёт и условный `ExecuteUpdate`.

**10. `WardService.GetLatestStayAsync` — «последняя» госпитализация выбирается случайно.**
- Сортировка идёт только по дате, а повторная госпитализация в тот же день допустима.
- При раздельных запросах (`AsSplitQuery()`) назначения и наблюдения могут подтянуться от разных госпитализаций.
- **Исправление:** добавить `ThenByDescending(s => s.Id)`.

**11. `ClinicDbContext` / миграция `AddInpatient` — каскадное удаление медкарты.**
- Связи `Stay → Box`, `Stay → Pet` и `Observation → Stay` по умолчанию получат `ON DELETE CASCADE`.
- Физическое удаление бокса или питомца сотрёт историю госпитализаций и наблюдений. При этом `Box` удаляется мягко (через флаг).
- **Исправление:** поставить `Restrict`. Миграцию стоит приложить к MR.

**12. `GetOccupancyAsync` — сортировка может потеряться.**
- `ORDER BY` стоит внутри сырого SQL, который EF оборачивает в подзапрос. PostgreSQL не гарантирует, что этот порядок сохранится во внешнем запросе.
- **Исправление:** сортировать в LINQ после проверки по белому списку (см. п. 1).

## Low

**13. `GetLatestStayAsync` — лишние данные из БД.**
- Загружаются полные сущности, а отменённые назначения отфильтровываются уже в памяти.
- **Исправление:** проекция в `StayCardDto` с фильтром и сортировкой в SQL.

**14. `DecommissionBoxAsync` — повторный вызов даёт 500.**
- Из-за фильтра уже выведенный бокс не находится, и `SingleAsync` бросает исключение.
- **Исправление:** `IgnoreQueryFilters()` и явная проверка состояния бокса.
