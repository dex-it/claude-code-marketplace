**Решения:**
- `Loan.IsOverdue`/`OverdueDays` считаются в C# и не переводятся в SQL. Поэтому в запросах условие просрочки записано явно (`ReturnedAt == null && DueDate < today`), а дни считаются после загрузки. Сортировка по `DueDate` по возрастанию, самые старые просрочки сверху.
- В выгрузке (б) контакты маскируются в загруженных строках, а не в записях `Reader`. Если бы маскировка меняла сами записи, сохранение ExportLog записало бы `***6789` в карточки читателей. Сумма считается по всем невозвращённым просроченным книгам по текущей ставке; ранее начисленный `FineBalance` в неё не входит. Номер билета в выгрузке полный, как на экране карточки. Файл в UTF-8 с BOM, разделитель `;`, ячейки, похожие на формулы, экранируются. Без заголовка `X-User` ответ 400. Сам заголовок ничем не проверяется: кто его прислал, тот и попадёт в журнал.
- В отчёте (в) даты из формы считаются местными (`Library:TimeZone`). Начало суток переводится в UTC, конец периода — начало следующего дня (не включается), поэтому выдачи ночью 1-го числа не попадают в прошлый месяц. Филиалы без выдач показываются с нулём; если `from > to`, ответ 400. «Сегодня» для просрочек, как и раньше в `Loan`, определяется по UTC, поэтому до 03:00 МСК дни просрочки могут быть на один меньше.
