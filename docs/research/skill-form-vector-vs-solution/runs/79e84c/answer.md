## Критичные/высокие дефекты

**1. `BatchService.CompliancePercentAsync` — неверная арифметика** (critical)
`compliant / total * 100` — целочисленное деление выполняется раньше умножения, из-за чего процент почти всегда получается 0 (кроме 100%). Плюс `DivideByZeroException`, если у партии 0 проб (упадёт дашборд LAB-147).

**2. Та же функция (и `GetCardAsync`) — проба без результатов засчитывается как «в норме»** (high)
`Results.All(r => r.Value <= r.Limit)` на пустой коллекции результатов возвращает `true` (vacuous truth), поэтому непроанализированные пробы искажают процент соответствия и признак превышения.

**3. `BatchService.ListAsync` — ошибка на единицу в пагинации** (high)
Комментарий говорит, что `page` с 1, но `Skip(page * pageSize)` для `page=1` пропускает первую страницу результатов — пользователь никогда не увидит самые новые партии.

**4. `BatchService.CloseAsync` — проверка «без результатов» покрывает не все пробы** (high)
`GetInAnalysisForBatchAsync` берёт только пробы со статусом `InAnalysis`; пробы в `Planned`/`Collected` (у которых результатов нет по определению) игнорируются и не блокируют закрытие партии — нарушение заявленного правила LAB-143.

## Средние/низкие

**5.** `CloseAsync` не проверяет, что партия уже закрыта — повторный вызов молча перезатирает `ClosedAt`/`ReportDate` (medium).

**6.** `GetCardAsync` — нет `OrderBy` для `Samples`/`Instruments`, порядок в карточке партии не гарантирован (low).

**7.** В `LabDbContext` нет уникального индекса `(SampleId, Tag)` для `SampleTag` — дедупликация только на уровне кода (low).
