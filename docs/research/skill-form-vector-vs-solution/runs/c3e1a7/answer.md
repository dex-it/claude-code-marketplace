Я провёл ревью MR !214 и нашёл 13 дефектов: 1 critical, 7 high, 3 medium и 2 low. Код не менял, сборку и тесты не запускал. Тот же текст записан в `_answer.md`.

## Critical

**1. `Services/InpatientReportService.cs` — `GetOccupancyAsync`: SQL-инъекция.**
- `ward` и `sortBy` приходят из query string и подставляются в SQL через интерполяцию, затем выполняются через `FromSqlRaw`.
- Эндпоинт доступен любому аутентифицированному пользователю: `ward=x' OR 1=1 --` или `sortBy=Id"; DROP TABLE ...--`.
- **Исправить:** передавать `ward` параметром. `sortBy` сверять с белым списком и сортировать через LINQ `OrderBy`.

## High

**2. `Data/ClinicDbContext.cs`, глобальный фильтр на `Box` (`HasQueryFilter`): пациенты в выведенном боксе пропадают.**
- `Stay → Box` — обязательная навигация. EF Core применяет фильтр боксов и в JOIN/Include этой навигации, поэтому госпитализации в выведенном боксе выпадают из результатов (EF предупреждает об этом, код 10622).
- `GetWardPatientsAsync`, `GetLongStaysAsync` и отчёт по занятости теряют этих пациентов. Это нарушает правило README: госпитализированные остаются в списках до выписки.
- `GetBoxCardAsync` отдаёт 404 по боксу, в котором лежат пациенты.
- `DischargeAsync` падает на `SingleAsync`, то есть такого пациента нельзя выписать.
- **Исправить:** убрать глобальный фильтр и проверять `!IsDecommissioned` явно, только при выборе бокса для поступления.

**3. `WardService.GetLongStaysAsync`: запрос не переводится в SQL.**
- `DaysInWard` — вычисляемое C#-свойство, в модели его нет. `Where(s => s.DaysInWard > 14)` даёт `InvalidOperationException`, и `/long-stays` всегда отвечает 500.
- **Исправить:** фильтровать по `AdmittedOn < today.AddDays(-14)`.

**4. `WardService.DischargeAsync`: неверная стоимость.**
- По README считаются все дни, включая день поступления и день выписки. Код считает на 1 день меньше, а при выписке в день поступления выходит 0.
- Та же ошибка есть в `Stay.DaysInWard`.
- **Исправить:** `days = ... + 1`.

**5. `Api/InpatientEndpoints.cs` — `POST /stays/{id}/discharge`: не та политика авторизации.**
- Стоит `RequireAuthorization()` без политики `Vet`, а по README выписывает только врач. Сейчас это может сделать ресепшен.

**6. `WardService.ReplaceMedicationPlanAsync`: `Clear()` удаляет назначения.**
- Вызов разрывает обязательную связь. При `Restrict` EF бросает исключение на `SaveChanges`, и замена плана не работает совсем.
- Если перейти на Cascade, назначения начнут физически удаляться, а README это запрещает: отмена делается через `CancelledAt`.
- **Исправить:** у текущих назначений ставить `CancelledAt` и добавлять новые. Желательно ещё валидировать вход и запретить менять план после выписки.

**7. `WardService.GetBoxCardAsync`: `SingleOrDefaultAsync` при вместимости больше 1.**
- По README в боксе может быть до `Capacity` животных. Если там больше одного пациента, метод бросает исключение и эндпоинт отвечает 500.
- `BoxCardDto` рассчитан только на одного пациента; нужен список.

**8. `Program.cs`: миграции при старте приложения (`MigrateAsync`).**
- В проде приложение работает под ролью `vet_app` без прав на DDL, поэтому при любой неприменённой миграции под уходит в crash-loop.
- Запуск при старте обходит ревью DBA и джобу `db-migrate`.
- 3 реплики при rolling update будут мигрировать одновременно, а блокировки миграций в EF 8 нет.
- Локальная проверка в MR шла под суперпользователем docker-postgres и прод-условия не отражает.
- **Исправить:** убрать автомиграцию, максимум оставить её под `IsDevelopment()`.

## Medium

**9. `WardService.GetLatestStayAsync`: «последняя» госпитализация выбирается случайно.**
- Повторная госпитализация в тот же день возможна, а сортировка только по `AdmittedOn` без вторичного ключа. Врач может увидеть закрытую утреннюю госпитализацию вместо текущей.
- **Исправить:** добавить `ThenByDescending(s => s.Id)`.

**10. `InpatientReportService.GetOccupancyAsync`: сортировка теряется.**
- EF оборачивает SQL с `ORDER BY` в подзапрос и добавляет JOIN, а PostgreSQL не гарантирует сохранение порядка подзапроса. Решается тем же переходом на LINQ `OrderBy`, что и в п. 1.

**11. `WardService.DischargeAsync`: гонка при двойной выписке.**
- Нет токена конкурентности или условного UPDATE. Два одновременных запроса пройдут проверку, и счёт может пересчитаться с другой датой.
- **Исправить:** `xmin` как токен конкурентности или `ExecuteUpdate ... WHERE "DischargedOn" IS NULL`.

## Low

**12. `WardService.DecommissionBoxAsync` / `FindBoxByCodeAsync`: побочные эффекты глобального фильтра.**
- Повторный вывод бокса отвечает 500 вместо 404 или 204.
- Выведенный бокс не находится по коду, хотя уникальный индекс по `Code` его учитывает: создать бокс с тем же кодом нельзя, а найти старый тоже нельзя.

**13. Эндпоинты: доменные ошибки превращаются в 500.**
- `SingleAsync` для несуществующего id, «Пациент уже выписан» и неверная дата выписки отвечают 500 вместо 404/409/400.
