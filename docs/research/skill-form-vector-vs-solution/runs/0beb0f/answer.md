Я проверил весь код этого MR (это новый код) и нашёл 11 дефектов, из них 3 critical. Этот же список записан в `_answer.md`.

Поведение библиотек я сверял с документацией тех версий, что указаны в `requirements.txt` (pydantic 1.10.13, fastapi 0.95.2, SQLAlchemy 1.4.49), и с документацией Python по `decimal`. Context7 в этой сессии не было, поэтому документацию я открывал напрямую. Код не запускал: по условиям нельзя, и доступа к shell у меня нет.

## Critical

**1. `app/schemas.py` — `RedeemRequest.confirm_amount`: поле не обязательное, пропуск списывает весь баланс.**
- **Что не так:** комментарий говорит, что `Optional` без значения по умолчанию делает поле обязательным. В pydantic 1.10 это неверно: такое поле необязательное и по умолчанию получает `None`. Обязательным оно становится только с `= ...` или `Field(...)`. Так в документации pydantic 1.10, раздел «Required Optional fields». Обязательным такое поле стало только в pydantic v2.
- **Почему дефект:** старый клиент не присылает поле и вместо обещанного 422 теряет весь баланс.
- **Исправление:** `confirm_amount: Optional[Decimal] = ...`.

**2. `app/schemas.py` — `RedeemRequest`: лишние поля не отвергаются.**
- **Что не так:** комментарий говорит, что pydantic по умолчанию отвергает лишние поля. В pydantic 1.10 по умолчанию стоит `Extra.ignore`: лишние поля молча отбрасываются.
- **Почему дефект:** клиент ошибся в имени поля (например, `confirm_amout`), в `confirm_amount` приходит `None`, и списывается весь баланс.
- **Исправление:** `class Config: extra = Extra.forbid`.

**3. `app/redeem.py` — `redeem`: отрицательная сумма не проверяется и начисляет баллы.**
- **Что не так:** `confirm_amount` не проверяется на знак.
- **Почему дефект:** при `confirm_amount = -1000` проверка баланса проходит, а `points -= int(-…)` увеличивает баланс. Любой клиент может начислить себе баллы без ограничений.
- **Исправление:** `condecimal(gt=0)` в схеме.

## High

**4. `redeem`, `get_member`, `save_member` — гонка при одновременных запросах, двойное списание.**
- **Что не так:** баланс читается в одной транзакции, а записывается абсолютным `UPDATE … SET points = :p` в другой. Строка не блокируется (`FOR UPDATE`), атомарного `points = points - :d WHERE points >= :d` тоже нет.
- **Почему дефект:** два параллельных запроса оба проходят проверку баланса и тратят одни и те же баллы; последняя запись затирает первую.

**5. `redeem`, `save_member`, `write_audit` — списание и аудит не атомарны.**
- **Что не так:** обе функции коммитят через отдельные `engine.begin()`.
- **Почему дефект:** если запись аудита упадёт, баллы уже списаны, а следа операции нет.

**6. `redeem` — `POINT_VALUE = 0.1` хранится как float.**
- **Что не так:** `Decimal(0.1)` даёт `0.1000000000000000055511151231…` (это прямо сказано в документации Python `decimal`), и вся денежная арифметика идёт с этим хвостом.
- **Почему дефект:** клиенту возвращаются суммы вида `10.00000000000000055…`. Частичное списание 5,05 ₽ даёт 50,4999… балла, дальше срабатывает п.7.
- **Не проверено:** возможно, при полном списании на счёте остаётся 1 балл. Это моё предположение, пробу я не запускал.
- **Исправление:** `Decimal("0.1")` и явное округление до копеек через `quantize`.

**7. `redeem` — `int()` отбрасывает дробную часть, клиенту сообщают о списании больше, чем реально списано.**
- **Что не так:** количество баллов считается через `int()`, а в ответе `redeemed` — полная запрошенная сумма.
- **Почему дефект:** запрос на 0,05 ₽ списывает 0 баллов, но в ответе `redeemed=0.05`. Если по этому полю выдаётся скидка, её можно получать бесплатно сколько угодно раз.

## Medium

**8. `RedeemRequest.points` — обязательное поле нигде не используется.**
- **Почему дефект:** непонятно, в чём задаётся сумма — в баллах или в рублях. Клиент с `points=100` и `confirm_amount=null` ожидает списания 100 баллов, а теряет весь баланс.

**9. `redeem` — срок действия на день длиннее, чем обещает комментарий.**
- **Что не так:** комментарий обещает 365 дней, включая сегодняшний, а `today + 365` даёт 366 дней.
- **Почему дефект:** кроме расхождения на день, `valid_until` нигде не сохраняется. Срок действия баллов из описания MR фактически не реализован. Кроме того, `date.today()` зависит от часового пояса сервера.

**10. `redeem` → `write_audit(req.dict())` — в аудит пишется запрос, а не результат операции.**
- **Почему дефект:** при полном списании в аудите `confirm_amount: null`, и не видно, сколько реально списано и какой остался баланс. К тому же в аудит без фильтрации попадает свободный текст `comment`.

## Low

**11. `redeem` — 404 без `detail`.**
- **Почему дефект:** клиент не отличит «участник не найден» от неверного адреса запроса.
