**Решения:**
- **(а) и (б), карточка заказа и заказы клиента.** Запросы только читают данные, поэтому без отслеживания (`AsNoTracking`) и сразу в DTO. Прокси и ленивая загрузка не используются. Позиции и платежи грузятся раздельными запросами (`AsSplitQuery`), чтобы тысячи заказов с двумя коллекциями не размножали строки в одном JOIN. `CreatedAt` хранится без часового пояса, прочитанное значение помечается как UTC.
- **(в) `GetProductBySku`.** Уникальна только пара (SKU, склад), поэтому параметр склада стал nullable (`string?`). Если склад не передан, а SKU лежит на нескольких складах, первый попавшийся продукт не берётся. Метод возвращает результат со статусом `Ambiguous` и списком складов. Два других статуса — `Found` и `NotFound`.
- **(г) дата последней отгрузки.** Максимум считается в БД только по отгруженным заказам. Если у клиента их нет, метод бросает `InvalidOperationException`, а не возвращает пустую дату (`default(DateTime)`). Дата приходит в UTC.

**Что нужно решить вам:**
- Метод (в) теперь принимает `string?` и возвращает результат со статусом вместо продукта, то есть сигнатура отличается от указанной в поручении. Вызывающему коду придётся обрабатывать случай, когда SKU есть на нескольких складах.
- Метод (г) бросает исключение, если у клиента нет отгруженных заказов. Вызывающему коду нужно его учесть.
