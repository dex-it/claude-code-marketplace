**Решения:**
- **(а) и (б), заказы с позициями и платежами:** данные сразу собираются в DTO, поэтому не подгружаются лишние поля и не срабатывает ленивая загрузка. Позиции и платежи читаются отдельными запросами (`AsSplitQuery`), чтобы строки заказа не перемножались между собой; это сделано и для карточки одного заказа. Выгрузка заказов клиента отсортирована по `CreatedAt`, затем по `Id`. `CreatedAt` хранится без часового пояса, поэтому прочитанное значение помечается как UTC.
- **(в) `GetProductBySku`:** склад можно не передавать (`string? warehouse`). Если он указан, поиск идёт по паре SKU + склад, и результат однозначный. Если склад не указан и SKU есть на нескольких складах, метод не выбирает продукт наугад, а возвращает `Ambiguous` со списком складов. Другие варианты ответа — `Found` и `NotFound`.
- **(г) дата последней отгрузки:** максимум `ShippedAt` считается в базе, удалённые заказы в расчёт не попадают. Метод возвращает `DateTime` без null, поэтому если у клиента нет отгруженных заказов, он бросает `NoShippedOrdersException`, а не общее `Sequence contains no elements`. Отгруженным считаю заказ с заполненным `ShippedAt`, поле `Status` не проверяю, так как его значения в проекте не описаны.
