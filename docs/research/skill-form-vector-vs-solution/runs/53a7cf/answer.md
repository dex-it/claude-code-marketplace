## Critical

1. **`appsettings.Production.json`: секреты в репозитории.**
   - **Что не так:** в коммит попали пароль БД прода (`Password=Kx7!pQ2vR9wz`) и пароль SMTP-релея (`rl_live_9f3a1c77e2b04d6d`).
   - **Почему дефект:** они остаются в истории git, поэтому удалить их из файла недостаточно.
   - **Что сделать:** ротировать оба секрета, убрать их из файла и передавать через переменные окружения или хранилище секретов (`ConnectionStrings__Notify`, `Smtp__Password`).

2. **`OutboxWorker.ProcessBatchAsync`: `SentAt` ставится до отправки и при ошибке не сбрасывается.**
   - **Что не так:** `m.SentAt = now` записывается в БД до отправки. Если `SendAsync` падает, `catch` увеличивает только `Attempts`, а `SentAt` остаётся заполненным.
   - **Почему дефект:** фильтр `SentAt == null` больше не выберет такую запись. Любое неудачное письмо теряется навсегда, а `MaxRetries`, `Attempts` и `LockedUntil` ни на что не влияют. Если процесс упадёт между двумя `SaveChangesAsync`, теряется вся пачка.
   - **Что сделать:** при захвате ставить только `LockedUntil`, а `SentAt` писать после успешной отправки.

3. **`Program.cs`: `SmtpOptions` привязаны к несуществующей секции.**
   - **Что не так:** в коде `GetSection("Mail")`, а во всех appsettings секция называется `"Smtp"`.
   - **Почему дефект:** `Host` и `FromAddress` получаются `null`, `Port` — 0. `MailboxAddress.Parse(null)` и `ConnectAsync` бросают исключение, и ни одно письмо не уходит. Вместе с п.2 каждое сообщение один раз выбирается, помечается отправленным и теряется.

4. **`ThrottleService.WaitAsync`: неверный ключ настройки и деление на ноль.**
   - **Что не так:** код читает `Throttle:MessagesPerMinute`, а в конфигурации лежит `Throttle:PerMinute`.
   - **Почему дефект:** `GetValue<int>` возвращает 0, и `60_000 / 0` бросает `DivideByZeroException` при каждой отправке. Ни одно письмо не уходит, а из-за п.2 все ещё и теряются.
   - **Дополнительно:** настройка читается из `IConfiguration` напрямую, в обход options, поэтому нет ни проверки на `> 0`, ни валидации при старте.

## High

5. **`OutboxOptions.PollInterval` / `OutboxWorker.ExecuteAsync`: у интервала нет единицы, код считает его секундами.**
   - **Что не так:** в MR нужен опрос раз в полсекунды, в конфигурации стоит `500` (подразумеваются миллисекунды), а код делает `TimeSpan.FromSeconds`.
   - **Почему дефект:** воркер опрашивает outbox раз в 500 с (~8,3 мин).
   - **Что сделать:** сделать свойство `TimeSpan` или переименовать в `PollIntervalMs` и использовать `FromMilliseconds`. В валидатор добавить проверку `> 0`: сейчас значение 0 даёт непрерывный опрос БД без пауз.

6. **`OutboxWorker` (конструктор): `IOptions<OutboxOptions>` не даёт менять настройки на лету, а MR этого требует.**
   - **Что не так:** `IOptions<T>` вычисляется один раз, и правка appsettings ни на что не влияет.
   - **Что сделать:** нужен `IOptionsMonitor<OutboxOptions>` с `CurrentValue` на каждой итерации (`IOptionsSnapshot` в singleton внедрить нельзя).
   - **Смежная проблема:** `_batchSize` берётся из `MaxBatchSize` один раз при старте. Если уменьшить `MaxBatchSize` на лету, ветка сжатия может держать размер пачки выше нового максимума.

7. **`Program.cs`: `OutboxOptionsValidator` не зарегистрирован, валидации при старте нет.**
   - **Что не так:** валидатор написан и покрыт тестами, но в DI не добавлен и не вызывается. `ValidateOnStart()` тоже нет.
   - **Почему дефект:** ошибки конфигурации (как в п.3, п.4, п.12) всплывают только в рантайме.
   - **Что сделать:** `AddOptions<OutboxOptions>().Bind(...).ValidateOnStart()` и `AddSingleton<IValidateOptions<OutboxOptions>, OutboxOptionsValidator>()`. То же для `SmtpOptions` и настроек троттлинга.

8. **`appsettings.Staging.json`: плейсхолдер `${NOTIFY_DB_PASSWORD}` не подставляется.**
   - **Почему дефект:** конфигурация .NET не раскрывает `${...}`, в Npgsql уйдёт буквальная строка, и подключение к БД на стейдже не пройдёт.
   - **Что сделать:** передавать строку подключения через переменную окружения `ConnectionStrings__Notify` или хранилище секретов.

9. **`Notify.Worker.csproj` + `tests/OutboxOptionsValidatorTests.cs`: сборка сломается.**
   - **Что не так:** SDK по умолчанию включает все `**/*.cs`, поэтому тест попадает в проект воркера, где пакет xunit не подключён.
   - **Почему дефект:** ошибка компиляции. Если xunit добавить, тесты уедут в прод-сборку.
   - **Что сделать:** вынести тесты в отдельный тестовый проект.

10. **`OutboxWorker.ProcessBatchAsync`: пачка захватывается без блокировки строк.**
    - **Что не так:** сначала SELECT, потом UPDATE `LockedUntil`, без `FOR UPDATE SKIP LOCKED` и без проверки конкурентности.
    - **Почему дефект:** два экземпляра воркера (например, при rolling-деплое) выберут одни и те же строки и отправят письма дважды.
    - **Что сделать:** захватывать атомарно (`UPDATE … RETURNING` или `SKIP LOCKED` в транзакции).

11. **`OutboxWorker.ExecuteAsync`: одно исключение останавливает весь сервис.**
    - **Что не так:** ошибки БД в цикле никак не обрабатываются.
    - **Почему дефект:** в .NET 8 по умолчанию `BackgroundServiceExceptionBehavior.StopHost`, поэтому один сбой Postgres кладёт весь сервис.
    - **Что сделать:** обернуть тело цикла в try/catch с логированием и паузой.

## Medium

12. **`OutboxOptionsValidator.Validate` + `appsettings.Production.json`: не проверяется связь между полями.**
    - **Что не так:** в проде `MinBatchSize: 200` больше `MaxBatchSize: 100`, валидатор этого не ловит. Воркер молча отключает адаптивный батчинг.
    - **Ещё случай:** при `MinBatchSize = 0` размер пачки может сжаться до 0 и навсегда там остаться, и воркер перестанет забирать сообщения.
    - **Что сделать:** проверять `0 < MinBatchSize <= MaxBatchSize`, добавить тест, исправить значения в проде.

13. **`SmtpOptions`: non-nullable `Host` и `FromAddress` без значения.**
    - **Что не так:** при `Nullable enable` эти свойства не инициализированы (предупреждение CS8618).
    - **Почему дефект:** если конфигурация их не задаст (как в п.3), во время работы там будет `null`, хотя тип обещает обратное.
    - **Что сделать:** пометить `required` / `[Required]` и проверять при старте.

14. **`ThrottleService.WaitAsync`: троттлинг не ограничивает общую скорость.**
    - **Что не так:** каждая задача ждёт `60000/perMinute` мс сама по себе, а параллельно работают `MaxInFlight` задач.
    - **Почему дефект:** реальная скорость в `MaxInFlight` раз выше лимита (в проде 5 × 1200 в минуту), лимит релея будет превышен.
    - **Что сделать:** использовать общий ограничитель из `System.Threading.RateLimiting`.

15. **`appsettings.Staging.json`: стейдж настроен агрессивнее прода.**
    - **Что не так:** на стейдже `MaxInFlight: 20`, в проде 5.
    - **Почему дефект:** стейдж не воспроизводит нагрузку прода на SMTP-релей и БД.
    - **Что сделать:** выровнять значения, на стейдже не выше прода.

## Low

16. **`OutboxWorker.ProcessBatchAsync`: остановка сервиса считается неудачной попыткой.**
    - **Что не так:** `catch (Exception)` ловит и `OperationCanceledException` при штатной остановке и увеличивает `Attempts`.
    - **Почему дефект:** прерванные сообщения тратят попытки. Кроме того, финальный `SaveChangesAsync(ct)` на отменённом токене не выполнится, и изменения `Attempts` потеряются.
    - **Что сделать:** отфильтровать отмену через `when (!ct.IsCancellationRequested)`.

17. **`OutboxOptions.MaxRetries`: смысл расходится с именем.**
    - **Что не так:** условие `Attempts < MaxRetries` даёт `MaxRetries` попыток всего, то есть на одну повторную попытку меньше, чем обещает имя.
    - **Что сделать:** переименовать в `MaxAttempts` или поправить условие.

18. **`SmtpMailSender.SendAsync`: новое SMTP-подключение на каждое письмо.**
    - **Почему дефект:** на каждое письмо выполняются подключение, TLS и аутентификация. Это лишняя нагрузка на релей, и он может начать отказывать в подключениях по лимиту.
    - **Что сделать:** переиспользовать соединение в пределах пачки или сделать пул.
