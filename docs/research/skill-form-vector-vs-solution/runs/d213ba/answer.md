## Решения

- **Удаление клиента.** По README данные нельзя удалять физически, поэтому удаление мягкое. Клиент, его питомцы, их аллергии и визиты получают `IsDeleted` и один общий `DeletedAt`. Существующие фильтры скрывают их везде, в том числе в расписании врачей. Поддержка может по этой метке восстановить ровно то, что удалила эта операция.
- **Замена аллергий.** Простой `Clear()` + `Add` физически удалил бы старые строки, а историю нужно хранить 5 лет. Поэтому старый список сравнивается с новым:
  - аллергии, которых нет в новом списке, помечаются удалёнными;
  - если у аллергии изменилась реакция или тяжесть, старая запись помечается удалённой и создаётся новая;
  - пустые аллергены, аллергены длиннее 200 символов и дубли в списке отклоняются с ответом 400.
- **Переименование.** Столбец переименовывается (`RenameColumn`), а не удаляется и создаётся заново, поэтому данные сохраняются. Старая версия приложения с новой схемой работать не будет, поэтому выкладывать только по обычной схеме: окно обслуживания → `db-migrate` → `deploy`. В API поле теперь называется `anamnesis`, эндпоинт — `/visits/{id}/anamnesis`, так что фронтенд нужно выкатить одновременно.

**Важно:** README ссылается на папку `Migrations`, но её в репозитории нет. Нет и снапшота модели (`ClinicDbContextModelSnapshot.cs`), и csproj. Я не стал придумывать снапшот, чтобы не разойтись с настоящим. EF найдёт новую миграцию и без него, но в существующем снапшоте нужно вручную заменить `Notes` на `Anamnesis` у `Visit`. Иначе следующая `dotnet ef migrations add` снова сгенерирует переименование.
