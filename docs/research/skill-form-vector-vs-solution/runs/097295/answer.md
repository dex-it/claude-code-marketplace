## Итоги ревью

**Critical**
1. `BatchService.ListAsync` — `Skip(page * pageSize)` при пагинации с 1-й страницы: самые новые партии (первая страница) теряются из выдачи полностью (off-by-one).

**High**
2. `BatchService.CompliancePercentAsync` — деление на ноль, если у партии нет проб.
3. `BatchService.CompliancePercentAsync` — целочисленное деление `compliant / total * 100` обрезает результат до умножения → процент почти всегда неверный (часто 0%).

**Medium**
4. `BatchService.CompliancePercentAsync` — проба без результатов засчитывается как «соответствующая норме» (`All()` на пустой коллекции = `true`).
5. `BatchService.CloseAsync` — проверка «нет результатов» смотрит только пробы со статусом `InAnalysis`, пробы в других статусах у партии не проверяются и не переводятся, но партия всё равно закрывается.
6. `Models.cs`/`LabDbContext.cs` — новая не-nullable колонка `Sample.PlannedLocal` на существующей таблице без видимой миграции/backfill-стратегии для исторических данных.

**Low**
7. `BatchService.GetCardAsync` — грузятся полные сущности через `Include`, хотя нужны только отдельные поля (стоит заменить на проекцию).
8. `SampleTag` — полноценная сущность с суррогатным Id для одного поля, кандидат на owned-тип/primitive collection.
9. Нет уникального индекса `(SampleId, Tag)` на уровне БД — защита от дублей только в коде.
10. `BatchService.CloseAsync` — нет защиты от гонки/идемпотентности при параллельном закрытии одной партии.
