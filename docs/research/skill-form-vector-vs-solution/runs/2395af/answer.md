Я провёл ревью MR !214 и нашёл 11 дефектов, которые стоит исправить до мерджа: 2 critical, 6 high и 3 medium. Ниже тот же текст, что я записал в `_answer.md`. Код я не менял, сборку и тесты не запускал, так что выводы сделаны только по чтению кода.

## 1. `Services/InpatientReportService.cs` → `GetOccupancyAsync` — SQL-инъекция через `ward` и `sortBy` (**critical**)
`ward` и `sortBy` приходят из query string (`/reports/occupancy?ward=…&sortBy=…`) и вставляются в текст запроса `FromSqlRaw` обычной интерполяцией строки. Это не параметры: `ward = x' OR 1=1 --` или `sortBy = Id"; DROP TABLE "Stays"; --` попадут прямо в SQL. Эндпоинт доступен любому аутентифицированному пользователю.

**Исправление:** передавать `ward` как параметр (`FromSql($"...{ward}")` или `DbParameter`). `sortBy` проверять по белому списку и сортировать через `OrderBy` в LINQ. Проще всего отказаться от сырого SQL.

## 2. `ClinicDbContext` (`HasQueryFilter` на `Box`) + `GetWardPatientsAsync` / `GetLongStaysAsync` / `DischargeAsync` / `GetOccupancyAsync` — пациенты из выведенного бокса пропадают, выписать их нельзя (**critical**)
Связь `Stay → Box` обязательная. Поэтому любое обращение к `s.Box` даёт INNER JOIN с уже отфильтрованной таблицей боксов, и госпитализации в выведенном боксе выпадают из выборки (EF предупреждает об этом, warning 10622). Что получается:
- **Пропадают из списков:** пациенты исчезают из списка отделения, из обхода главврача и из отчёта занятости. README требует обратного: бокс выводят, пока в нём ещё лежат пациенты, и они должны оставаться в списках до выписки.
- **Не выписать:** в `DischargeAsync` вызов `Include(Box).SingleAsync` бросает исключение. Пациента из выведенного бокса нельзя выписать и выставить ему счёт.

**Исправление:** убрать глобальный фильтр и фильтровать выведенные боксы явно там, где бокс выбирают при поступлении. Другой вариант — `IgnoreQueryFilters()` во всех запросах по госпитализациям.

## 3. `Program.cs` — `MigrateAsync()` при старте приложения (**high**)
- **Нет прав на DDL:** в проде приложение работает под ролью `vet_app`. Если есть неприменённая миграция, старт падает с permission denied, и все 3 реплики уходят в crash loop.
- **Обход процесса:** если права всё же есть, миграция обходит принятый порядок: идемпотентный скрипт, проверка DBA, ручной запуск `db-migrate` под `vet_migrator`.
- **Гонка реплик:** в EF Core 8 у `Migrate` нет блокировки (она появилась только в EF 9). При rolling update несколько подов могут применять одну миграцию одновременно.

**Исправление:** удалить блок. Если нужно, оставить автомиграцию только для Development.

## 4. `WardService.ReplaceMedicationPlanAsync` — `Clear()` при `DeleteBehavior.Restrict` (**high**)
`Clear()` разрывает обязательную связь назначений с госпитализацией. При `Restrict` вызов `SaveChanges` бросает `InvalidOperationException`, поэтому замена плана не работает, если назначения уже есть, а это основной сценарий. Переход на `Cascade` тоже не подходит: по README назначения физически не удаляются, отменённым ставится `CancelledAt`.

**Исправление:** ставить активным назначениям `CancelledAt = DateTime.UtcNow` и добавлять новые.

Кроме того, нет защиты от параллельной правки: если два врача одновременно заменяют план, активных назначений станет вдвое больше. Нужен concurrency token (`xmin`) или `FOR UPDATE` в явной транзакции.

## 5. `WardService.GetLongStaysAsync` — `DaysInWard` в `Where` не переводится в SQL (**high**)
`DaysInWard` — вычисляемое свойство без столбца в БД. EF не может перевести его в SQL и бросает исключение, так что `/long-stays` всегда отвечает 500.

**Исправление:** вычислить границу заранее (`cutoff = today.AddDays(-14)`) и фильтровать по `AdmittedOn < cutoff`. Тогда фильтр выполнится в SQL.

## 6. `WardService.DischargeAsync` — неверная стоимость стационара (**high**)
По README оплачиваются календарные дни, включая день поступления и день выписки. Код считает просто разность дат без `+1`. В итоге каждый счёт меньше на одни сутки, а при выписке в день поступления стоимость равна 0. Та же ошибка есть в `Stay.DaysInWard`.

## 7. `Api/InpatientEndpoints.cs` → `POST /stays/{id}/discharge` — нет политики `Vet` (**high**)
Стоит `RequireAuthorization()` без политики, поэтому выписать пациента и выставить счёт может и администратор ресепшена. README требует, чтобы выписку оформлял только врач.

**Исправление:** `.RequireAuthorization("Vet")`.

## 8. `WardService.GetBoxCardAsync` — `SingleOrDefaultAsync` на неуникальном условии (**high**)
В одном боксе одновременно лежат до `Capacity` животных (README: помёт, животные одного владельца). Если пациентов два и больше, запрос бросает исключение, и карточка бокса отвечает 500.

**Исправление:** возвращать список текущих пациентов через проекцию, без загрузки полных сущностей через `Include`.

## 9. `WardService.DischargeAsync` — гонка при параллельной выписке (**medium**)
Проверка `DischargedOn` и запись идут без concurrency token и без блокировки. При двух одновременных запросах (например, двойной клик) второе сохранение молча перезапишет дату и сумму первого.

**Исправление:** concurrency token `xmin` с обработкой `DbUpdateConcurrencyException`, либо `ExecuteUpdate … WHERE "DischargedOn" IS NULL` с проверкой числа затронутых строк.

## 10. `WardService.GetLatestStayAsync` — «последняя» госпитализация выбирается случайно, фильтр в памяти (**medium**)
- **Порядок не детерминирован:** сортировка только по `AdmittedOn` (дата без времени), а повторная госпитализация в тот же день — штатная ситуация. Тогда врач может увидеть уже закрытую госпитализацию. Нужно добавить `.ThenByDescending(s => s.Id)`.
- **Лишние данные:** отменённые назначения загружаются целиком и отфильтровываются в памяти. Лучше сделать проекцию в DTO с фильтром `CancelledAt == null` прямо в SQL.

## 11. `ClinicDbContext`, связь `Stay → Box` — `ON DELETE CASCADE` на мягко удаляемую сущность (**medium**)
Поведение при удалении не задано, поэтому миграция создаст FK с каскадным удалением. Если бокс когда-нибудь удалят физически, вместе с ним пропадёт история госпитализаций, то есть медкарта и счета.

**Исправление:** задать `.OnDelete(DeleteBehavior.Restrict)`. Связь `Stay → Pet` стоит проверить так же: там по умолчанию тоже каскад.
