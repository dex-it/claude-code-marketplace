**Файлы:**
- `PaymentImportService.cs` — новый: загрузка выписки и возврат приостановленных абонентов в Active (а, б). Кодировка файла определяется автоматически: UTF-8 или windows-1251.
- `Models.cs` — новая сущность `UnmatchedPayment` для неразобранных строк; у `Subscriber` добавлены `ResumedAt` и `PhoneDigits`.
- `BillingDbContext.cs` — таблица `UnmatchedPayments` с уникальным `BankRef`. `PhoneDigits` — вычисляемая колонка: телефон без всего, кроме цифр.
- `SubscriberService.cs` — `SearchByPhoneTailAsync`.
- `Program.cs` — `POST /bank/statements` (файл можно передать как тело запроса или как multipart) и `GET /subscribers/search?phone=`.

**Решения:**
- **Повторная загрузка:** строка пропускается, если её `BankRef` уже есть среди платежей или неразобранных; на обеих таблицах уникальный индекс. Выписка загружается в одной транзакции, абоненты на это время блокируются (`FOR UPDATE`). Если ту же выписку параллельно грузят второй раз, вся транзакция откатывается и возвращается 409.
- **Неразобранные:** туда попадают строки без номера договора, с неизвестным или расторгнутым (Closed) договором и с суммой ≤ 0, у каждой записана причина. Платежи по расторгнутым договорам я тоже отправляю бухгалтеру, а не на баланс. Приостановленный абонент возвращается в Active, как только баланс становится ≥ 0, момент записывается в `ResumedAt`.
- **Поиск по телефону:** телефоны хранятся в том виде, как их ввели (например «+7 (912) 345-45-18»), поэтому ищем по колонке с одними цифрами. Нужно минимум 4 цифры, иначе 400. Возвращается не больше 20 абонентов, сортировка по ФИО.
