## 1. `TripService.GetOpenWaybillsAsync` — критическая ошибка композиции `FromSqlRaw`
**critical** — сырой SQL заканчивается `;` и содержит `ORDER BY`. Когда задан `vehicleId` (сценарий FLEET-112 «с фильтром по машине»), EF оборачивает `FromSqlRaw` в подзапрос, и `;` внутри скобок даёт синтаксическую ошибку Postgres в рантайме. В MR протестирован только вариант без фильтра — отсюда баг не поймали.

## 2. `TripRows.ToRows` / `TripService.OffDayTripsAsync` — нетранслируемое условие в `Select`
**critical** — `OffDay = !WorkCalendar.IsWorkingDay(...)` — обычный C#-метод без `HasDbFunction`, используется в проекции, после которой идут ещё `Where`/`OrderByDescending`. EF не может транслировать такое условие вне финального `Select` → `InvalidOperationException`, основной отчёт FLEET-109 не заработает.

## 3. `VehicleService.GetLastInspectionAsync` — «последний осмотр» по времени синхронизации, а не осмотра
**high** — сортировка по `CreatedAt` вместо `InspectedAt`, хотя сам комментарий к коду описывает офлайн-буферизацию и рассинхрон порядка прихода/факта осмотра. Это напрямую влияет на решение о выпуске на линию в `StartTripAsync`.

## 4. `TripService.StartTripAsync` — допуск считается истёкшим на дату окончания
**high** — `p.ValidUntil > today` вместо `>= today`; по требованию допуск действует «включительно» по указанную дату.

## 5. Миграция `VehicleEquipmentAndModelLength` — сужение `model` до 40 символов без учёта существующих данных
**critical** — `AlterColumn` на `varchar(40)` упадёт на проде, если есть строки длиннее 40 символов, а сама мотивация задачи (принтер обрезал длинные названия) говорит, что такие данные, скорее всего, уже есть. Нет предварительного шага усечения/проверки данных.

## 6. `Program.cs` — эндпоинт замены комплектации машины без проверки роли
**high** — `PUT /vehicles/{id}/equipment` не имеет `.RequireAuthorization("...")` в отличие от всех соседних мутирующих эндпоинтов — любой аутентифицированный пользователь может менять комплектацию (аптечка, огнетушитель и т.д.).

## 7. `TripService.StartTripAsync` — лишний трекинг read-only сущностей
**low** — `vehicle` и `driver` читаются без `AsNoTracking()`, хотя не сохраняются в этом юните работы.

## 8. `TripService.StartTripAsync` — нет защиты от двойного выпуска одной машины
**medium** — check-then-act без блокировки/транзакции, два параллельных запроса могут создать два рейса на одной машине.
