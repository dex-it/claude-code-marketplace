## Решения
- **Сортировка реестра.** ORDER BY собирается из фиксированного набора фрагментов, а неверные `sort`/`dir` дают 400. Порядок однозначный: последний ключ — `r.id`, поэтому страницы не пересекаются. Квартиры сортируются по числу (сначала числовая часть номера, затем вся строка). Статусы идут по жизненному циклу, а не по алфавиту. В `SELECT` для `FromSqlRaw` добавлены новые колонки: без них запрос реестра падал бы.
- **Закрытие заявки и план.** Проверка статуса и закрытие выполняются одним условным `ExecuteUpdate`: при неподходящем статусе — 409, если заявки нет — 404, без комментария — 400. В плане работы сопоставляются по коду: оставшиеся обновляются на месте и сохраняют историю, новые добавляются. Отсутствующие удаляются явно через `Remove`, потому что в контексте `DeleteOrphansTiming = Never`. Их история удаляется каскадом FK. Если по актам её нужно хранить, нужно мягкое удаление.
- **Миграция.** Она только добавляет nullable-колонки, поэтому совместима со старой версией приложения в промежутке между efbundle и rollout. Написана вручную, сборка и тесты не запускались. Файла `HousingDbContextModelSnapshot` в каталоге нет, его нужно обновить через `dotnet ef migrations add`. `MapHousingEndpoints()` нужно вызвать в `Program.cs` и проверить, нет ли уже таких маршрутов.
