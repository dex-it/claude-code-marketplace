Провёл ревью, ответ записан в `_answer.md`. Основные находки:

**Critical**
1. `app/redeem.py: redeem()` — `POINT_VALUE = 0.1` (float), а не `Decimal("0.1")`: `Decimal(float)` даёт искажённое число (подтверждено docs модуля `decimal`), ошибка протекает во весь расчёт баланса.
2. `app/redeem.py: redeem()` — `int(amount / Decimal(POINT_VALUE))` усекает дробную часть; `redeemed`, реально списанные баллы и `balance_left` могут не сходиться — нарушение сохранения баланса.
3. `app/redeem.py: redeem()` — нет валидации `confirm_amount > 0`; отрицательное значение проходит проверку `amount > balance` и **увеличивает** баланс баллов вместо списания.
4. `app/repo.py: get_member/save_member` — чтение и запись баланса без блокировки строки/оптимистичной проверки в разных транзакциях → race condition, возможен double-spend при параллельных запросах.

**High**
5. `app/repo.py: save_member/write_audit` — обновление баланса и запись аудита не атомарны (разные транзакции), возможен провал аудита без отката баланса.
6. `app/schemas.py: RedeemRequest.points` — поле никогда не используется в логике (подтверждено grep) — либо мёртвый код, либо недоделанная бизнес-логика.
7. `app/redeem.py: redeem()` — в аудит пишется сырой `req.dict()`, а не фактический результат операции (списанная сумма, остаток, срок действия) — не выполняет заявленную в MR цель «аудит операции».

**Medium**
8. `RedeemResult` — pydantic 1.10.13 по умолчанию кодирует `Decimal` с дробной частью во `float` при сериализации JSON (подтверждено исходником `pydantic/json.py` тега v1.10.13) — теряется точность на уровне API-контракта.
9. Срок действия баллов нигде не персистируется, несмотря на то что заявлен в описании MR.
10. Нет проверки авторизации вызывающего на `member_id`.

**Low**
11. `HTTPException(404)` без `detail`.
12. `date.today()` без UTC — возможен разнобой при разных таймзонах инстансов.

Отдельно проверил и **исключил** как дефект: комментарий про `Optional[Decimal]` без default в `schemas.py` — для pydantic 1.10 это действительно обязательное поле (подтверждено официальной документацией версии 1.10), код и комментарий корректны.
