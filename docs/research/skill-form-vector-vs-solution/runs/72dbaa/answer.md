Нашёл 14 дефектов: 2 critical, 6 high, 4 medium и 2 low. Код не менял, сборку и тесты не запускал. Этот же ответ записан в `_answer.md`.

## Critical

**1. `Controllers/PaymentWebhookController.cs`, `Handle` — копейки зачисляются как рубли**
- **Что не так:** провайдер присылает `PaymentEvent.Amount` в копейках, а `Payment.Amount` и `Booking.PaidAmount` хранятся в рублях. Код делает `PaidAmount += evt.Amount`, не деля на 100.
- **Почему это дефект:** бронь переходит в `Confirmed`, когда оплачен всего 1 % депозита. При отмене `CancelAsync` возвращает клиенту `PaidAmount`, то есть в 100 раз больше, чем он заплатил. Это прямые потери денег марины.
- **Как исправить:** делить на `100m`.
- **Заодно (low):** валюта `evt.Currency` не проверяется.

**2. `Controllers/PaymentWebhookController.cs`, `Handle` — повторное событие засчитывается ещё раз**
- **Что не так:** провайдер доставляет события по схеме at-least-once, а повторы по `ProviderEventId` не отсекаются. Уникального индекса на `Payment.ProviderEventId` тоже нет.
- **Почему это дефект:** каждый повтор добавляет новый `Payment` и снова увеличивает `PaidAmount`. В итоге возврат при отмене больше, чем марина реально получила.

## High

**3. `Services/TariffCalculator.cs`, `Calculate` — длина судна округляется до ближайшего метра**
- **Что не так:** используется `Math.Round(..., AwayFromZero)`, поэтому 12.3 м превращается в 12. По условию тарифицируется каждый начатый метр, то есть нужно `Math.Ceiling`.
- **Почему это дефект:** марина недополучает деньги почти по каждой брони.

**4. `Services/BookingService.cs`, `CreateAsync` — сезонные ставки никогда не применяются**
- **Что не так:** место читается через `FromSql(... FOR UPDATE)` без `Include(SeasonalRates)`, а lazy loading не настроен.
- **Почему это дефект:** `berth.SeasonalRates` всегда пуст, и расчёт всегда идёт по базовой ставке. Летние тарифы фактически не работают.

**5. `Controllers/BookingsController.cs`, `List` — чужие брони доступны через `?vesselId=`**
- **Что не так:** если передан `vesselId`, фильтр `OwnerId == userId` не применяется (они стоят в ветках `if/else if`).
- **Почему это дефект:** любой владелец видит брони любого чужого судна, включая телефон шкипера и суммы.

**6. `Controllers/BookingsController.cs`, `Calendar` — анонимный эндпоинт отдаёт персональные данные**
- **Что не так:** публичный календарь возвращает полный `BookingDto`: телефон, название судна, `Total`, `Deposit`, `PaidAmount`, Id брони.
- **Почему это дефект:** телефоны клиентов доступны без авторизации. Календарю нужны только даты занятости.

**7. `Services/BookingService.cs`, `CancelAsync` — неудачный возврат записывается как выполненный**
- **Что не так:** `PaymentGatewayException` только логируется. Бронь всё равно становится `Cancelled`, а в `RefundedAmount` записывается сумма возврата.
- **Почему это дефект:** клиент денег не получил, а система считает, что вернула их. Повторить отмену нельзя — придёт ответ `AlreadyCancelled`.

**8. `Services/BookingService.cs`, `CancelAsync` — деньги возвращаются до сохранения брони**
- **Что не так:** `RefundAsync` вызывается до `SaveChangesAsync`.
- **Почему это дефект:** если параллельно пришёл вебхук или вторая отмена, проверка версии через `xmin` упадёт с 500, хотя деньги уже ушли, а бронь не отменена. Повторная отмена вернёт деньги ещё раз.

## Medium

**9. `Services/BookingService.cs`, `CreateAsync` — нельзя заселить следующую яхту в день выезда предыдущей**
- **Что не так:** проверка пересечения `Arrival <= Departure && Departure >= Arrival` включает границы.
- **Почему это дефект:** по MR место в день выезда отдаётся следующей яхте, а код отклоняет такую бронь как «Место занято». Нужны строгие `<` и `>`. В `Calendar` неравенства уже строгие, то есть логика расходится.

**10. `Services/BookingService.cs`, `CancelAsync` — местное время марины сравнивается с UTC**
- **Что не так:** заезд в 14:00 по местному времени вычитается из `DateTime.UtcNow`.
- **Почему это дефект:** для Москвы граница 48 часов сдвинута на 3 часа, и часть клиентов получает полный возврат вопреки правилу.
- **Заодно (low):** в `CreateAsync` «сегодня» тоже считается по UTC-дате, а не по дате марины.

**11. `Controllers/PaymentWebhookController.cs`, `Handle` — оплата уже отменённой брони теряется**
- **Что не так:** если оплата пришла после отмены, `PaidAmount` растёт, но бронь остаётся `Cancelled`.
- **Почему это дефект:** возврат не запускается и никто об этом не узнаёт — деньги клиента зависают.

**12. `Services/BookingService.cs`, `CreateAsync` — неоплаченная бронь занимает место бессрочно**
- **Что не так:** `CreateDepositAsync` вызывается после коммита. Если провайдер недоступен, запрос падает с 500, но бронь `AwaitingDeposit` уже сохранена. Срока жизни у неоплаченных броней нет.
- **Почему это дефект:** место остаётся занятым навсегда, в том числе если кто-то намеренно наделает неоплаченных броней.

## Low

**13. `Services/BookingService.cs`, `CreateAsync` — `ContactPhone` не проверяется**
- **Почему это дефект:** в базе поле ограничено 32 символами, поэтому слишком длинное значение даёт ошибку базы и 500 вместо 4xx.

**14. `Controllers/BookingsController.cs`, `Calendar` — параметры `from` и `to` не проверяются**
- **Почему это дефект:** без параметров запрос молча возвращает пустой список. Ширина диапазона не ограничена, и анонимный клиент может запросить сколь угодно большой период.
