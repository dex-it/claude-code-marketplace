## Ревью MR «Списание баллов лояльности»

**1. Отрицательный `confirm_amount` позволяет накручивать баллы** — `app/redeem.py: redeem()`. Проверка `amount > balance` не отсекает отрицательные суммы, а `member.points -= int(amount/POINT_VALUE)` при отрицательном `amount` увеличивает баланс. **critical**

**2. Гонка чтения-изменения-записи баланса, нет блокировки строки** — `app/repo.py: get_member/save_member` + `app/redeem.py: redeem()`. Отдельные транзакции без `SELECT ... FOR UPDATE`; параллельные запросы могут привести к двойному списанию/отрицательному балансу. **critical**

**3. `POINT_VALUE = 0.1` — float, `Decimal(POINT_VALUE)` неточен** — `app/redeem.py`. Нужно `Decimal("0.1")`; иначе ошибки округления во всех денежных расчётах. **high**

**4. Дробная сумма меньше стоимости балла "списывается" без реального изменения баланса** — `app/redeem.py: redeem()`, `int(amount / Decimal(POINT_VALUE))` усекает к нулю. Клиенту сообщается об успешном списании, а баланс не меняется. **high**

**5. Списание, сохранение баланса и запись аудита не атомарны** — `app/repo.py` (три отдельные транзакции), вызывается из `redeem()`. При сбое между шагами баллы спишутся без записи в аудит, что нарушает заявленное в MR требование аудита. **high**

**6. Поле `points` в `RedeemRequest` объявлено, но не используется** — `app/schemas.py`/`app/redeem.py`. Обязательный параметр молча игнорируется бизнес-логикой. **medium**

**7. "Срок действия баллов" фактически не реализован** — `app/redeem.py: redeem()`, `app/repo.py: get_member()`. `valid_until` только вычисляется для ответа, не хранится и не влияет на то, можно ли списывать просроченные баллы — заявленная в MR фича отсутствует по существу. **medium**

**8. Нет идемпотентности** — `app/redeem.py: redeem()`. Ретрай запроса приведёт к повторному списанию. **medium**

**9. Нет проверки, что вызывающий владеет `member_id`** — `app/redeem.py: redeem()`. Возможность списать чужие баллы, если авторизация не закрыта выше по стеку. **medium**

**10. 404 без `detail`, непоследовательно с 409** — `app/redeem.py: redeem()`. **low**

**11. `confirm_amount = 0` создаёт бессмысленную "успешную" операцию с записью в аудит** — `app/redeem.py: redeem()`. **low**
