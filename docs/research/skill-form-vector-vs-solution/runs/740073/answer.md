Готово. Изменённые/созданные файлы:

- **Models.cs** — сущность `StudentLoginCode`; `Student.MaskEmail`/`Student.MaskPassport` вынесены как статические методы для переиспользования.
- **SchoolDbContext.cs** — `DbSet<StudentLoginCode>` + конфигурация и FK на `Student`.
- **QueryFilters.cs** — query filter по `SchoolId` для нового набора.
- **StudentAppService.cs** (новый) — запрос/проверка одноразового кода входа (а) и прогресс по часам вождения (г).
- **ReportsService.cs** (новый) — отчёт по выпускникам за год по инструкторам, включая уволенных (б).
- **InstructorAppService.cs** (новый) — список текущих учеников инструктора с маскированием и ближайшим занятием (в).
- **Program.cs** — регистрация сервисов и 5 новых эндпойнтов.

Ключевые решения:
- Логин ищет e-mail через `ToLower()` (транслируется в SQL), а не `Single`, т.к. регистронезависимое совпадение не гарантировано уникальным индексом схемы; код хранится как SHA-256-хеш, сверяется `FixedTimeEquals`, старые коды гасятся одним `ExecuteUpdateAsync`, есть лимит попыток, ответ на `request` не палит существование e-mail.
- В отчёте по выпускникам `IgnoreQueryFilters()` на `Instructors` снимает заодно и изоляцию по школе, поэтому она восстановлена явным условием `SchoolId == db.SchoolId`.
- Список учеников инструктора с ближайшим занятием — один LEFT JOIN с `GROUP BY/MIN(StartsAt)` в SQL, без запросов в цикле.
