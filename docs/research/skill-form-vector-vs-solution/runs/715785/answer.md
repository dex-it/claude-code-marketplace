В нынешнем виде MR мерджить нельзя. Сервис не отправит ни одного письма, но все сообщения пометит как отправленные. В репозиторий попали боевые секреты. Требование менять лимиты на лету без рестарта не выполнено. Код я не запускал и не собирал, всё ниже найдено чтением исходников. Тот же список записан в `_answer.md`.

## Critical

1. **`appsettings.Production.json`: секреты в репозитории.**
   Открытым текстом лежат пароль БД (`Password=Kx7!pQ2vR9wz`) и боевой ключ SMTP-релея (`Smtp:Password` = `rl_live_…`).
   - **Почему дефект:** секреты остаются в истории git и видны всем, у кого есть доступ к репозиторию.
   - **Что сделать:** вынести в переменные окружения или secret store (`ConnectionStrings__Notify`, `Smtp__Password`). Оба секрета уже скомпрометированы, их нужно ротировать.

2. **`Program.cs`: опции SMTP читаются из несуществующей секции.**
   Вызов `Configure<SmtpOptions>(GetSection("Mail"))`, а в конфигах секция называется `"Smtp"`.
   - **Почему дефект:** `Host` и `FromAddress` остаются null, `Port` = 0. `MailboxAddress.Parse(null)` падает на каждом письме, ничего не отправляется.

3. **`ThrottleService.WaitAsync`: неверный ключ конфигурации.**
   Код читает `Throttle:MessagesPerMinute`, а в конфигах ключ называется `Throttle:PerMinute`.
   - **Почему дефект:** отсутствующий ключ даёт 0, а `60_000 / 0` бросает `DivideByZeroException` на каждой отправке. Это вторая независимая причина, по которой ничего не уходит.
   - **Что сделать:** перейти с сырого `IConfiguration` на `ThrottleOptions` с валидатором.

4. **`OutboxWorker.ProcessBatchAsync`: `SentAt` ставится до отправки.**
   `SentAt = now` сохраняется в БД ещё до `SendAsync`.
   - **Почему дефект:** если отправка упала, увеличивается только `Attempts`, а `SentAt` уже заполнен. Такие сообщения больше не выбираются, ретраев нет, письма теряются молча. Если процесс упадёт после первого `SaveChanges`, потеряется вся пачка.
   - **Что сделать:** до отправки ставить только `LockedUntil`. `SentAt` ставить после успешной отправки.

## High

5. **`OutboxWorker.ExecuteAsync`: интервал опроса в 1000 раз больше нужного.**
   В конфиге `"PollInterval": 500`, а код делает `TimeSpan.FromSeconds(o.PollInterval)`.
   - **Почему дефект:** опрос идёт раз в 500 с, а описание MR требует 0.5 с.
   - **Что сделать:** добавить единицу в имя (`PollIntervalMs` + `FromMilliseconds`) или сделать тип `TimeSpan`. Также валидировать значение > 0.

6. **`OutboxWorker`: `IOptions<OutboxOptions>` вместо `IOptionsMonitor`.**
   - **Почему дефект:** `IOptions` не видит изменения appsettings, значит `MaxInFlight` и размер пачки на лету не меняются. Это прямо противоречит описанию MR. Нужен `IOptionsMonitor.CurrentValue`: `IOptionsSnapshot` в singleton-`BackgroundService` недоступен.
   - **Дополнительно:** `_batchSize` берётся из `MaxBatchSize` один раз и меняется только в ветке adaptive batching. Даже с монитором новый размер пачки при `Min >= Max` не применится, и значение не ограничивается диапазоном `[Min, Max]`.

7. **`Program.cs`: валидатор не зарегистрирован, проверки при старте нет.**
   Нет ни `IValidateOptions<OutboxOptions>`, ни `ValidateOnStart()`, поэтому `OutboxOptionsValidator` в рантайме не вызывается никогда.
   - **Что сделать:** зарегистрировать валидатор с `ValidateOnStart()`. Для `SmtpOptions` валидации нет вообще, хотя она поймала бы п. 2 ещё при старте.

8. **`OutboxOptionsValidator.Validate`: нет проверки `MinBatchSize <= MaxBatchSize`.**
   Также не проверяются `MinBatchSize > 0` и `PollInterval > 0`.
   - **Почему дефект:** в проде стоит `Min = 200`, `Max = 100`. Валидатор это пропускает, и adaptive batching в проде молча отключён.

9. **`appsettings.Staging.json`: плейсхолдер `${NOTIFY_DB_PASSWORD}` не подставится.**
   - **Почему дефект:** конфигурация .NET не раскрывает `${...}`, строка уйдёт в Npgsql буквально, и на стейдже будет ошибка аутентификации в БД.
   - **Что сделать:** переопределять всю строку подключения через `ConnectionStrings__Notify`.

10. **`tests/OutboxOptionsValidatorTests.cs` лежит внутри каталога проекта воркера.**
    - **Почему дефект:** SDK по умолчанию компилирует `**/*.cs`, а ссылки на xunit в проекте нет. Сборка падает с CS0246.
    - **Что сделать:** вынести тесты в отдельный тестовый проект или добавить `<Compile Remove="tests/**" />`.

## Medium

11. **`ProcessBatchAsync`: пачка захватывается без блокировки строк.**
    Нет ни `FOR UPDATE SKIP LOCKED`, ни concurrency token.
    - **Почему дефект:** несколько экземпляров воркера возьмут одни и те же строки и отправят письма дважды.

12. **`ExecuteAsync`: нет try/catch внутри цикла.**
    - **Почему дефект:** любая ошибка БД выходит из цикла, а в .NET 8 по умолчанию (`BackgroundServiceExceptionBehavior.StopHost`) это останавливает весь хост.

13. **`ThrottleService`: лимит скорости не глобальный.**
    Каждая параллельная задача ждёт отдельно, поэтому реальный темп в `MaxInFlight` раз выше лимита. В проде это 5 × 1200 = 6000 писем в минуту, лимит релея нарушается.
    - **Что сделать:** общий rate limiter, например `TokenBucketRateLimiter`.

14. **Staging нагружает сильнее Production.**
    На стейдже `MaxInFlight` = 20, в проде 5. Стейдж не воспроизводит прод и сильнее бьёт по своим SMTP и БД.

15. **Staging не переопределяет часть базовых значений.**
    `Smtp:FromAddress` и учётные данные SMTP не заданы, а `Throttle` и `PollInterval` наследуются из базового файла. В итоге письма уйдут от `noreply@localhost` без аутентификации. Dev-значения из базового `appsettings.json` молча попадают в любое окружение, где ключ не переопределён.

16. **`SmtpOptions`: non-nullable `Host` и `FromAddress` без значений.**
    - **Почему дефект:** при включённом `Nullable` это даёт предупреждения CS8618, а тип обещает «не null», хотя без значения в конфигурации там будет null.
    - **Что сделать:** `required` / `[Required]` плюс проверка при старте.

## Low

17. **`ProcessBatchAsync`: остановка сервиса считается неудачной попыткой.**
    `OperationCanceledException` при остановке ловится в `catch (Exception)` и увеличивает `Attempts`. Последний `SaveChangesAsync(ct)` с уже отменённым токеном не сохранит результаты отправок.

18. **`SmtpMailSender.SendAsync`: новое SMTP-соединение с аутентификацией на каждое письмо.**
    Это дорого, под нагрузкой легко упереться в лимиты релея.

19. **`OutboxOptionsValidator`: пропускает `MaxRetries = 0`.**
    При нуле условие `Attempts < 0` никогда не выполняется, и не отправится ни одно сообщение.
