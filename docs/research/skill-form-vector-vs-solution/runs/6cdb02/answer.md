Ревью MR !214 готово, тот же текст записан в `_answer.md`. Код не менял, сборку и тесты не запускал, поэтому всё ниже найдено чтением кода. В файле к каждой находке есть описание того, как исправить.

## Critical
1. **`Services/InpatientReportService.cs` — `GetOccupancyAsync`: SQL-инъекция.**
   - `ward` и `sortBy` из query string вставляются в `FromSqlRaw` интерполяцией строки, без параметров.
   - Любой вошедший пользователь, включая ресепшен, может выполнить произвольный DML под ролью `vet_app`.
   - Исправление: `ward` передавать параметром или через LINQ, `sortBy` сверять с белым списком и сортировать через `OrderBy`.

## High
2. **`Data/ClinicDbContext.cs`: глобальный фильтр `HasQueryFilter(!IsDecommissioned)` на `Box` при required-связи `Stay.Box`.** EF строит INNER JOIN с уже отфильтрованными боксами, поэтому:
   - пациенты из выведенного бокса пропадают из `GetWardPatientsAsync`, `GetLongStaysAsync` и `GetOccupancyAsync`;
   - `DischargeAsync` падает на `Include(Box).SingleAsync`, то есть таких пациентов нельзя выписать;
   - `GetBoxCardAsync` отвечает 404.

   Это противоречит README: пациенты должны оставаться в списках, пока их не выписали.
3. **`WardService.ReplaceMedicationPlanAsync`: `Clear()` при связи с `DeleteBehavior.Restrict`.**
   - Разрыв required-связи при `Restrict` бросает `InvalidOperationException`, поэтому существующий план поменять нельзя.
   - Если «починить» переходом на Cascade, назначения начнут удаляться физически, а по README им нужно ставить `CancelledAt`.
4. **`WardService.DischargeAsync`: стоимость считается без `+1`.** По README день поступления и день выписки входят в счёт. Сейчас выписка в тот же день стоит 0, в остальных случаях теряется один день.
5. **`Api/InpatientEndpoints.cs`, эндпоинт discharge: `RequireAuthorization()` без политики `"Vet"`.** Выписать пациента может ресепшен, хотя по README это делает только врач.
6. **`WardService.GetBoxCardAsync`: `SingleOrDefaultAsync` по текущим пациентам бокса.** В боксе может лежать до `Capacity` животных, при двух и больше эндпоинт отвечает 500. DTO рассчитан на одного пациента, что тоже не соответствует домену.
7. **`WardService.GetLongStaysAsync`: фильтр `s.DaysInWard > 14`.** Это неотображённое C#-свойство, EF его не транслирует, поэтому эндпоинт отвечает 500 на каждый запрос. «Сегодня» к тому же берётся по UTC, а не по местной дате клиники.
8. **`WardService.GetLatestStayAsync`: сортировка только по `AdmittedOn`.**
   - Повторная госпитализация в тот же день допустима, и тогда «последняя» выбирается произвольно.
   - С `AsSplitQuery` коллекции грузятся отдельными запросами и могут подтянуться от другой госпитализации.
   - Врач может увидеть план назначений не той госпитализации. Нужно добавить `ThenByDescending(Id)`.
9. **`Program.cs`: `MigrateAsync()` при старте.**
   - У `vet_app` нет прав на DDL: при непримененной миграции поды уходят в crash loop.
   - Схема меняется в обход идемпотентного скрипта и ревью DBA.
   - В EF Core 8 нет блокировки миграций, а rolling update поднимает 3 реплики одновременно, поэтому они могут мигрировать наперегонки.

## Medium
10. **`DischargeAsync` и `ReplaceMedicationPlanAsync`: нет контроля одновременной правки.** При двух одновременных запросах последний молча перезапишет дату и счёт (или план назначений). Нужен токен конкурентности (`xmin`) и ответ 409.
11. **`ClinicDbContext`: каскадное удаление в БД у `Stay→Box`, `Stay→Pet` и `Observation→Stay`.** Боксы удаляются мягко, а физическое удаление бокса или питомца сотрёт медкарты. Нужен `Restrict`.

## Low
12. **`SingleAsync` по несуществующему id отвечает 500 вместо 404.** Кроме того, `Drug.Trim()` падает на null, а входные данные не проверяются.
13. **`GetBoxCardAsync`: полная сущность `Pet` через `Include` ради одного имени.** Хватит проекции.
