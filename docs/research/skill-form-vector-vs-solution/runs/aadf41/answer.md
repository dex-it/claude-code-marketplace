Полный список находок записан в `/Users/anonymous/.cache/research/runs/aadf41/work/_answer.md`. Кратко, самое критичное:

1. **critical** — `redeem()` не проверяет знак `confirm_amount`: отрицательная сумма проходит проверку `amount > balance` и в итоге **увеличивает** баланс баллов вместо списания.
2. **critical** — `get_member`/`save_member` работают в разных транзакциях без блокировки строки — гонка (double-spend) при параллельных списаниях.
3. **critical** — комментарий в `schemas.py` о том, что `Optional[Decimal]` без default делает поле обязательным, **фактически неверен для pydantic 1.10** (проверено по официальному migration guide): поле получает неявный default `None`, старый клиент без `confirm_amount` спишет весь баланс молча, без 422.
4. **high** — `save_member` и `write_audit` не в одной транзакции — возможен списанный баланс без аудиторской записи.
5. **high** — `POINT_VALUE = 0.1` (float) оборачивается в `Decimal(POINT_VALUE)`, что даёт неточное число (задокументированное поведение `decimal`), а не `Decimal("0.1")`.
6. **high** — заявленный в MR «срок действия баллов» нигде не хранится и не проверяется — только косметическое поле в ответе.
7. Ещё ряд medium/low находок (усечение вместо округления при пересчёте в баллы, неполный аудит, неиспользуемое поле `points`, неверный комментарий про отклонение лишних полей, отсутствие auth, пустой `detail` в 404) — подробности в файле ответа.
