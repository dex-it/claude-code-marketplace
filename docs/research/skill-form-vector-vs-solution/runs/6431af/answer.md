Решения:
- Список из маркетинговой системы может быть большим и с повторами, поэтому id дедуплицируются (HashSet) и обрабатываются пачками по 1000. На каждую пачку один запрос `AsNoTracking`, который выбирает только `Id`/`Email`: нет N+1, в память не грузятся все клиенты и не отслеживаются сущности.
- Неизвестные id и клиенты без email пропускаются. Если отправка одному клиенту упала, рассылка остальным продолжается, а в конце выбрасывается `AggregateException` со списком id, которым письмо не ушло. Отмена через `CancellationToken` прерывает рассылку сразу.
- `IEmailSender` асинхронный, поэтому метод возвращает `Task<int>` (число отправленных писем) и принимает необязательный `ct`. В задаче не указана тема письма, поэтому она задаётся параметром конструктора (по умолчанию "Shop").
