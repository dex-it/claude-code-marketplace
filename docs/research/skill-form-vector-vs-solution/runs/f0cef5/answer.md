Провёл ревью MR !87, ответ записан в `_answer.md`. Ключевые находки:

**Critical**
- `BatchService.CompliancePercentAsync` — `compliant / total * 100`: целочисленное деление усекается до умножения, процент почти всегда 0 или 100 (LAB-147 фактически не работает). На стенде этот метод не проверялся.
- Там же — деление на ноль при `total == 0` (партия без проб) бросает `DivideByZeroException`.

**High**
- `BatchService.ListAsync` — `Skip(page * pageSize)` при документированной нумерации страниц с 1 пропускает первую (самую новую) страницу — нарушает LAB-141.
- `BatchService.CloseAsync` — проверка «нет проб без результатов» и перевод в `Done` идут только по пробам со статусом `InAnalysis` (через `GetInAnalysisForBatchAsync`); пробы в статусах `Planned`/`Collected` без результатов не проверяются, партия может закрыться с такими пробами — прямое нарушение правила LAB-143.

**Medium**
- `CompliancePercentAsync` — `Results.All(...)` на пустой коллекции результатов даёт `true`, проба без результатов засчитывается как «соответствующая».
- `CloseAsync` — нет защиты от повторного закрытия уже закрытой партии.
- `GetCardAsync` — через `Include` подтягиваются полные сущности `Result`, хотя в DTO нужны только `Count`/`Any` — стоит заменить на проекцию в SQL.

Плюс несколько low-приоритетных замечаний (отсутствие `HasMaxLength` для `LabCode`/`Number`, отсутствие конвертации `PlannedLocal`+`TimeZoneId`, отсутствие optimistic concurrency) — все в файле ответа.
