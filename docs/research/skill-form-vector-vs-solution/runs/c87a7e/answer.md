**Решения:**
- **Удаление клиента — мягкое**, потому что README запрещает физически удалять данные. В одной транзакции клиент, его питомцы, их аллергии и визиты помечаются удалёнными с одним общим временем удаления. Визиты нужно помечать явно: фильтр по визитам не проверяет питомца, и без этого визиты остались бы в расписании врача. По общему времени поддержка сможет восстановить удаление целиком.
- **При замене аллергий тоже ничего не удаляется физически.** Неизменившиеся записи остаются как есть. Пропавшие из списка или изменённые записи помечаются удалёнными, изменённые добавляются заново, так что прежние значения остаются в истории. На время замены строка питомца блокируется. Пустой аллерген, повтор в списке или недопустимая тяжесть дают ответ 400.
- **Колонка переименовывается через `RenameColumn`, а не удаляется и создаётся заново**, поэтому данные не теряются. Миграция идёт через обычный процесс CI: скрипт, проверка DBA, запуск в окно обслуживания.
