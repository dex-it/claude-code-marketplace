Решения:
- **Заказы (а, б).** Все методы только читают данные: заказы проецируются в DTO, продукты читаются с AsNoTracking, так что lazy-load прокси и трекинг не задействуются. Soft-delete фильтр для заказов работает сам. Одна карточка грузится одним запросом (AsSingleQuery). Выгрузка тысяч заказов идёт через AsSplitQuery с OrderBy(Id), чтобы не было декартова произведения Items x Payments.
- **GetProductBySku (в).** `warehouse` стал `string?`. Если склад передан, работает SingleOrDefault по паре (Sku, Warehouse). Если склад null, а SKU лежит на нескольких складах, метод бросает исключение о неоднозначности. Произвольный склад не выбирается, потому что у складов разные цена и остаток. Для списка по всем складам добавлен GetProductsBySkuAsync.
  - Раз бизнес сейчас передаёт только sku, для SKU с нескольких складов этот метод будет падать. Такие вызовы нужно перевести на GetProductsBySkuAsync.
  - Уникальность (Sku, Warehouse) стоит закрепить уникальным индексом через отдельную миграцию. Я её не добавлял.
- **Дата последней отгрузки (г).** Считается в БД через MAX по ShippedAt с фильтром `!= null`. Если у клиента нет отгрузок, метод бросает понятное исключение и не возвращает default(DateTime). У ShippedAt не задан тип колонки, поэтому Npgsql 8 по умолчанию делает `timestamptz` и возвращает Kind=Utc. CreatedAt при этом хранится как `timestamp without time zone`.
