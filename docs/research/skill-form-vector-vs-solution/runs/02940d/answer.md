**Решения**
- **Сортировка реестра.** В SQL попадают только заранее заданные фрагменты, значения от фронта туда не вставляются. Статусы идут по ходу работы с заявкой, а не по алфавиту. Квартиры сортируются по номеру как по числу, чтобы «2» шла раньше «10». Новые колонки пришлось добавить и в SELECT реестра: без них весь реестр падал бы с ошибкой.
- **Закрытие заявки.** Проверка статуса и закрытие — один запрос к базе, поэтому два мастера не смогут закрыть одну заявку одновременно. Если заявки нет — 404, если она не в статусе InProgress — 409, без комментария — 400.
- **Замена плана.** Работы сопоставляются по коду: те, что остаются, обновляются на месте и сохраняют историю выполнения. Новые добавляются. Отсутствующие удаляются вместе с отметками о выполнении — это следует из «план должен стать таким, как прислано», но учтите, что акты по удалённым работам пропадут. Повторяющиеся коды и периодичность меньше одного дня дают 400.
