## Решения

- **Площадь «Теплицы №1».** Она неизвестна, поэтому в базе площадь может быть пустой, и миграция её не выдумывает. Её нужно внести вручную. Для новых теплиц площадь обязательна и должна быть больше нуля.
- **Время показаний без времени измерения.** Время в базе хранится по местным часам площадки, поэтому момент приёма пакета переводится в часовой пояс из `Monitoring:SiteTimeZone`. Просто записать время сервера в UTC было бы неверно, и драйвер Npgsql такое значение в эту колонку не запишет. Если пояс не задан, пакет без времени завершится понятной ошибкой.
- **Фильтр по метке.** Поиск идёт без учёта регистра, введённый фрагмент ищется буквально: символы `%`, `_` и `\` не работают как шаблоны.

## Что нужно сделать до выкатки

- **Часовой пояс площадки.** Задать `Monitoring:SiteTimeZone` в конфигурации (например, `Europe/Moscow`) и подключить его через `services.Configure<MonitoringOptions>(...)`.
- **Регистрация датчиков.** Вызывающий код (контроллер) не входит в этот каталог. Его нужно дополнить параметром теплицы, иначе он не соберётся.
- **Обнаружение миграции.** В каталоге нет файлов `*.Designer.cs` и снимка модели (`ModelSnapshot`). Поэтому метки, по которым bundle находит миграцию, я записал прямо в файл миграции. Если снимок есть в основном репозитории, его нужно обновить, иначе следующая сгенерированная миграция будет неверной.
- **Окно между migrate и deploy.** Пока работает старая версия приложения, регистрировать датчики она не сможет: колонка теплицы уже будет обязательной.
- **Регистр кириллицы.** Фильтр по метке корректно не учитывает регистр русских букв, только если локаль базы (`lc_ctype`) не `C`.
