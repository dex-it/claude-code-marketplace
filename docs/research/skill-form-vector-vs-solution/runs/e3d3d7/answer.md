**Решения:**
- **(а) Отметка прихода `/checkin`.** Уникален не сам e-mail, а пара (EventId, Email), поэтому один e-mail может быть зарегистрирован на несколько мероприятий. Ищу регистрацию только среди мероприятий на сегодня (по локальной дате сервера). Можно передать необязательный `eventId`. Если подходят несколько мероприятий, возвращаю 409 со списком вариантов и ничего не отмечаю наугад. Если регистрации нет — 404. При повторной отметке `CheckedInAt` не перезаписывается. Список воркшопов для бейджа выбираю без обращения к залу, поэтому фильтр удалённых залов (`IsDeleted`) не скрывает оплаченные воркшопы. На бейдж добавлена компания.
- **(б) Отчёт по выручке.** Квартал берётся по `PaidOn` как интервал [начало, начало + 3 мес.). Суммирую фактически оплаченное `PaidAmount`, а не текущую `Price`. Число мест = число билетов. Фильтр удалённых залов в отчёте отключён (`IgnoreQueryFilters`), иначе пропадут деньги залов, выведенных из эксплуатации. Добавил индекс по `PaidOn`.
- **(в) Программа.** `PublishedOn` хранит только дату, поэтому при нескольких версиях в один день выбирается версия с большим Id. Пункты отсортированы по `StartsAt`. Если программы нет — 404.
- **(г) Компания.** `Registration.Company` — `string?`, не длиннее 200 символов. Это необязательный параметр в `RegisterRequest`, так что старые клиенты продолжат работать. **Нужно создать миграцию:** в проекте нет каталога миграций, а сам я `dotnet ef` не запускал. Для уже существующей регистрации `RegisterAsync` по-прежнему просто возвращает её Id и компанию не обновляет.
