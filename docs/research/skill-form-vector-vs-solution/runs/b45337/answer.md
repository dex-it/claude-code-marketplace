# Ревью MR !238: найденные дефекты

Код только читал, сборку и тесты не запускал. Этот же ответ записан в `_answer.md`.

## 1. [critical] Последний осмотр выбирается по времени приёма сервером
**Где:** `VehicleService.cs`, `GetLastInspectionAsync` (используется в `StartTripAsync`).

**Что не так:**
- Сортировка идёт по `CreatedAt`. Это время приёма сервером, его задаёт `now()`.
- Планшет без сети присылает осмотры пачкой, и вся пачка сохраняется одним `SaveChanges`. В PostgreSQL `now()` возвращает время начала транзакции, поэтому у всех осмотров пачки одинаковый `created_at`. Какой осмотр окажется «последним», не определено.
- Между разными планшетами: старый осмотр, отправленный позже, «перекрывает» более свежий.

**Почему дефект:** машину с блокирующей неисправностью можно выпустить на линию. Кроме того, свежесть проверяется по `InspectedAt`, а сам осмотр выбирается по `CreatedAt`, и эти правила не согласованы.

**Исправление:** сортировать по `InspectedAt`, затем по `Id`, и добавить индекс `(vehicle_id, inspected_at)`.

## 2. [high] `ReplaceEquipmentAsync` не заменяет комплектацию
**Где:** `VehicleService.cs`, `ReplaceEquipmentAsync`.

**Что не так:** машина загружается без `Include(v => v.Equipment)`, поэтому `Clear()` ничего не удаляет. При второй отправке с тем же кодом срабатывает уникальный индекс `(vehicle_id, code)`, и клиент получает 500. Коды, которых больше нет в новом составе, остаются в базе.

**Почему дефект:** основной сценарий FLEET-104 не работает. Правильный образец есть в `DriverService.ReplacePermitsAsync`.

## 3. [high] Endpoint `PUT /vehicles/{id}/equipment` без политики доступа
**Где:** `Program.cs`.

**Что не так:** нет `.RequireAuthorization("Mechanic")`. Комплектацию любой машины может переписать любой пользователь с токеном.

## 4. [high] Миграция сужает `vehicles.model` с 200 до 40 символов
**Где:** `Migrations/20260924100000_VehicleEquipmentAndModelLength.cs` (`Up`) и `FleetDbContext`.

**Что не так:** в MR сказано, что длинные названия уже есть в базе. На prod `ALTER TYPE varchar(40)` упадёт с ошибкой `value too long`, и выкатка сломается. Если данные заранее обрезать, информация потеряется. Вдобавок `ALTER` переписывает таблицу под `ACCESS EXCLUSIVE` lock.

**Исправление:** ограничение печатной графы — это вопрос отображения. Обрезать строку нужно при печати путевого листа, а длину колонки оставить 200.

## 5. [high] Отчёт FLEET-109 всегда возвращает 500
**Где:** `TripService.cs`, `OffDayTripsAsync`.

**Что не так:** поле `OffDay` вычисляется C#-методом `WorkCalendar.IsWorkingDay`. В конечной проекции EF может выполнить его на клиенте. Но здесь после проекции стоят `.Where(r => r.OffDay)` и `.OrderByDescending(r => r.Km)`, и EF выбрасывает «could not be translated».

**Исправление:** загрузить поездки за месяц, а фильтровать и сортировать в памяти.

## 6. [high] Фильтр по машине ломает SQL незакрытых путевых листов
**Где:** `TripService.cs`, `GetOpenWaybillsAsync`.

**Что не так:**
- Без фильтра SQL выполняется как есть, поэтому проверка «по всему парку» прошла.
- С `vehicleId` EF оборачивает SQL в подзапрос. Завершающая `;` внутри подзапроса даёт синтаксическую ошибку, и клиент получает 500.
- `ORDER BY` внутри подзапроса не гарантирует порядок результата.

**Исправление:** убрать `;` и `ORDER BY` из SQL и сортировать через LINQ.

## 7. [medium] Допуск не действует в последний день
**Где:** `TripService.cs`, `StartTripAsync`.

**Что не так:** условие `ValidUntil > today`. По требованию допуск действует включительно, нужно `>=`.

**Почему дефект:** в последний день действия допуска водителю отказывают в выпуске.

## 8. [medium] Нет проверки на открытую поездку и гонки
**Где:** `TripService.cs`, `StartTripAsync`.

**Что не так:** не проверяется, что у машины или водителя уже есть незакрытая поездка. В базе тоже нет ограничения, например частичного уникального индекса `trips(vehicle_id) WHERE finished_at IS NULL`.

**Почему дефект:** повторный клик или два диспетчера создают дубли путевых листов.

## 9. [low] Осмотр «из будущего» всегда считается свежим
**Где:** `StartTripAsync`.

**Что не так:** `InspectedAt` берётся с часов планшета, а у проверки свежести нет верхней границы.

## 10. [low] Нет валидации входных данных
- `ReplaceEquipmentAsync`:
  - `Qty` может быть ≤ 0.
  - `Code` длиннее 32 символов даёт 500 вместо 400.
  - `DistinctBy` чувствителен к регистру и молча отбрасывает дубли.
  - Комплектацию можно заменить у списанной машины.
- `OffDayTripsAsync`: неверный `month` даёт 500 вместо 400.
