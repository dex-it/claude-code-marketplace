Решения:
- **(а) и (б)** Запросы только читают данные (`AsNoTracking`) и сразу выбирают нужные поля в DTO. Поэтому ленивая загрузка из `UseLazyLoadingProxies` не срабатывает и лишних запросов на каждый заказ не будет. Карточка одного заказа грузится одним запросом с JOIN. Для выгрузки всех заказов клиента стоит `AsSplitQuery`, иначе при тысячах заказов позиции и платежи перемножаются в огромную выборку. Заказы отсортированы по `CreatedAt desc, Id`. Если объёмы вырастут ещё, понадобится постраничная выдача.
- **(в)** Если склад передан, метод ищет продукт по паре (Sku, Warehouse), она уникальна. Если склад null, под одним SKU может быть несколько складов, поэтому `Single` упал бы. Вместо него метод берёт первую строку, отсортированную по складу, чтобы результат был предсказуемым. Какой склад выбирать, когда он не передан, должен решить бизнес. Уникальность (Sku, Warehouse) стоит закрепить уникальным индексом через миграцию, я его не добавлял.
- **(г)** Заказы без даты отгрузки отсекаются, а максимальная дата считается в SQL. Если у клиента нет ни одного отгруженного заказа, метод бросает `InvalidOperationException` с понятным текстом: вернуть «пусто» при не nullable `DateTime` нельзя. Удалённые заказы (`IsDeleted`) отсекает уже настроенный глобальный фильтр.
