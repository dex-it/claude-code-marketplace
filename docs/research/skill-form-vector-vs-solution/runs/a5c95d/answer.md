**Решения:**
- **(а) и (б)** Все запросы только читают данные (`AsNoTracking`) и сразу собирают DTO. Поэтому ленивая загрузка связанных данных не срабатывает и лишних запросов нет. Карточка одного заказа грузится одним запросом с JOIN. Выгрузка всех заказов клиента разбита на три запроса (`AsSplitQuery`): заказы, позиции, платежи. Иначе при тысячах заказов строки перемножились бы. Сортировка по `CreatedAt, Id`, чтобы порядок был стабильным.
- **(в)** Параметр склада сделан `string?`. Если склад передан, продукт ищется по паре SKU + склад, которая уникальна (`SingleOrDefault`). Если склада нет, берётся первый продукт с сортировкой по складу (`FirstOrDefault`). `Single` здесь упал бы, как только SKU окажется на двух складах. **Нужно решение бизнеса:** какой склад выбирать, когда он не указан. Сейчас это просто первый по алфавиту.
- **(г)** Максимальная дата отгрузки считается в базе, заказы без даты отгрузки отфильтрованы явно. Если у клиента нет отгруженных заказов, метод бросает `InvalidOperationException` с понятным сообщением, поэтому возвращаемый тип остаётся `DateTime`. Удалённые заказы отсекает фильтр, который уже есть в модели.
