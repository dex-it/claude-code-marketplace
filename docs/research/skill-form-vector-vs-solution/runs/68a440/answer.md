Нашёл 14 дефектов: 1 critical, 6 high, 4 medium, 3 low. Код не менял, сборку и тесты не запускал, выводы сделаны только по чтению кода. Тот же список записан в `_answer.md`.

## Critical
1. **`Services/InpatientReportService.cs`, `GetOccupancyAsync`: SQL-инъекция.**
   - **Что не так:** `ward` и `sortBy` приходят из query string и вставляются в строку SQL, которая выполняется через `FromSqlRaw`.
   - **Почему дефект:** эндпоинт доступен любому вошедшему пользователю. Он может выполнить произвольный SQL от имени `vet_app`, то есть читать и менять любые данные.
   - **Как исправить:** `ward` передавать параметром. `sortBy` — это имя столбца, параметром его не передать: нужен белый список столбцов и сортировка через `OrderBy` в LINQ.

## High
2. **`Data/ClinicDbContext.cs`, фильтр `HasQueryFilter(!IsDecommissioned)` на `Box`.**
   - **Что не так:** `Stay.Box` — обязательная связь, поэтому EF соединяет госпитализации с отфильтрованными боксами через INNER JOIN.
   - **Почему дефект:** пациенты из выведенного бокса пропадают из списка отделения, отчёта о занятости и обхода главврача, а README требует, чтобы они там оставались до выписки. Их нельзя выписать: `DischargeAsync` падает. Карточка такого бокса отдаёт 404.
3. **`WardService.GetLongStaysAsync`.**
   - **Что не так:** в `Where` стоит `DaysInWard`, а это вычисляемое свойство C#, которого нет в базе.
   - **Почему дефект:** EF не может перевести его в SQL и бросает исключение, так что эндпоинт `/long-stays` будет падать всегда. Вдобавок «сегодня» считается по UTC.
4. **`WardService.ReplaceMedicationPlanAsync`.**
   - **Что не так:** `MedicationOrders.Clear()` отвязывает существующие назначения, а внешний ключ обязательный и стоит `Restrict`.
   - **Почему дефект:** `SaveChanges` бросает исключение, то есть заменить план, в котором уже есть назначения, нельзя. Если обойти это каскадом, назначения будут физически удаляться, а README это запрещает.
   - **Как исправить:** ставить `CancelledAt` старым назначениям и добавлять новые.
5. **`WardService.DischargeAsync`: счёт занижен на один день.**
   - **Что не так:** по README оплачиваются и день поступления, и день выписки, а формула считает на день меньше.
   - **Почему дефект:** каждый счёт меньше на суточный тариф, а при выписке в день поступления сумма равна 0. Та же ошибка в `Stay.DaysInWard`.
6. **`Api/InpatientEndpoints.cs`, эндпоинт выписки.**
   - **Что не так:** стоит `RequireAuthorization()` без политики `Vet`.
   - **Почему дефект:** выписать пациента и сформировать счёт могут администраторы ресепшена, хотя по README это право только врача.
7. **`Program.cs`: миграции при старте приложения.**
   - **Что не так:** `MigrateAsync()` вызывается при каждом запуске.
   - **Почему дефект:** в проде у роли `vet_app` нет прав на изменение схемы. Если появится миграция, которую ещё не применили, приложение упадёт при старте и будет перезапускаться по кругу. Кроме того, это обход проверки скрипта DBA. И три реплики при rolling update начнут мигрировать одновременно, а в EF Core 8 блокировки миграций нет.

## Medium
8. **`GetBoxCardAsync`.** Текущий пациент бокса ищется через `SingleOrDefaultAsync`, а в боксе может лежать до `Capacity` животных. Если пациентов больше одного, карточка падает с 500.
9. **`GetLatestStayAsync`.** Повторная госпитализация в тот же день — обычная ситуация, и тогда сортировка только по `AdmittedOn` неоднозначна. С `AsSplitQuery` шапка карточки и назначения/наблюдения могут взяться из разных госпитализаций. Нужно добавить `ThenByDescending(Id)`.
10. **`GetOccupancyAsync`.** EF оборачивает сырой SQL в подзапрос, и PostgreSQL не обязан сохранять `ORDER BY` из подзапроса. Сортировка с экрана может не работать.
11. **`ClinicDbContext`.** Связи `Stay → Box` и `Stay → Pet` по умолчанию удаляются каскадом. Удаление бокса или питомца молча сотрёт госпитализации и наблюдения, то есть часть медкарты.

## Low
12. **`DischargeAsync`, `ReplaceMedicationPlanAsync`.** Нет защиты от одновременных изменений: при двух одновременных выписках вторая перезапишет дату и сумму.
13. **Уникальный `Code` и фильтр боксов.** Выведенный бокс не находится по коду, но создать новый бокс с тем же кодом нельзя.
14. **Коды ответов.** Несуществующий id и бизнес-ошибки («уже выписан», неверная дата) возвращаются как 500 вместо 404/409/400.
