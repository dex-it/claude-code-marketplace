# Ревью MR !214 — стационар

## 1. `Services/InpatientReportService.cs` — `GetOccupancyAsync`: SQL-инъекция через `FromSqlRaw` — **critical**
`ward` и `sortBy` приходят из query-string и подставляются в SQL через интерполяцию C#-строки, которая потом передаётся в `FromSqlRaw`.
- **Почему дефект:** любой авторизованный пользователь, включая ресепшен, может выполнить произвольный SQL от имени `vet_app`: прочитать или изменить любые данные.
- **Как исправить:** значение `ward` передавать параметром. `sortBy` — идентификатор, параметром его не передать, поэтому нужен белый список столбцов (switch → `OrderBy` в LINQ). Лучше вообще отказаться от сырого SQL: запрос целиком выражается в LINQ.
- **Вторая проблема:** EF оборачивает `FromSqlRaw` в подзапрос и дописывает к нему JOIN'ы. `ORDER BY` внутри подзапроса PostgreSQL не обязан сохранять, поэтому сортировка, выбранная на экране, может теряться. Сортировать нужно во внешнем LINQ.

## 2. `Api/InpatientEndpoints.cs` — `POST /stays/{id}/discharge`: нет политики `Vet` — **high**
Стоит `.RequireAuthorization()` без политики, поэтому выписать пациента и сформировать счёт может любой аутентифицированный пользователь, в том числе ресепшен.
- **Почему дефект:** README прямо запрещает это: выписку оформляет только врач.
- **Как исправить:** `.RequireAuthorization("Vet")`.

## 3. `Services/WardService.cs` — `DischargeAsync`: стоимость меньше на одни сутки — **high**
`days = dischargedOn.DayNumber - AdmittedOn.DayNumber` не включает один из граничных дней.
- **Почему дефект:** по README считаются все календарные дни, включая день поступления и день выписки. Сейчас каждый счёт меньше на один суточный тариф, а при выписке в день поступления сумма равна 0.
- **Как исправить:** `+ 1`.

## 4. `Data/ClinicDbContext.cs` — глобальный фильтр `!IsDecommissioned` на `Box` при required-связи `Stay → Box` — **high**
Фильтр применяется и к навигациям. Для required-навигации EF строит INNER JOIN на отфильтрованные `Boxes` (и выдаёт warning 10622 об этом сочетании).
- **Почему дефект:** по README бокс можно вывести из эксплуатации, пока в нём лежат пациенты, и такие пациенты должны оставаться в списках до выписки. Сейчас:
  - `GetWardPatientsAsync`, `GetLongStaysAsync` и `GetOccupancyAsync` молча теряют пациентов из выведенного бокса;
  - `DischargeAsync` (`Include(s => s.Box).SingleAsync`) бросает исключение, и пациента нельзя выписать;
  - `GetBoxCardAsync` для такого бокса возвращает 404.
- **Как исправить:** фильтр не делать глобальным, а применять явно там, где подбирается бокс при поступлении.

## 5. `Services/WardService.cs` — `ReplaceMedicationPlanAsync`: `Clear()` при `Restrict` — **high**
`Clear()` разрывает required-связь, а связь настроена как `DeleteBehavior.Restrict`.
- **Почему дефект:** `SaveChangesAsync` бросает `InvalidOperationException`, и `PUT /medications` падает с 500 на любой госпитализации, где уже есть назначения. Настройка каскада проблему не решит: README запрещает физически удалять назначения.
- **Как исправить:** действующим назначениям ставить `CancelledAt`, новые добавлять, `Clear()` убрать.

## 6. `Services/WardService.cs` — `GetLongStaysAsync`: нетранслируемое условие `DaysInWard` — **high**
`DaysInWard` — вычисляемое C#-свойство, в модели оно не замаплено.
- **Почему дефект:** EF не может перевести `s.DaysInWard > 14` в SQL и на выполнении бросает `InvalidOperationException`, поэтому `/long-stays` не работает вообще.
- **Как исправить:** условие на маппленых полях, например `s.AdmittedOn < today.AddDays(-14)`.

## 7. `Services/WardService.cs` — `GetBoxCardAsync`: `SingleOrDefaultAsync` на неуникальном условии — **high**
В боксе может лежать до `Capacity` животных (README: помёт или животные одного владельца).
- **Почему дефект:** при двух и более пациентах в боксе `SingleOrDefaultAsync` бросает исключение, и карточка бокса возвращает 500.
- **Как исправить:** вернуть список текущих пациентов через проекцию, без `Include(s => s.Pet)` ради одного `Name`.

## 8. `Program.cs` — `MigrateAsync()` при старте приложения — **high**
- **Почему дефект:**
  - у роли `vet_app` нет прав на DDL, поэтому при любой неприменённой миграции все 3 реплики уходят в crash loop;
  - схема меняется в обход принятого процесса: идемпотентный скрипт → ревью DBA → `db-migrate` под `vet_migrator`;
  - при rolling update реплики применяют миграции одновременно, а блокировки миграций в EF Core 8 нет.
- **Как исправить:** убрать вызов. Для локальной разработки — `dotnet ef database update` или вызов только в Development.

## 9. `Services/WardService.cs` — `GetLatestStayAsync`: «последняя» госпитализация выбирается недетерминированно — **medium**
`OrderByDescending(AdmittedOn)` не уникален: повторная госпитализация в тот же день бывает, а дата хранится без времени.
- **Почему дефект:** при совпадении дат может вернуться не последняя госпитализация. С `AsSplitQuery` хуже: корень и коллекции выбираются отдельными запросами и могут попасть на разные госпитализации. Тогда врач видит пустой или чужой план назначений.
- **Как исправить:** добавить `.ThenByDescending(s => s.Id)`. Сам split при двух коллекциях обоснован.
- **Попутно (low):** отменённые назначения сейчас загружаются и фильтруются в памяти. Лучше фильтровать в БД через filtered include или проекцию.

## 10. `Data/ClinicDbContext.cs` — каскад на FK `Stay → Box`, `Stay → Pet`, `Observation → Stay` — **medium**
По конвенции эти FK созданы с `ON DELETE CASCADE`.
- **Почему дефект:** у `Box` soft-delete, а госпитализации и наблюдения — медицинская история. Одно физическое удаление бокса или питомца молча её сотрёт. Если у госпитализации есть назначения, удаление упадёт на `Restrict`, то есть поведение ещё и непоследовательное.
- **Как исправить:** `OnDelete(DeleteBehavior.Restrict)`.

## 11. `Services/WardService.cs` — `DischargeAsync` / `ReplaceMedicationPlanAsync`: нет защиты от параллельной правки — **medium**
Нет ни concurrency token, ни блокировки.
- **Почему дефект:** двойная выписка проходит дважды, проверка «уже выписан» не срабатывает. Два врача, параллельно меняющие план, получают задвоенные назначения или теряют чужие изменения.
- **Как исправить:** concurrency token на `Stay` (например, `xmin` через `UseXminAsConcurrencyToken()` в Npgsql) и `DbUpdateConcurrencyException` → 409.

## 12. `Services/WardService.cs` — `SingleAsync` по id в `DecommissionBoxAsync`, `ReplaceMedicationPlanAsync`, `DischargeAsync` — **low**
- **Почему дефект:** для несуществующего id клиент получает 500 вместо 404. Повторный вывод уже выведенного бокса из-за фильтра тоже даёт 500.
- **Как исправить:** `SingleOrDefaultAsync` и `NotFound`.
