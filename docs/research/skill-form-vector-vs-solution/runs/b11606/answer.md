Решения:
- **Complexity:** обычное `int`-свойство заказа, по умолчанию 1. Диапазон 1..5 проверяет CHECK-ограничение `CK_Order_Complexity`. Миграцию сюда не добавлял, в проекте их нет. Когда будете её создавать, задайте колонке `defaultValue: 1`, иначе у существующих заказов будет 0 и ограничение не пройдёт.
- **CreatedAt:** колонка по-прежнему `timestamp without time zone`. При записи значение переводится в UTC и сохраняется без пометки таймзоны, иначе Npgsql бросает исключение. При чтении значение получает `Kind=Utc` без сдвига времени, так что в коде оно всегда в UTC.
- **Связи:** мягкое удаление заказа — это UPDATE, поэтому каскадного удаления в БД нет ни у одной связи. Позиции (`ClientCascade`) удаляются только через EF, на этом работает `ClearItemsAsync`: загрузить заказ с позициями, очистить список, сохранить. Платежи (`Restrict`) вместе с заказом не удаляются никогда.
- **Имя метода:** назвал `ClearItemsAsync`, а не `ClearItems`, чтобы совпадало с остальными async-методами репозитория. Если нужно точно имя из поручения, это правка в одном месте.
- **virtual:** в проекте включены lazy-loading proxies (`UseLazyLoadingProxies`), а они требуют виртуальных навигаций. Без этого EF отказался бы строить модель. `Customer.Orders` тоже был невиртуальным, это уже было ошибкой в исходном коде, поэтому я его исправил.
