Решения:
- **Complexity** — простое поле `int` на `Order` (не отдельный тип из одного поля) с ограничением в БД `BETWEEN 1 AND 5`, по умолчанию 1. Миграций в проекте нет. Когда её будут делать, для существующих строк нужен `defaultValue: 1`, иначе ограничение не пропустит 0.
- **CreatedAt**: колонка остаётся `timestamp without time zone`. При записи время приводится к UTC без пометки Kind, потому что Npgsql 6+ не даёт записать `Kind=Utc` в такую колонку. При чтении значению только ставится `Kind=Utc`, без сдвига в локальное время.
- **Связи и ClearItems**: для Items и Payments удаление вместе с заказом в БД запрещено (`OnDelete(Restrict)`), поэтому ручной `DELETE` заказа не снесёт позиции и платежи. Из-за этого `ClearItemsAsync` не может использовать `Items.Clear()`: при обязательном `OrderId` EF выбросит исключение при сохранении. Вместо этого позиции удаляются одним `ExecuteDeleteAsync` и только у существующего, не удалённого мягко заказа.

Метод назван `ClearItemsAsync`, а не `ClearItems`, как принято в репозитории. Если нужно ровно то имя, что в поручении, переименую.
