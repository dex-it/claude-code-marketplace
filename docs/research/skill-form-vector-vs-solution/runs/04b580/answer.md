Нашёл 13 дефектов: один critical (SQL-инъекция), восемь high, два medium, два low. Сборку и тесты не запускал, код не менял; ответ записан в `_answer.md`.

# Ревью MR !214 — стационар (VetClinic.Hospital)

## Critical

### 1. `Services/InpatientReportService.cs` — `GetOccupancyAsync`: SQL-инъекция через `ward` и `sortBy`
`ward` и `sortBy` берутся из query string и подставляются в текст SQL интерполяцией строки, потом передаются в `FromSqlRaw`. Значения не уходят как `DbParameter`.
- Любой авторизованный пользователь может выполнить произвольный SQL под ролью `vet_app`. Эндпоинт закрыт только `RequireAuthorization()`.
- Примеры: `ward=x' OR 1=1 --` или `sortBy=Id"; DELETE FROM "Stays"; --`.

**Исправление:**
- Фильтр написать на LINQ, а сортировку выбирать через `switch` по белому списку допустимых столбцов.
- Если SQL оставлять, `ward` передавать параметром через `FromSql($"…{ward}…")`, а `sortBy` пропускать только через белый список.

## High

### 2. `Data/ClinicDbContext.cs` — `HasQueryFilter` на `Box` при required-связи `Stay → Box`: пациенты из выведенных боксов пропадают
У `Box` есть фильтр `!IsDecommissioned`, а у `Stay` согласованного фильтра нет. Через required-навигацию EF делает INNER JOIN с уже отфильтрованным `Box`, и госпитализации в выведенных боксах выпадают из результата. Это нарушает правило README: пациенты остаются в списках отделения, пока их не выписали.
- **`GetWardPatientsAsync`:** пациенты выведенного бокса пропадают из списка отделения.
- **`GetLongStaysAsync` и `GetOccupancyAsync`:** эти госпитализации тоже выпадают.
- **`DischargeAsync`:** `SingleAsync` бросает исключение, выписать пациента из выведенного бокса нельзя (500).
- **`GetBoxCardAsync`:** для выведенного бокса возвращается 404, хотя в нём ещё лежат пациенты.
- **`DecommissionBoxAsync`:** повторный вызов падает с 500.

**Исправление:** глобальный фильтр убрать и фильтровать `IsDecommissioned` явно при подборе бокса для поступления. Если фильтр оставлять, в запросах по госпитализациям нужен `IgnoreQueryFilters()`.

### 3. `Services/WardService.cs` — `ReplaceMedicationPlanAsync`: `Clear()` при `Restrict`
`Clear()` разрывает required-связь, а для неё задано `DeleteBehavior.Restrict`, поэтому `SaveChanges` бросит `InvalidOperationException`.
- Первый план сохранится, потому что коллекция пустая. Любая замена плана будет падать с 500.
- Переход на Cascade тоже не годится: по README назначения физически не удаляются, при отмене выставляется `CancelledAt`.

**Исправление:** у активных назначений проставлять `CancelledAt = DateTime.UtcNow` и добавлять новые, без `Clear()`.

### 4. `Services/WardService.cs` — `GetLongStaysAsync`: нетранслируемое условие `s.DaysInWard > 14`
`DaysInWard` — вычисляемое C#-свойство без колонки. EF Core 8 не может перевести его в SQL и бросает исключение, поэтому эндпоинт `/long-stays` всегда отвечает 500.

**Исправление:** условие через колонку, например `s.AdmittedOn < today.AddDays(-14)`, где `today` посчитан заранее.

### 5. `Services/WardService.cs` — `GetBoxCardAsync`: `SingleOrDefaultAsync` на неуникальном условии
Условие «бокс + не выписан» неуникально: по README в боксе может лежать до `Capacity` животных. Если пациентов больше одного, метод бросает исключение и отдаёт 500. Кроме того, `BoxCardDto` рассчитан только на одного пациента.

**Исправление:** вернуть список текущих пациентов, через проекцию, а не `Include` полной сущности.

### 6. `Services/WardService.cs` — `DischargeAsync`: неверный расчёт стоимости
По README в стоимость входят и день поступления, и день выписки, а в коде нет `+ 1`.
- Каждый счёт занижен на один суточный тариф.
- При выписке в день поступления сумма получается 0.

### 7. `Api/InpatientEndpoints.cs` — `/stays/{id}/discharge`: не та политика авторизации
На эндпоинте стоит только `RequireAuthorization()`, поэтому выписать пациента и сформировать счёт может любой авторизованный пользователь, включая ресепшен. По README выписку оформляет только врач.

**Исправление:** `.RequireAuthorization("Vet")`.

### 8. `Program.cs` — `MigrateAsync()` при старте приложения
Это нарушает процесс выкладки: идемпотентный SQL-скрипт, проверка DBA, джоба `db-migrate` под `vet_migrator`.
- **Нет прав на DDL:** в проде приложение работает под `vet_app`. Если хоть одна миграция не применена, `MigrateAsync` попытается выполнить DDL и упадёт, под-ы уйдут в crash-loop.
- **Гонка реплик:** 3 реплики при rolling update будут запускать миграции одновременно. В EF Core 8 нет блокировки миграций (она появилась в EF 9).
- **Обход DBA:** миграции применяются без проверки.

**Исправление:** вызов убрать или включать только для Development; миграции катить артефактом через `db-migrate`.

### 9. `Services/WardService.cs` — `GetLatestStayAsync`: `AsSplitQuery` + `FirstOrDefault` с неуникальной сортировкой
В домене повторная госпитализация в тот же день допустима, поэтому сортировка только по `AdmittedOn` не детерминирована.
- При split query запросы коллекций повторяют `ORDER BY … LIMIT 1` отдельно и могут выбрать другую госпитализацию.
- В итоге в карточку одной госпитализации попадут назначения и наблюдения другой, и врач увидит неверные назначения.
- К тому же отменённые назначения грузятся полными сущностями и фильтруются в памяти.

**Исправление:** добавить `ThenByDescending(s => s.Id)` и собрать карточку одной проекцией в `StayCardDto`, с фильтром отменённых в SQL.

## Medium

### 10. `Services/WardService.cs` — `DischargeAsync` и `ReplaceMedicationPlanAsync`: нет защиты от параллельной правки
Ни у `Stay`, ни у `MedicationOrder` нет concurrency token.
- Две одновременные выписки обе пройдут проверку, и последняя молча перезапишет дату и сумму счёта.
- Две параллельные замены плана (после исправления п. 3) задвоят план.

**Исправление:** concurrency token на `Stay` (например, `xmin`) и обработка `DbUpdateConcurrencyException` с ответом 409. Альтернатива — `SELECT … FOR UPDATE` в явной транзакции.

### 11. `Data/ClinicDbContext.cs` — FK `Stay → Box` с `ON DELETE CASCADE`
Связь объявлена required без `OnDelete`, поэтому миграция создаст каскадное удаление. Физическое удаление бокса снесёт госпитализации, то есть медкарты. Помешают только назначения (`Restrict`); у госпитализаций без назначений вместе с ними удалятся и наблюдения.

**Исправление:** `.OnDelete(DeleteBehavior.Restrict)` для `Stay → Box`.

## Low

### 12. `Services/WardService.cs` — `ReplaceMedicationPlanAsync`, `DecommissionBoxAsync`, `DischargeAsync`: `SingleAsync` на несуществующий id
`SingleAsync` бросает исключение, и клиент получает 500 вместо 404.

### 13. `Services/WardService.cs` — `DischargeAsync`: лишняя загрузка `Box`
`Include(s => s.Box)` загружает и отслеживает полную сущность `Box`, хотя нужен только `DailyRate`, а сам бокс не меняется. Тариф лучше получить проекцией.
