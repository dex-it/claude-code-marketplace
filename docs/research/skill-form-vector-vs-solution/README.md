# Форма пункта trap-skill: вектор или решение

**Вопрос.** Держит ли качество trap-skill, если пункт задаёт вектор (название ситуации, идея Макса из
PR #280), а не решение (триада «Плохо / Правильно / Почему» с готовым ответом)?

**Ответ.** Наполовину.

- **Где Макс прав.** Готовый ответ старой триады вредит на всех трёх тирах: где он неверен, модель
  выполняет его буквально. События вреда класса D:
  - sonnet: триада 13/20, название 6/20;
  - opus: 9/12 против 4/12;
  - haiku: 11/12 против 4/12 (p = 0.009).
- **Где Макс неправ.** Одного названия не хватает там, где решение модели по умолчанию в названной
  ситуации неверно (каскад при soft-delete, алиас `FromSqlRaw`) или где исход - конвенция команды.
  - На sonnet по правилу PREREG названия не хватает в классе A (-25 п.п.).
  - На opus - в A и C.
  - На haiku - в A и C: в классе C названия дают 0/12 против 9/12 у триады.
- **Лучшая форма из проверенных** - название плюс обязательный исход, сверенный заранее (F4, шаг 3
  «Формы пункта»):
  - 36/36 на кейсах лестницы (sonnet), вредных событий 0;
  - 100% во всех классах на opus, вредных событий 0.

  Это не «рыба» старого формата и не «удочка» без наживки, а короткий проверенный ответ.

Норма «Форма пункта» здесь не правится, рекомендация - в последнем разделе.

Предрегистрация - [PREREG.md](PREREG.md), коммит `f9da2ee1` сделан до первого прогона. Отклонения
записаны там же, в разделе «Отклонения от плана», до стадий, которых они касаются. Источники и линия
идеи - [SOURCES.md](SOURCES.md).

## Гипотезы

- **H1 (Макс: название не хуже триады) - опровергнута по правилу PREREG.** На стадии A названия не
  хватает в классе A (-25 п.п., интервал [-45; -6]). На opus и haiku - также в классе C. Названия
  достаточно в B (sonnet, opus) и в D (все тиры).
- **H2 (триада вредит больше) - по правилу стадии A не подтверждена.** Пул: 18/48 против 9/48, p = 0.068.
  Класс D: 13/20 против 6/20, p = 0.056. Порог p < 0.05 не пройден. Направление повторилось на opus
  (9/12 против 4/12) и на haiku (11/12 против 4/12, p = 0.009). По совокупности данных вред готового
  ответа - устойчивый эффект, но в заранее записанный критерий стадия A не уложилась.
- **H3 (в A название достаточно, в B и C - нет) - опровергнута в этой формулировке.**
  - Вышло наоборот для A и B: в A названия не хватает, в B (sonnet, opus) - хватает.
  - C требует исхода на opus и haiku; на sonnet - не решено.
  - Классификация A/B/C/D по признаку, записанному до прогонов, форму не предсказала. Обе провалившиеся
    единицы A - ситуации, которые название называет, а модель по умолчанию решает неверно. Это не
    «пробел узнавания».
- **H4 (тир и поиск) - описательно.**
  - Разрыв F1 и F5 растёт вниз по тиру: в классе C sonnet -17 п.п., opus -33, haiku -75 (кейсы
    стадии C).
  - Opus закрывает класс B без скилла.
  - Предписанный поиск разрыв не закрывает: F1 79% без предписания, 71% с ним.

## Отклонения от предрегистрации

Все записаны в PREREG до стадии, которой касаются:

- стенд E4 - копия с тремя поправками: `ClearItems` ищется в любом классе, допуск по времени 1 мс,
  запасная запись заказа сырым SQL;
- включена стадия H (haiku);
- в стадию B сверх правила добавлен N0;
- в стадию C взята лучшая форма B - F4;
- DISPUTED на строках без спорного исхода решались вручную;
- счёт вреда класса D добавлен в анализ.

D и H шли параллельно с C, три раннера по два процесса одновременно, по решению пользователя.

## Угрозы валидности

- **F4 писал автор, знающий ключ.** Обязательный исход F4 - это верный ответ, записанный тем, кто
  составлял ключ. В жизни исход верен, только если сверен с первоисточником. F4 проверен на
  единицах, по которым лестница B не гонялась (C: E2, L5, FVB, K1), но и там исходы писал автор.
- **Мало единиц.** 4-6 единиц на класс, n=4 на ячейку. На стадии A различимы разности около 40 п.п.,
  а разности 10-20 п.п. - нет.
- **Узкий стек.** Все кейсы .NET, кроме FVB (Python). Кейсы и ловушки взяты из наборов
  PR #280.
- **Классы назначил автор.** Признак записан заранее, но он не предсказал форму (см. H3).
- **Упрощённая среда.** `--restricted`: системный промпт короче, чем у агентов-потребителей
  (`dotnet-coder`), сборка запрещена (кроме исполнения E4 грейдером). Effort фиксирован: sonnet high,
  opus medium, haiku - по умолчанию.
- **Судья - LLM.** Согласие с ручной оценкой 98.9% на 20% выборке. Ручная оценка не полностью слепая:
  ответы исполнителей иногда упоминают `SKILL.md`, и видно, был ли скилл.
- **Подача плагином** шла без `--disable-slash-commands`: встроенные скиллы CLI были видны в сессии.
- **Покрытие тиров.** Opus и haiku гонялись на 6 кейсах из 12, F4 на sonnet - только на 4 кейсах
  стадии B.

## Что это значит для нормы «Форма пункта» и эпика #264

Рекомендация, норма в этой ветке не правится.

1. **Готовый ответ, не сверенный с документацией версии, в пункт не пишется.** Это подтверждено
   на всех тирах. Здесь норма и идея Макса правы.
2. **Название - кандидат, а не форма по умолчанию.** Оно остаётся, только если прогон F1 проходит.
   Ни одну из четырёх целевых единиц стадии B название не взяло полностью: 1/4, 3/4, 1/4, 0/4.
3. **Шаг 3 делится на два, и исход сильнее проверки.** Где нужен шаг 3, ставится обязательный исход
   (F4), сверенный с первоисточником. «Что сверить» (F3) на каскаде при soft-delete дал 0/4.
4. **Факт версии - когда название ведёт в неверное знание.** Факт (шаг 2) ставится, если название
   само вызывает ложные находки (N0: F1 4/4 ложных, F2 0/4).
5. **Класс до прогона определяется только для двух случаев.**
   - Конвенция команды (C) - сразу исход: название не держит её на opus и haiku.
   - Неверная триада (D) - снять готовый ответ.
   - Для остального класс по признаку форму не предсказал. Форма определяется прогоном F0 / F1 / F4
     на кейсе, как и требует метод «Сжатие по свидетельству».
6. **Тир потребителя важен.** Для скиллов с потребителями на haiku названия недостаточно. Для opus
   класс B на этих единицах закрыт без скилла.
7. **Сужение ревью.** Любая форма чек-листа сужает охват ревью на 9-18 п.п. Как это лечить, здесь не
   мерилось.

Для эпика #264: пачки, где потребитель - главный поток или `dotnet-coder` (sonnet), можно сжимать по
лестнице, но с F4 вместо F3 и с прогоном F1 до снятия триады. Пачки с потребителями на haiku - только с
обязательными исходами.
