# Fact Verification

Сверка технического утверждения с источником истины, прежде чем оно попадёт в вывод как факт. Применимо везде, где вердикт держится на поведении фреймворка или библиотеки: находка ревью, корневая причина в диагностике, дефолт в аудите конфигурации. Чтение кода подтверждает, что путь применяется в репозитории, но не истинность утверждения о самом фреймворке. Источник истины - документация версии, используемой в проекте. Каскад по порядку:

1. **context7** по библиотеке. Дефолт платформы - отложенная загрузка MCP: в сессии видно имя тула, определение добирается через `ToolSearch` (select по фактическому имени тула, не по слову «context7»). Тул уже виден в контексте целиком - отложенной загрузки в этой среде нет (`ENABLE_TOOL_SEARCH=false`, `alwaysLoad` у сервера, платформа без tool search), звать напрямую.
2. **WebSearch/WebFetch** первоисточника (docs, changelog релиза) - для общеязыкового факта либо когда звено 1 недоступно или пройдено без ответа. Статья, блог, ответ форума первоисточником не являются: факт, найденный только там, - `unverifiable`, пока его не подтвердило звено 1-4.

Альтернативные звенья - когда 1-2 недоступны, не дали ответа или документация неоднозначна:

3. **Проба на версии проекта.** Минимальный код в изолированном каталоге вне рабочего дерева, на версии пакета из манифеста, без подключения к базам и сервисам пользователя: сгенерированный SQL или скрипт, вывод, текст исключения. В вывод - команда и её результат. Проба показывает поведение версии, а не гарантию: поведение, которого документация не обещает, помечено как наблюдаемое.
4. **Исходник этой версии** - файл по тегу релиза в репозитории библиотеки; у пакета без открытого исходника - декомпиляция сборки из кэша пакетов. В вывод - файл и тег или сборка, по которым прочитано.

Попытки достать не было - звено не пройдено, а не недоступно. Уход от сверки фиксируется явным статусом (`unverifiable` / пометка-предположение / снятие утверждения), не молчанием.

## Чек-лист

Пункт называет ситуацию, в которой факт сверяется.

- Имя API или сигнатура по памяти
- Причинно-следственная связь
- Технический факт из MR, кода или лога: чем подтверждено утверждение в комментарии кода или описании MR
- Сверка по latest вместо версии проекта: версия библиотеки в манифесте проекта и документация этой версии
- Разрешение нормы без условия применимости
- Статус источника на дату использования
- Отрицательный факт «такого API нет»
