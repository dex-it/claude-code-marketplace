# .NET DI - чек-лист

Пункт называет ситуацию, которую изменение проверяет; решение - по документации .NET версии из манифеста проекта.

- Scoped-зависимость в Singleton
- Transient `IDisposable`
- `AddSingleton` с готовым экземпляром
- Повышение lifetime до Singleton
- Регистрация конкретного класса вместо интерфейса
- `new` сервиса вместо DI
- Двойная регистрация одного сервиса
- Open generics и ограничения типа
- `IServiceProvider` в бизнес-коде
- Порядок декораторов
- Ключ keyed-сервиса строкой-литералом в регистрации и в `[FromKeyedServices]`: сколько мест держат один и тот же ключ
- `ValidateScopes` в Production
