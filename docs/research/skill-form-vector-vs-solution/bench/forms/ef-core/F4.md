# Entity Framework Core - чек-лист

Пункт называет ситуацию, которую изменение проверяет; решение - по документации EF Core / Npgsql версии из манифеста проекта.

- Ленивая загрузка навигации в цикле
- Трекинг выборки только для чтения: выборка только для чтения не отслеживается - `AsNoTracking` или проекция
- Полная сущность там, где нужна часть полей
- Фильтр после материализации
- Группировка и агрегаты после материализации
- Нетранслируемое условие фильтра: условие целиком в `IQueryable` до материализации
- Репозиторий материализует выборку
- `!` на nullable-значении без фильтра по null
- `Single` на условии, которое в домене не уникально: при нескольких совпадениях запись не выбирается молча - условие уточняется до уникального или неоднозначность возвращается явно
- Null-guard в спецификации на ненулевом параметре
- Динамически собираемый `FromSqlRaw`: условия ссылаются на алиас шаблона, значения идут параметрами
- `Add` и `AddAsync`
- Owned-тип из одного поля
- `DateTime` и тип колонки в Npgsql: с Npgsql 6 свойство без явного типа - `timestamptz`; в `timestamptz` пишется `Kind=Utc`; в `timestamp without time zone` пишется `Kind=Unspecified`, прочитанное помечается `Utc`
- Soft-delete (`HasQueryFilter`) и каскад FK: FK зависимых в БД без каскада
- Разрыв required-связи (`Clear()` коллекции зависимых): при `Restrict` и `ClientSetNull` разрыв required-связи в `SaveChanges` бросает `InvalidOperationException`; зависимые удаляет код, и разрыв required-связи не бросает исключение
- Параллельная правка одной записи
- `FOR UPDATE` и граница транзакции
- `SaveChanges` в цикле по строкам
- Массовое удаление одной транзакцией
- `UpdateRange` на отслеживаемых сущностях
- Несколько коллекций в одном `Include`-запросе
- Split query на выборке одной сущности: две и более коллекций одного уровня - split законен и на одной сущности
- Применение миграции на production: в production-пайплайне нет `dotnet ef database update` - SQL идёт через idempotent-скрипт с ревью или migrations bundle
- Данные и схема в одной миграции
- Схемная миграция и исторические данные
- Время жизни `DbContext`
- `DbContext` в `BackgroundService`
