# Entity Framework Core - чек-лист

Пункт называет ситуацию, которую изменение проверяет; решение - по документации EF Core / Npgsql версии из манифеста проекта.

- Ленивая загрузка навигации в цикле
- Трекинг выборки только для чтения
- Полная сущность там, где нужна часть полей
- Фильтр после материализации
- Группировка и агрегаты после материализации
- Нетранслируемое условие фильтра
- Репозиторий материализует выборку
- `!` на nullable-значении без фильтра по null
- `Single` на условии, которое в домене не уникально
- Null-guard в спецификации на ненулевом параметре
- Динамически собираемый `FromSqlRaw`
- `Add` и `AddAsync`
- Owned-тип из одного поля
- `DateTime` и тип колонки в Npgsql
- Soft-delete (`HasQueryFilter`) и каскад FK
- Разрыв required-связи (`Clear()` коллекции зависимых)
- Параллельная правка одной записи
- `FOR UPDATE` и граница транзакции
- `SaveChanges` в цикле по строкам
- Массовое удаление одной транзакцией
- `UpdateRange` на отслеживаемых сущностях
- Несколько коллекций в одном `Include`-запросе
- Split query на выборке одной сущности
- Применение миграции на production
- Данные и схема в одной миграции
- Схемная миграция и исторические данные
- Время жизни `DbContext`
- `DbContext` в `BackgroundService`
