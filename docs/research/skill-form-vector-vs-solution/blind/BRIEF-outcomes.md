# Задание: обязательный исход для каждого пункта чек-листа EF Core

Есть trap-skill (скилл-подсказка для модели-исполнителя, которая пишет и ревьюит код на EF Core 8 +
Npgsql 8, .NET 8). Старая редакция - `OLD-SKILL.md` (триады «Плохо / Правильно / Почему»); часть её
«Правильно» неверна или неполна. Новая редакция - чек-лист: на каждую ситуацию одна строка
«название: [факт;] обязательный исход».

Тебе даны названия ситуаций (и для двух - сверенный факт версии) в `units-table.md`. Для КАЖДОЙ
строки реши и запиши одно из трёх:

- `outcome` - обязательный исход: какой наблюдаемый результат должен быть верен в коде/схеме/поведении,
  когда ситуация встретилась. Одна строка, <= 200 символов. Исход, а не способ: конкретный API
  называется, только если верный путь один. Исход должен быть верен для любого проекта на этом стеке,
  а не для одной команды.
- `convention` - верный исход зависит от выбора команды (противоположный выбор тоже работает);
  в каталожный скилл он не годится. Коротко - почему.
- `none` - общего обязательного исхода нет или он тривиален из названия. Коротко - почему.

## Правила

- **Каждый `outcome` сверен с официальной документацией** версии стека (learn.microsoft.com/ef,
  npgsql.org, learn.microsoft.com/dotnet) через WebSearch/WebFetch. URL и короткая цитата - в поле
  `source`. Если по документации подтвердить не удалось - не `outcome`, а `none` с пометкой
  «не подтверждено».
- Не копируй «Правильно» старой редакции на веру: она для тебя - черновик, не источник.
- Работай только в текущем каталоге. Не ищи в сети репозитории, PR, issue про «trap-skill», «dex-it»,
  «claude-code-marketplace» - нужна только документация.

## Выход

Файл `outcomes.yaml` в текущем каталоге:

```yaml
- id: <id из таблицы>
  decision: outcome | convention | none
  text: "<исход одной строкой | причина>"
  source: "<URL> - «цитата»"   # для outcome обязательно
```

Все строки таблицы, в том же порядке.
