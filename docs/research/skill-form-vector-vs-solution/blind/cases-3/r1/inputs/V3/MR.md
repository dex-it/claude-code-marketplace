# MR !342: регистрация участников, промокоды, групповые заказы и отмена с возвратом

## Зачем

К «Биоинформатике-2027» переезжаем с Google-форм на свою регистрацию: оргкомитету нужны промокоды
партнёров, счета для организаций и честный расчёт возвратов.

## Что сделано

**Индивидуальная регистрация** — `POST /api/conferences/{id}/registrations`
- Типы билетов конференции: стандартный (18 000 ₽), студенческий (3 500 ₽), партнёрский пакет
  (60 000 ₽). У каждого типа есть ранняя цена; она действует по дату `EarlyBirdUntil` включительно
  (в этом году - по 15 ноября).
- Промокоды двух видов: процентные (например, 15 % для членов ассоциации) и фиксированные
  (партнёрские, 5 000 ₽). У промокода есть лимит использований и срок действия. Если промокод не
  найден, истёк или исчерпан, регистрацию не оформляем и отвечаем 422 с причиной, чтобы участник
  исправил код.
- Один пользователь - одна активная регистрация на конференцию; после отмены можно
  зарегистрироваться снова.
- Иностранные участники указывают паспортные данные - они нужны для визового приглашения.
  Паспортные данные - персональные данные, доступ к ним есть только у оргкомитета.
- `GET /api/promo-codes/check` — проверка промокода на форме до отправки.

**Отмена и возврат** — `POST /api/registrations/{id}/cancel`
- Возврат считается от суммы, которую участник заплатил за билет: за 30 дней и более до начала
  конференции - 100 %, от 7 до 29 дней - 50 %, позже - без возврата. Возвраты проводит бухгалтерия
  по выгрузке `RefundedKopecks`.
- Отменить регистрацию может сам участник или администратор организации, от которой он едет
  (администратор отвечает за сотрудников своей организации).

**Групповые заказы для организаций** — `POST /api/conferences/{id}/group-orders`
- Администратор организации покупает сразу пачку мест (от 1 до 500) одного типа по счёту; имена
  участников организация вносит позже.
- Фронт при таймауте повторяет POST с тем же заголовком `Idempotency-Key`, а бухгалтерии
  организаций иногда дважды нажимают «Оформить». Повтор с тем же ключом должен вернуть уже созданный
  заказ, а не создать второй счёт. API работает в двух репликах за балансировщиком.

**Отчёт для оргкомитета** — `GET /api/reports/registrations?conferenceId=&from=&to=`
- Количество регистраций и оплат по типам билетов за период (даты включительно).
