# MR !58: приёмка мёда с терминалов весовой и ежемесячные выплаты пчеловодам

## Зачем

Приёмщики на трёх пунктах записывают взвешивания в журнал, бухгалтерия потом переносит их в
таблицу и считает выплаты. Теряются листы, путаются сорта. Терминалы у весов теперь отправляют
взвешивания прямо в систему, а выплаты считаются автоматически.

## Что сделано

**Приёмка** — `POST /api/terminal/weighings` (аутентификация терминала по API-ключу)
- Терминал присылает номер пчеловода, тип тары, вес брутто и влажность. Вес приходит строкой
  в формате прибора, как его отдают весы: килограммы с тремя знаками после запятой, например
  `"41,250"`. Влажность приёмщик вводит на терминале по рефрактометру, она приходит числом.
- Нетто = брутто − масса тары (масса тары берётся из справочника `ContainerTypes`).
- Сорт по влажности: до 18,5 % включительно - сорт A, до 20 % включительно - сорт B, выше 20 % мёд
  не принимаем (партия фиксируется как отклонённая).
- У каждого терминала свой счётчик взвешиваний (`WeighingNo`), номера на разных пунктах
  пересекаются. Повторно присланное взвешивание не должно создавать вторую партию.
- Терминал хранит взвешивания в локальном буфере и удаляет запись только после ответа 2xx. На ответ
  4xx терминал показывает приёмщику причину и оставляет запись, чтобы приёмщик исправил номер
  пчеловода или тару; при сетевой ошибке и 5xx - повторяет позже.

**Выплаты** — `POST /api/payouts` (бухгалтерия)
- Выплата считается за календарный месяц по принятым партиям пчеловода.
- Цена за килограмм нетто - по прейскуранту, действовавшему в день приёмки партии (прейскурант
  меняется в течение сезона, обычно 2-3 раза).
- Комиссия кооператива - 3 % от суммы за мёд.
- Если пчеловод брал аванс, он удерживается из выплаты, но выплата не уходит в минус: непогашенный
  остаток аванса переносится на следующие выплаты.
- `POST /api/payouts/{id}/approve` — утверждение. Действует принцип четырёх глаз: выплату
  рассчитывает один бухгалтер, утверждает другой. После утверждения партии помечаются оплаченными.
