# Раунд усложнения

Кейсы V1-V4 прогнаны без скилла: opus (effort medium), по 2 прогона на кейс. Ревьюер нашёл все
строки `coverage` во всех прогонах (62 из 62), прошёл все `unit` и не попался ни на одну приманку.
Для замера кейсы бесполезны: потолок не оставляет места, чтобы увидеть сужение охвата.

Найдено 2 из 2 - каждая строка `coverage` всех четырёх кейсов.

## Что сделать

Перепиши кейсы V1-V4 на месте (те же id кейсов и тот же домен), чтобы ревьюер без скилла находил
заметно меньше строк `coverage` - ориентир: половина-две трети. Требования брифа (`BRIEF.md`) в силе:
дефект вне EF наблюдаемый при любом выборе команды, проект сообщает факты, а не исход, не больше
двух строк одного рода, 1-2 `unit`, 2-3 `harm`, сверка с документацией.

Что делало дефекты лёгкими - и чем их заменить:

- **Дефект виден на одном экране.** Описание MR прямо формулирует правило рядом с кодом, который
  его нарушает. Сложнее: правило выводится из факта домена, который лежит в другом файле или не в
  MR вовсе (модель, существующий сервис, константа), и для нарушения нужно пройти 2-3 перехода.
- **MR маленький и плотный.** 8 файлов, почти каждый метод с дефектом. Сложнее: MR 12-16 файлов,
  большая часть кода верна и выглядит как обычная работа (маппинг, DTO, валидаторы, регистрация в
  DI); дефекты - в небольшой доле методов.
- **Дефект - знакомый шаблон** (граница `<` vs `<=`, int-переполнение, лог запроса целиком, IDOR по
  параметру). Сложнее: дефект, который проявляется только на сочетании условий домена или на
  последовательности операций (порядок шагов, частичный сбой между двумя записями, повторный вызов
  после изменения состояния, две роли одного пользователя), и который нельзя найти поиском по шаблону.
- **Описание MR перечисляет требования списком.** Сложнее: живое описание, где требование упомянуто
  мимоходом или следует из контекста бизнеса.

Строки `coverage` можно заменять и переписывать; отчитайся, какие строки новые. Приманки и `unit` не
должны стать заметнее, чем сейчас.

В конце - та же короткая сводка по строкам `coverage` (какие места надо связать) и список изменений
против предыдущей редакции.
